# CareerMatri 소개 사이트

나라별 소개·영업용 사이트다. 학생이 검사를 보는 **플랫폼과는 별개 앱**이다
(설계 원칙 5). 각 사이트의 로그인 버튼은 전부 같은 플랫폼 한 곳을 가리킨다.

**이름은 CareerMatri 다** (R059 · 2026-10-02). 한 단어이고 C 와 M 만 대문자다.
워드마크 그림은 아직 없어 머리의 로고는 **글자**다 — `public/logo/` 의 옛
파일은 METRI 워드마크이므로 쓰지 않는다. 새 워드마크가 오면
`src/components/site-header.tsx` 의 글자 자리에 넣는다.

**도메인은 careermatri.com 하나다** (R069 · 등록 완료). 한국판이 루트에 선다.
플랫폼은 `app.careermatri.com` 으로 옮겨 간다(아직 열리지 않았다).

## 나라를 고르는 방법

코드는 하나고, 빌드할 때 `SITE` 로 어느 원고를 실을지 정한다.

```bash
SITE=global npm run dev     # 영어판
SITE=kr     npm run dev     # 한국어판
SITE=kz     npm run dev     # 카자흐어판
```

배포도 같다. 도메인마다 `SITE` 만 다르게 준 빌드를 올린다.

| SITE | 주소 | 언어 | 상태 |
|---|---|---|---|
| `kr` | **careermatri.com** | ko | 있음 · 먼저 올라간다 |
| `global` | 주소 없음 | en | 있음 |
| `kz` | 주소 없음 | kk | 있음 · **원어민 검수 전** |
| `tr` | 주소 없음 | tr | 원고 없음 |

등록된 주소는 하나뿐이다. 원고의 `domain` 은 세 판 모두 `careermatri.com`
이고, 나라별 주소를 지어내지 않는다 — 글로벌·카자흐판 꼬리의 다른 나라 줄은
"준비 중" 으로만 둔다.

## Vercel 설정

배포는 **대표 Vercel 팀(PCA)에서 이 저장소를 Import** 하는 방식이다
(2026-10-02 지시 · R033 의 Firebase 를 대신한다). 저장소 뿌리가 아니라
이 폴더가 앱이므로 Root Directory 를 반드시 지정해야 한다.

| 항목 | 값 |
|---|---|
| Framework Preset | Next.js |
| Root Directory | `pca-platform/marketing` |
| Build Command | `SITE=kr npm run build` |
| Output Directory | `out` |
| Install Command | (기본값 `npm install`) |
| Node.js Version | 20.x 이상 |

**Output 은 `out` 이다.** `output: "export"` 가 정적 파일을 그리로 내보낸다
(`next.config.ts`). `.next` 가 아니다.

환경변수 — Production·Preview 모두에 넣는다.

| 이름 | 값 | 없으면 |
|---|---|---|
| `SITE` | `kr` | 조용히 영어판이 올라간다. Build Command 에 이미 있으므로 둘 중 하나로 족하지만, 변수로도 넣어 두면 빌드 로그에서 확인하기 쉽다 |
| `PLATFORM_URL` | `https://app.careermatri.com` | 원고의 임시값(같은 주소)을 쓴다 |

도메인은 Vercel 프로젝트의 Domains 에 `careermatri.com` 과 `www` 를 붙인다.
**DNS 는 Vercel 안내값을 쓴다** — R033 에 적힌 Firebase 의 A·TXT 값은 이제
쓰지 않는다. 섞으면 어느 쪽도 뜨지 않는다.

빌드 로그 첫 줄에 `[careermatri] SITE=kr` 이 찍힌다. 그 줄이 `(없음 → global)`
이면 한국 주소에 영어판이 올라간 것이다.

### PG(KCP) 심사가 이 주소에서 찾는 것

| 무엇 | 어디 |
|---|---|
| 상품·가격 | `/pricing` (개인 25,000원 · 30명 이하 1인 22,000원 · 부가세 포함) |
| 이용약관 | `/terms` |
| 환불·취소 정책 | `/refund` |
| 개인정보 처리방침 | `/privacy` |
| 사업자 정보 | 모든 페이지 꼬리 (`footer.biz`) |

⚠️ 약관과 환불 정책은 **변호사 검토 전**이다. 같은 회사가 haricareer.com 에
게시해 둔 문서를 1차 출처로 읽어 이 사이트의 상품·단체 계약에 맞게 옮긴
것이고, 검토 전이라는 사실은 화면에 적지 않는다(처리방침과 같은 규칙).
원고 파일(`src/content/kr.ts`)의 주석에 적어 두었다.

## 미리보기

빌드해서 정적 한 장으로 뽑은 미리보기다. 메뉴는 실제로 넘어가고, 문의 폼만
접수되지 않는다 (뒤에 서버가 없다).

**이름을 바꾼 뒤(2026-10-02) 세 판을 다시 뽑아 `check-preview` 로 확인했다**
— 한국판 10쪽(약관·환불이 늘었다), 글로벌·카자흐판 8쪽, 전부 통과.
그 파일을 아티팩트 링크로 올리는 것은 이 세션에서 막혔다(사업자 정보가 들어간
문서를 공유된 페이지에 덮어쓰는 것을 환경이 거절한다). 그래서 **링크 갱신은
남아 있다** — 아래 명령으로 다시 뽑아 올리면 된다.

```bash
SITE=kr npm run build
node scripts/serve-static.mjs out-kr 3100        # 다른 창에서
node scripts/export-preview.mjs kr /tmp/careermatri-kr.html
node scripts/check-preview.mjs /tmp/careermatri-kr.html   # 경로가 실제로 넘어가는지
```

| 사이트 | 링크 |
|---|---|
| 한국 (한국어) | *갱신 필요* — 위 명령으로 뽑아 올릴 것 |
| 글로벌 (영어) | *갱신 필요* |
| 카자흐스탄 (카자흐어) | *갱신 필요* |

주소가 열리면 미리보기는 버리고 `careermatri.com` 을 보면 된다.

`check-preview.mjs` 는 뽑아낸 파일을 브라우저로 열어 경로마다 제 페이지가
나오는지 본다. 타입 검사와 빌드로는 이걸 못 잡는다 — 본문 앵커와 칸의
id 가 겹쳐 요금제를 눌러도 홈이 나오던 적이 있었고, 그때도 타입과 빌드는
멀쩡했다. CI 가 나라마다 이 검사를 돌린다. 경로 목록은 파일에서 읽으므로
페이지를 늘려도 이 스크립트는 고치지 않는다.

## 플랫폼으로 넘어가기

머리와 꼬리의 **담당자 로그인**은 검사 플랫폼으로 간다. 나라가 달라도 가리키는 곳은
한 군데다 — 소개 사이트는 나라별이지만 학생이 검사를 보는 플랫폼은 전 세계
하나이기 때문이다 (설계 원칙 5).

주소는 두 곳에서 온다. `PLATFORM_URL` 이 있으면 그것을, 없으면 원고의
`platformUrl` 을 쓴다. 둘 다 지금은 `https://app.careermatri.com` 이다.
**그 주소는 아직 열리지 않았다** — 플랫폼이 옮겨 오기 전에 누르면 아무 데도
닿지 않는다.

**빌드할 때 줘야 한다.** `SITE` 와 같다 — 페이지가 빌드 시점에 정적으로
만들어지므로, `npm start` 에만 주면 반영되지 않는다.

```bash
PLATFORM_URL=https://app.careermatri.com SITE=kr npm run build
```

바꾼 뒤 반영이 안 되면 `.next` 를 지우고 다시 빌드한다. 이전 빌드가 캐시에
남아 옛 주소가 그대로 나올 수 있다.

두 앱을 함께 띄워 확인할 수 있다.

```bash
node scripts/e2e-platform-link.mjs   # 눌러서 플랫폼 로그인까지 가는지
```

## 나라를 추가하려면

1. `src/content/tr.ts` 를 만들고 `SiteContent` 형태를 채운다
2. `src/content/index.ts` 의 `SITES` 에 한 줄 추가한다
3. `.github/workflows/ci.yml` 의 `matrix.site` 에 한 줄 추가한다

컴포넌트는 손대지 않는다. 화면에 박힌 한국어가 없도록 문구는 전부 원고에 있다.
검사 플랫폼의 `translations` 테이블과 같은 사고방식이다 — 나라가 늘 때
늘어나는 것은 구조가 아니라 내용이어야 한다.

`ui` 블록에 화면 문구가 들어 있다. 나라가 둘일 때는 `kr ? "…" : "…"` 로
버틸 수 있었지만 셋이 되는 순간 새 나라가 영어판 문구를 뒤집어쓴다.
그래서 전부 원고로 옮겼다.

**법적 문서(`terms`·`refund`)는 번역 대상이 아니다.** 그 나라 법률의
문제이므로 비워 두고, 비어 있으면 그 판은 `/terms`·`/refund` 가 404 다.

## 색과 결 (theme)

원고의 `theme` 이 `<html data-theme="…">` 로 나가고, `globals.css` 의
`[data-theme="…"]` 가 토큰을 갈아 끼운다. 비우면 기본(밝은 바탕 · 잉크 ·
로고 파랑)이다.

| theme | 어디에 | 어떤 결 |
|---|---|---|
| (없음) | global · kr | 흰 종이 · 딥네이비 잉크 · 로고 파랑. 대학에 내는 문서 |
| `steppe` | kz | 어두운 바탕 · 각진 모서리 |

`steppe` 에서도 **결과지는 흰 문서**다. 어두운 화면 한가운데 흰 종이가
떠 있는 것이 이 브랜드의 규칙이라, `.doc`·`.report`·`.cover` 안에서만
토큰을 밝은 판으로 되돌린다.

새 결을 만들 때 색을 직접 박지 않는다. `--strong`(눌러 쓰는 블록)과
`--cta`(마감 배너의 주 단추)까지 토큰으로 빠져 있으므로 토큰만 갈아 끼우면
된다.

## 라이브 플랫폼의 경로 (2026-09-09 확인)

지금 돌고 있는 플랫폼은 `pcagroup.haricareer.com` 이고, 그 안의 경로를 직접
눌러 확인했다. **옮겨 간 뒤에도 경로는 같을 것이라고 가정하지 않는다** —
`app.careermatri.com` 이 열리면 다시 확인해야 한다.

| 경로 | 응답 | 무엇 |
|---|---|---|
| `/` | 200 | 홈 |
| `/admin/login` | 200 | **담당자 로그인.** 소개 사이트의 로그인 단추가 여기로 간다 |
| `/survey` | 200 | 학생 응시. 실제로는 `?univ=…&pwd=…` 가 붙은 전용 링크로 들어온다 |
| `/login` | **404** | 없다. 예전에 여기로 걸어 두었다가 고쳤다 |
| `/privacy` | **404** | 없다. 그래서 처리방침은 이 사이트가 갖는다 |

**학생은 로그인 단추로 들어오지 않는다.** 학교가 받은 전용 링크로 들어온다.
그 링크는 학교마다 값이 달라 소개 사이트가 만들어 낼 수 없다. 그래서 단추는
담당자용이고, 학생에게는 꼬리에서 "학교에서 받은 링크로 들어가라" 고 알린다
(`nav.loginNote`).

**처리방침·약관·환불 링크는 그 판에 문서가 있을 때만 걸린다.** 한국판은
셋 다 있고(`/privacy`·`/terms`·`/refund`), 글로벌·카자흐판은 처리방침만
있다. 죽은 링크를 거는 것보다 없는 편이 낫다.

## 아직 안 된 것

- **약관·환불 정책의 변호사 검토.** 문구는 들어가 있다
- **미리보기 링크 셋 갱신** (위 "미리보기" 참고)
- **새 워드마크.** 지금은 글자 로고다
- **`app.careermatri.com` 이 열리지 않았다.** 로그인 단추가 가리키는 곳이다
- **카자흐어 원고가 원어민 검수를 받지 않았다.** 구조와 사실관계는 맞지만
  문장은 초안이다. 배포 전에 카자흐어를 쓰는 사람이 한 번 읽어야 한다.
  러시아어판이 따로 필요할 수도 있다 (`src/content/kz.ts` 머리말 참고)
- **영문 상호와 대표자 영문 표기.** 받지 못해 해외판 꼬리에는 사업자 정보가
  없다 — 지어내지 않는다
- 터키 원고
