# 단체 PCA 플랫폼

이 파일은 Claude가 매 세션 시작할 때 읽는 프로젝트 설명서다.
새 결정이 생기면 여기에 추가한다.

---

## 무엇을 만드는가

대학 공과계열 학과에 파는 진로 지표 검사 플랫폼.

학생이 검사를 보면 **그 전공으로 갈 수 있는 직무 분야**를 알려주고,
그 직무에 필요한 **역량**과 채우기 위해 들어야 할 **과목**까지 제시한다.

- 응시 대상: 대학 재학생
- 계약 주체: 학과 (또는 취업지원처)
- 첫 대상 학과: 기계공학과
- 참고 모델: 르네상스러닝 (검사 → 리포트 → 처방 구조가 동일)

| 응시 자격 | 학과가 올린 명단 기반 |
| 결과 공개 | 학과 담당자 승인 후 공개 |

| 결과지와 현멘의 관계 | 결과지 안에서 바로 현직자로 간다. 별개 서비스처럼 두지 않는다 |

## 설계 원칙 (어기면 안 됨)

**1. 로그인 주체는 users 하나다.**
기관 소속 학생이든 개인회원이든 전부 `users`에 들어간다.
소속은 `memberships`로 연결한다. 회원 테이블을 기관용/개인용으로 나누지 않는다.

**2. 사람이 읽는 이름은 전부 translations에 모은다.**
`name_ko`, `name_en` 같은 컬럼을 만들지 않는다.
나라를 추가할 때 컬럼이 아니라 행이 늘어나야 한다.

**3. 채점 산식은 코드가 아니라 데이터다.**
직무 적합도는 `scoring_weights` 테이블의 가중치로 계산한다.
산식을 코드에 하드코딩하면 학과별·국가별로 다르게 줄 수 없고, 바꿀 때마다 배포해야 한다.

**4. 검사 문항은 수정하지 않고 버전을 올린다.**
`instruments.version`. 작년 응시자의 결과가 올해 문항 수정으로 바뀌면 안 된다.

**5. 마케팅 사이트와 검사 플랫폼은 별개다.**
국가별 도메인은 소개·영업용. 학생이 검사를 보고 결과를 받는 플랫폼은 전 세계 하나다.
그래야 국가 간 비교가 가능하고, 그게 이 서비스의 핵심 자산이다.

**6. 현멘의 익명은 기능이 아니라 전제다.**
신청자에게 보이는 어떤 화면에도 멘토의 실명·회사명·이메일이 나가지 않는다.
표시 규칙은 `src/lib/anon.ts` 한 곳에 모았고, 화면마다 따로 판단하지 않는다.
회의 호스트 링크(`meetings.host_url`)는 멘토에게만 보인다.
실명이 보이는 화면은 운영사 승인 화면(`/admin/mentors`) 하나뿐이다 — 현직 인증을
하려면 누구인지 알아야 하기 때문이고, 그 대신 superadmin 으로 닫혀 있다.

## 개발 순서

1. **계정** — users, organizations, memberships, 로그인, 비밀번호 재설정, 관리자에서 기관 생성 ✔
2. **계약과 회차** — contracts, seats, test_sessions, 명단 엑셀 업로드로 계정 일괄 생성 ✔
3. **응시** — 응시 화면, responses 저장, 이어보기 ✔
4. **채점과 결과** — scoring_weights 적용 ✔, 결과지 ✔, 단체 리포트가 남았다
   채점은 `src/lib/scoring.ts`. 가중치를 `/admin/instruments/[id]` 에서 채우고,
   담당자가 회차 화면에서 돌린다. 가중치가 비어 있으면 채점이 시작되지 않는다.

3단계까지는 채점 산식 없이 진행 가능하다.

**4단계에서 정한 것**

- 지표 점수는 선택한 배점의 합을 그 지표 문항의 최소~최대로 0~100 환산한 값이다.
  역채점 문항은 `lo + hi - score` 로 뒤집는다
- 직무 적합도 = 지표 환산점수의 가중평균. 가중치 합이 0인 직무는 결과지에 안 나온다
- 역량 보유 수준은 역량 문항의 선택 순번을 0~5 로 옮긴다. 같은 역량을 여러 번 물었으면 높은 쪽
- 채점은 여러 번 돌려도 된다. 가중치를 바꾸면 다시 돌려야 반영된다
- 채점과 공개는 누른 뒤에도 그 칸이 남는다. 칸째로 사라지면 무슨 일이 일어났는지 알 수 없다

**3단계에서 정한 것**

- 문항은 화면을 열 때 한 번에 다 내려준다. 문항 이동에 서버를 부르지 않는다 —
  이동이 한 박자 늦으면 사람은 두 번 누른다. 서버로 가는 것은 시작·저장·제출뿐이다
- 선택지의 **배점(score)은 화면에 내리지 않는다**. 응답이 점수에 어떻게 반영되는지
  보이면 답이 흔들린다. 화면이 받는 것은 문항과 선택지 라벨뿐이다
- 저장은 대기열로 처리한다. 고르면 화면은 즉시 바뀌고 저장은 뒤에서 보낸다.
  실패하면 간격을 늘려가며 다시 보내되, **다시 보내도 소용없는 실패**(마감·제출 완료·
  남의 응답)는 거기서 멈추고 새로고침을 권한다. 무한 재시도는 화면을 거짓말하게 만든다
- 저장 안 된 응답이 남아 있으면 **제출을 막는다**. 그 상태로 제출하면 그 문항은
  빈 채로 채점된다. 창을 닫으려 하면 붙잡는다
- `last_order_no` 는 뒤로 가지 않는다. 앞 문항을 고치러 돌아갔다고 이어보기 지점이
  당겨지면 다음에 열 때 이미 답한 곳부터 다시 보게 된다
- 응시권은 **시작할 때** 소진된다(`seats.consumed_at`). 명단에 올린 시점이 아니다
- 제출하려면 전 문항에 답해야 한다. 미응답은 번호를 눌러 그 문항으로 건너뛴다
- 완료 화면은 서버가 그린다. 서버 액션이 끝나면 현재 라우트가 다시 그려지므로,
  클라이언트에만 완료 화면을 두면 제출하자마자 덮여 사라진다
- 선택지는 라디오 그룹이다. 방향키는 그룹 안 이동(표준), 문항 이동은 Alt+방향키와
  PageUp/PageDown, 고르기는 숫자키와 Space·Enter다

**2단계에서 정한 것**

- 응시권(seats)은 계약을 만들 때 seat_count 만큼 미리 만든다. 몇 장 남았는지를
  계산이 아니라 행 개수로 답하기 위해서다. 명단을 올릴 때 한 장씩 배정된다
- 같은 명단을 두 번 올려도 응시권을 두 장 쓰지 않는다. 이미 있는 계정은 다시 쓰고,
  비밀번호도 건드리지 않는다 — 남의 비밀번호를 바꾸는 일이 되기 때문이다
- 임시 비밀번호는 발급 직후 화면에서만 보이고 어디에도 저장하지 않는다.
  종이로 나눠주는 운영을 전제한다(인쇄 버튼이 그 표만 남긴다)
- 발급은 10명씩 끊어서 진행한다. 비밀번호 해싱이 1건당 0.4초라(bcryptjs 12라운드)
  100명을 한 요청에 넣으면 40초가 걸리고, 끊기면 어디까지 됐는지 알 수 없다.
  라운드 수를 낮추면 빨라지지만 그건 보안 설정이라 임의로 정하지 않았다

## 기술 스택

- Next.js (App Router) + TypeScript
- PostgreSQL
- 인증은 직접 구현하지 말고 검증된 라이브러리 사용
- 파일 저장은 S3 호환 스토리지
- 브라우저 저장소(localStorage 등)에 응답을 보관하지 않는다. 서버에 저장한다.

## 현멘 — 현직자 멘토링 (2026-09-12 결정)

career peak 브랜드로 붙는 기능. **석·박사가 석·박사에게 묻는 자리**다.
지금은 이공계 석·박사가 대상이고, 인문·경상 석·박사로 넓힌다.

**고르는 축이 학부 취업 서비스와 다르다.**
회사 규모가 아니라 학위(석사·박사)와 진로 경로가 먼저다.
진로 경로 여섯 가지 — 산업계 R&D · 산업계 비R&D · 정부출연연구기관 · 대학·학계 ·
창업·스타트업 · 공공·정책. 이것이 갤러리의 첫 번째 필터다.
전공 계열(`field_track`)은 이공계·인문사회·경상. 넓힐 때 컬럼이 아니라 값이 늘어난다.

**흐름**

```
갤러리(익명 카드)  →  시간대 선택 + 질문 작성  →  멘토 승낙
                                                  ↓
                        줌 회의 자동 생성 (운영사 계정 하나로)
                                                  ↓
              신청자 = 참가 링크 · 멘토 = 호스트 링크, 즉시 발송
                                                  ↓
                    24시간 전 · 1시간 전 리마인더 자동 발송
```

**자동화를 두 겹으로 나눈 이유.**
줌 회의 생성은 승낙 버튼과 같은 요청에서 끝나야 한다 — 사용자가 결과를 기다리고 있다.
알림은 그럴 필요가 없고, 메일 서버 사정으로 승낙이 실패하면 안 된다.
그래서 회의는 즉시 만들고, 알림은 `notifications` 큐에 쌓아 `scripts/notify.ts` 가 비운다.
리마인더도 같은 큐에 미래 시각으로 들어간다.

**코멘토(comento.kr)에서 가져온 것**

| 코멘토 | 현멘에 옮긴 방식 |
|---|---|
| 인증된 현직자 | 인증 근거 없이는 승인 불가. DB CHECK 로 막았다 (`mentors_active_needs_verify`) |
| 익명 · 3줄 · 3분 | 익명은 전제. 질문은 20–600자, 세 줄 가이드 |
| 24시간 내 답변 | `mentoring_requests.respond_by`. 넘기면 자동 만료되고 시간대가 풀린다 |
| 대학 제휴로 학생 무료 | 학과 계약 모델과 같다. 다만 현멘 과금은 아직 정하지 않았다 |
| 만족도·후기 | 세션 완료 후 별점·한 줄 후기. 갤러리 카드에 평균이 뜬다 |

**운영에 필요한 것**
- 줌 Server-to-Server OAuth 앱 (`.env.example` 의 ZOOM_* 세 값)
- 알림 발송 웹훅 (`MAIL_WEBHOOK_URL`). 없으면 큐에 그대로 쌓인다 — 보낸 척하지 않는다
- 크론: `*/5 * * * * cd <프로젝트> && npm run notify`

## 앵커사업 (2026, 교육부)

한국판 소개 사이트의 대학 대상 논지는 이 정책에 맞춘다.

- 2025년 출범한 **라이즈(RISE, 지역혁신중심 대학지원체계)** 가 2026년
  **‘지역성장 인재양성체계(앵커)’** 로 명칭·체계가 재정립됐다
- 목표는 ‘지역인재육성-취·창업-정주’ 선순환 생태계와 5극3특 균형성장
- 2026년 예산 21,403억 원(’25년 19,410억). 이 중 **약 4,000억 원을 성과평가
  인센티브 재원**으로 써 지방정부별로 차등 지원한다. 초광역 단위 사업 2,000억 원
- 평가는 ① 예산 나눠먹기가 없었는지 ② 지방정부-대학 소통 ③ **학생·인재에 대한
  충분한 고려가 있었는지** 를 집중 점검한다. 17개 지방정부 평가 결과는 공개된다
- 시도 중점 사항이 ‘대학 선정·사업비 교부’ 에서 **‘학생 중심 지원 강화’** 로 옮겨갔다
- 성과지표 예시에 **지역정주 취업률(졸업 후 해당 시도 내 취업자 비율)** 과
  **지역 내 유지취업률** 이 있다. 교육부 평가 전 지방정부는 대학 대상 자체평가를 한다

**PCA 가 댈 수 있는 것과 없는 것을 섞지 않는다.**
지역정주 취업률은 졸업 후 취업 통계로 확정되는 지표이므로 PCA 가 산출한다고 쓰지 않는다.
PCA 가 대는 것은 학생 체감의 증거(개인 15–20페이지 전략서)와 정주로 가는 과정
데이터(지역기업 매칭률·정주 관심)다.

## 아직 정해지지 않은 것

- 채점 가중치 값 — 표는 `/admin/instruments/[id]` 에 있고 아직 비어 있다.
  어느 지표가 어느 직무에 얼마나 중요한지는 사람이 채워야 한다
- 학생의 역량 보유 수준 판정 방법 — 지금은 역량 문항의 선택 순번을 0~5 로 옮긴다.
  문항이 없는 역량은 0 으로 잡히므로 결과지에 "부족"으로 나온다
- 실제 문항 수와 문항 내용
- 도메인
- **현멘 과금** — 무료인지, 학과 계약에 포함인지, 건당인지. 화면에 값을 쓰지 않았다
- **멘토 보상** — 코멘토는 크레딧을 현금으로 바꿔준다. 현멘은 정해진 것이 없다
- **현멘과 careerpeak.co.kr 의 관계** — 기존 사이트에 붙이는지, 이 플랫폼 안에 두는지.
  지금은 플랫폼(`/mentoring`)에 만들었다. 로그인·DB·서버 동작이 필요해서다

이 항목들은 임의로 정하지 말고 물어볼 것.
