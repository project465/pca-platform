# 기계공학 500명 시뮬레이션 — 전공을 늘리기 전에

> 전기전자·컴퓨터로 같은 뼈대를 복사하기 전에 확인할 것은 하나다.
> **산식이 실제로 사람을 갈라내는가.**
> 500명을 넣었는데 전부 같은 직무가 1순위로 나오거나, 적합도가 55~65 사이에
> 몰려 있으면 그 결과지는 팔 수 없다. 전공을 세 개로 늘려도 셋 다 못 판다.

`npm run metri:sim` · `scripts/metri/simulate.ts` · seed 20260911

---

## 어떻게 흉내 냈나

1. 사람마다 **숨은 성향**을 뽑는다 — 직무분야 10개 + 업무성향 6개
2. 그 성향대로 253문항에 답한다. 잡음을 섞어 실제 응답처럼 흔든다
3. 일부는 일부러 불성실하게 답한다 (같은 보기 연타 6.4% · 무작위 2.4% · 성실도 실패 2.2%)
4. 채점 엔진이 **1번의 숨은 성향을 되찾아 내는지** 본다

원형 여섯 가지 — 설계형 · 현장형 · 연구형 · 소프트형 · 로봇형, 그리고 **두루형**.
마지막이 진짜 시험대다. 뚜렷한 사람은 아무 산식이나 맞히고, 평평한 사람에게
무엇을 말해 주느냐가 제품의 값이다.

## 처음 돌렸을 때 — 두 군데가 깨져 있었다

### 문제 1. 직무가 구조적으로 치우친다

```
로봇·자동화 엔지니어  28.1%     기계설계        5.2%
생산기술·제조       23.6%     품질·신뢰성      2.0%
                            반도체·디스플레이 장비  0%   ← 아무도 안 나옴
```

**설계형 학생이 기계설계로 안 갔다.** 구조·유동 해석(CAE)으로 30.3% 갔다.

원인은 분야→축 변환 행렬의 열 합이 제각각이라는 것이었다.

| 축 | 몇 개 분야에서 오는가 | 합 |
|---|---|---|
| CODE | 2 | 0.75 |
| ANALYZE | 8 | 1.98 |

ANALYZE 는 여덟 분야를 평균해 **평평해지고**, CODE 는 둘뿐이라 **크게 흔들린다.**
그래서 CODE 에 가중치를 둔 직무(로봇·자동화 .22)가 사람과 무관하게 유리했다.
검사가 사람이 아니라 행렬의 모양을 읽고 있었던 것이다.

**고친 방법** — 직무 순위를 매길 때 축의 절대 높이 대신 **그 사람 안에서의
높낮이(z)** 를 쓴다. 성향(`traitZ`)에 이미 쓰던 방법을 활동 축에도 그대로
적용했다. 절대 높이는 결과지의 8축 레이더가 따로 보여주므로 잃는 것이 없다.

### 문제 2. 등수가 없는 정밀도였다

```
1위와 2위 적합도 차이   중앙 3.7점
측정 오차 (95% 구간)    중앙 7.3점    ← 오차가 차이보다 크다
1위와 2위 구간이 겹치는 사람  100%
```

신뢰구간이 **±6 이라는 상수**였다. 근거 없이 내가 정한 숫자였고, 실제 오차와
맞을 이유가 없었다. 결과지는 매번 등수를 적어 놓고 바로 아래에 "순위 차이를
크게 읽지 마십시오" 라고 쓰고 있었다. 그건 제품이 아니라 변명이다.

**고친 방법 두 가지.**

1. **구간을 잰다.** 분야 점수는 25문항 평균이므로 표준오차는 `sd/√25` 다.
   그것을 변환 행렬로 축까지 전파하고, 로지스틱 기울기를 곱해 적합도 단위로
   옮긴다. 여기에 응답 품질 벌점을 더한다.
2. **등수 대신 묶음.** 구간이 겹치는 직무는 한 묶음으로 묶는다.
   "1위 기계설계" 가 아니라 "1군 — 기계설계 · 반도체 장비" 다.

폭은 **표준오차 1배(약 68%)** 로 잡았다. 95%(1.96배)로 해 봤더니 절반이 1군에
직무 네 개 이상을 담았고 열에 하나는 여덟 개가 전부 한 묶음이 됐다.
"여덟 중 어느 것인지 모르겠습니다" 는 결과지가 아니다.
검사 점수 보고에서 표준오차 1배는 관례이기도 하다.

### 숨은 성향을 되찾았는가

```
분야  1순위 일치 91.2%   3순위 안에 99.6%     (무작위라면 10% · 30%)
성향  1순위 일치 73.5%   2순위 안에 92.6%     (무작위라면 16.7% · 33.3%)
```

## 그래서 전공을 늘려도 되는가

**된다. 다만 두 가지를 같이 들고 가야 한다.**

1. **분야→축 변환 행렬을 전공마다 새로 짤 때 열 합을 봐야 한다.**
   어떤 축이 한두 분야에서만 오면 그 축에 가중치를 둔 직무가 이유 없이
   유리해진다. 기계공학에서 겪은 그대로 반복된다.
2. **직무별 1순위 비율을 시뮬레이션으로 먼저 본다.** 어떤 직무가 0% 이거나
   30% 를 넘으면 가중치가 잘못된 것이다. `npm run metri:sim` 을 전공마다
   돌린다.

## 이 시뮬레이션이 증명하지 **못하는** 것

정직하게 적어 둔다.

- **가짜 응시자는 내가 만든 모형대로 답했다.** 실제 학생이 그렇게 답한다는
  근거는 없다. 이 시뮬레이션이 보여주는 것은 "산식이 넣은 신호를 되찾는가"
  이지 "산식이 현실을 맞히는가" 가 아니다.
- **원형 여섯 가지는 가정이다.** 실제 기계공학과가 이렇게 갈린다는 자료가
  아직 없다.
- **적합도 점수의 절대값은 의미가 없다.** 65점이 "잘 맞는다" 는 뜻이 되려면
  규준(norm)이 필요하고, 규준은 실제 응시자 100명부터 나온다.

**1차 100명 검증에서 반드시 잴 것** —
Top-3 수용률(학생이 "맞다" 고 하는 비율), 재검사 신뢰도, 그리고
`docs/metri/11_scale.md` 의 교육 전환율 20%.
그 셋이 나와야 이 문서의 숫자가 추정에서 실측으로 바뀐다.
