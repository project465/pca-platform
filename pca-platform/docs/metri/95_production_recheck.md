## 왜 닿지 못했는가

이 세션의 바깥 통신은 프록시를 지나고, 그 프록시가 운영 호스트의 연결을
정책으로 거절한다. 세 주소를 두드려 전부 `000` 을 받았다.

```
https://app.careermatri.com/api/health   000
https://app.careermatri.com/             000
https://careermatri.com/                 000

프록시 기록
  connect_rejected  app.careermatri.com:443  gateway answered 403 to CONNECT
  connect_rejected  careermatri.com:443      gateway answered 403 to CONNECT
```

**`000` 은 정책이고 사이트가 죽었다는 뜻이 아니다.** 사이트가 살아 있는지
아닌지를 이 자리에서는 가릴 수 없다.

## 사업주가 직접 누를 열두 걸음

운영 주소는 `https://app.careermatri.com` 이다. 각 걸음에 주소와 누를 것과
정상과 FAIL 기준을 적었다. 실패한 줄만 화면을 찍어 함께 보내 주시면 된다.

**높이를 눈으로 재는 법.** 오른쪽 스크롤 막대가 **손톱만 하게 줄어들면**
그 쪽이 창 열 배를 넘긴 것이다. 정확히 보시려면 브라우저 개발자 도구의
콘솔에 아래 한 줄을 넣는다. 나오는 수가 `이 화면이 창 몇 개 분량인가` 다.

```js
document.documentElement.scrollHeight / window.innerHeight
```

## 보내 주실 모양

줄마다 `PASS` 또는 `FAIL` 과 실제 증상만 적어 주시면 된다.

```
6. 절 하나 펼치기 — FAIL — 눌러도 열리지 않고 콘솔에 오류가 찍힌다
```

열두 줄이 전부 `PASS` 면 다음 판정은
`RESULT WEB RENDERING PRODUCTION PASS` 이고, 하나라도 `FAIL` 이면
`PRODUCTION ISSUE FOUND` 다. 그 둘이 갈리기 전까지 `COMMERCIAL READY` 를
쓰지 않는다.
