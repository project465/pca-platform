# ARCH_CORE_V1 — 건축·실내건축 (2026-10-13)

PHASE 2 의 열두 번째 Core 다. `src/` 아래에서 바뀐 파일이 **한 벌**이고 그것도
더하기만 했다(`result/chains.ts` · 영역 열둘의 작성 차례 · 판정 로직 0줄).
채점과 결과 판정과 Workspace UI 와 DB 스키마가 한 줄도 바뀌지 않았고 앞 열다섯
Core 의 지문이 그대로다.

```
영역 12 · 문항 369 (Core 233 · 팩 136) · 산업팩 8 · 역할팩 8 · 갈래 2
배재대 자리 81 → 85
```

## 등록부의 이름을 넓혔다

등록만 되어 있던 `ARCH_CORE_V1` 의 이름이 `건축공학` 이었다. 짓고 보니 이 Core
가 재는 열두 영역에 **실내 공간과 마감이 함께 들어 있고**, 배재대의 자리도
건축학과와 실내건축학과 둘이다. 이름이 좁으면 실내건축학과 학생이 자기 자리를
찾지 못한다. 그래서 `건축·실내건축` 으로 넓혔고 **코드와 `major` 는 그대로
둔다**: 코드를 바꾸면 그 코드로 적힌 줄이 조용히 다른 Core 를 가리킨다.

## 공간 감각과 그림 솜씨를 재지 않는다

묻는 것은 `도면 보는 것이 좋다` 나 `공간 감각이 좋다` 가 아니라 **치수와 조문과
수를 놓고 무엇을 직접 정했는가**다. 그래서 `공간 감각이 좋다` 는 영역으로도 두지
않았다: 그것은 **응시자 자신에 대한 믿음**이고 이 Core 가 재는 것은 가르고
남기는 판단이다. 문서에 적는 것으로는 지켜지지 않으므로 둘이 막는다: 짝
표(`src/lib/me-v3/measurement/registry.ts`)가 `PREFERENCE × OWNERSHIP_4` 를
거절하고, 문항마다 primary construct 를 적어 두어(`arch-v1-constructs.json`)
추론으로 지나갈 수 없다.

**대지·법규와 공간 계획을 나눈 까닭**은 앞엣것이 **지을 수 있는 한계를 가르는**
일이고 뒤엣것이 그 한계 안에서 배치를 정하는 일이어서다. 같은 까닭으로 공간
계획과 실내 공간을 나눴다: 앞엣것은 **건물 전체의 방 구성과 층**을 가르고
뒤엣것은 **한 실 안에서 쓰는 사람의 움직임과 치수**를 가른다. 도면·상세와 공사비
산출도 나눴다 — 그대로 지을 수 있게 그리는 일과 **얼마가 드는지 수로 내는 일**이
다른 판단이다.

**필수 축을 영역의 성질에서 골랐다.** 공간 계획과 형태·입면과 실내 공간과
도면·상세와 인허가 쪽은 산출물이 걸린다 — 평면과 입면과 상세와 서류 묶음이
남아야 다음 사람이 이어 받는다. 대지·법규와 구조와 설비·환경과 재료 쪽은
비교·검증이 걸린다: 계산한 규모와 잡은 틀과 돌린 모의와 고른 재료는 **조문이나
기준이나 성적서에 대어 보기 전까지 근거가 아니다.** 공사비 산출 쪽은 요구사항
해석과 방법·도구가 걸린다 — **셀 수 있는 항목으로 옮기지 않으면 셀 수 없다.**
시공 관리 쪽은 직접 판단과 실패·수정이 걸린다.

## 조경과 토목은 이 Core 에 두지 않았다

`조경학과` 가 묻는 판단은 심어 살려 내는 쪽이라 `AGRI_CORE_V1` 의 조경 갈래가
들고 있다. `토목공학과` 와 `도시계획학과` 도 별칭에 넣지 않았다 — 앞엣것은
구조물과 기반 시설을, 뒤엣것은 도시 단위의 배분을 묻고 이 Core 의 열두 영역과
겹치지 않는다. 사업성과 자금과 분양을 묻는 판단은 `BIZ_CORE_V1` 이 든다.
**한 자리를 두 Core 가 묻게 되면 그 학생이 어느 자로 재어졌는지 아무도 모른다.**

## 축과 역할기능과 조직환경은 같은 코드다

J1~J8 과 RF1~RF8 과 OC1~OC7 이 기계공학 Core 와 **같은 코드**다. 이름은
건축·실내건축계열의 말로 바꿨다: 기계 도면 자리에 **평면도와 상세도와 수량
산출서와 신청 서류 묶음**이 선다. 공통 판단 여섯과 학위 묶음 스물넷의 문항
번호도 같게 둔다 — 결과지가 그 번호로 사람이 읽는 이름을 찾고 그 표는 Core 를
모른다.

## 산업팩 여덟

주거 건축 · 공공·문화 시설 · 상업·업무 건축 · 실내건축·인테리어 ·
리테일·전시 공간 · 시공·현장 · 리모델링·대수선 · BIM·건축 자료.

**`건축` 을 산업으로 두지 않는다.** 그것은 하는 일의 이름이지 서는 자리가
아니고, 같은 도면을 놓고 주거와 공공과 상업과 실내가 서로 다른 판단을 묻는다.
주거와 공공을 따로 둔 까닭은 앞엣것은 **같은 평면이 수백 벌 되풀이된다**가,
뒤엣것은 **심의와 예산을 통과해야 한다**가 기준을 정하기 때문이다. 리모델링을
따로 둔 것도 같은 까닭이다: 그 자리는 **뜯어 보기 전까지 안에 무엇이 있는지
모른다**가 기준을 정한다.

## 역할팩 여덟

기획·설계 · 조사·검토 · 판정·검사 · 도면·표준 관리 · 현장 관리 · 운영·조정 ·
조사·연구 · 안전·규정 관리. 여덟이 역할기능 여덟과 하나씩 맞물리고, 묻는 것은
기술영역이 아니라 **그 자리에서 가진 권한과 범위**다.

자리에 붙이는 일은 다른 일이다.**

## 자동 검사가 잡은 자리 다섯

눈으로는 다섯 다 멀쩡해 보인다.

- **영역 둘의 둘째 J7 이 글자까지 같았다**(1.00): 형태·입면과 실내 공간이 둘 다
  `한 가지를 바꿔 나아진 것을 적어 본` 이었다. 그 영역이 실제로 바꾸는 것으로
  다시 적었다 — 앞엣것은 창의 크기나 재료, 뒤엣것은 가구 하나
- **재료·마감의 둘째 J7 도 같은 꼴이었다**(0.72). `같은 자리에 다른 재료를 써
  보고 덜 상한 것` 으로 바꿨다
- **역할팩이 Core 문항을 어미만 바꿔 베꼈다**(0.46): 현장 관리가 `사람과 자재가
  모자란 날 무엇을 먼저 할지` 를 그대로 물었다. **권한과 범위**를 묻는 쪽으로
  다시 썼다 — `공정 차례를 바꿀 권한이 내게 있어 따로 승인을 받지 않고 바꾼`
- **역할팩이 심화 문항과 같은 말로 묻고 있었다**(0.50): 안전·규정 관리가 `내가
  정한 점검 주기가 그 건물의 정기 점검으로` 였다. `그 조직의 다른 현장에도 같이
  쓰이게 된` 으로 넓혔다
- **산업팩과 역할팩이 같은 말로 묻는 자리가 있었다**(0.54): 시공·현장과 현장
  관리가 둘 다 먼저 넣을 공정을 물었다. 위의 역할팩 고침으로 함께 풀렸다

## 사람 열두 벌에서 고른 자리

영역을 고를 때 **필수 축이 무엇인지를 보고 골랐다.** 산출물이 빈 자리를
그리려면 산출물이 필수인 영역(TD03 · `J3`·`J5`)이 필요하고, 산출물만 비는 자리를
그리려면 산출물이 필수가 아닌 영역(TD09 · `J2`·`J4`)이 필요하다. **그 영역은
P11 과 P12 가 같이 가리켜야 한다**: 변형 검사 F 는 P11 에서 산출물을 더해 보고
소유 검사는 P12 에서 선별 축의 두 문항을 세므로, 둘이 다른 영역을 가리키면 두
검사 가운데 하나가 빈 자리를 본다.
