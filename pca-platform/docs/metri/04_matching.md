# 매칭 산식과 AI

## 원칙 — 점수는 산식이, 문장은 모델이

이 문서의 모든 것이 이 한 줄에서 나온다.

| | 누가 만드나 | 왜 |
|---|---|---|
| 직무 적합도 82점 | **산식** | 같은 입력이면 항상 같은 값이 나와야 한다. 학과 담당자가 재계산해 볼 수 있어야 한다 |
| "해석 성향이 높고 구조해석 경험이 있어…" | **LLM** | 문장은 조금 달라도 문제없다 |
| 공고에서 스킬 뽑기 | 사전 + 임베딩 + **LLM 판정** | 사람이 검수한다 |

**LLM 이 만든 숫자는 `job_fit_scores` 에 절대 들어가지 않는다.**
"AI 가 82점을 줬습니다" 는 팔 수 없다. 학생이 "왜요?" 라고 물으면 대답이 없기 때문이다.

## 1. 직무 적합도

```
Fit(직무) = 100 × ( wA·A + wS·S + wP·P + wC·C )
```

네 항이 각각 다른 질문에 답한다.

| 항 | 질문 | 데이터 출처 |
|---|---|---|
| **A** 성향·활동 | 이 일을 **좋아할** 사람인가 | 검사 응답 |
| **S** 역량 충족 | 이 일을 **할 수 있나** | 이수 과목·자격·프로젝트 |
| **P** 선호 일치 | 이 일을 **원하나** | 산업·지역·기업형태 선택 |
| **C** 이력 방향 | 그쪽으로 **가고 있나** | 최근 학기의 과목·프로젝트 |

가중치는 `scoring_profiles` 테이블에 있다. **코드가 아니라 데이터다.**

| 트랙 | wA | wS | wP | wC | 표시 |
|---|---|---|---|---|---|
| `HS` + 진학형 | 0.60 | 0.10 | 0.30 | 0.00 | 구간 |
| `HS` + 취업형 | 0.40 | 0.30 | 0.20 | 0.10 | 구간 |
| `UNIV_LOW` | 0.45 | 0.25 | 0.20 | 0.10 | 점수 |
| `UNIV_HIGH` | 0.30 | 0.40 | 0.15 | 0.15 | 점수 |
| `GRAD` | 0.25 | 0.45 | 0.15 | 0.15 | 점수 |

**학년이 올라갈수록 S 가 커지고 A 가 작아진다.**
고1은 해 본 게 없으니 성향으로 볼 수밖에 없고, 4학년은 성향보다 실력이 말해준다.

## 2. A — 성향·활동 적합

```
z_i = (T_i - 50) / 10          T 점수를 표준화. -2.5 ~ 2.5 로 절단
a   = Σ_i ( w_ij · z_i )       w 는 job_axis_weights. 직무마다 합이 1
A   = σ(1.2 · a)               σ 는 로지스틱. 0~1
```

**왜 로지스틱인가.** 선형으로 두면 극단값 하나가 점수를 지배한다.
해석 성향만 극단적으로 높은 학생이 CAE 100점이 나오는데, 실제로는 그렇지 않다.
기울기 1.2 는 `a=2.5`(모든 축이 최상위) 일 때 A≈0.95 가 되도록 잡은 값이다.

**왜 평균이 0.5 인가.** 평범한 학생이 모든 직무에서 0.5 를 받아야
직무 간 순위가 성향 차이에서만 나온다.

## 3. S — 역량 충족도

```
cov_c = min(1, h_c / r_c)              보유 / 요구. 넘쳐도 1로 자른다
S     = Σ_c ( κ_c · cov_c ) / Σ_c κ_c   κ 는 필수도 (필수 3 · 중요 2 · 보조 1)
```

**넘치는 걸 1로 자르는 이유.** ANSYS 를 5레벨로 다뤄도 요구가 4면 4까지만 쳐준다.
안 자르면 한 역량이 뛰어난 학생이 나머지 미달을 덮어버린다.

**필수도로 가중하는 이유.** 12개 요구 역량을 평등하게 평균 내면
필수 3개를 못 채운 학생과 보조 3개를 못 채운 학생이 같은 점수를 받는다. 전혀 다른 상태인데.

### 보유 수준 h 는 어떻게 정하나 — 증거 모델

**학생이 "나 3레벨" 이라고 입력하지 않는다.** 증거를 쌓고 계산한다.

```
held_raw(역량) = Σ ( 배점 × 성적계수 × 신뢰도 )     상한 6.0
```

| 증거 | 배점 | 신뢰도 | 증빙 |
|---|---|---|---|
| 이수 과목 | 2.0 | 0.95 | 불필요 |
| 프로젝트 | 2.5 | 0.80 | 필요 |
| 자격증 | 2.5 | 1.00 | 필요 |
| 인턴·현장실습 | 2.5 | 0.85 | 필요 |
| NCS 능력단위 | 2.0 | 0.95 | 필요 |
| 공모전·수상 | 1.5 | 0.90 | 필요 |
| 소프트웨어 사용 (자기보고) | 1.5 | 0.60 | 불필요 |
| 검사 내 자기평가 | 1.5 | 0.50 | 불필요 |

성적계수 — A+ 1.00 / A 0.95 / B+ 0.85 / B 0.75 / C+ 0.65 / C 0.55 / D 0.35 / P 0.70

성적을 적지 않은 과목은 **가장 낮은 계수(0.35)** 로 잡는다. 비워서 이득을
보게 두면 아무도 안 적는다. 이 값들과 사다리는 코드가 아니라 `grade_points` ·
`level_ladder` 에 있다 — 학교마다 성적 체계가 다르고, 사다리는 1차 100명
검증에서 가장 먼저 조정될 값이기 때문이다.

```
「전산구조해석」 A+  →  2.0 × 1.00 × 0.95 = 1.90
자기보고 "ANSYS 좀 함" →  1.5 × 0.60      = 0.90
                                     합 2.80  →  레벨 3
```

경계는 하한 포함이다. 2.80 은 `[2.8, 3.8)` 안이므로 3이다.
(2026-09-11 정정 — 이 예제가 레벨 2 라고 적혀 있었는데 바로 위 사다리와
어긋났다. 구현은 사다리를 따른다.)

사다리 — `[0, 0.8)→0  [0.8,1.8)→1  [1.8,2.8)→2  [2.8,3.8)→3  [3.8,4.8)→4  [4.8,∞)→5`

**"나 ANSYS 할 줄 안다" 와 "구조해석 A+" 를 같은 무게로 세면 안 된다.**
이 표가 그 차이를 데이터로 들고 있다(`evidence_sources`).
결과지에서 "왜 2레벨인가" 를 누르면 위 두 줄이 그대로 나온다.

## 4. P — 선호 일치

```
P = 0.60 · cos(학생 산업선호, 직무 산업벡터)
  + 0.25 · 지역 일치
  + 0.15 · 근무형태 일치
```

**지역에 0.25 를 주는 이유.** 앵커사업 성과지표에 지역정주가 들어 있다.
학생이 그 지역에 남고 싶은지가 학과 리포트의 핵심 숫자가 된다.
이 항이 없으면 지역 대학에 팔 수 없다.

---

## 5. C — 이력 방향

```
C = 0.50 · 최근 2개 학기 관련 과목 비율
  + 0.30 · 관련 프로젝트 적합도
  + 0.20 · 관련 인턴·실습
```

**S 와 뭐가 다른가.** S 는 "얼마나 갖췄나", C 는 "그쪽으로 가고 있나" 다.
같은 3레벨이어도 1학년 때 듣고 2년간 안 건드린 학생과
지난 학기에 집중한 학생은 다르다. 기업도 그걸 본다.

## 6. 계산 예시 — 기계공학 3학년, CAE 직무

**A · 성향**

| 축 | T | z | 가중치 | 기여 |
|---|---|---|---|---|
| 해석·계산 | 68 | 1.8 | 0.40 | 0.720 |
| 탐구·이론 | 60 | 1.0 | 0.20 | 0.200 |
| 설계·구상 | 55 | 0.5 | 0.14 | 0.070 |
| 구현·코딩 | 58 | 0.8 | 0.12 | 0.096 |
| 개선·효율 | 52 | 0.2 | 0.10 | 0.020 |
| 제작·실험 | 45 | −0.5 | 0.04 | −0.020 |
| | | | | **a = 1.086** |

`A = σ(1.2 × 1.086) = 0.786`

**S · 역량** (12개 요구 역량)

| 역량 | 요구 | 보유 | cov | κ |
|---|---|---|---|---|
| 유한요소법 | 4 | 3 | 0.75 | 3 |
| ANSYS Mechanical | 4 | 2 | 0.50 | 3 |
| 고체역학 | 4 | 4 | 1.00 | 3 |
| 공학수학 | 4 | 4 | 1.00 | 3 |
| ABAQUS | 3 | 1 | 0.33 | 2 |
| 유체역학 | 3 | 3 | 1.00 | 2 |
| ANSYS Fluent | 3 | 2 | 0.67 | 2 |
| 전산유체 이론 | 3 | 2 | 0.67 | 2 |
| Python | 3 | 3 | 1.00 | 2 |
| MATLAB | 3 | 3 | 1.00 | 2 |
| 기술문서 | 3 | 3 | 1.00 | 2 |
| 기계진동 | 2 | 2 | 1.00 | 1 |

`S = 22.08 / 27 = 0.818`

**P · 선호** — 자동차 1.0, 항공 0.8, 반도체 0.4 / 직무 산업 {자동차·항공·배터리·기계}
`cos = 0.671` → `P = 0.6×0.671 + 0.25 + 0.15 = 0.803`

**C · 이력** — 최근 과목 0.8, 프로젝트 1.0, 인턴 0.5 → `C = 0.800`

**합산** (`UNIV_HIGH`: 0.30 / 0.40 / 0.15 / 0.15)

```
A  0.786 × 0.30 = 23.6
S  0.818 × 0.40 = 32.7
P  0.803 × 0.15 = 12.0
C  0.800 × 0.15 = 12.0
                ─────
          Fit = 80.3  →  80 (±6)
```

**이 표 전체가 결과지의 "왜 80점인가" 버튼 뒤에 그대로 들어간다.**
`job_fit_scores` 에 A·S·P·C 를 따로 저장하는 이유다.

## 7. Skill Gap 우선순위

부족한 역량이 20개 나온다. **20개를 처방하면 0개를 처방한 것과 같다.** 5개로 줄인다.

```
Priority(c) = (r_c − h_c) × κ_c × demand_share_c × feasibility_c
```

| 인자 | 뜻 | 출처 |
|---|---|---|
| `r − h` | 얼마나 모자란가 | 계산값 |
| `κ` | 그 직무에 얼마나 중요한가 | `job_competency_map.criticality` |
| `demand_share` | **실제 공고에서 얼마나 요구되는가** | `jd_skill_stats.share` |
| `feasibility` | 남은 학기에 채울 수 있나 | 개설 과목 1.0 / 온라인 0.8 / 장기 0.5 |

위 예시 학생:

| 역량 | 계산 | 우선순위 |
|---|---|---|
| ANSYS Mechanical | (4−2)×3×0.67×1.0 | **4.02** |
| 유한요소법 | (4−3)×3×0.54×1.0 | **1.62** |
| ABAQUS | (3−1)×2×0.31×0.8 | 0.99 |
| ANSYS Fluent | (3−2)×2×0.42×1.0 | 0.84 |
| 전산유체 이론 | (3−2)×2×0.28×0.5 | 0.28 |

**`demand_share` 가 이 산식의 핵심이다.** 교수가 생각하는 중요도가 아니라
**공고에 실제로 적힌 빈도**로 우선순위를 매긴다. 학생이 납득하는 근거가 이것이다 —
"ANSYS 를 하세요" 가 아니라 "이 직무 공고 132건 중 89건이 ANSYS 를 요구합니다".

## 8. 공고 매칭 (JD Match)

```
JDfit = 0.55 · SkillMatch + 0.20 · JobFit + 0.15 · Preference + 0.10 · Qualification
```

`SkillMatch` 는 공고에서 뽑은 스킬로 계산한다. must 는 κ=3, nice 는 κ=1.

**하드 필터가 따로 있다.** 전공 제한·학위·비자·경력 요건에 미달하면
점수와 무관하게 `qualified = false` 로 표시한다. 숨기지는 않는다 —
"매칭 79점이지만 영어 요건 미달" 이라고 **적어서** 보여준다.
숨기면 학생이 왜 안 나오는지 모르고, 그때부터 시스템을 안 믿는다.

`missing_must` 개수를 따로 저장해 **"필수 요건 2개 부족"** 을 화면에 띄운다.

## 9. AI 를 쓰는 곳 — 스킬 추출 3단계

공고 한 건에서 스킬을 뽑는 일. 여기가 유일하게 모델이 필요한 곳이다.

```
공고 원문
   ↓
[1] 사전 매칭 — competency_aliases 565개로 문자열 매칭
   ↓            약 80% 가 여기서 잡힌다. 비용 0
[2] 임베딩 후보 — 다국어 임베딩으로 유사도 top-5, 0.82 이상만 통과
   ↓            신조어·표기 변형을 잡는다
[3] LLM 판정 — 후보만 넘겨서 {competency_id, must/nice, 근거 문장} 을 JSON 으로 강제
   ↓
[4] 사람 검수 — 사전에 없던 말은 skill_candidates 로. 주 1회 판정
```

**왜 LLM 을 1단계에 안 쓰나.** 세 가지 이유가 있다.

1. **원가** — 공고 10만 건을 전부 LLM 에 넣으면 파이프라인이 감당 못 한다. 사전이 80% 를 무료로 처리한다
2. **재현성** — 같은 공고를 두 번 넣으면 다른 결과가 나온다. 수요 통계가 흔들린다
3. **통제** — 사전에 없는 스킬을 LLM 이 마음대로 만들어내면 온톨로지가 오염된다

**LLM 은 판정자로만 쓴다.** 후보를 만드는 건 사전과 임베딩이고,
LLM 은 "이 후보가 맞나, must 인가 nice 인가" 만 답한다.
그리고 **근거 문장을 반드시 같이 받는다**(`jd_skills.evidence_span`) —
근거가 없으면 사람이 검수할 수 없다.

## 10. 가중치를 학습으로 고치는 것

초기 가중치(`job_axis_weights`)는 전문가 설정값이다. **추측이라는 뜻이다.**
100명 검증(`match_feedback`)이 정답지를 만들면 거기서 고친다.

```
학생 100명 × 직무 8개 = 800개 판정 ("맞다 / 아니다 / 모르겠다")
   ↓
ridge 로지스틱 회귀로 w 를 재추정
   ↓
제약: w ≥ 0, Σw = 1, 전문가 설정값에서 ±0.15 이상 못 벗어난다
```

**±0.15 제약을 거는 이유.** 100명은 회귀에 적은 표본이다.
제약 없이 돌리면 표본 특이성이 가중치를 이상한 데로 끌고 가고,
그러면 "CAE 직무에 조율·관리 성향이 제일 중요" 같은 설명 불가능한 값이 나온다.
**설명할 수 없는 가중치는 못 쓴다.**

블랙박스 학습 모델(신경망 등)로 적합도를 직접 예측하지 않는다.
정확도가 조금 오를 수는 있지만, 학과 담당자에게 설명할 수 없으면 팔리지 않는다.

## 11. 평가 지표

| 지표 | 뜻 | 1차 목표 |
|---|---|---|
| **Top-3 수용률** | 상위 3개 직무에 "맞다" 가 하나라도 있는 비율 | **70%** |
| Precision@5 | 상위 5개 중 "맞다" 비율 | 45% |
| Skill Gap 실행률 | 처방받은 것을 실제로 수강·취득한 비율 | 25% |
| 6개월 후 일치 | 실제 지원 직무가 상위 3개 안에 있는 비율 | 55% |
| 학과 재계약률 | | 70% |

**Top-3 수용률 70% 가 1차 검증의 통과선이다.** 이걸 못 넘기면 산식을 고친다.

## 12. 안 넣는 것

입력 자체에서 뺀다.

- **성별·나이·출신 고교·출신 지역** — 넣으면 성능이 오를 수도 있다. 그래도 뺀다.
  "여학생이라 이 직무" 가 나오는 순간 제품이 끝난다
- **대학 이름** — 학교 서열이 적합도에 들어가면 그건 진로 진단이 아니라 학벌 확인이다
- **학점 총점(GPA)** — 역량별 성적은 쓰지만 총점은 안 쓴다. 총점은 직무 방향을 말해주지 않는다

규준 집단(`norm_groups`)도 트랙·전공·학년·국가 넷으로만 나눈다.
