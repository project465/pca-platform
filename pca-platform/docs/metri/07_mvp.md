# 1차 MVP

## 범위를 한 줄로

**기계공학 한 전공 · 한국만 · 학과 계약(B2B)과 개인 결제(B2C) 동시 · 12주.**

넓히고 싶은 유혹이 세 군데에서 온다. 셋 다 막는다.

| 유혹 | 왜 막나 |
|---|---|
| 전공 3개를 한꺼번에 | Skill Tree 는 이미 3개 다 만들었다. **문제는 검증이다.** 한 전공에서 Top-3 수용률 70% 를 못 넘기면 3개를 만들어도 셋 다 틀린 것이다 |
| 미국 JD 를 같이 | 민간 공고가 유료다. 원가가 열 배다. 한국에서 산식이 맞는지부터 본다 |
| 고교를 같이 팔기 | 데이터 자산으로는 남기되 **영업 자원은 대학에만 쓴다.** 고교는 3차 |

### 데이터 준비

| 항목 | 목표 | 현재 | 남은 일 |
|---|---|---|---|
| 기계공학 Skill Tree | 역량 49 · 직무 8 | **완료** | 현직자 검수 |
| 요구 수준·필수도 | 96개 관계 | **완료** (추정치) | 현직자 8명 검수 |
| 동의어 사전 | 200+ | **완료** (ME 분 약 190) | 공고 돌려보며 보강 |
| 검사 문항 | 기존 PCA 문항 + 48 | 공학축 초안 16 | **기존 문항 이식** + 공학축 32개 추가 집필 |
| 국내 공고 | 20,000건 | 0 | 워크넷 API 60일 수집 |
| 대상 대학 과목 매핑 | 1개 학과 | 0 | 학과 협조로 교육과정 받기 |

**가장 오래 걸리는 것은 공고 수집이다.** 하루 300~800건이면 20,000건에 30~60일.
**그래서 이걸 1주차에 시작한다.** 화면보다 먼저다.

**문항은 기존 PCA 것을 쓴다** (2026-09-11 결정, `docs/metri/03_assessment.md` 0장).
140개를 새로 쓰는 게 아니라 기존 문항을 이식하고 **공학 활동 8축 48문항만 추가**한다.
집필·검수가 4~5주에서 1.5주로 줄어든다. 대신 **문항 원문과 채점 키를 넘겨받는 것이
1주차 선행 과제**가 된다 — 이게 늦어지면 4주차가 통째로 밀린다.

**굵은 주차가 못 밀리는 지점이다.** 나머지는 밀려도 된다.

## 100명 검증

### 방법

1. 기계공학과 3–4학년 100명에게 검사와 결과지를 준다
2. 상위 8개 직무 각각에 **"맞다 / 아니다 / 모르겠다"** 를 받는다 (`match_feedback`)
3. 이유를 한 줄 받는다 — **이게 산식을 고칠 실마리다**
4. 부족 역량 5개에 대해 "이미 있다 / 없는 게 맞다 / 필요 없다" 를 받는다

### 통과선

| 지표 | 통과선 | 못 넘기면 |
|---|---|---|
| **Top-3 수용률** | **70%** | 산식을 고친다. 제품을 못 판다 |
| 부족 역량 동의율 | 60% | 요구 수준을 다시 잡는다 |
| 완료율 (시작 → 제출) | 85% | 문항 수를 줄인다 |
| 프로필 입력 완료율 | 70% | 입력을 더 줄인다 |
| 결과지 이해도 (5점) | 3.8 | 결과지를 다시 쓴다 |

**Top-3 수용률 70% 가 이 프로젝트의 유일한 관문이다.**
나머지 지표는 개선 과제지만 이건 통과/실패다.

### 예상되는 실패 모드

| 증상 | 진짜 원인 | 대응 |
|---|---|---|
| 모든 학생이 같은 직무 1위 | 필수도 가중이 약하거나 규준이 없다 | `criticality` 반영 확인, 전문가 기준점 조정 |
| 점수가 다 70~85 사이 | 로지스틱 기울기가 낮다 | 1.2 를 올린다 |
| "아니다" 이유가 대부분 "그 일이 뭔지 모르겠다" | **산식 문제가 아니라 설명 문제** | 직무 설명을 결과지에 넣는다 |
| 부족 역량이 전부 소프트웨어 | 공고가 도구만 적기 때문 | L2 이론 역량의 `demand_share` 를 따로 보정 |

네 번째가 실제로 가장 많이 날 것이다. 공고는 "ANSYS" 라고 적지 "유한요소법" 이라고 안 적는다.

## 완료 기준

MVP 가 끝났다고 말할 수 있는 조건.

- [ ] 학생 100명이 검사 → 결과지까지 실제로 통과했다
- [ ] Top-3 수용률 70% 이상
- [ ] 학과 담당자가 D3 리포트를 보고 **"이 숫자 어디서 나왔어요?"** 에 화면 안에서 답이 된다
- [ ] 공고 20,000건이 쌓였고 `demand_share` 가 직무당 200건 이상에서 나온다
- [ ] 개인 결제가 실제로 한 건 이상 일어났다 (B2C 경로가 살아있는지 확인)
- [ ] 검수 큐가 주 1회 돌아가고 신규 스킬이 반영된 이력이 있다

## 정리하고 넘어가야 할 충돌

기존 `CLAUDE.md` 마지막에 적힌 문제다. **여기서 정한다.**

| 항목 | 플랫폼 스펙 | ACADEMIX 제안서 | **결정** |
|---|---|---|---|
| 처방 | 역량 갭 → 개설 과목 | 자격·프로젝트·포트폴리오·면접·창업·지역기업 | **둘 다 낸다.** `skill_gap_items.action_kind` 가 `course` 든 `cert` 든 담는다. 트랙별로 기본 처방 종류만 다르다 |
| 응시 자격 | 학과 명단 기반 | 전용 링크 발급 | **둘 다.** 명단은 B2B, 전용 링크는 B2C 와 소규모 계약. `seats` 하나로 처리된다 |
| 직무 영역 | 전공별 직무군 8개 | 전 학과 공통 10개 영역 | **공존한다.** 공통 10개는 성향 축(기존 PCA), 전공별 8개는 METRI 축. 결과지에서 층이 다르다 |

**세 충돌 모두 "하나를 고른다" 가 아니라 "데이터로 흡수한다" 로 풀린다.**
스키마가 이미 그렇게 돼 있다.
