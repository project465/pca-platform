## B. 홈 (규격 §10)

첫 화면이 넷을 든다: **현재 상태 셋 · 지금 할 일 하나 · 최근 변화 한 줄 ·
기록 둘.** 전에는 넷째가 첫 화면 밖이었다.

- 묶음마다 서 있던 `보기` 단추를 **묶음 머리 오른쪽의 글자 링크**로
  옮겼다. 단추 줄 하나가 50px 이고 넷이면 마지막 묶음이 통째로 밀린다
- `지금 할 일` 이 **지금 판본의 짧은 지시**를 적는다. 옛 줄에는 화살표 넷짜리 체인이 들어 있어 두 줄을 먹었다
- `최근 변화` 가 한 줄이다. 나머지는 현재 상태의 `달라진 것 모두` 가 든다
- 홈이 **묻지 않는 것은 읽지도 않는다**: 고르신 산업·직무·지역과 결과
  기록을 네 번 더 묻던 질의를 걷었다

## C. 검사 데스크톱 (규격 §15)

영역 훑기 격자가 **표 계산기처럼 읽히던 것**을 고쳤다.

- 칸마다 줄인 말을 또 적어 **열두 줄 × 다섯 칸에 같은 낱말이 예순 번**
  섰다. 지금은 칸에 번호만 서고, 뜻은 격자 머리가 한 번 든다
- 칸의 테두리를 걷었다. 선 예순 개 위에 같은 낱말 예순 개가 겹치면
  전문 검사로 읽히지 않고 표가 된다
- 격자 머리가 **붙어 선다**(`position: sticky`). 열두 줄은 한 화면에 다
  들어오지 않아서, 머리가 같이 흘러가면 번호가 무엇을 가리키는지 알 수 없다
  그러려고 `.qs-sweep` 의 `overflow` 를 `hidden` 에서 `clip` 으로 바꿔야 했다.
  `hidden` 은 스크롤 상자를 만들어 안쪽 `sticky` 를 죽인다
- 경험 칸 셋(`없다 · 한두 번 · 여러 번`)은 **낱말이 값이라** 반대로
  낱말만 두고 머리를 세우지 않았다. `0 · 1 · 2` 는 횟수의 자리표로 읽히지 않고
  점수로 읽힌다

## D. 검사 모바일 (규격 §14)

좁은 화면에서 격자 머리의 가운데 셋을 감추고 있었다. 그래서 손전화에서
읽히는 말이 `1 전혀 관심 없음` 과 `5 매우 관심 있음` 둘뿐이었고,
**가운데 셋이 무엇인지가 화면 어디에도 없었다.**

지금은 칸 너비를 버리고 다섯 단계를 **줄글로 끝까지** 적는다. 관심이면
`1 전혀 관심 없음 · 2 관심 적음 · 3 보통 · 4 관심 있음 · 5 매우 관심
있음`, 배울 뜻이면 `1 전혀 배우고 싶지 않음 … 5 매우 배우고 싶음`.
**자리가 좁다고 축의 뜻을 줄이지 않는다.**

`shortOf()` 가 들고 있던 줄인 말 표를 지웠다. 머리와 칸이 서로 다른 말을
들고 있었고(`관심 있음` vs `있음`), 그 어긋남은 좁은 화면에서만 드러났다.
**은행과 저장되는 값과 `band()` 는 한 글자도 바뀌지 않았다.**

## E. 경험 추가 (규격 §2·§3·§4)

390px 첫 화면에 **종류 · 제목 · 시작한 달 · `다음` 이 전부 들어온다.**
전에는 걸음 표가 260px 을 먹고 첫 입력 칸이 화면 밖이었다.

- 걸음 표를 카드 셋에서 **한 줄**로 줄였다(`1 무슨 경험 › 2 기술 판단 ›
  3 남은 것`). 무엇을 묻는지는 그 걸음의 칸이 적는다
- 1단의 보조 설명을 전부 걷었다. 보기 아홉이 그대로 보이는 자리에
  `가장 가까운 하나를 고르세요` 는 보고 있는 것을 글로 한 번 더 읽게 한다
- `이걸 적으면 무엇이 달라지나요` 를 폼 **아래**로 내렸다
- **종류를 미리 고르지 않는다.** `수업` 을 켜 둔 채로 두면 그냥 넘긴
  사람의 기록이 전부 수업이 되고, 그 값은 그 사람이 고른 값이 아니다
- 폼 쪽의 글 폭을 1100 에서 **840** 으로 좁혔다(규격 §17)

**적다 만 것을 들고 나가지 않게 막는다**(`src/app/me/unsaved.tsx`).
손전화에서 저장 단추 바로 아래가 아래 띠라, 한 칸 아래를 누르면 적던 것이
통째로 사라지는 자리였다. 막는 자리는 **띠의 링크로 좁혔다**: 폼 안의
`이전` 까지 가로채면 묻는 창이 거들지 않고 거치적거리기만 한다.
`npm run v3:product-loop` 이 둘을 센다. 적다 말고 띠를 누르면 묻는가,
그리고 **적은 것이 없으면 묻지 않는가.**

## F. 현재 상태 (규격 §5·§6·§7)

첫 화면이 다섯을 차례로 든다: 현재 상태 · 기준 날짜 · 지금 설명할 수 있는
영역(최대 셋) · 최근 달라진 것(한 줄) · 지금 할 일(하나).

- `지금 할 일` 이 Gap 목록 아래에 있어 첫 화면 밖이었다. 위로 올렸고,
  비어 있는 자리 전부 · 달라진 것 전부 · 전체 기술영역 · 검사 당시 결과와
  지금 · 산업과 직무 · 지역은 그 아래다(규격 §6)
- **같은 문장을 영역마다 되풀이하지 않는다.** `지원서에서 설명할 경험이
  확인됐습니다` 가 영역 카드마다 한 번씩 서서 셋이면 같은 줄이 셋 섰다.
  뜻은 묶음 머리에 한 번 적고 아래에는 영역 이름만 세운다
- 두 칸 격자에 셋을 담아 **오른쪽에 큰 빈 면**이 남던 것을 한 칸으로 폈다
- 짙은 단추가 `경험 추가` 에서 **`지금 할 일 보기`** 가 됐다(규격 §19)
- `전체 기술영역` 의 칩을 묶음마다 다섯까지 세우고 나머지는 `외 N곳` 으로
  적는다(규격 §13). 아홉이 깔리던 줄이 있었다

자동검사도 같이 고쳤다. 넷이 **있는지만** 세던 줄은 `다음 행동` 이 첫
화면 밖으로 밀려도 통과했다. 지금은 묶음 머리를 읽어 **차례까지** 센다.

## G. 다음 할 일 (규격 §9)

`구조·내구 해석 사례 하나를 골라 하중과 구속조건 → 이상화와 모델 →
해석값 → 검증 대조 → 설계 변경 차례로 한 쪽에 정리해보세요.`

읽는 사람이 **그래서 지금 무엇을 하면 되는가**에 닿기까지 화살표 넷을
지나야 했다. `actionKo()` 가 `do` 와 `guide` 를 가른다:

- 지시: `구조·내구 해석 사례 하나를 골라 한 쪽으로 정리해보세요.`
- 차례: `적는 차례는 하중과 구속조건 → … → 설계 변경 입니다.` (펼침 안)

`EXPLORE_BROADLY` 의 앞 문장(`어느 영역이 앞선다고 보기 어렵습니다`)은
판정이라 할 일 자리에서 걷고 화면의 `왜 필요한가` 가 든다.

**담아 둔 줄의 옛 문장도 짧게 적는다.** `v3_actions.body` 에는 담을 때의
문장이 남아 있어서, 굳은 결과에서 같은 할 일을 찾으면 지금 판본의 짧은
지시로 그리고 못 찾으면 담아 둔 문장을 그대로 쓴다. **지어내지 않는다.**

## L. 문장 (규격 §20)

**쪽을 띄워서 글자를 센다.** 소스에서 세면 식별자(`function Gap`)와
주석까지 걸려 맞는 기록을 지우라고 요구하게 된다.

| 말 | 전 | 후 |
|---|---|---|
| 반영 | 11 | **0** |
| Evidence | 없음 | **0** |
| Gap | 없음 | **0** |
| 스냅샷 · 묶음 · 번역 · 가져오기 | 없음 | **0** |
| 자리(우리 비유) | 8 | **0** |
| 판정(우리 결과) | 1 | **0** |

남은 `자리` 일곱과 `판정` 셋은 **영역 사전과 산업 자료의 기계공학 말**이다
(`공정과 품질 판단이 자리를 많이 쓴다` · `기준을 만족하는지 재서
판정한다`). 이쪽은 뜻이 정확한 자리라 고치지 않았다. 규격도 `단 의미가
정확해야 한다` 고 적었다.

바뀐 말: `반영하다` → `더하다`, `비어 있는 자리` → `부족한 부분`,
`쓰인 자리` → `쓰인 곳`, `최근 반영 YYYY-MM-DD` → `YYYY-MM-DD 기준`,
`새 경험 반영하기` → `새 경험 더하기`, `경험 반영` → `경험 더함`.

돌아오지 않게 `npm run v3:copy` 에 규칙 넷을 더했다(파일 28벌 · 규칙 28가지).

## O. 시각 회귀 (규격 §26·§27)

`npm run v3:visual` 이 자리 스무 곳을 **폭 열하나 × 확대 넷**으로 본다.

- 폭 320 · 360 · 375 · 390 · 430 · 768 · 1024 · 1280 · 1366 · 1440 · 1920
- 확대 100 · 125 · 150 · **200%**

세는 것: 가로 밀림 · 창을 넘는 덩이 · 말줄임으로 잘린 글 · 바닥 띠가 본문을
덮는가 · **첫 화면의 짙은 단추 수** · **첫 화면 아래의 큰 빈 면**.

뒤의 둘이 이번에 들어왔고, **되돌려 실제로 걸리는 것까지 확인했다**:
가짜 단추를 하나 넣으면 둘로 세고, Track 의 가운데 세우기를 끄면
`603px 비어 있다` 로 걸린다.

**큰 빈 면은 규격이 이름을 댄 자리만 센다.** 검사 화면은 담긴 글이 몇
줄뿐인 것이 정상이고, 짧다고 가운데로 올리면 **질문이 화면마다 올라갔다
내려간다**. 이 저장소는 그 반대를 규칙으로 두었다.

찍은 그림의 지문은 **한 걸음 안에서만** 견준다. 걸음을 가로질러 견주면
바탕으로 쓰는 굳은 결과가 한 벌이라 **새로 온 사람의 결과지와 돌아온
사람의 결과지**가 걸린다. 그 둘은 같은 것이 맞다.

## P. Journey 캡처 (규격 §28)

`docs/metri/shots/v3/loop/` 에 스물두 장.

찍고, 여기서 찍는 것은 이음매다.

## P-2. 검사하는 서버를 틀리면 검사가 거짓말을 한다

이 회차에 한 번 속았고, 그 자리에 장치를 달았다.

`npm run build` 는 `.next/standalone` 을 **통째로 지우고 다시 만든다.**
그때 떠 있던 서버는 지워진 디렉터리를 `cwd` 로 들고 계속 돈다
(`/proc/<pid>/cwd -> …/.next/standalone (deleted)`). 쪽은 멀쩡히 뜨는데
`sites/pca-platform/content/*.json` 을 상대 경로로 읽는 자리가 전부
`ENOENT` 로 500 이 된다.

그 500 이 격리 검사에서는 이렇게 보였다.

```
걸림  응시 · 남의 응시 화면이 열리지 않는다 · A 500 · B 404
```

**A 가 제 화면을 못 여는 것인데 `막힘` 으로 적혔다.** 고칠 것은 제품이
제품이 아니었다. 서버였다.

띄우는 쪽이 `var/.serving-build` 에 지금 빌드를 적고(그 자리는 `.next`
밖이라 지워지지 않는다), 눌러 보는 검사들이 `assertFreshServer()` 로
`.next/BUILD_ID` 와 견준다. 다르면 그 자리에서 멈춘다. **되돌려 실제로
멈추는 것까지 확인했다.**

```
Error: 떠 있는 서버가 지난 빌드입니다(STALE000 ≠ XivZZ2L1gbgWqDjZ3Sgug).
       `npm run stage:serve <포트>` 로 다시 띄우십시오.
```

서버를 다시 띄우고 돌린 격리 검사는 **11가지 전부 통과**다.

## R. 운영 명령 (규격 §25) · **미실행**

Railway → 서비스 → ⋯ → Shell. **운영 이미지의 `package.json` 에 있는
여덟 줄만 돈다**: `db:init` `db:upgrade` `db:verify` `make:admin`
`ops:check` `pg:smoke` `pg:confirm` `pilot:check`.

```bash
# 1. 지금 코드까지 올라와 있는가 (읽기만 한다)
npm run db:verify          # 핵심 7/7 · ME_V3 5/5 · 내 CareerMatri 5/5

# 2. 안 올라와 있으면 한 줄
npm run db:upgrade

# 3. 운영 한 장 — DEPLOY · DOMAIN · DATABASE · PDF_VOLUME · EMAIL · OAUTH · PAYMENT
npm run ops:check

# 4. 이번 회차가 운영 응답에 닿는지 (읽기만 한다)
psql "$DATABASE_URL" -f /app/db/checks/v3_measurement_impact.sql
```

바깥에서 도는 것(저장소 쪽):

```bash
npm run launch:check    # 오늘 켤 수 있는가 — 갈래 열둘
npm run image:check     # 최종 runtime image 구성
npm run mail:check      # 메일 코드 쪽 + 자격증명이 있으면 한 통
npm run oauth:ready     # 소셜 로그인 코드 쪽 (공급자에 붙지 않는다)
npm run pg:smoke        # 돈을 한 푼도 움직이지 않고 결제 배선을 센다
PLAN=1 bash scripts/backup-restore.sh   # 복구 계획만 찍는다
npm run prod:check      # 밖에서 열한 쪽 — 이 컨테이너에서는 프록시가 막는다
```

**실제 PG 를 켜지 않았다.** `pg:smoke` 는 승인을 내는 코드가 아니고,
카드를 긁는 일은 사람이 한 뒤 `pg:confirm` 이 받는다.

## T. 남은 것

- **운영 배포본을 밖에서 한 번도 열지 못했다.** 네트워크 정책이

  못해 크로뮴에 iOS 화면과 터치를 씌운다

- 영어판은 한 줄도 쓰지 않았다
- 규준이 없으므로 **`검증된 검사` 로 팔지 않는다**
