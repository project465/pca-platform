# 메트리 플러스 — 중·고등학생용

2026-09-12 결정. 이 문서는 **왜 따로 만드는가**와 **무엇을 따로 만들지 않는가**를
가른다. 뒤엣것이 더 중요하다. 브랜드가 둘이 되는 것과 코드가 둘이 되는 것은
전혀 다른 일이고, 여기서 갈라지는 것은 앞엣것뿐이다.

---

## 1. 왜 따로인가 — 대학판 문항을 고등학생이 못 푼다

`00_positioning.md` 는 "나누는 축은 학교급이 아니라 전공" 이라고 못 박았고,
그 판단은 **상품 개수**에 대해서는 지금도 맞다. 전공이 늘면 매출이 늘고
학교급이 늘면 비용만 는다.

그런데 그 문서가 전제한 것이 하나 틀렸다. **"고교판 검사지 한 벌" 은
있다고 적혀 있지만 실제로는 없다.** 2026-09-12 기준 DB 확인:

```
instruments        1행 · 1.0.0 / UNIV_LOW 뿐
HS_V1              없음
hs_subjects        0행
```

있는 것은 껍데기다 — `tracks.HS`, `major_fit_weights` 47행,
`job_cluster_tracks.HS` 10행, `products.REPORT_HS` 19,000원. **문항이 0개다.**

그리고 대학판 250문항을 그대로 줄 수 없다. 실제 문항 세 개를 그대로 옮긴다.

> 전공 수업에서 배운 CAD로 제품 모양을 3차원으로 그려보는 과정이 흥미롭다.
> 재료역학 수업에서 배운 내용을 실제 부품이 견디는 힘 계산에 적용해보고 싶다.
> 캡스톤 설계에서 처음부터 완벽하게 그리기보다 빠르게 만들어 보완하는 편이다.

중2에게 "재료역학", 고1에게 "캡스톤 설계" 를 물으면 답이 성향을 재는 게 아니라
**그 단어를 아는지를 잰다.** 모르는 학생은 전부 3번(보통이다)을 찍고, 그러면
성실도 검사에 걸린다. 문항을 새로 쓰는 것 말고 방법이 없다.

**그래서 문항은 따로 만든다. 그 이상은 따로 만들지 않는다.**

## 2. 무엇을 공유하는가 — 엔진은 하나다

| | 메트리 | 메트리 플러스 | 공유하나 |
|---|---|---|---|
| 문항 | `PCA_ME_V1` 253개 | `HS_V1` | **아니다** |
| 활동 축 8개 | ANALYZE·DESIGN·BUILD·CODE·FIELD·OPTIMIZE·RESEARCH·ORCHESTRATE | 같다 | **그렇다** |
| 업무 성향 6개 | 독립·도전·속도 ↔ 협력·안정·품질 | 같다 | **그렇다** |
| 채점 산식 | `src/lib/scoring.ts` | 같다 | **그렇다** |
| 가중치 | `scoring_profiles` 행 | 행만 다르다 | 표는 같다 |
| 결과 대상 | 직무 적합 | 전공 적합 | 표가 다르다 |
| 결과지 | 대학판 | 고교판 | 템플릿 다름 |
| 사람 | `users` 한 표 | 같다 | **그렇다** |
| 결제 | `orders`·`payments` | 같다 | **그렇다** |

**축 8개와 성향 6개를 공유하는 것이 이 제품의 전부다.** 고1 때 잰 DESIGN 0.8 이
대학 2학년 때 잰 DESIGN 0.8 과 같은 자로 읽혀야, `learner_profiles` 의
"고1 때 만든 행이 대학 4학년까지 따라간다" 가 말이 된다. 축을 새로 만들면
메트리 플러스는 그냥 별개 회사의 별개 검사가 된다.

그래서 **HS_V1 문항은 새로 쓰되, 재는 축은 대학판과 같은 축이다.**
`indicators.axis_code` 가 그 약속을 스키마에서 강제한다.

## 3. 갈리는 곳은 결과지 뒷부분 한 군데다

`learner_goals` 값 하나가 정한다. 코드에 `if (학교유형)` 이 없다.

| `goal` | 누가 | 결과지 뒷부분 |
|---|---|---|
| `univ` 진학형 | 일반계고 (기본값) | 전공 적합 → **과목 처방** (고교학점제 선택과목) |
| `job` 취업형 | 마이스터고·특성화고 (기본값) | 직무 적합 → **자격·NCS 처방** |
| `hs` 고교선택형 | 중학생 (신설) | 계열 적합 → **어떤 고등학교를 볼 것인가** |

중학생을 위해 트랙을 새로 만들지 않는다. `learner_goals` 에 행 하나가 는다.
중학생에게 고교학점제 과목을 처방하는 것은 의미가 없고(아직 고등학생이 아니다),
직무를 처방하는 것은 더 의미가 없다. 중학생이 실제로 앞두고 있는 선택은
**어떤 고등학교에 갈 것인가** 하나다.

## 4. 점수를 몇 자리까지 보여주는가

대학생은 `display_mode = score`, 고등학생은 `band` 다. 이유가 있다.

```
scoring_profiles
  HS  / univ   A 0.60  S 0.10  P 0.30  C 0.00   band   top 3
  HS  / job    A 0.40  S 0.30  P 0.20  C 0.10   band   top 5
  UNIV_LOW     A 0.45  S 0.25  P 0.20  C 0.10   score  top 6
```

고1은 증거가 거의 없다. 수강한 전공 과목도, 프로젝트도, 자격증도 없다.
`S`(역량 충족)와 `C`(이력) 가중치가 낮은 것은 그 때문이고, **증거가 없는
학생에게 소수점 한 자리 점수를 주면 그건 거짓말**이라서 구간으로 보여준다.

"기계공학 67.3점" 은 고등학생에게 아무 의미가 없고, 틀렸을 때 되돌리기도
어렵다. "지금 재 보면 기계·전기전자 쪽이 앞에 있고, 컴퓨터가 그 다음이다"
라고 적는 편이 정직하다.

## 5. 파는 방식

| | 메트리 | 메트리 플러스 |
|---|---|---|
| 결재권 | 학과장 | 진로진학부장·담임 |
| 계약 단위 | 학과 × 학기 | 학교 × 학년 |
| 개인 단가 | `REPORT_UNIV` 29,000원 | `REPORT_HS` 19,000원 |
| 자연 확장 | 취업까지 | **대학 입학 후 메트리로 넘어간다** |

메트리 플러스의 진짜 값은 단가가 아니라 **연결**이다. 고1에 검사를 본
학생이 대학에 가서 메트리를 다시 보면, 두 결과가 같은 축 위에 놓인다.
획득 비용이 0인 대학생 사용자가 해마다 쌓인다.

> `00_positioning.md` 는 "고교는 단가가 낮고 결재선이 길다" 고 적었고
> 그 지적은 지금도 유효하다. 고교를 **단독 사업**으로 보면 그 계산이 맞다.
> 메트리 플러스는 단독 사업이 아니라 메트리의 입구다. 그래서 만든다.

## 6. 만든 것과 아직 없는 것

**2026-09-12 기준으로 도는 것** — 결제 → 응시 → 채점 → 결과지가 실제 DB 로
한 바퀴 돈다 (`npm run metri:hs`).

| | |
|---|---|
| 검사지 `HS_V1` | 115문항 (8계열 × 14 + 성실도 3) · 한국어·영어 · 예상 14분 |
| 성향 문항 | 96개 (6성향 × 16). 대학판과 **같은 축**이다 |
| 전공 적합 | `major_fit_scores` 에 8전공 × (점수·A·P·구간·묶음) |
| 결과지 | 같은 화면이 그린다. 갈라지는 것은 문구뿐(`repXxxHs`) |
| 단체 리포트 | 1순위 분포가 전공으로 집계된다 |
| 과목 처방 | 2022 개정 교육과정 73과목 · 학년별 · 선수과목 · 서울대 권장 대조 |

**시뮬레이션 500명** (`npm run metri:sim:hs`)

```
1순위 계열이 갈리는가     8개 전부 나옴. 가장 몰린 곳 19.6%
원형이 심은 계열 회복      1순위 89.2% · 3순위 안에 99.3%  (무작위 12.5%)
성향 회복                 1순위 76.5% · 2순위 안에 93.0%  (무작위 16.7%)
묶음                     1군 크기 중앙 2개 · 둘 이상으로 갈린 사람 100%
불성실 응답              연타 100% · 무작위 100% · 성실도 무시 100% 걸러냄
                        성실하게 답한 사람 99.5% 정상 판정
```

시뮬레이션이 두 가지를 잡아냈고 둘 다 고쳤다.

**하나 — 축을 거치면 전공이 자기 자신을 못 찾는다.** 처음에는 대학판과 똑같이
영역 → 활동 8축 → 전공으로 갔는데, 전기·전자 문항만 높게 답한 학생의 1순위가
컴퓨터공학 74% 로 나왔다. `W·Wᵀ` 를 보면 이유가 분명하다 — 전기·전자의 축
분포는 평평해서(최대 ANALYZE .24) 자기를 가리키는 힘이 0.155 인데, 컴퓨터공학은
CODE .38 로 뾰족해 0.250 이다. **대학판은 문항이 직무를 직접 재지 않아 축을
거쳐야 하지만, 고교판은 계열 14문항이 그 계열을 바로 잰다.** 자기 자신과 자기
자신 사이에 변환을 한 번 끼우면 신호가 섞이기만 한다. A 항을 영역 점수에서
바로 가져오게 고쳤더니 89.2% 로 올라왔다. 축 8개는 레이더와 대학판과의
연속성에 그대로 쓴다 — 재는 데 안 쓸 뿐 없애지 않는다.

**둘 — 성실도 확인을 세 개 중 둘 틀려도 통과했다.** "전부 틀렸을 때만 무효"
였는데, 3문항에서 무작위로 찍으면 하나쯤은 우연히 맞는다(P≈38%). 절반 이상을
틀리면 무효로 바꿨다. 대학판에도 있던 구멍이라 같이 막혔다.

그리고 고교 검사지를 올리는 과정에서 **운영에 나갔으면 사고였을 것 두 개**를
막았다. `openAttempt` 가 검사지를 `ORDER BY id DESC` 로 골라서, 29,000원을 내고
대학판을 산 사람에게 고교 문항 115개가 나갈 참이었다(이제 `products.track_code`
가 정한다). 채점은 `job_areas` 를 통째로 긁어서, 고교 영역 8개가 대학 응시자의
채점에 응답 0개짜리로 끼어들 참이었다(이제 검사지에 묶인 영역만 본다).

## 7. 이공계만 한다 (설계 원칙 7)

메트리 플러스도 이공계다. 8개 계열로 고정한다.

```
ME   기계공학          EE   전기·전자공학
CE   컴퓨터공학        CHE  화학공학
MSE  신소재공학        IE   산업공학
CIV  건설·환경공학     BME  바이오·의공학
```

경영·경제·인문·예체능 계열은 다루지 않는다. 중학생용이라고 해서 "모든 계열을
다 봐 주는 진로검사" 로 넓히면, 이공계 한 갈래를 끝까지 판다는 이 사업의
유일한 근거가 사라진다. 넓은 진로검사는 이미 시장에 많고 무료다.
