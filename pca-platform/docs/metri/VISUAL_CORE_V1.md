# VISUAL_CORE_V1 — 시각·디자인 (2026-10-13)

PHASE 2 의 열세 번째 Core 다. `src/` 아래에서 바뀐 파일이 **한 벌**이고 그것도
더하기만 했다(`result/chains.ts` · 영역 열둘의 작성 차례 · 판정 로직 0줄).
채점과 결과 판정과 Workspace UI 와 DB 스키마가 한 줄도 바뀌지 않았고 앞 열여섯
Core 의 지문이 그대로다.

```
영역 12 · 문항 369 (Core 233 · 팩 136) · 산업팩 8 · 역할팩 8 · 갈래 4
배재대 자리 85 → 93
```

## 그림 솜씨와 감각을 재지 않는다

이 Core 가 가장 쉽게 취향 검사로 미끄러지는 자리다. 묻는 것은 `그림 그리는 것이
좋다` 나 `감각이 좋다` 가 아니라 **무엇을 어떤 근거로 정했고 그것이 어디까지
갔는가**다. 그래서 `그림을 잘 그린다` 는 영역으로도 두지 않았다: 그것은
**응시자 자신의 손**이고 이 Core 가 재는 것은 가르고 남기는 판단이다.
**포트폴리오의 잘 그린 정도를 묻지도 않는다** — 그것은 사람이 보는 일이다.
문서에 적는 것으로는 지켜지지 않으므로 둘이 막는다: 짝
표(`src/lib/me-v3/measurement/registry.ts`)가 `PREFERENCE × OWNERSHIP_4` 를
거절하고, 문항마다 primary construct 를 적어 두어(`visual-v1-constructs.json`)
추론으로 지나갈 수 없다.

**과제 정의와 콘셉트를 나눈 까닭**은 앞엣것이 **무엇이 문제이고 누구를 위한
것인지** 가르는 일이고 뒤엣것이 그 문제를 어느 결로 풀지 가르는 일이어서다.
같은 까닭으로 조형·레이아웃과 타이포그래피를 나눴다: 앞엣것은 **덩어리와 자리와
여백**을, 뒤엣것은 **글자가 읽히는 크기와 흐름**을 가른다. 서사·연출과
동작·애니메이션도 나눴다 — 어느 차례로 보여 줄지 정하는 일과 **그 사이가 어떻게
움직일지 정하는 일**이 다른 판단이다.

**필수 축을 영역의 성질에서 골랐다.** 콘셉트와 조형과 캐릭터와 연출과 제품
형태와 권리·납품 쪽은 산출물이 걸린다 — 보드와 시안과 설정집과 콘티와 모델과
목록이 남아야 다음 사람이 이어 받는다. 과제 정의와 타이포그래피와 색과 제작
사양 쪽은 비교·검증이 걸린다: 세운 정의와 짠 조판과 고른 색과 적은 사양은
**쓰는 사람의 말이나 기준이나 견본에 대어 보기 전까지 근거가 아니다.** 동작과
사용자 반응 쪽은 실패·수정이 걸린다 — 처음에 안 되는 것이 흔하고 까닭을 좁히는
것이 그 일이다.

## 계열을 `OTHER_INTERDISCIPLINARY` 에서 `STEM` 으로 옮겼다

처음에는 `OTHER_INTERDISCIPLINARY` 로 적었는데 **그 계열은 어느 시장에도 서지
않는다**: `markets.json` 이 KR 에 STEM 과 인문·사회와 경상만 연다. `v3:arch` 가
그 자리에서 `어느 시장에도 못 서는 core` 로 걸렸다. **시장 정책을 Core 하나의
사정으로 넓히지 않았다** — 넓히면 다음 Core 가 그 넓어진 줄을 물려받는다.
짓고 보니 열두 영역의 절반이 **만들어질 수 있게 하는 판단**이라(제작 사양과 양산
검토와 제품 치수와 동작의 용량과 색의 보정) `ARCH_CORE_V1` 과 같은 자리에 둔다.

## 광고와 패션은 이 Core 에 두지 않았다

매체와 집행과 반응을 묻는 판단은 `MEDIA_CORE_V1` 이 들고, 입는 것과 꾸미는 것은
`STYLE_CORE_V1` 이 든다. `실내건축학과` 와 `건축학과` 도 별칭에 넣지 않았다:
치수와 조문으로 지을 수 있게 하는 쪽은 `ARCH_CORE_V1` 이다. `게임공학전공` 도
넣지 않았다 — 그쪽은 구현과 자료구조를 묻고 `CS_CORE_V1` 이 든다. **한 자리를 두
Core 가 묻게 되면 그 학생이 어느 자로 재어졌는지 아무도 모른다.**

## 축과 역할기능과 조직환경은 같은 코드다

J1~J8 과 RF1~RF8 과 OC1~OC7 이 기계공학 Core 와 **같은 코드**다. 이름은
시각·디자인계열의 말로 바꿨다: 기계 도면 자리에 **콘셉트 보드와 콘티와 스타일
가이드와 제작 사양서**가 선다. 공통 판단 여섯과 학위 묶음 스물넷의 문항 번호도
같게 둔다 — 결과지가 그 번호로 사람이 읽는 이름을 찾고 그 표는 Core 를 모른다.

## 산업팩 여덟

웹툰·만화 · 게임 아트 · 애니메이션·영상 · 브랜드·아이덴티티 · 편집·출판·인쇄 ·
제품·패키지 · 디지털 제품 화면 · 전시·공간 그래픽.

**`디자인` 을 산업으로 두지 않는다.** 그것은 하는 일의 이름이지 서는 자리가
아니고, 같은 그림을 놓고 웹툰과 게임과 브랜드와 제품이 서로 다른 판단을 묻는다.
웹툰과 게임 아트를 따로 둔 까닭은 앞엣것은 **한 주를 밀면 그 주의 독자가
빠진다**가, 뒤엣것은 **돌아가지 않으면 예쁜 것이 뜻이 없다**가 기준을 정하기
때문이다.

## 역할팩 여덟

기획·콘셉트 · 조사·레퍼런스 · 판정·검수 · 가이드·에셋 관리 · 제작 실무 ·
운영·조정 · 조사·연구 · 권리·규정 관리. 여덟이 역할기능 여덟과 하나씩 맞물리고,
묻는 것은 기술영역이 아니라 **그 자리에서 가진 권한과 범위**다. **조사·레퍼런스와
조사·연구를 따로 둔 까닭**은 앞엣것이 **이미 있는 것을 모아 고르는** 일이고
뒤엣것이 **아직 답이 없는 것을 좁히는** 일이어서다.

## 자동 검사가 잡은 자리 열

눈으로는 열 다 멀쩡해 보인다.

- **타이포그래피와 서사·연출의 둘째 J7 이 글자까지 같았다**(1.00): 둘 다
  `한 가지를 바꿔 읽히게 된 것을 적어 본` 이었다. 그 영역이 실제로 바꾸는
  것으로 다시 적었다 — 앞엣것은 글자 크기와 간격, 뒤엣것은 컷을 더 끊기
- **다섯 영역의 첫째 J3 가 한 틀을 돌려 썼다**(0.77~0.87): 색과 캐릭터와 동작과
  제품 형태와 제작 사양이 모두 `~이 둘로 갈릴 때 어느 쪽으로 갈지 직접 정해 본`
  이었다. 다섯 다 그 자리에서 실제로 고르는 것으로 다시 썼다
- **조형과 제품 형태의 둘째 J5 가 같은 꼴이었다**(0.79): `읽히는 차례` 와
  `쓰는 차례` 가 한 글자만 달랐다. 뒤엣것을 `열고 쥐고 버리는 차례를 그림으로`
  로 넓혔다
- **산업팩과 역할팩의 문항이 글자까지 같았다**(1.00): 브랜드와 가이드 관리가
  둘 다 `규칙이 지켜지지 않은 뒤 어느 조항이 어려웠는지 좁혀 가이드를 고친`
  이었다. 산업팩 쪽을 **그 자리의 조건**(현장에서 다른 글꼴로 바꿔 쓴 것을 보고
  지킬 수 있는 선으로 낮추기)으로 다시 썼다
- **산업팩 셋이 Core 심화 문항을 어미만 바꿔 베꼈다**(0.43~0.56). 셋 다 그
  산업의 조건을 들게 다시 썼다: 브랜드는 한 결이 여러 자리로 퍼지는 일,
  제품은 가장 작은 손을 기준으로 적는 일과 한 개에서 몇 원을 줄이는 일

## 사람 열두 벌에서 고른 자리

영역을 고를 때 **필수 축이 무엇인지를 보고 골랐다.** 산출물이 빈 자리를
그리려면 산출물이 필수인 영역(TD07 · `J3`·`J5`)이 필요하고, 산출물만 비는 자리를
그리려면 산출물이 필수가 아닌 영역(TD11 · `J6`·`J7`)이 필요하다. **그 영역은
P11 과 P12 가 같이 가리켜야 한다**: 변형 검사 F 는 P11 에서 산출물을 더해 보고
소유 검사는 P12 에서 선별 축의 두 문항을 세므로, 둘이 다른 영역을 가리키면 두
검사 가운데 하나가 빈 자리를 본다. 검증만 비는 자리는 **비교·검증이 필수가 아닌
영역**(TD08 · `J4`·`J7`)이어야 한다.
