# 25. METRICAREER 제안서와 지금 코드의 차이

2026-09-16. 받은 문서: `METRICAREER 제안서.docx` (본문 13절 + 화면 22장).

---

## 0. 한 줄

**제안서가 파는 것이 지금 코드가 만드는 것보다 넓다.** 엔진은 그대로
쓸 수 있고, 모자란 것은 문항 은행과 지역 데이터다.

## 2. 이번에 만든 것

### 부가 문항 — 지역 정주와 만족도

`db/schema_metri.sql` 36절 · `src/lib/survey.ts` · `npm run metri:survey`

제안서가 의뢰 기관에 약속한 성과지표다. **검사 문항과 표를 나눴다.**

```
검사 문항(questions·responses)  →  점수를 만든다
부가 문항(survey_items·survey_responses)  →  점수를 만들지 않는다
```

섞으면 정주 의향이 직무 적합도를 흔든다. `scoring.ts` 가 이 표를 아예
읽지 않는 것을 검사 2절이 확인한다.

**짝이 맞는 사람만 센다.** 앞만 답하고 나간 사람을 한쪽 평균에 넣으면
두 평균이 서로 다른 사람들의 평균이 되어 뺄셈이 거짓말을 한다. 검사
4절이 여덟 명 중 여섯 명만 세는 것을 확인한다.

**문항 전문은 제안서 그대로 넣었다.** 응시 전과 후의 문장이 조금이라도
달라지면 비교가 의미를 잃는다.

**5명 미만이면 감춘다.** 기존 단체 리포트와 같은 규칙이다.

### 학과 카탈로그 28개

`data/metri/majors_kr.json` · `major_programs` 표 · `npm run metri:majors`

제안서 03절의 표를 **한 줄도 바꾸지 않고** 옮겼다. 다만

**문항이 없는 학과는 켜지 않는다.** 28개 중 실제로 문항 은행이 있는 것은
기계공학 하나다. 스키마의 `CHECK (NOT active OR instrument_key IS NOT NULL)`
가 검사지 없는 학과를 켜지 못하게 막는다. 켜 두면 학생이 전공을 고르고
들어가 빈 검사를 만난다.

```
학과 28개를 넣었다.
  켜짐 1개 — ME
  꺼짐 27개 — 문항 은행이 없다. 지어내지 않는다
```

## 3. 만들지 않은 것과 그 이유

**27개 학과 문항.** 제안서는 경영학과 문항 8개를 예시로 보여줄 뿐이고,
나머지는 문서에 없다. 문항은 지어내지 않는다 — 기존 250문항도 엑셀에서
그대로 가져왔고 한 글자도 고치지 않았다(CLAUDE.md). 학과 하나를 여는 데
필요한 것은 ① 직무영역 10개 정의 ② 영역당 25문항 ③ 영역↔활동축 변환
행렬이다.

**지역 기업 13,920곳.** 표(`companies`)는 있고 데이터가 없다. 제안서는
"큐레이션 2,742 + 벤처기업 9,155 + 코스피 688 + 코스닥 1,335" 라고
출처를 밝혀 뒀으니 그 네 벌을 받아 적재하면 된다. **없는 것을 있다고
화면에 그리지 않는다.**

**결과지 8섹션 재구성.** 지금 결과지는 무료·유료 경계 위에 서 있어서
(설계 원칙 10) 섹션을 바꾸면 그 경계도 같이 움직인다. 제안서는 기관
의뢰(B2B)만 말하고 개인 결제를 말하지 않아, **어느 쪽으로 파는지가
정해져야** 섹션을 다시 짤 수 있다.

## 4. 순서

1. **이름과 범위를 정한다** (5절) — 이게 끝나야 원고·화면이 안 흔들린다
2. **학과 하나를 더 연다** — 제안서가 앞세우는 경영학과가 자연스럽다.
   직무영역 10개는 제안서와 `academix.co.kr` 에 이미 있다
3. **지역 기업 데이터를 받는다** — 매칭 로직은 그 다음이다
4. **기관 리포트를 제안서 10절 구성으로 맞춘다** — 정주·만족도 절은
   이번에 만든 집계를 그대로 쓴다
5. 결과지 8섹션

## 5. 정해야 하는 것 둘

### ① 이름 — METRICAREER 인가 Careermetri 인가

어제 `Careermetri` 로 79개 파일을 바꿨는데 제안서는 전부 **METRICAREER**
다. 같은 두 낱말의 순서만 다르다. 한쪽으로 못 박아야 원고가 안 흔들린다.

도메인은 `metricareer.com` · `.co.kr` · `.kr` 이 전부 조용하다
(`careermetri.*` 도 마찬가지다). **다만 제안서 푸터에 `www.hari.re.kr`
가 적혀 있고 그 주소는 살아 있다** — 이미 쓰는 도메인이 있다는 뜻이라,
도메인 결정도 이 답에 딸려 있다.

### ② 이공계만인가, 28개 학과인가

설계 원칙 7은 "이공계만 다룬다. 별도 지시가 없으면 이 원칙이 기본값" 이다.
제안서에는 경영·심리·디자인·미용·언어까지 들어 있다. **제안서대로 가면
원칙 7을 접는 것**이고, 그러면 원고의 논지 하나가 같이 바뀐다 — 지금
홈페이지는 "공학 직무는 나라가 달라도 같은 역량을 요구한다" 를 해외 진출
근거로 쓰고 있는데, 28개 학과로 넓히면 그 근거가 약해진다.

**표는 28개를 다 담아 뒀으니 어느 쪽이든 코드는 안 바뀐다.** 바뀌는 것은
무엇을 켜고 무엇을 원고에 쓰느냐다.
