## A. 데이터 사전 (§5) — 그래프를 그리기 전에 적는다

> 정의 없이 그래프부터 만들지 않는다.

여기 적힌 값 **밖의 값은 어떤 그래프에도 들어가지 않는다.** 모든 값은
굳어 있는 결과 모델(`src/lib/me-v3/result/model.ts`)과 채점 스냅샷이 이미
들고 있는 것이고, 이 층은 **그 값을 다시 계산하지 않는다.**

### A-0. 만들지 않는 값

역량점수 · 적성점수 · 직무 적합도 · 전공 적합도 · 백분위 · 순위 ·
합격가능성 · 추천확률 · 임의 100점 환산 · 임의 5점 환산. 넷 다 이 제품이
계산하지 않는 값이고, 차트는 **presentation layer** 다.

그래서 어떤 축에도 `%` 가 붙지 않고, 어떤 축도 서로 다른 뜻의 값을 한
눈금에 섞지 않는다.

### A-1. 읽는 원본 — 이미 존재하는 칸만

| 칸 | 어디서 오는가 | 뜻 |
|---|---|---|
| `domains[].code` · `name` | taxonomy | 그 Core 의 기술영역 (BIZ 는 TD01~TD12) |
| `domains[].opened.probe` / `.deep` | 응시 routing | 그 영역의 축을 **물었는가** |
| `domains[].experience` | 영역 훑기 격자 | `NONE` · `ONCE_OR_TWICE` · `SEVERAL` (응답 그대로) |
| `domains[].interest` · `learning` | 영역 훑기 격자 | `LOW` · `MID` · `HIGH` 또는 `null`(잘 모르겠다) |
| `domains[].axes[].state` | 채점 | `NOT_OBSERVED` · `PARTICIPATED` · `CONFIRMED` · `OWNED` |
| `domains[].axes[].missing` | 채점 | `NOT_ROUTED` · `SKIPPED` · `ANSWERED_NONE` · `ANSWERED_UNKNOWN` · `NONE_MISSING` |
| `domains[].confirmed` | 채점 | 해 본 것 이상으로 **확인된** 축 목록 |
| `domains[].owned` | 채점 | 조건·기준까지 **직접 정한** 것으로 확인된 축 목록 |
| `domains[].did` · `decided` | 응답 | 그 사람이 고른 판단 항목 (해 본 일 · 직접 정한 일) |
| `domains[].artifacts` | 응답 | 그 영역에서 고른 **산출물** 목록 |
| `domains[].verifications` | 응답 | 그 영역에서 고른 **비교·검증 대상** 목록 |
| `domains[].required` | taxonomy | 그 영역에서 빠지면 안 되는 축 둘 |
| `evidence.ready` / `partial` | 결과 모델 | 지금 설명할 수 있는 근거 · 재료가 모자란 근거 |
| `gaps[]` | 결과 모델 | `domain` · `axis` · `kind` · `why` · `rank` |
| `actions[]` | 결과 모델 | `domain` · `axis` · `code` · `horizon`(NOW/NEXT/LATER) · `material` |
| `overview.counts` | 결과 모델 | `confirmed_axes` · `owned_axes` · `evidence_items` |

여덟 축의 이름은 taxonomy 가 들고 있다: J1 문제 정의 · J2 요구사항 해석 ·
J3 직접 기술 판단 · J4 방법·도구 · J5 산출물 · J6 비교·검증 ·
J7 실패·수정 · J8 조직 활용.

### A-2. 시각화 A — Radar「경험·근거 분포」 (2026-10-14 재정의)

**축**: **이번 응시에서 실제로 판단을 물은 영역만** 선다
(`opened.probe ∪ opened.deep`). BIZ PRO 의 한 예가 경영전략·기획 ·
마케팅·시장 · 영업·사업개발 · 재무·투자 판단 넷이다. routing 이 축을
묻는 영역이 두셋에서 네댓이라, 그 Core 의 영역 전부를 꼭짓점으로 두면
**나머지가 중심에 찍히고 그 점은 0점으로 읽힌다.** 전체 영역은 A-4 의
Evidence Matrix 가 줄로 들고 거기에 `이번에 묻지 않음` 이 적힌다.

**앞 판본과 달라진 자리.** 2026-10-13 판은 열두 영역을 전부 축으로 두고
묻지 않은 영역을 빈 점으로 그렸다. 빈 점은 **중심에 찍히는 점**이라, 모양
으로는 `아주 낮음` 과 구별되지 않는다. 글자로 `묻지 않음` 을 적어도 먼저
읽히는 것은 모양이다. 그래서 축에서 뺀다.

**반지름의 뜻은 하나다**(§9). 중심에서 바깥으로 가는 거리는 **그 영역의
응답이 어느 단계까지 확인됐는가** 하나이고, 관심도도 학습 의향도 적합도도
들어가지 않는다. 서로 다른 개념을 합친 composite score 가 아니다.

**표시값은 점수가 아니라 이름이 붙은 네 단계다.** 눈금마다 그 단계의
이름이 적히고, 숫자도 퍼센트도 적지 않는다. 이미 결과지가 여덟 축을 네
상태 눈금으로 적는 방식과 같은 자다.

| 눈금 | 이름 | 정확히 무엇을 뜻하는가 |
|---|---|---|
| 0 | 해본 적 없음 | `experience` 가 `NONE` 이거나 비어 있고 확인된 축이 없다 |
| 1 | 경험이 있다고 답함 | `experience` 가 `ONCE_OR_TWICE` 이상. 축 확인은 아직 없다 (`confirmed.length === 0`) |
| 2 | 응답에서 확인됨 | `confirmed.length >= 1` — 해 본 것 이상으로 확인된 축이 하나 이상 |
| 3 | 조건·기준까지 직접 정함 | `owned.length >= 1` — 직접 정한 것으로 확인된 축이 하나 이상 |

위에서 아래로 **단조**다: 뒤 단계는 앞 단계를 포함한다. 그래서 한 눈금에
서로 다른 뜻이 섞이지 않는다.

**그리지 않는 경우**: 물은 영역이 셋 미만이면 다각형이 서지 않는다(둘이면
선분이고 하나면 점이다). 그때는 **억지로 그리지 않고** 시각화 B 와 A-4 가
그 자리를 글자로 든다(`canRadar()`).

### A-3. 시각화 B — Domain별 경험 단계 (수평 누적 막대)

**행**: 축을 물은 영역만 (`opened.probe ∪ opened.deep`, 선별 둘 ~ 심화 넷).
묻지 않은 영역은 행을 만들지 않는다.

**한 행의 전체 길이** = 그 영역에서 **실제로 물은 축의 수** (선별만 열린
영역은 넷, 심화가 열린 영역은 여덟). 길이가 다른 행을 비율로 바꾸지 않고,
행 끝에 `물은 축 N개` 를 적는다. **비율로 바꾸면 적게 물은 영역이 많이
확인된 것처럼 보인다.**

| 칸 | 정확히 무엇을 뜻하는가 |
|---|---|
| 해본 적 없음 | `axes[].state === "NOT_OBSERVED"` 인 축의 개수 |
| 주어진 조건으로 수행 | `state === "PARTICIPATED"` 인 축의 개수 |
| 직접 수행 | `state === "CONFIRMED"` 인 축의 개수 |
| 조건·기준까지 직접 정함 | `state === "OWNED"` 인 축의 개수 |

네 칸의 합은 늘 그 행의 전체 길이와 같다. 색만으로 가르지 않고 칸 안에
수를 적고, 범례에 네 이름을 그대로 적는다.

### A-4. 시각화 C — Evidence Matrix

**행**: 축을 물은 영역 (B 와 같은 목록). **열 다섯**이고 각 칸은 **수**이거나
**있음/아직** 둘 중 하나다. 평균도 합계도 만들지 않는다.

| 열 | 정확히 무엇을 뜻하는가 |
|---|---|
| 직접 수행 | `confirmed.length` — 해 본 것 이상으로 확인된 축의 개수 |
| 기준 설정 | `owned.length` — 직접 정한 것으로 확인된 축의 개수 |
| 산출물 | `artifacts.length` — 그 영역에서 **고른 산출물**의 개수 |
| 비교 | `verifications.length` — 그 영역에서 **고른 검증 대상**의 개수 |
| 검증 | J6(비교·검증) 축의 상태 이름 하나 (`axes` 에서 J6 를 찾아 적는다) |

칸이 0 이면 `0` 이 아니라 `아직` 으로 적고, 그 영역에서 그 자리를 묻지
않았으면 `묻지 않음` 으로 적는다. **0 과 묻지 않음을 같은 글자로 적지
않는다.**


**2026-10-14**: 행이 **그 Core 의 영역 전부**가 됐다(§8 2순위). Radar 가
이번에 판단한 영역만 축으로 두므로, 나머지 영역이 어디로 갔는지를 적는
자리가 있어야 한다. 묻지 않은 줄은 개수를 `0` 으로 적지 않고 칸을 합쳐
`이번에 묻지 않음` 한 번만 적는다: **0 은 `없다` 로 읽히고, 안 물어본 것을
없다고 적으면 응시자가 자기가 빠뜨린 줄 안다.**

### A-5. 시각화 D — Action Roadmap

**네 칸이고 전부 `actions[]` 와 `gaps[]` 에서 온다. 새 Action 을 만들지
않는다.**

| 칸 | 정확히 무엇을 뜻하는가 |
|---|---|
| 지금 | `actions.filter(a => a.horizon === "NOW")` |
| 다음 경험 | `horizon === "NEXT"` (없으면 `LATER`) |
| 남길 Evidence | 그 할 일의 `material.artifacts` 와 `material.verify_targets` |
| 지원서/면접 | PRO 에서 이은 문장(`draftKo`)이 서는지, 그리고 `evidence.ready` 의 영역·축 |

칸이 비면 비었다는 것과 **왜 비었는가**를 적는다(빈자리가 없어서인지,
아직 축을 묻지 않아서인지는 `overview.first_move` 가 이미 가른다).

### A-6. 두 번 적지 않는다

차트는 **같은 사실을 글로 적는 절의 옆자리**에 선다. 차트를 넣는다고 그
절의 글을 지우지 않고, 반대로 모든 절에 차트를 넣지도 않는다. 시각화는
위의 **넷뿐**이다.

### A-7. 관리자 화면의 차트 (§24)

관리자 쪽 차트는 **집계만** 읽고 그 집계는 `cell()` 과 `MIN_CELL` 을
그대로 지난다. 5명 미만 칸은 수를 내지 않고 차트에서도 **막대를 0 으로
그리지 않는다**(빗금으로 그리고 `5명 미만` 을 적는다). 빈 막대는 0 으로
읽힌다. 학생 개인 응답은 어느 차트에도 들어가지 않는다.

### C-1. 지금 드러난 충돌 하나

§3 은 Result Identity 에 `CareerMatri PRO` 를 적으라고 한다. 그런데 앞

그 밖의 자리에 혼자 선 `PRO` 는 여전히 걸린다.

## D. 289% 를 끝까지 따라갔다 (§23)

**숨기지도 100 으로 자르지도 않았다.** 비율이 100 을 넘었다는 것은 두 수
가운데 하나가 틀렸거나 둘이 서로 다른 모집단을 세고 있다는 뜻이고, 자르면
그 사실이 화면에서 사라질 뿐이다.

### D-1. 두 수가 정확히 무엇을 세는가

| 자리 | 지금 세는 것 |
|---|---|
| 분자(완료자) | `v3_attempts` 에서 `status='scored'` 인 **사람 수**(`count(DISTINCT user_id)`) |
| 분모(대상자) | `campus_students` 의 줄 수 — 학교가 발급한 계정 |
| 묶는 조건 | 담당자 기관에 소속되었거나(`memberships`) 응시 줄에 그 학교 코드가 적혀 있거나 |

### D-2. 넘친 까닭 둘

**첫째, 분자와 분모의 모집단이 다르다.** 분모는 **명단에 오른 사람**이고
분자는 **그 학교로 들어와 친 사람**이다. `/campus/pcu` 로 혼자 들어온
학생은 명단에 없어도 응시 줄에 학교 코드가 적힌다. 그래서 분자가 분모를
넘을 수 있고, 넘은 그 수가 289% 다. 이 기계의 자료에서도 **명단에 없는
응시자가 한 명** 있다.

바닥을 `max(명단, 시작)` 으로 바꾼 것이 앞 회차의 고침이고, 그것으로 100 을
넘는 일은 끝났다. **명단을 늘려 맞추지 않는다**: 그 수는 학교가 올린 것이고
우리가 고칠 값이 아니다.

**둘째, 시연·검사 계정이 두 수에 함께 섞였다.** 이것이 이번 회차에 새로
찾은 자리다. 이 저장소는 운영 지표에서 `users.is_demo` 를 거르는 규칙을
전부터 들고 있었는데(`admin-overview` · `funnel` · `ops` · `workspace-events`),
**학교 집계만 그 줄을 빠뜨리고 있었다.** 그래서 우리가 만든 계정이 대상자
에도 완료자에도 섞이고, 섞이는 비율이 다르면 그 둘로 낸 비율이 흔들린다.

이 기계의 자료가 그것을 그대로 보인다.

| 세는 것 | 전부 | 시연 제외 |
|---|---|---|
| 대상자(명단) | 27 | 0 |
| 시작한 사람 | 14 | 0 |
| 결과를 받은 사람 | 14 | 0 |

### D-3. 중복은 아니었다

분자와 분모 모두 **사람 단위**다. 한 사람이 응시를 두 번 열어도
`count(DISTINCT user_id)` 라 한 번 세어지고, 명단도 사람 수로 센다(이번에
`count(*)` 를 `count(DISTINCT user_id)` 로 바꿨다). 이 기계에서 명단 줄
27 과 사람 27 이 같다.

### D-4. 고친 것과 고치지 않은 것

- **고쳤다**: 학교 집계가 시연·검사 계정을 거른다. 섞어 보려면
  `/org/v3?demo=1` 이고, 그때는 **화면이 그 사실을 적는다.**
- **고쳤다**: 명단을 사람 수로 센다.
- **그대로 둔다**: 바닥이 `max(명단, 시작)` 인 것과, 바닥이 어느 쪽인지를
  KPI 아래에 적는 것. 이름도 `완료율(대상자 기준)` · `(시작한 학생 기준)`
  으로 갈려 있다.
- **만들지 않았다**: 완료율을 100 으로 자르는 코드.

## E. 담당자 첫 화면의 차례 (§22)

대상자 → 시작 → 완료 → 완료율 → 응시 추이 → 단과대학별 → 학과별 →
**주의가 필요한 학과** → **최근 응시** 이고, 전공 · 학위 · 산업 · 직무 ·
영역 분포 다섯은 `전공 · 학위 · 산업 · 직무 · 영역 분포 보기` 안으로
내렸다(§22 의 drill-down). **담긴 것은 그대로다.**

`주의가 필요한 학과` 는 **새 지표가 아니다.** 서는 둘은 이미 세던 것이고
(시작한 사람 · 결과를 받은 사람) 셋째는 그 둘의 차다. **학과끼리 줄을
세우지 않고**, 시작한 사람이 다섯이 안 되는 학과는 이 목록에 서지 않는다:
그런 학과에서 `한 명이 아직 안 끝냈습니다` 는 그 한 사람을 가리키는 말이다.

`최근 응시` 는 날짜마다 시작과 완료의 사람 수이고 **5명 규칙을 날짜 칸에도
건다**(§24). 하루에 한 사람만 친 날이 그대로 찍히면 그 사람이 누구인지
담당자가 짐작할 수 있다.

  리포트다. 자동 감사의 스물두 벌은 11~12쪽이고, 그 극단에서 한 쪽이

  종이에 세로 균형을 잡는 수단이 없어 문서 길이가 쪽 경계에 어디쯤
  떨어지는가로 몇 %는 늘 흔들린다.
- **`/my` 와 `/me/experience/new` 가 응시 전인 사람에게 막힌다.** 열린
  Core 가 둘이라 `activeCore()` 가 하나를 고르지 못한다
  (`platform.ts:86`). **이 회차 전부터 있던 자리**이고, 작업공간이 Core 를
  고르는 규칙을 바꾸는 일이라 따로 승인받는다.
- **운영 배포본을 밖에서 열지 못했다.** 네트워크 정책이
  `app.careermatri.com:443` 을 막는다. 운영 Canary 는 별개로 남는다.
