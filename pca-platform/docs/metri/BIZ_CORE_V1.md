# 경영 Core 를 콘텐츠만으로 더했다 (BIZ_CORE_V1 · 2026-10-13)

이 회차의 1순위는 Core 하나를 더 만드는 것이 아니다. **공통 엔진과 공통
UI 와 DB 와 공통 테스트 구조를 수정하지 않고 콘텐츠만 더해 Core 하나를
완성할 수 있는가**였다. 앞 회차(CS)가 그것을 한 번 보였고, 이번에는
**이공계가 아닌 계열**에서 같은 일이 되는지를 본다.

판정은 이렇다.

| 목표 | 결과 |
|---|---|
| 공통 채점 엔진 변경 | **0** |
| 결과 엔진(판정) 변경 | **0** |
| Workspace UI 변경 | **0** |
| DB 스키마 변경 | **0** |
| 공통 테스트 harness 변경 | **0** (`scripts/` 와 `package.json` 이 글자까지 그대로다) |
| ME · EE · CS 응시자가 읽는 한국어 | **775줄 그대로** (글자로 견줬다) |

**`src/` 아래에서 바뀐 파일이 한 벌**이고 그것도 더하기만 했다:
`src/lib/me-v3/result/chains.ts` 에 `BIZ_CORE_V1` 열두 줄을 붙였다
(28줄 추가 · 삭제 0 · 판정 로직 0줄). 그 파일은 **Core 를 열쇠로 둔 자료
표**이고 판정에 들어가지 않는다. 9절 ③에 왜 아직 `content/` 밖에 있는지와
고칠 방향을 적어 두었다.

## 1. 측정 영역과 역량 구조

**열둘이다. 기계공학과 전기전자와 컴퓨터의 수를 맞춘 값이 아니다.**
오는 길은 이렇다.

1. 사업주 후보 열에서 **재무와 회계를 갈랐다**(열하나). 돈이 들어오고
   나갈 것을 추정해 넣을지 판단하는 일과, 이미 일어난 거래를 기준에 맞춰
   기록하고 원가를 배부하는 일은 **보는 것과 남기는 것이 다르다.**
2. **정보시스템·업무 요구**를 세웠다(열둘). IT경영정보학과 갈래의 중심이
   여기다(7절).
3. **수요·예약·가격 관리**를 세웠다(열셋). 관광과 호텔과 항공이 실제로
   내리는 판단이 여기 있다(8절).
4. `개발 환경과 협업` 같은 **일하는 방식은 영역으로 두지 않는다.** 열두
   영역 전부에 걸쳐 있어서 영역으로 두면 같은 자리를 두 번 센다. 들어간
   자리는 축(J4 방법·도구 · J7 실패·수정)과 역할팩이다. 그래서 **열둘에서
   멈췄다.**

| 코드 | 영역 | 필수 축 | 무엇을 보고 무엇을 남기는가 |
|---|---|---|---|
| TD01 | 경영전략·기획 | J2 · J3 | 전사 목표와 자원을 보고 **하지 않을 것**을 정해 사업계획과 지표 표를 남긴다 |
| TD02 | 마케팅·시장 | J3 · J6 | 고객 자료와 지난 반응을 보고 채널 배분을 정해 캠페인 기획서와 성과 비교표를 남긴다 |
| TD03 | 영업·사업개발 | J3 · J5 | 고객 요구와 우리 단가를 보고 가격과 납기를 정해 제안서와 합의 조건을 남긴다 |
| TD04 | 재무·투자 판단 | J4 · J6 | 들어올 돈과 나갈 돈을 보고 가정을 정해 추정 재무제표와 민감도 표를 남긴다 |
| TD05 | 회계·원가 | J5 · J6 | 증빙과 적용 기준을 보고 계정과 기간을 정해 결산 자료와 대조표를 남긴다 |
| TD06 | 인사·조직 | J2 · J3 | 할 일과 인원을 보고 무엇을 볼지 정해 직무 기준과 평가표를 남긴다 |
| TD07 | 운영·프로세스 | J3 · J7 | 할 일과 자원을 보고 순서와 역할을 정해 업무 절차서와 개선 전후 비교를 남긴다 |
| TD08 | 데이터·의사결정 | J4 · J6 | 쌓인 자료와 품질을 보고 지표와 비교 대상을 정해 지표 정의표와 분석 보고를 남긴다 |
| TD09 | 고객·서비스 운영 | J3 · J7 | 요구와 불만 기록을 보고 그 자리에서 해결할 범위를 정해 응대 기준과 품질 측정을 남긴다 |
| TD10 | 수요·예약·가격 관리 | J3 · J6 | 남은 수량과 기간을 보고 언제 얼마에 몇 개를 열지 정해 가격·배정 기준과 예측·실적 비교를 남긴다 |
| TD11 | 글로벌 비즈니스 | J2 · J6 | 상대국 규정과 환율을 보고 적용 규정과 현지화 범위를 정해 수출입 서류와 진입 계획을 남긴다 |
| TD12 | 정보시스템·업무 요구 | J2 · J3 | 업무 흐름과 서식을 보고 사람이 할 일과 시스템이 할 일을 갈라 요구사항 정의서와 도입 전후 비교를 남긴다 |

**영역 기준은 교과목이 아니다.** 각 줄이 `이 영역에서 무엇을 보고, 어떤
판단을 하고, 무엇을 남기는가` 로 적혀 있고, 그 셋이 비어 있으면 영역으로
두지 않았다.

**축 여덟과 척도 둘과 수준 넷은 기계공학 Core 와 같은 값이다.** 같은 자
위에 서야 두 전공의 결과를 견줄 수 있다(전공마다 자를 새로 만들면 같은
학교 안에서 비교가 끊긴다). **역할기능 여덟과 조직환경 일곱도 같은 코드를
쓰고 이름만 경영계열의 말로 적었다**: `설계·개발` 과 `시험·검증` 은 만드는
일의 말이라 기획이나 회계를 하는 학생이 자기 자리를 찾지 못한다. 하는 일의
뜻을 바꾼 것이 아니므로 축이 갈린 것이 아니고, 갈리는 것은 **내놓는
산출물의 종류**다: 도면 자리에 사업계획과 결산 자료와 업무 절차서가 선다.

## 3. 적성검사화 금지 — 구조가 막는다

문서에 적어 두는 것으로는 지켜지지 않는다. 막는 자리가 셋이다.

1. **짝 표가 `PREFERENCE × OWNERSHIP_4` 를 거절한다**
   (`src/lib/me-v3/measurement/registry.ts`). `사람을 좋아한다` 류는
   선호(`PREFERENCE`)이고, 선호 문항에 소유 사다리 넷을 붙이는 길이
   구조적으로 없다. 문항마다 primary construct 를 적어 두므로
   (`biz-v1-constructs.json`) 추론으로 지나갈 수 없다.
2. **문면이 소유가 아니라 행동을 묻는지 센다**(`v3:wording`). 문면은 그
   축의 `l2` 행동까지만 묻고 소유는 보기 넷이 가른다.
3. **선별 등급 응답의 40% 이상이 실제 판단인지 센다**(같은 검사).

그래서 금지 예시 여섯(`사람을 좋아한다` · `리더십이 있다` · `창의적이다` ·
`숫자를 좋아한다` · `외향적이다` · `협업을 좋아한다`)은 이 은행에 **0개**다.
대신 들어간 모양은 이렇다.

- `목표를 지표로 옮기고 그 가운데 하나를 버린 경험이 있다`
- `들어올 돈과 나갈 돈을 추정해 넣을지 말지를 판단한 경험이 있다`
- `고객이나 시장 자료를 보고 채널이나 메시지를 바꾼 경험이 있다`
- `일정과 역할과 자원을 나눠 배분한 경험이 있다`
- `자료를 근거로 내 판단을 설명해 결정에 쓰인 경험이 있다`

**공통 테스트를 한 줄도 고치지 않았다.** 위 셋은 전부 전부터 있던 검사이고
이 Core 의 자료가 그 검사를 지난다.

## 4. 경험 범위 — 학생이 실제로 답할 수 있는 자리

문면의 장면을 **수업 · 팀프로젝트 · 공모전 · 학생회 · 동아리 · 마케팅
활동 · 창업 프로젝트 · 인턴 · 현장실습 · 아르바이트 · 조사·분석 과제 ·
행사 운영**에서 가져왔다. **기업 실무자만 답할 수 있는 문항을 만들지
않는다**: 결재선과 승인 권한과 전사 시스템 운영 경험을 전제하는 문면이
0개이고, 권한과 범위를 묻는 자리는 역할팩에만 둔다(6절).

학위는 **장면만 바꾸고 보기와 척도를 바꾸지 않는다.** 같은 J1 문항이
학부에서는 `수업 과제나 팀 프로젝트에서`, 포닥에서는 `맡은 과제나
제안서에서` 로 선다. 같은 응답이면 학부와 포닥의 Core 판정 지문이 글자까지
같다(`v3:scoring` A).

## 5. 연결된 학과와 갈래 여섯

배재대 경영대학 여섯 학과가 두 Catalog(재학생 · 2027)에 각각 서서
**열두 자리**가 이 Core 를 가리킨다.

| 학과 | 갈래 | 중심 영역 |
|---|---|---|
| 경영학과 | `SPEC_BIZ_GENERAL` | TD01 · TD04 · TD06 |
| IT경영정보학과 | `SPEC_BIZ_MIS` | TD12 · TD08 · TD07 |
| 글로벌비즈니스학과 | `SPEC_BIZ_GLOBAL` | TD11 · TD03 · TD01 |
| 관광경영학과 | `SPEC_BIZ_TOURISM` | TD10 · TD02 · TD09 |
| 호텔항공경영학과 | `SPEC_BIZ_HOTEL_AIR` | TD10 · TD09 · TD07 |
| 항공서비스학과 | `SPEC_BIZ_AIR_SERVICE` | TD09 · TD07 · TD12 |

**갈래는 Core 판정을 바꾸지 않는다.** 조정하는 층은 다섯이다: 영역 강조 ·
산업 연결 · 역할 연결 · 사례와 산출물 · Evidence 와 Gap 과 Action 의 첫
걸음. 축 수준과 묶음 조건과 확인된 축 개수와 등급 경계에는 들어가지 않고,
그것을 `campus:check` 가 채점·결과 모듈 여덟 벌에서 갈래 코드를 세어 막는다.

**아펜젤러공유대학의 경영·비즈 이름을 가진 전공(글로벌경영전공 ·
지역소상공비즈니스전공 · 국제의료관광전공 · 아트컬처비즈니스전공)은 잇지
않았다.** 사업주가 연결 대상으로 적어 준 자리가 경영대학 여섯이고, 그
학부들은 성인학습자와 외국인 유학생을 받는 자리라 계약 범위가 따로 정해질
자리다. **이름이 비슷하다는 까닭만으로 자를 붙이지 않는다.**

## 6. 산업·역할 Pack 연결

**산업팩은 일곱이다.** 사업주 후보 여덟에서 `스타트업` 을 뺐다: 그것이
가리키는 것은 **조직의 크기와 단계**이고, 조직환경 축이 `OC7 스타트업·소규모
팀` 으로 그 자리를 이미 들고 있다. 두 축에서 같은 것을 묻게 되면 고른 산업이 결과를
바꾸지 않는 칸이 하나 생긴다.

| 산업팩 | 그 산업이 요구하는 판단의 예 |
|---|---|
| 일반기업·B2B | 고객사 요구와 우리 단가 사이에서 조건을 정한다 |
| 소비재·유통 | 재고와 회전과 진열을 함께 본다 |
| IT·플랫폼 | 지표를 정의해 기능과 가격을 바꾼다 |
| 금융 | 규정과 위험 한도 안에서 판단한다 |
| 관광·호텔 | 오늘 안 팔리면 사라지는 재고를 값과 배정으로 다룬다 |
| 항공·서비스 | 안전·보안 규정 안에서 정해진 시각을 지킨다 |
| 공공기관 | 예산 집행 근거와 공개 가능성을 함께 본다 |

**경영계열은 기능이 여러 산업에 걸쳐 있어서 산업팩을 억지로 세분화하지
않았다.** 문항마다 그 판단을 일반 경영 말로 바꿔 적은 줄(`gloss`)이 붙어
있어 **용어를 모른다고 부적합으로 적지 않는다.**

**역할팩은 여덟이다**: 경영기획 · 마케팅 · 영업·사업개발 · 인사 ·
재무·회계 · 운영관리 · 데이터·Business Analytics · 서비스·고객운영.

역할팩이 묻는 것은 `무슨 성향인가` 가 아니라 **그 자리에서 가진 권한과
범위와 남기는 Evidence** 다. 그래서 Core 문항을 어미만 바꿔 되묻지 않는다:
`v3:measure` F 가 같은 (영역·축)을 같은 말로 두 번 묻는 자리를 세고, 이번
회차에 실제로 하나 걸렸다(9절 ①).

## 7. IT경영정보 갈래가 CS Core 와 겹치지 않는다

`SPEC_BIZ_MIS` 의 중심은 TD12(정보시스템·업무 요구)와 TD08(데이터·의사결정)
과 TD07(운영·프로세스)이고, 묻는 것은 **정보시스템 활용 · 비즈니스 프로세스
· 자료 기반 의사결정 · 시스템 도입과 운영 · 업무 요구사항 정리**다.

**프로그래밍 능력을 BIZ Core 의 핵심 판정으로 만들지 않았다.** TD12 의
필수 축이 J2(요구사항 해석)와 J3(직접 판단)이고, 구현과 자료구조와 시스템
프로그래밍은 이 Core 의 영역에 0개다. 그쪽은 CS Core 의 TD01~TD06 이 든다.
그래서 IT경영정보학과 학생이 두 Core 를 다 풀어도 같은 자리를 두 번 세지
않는다.

## 8. 관광·호텔·항공 계열은 서비스 성향 검사가 아니다

세 갈래가 가리키는 영역은 TD10(수요·예약·가격) · TD09(고객·서비스 운영) ·
TD07(운영·프로세스)이고, 묻는 것은 실제 판단이다.

- 고객 여정의 어느 단계를 손볼지 정한 경험
- 현장 절차와 점검표를 적어 누가 와도 같게 만든 경험
- 남은 수량과 남은 기간을 보고 값이나 배정을 바꾼 경험
- 약속한 처리 시간과 실제를 대조한 경험
- 규정과 안전 기준 안에서 그 자리에 판단을 내린 경험
- 일정과 인원을 다시 배분한 경험
- 매출과 비용을 함께 본 경험

`친절한 편이다` 와 `사람을 만나는 일이 좋다` 는 0개다(3절의 짝 표가 막는다).

## 9. Evidence · Gap · Career Action

- **Evidence** 는 그 사람이 **실제로 한 판단과 남은 산출물**이다. 응답과
  고른 근거 둘이 함께 서야 소유로 올라간다(`OWNED_EVIDENCE_MIN`).
- **Gap** 은 판단이나 산출물이나 검증이 **비어 있는 자리**이고, 까닭 코드로
  적는다(`MISSING_REQUIRED_AXIS` · `MISSING_OUTPUT` ·
  `MISSING_OUTPUT_EVIDENCE` · `MISSING_VERIFICATION` ·
  `INSUFFICIENT_CONFIRMED_AXES`).
- **Action** 은 **학생이 다음으로 실제 할 수 있는 행동**이고, 재료를 그
  영역의 `verify_targets` 와 `artifacts` 에서 가져온다. 여기서 새 재료를
  지어내지 않는다.

적는 차례는 `chains.ts` 의 `BIZ_CORE_V1` 열두 줄이고 **이 Core 의 업무
흐름에서 뽑았다**: 받는 입력 → 먼저 정하는 것 → 쓰는 방법 → 내놓는 산출물
→ 무엇과 견주는가. 보기:

```
TD05 회계·원가   증빙과 적용할 기준 → 계정과 넣을 기간 → 거래 분류와 원가 배부
                → 결산 자료와 대조표 → 증빙 원본과 기준 대조
TD10 수요·예약   남은 수량과 남은 기간 → 언제 얼마에 몇 개를 열지 → 수요 추정과 값 조정
                → 가격과 배정 기준 → 마감 뒤 판매율 대조
```

실제 엔진이 낸 Evidence·Gap·Action 예시 세 벌은 검토 묶음
(`docs/metri/BIZ_CORE_V1_REVIEW.md`)에 있다. **손으로 적은 예시가 아니다.**

## 10. Provenance

응시 줄과 스냅샷이 여섯을 적는다: `core_code` · `specialization` ·
`item_bank_version`(`BIZ_V1_ITEM_BANK_V1`) · `scoring_version`
(`me-v3-scoring.5`) · `result_model_version`(`me-v3-result-model.6`) ·
`assessment_ui_version`.

**ME · EE · CS · BIZ 가 섞이지 않는 것을 실제 DB 로 봤다**
(`v3:provenance`, 18가지). 네 Core 를 **번갈아** 열어 여덟 줄을 만들고
(`[ME, EE, CS, BIZ, ME, EE, CS, BIZ]`) 줄마다 Core 와 판본의 짝이 맞는지
본다. 같은 Core 를 잇따라 열면 섞이는 것을 볼 수 없다. 닫아 둔 Core 는
학교 맥락이 통째로 버려지는 것이 설계이므로 개방 칸을 잠시 열고 **반드시
되돌린다**: `finally` 가 되돌리고 등록부 지문을 견준다.

## 13. 이번 회차에 걸린 것과 고친 자리

### ① 역할팩이 다른 역할팩과 같은 말로 묻고 있었다 (고쳤다)

`ROLE_MKT_V1_R4` 와 `ROLE_ANALYTICS_V1_R1` 이 둘 다 TD08·J4 에 얹혀
`방법을 골라 그 까닭을 남긴 경험이 있다` 로 읽혔다(닮음 0.67). 그러면
마케팅 역할을 고른 사람이 분석 역할의 문항을 다시 받는 셈이고, 역할팩이
파는 것(**그 자리에서 가진 권한과 범위**)이 사라진다. 마케팅 쪽을
`비교할 기간과 대조 집단을 어떻게 잡을지 정해 측정 틀을 세운 경험` 으로
다시 썼다. EE 회차에서 **스물아홉 문항**을 같은 까닭으로 다시 쓴 적이 있다.

### ② `상위 목표` 가 결과 문장 검사에 걸렸다 (콘텐츠를 고쳤다)

결과지 문장 검사가 `상위 ` 를 막는다. 막으려는 것은 `상위 10%` 같은 **규준
없는 백분위 표현**인데, 경영계열의 `상위 목표`(윗단계 목표)가 그 모양에
걸렸다. **공통 검사를 고치지 않았다**: 그 규칙은 규준이 없는 동안 반드시
서 있어야 하는 줄이고, 한 Core 의 사정으로 느슨하게 하면 다음 Core 가 그
느슨해진 줄을 물려받는다. 콘텐츠를 `전사 목표` 로 고쳤다(영역 자료 3자리).

### ③ 사람 열두 벌의 기대값 넷을 바로잡았다

- **P04 `전부 최고로 답한 사람` 이 격자를 가운데 값으로 답하고 있었다.**
  적지 않은 열 영역의 기본값과 같아져 격자가 한 값이 되고, 그러면 과대 보고
  어긋남 대신 `고르게 답함` 으로 적힌다. 최고로 답하게 고쳤다.
- **P06 TD03 의 까닭이 하나가 아니다.** 이 Core 에서 TD03 의 필수 축이
  `J3`·`J5` 라 산출물을 비우면 필수 축도 함께 빈다. 기대값을 둘로 적었고,
  **산출물만 빈 자리**는 P11 의 TD08(필수 축 `J4`·`J6`)이 든다.
- **P08 TD02 는 필수 축만 비운다.** 검증까지 비우면 까닭이 둘이 되어
  `필수 축이 빈 자리` 를 가리키는 읽기가 흐려진다.
- **P08 TD12 가 `근거가 섰고 비교·검증만 남았다` 를 든다.** 산출물 근거를
  채우니 나머지가 다 서고 검증만 비는 자리가 되는데, **그 자리를 드는 벌이
  어느 Core 에도 없었다**(`zones.ts` 의 `rest` 가지가 한 번도 돌지 않았다).
  EE 회차에서 `D_LOW_LOW` 칸이 비어 있던 것과 같은 종류의 구멍이다.

### ④ 관심만 올리는 변형(E)이 짚을 자리가 없었다

그 변형은 `관심만` 올려야 하는데, 짚던 영역의 경험이 0 이어서 관심을 올리면
**둘째 선별 문항이 함께 열려** 축 상태까지 갈렸다. P11 에 경험 1 · 관심 낮음
인 영역(TD04)을 세워 그 자리를 가리키게 했다. ME 와 EE 의 같은 변형도 경험
1 인 영역을 짚고 있다.

## 14. 고치지 않고 적어 두는 것

### ⓐ 결과지 작성 차례가 아직 `content/` 밖에 있다

`src/lib/me-v3/result/chains.ts` 는 Core 를 열쇠로 둔 자료 표인데 파일이
`src/` 에 있다. 그래서 Core 를 하나 더 만드는 일이 TypeScript 파일 한 벌을
남긴다. 고칠 방향은 그 줄을 `<prefix>-domains.json` 의 영역마다 한 줄로
옮기는 것이고, **이번에도 하지 않았다**: 결과 층이 읽는 자리를 바꾸는 일이라
ME·EE·CS 의 차례를 옮기면서 글자가 한 자라도 달라지면 이미 응시한 사람의
결과지가 바뀐다. **이 파일은 어느 동결 목록에도 없다.** 지키는 것은
`v3:provenance` 의 두 줄이다(`Core 마다 영역 전부에 적는 차례가 있다` ·
`두 Core 가 같은 차례를 돌려 쓰지 않는다`).

### ⓑ 이용권이 Core 를 가리키지 않는다

`entitlements` 에 Core 칸이 없어서 한 사람이 여러 Core 를 풀 때 어느
이용권으로 어느 Core 를 열었는지 줄에 남지 않는다. EE 회차부터 적어 둔
자리이고 **DB 스키마를 바꾸는 일**이라 승인 대기다.

### ⓒ `recompute.ts:377`

`errors:check` 가 집는 자리이고 현재 상태 계산 경로다. 재분석 동작을
건드리는 일이라 그대로 둔다(굳은 결과와 채점에 닿지 않는다).

### ⓓ `v3:migrate` 는 이 Core 에 돌지 않는다

그 검사가 세는 것은 ME_V3 V1 은행에서 V2 로 온 길이다. 새 Core 에는 옛
은행이 없다.

## 15. 개방 가능 여부

**학생에게 열지 않았다.** `status: building` · `maturity:
READY_FOR_DOMAIN_REVIEW` · `open_to_students: false` 다. 자료와 자동 검사는
끝났고 남은 것은 **그 전공 전문가가 읽는 일**이다. 검토 묶음이
`docs/metri/BIZ_CORE_V1_REVIEW.md` 와 같은 이름의 `.csv` 이고, 그 판정이
돌아오기 전에는 개방 칸을 올리지 않는다.

### 아직 하지 않은 검증

- 전공자 검토(문항 359개가 현장 말인지, 보기 둘·셋·넷이 실제로 갈리는지)
- 인지 면접
- 실제 응답 기반 신뢰도·타당도 검증

그래서 **`검증된 검사` 로 팔지 않고** 규준도 백분위도 적합도 비율도 내지
않는다.

### 운영

DB 스키마를 한 줄도 바꾸지 않았으므로 마이그레이션은 필요 없다. 바뀐 것이
전부 이미지 안으로 들어가는 파일이라 **재배포가 먼저다.** 네트워크 정책이
`app.careermatri.com:443` 을 막아 **운영 배포본을 밖에서 열지 못했다**:
위의 결과는 전부 이 기계에서 운영과 같은 배치로 띄워 돌린 것이다.
