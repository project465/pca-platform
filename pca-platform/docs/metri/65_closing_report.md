# CareerMatri ME_V3_2 마감 · 보고 A–W

이 회차의 기준은 "검사가 돈다" 가 아니다. **검사를 끝낸 사람이 내
CareerMatri에 들어가 Evidence와 Gap을 보고, 경험을 추가하고, 산업·직무·지역을
다시 보고, Track으로 이어 갈 수 있는 구조가 실제 화면으로 보이는가**다.

판본은 이렇다.

| 무엇 | 판본 |
|---|---|
| 검사 | `ME_V3_2` |
| 문항 은행 | `ME_V3_ITEM_BANK_V2.3` |
| 판단 규칙 | `me-v3-scoring.5` |
| 검사 화면 | `ME_V3_2_ASSESSMENT_UI_V2` · 문장 `me-v3-2-assessment-copy.4` |
| 결과지 | `ME_V3_RESULT_UI_V3` · 문장 `me-v3-result-copy.4` · 모델 `me-v3-result-model.4` |

## A. 전체 CareerMatri 구조

```
기본정보 → Major Core → BASIC → 기술영역 심화 → Industry → Role → Region
→ Evidence / Gap → Career Action → 결과 저장
→ 새로운 경험 추가 → 재분석 → CareerMatri Track
```

쪽으로 옮기면 이렇다.

| 걸음 | 쪽 | 지금 상태 |
|---|---|---|
| 전공 Core 고르기 | `/cores` | 기계공학만 열림 · 아홉은 등록만 |
| 검사 | `/v3/start` → `/v3/{id}` | 실제 응시 |
| 결과 | `/v3/{id}/result` | 아홉 절 |
| 종이 | `/v3/{id}/result/pdf` | 같은 모델을 읽는다 |
| 내 CareerMatri | `/me` | 카드 여덟 |
| 경험 | `/me/experience` · `/me/experience/new` | 일곱 칸을 받는다 |
| 재분석 | `/me/recompute` | 미리 보고 반영한다 |
| 탐색 | `/me/explore` · `/me/region` | 산업 · 직무 · 권역 · 기관 유형 |
| 공고 | `/me/jobs` · `/me/apply` | 계약만 · 지원 기록은 실제 |
| Track | `/me/track` | 아홉 기능 · 결제 없음 |

**검사는 끝이 아니라 시작이다.** 결과지 끝에 갈 자리가 여섯이고 그 가운데
다섯이 플랫폼 안쪽이다.

## B. 검사 최종 flow

```
기본 정보(학업 단계 · 대학원 계열 · 학부 전공)
→ 관심 산업 둘 고르기 → 산업 장면 읽기
→ 영역 훑기 두 화면(열두 영역 × 관심 · 경험 · 배울 뜻)
→ 공통 판단 여섯 → 학위 묶음 여섯 → 선별 네 축
→ (STANDARD+) 심화 여덟 축 → 근거 고르기
→ 관심 직무 · 선호 조직 → 역할 판단 → 산업 판단
→ (PRO) 경험 번역 열 단계 → 목표 → 완료
```

**무엇을 묻지 않는지가 adaptive 다.** 배울 뜻은 선별된 영역에만, 선별 축의
둘째 문항은 STANDARD 부터, 해 본 적이 없다고 답한 영역에서는 둘째를 묻지
않고, 일관성은 덜 확인된 축의 한 짝만 본다.

## C. 학위별 차이

학위 묶음이 넷이고 **같은 보기 넷을 쓰며 가중치가 없다.** 포닥이 박사보다
저절로 높게 나오지 않는다(`v3:length` 가 네 묶음이 다른지 센다).

| 학위 | 묻는 자리 | 결과에서 읽히는 곳 |
|---|---|---|
| 학부 | 범위 · 조건 · 산출물 · 대조 · 수정 · 쓰임 (수업 · 캡스톤 · 실험 · 동아리 · 인턴) | 영역을 가리지 않고 확인된 판단 |
| 석사 | 연구 문제 · 측정 조건 · 실험/해석 조건 · 재현 가능한 기록 · 다른 방법과 대조 · 산업 말로 옮기기 | 같은 자리 + 번역 절 |
| 박사 | 문제 자르기 · 가정이 깨지는 조건 · 방법 선택의 까닭 · 변수 · 불확실성 · 한계 | 같은 자리 |
| 포닥 | 책임 범위 · 과제 운영 · 독립 판단 · 받아 이어 붙이기 · 성과 전환 · 바깥 기관에 쓰임 | 같은 자리 |

**연구 주제의 난이도를 평가하지 않는다.** 묻는 것은 그 자리에서 무엇을
직접 정했는가다.

**학부 전공을 대학원생 전부에게 묻는다.** 학부가 기계공학이고 대학원이
타계열인 분은 받고, 대학원 경험은 축 수준에 넣지 않고 번역 맥락으로만 다룬다.

그 까닭은 아래 영역 절이 한 자리에서 말한다. 첫 화면의 자리는 **비어 있는
것**에 내줬다.

## F. Industry 결과 연결

전에는 산업 문항 여든의 응답을 받아 두고 **어느 코드도 읽지 않았다.**
결과지가 산업 이름만 돌려주고 답한 내용은 한 글자도 돌려주지 않았다.

지금 산업 절이 적는 것은 다섯이다.

1. **기술영역과 그 산업 양쪽에서 확인된 경험**: 한 경험을 두 쪽 언어로
   설명할 수 있는 자리라 지원서에서 가장 먼저 쓴다
2. 기술영역 결과에서 확인된 경험
3. **그 산업 문항에서 확인된 판단**
4. **그 산업 문항에서 `없다` 로 답한 판단**: 안 물어본 것과 가른다
5. 여기서 한 번 더 확인하는 경험 → 그리고 **다음에 만들 근거** 한 줄

**Core 판정은 바뀌지 않는다.** 산업을 바꿔 가며 Core 지문을 대조하는 검사가
그대로 통과한다(`v3:result`).

## G. Role 결과 연결

같은 다섯에 **관련된 기술영역**이 더 선다. 산업 절과 직무 절은 같은 함수를
쓴다(`PackBody`): 두 벌을 따로 들고 있으면 한쪽에 줄을 더할 때 다른 쪽이
조용히 뒤처진다.

그리고 **역할팩이 Core 문항을 베끼고 있던 것을 고쳤다.** 어미만 `적이` 에서
`경험이` 로 바꾼 자리가 있었다(`구속 조건과 하중 작용점을 직접 정해 본`).
역할팩이 묻는 것은 기술 판단이 아니라 **그 자리에서 가진 권한과 범위**이므로
스물아홉 문항을 다시 썼다.

| 직무 | 지금 묻는 것 |
|---|---|
| 설계 | 요구가 부딪힐 때 어느 쪽을 깎을지 결론 내고 설명했는가 |
| 해석·예측 | 해석 조건을 정하고 설계자와 합의했는가 · 어디부터 시험으로 넘길지 그었는가 |
| 시험·검증 | 무엇을 재고 무엇은 재지 않을지 정했는가 · 내 이름으로 판정했는가 |
| 생산기술 | 양산에 올릴 조건을 확정해 넘겼는가 · 라인을 세울지 판단했는가 |
| 설비·보전 | 언제 세우고 언제까지 두고 볼지 기준을 세웠는가 |
| 품질·신뢰성 | 출하를 막을 권한을 가지고 판단했는가 |
| 기술기획·과제관리 | 무엇을 이번에 하고 무엇은 미룰지 · 책임이 비는 자리를 찾았는가 |

## H. Evidence / Gap

**근거는 점수를 매기지 않고 확인된 판단 축으로 센다.** 묶음 다섯이고 `아직 근거가 덜
섰다` 와 `판단할 근거가 부족하다` 를 섞지 않는다. 많이 해 봤는데 남은 것이
없는 사람과 아직 아무 경험이 없는 사람은 다음 걸음이 다르다.

Gap 은 셋을 한 묶음으로 적는다: 무엇이 비었는가 · 왜 그 자리가 필요한가 ·
다음에 무엇을 하면 메워지는가. 할 일의 재료는 **그 영역의 자료**에서 온다.

## I. Action

세 층이다: **지금 할 것**(오늘 앉아서 시작할 수 있다) · **다음 과제에서**
(맡는 일이 생겨야 한다) · **나중에 볼 것**. 날수를 그대로 보여 주지 않는
까닭은 그 값이 마감을 뜻하지 않고 **할 수 있는 때**를 뜻하기 때문이다.

## J. Region

Core scoring 에 들어가지 않는다. 권역 다섯 · 기관 유형 일곱 · 이동 범위 넷.

**이름 겹침을 끊었다.** Core 의 조직환경(`OC1~OC7`, 그 일을 하는 자리의
성격)과 지역 층의 기관 유형(`ORG_*`, 그 자리를 가진 기관의 종류)이 같은
코드를 쓰고 다른 뜻이었다. 칸도 나눴다(`target_org_context` / `target_org`).

기관 유형은 **대기업 · 중견기업 · 중소기업 · 스타트업 · 출연연 · 공공기관 ·
대학** 일곱이다. 결과지 8절과 `/me/region` 이 **산업 × 직무 × 권역 × 기관
유형** 넷을 한 자리에 세우고, 그 넷이 `org_registry` 의 열쇠다.

**기업 자료는 한 줄도 없다.** 기관 수를 짐작으로 채우지 않는다.

## K. Dashboard

카드 여덟: 현재 방향 · 기술 Evidence · 먼저 채울 것(가장 급한 셋을 **문장**
으로) · 다음에 할 일(세 층) · 최근 움직임 · 내가 적은 경험 · 저장한 공고
(0개면 0개로) · Track.

## L. Experience update

갈래 아홉(수업 · 과제 · 캡스톤 · 연구 · 논문 · 인턴 · 프로젝트 · 직장 ·
자격)과 칸 일곱을 받는다.

| 받는 것 | 어디서 오는가 | 어느 축으로 가는가 |
|---|---|---|
| 어떤 문제였나 | 그 영역의 J1 체크리스트 | J1 |
| 무엇을 직접 정했나 | 그 영역의 J3 체크리스트 | J3 |
| 무엇이 남았나 | 그 영역의 산출물 | J5 |
| 무엇과 견주어 확인했나 | 그 영역의 검증 대상 | J6 |
| 어디에 쓰였나 | 고정 메뉴 여덟 | J8 |

**`직접 정한 것` 이 표에도 저장 함수에도 있는데 고르는 자리가 없었다.**
모든 경험이 그 칸을 빈 채로 쌓였고, 지원서에서 읽히는 자리가 거기다.

## M. 재분석: 어디까지 실제인가

**실제로 돈다.** `npm run v3:recompute` 가 일곱 가지를 센다.

```
저장한 경험 → (영역 · 축) 후보 → 굳은 결과와 대조 → 묶음 다시 판정
→ 비어 있는 자리 다시 계산 → 할 일 손질 → 지금 값 저장
```

| 묻는 것 | 결과 |
|---|---|
| 적은 경험이 판단축 후보로 묶이는가 | 후보 10칸 · 올라가는 축 5개 |
| 근거가 둘이면 확인까지 올라가는가 | 올라간다 |
| **경험만으로 `직접 결정` 이 서는가** | 서지 않는다 — 보기 넷은 검사에서만 |
| 이미 더 높이 선 축을 내리는가 | 내리지 않는다 |
| 지금 값에 적히는가 | 축 수준 · 묶음 · 빈자리 |
| **굳은 결과가 바뀌는가** | 한 글자도 바뀌지 않는다 |
| 두 번 돌려도 같은가 | 같다 |

**사람이 누를 때만 돈다.** 저장하는 순간 자동으로 돌리지 않는 까닭은 둘이다.
계산이 깨진 날 저장까지 막히지 않게 하려는 것이 하나이고, 무엇이 달라지는지
먼저 보고 누르게 하려는 것이 둘이다. `/me/recompute` 가 어느 경험이 어느
판단으로 가는지를 줄로 적는다.

**아직 아닌 것**: 사람이 누르지 않으면 돌지 않는다(밤 당번에 붙이지 않았다).

## N. CareerMatri Track

아홉 기능이고 **결제는 붙이지 않았다.**

| 기능 | 지금 |
|---|---|
| 새 채용공고 추적 | 공고 자료 검토 전 |
| 산업별 요구역량 변화 | 표본과 근거 등급 필요 |
| 내 근거와 공고 자동 비교 | 공고 자료 검토 전 |
| Gap 변화 추적 | 자동 재분석 전 |
| 월간 Career Report | 메일 연결 전 |
| 목표를 바꾸면 다시 분석 | 자동 재분석 전 |
| **관심 산업·직무 바꾸기** | **지금 됩니다** (`/me/explore`) |
| **지원한 곳 관리** | **직접 적는 데까지** (`/me/apply`) |
| 지원 직무별로 모아 보기 | 지원 기록이 쌓인 뒤 |

**지금 되는 것을 `준비 중` 으로 적지 않는다.**

## O. Job architecture

```
수집 → 산업 분류 → 직무 분류 → 요구역량 정리 → TD · RF → 내 근거와 비교
→ Gap → Action
```

표 셋이 계약을 들고 있다: `v3_job_postings`(출처와 사상 등급까지) ·
`v3_saved_jobs` · **`v3_applications`**(새로 섰다). 지원 기록을 공고에 외래
키로 걸지 않은 까닭은, 공고가 들어오기 전까지 그 표가 영원히 비기 때문이다.

**알선하지 않는다.** 이력서 발송 대행과 취업추천서는 직업정보제공사업으로
할 수 없다. 지원은 본인이 하고 여기에는 그 사실만 적는다.

## P. Major Core 확장성

`npm run v3:extend` 가 전기전자(영역 여섯)와 경영학(영역 다섯) core 를
데이터로만 만들어 1~4단계 검사를 **코드 한 줄 안 고치고** 돌린다. 열넷 통과.

**플랫폼 층은 아직 기계공학 하나에 묶여 있다.** `platform.ts` 와
`recompute.ts` 가 `ME_CORE_V3` 을 상수로 들고 있다. 검사와 채점은 core 를
모르지만 내 CareerMatri 는 아직 모른다. 둘째 core 를 실제로 열 때 할 일이다.

## Q. PDF

**웹과 같은 결과 모델을 읽는다.** 따로 그리지 않고 결과 쪽을 인쇄 매체로
열어 접는다. 그래서 둘의 판단이 갈릴 수 없다. 아홉 절이 그대로 들어가고
10쪽이다.

고친 것 셋.

- **첫 쪽이 머리글 두 줄만 남긴 채 비어 뽑혔다.** 영역 패널에 걸린
  `break-inside: avoid` 가 한 쪽에 안 들어가는 상자를 통째로 다음 쪽으로
  밀고 있었다
- **공개 전 띠가 종이에 찍혔다**
- **`결과 PDF 저장` 을 `Link` 로 걸어 두었더니 아래까지 내려 읽기만 해도
  종이가 한 벌씩 만들어졌다.** Next 가 화면에 들어온 `Link` 를 미리 불러오는데,
  그 길은 머리 없는 브라우저를 띄우는 자리다. 평범한 `a` 로 바꿨다

내려받는 자리는 결과 첫 화면과 `이 다음에` 두 곳이다. `npm run v3:shots` 가
종이를 받아 쪽을 그림으로 뜨고 **빈 쪽과 내부 코드를 센다.**

## R. DB migration

운영에서 `column "undergrad_core" does not exist` 가 났다. 스키마 파일에는
그 칸을 더하는 `ALTER` 가 있었고, **저장소 안의 어느 검사도 옛 DB 에서
올려 보지 않았다.** 개발 DB 는 칸이 생길 때마다 손으로 올려 와서 늘 최신이고,
그래서 빠진 것이 보이지 않는다.

`npm run db:migration` 이 여섯 가지를 센다.

| 묻는 것 | 결과 |
|---|---|
| 옛 DB(ME_V3_2 직전 판본)에서 `db:upgrade` 가 **두 번** 도는가 | 두 번 다 끝까지 |
| 올린 DB 에 새로 세운 DB 의 칸이 전부 있는가 | 1,002칸 (옛 DB 는 761칸으로 시작) |
| 막는 것(PK·FK·UNIQUE·CHECK)이 전부 있는가 | 484개 |
| 인덱스가 전부 있는가 | 255개 |
| **코드가 부르는 칸이 전부 서 있는가** | 표 85곳 · 칸 508개 |
| 올린 DB 에서 ME_V3 응시가 끝까지 도는가 | `v3:runtime` 28가지 |

만들면서 둘을 배웠다. **`IN` 에 낱말 경계를 안 붙이면** `straightline_run`
한가운데의 `in` 이 연산자로 잡혀 칸 이름이 `straightl` 로 잘린다(멀쩡한 칸
스물한 개가 그렇게 걸렸다). 그리고 **표가 하나뿐인 SQL 에서는 앞에 안 붙인
이름도 그 표의 칸이다**: `career_events` 에 없는 `processed_at` 을 쓰는 줄이
그 규칙이 없어서 이 검사를 그대로 지나갔고, 화면에서 500 이 나고서야 보였다.

이번에 더해진 칸과 표: `career_profiles.target_org_context` ·
`v3_experiences.problems` · `.used_where` · `org_registry.org_type_code` ·
`.role_code` · `v3_applications`(새 표) · `v3_track_interest` 갈래 아홉.
전부 `IF NOT EXISTS` 와 `DROP CONSTRAINT IF EXISTS` 로 짜여 여러 번 돌아간다.

## S. Production smoke

`npm run v3:smoke` 가 배포본에서 열일곱 자리를 연다. **저장소 코드를 보지
않고 거기서 도는지를 묻는다.**

```
/api/health · /cores · /v3/start · /pricing · /sample
/me · /me/experience · /me/experience/new · /me/recompute · /me/gap
/me/explore · /me/region · /me/jobs · /me/apply · /me/track · /my/assessments
```

이 기계의 공개 전 배포본에서 **열일곱 자리 전부 200 · 500 없음**.
로그인 열쇠를 안 주면 뒤쪽 열한 자리는 `못 봄` 으로 적는다: **못 본 것을
초록으로 적지 않는다.**

## T. 사용자 노출 copy QA

`npm run v3:copy` 가 파일 21벌 · 화면 글 160줄 · 규칙 24가지를 센다.
이번에 더한 틀 다섯: `연결됩니다` · `확인됐습니다` · `반영됩니다` ·
`바탕으로` · `제시합니다`. 거기서 다섯 자리가 걸려 고쳤다.

`npm run copy:audit`(대시 · `A가 아니라 B` · 토막 문단)과
`npm run v3:result:copy`(조사 · 되풀이 · 내부 코드) 도 전부 통과.

**판정 개념은 그대로 두고 문장만 사람이 쓴 말로 간다.**

## U. 사업주 테스트 방법

`docs/metri/66_owner_test.md` 에 따로 적었다. 요지는 이렇다.

- **시작 URL**: 배포본 주소 + `/cores`
- **로그인**: 운영자가 `npm run make:admin` 으로 만든 계정. 개발 DB 의
  시드 계정은 `scripts/db-init.sh` 가 만들지 않는다
- **등급**: BASIC 은 가격표에서 무료로 열리고, STANDARD·PRO 는 파일럿
  초대가 그 등급 이용권을 한 줄 준다(`/admin/v3-pilot`)
- **새 응시**: `/v3/start`. **기존 응시 초기화**는 `/my/assessments` 에서
  그 응시를 버리고 새로 연다
- **대시보드** `/me` · **운영** `/admin` · **파일럿** `/admin/v3-pilot`

**실제 비밀번호는 적지 않는다.**
