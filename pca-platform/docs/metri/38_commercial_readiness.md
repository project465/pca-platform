# 상용화 준비 — 끝낸 것과 막힌 것

Phase 2.1 의 8~18번 결과다. **섞지 않는 것이 이 문서의 요지다.**

```
[됨]      우리가 끝낼 수 있고 끝낸 것. 깨지면 실패다
[블로커]  우리 밖에서 정해져야 하는 것. 실패로 세지 않고 적는다
```

섞으면 검사가 늘 빨간불이어서 아무도 보지 않게 되고, 그러면 진짜 회귀가
그 빨간불에 섞여 든다. 가격과 PG 가 정해지지 않은 것은 코드의 잘못이
아니고, 코드가 **그 상태를 정확히 말하고 있는가**가 코드의 일이다.

```bash
npm run commercial:check    # 끝낸 것 69가지 · 막힌 것 4가지
```

운영 화면 `/admin/readiness` 가 **같은 함수**를 부른다
(`src/lib/commercial.ts`). 두 곳에서 따로 세면 숫자가 갈리고, 갈리는
순간 둘 다 못 믿는다.

---

## 1. 0원이 두 가지를 말하고 있었다

표에서 둘이 똑같이 생겼다.

```
HS_FREE · UNIV_FREE   금액 0 = 진짜 무료 구간
ME_V2_* 여섯          금액 0 = 값을 아직 못 정했다
```

그런데 `sellable()` 이 '0원이면 운영에서 팔지 않는다' 로 막고 있었다.
**법이 요구하는 무료 구간까지 닫힌다.** 전자상거래법 제17조 제6항은
제공 개시 후 철회를 제한하려면 ① 불가 사실 표시와 ② 시험 사용 제공을
둘 다 하라고 하고, 무료 구간이 그 ②다. 닫히면 유료 상품의 환불 거절이
무효가 된다.

뜻을 칸으로 꺼냈다(`products.price_status`). 상태가 셋이고
`catalog.priceState()` 한 함수가 정한다.

| 상태 | 뜻 | 화면 |
|---|---|---|
| `PRICE_APPROVED` | 값이 정해진 유료 상품 | 금액 |
| `FREE` | 승인된 0원. **닫으면 안 된다** | '무료' |
| `PRICE_NOT_APPROVED` | 아직 못 정했다 | '값이 아직 승인되지 않았습니다' |

**승인되지 않은 가격은 금액이 0 이어야 한다**를 DB 제약으로 걸었다.
숫자를 적어 두고 상태만 '미승인' 으로 두면, 승인 안 된 값이 화면에
찍히다가 어느 날 그대로 결제된다.

**모르면 덜 준다.** 칸이 없는 옛 상품은 금액으로 읽되, 0 인데 상태가
비어 있으면 승인된 무료로 보지 않고 미승인으로 본다.

## 2. 금액만 보고 통화를 안 보고 있었다

`settlePayment` 이 승인 금액만 주문과 견주고 통화를 안 봤다.

```
USD 29  →  KRW 29 주문을 확정시킨다
```

숫자가 같아서 금액 대조를 그대로 통과한다. **한 시장만 열어 두었을 때는
드러나지 않는 자리이고, 글로벌 시장을 여는 순간 열린다.**

대조를 `src/lib/payments/verify.ts` **한 곳**에 뒀다. 어댑터의
`verifyPayment` 와 주문 확정이 둘 다 그 함수를 부른다. 두 곳에 적으면
한쪽이 느슨해지고, 느슨해진 쪽이 확정 경로면 돈이 통과한다. 승인 통화를
적어 둘 칸도 없었다(`payments.currency` 추가).

옛 결제 줄에는 통화 칸이 없다. **그것을 불일치로 보면 이미 확정된
주문을 되돌리게 되므로**, 한쪽이 비면 금액으로만 본다.

## 3. 어댑터가 다섯 가지를 한다

규격이 이름을 다섯으로 적어 두었고 두 어댑터(`mock` · `portone`)가 그
다섯을 다 가진다.

| 이름 | 하는 일 |
|---|---|
| `createCheckout` | 결제창에 넘길 값. **비밀키는 들어가지 않는다** |
| `getPaymentStatus` | PG 에 직접 물어본다. 리다이렉트 값은 믿지 않는다 |
| `verifyPayment` | 이 결제가 **이 주문**의 금액과 통화로 승인됐는가 |
| `handleWebhook` | 서명을 검증하고 어떤 결제인지만 알려준다 |
| `refundPayment` | 환불 집행. **얼마를 돌려줄지는 정하지 않는다** |

**상태 조회와 검증을 한 함수로 합치지 않는다.** 조회는 지금 상태를 묻고,
검증은 금액·통화까지 묻는다. 합치면 부르는 쪽이 금액 대조를 잊어도
통과한다.

**환불 금액은 어댑터가 정하지 않는다.** 그 판단은 `src/lib/refund.ts` 의
`refundable()` 한 곳이고 어댑터는 집행만 한다. 둘을 합치면 환불선이 두
곳에서 정해진다. 가짜 어댑터는 돈을 움직이지 않으므로 **집행했다고 적지
않는다**: 적으면 검사가 환불을 통과시키고, 운영에서 돈이 안 돌아간 것을
아무도 모른다.

## 4. 시장마다 누가 받는지를 **값으로** 돌려준다

`marketReadiness('GLOBAL')` 이 `{ ready, blocker, provider }` 를 돌려준다.
해외 PG 가 아직 정해지지 않았는데 주석으로만 적어 두면 화면이 결제
버튼을 그리고 누른 사람이 예외를 만난다. **상용화를 막는 항목은 코드가
말해야 검사가 센다.**

국내 PG 의 일반 카드결제로는 해외 발급 Visa·Mastercard 가 승인되지
않는다. 그래서 채널이 둘이고, 해외 쪽 값이 비어 있으면 **닫혀 있는 것이
맞다.**

## 5. 멱등과 감사

- 같은 결제를 두 번 적을 수 없다: `payments` 의 `UNIQUE(provider, provider_payment_id)`
- 같은 웹훅을 두 번 쌓지 않는다: `payment_events` 의 `UNIQUE(provider, event_id)`
- **결제 이벤트를 고치거나 지울 수 없다.** 트리거가 막는다.
  감사 자료는 고칠 수 있으면 감사 자료가 아니다
- 서명이 틀린 요청도 남긴다. 공격을 받고 있는지 나중에 알아야 한다
- 웹훅은 서명과 **타임스탬프**를 본다(5분). 재전송을 받으면 같은 결제가
  다시 확정 경로로 들어간다
- 주문 상태를 제약으로 못 박았다. 글자였고 제약이 없어서 오타 하나가
  들어가면 그 주문이 어느 조회에도 걸리지 않았다

## 6. 동의

`consent_documents`(종류·판·언어·유효시점·번역 상태)와
`consent_records`(사람·판·사이트·시각·철회).

- **판까지 본다.** 약관을 v1.1 로 올리면 v1.0 에 동의한 사람은 다시
  받아야 한다. 종류만 보면 고친 약관에 동의 없이 서비스가 계속된다
- **막는 것은 서버다.** 체크박스의 `required` 는 안내이고, 개발자 도구로
  지울 수 있는 것은 막는 것이 아니다. 필수가 빠지면 가입을 되돌린다
- **가입과 같은 요청에서 적는다.** 다음 화면에서 받으면 그 사이에 창을
  닫은 사람이 동의 없이 계정을 가진 상태로 남는다
- **지우지 않고 철회 시각을 적는다.** 필수 동의는 철회로 끄지 않는다:
  그건 탈퇴이고 `erasure.ts` 가 한다
- **IP 와 User-Agent 를 담지 않는다.** 분쟁에 쓰이는 것은 '어느 판에
  동의했는가' 이고, 그 둘은 그 질문에 답하지 않으면서 파기 대상만 늘린다

## 7. 거래 메일

언어를 **쌓을 때 적는다**(`outbox.locale`). 보낼 때는 그 사람이 화면에
없어서 고를 수 없고, 그 자리에서 짐작하면 영어로 결제한 사람에게 한국어
메일이 간다. 결과지 알림은 **그 응시를 본 언어**로, 가입 인사는 **가입한
화면의 언어**로 간다.

**운영 경보는 두 언어로 두지 않는다.** 받는 사람이 우리 쪽 운영자다.

## 8. 도메인 철자

규격은 `careermatri`, 저장소는 `careermetri` 를 쓰고 있었다. 플랫폼의
`site_configs` 만 규격 철자였고 소개 사이트 원고 네 벌과 정적 페이지는
옛 철자였다. **소개 사이트의 '시작하기' 가 플랫폼이 아닌 주소를
가리키고 있었다.** 저장소 전체를 규격 철자로 맞췄다(52줄).

`npm run domains:audit` 이 두 철자가 같이 사는 것과, 허용 목록 밖에
도메인이 박히는 것을 막는다. 자세한 것과 **남은 결정**은
`docs/metri/41_domain_spelling.md`.

## 9. 막힌 것 (우리 밖에서 정해진다)

| 무엇 | 왜 | 누가 정하는가 |
|---|---|---|
| 가격 승인 | ME_V2 여섯 상품의 값이 정해지지 않았다. **지어내지 않았다** | 사업 결정 |
| 영문 약관 | 구조는 다 되어 있고 본문만 넣으면 된다. 기계로 옮겨 올리면 그걸 읽고 동의한 사람이 생긴다 | 법률 검토·번역 |
| 도메인 소유 | 아직 사지 않았다. 규격 철자의 `.com` 에 이미 남의 서버가 응답한다 | 도메인 구매 |
| 사업자 정보 | 전자상거래법 제10조 표시가 비어 있다 | 사업자 등록 |

운영 결제를 켜면(`PAYMENTS_PROVIDER=portone`) 다섯째가 붙는다:
해외 결제 채널이 비어 있다는 것. 지금은 개발 설정이라 그 줄이 뜨지 않는다.

**'TODO' 로 적지 않는 것이 일부러다.** TODO 는 개발이 할 일로 읽히고,
그러면 아무도 결정하지 않는다.
