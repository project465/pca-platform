# 09. QA — 열기 전에 세는 것

`status` 를 `building` 으로 올리기 전에 전부 통과해야 한다. **등록만 된
상태로 열지 않는다.**

## 자료가 섰는가

| | 세는 것 | 명령 |
|---|---|---|
| 1 | 등록부 계약과 파일 넷 | `npm run v3:majors` |
| 2 | 영역·역할·조직·경계·별칭 | `CORE=XX npm run v3:domains` |
| 3 | 문항 자리와 응답 수 | `CORE=XX npm run v3:items` |
| 4 | 체크리스트 칸마다 둘 이상 | `CORE=XX npm run v3:domains` |
| 5 | 베낀 문장이 없는가 | `npm run v3:wording` |
| 6 | 엔진을 고치지 않고 더해지는가 | `npm run v3:extend` |
| 7 | Kit 이 실제 구조와 같은가 | `npm run major:kit` |

## 실제로 도는가

| | 세는 것 | 명령 |
|---|---|---|
| 8 | 화면이 문항을 빠짐없이 세우는가 | `npm run v3:ui` |
| 9 | 끝까지 응시되는가 | `npm run v3:runtime` |
| 10 | 판정이 규칙대로인가 | `npm run v3:scoring` · `npm run v3:persona` |
| 11 | 결과 모델이 스냅샷과 같은가 | `npm run v3:result` |
| 12 | 경험이 지금 값에 들어가는가 | `npm run v3:recompute` |
| 13 | 한 사람이 이어서 끝까지 가는가 | `npm run v3:launch` |

## 다른 전공을 깨지 않았는가

전공을 더했는데 **기존 전공의 결과가 달라지면 FAIL** 이다.

```bash
npm run v3:freeze:measure   # 기록을 다시 적지 않은 채로 통과해야 한다
npm run v3:scoring          # 사람 열두 벌 지문
npm run v3:result
```

## GAP 보고

공통 판단축 여덟으로 표현할 수 없는 영역을 만나면 **축을 임의로 늘리지
않는다.** 아래를 적어 사업주에게 올린다.

- 어느 영역의 어떤 판단인가
- 여덟 축 가운데 어디에 넣어 봤고 왜 맞지 않는가
- 그 판단이 빠지면 결과에서 무엇이 사라지는가
- 그 전공에서 그 판단이 얼마나 자주 일어나는가

## 사람이 봐야 하는 것

기계가 세지 못하는 자리다.

- 문항 문면이 그 전공의 현장 말인가
- 영역 가름이 실무와 맞는가
- 산업팩의 판단이 그 산업 경력자에게 맞는가
- 보기 둘과 셋과 넷을 응시자가 실제로 가르는가
