# F. 결과모델과 입력까지의 추적

## 1. 직무 순위표를 내지 않는다

결과는 아홉 항목이고 그 가운데 차례를 만드는 항목이 없다. 영역 비교는
`비교가 필요한 영역` 으로만 나가고, 공고 직무 비교는 열 번째 항목으로
STANDARD 이상에서 붙는다.

## 2. 입력 키 목록

추적표가 가리키는 입력의 이름을 먼저 적는다. 결과지의 되짚기 부록에
이 키가 그대로 나간다.

| 키 | 무엇 | 어디서 |
|---|---|---|
| `grid.interest[TD]` | 영역 관심 1~5 | `CORE-GRID` |
| `grid.exposure[TD]` | 영역 경험 없음·한두 번·여러 번 | `CORE-GRID` |
| `grid.learning[TD]` | 영역 학습 의향 1~5 | `CORE-GRID` |
| `judge.common[4]` | 공통 판단 넷(역방향 1 포함) | `CORE-JUDGE` |
| `force.pick[2]` | 강제 선택 결과 | `CORE-FORCE` |
| `probe[TD].J{3,5,6,8}` | 선별 네 축의 L0~L3 | `PROBE-J4` |
| `deep[TD].J{1,2,4,7}` | 남은 네 축의 L0~L3 | `DEEP-J8` |
| `check[TD].judgements[]` | 판단 체크리스트에서 고른 항목 | `DEEP-CHECK` |
| `check[TD].artifacts[]` | 산출물 체크 | `DEEP-CHECK` |
| `check[TD].verified_against[]` | 검증 대상 선택 | `DEEP-CHECK` |
| `check[TD].notes{}` | 체크한 항목의 한 줄 근거 | `DEEP-CHECK` |
| `pref.rf[]` · `pref.oc[]` | 역할·조직환경 선호 | `PREF-RF-OC` |
| `consist.pairs[2]` | 같은 축 두 장면의 차이 | `CONSIST` |
| `branch.block[]` | 학위·계열 분기 블록의 응답 | `UG-COURSE` · `GRAD-*` |
| `trans.T1..T10` | 번역 열 단계 | `TRANS-10` |
| `target.role` · `target.industry` · `target.oc` | 목표 입력 | `TARGET` |
| `region.home` · `region.range` | 희망 지역과 이동 범위 | 시작 화면 |

## 3. 파생값 다섯

입력에서 바로 결과를 만들지 않고 파생값을 거친다. 파생값을 적어 두는
까닭은 결과 항목 아홉이 같은 값을 읽어야 서로 어긋나지 않기 때문이다.

| 파생값 | 산식 | 읽는 결과 항목 |
|---|---|---|
| `I[TD]` 관심 | `grid.interest` 를 높음·중간·낮음 세 마디로 | A · B · C |
| `L[TD]` 학습 의향 | `grid.learning` 을 세 마디로 | C · I(다음 행동) |
| `axis[TD][J]` 축 수준 | `probe` · `deep` · `check` · `trans` 가운데 **가장 높은 근거**를 L0~L3 로 | D · E · F · G |
| `G4[TD]` · `G8[TD]` | `axis` 가 L2 이상인 축의 **개수**. S4 와 S8 을 따로 센다 | A · B |
| `Z[TD]` 묶음 | 아래 4절의 조건 | A · B · C |

### 3-1. `axis` 를 가장 높은 근거로 두는 까닭

같은 축에 근거가 여러 곳에서 온다. 선별에서 L2 로 답하고 체크리스트에서
그 항목을 고르고 번역 T8 에서 또 고르면 근거가 셋이다. 셋 가운데 가장
높은 것을 쓰되, **L3 로 올리려면 근거가 둘 이상이어야 한다.** 하나로
올리면 칸 하나를 누른 사람과 실제로 정한 사람이 같아진다.

### 3-2. 자기보고와 서술이 어긋날 때

| 응답 | 체크·서술 | `axis` 결과 | 결과지의 말 |
|---|---|---|---|
| L2 이상 | 그 축의 항목을 골랐다 | 그대로 | 확인 |
| L2 이상 | 아무 항목도 고르지 않았다 | **L1 로 내린다** | 설명할 재료가 아직 없습니다. 한 줄만 적으시면 확인으로 바뀝니다 |
| L0 | 그 축의 항목을 골랐다 | **L2 로 올린다** | 적어 주신 것으로는 하신 것으로 읽힙니다 |
| L2 이상 | 다른 축의 항목만 골랐다 | 그대로 | 그 자리를 비우고 무엇을 적어야 하는지 적는다 |

세 번째 줄이 지금 구조에서 가장 크게 바뀌는 자리다. 지금은 올리는
쪽으로만 걸러서 겸손하게 답한 사람이 자기 경험을 결과지에서 못 본다.

## 4. 묶음 조건

| 묶음 | 조건 | BASIC 에서 |
|---|---|---|
| Z1 근거가 선 영역 | `G8 ≥ 4` 이고 그 영역의 **필수 축 둘이 모두 L2 이상** 이고 **`J5` 산출물이 L2 이상** 이고 `I` 가 낮음이 아님 | 쓰지 않는다. BASIC 은 S8 을 묻지 않는다 |
| Z2 관심은 있고 근거가 얕은 영역 | `I` 높음 이고 (`G8 ≤ 2` 또는 **`J5` 가 L2 미만**) | `I` 높음 이고 (`G4 ≤ 1` 또는 `J5` 가 L2 미만) |
| Z3 근거는 있고 관심이 낮은 영역 | `G8 ≥ 3` 이고 `I` 낮음 | `G4 ≥ 2` 이고 `I` 낮음 |
| Z4 아직 판단할 수 없는 영역 | 심화를 열지 않았거나 응답 부족 | 선별 심화를 열지 않은 영역 전부 |

**산출물이 없으면 Z1 이 아니다.** 개수 조건과 필수 축 조건을 둘 다
만족하면서 남은 것이 없는 자리가 있다. 문제를 정의하고 방법을 고르고
결과를 견주었는데 도면도 보고서도 코드도 남지 않은 경우이고, 연구 중심
경력에서 흔하다. 그 상태에서 `지원서와 면접에 쓸 근거가 섰다` 고 적으면
읽은 사람이 들고 갈 것이 없다. 앞 판본의 `APPLICATION_EVIDENCE_AVAILABLE`
이 이미 `산출물 이상 하나` 를 요구했고, 같은 선을 여기에도 둔다. 이 조건이
없을 때 어떤 사람이 통과하는지는 `npm run v3:persona` 의 여덟째 사람이
보여 준다.

**그 영역을 Z4 로 보내지 않는다.** Z1 에서 떨어뜨리기만 하면 축을 여럿
확인한 영역이 `아직 판단할 수 없는 영역` 에 가서 앉는다. 많이 답한 사람에게
응답이 모자란다고 말하는 셈이고, 모자란 것은 응답이 아니라 **남은 것**이다.
그래서 Z2 조건에 산출물 미확인을 더해서, 영역 이름과 함께 비어 있는 축이
산출물이라는 것과 그것이 다음 할 일이라는 것을 적는다.

**BASIC 에 Z1 이 없다.** 선별 네 축만으로 `근거가 섰다` 고 말하지 않는다.
BASIC 이 말하는 것은 `선별 네 축 가운데 둘이 확인됐습니다` 까지이고,
묶음 이름은 `먼저 확인해 보실 영역` 으로 적는다. 무료 결과를 깎아서
유료를 권하지 않되, 없는 판정을 만들지도 않는다.

### 4-1. 묶음 안에서 차례를 만들지 않는다

같은 `G` 값이면 순서를 만들지 않는다. 2026-10-07 회차에서 확정한 동점
규칙을 그대로 가져온다. `force.pick` 이 있으면 묶인 영역 안에서 **고르신
쪽을 먼저 적고 그 사실을 적는다.** 경험이나 산출물을 2차 정렬에 쓰지
않는다.

## 5. 결과 항목 아홉과 추적

### A. 강하게 드러난 기술영역

| | |
|---|---|
| 무엇 | Z1 묶음. 영역 이름과 확인된 축의 개수와 **그 축의 이름** |
| 입력 | `probe` · `deep` · `check` · `trans` → `axis` → `G8` → `Z` |
| 등급 | 개수는 BASIC(S4 기준) · 이름은 STANDARD 이상 |
| 금지 | 점수 · 백분율 · 차례. 비율로 바꾸지 않는다 |

### B. 비교가 필요한 영역

| | |
|---|---|
| 무엇 | `G8` 이 같거나 하나 차이인 영역 둘셋과 **무엇을 더 확인하면 갈리는지** |
| 입력 | A 와 같다. 갈리는 축은 두 영역의 필수 축 차집합에서 고른다 |
| 등급 | STANDARD 이상. BASIC 은 `같은 수로 묶였습니다` 까지 |
| 금지 | 둘 중 하나를 고르라는 말 |

### C. 아직 판단하기 어려운 영역

| | |
|---|---|
| 무엇 | Z4. 심화를 열지 않은 영역과 미응답 수, 그리고 `L` 이 높은 영역의 다음 걸음 |
| 입력 | 심화에서 고르지 않은 영역 목록 + `grid.learning` |
| 등급 | 전 등급 |
| 금지 | 비어 있는 것을 낮은 것으로 적기 |

### D. 실제 해본 업무

| | |
|---|---|
| 무엇 | 영역 workflow 가운데 **내가 한 것으로 확인된 활동** |
| 입력 | `grid.exposure` + `probe`·`deep` 의 L2 이상 + `check.judgements` + `branch.block` + `trans.T5` |
| 등급 | 전 등급(BASIC 은 선별 두 영역) |
| 금지 | 영역 설명을 그대로 옮기기 |

### E. 직접 해본 기술 판단

| | |
|---|---|
| 무엇 | `axis[TD][J3]` 가 L2 이상인 자리와 체크리스트에서 고른 판단 항목. **이 절이 제품의 중심이다** |
| 입력 | `probe[TD].J3` · `deep` · `check.judgements` · `trans.T3` · `T4` · `T8` |
| 등급 | 개수는 BASIC · 항목 이름은 STANDARD 이상 |
| 금지 | 참여와 판단을 섞어 적기. 팀의 결정을 따른 것(L1)은 따로 적는다 |

### F. 이미 있는 근거

| | |
|---|---|
| 무엇 | 한 경험에서 J5 산출물과 J6 검증과 J8 활용이 함께 L2 이상인 묶음 |
| 입력 | `check.artifacts` + `check.verified_against` + `check.notes` + `trans.T9` · `T6` · `T10` |
| 등급 | STANDARD 이상 |
| 금지 | 산출물만 있고 검증이 없는 것을 근거로 적기 |

### G. 부족한 근거

| | |
|---|---|
| 무엇 | 그 영역에서 L2 미만인 축의 이름과 **그것을 채우는 조건** |
| 입력 | `axis` 의 L0·L1 축 + 영역 사전의 `l2` 문면 |
| 등급 | 개수는 BASIC · 이름과 조건은 STANDARD 이상 |
| 금지 | 축 이름만 적기. 무엇을 어떤 조건으로 남기면 되는지 함께 적는다 |

### H. 직무로 번역 가능한 경험

| | |
|---|---|
| 무엇 | 서술이나 번역 단계에는 있는데 체크리스트에서 고르지 않은 자리, 그리고 비어 있는 번역 단계 |
| 입력 | `trans.T1~T10` 의 보기 선택과 `check` 응답의 차집합 + 서술 키워드 매칭(보조) |
| 등급 | PRO. STANDARD 는 비어 있는 단계의 개수까지 |
| 금지 | 경험 부족이라고 적기. 번역되지 않은 것과 없는 것은 다르다 |

### I. 다음 행동

| | |
|---|---|
| 무엇 | 30일 안에 만들 것 하나와 그 조건. 90일과 365일은 상위 등급 |
| 입력 | G 의 미확인 축 + `current_status` + `region.range` + 영역 사전의 산출물 목록 + `L` |
| 등급 | 30일은 전 등급 · 90일은 STANDARD · 365일은 PRO |
| 금지 | 일반론. 무엇을 · 어떤 조건으로 · 무엇과 견주어 · 무엇으로 남길지 넷이 다 들어가야 한다 |

### J. 비교할 직무 (열 번째)

| | |
|---|---|
| 무엇 | 영역과 역할 조합에서 나오는 공고 직무명 둘셋과 가르는 질문 |
| 입력 | `Z1` 영역 + `pref.rf` + `pref.oc` → 별칭표 → 경계표의 구분 질문 |
| 등급 | STANDARD 이상 |
| 금지 | 차례와 적합도 |

## 6. 전공계열이 결과에 나타나는 단 한 자리

| 절 | 무엇을 적는가 |
|---|---|
| 1절 끝 `이 결과를 어떻게 읽어야 하는가` | 어느 학위와 어느 계열의 장면으로 물었는지, 그리고 그 계열의 경험이 어느 영역까지 닿는지 |

예시 셋을 적는다.

> **이공계 석사** 연구 장면으로 물었습니다. 연구에서 쓰신 방법이 기술영역
> 둘에 근거를 주었고, 그 영역의 비어 있는 축을 아래에 적었습니다.

> **인문·사회·경상 석사** 조사·분석 장면으로 물었습니다. 적어 주신 방법은
> 시스템·요구사항과 엔지니어링 데이터 쪽에 근거를 줍니다. 설계와 해석
> 영역은 이 응답으로는 확인되지 않았고, 확인되지 않았다는 것이 못 한다는
> 뜻은 아닙니다.

> **기타·융합 석사** 두 장면을 함께 물었습니다. 물리 시스템과 조직 양쪽의
> 보기를 열어 두었고, 고르신 것에서만 근거를 셌습니다.

**이 절 밖에서 계열을 적지 않는다.** 영역 표와 축 표와 다음 행동에는
계열이 나오지 않는다.

## 7. 되짚기 부록이 담는 것

| 담는 것 | 왜 |
|---|---|
| 문항 번호와 그 응답 | 학과 담당자가 다시 채점해 볼 수 있어야 한다 |
| 축마다 어느 입력에서 그 수준이 나왔는지 | 자기보고와 체크리스트가 어긋난 자리를 본인이 본다 |
| 영역 사전의 축 정의와 필수 축 | `8개 중 5개` 의 뜻을 읽을 수 있게 |
| 판본 지문 다섯 | 스냅샷이 거짓을 적지 않게 |
| 못 하는 것 목록 | 숙련도·합격 가능성·규준 없음 |

## 8. 결과가 반응하는지 보는 검사

| 검사 | 무엇 |
|---|---|
| 재현성 | 같은 응답이면 아홉 항목이 글자까지 같다 |
| 계열 중립 | 계열만 바꾸면 6절의 한 절 말고는 같다 |
| 지역 중립 | 지역만 바꾸면 아홉 항목이 전부 같다 |
| 반응성 | 한 축의 응답을 L0 에서 L3 로 바꾸면 A·E·F·G 가 바뀐다 |
| 동점 | 전 영역 같은 값이면 차례가 생기지 않는다 |
| 빈칸 | 번역을 비우면 그 단계가 빈 채로 적힌다 |
| 문항 쓰임 | 아홉 항목이 읽지 않는 문항이 0 개다 |
