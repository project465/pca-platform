# H. 새 측정모델 · I. 대학원 경험 번역모델

## 1. 무엇을 측정하는 제품인가

한 줄로 다시 적는다.

> **이 사람이 어느 기술영역에서 어떤 판단을 직접 내렸고, 그 판단이 무엇으로
> 남았는가.**

관심은 그 판단을 어디서 더 쌓을지 고르는 데만 쓴다. 관심으로 직무 차례를
만들지 않는다.

## 2. 측정 축 열하나

각 축에 네 가지를 적는다. 왜 필요한가 · 몇 문항인가 · 직무 판단에 어떻게
쓰이는가 · 경험 입력과 어떤 관계인가.

### M1 관심

- **왜** 근거가 없는 영역에서 다음 걸음을 고를 때 쓸 유일한 신호다.
- **몇 문항** 선별 12(영역마다 1) + 심화 3(고른 영역의 강제 선택). 선별
  12 가운데 셋은 역방향 문면으로 둔다.
- **쓰임** 영역 묶음을 만든다. **차례를 만들지 않는다.**
- **경험 입력과** 무관하다. 둘을 합치지 않는다.

### M2 경험 노출

- **왜** 해본 적이 있는지와 얼마나 반복했는지는 다음 걸음을 가른다.
- **몇 문항** 선별 12 + 심화 3.
- **쓰임** 묶음 안에서 `근거 있음 · 얕음 · 없음` 을 가른다.
- **경험 입력과** 자기보고와 서술이 어긋나면 그 사실을 적는다.

### M3 문제 정의

- **왜** 기계공학에서 주어진 문제를 푸는 사람과 문제를 세우는 사람은 다른
  자리에 간다. 선행개발과 연구가 이 축으로 갈린다.
- **몇 문항** 고른 영역마다 1.
- **쓰임** 역할축 RF7(탐색·연구) 판정의 주 신호.
- **경험 입력과** 서술에서 `무엇을 왜 해석·시험·설계하기로 정했는가` 를
  받아 근거로 쓴다.

### M4 직접 기술 판단

- **왜** 이 제품의 중심이다. 같은 프로젝트에 참여한 두 사람을 가르는 것은
  **무엇을 정했는가**다.
- **몇 문항** 고른 영역마다 1 + 그 영역의 **판단 체크리스트**(문항이 아니고
  선택 입력). TD01 이면 `두께·단면 · 재질 · 공차 배분 · 체결 방식 · 안전
  여유` 가운데 내가 정한 것을 고른다.
- **쓰임** 영역별 `확인된 판단 수` 를 만든다. 이 값이 결과 묶음을 가른다.
- **경험 입력과** 체크리스트가 경험 입력의 일부가 된다. 자유입력 키워드
  매칭에 의존하지 않는다.

### M5 방법·도구 사용

- **왜** 도구 이름만으로는 아무것도 모른다. 무엇에 썼는지가 역량이다.
- **몇 문항** 영역마다 1 + 도구 선택 입력(갈래 · 수준 · 용도).
- **쓰임** 판단과 묶어 읽는다. 도구만 있고 판단이 없으면 그 사실을 적는다.
- **경험 입력과** 기존 `me-tools.json` 여덟 갈래를 그대로 쓴다.

### M6 산출물

- **왜** 지원서와 면접에서 꺼내는 것은 산출물이다.
- **몇 문항** 영역마다 1 + 산출물 체크(도면 · 해석 보고 · 시험성적 ·
  작업표준 · 스크립트 · 논문 · 특허 · 시작품).
- **쓰임** `설명할 재료가 있다` 판정의 필수 조건.
- **경험 입력과** 체크한 산출물마다 한 줄 설명을 받는다.

### M7 비교·검증

- **왜** 기계공학에서 결과를 믿을 수 있게 만드는 것은 대조다. 손계산과
  해석, 해석과 시험, 전후 비교, 규격 대조.
- **몇 문항** 영역마다 1.
- **쓰임** 깊이 판정의 분기점. 이 축이 비면 산출물이 있어도 `확인` 으로
  올리지 않는다.
- **경험 입력과** `무엇과 견주었는가` 를 선택지로 받는다.

### M8 실패·수정

- **왜** 예상과 다른 결과를 되짚은 경험은 현업에서 가장 자주 묻는 질문이다.
- **몇 문항** 영역마다 1(공통 1문항도 둔다).
- **쓰임** 판단 소유를 한 단계 올리는 신호.
- **경험 입력과** 원인 후보를 어떻게 좁혔는지 선택지로 받는다.

### M9 결과의 사용

- **왜** 내 결과가 남의 결정에 쓰였는지가 조직 가치의 경계다.
- **몇 문항** 영역마다 1.
- **쓰임** `조직 성과로 읽히는 근거` 판정.
- **경험 입력과** 누가 무엇에 썼는지 한 줄을 받는다.

### M10 반복·재사용

- **왜** 한 번 한 것과 다시 쓸 수 있게 남긴 것은 다르다.
- **몇 문항** 0. 산출물 체크와 경험 입력에서만 본다.
- **쓰임** 깊이의 마지막 칸.
- **경험 입력과** 다른 사람이 썼는지를 받는다.

### M11 학습 의향

- **왜** 근거가 없는 영역에서 무엇을 먼저 배울지 고를 때 쓴다.
- **몇 문항** 선별 12(영역마다 1).
- **쓰임** `아직 판단할 수 없는 영역` 의 다음 걸음을 고른다.
- **경험 입력과** 무관하다.

### 축에서 뺀 것

**업무 방식 여섯 문항은 측정 축에서 뺀다.** 두 문항으로 성향 축 하나를
가르는 구조에서는 판정에 쓸 수 없고, 지금도 판정에 쓰이지 않는다. 대신
근무 환경 선호(장소 · 조직 형태 · 이동 가능성)를 **점수 없는 입력**으로
받아 조직환경 축과 지역 layer 에 넘긴다.

## 3. 직무 판단을 만드는 방법

### 3-1. 영역마다 값 셋

| 값 | 어디서 | 모양 |
|---|---|---|
| 관심 I | M1 | 높음 · 중간 · 낮음 (수치 없음) |
| 근거 G | M3~M10 에서 확인된 축 수 | 0~8 (개수) |
| 학습 의향 L | M11 | 높음 · 중간 · 낮음 |

**G 는 점수가 아니고 개수다.** 여덟 축 가운데 몇 개가 확인됐는지를 적는다.
개수로 두는 까닭은 소수점이 없는 정밀도를 만들지 않으려는 것이고, 비어
있는 축의 이름을 그대로 다음 할 일로 쓸 수 있기 때문이다.

### 3-2. 네 묶음

차례를 만들지 않고 처지를 가른다.

| 묶음 | 조건 | 결과지에서 하는 말 |
|---|---|---|
| Z1 근거가 선 영역 | G ≥ 4 이고 I 가 낮음이 아님 | 지원서에서 이 영역으로 설명할 수 있습니다. 비어 있는 축은 이것입니다 |
| Z2 관심은 있고 근거가 얕은 영역 | I 높음 이고 G ≤ 2 | 먼저 한 건을 끝까지 해 보실 자리입니다. 어떤 판단을 남겨야 하는지 적었습니다 |
| Z3 근거는 있고 관심이 낮은 영역 | G ≥ 3 이고 I 낮음 | 이미 가진 자산입니다. 다른 영역에 옮겨 쓸 수 있는 축은 이것입니다 |
| Z4 아직 판단할 수 없는 영역 | 선별까지만 봤거나 응답 부족 | 이 영역은 선별 단계까지만 봤습니다. 더 보시려면 여기를 엽니다 |

Z1 안에서 순서는 **확인된 축 수**로만 가른다. 같은 수면 순서를 만들지
않는다. Z1 이 비면 Z2 를 먼저 보여 준다.

### 3-3. 자기보고와 서술이 어긋날 때

| 문항 | 경험 입력 | 결과지의 말 |
|---|---|---|
| 판단했다고 답함 | 서술에 그 판단이 있다 | 확인 |
| 판단했다고 답함 | 서술이 비어 있다 | **설명할 재료가 아직 없습니다.** 한 줄만 적으시면 확인으로 바뀝니다 |
| 판단했다고 답함 | 서술에 다른 축만 있다 | 그 자리를 비워 두고 무엇을 적어야 하는지 적는다 |
| 안 했다고 답함 | 서술에 그 판단이 있다 | **적어 주신 것으로는 하신 것으로 읽힙니다.** 확인으로 올리고 그 사실을 밝힌다 |

마지막 줄이 지금 구조에서 가장 크게 바뀌는 자리다. 지금은 올리는 쪽으로만
걸러서, 겸손하게 답한 사람이 자기 경험을 결과지에서 못 본다.

### 3-4. 매칭 방식을 바꾼다

자유입력 키워드 매칭을 **보조로 내린다.** 주 입력은 영역별 **판단
체크리스트**다. `CAE_BOUNDARY` 를 키워드로 찾던 자리가, 구조해석 영역의
판단 목록에서 `경계조건과 하중을 정했다` 를 고르는 것으로 바뀐다.
키워드는 서술에서 추가 근거를 찾는 데만 쓴다.

이 변경으로 **해본 사람에게 안 했다고 말하는 오류**가 사라진다. 지금은
`fixed support 로 잡고 베어링 반력을 분배했다` 가 매칭되지 않는다.

## 4. 현장직무역량을 중심축으로 두는 방법

한국판에서 중심에 두는 것이 이 묶음이다. 축 이름과 **그 축이 확인되는
조건**을 못 박아 둔다. 조건을 못 박지 않으면 같은 말이 사람마다 다르게
읽힌다.

| 축 | 확인 조건 | 부분 확인 | 미확인 |
|---|---|---|---|
| 요구 해석 | 요구를 수치와 제약으로 옮긴 것을 적었다 | 요구는 받았고 수치로 옮긴 것은 없다 | 둘 다 없다 |
| 문제 정의 | 무엇을 왜 다루기로 정했는지 적었다 | 주어진 문제를 받아 수행했다 | 적지 않았다 |
| 값 계산 | 수식이나 모델로 값을 낸 것을 적었다 | 도구를 썼고 값의 근거가 없다 | 없다 |
| 대안 비교 | 둘 이상을 같은 기준으로 견준 것을 적었다 | 하나만 했다 | 없다 |
| 직접 판단 | 내가 정한 항목을 체크리스트에서 골랐다 | 팀의 결정을 따랐다 | 없다 |
| 도구 사용 | 도구와 용도와 수준을 적었다 | 이름만 적었다 | 없다 |
| 산출물 | 종류를 고르고 한 줄 설명을 적었다 | 종류만 고름 | 없다 |
| 결과 검증 | 무엇과 견주었는지 적었다 | 결과만 있다 | 없다 |
| 실패 분석 | 원인 후보를 좁힌 방법을 적었다 | 실패했다고만 적었다 | 없다 |
| 결정 사용 | 누가 무엇에 썼는지 적었다 | 보고만 했다 | 없다 |
| 재사용 | 다른 사람이 썼거나 다시 쓴 기록 | 남겨 두기만 했다 | 없다 |

**기존 Evidence Engine 에서 살릴 것**을 분명히 적는다.

| 지금 자산 | 판정 | 왜 |
|---|---|---|
| `me-evidence-map.json` 의 영역 199개 | **살린다** | 현업 용어로 정확하다. TD 열둘로 재배치하고 판단 체크리스트의 원본으로 쓴다 |
| 증거 사다리 E0~E5 | **살린다** | 깊이 개념은 맞다. 표시 이름만 고객 말로 바꾼다 |
| `minimum_depth` 와 `gap_kind` | **살린다** | 영역마다 어디까지 가야 확인인지를 데이터로 들고 있다 |
| `match.keywords` | **내린다** | 주 입력에서 보조로 내린다 |
| `evidence-rules.json` 의 여덟 직무 신호 | **다시 만든다** | 열두 영역 전부로 늘리지 않으면 판정 경로가 갈린다 |
| `followups.json` 되묻는 말 | **살린다** | 빈 칸을 선택지로 채우는 방식이 맞다 |
| `me-value-paths.json` 가치 사슬 | **구조만 살린다** | 고정 텍스트를 응답에 따라 고르는 구조로 바꾼다 |

## 5. I. 대학원 경험 번역모델

석사와 박사에게 이 모델이 제품의 값이다. 연구 경험을 `논문 있음 ·
프로젝트 있음 · 실험함` 으로 처리하면 그 사람이 받는 것이 없다.

### 5-1. 열 단계

| 단계 | 받는 것 | 어떻게 받는가 | 직무 언어로 |
|---|---|---|---|
| 1 연구 문제 | 무엇을 다뤘는가 | 짧은 서술 + 영역 태그 | 문제 정의 |
| 2 가설·문제 정의 | 왜 그것이 문제인가 | 선택 + 한 줄 | 요구 해석 |
| 3 방법 선택 | 왜 그 방법인가 | 선택(실험 · 해석 · 측정 · 모델링) + 대안 | 방법론 판단 |
| 4 변수·가정 | 무엇을 고정하고 무엇을 바꿨는가 | 체크 + 한 줄 | 경계조건과 가정 정리 |
| 5 실험·해석 수행 | 무엇을 몇 번 어떻게 | 선택(장비 · 코드 · 반복 수) | 도구·방법 사용 |
| 6 비교·검증 | 무엇과 견주었는가 | 선택(이론 · 선행 연구 · 다른 방법 · 실측) | 결과 검증 |
| 7 오차·불확실성 | 산포와 한계를 어떻게 다뤘는가 | 선택(반복 · 불확도 · 민감도 · 격자) | 측정 불확도와 수렴 |
| 8 기술 판단 | 결과를 보고 무엇을 정했는가 | 체크리스트 | 직접 판단 |
| 9 산출물 | 무엇이 남았는가 | 선택(논문 · 특허 · 코드 · 장치 · 데이터셋 · 보고서) | 산출물 |
| 10 조직·산업 가치 | 누가 무엇에 쓸 수 있는가 | 선택 + 한 줄 | 결과의 사용 |

### 5-2. 방법에서 기술영역으로 가는 규칙

연구 내용을 TD 로 옮기는 규칙을 데이터로 둔다. **학위가 아니라 방법과
대상이 영역을 정한다.**

| 연구에서 한 일 | 이어지는 기술영역 | 함께 켜지는 역할 |
|---|---|---|
| 유한요소 해석 모델을 만들고 돌렸다 | TD02(구조) · TD03(열유체) | RF2 · RF7 |
| 격자와 난류 모델을 골랐다 | TD03 | RF2 |
| 모달 시험이나 진동 측정을 했다 | TD04 · TD07 | RF2 · RF3 |
| 제어기를 설계하고 실장했다 | TD05 | RF1 · RF2 |
| 시편을 만들고 기계 시험을 했다 | TD06 · TD07 | RF3 |
| 파면이나 조직을 관찰했다 | TD06 | RF3 |
| 계측 체인을 구성하고 불확도를 따졌다 | TD07 | RF3 |
| 가공·성형·적층 조건을 바꿔 실험했다 | TD08 | RF4 · RF7 |
| 장치를 설계하고 도면을 그렸다 | TD01 | RF1 |
| 데이터 처리와 모델 학습을 했다 | TD12 | RF2 |
| 과제 목표를 세부 과업으로 쪼갰다 | TD11 | RF6 |
| 신뢰성·수명 분포를 다뤘다 | TD10 | RF3 |

한 연구가 여러 줄에 걸리는 것이 보통이다. 그래서 **연구 하나가 영역
둘이나 셋에 근거를 준다.** 지금 구조에서는 연구 경험이 어느 영역에도
근거를 주지 못한다.

### 5-3. 산업 가치로 옮기는 문장 틀

결과지에 나가는 문장을 틀로 둔다. 빈칸은 전부 응답에서 온다.

> `{연구 대상}` 에서 `{방법}` 으로 `{무엇}` 을 정하고 `{무엇}` 과 견주어
> `{산출물}` 로 남기셨습니다. 이 묶음은 `{영역}` 의 `{판단 축}` 에
> 해당하고, `{조직환경}` 에서는 `{성과의 이름}` 으로 읽힙니다.

예시 하나를 적어 둔다. 지어낸 사람이고 실제 응답이 아니다.

> 전기차 구동모터 하우징의 열변형을 유한요소 모델로 다루면서, 접촉
> 열저항을 측정값으로 보정하고 격자 독립성을 확인한 뒤 실측 온도와
> 2도 안에서 맞추셨습니다. 이 묶음은 **구조·내구 해석의 모델 검증**과
> **열·유체 시스템의 경계조건 설정**에 해당하고, 부품·장비 기업에서는
> **시작품 수 감소와 설계 변경 근거**로 읽힙니다.

### 5-4. 금지 규칙

1. **학위로 단계를 올리지 않는다.** 단계는 응답한 facet 둘 이상의 근거로만
   올린다(지금 규칙을 그대로 유지한다).
2. **논문 수와 연구비를 역량으로 세지 않는다.** 산출물 종류는 세고 수량은
   세지 않는다.
3. **연구 주제의 새로움을 평가하지 않는다.** 제품이 잴 수 있는 값이 아니다.
4. **빈 단계를 추정으로 채우지 않는다.** 7단계를 비우면 그 자리에 `오차를
   어떻게 다뤘는지 아직 적지 않으셨습니다` 를 적는다.
