# PCU 상용 콘텐츠 QA — 전 Core 실제 출력 검수

**이 회차가 바꾼 것은 사람이 읽는 표현과 정보 구조뿐이다.** 채점과 문항
구성과 판정은 한 줄도 바뀌지 않았고, 그것을 **같은 응답을 다시 돌려 지문
으로** 확인했다(아래 F절).

읽는 순서는 이렇다. A 무엇을 쟀는가 · B 자동 검사 둘 · C 찾은 것과 고친
것 · D Before/After · E PDF · F 판정 불변 · G 남은 것 · H 최종 보고.

---

## A. 무엇을 쟀는가 — raw JSON 이 아니라 실제 출력

**문장을 고치기 전에 먼저 쟀다.** 소스를 읽어서 고치면 그 문장이 실제로
어느 화면에 어떤 차례로 서는지를 모르고 고치게 된다. 그래서 제품과 똑같은
길을 지나는 하네스를 만들었다(`npm run v3:content:qa`).

```
응시를 연다 → 사람 셋의 답을 넣는다 → 제출한다
            → 로그인한 본인으로 웹 결과를 받는다 → 그 자리에서 종이를 뽑는다
```

**전 Core 20 × 사람 셋 = 60벌**이고 자리마다 넷을 떠 둔다.

| 떠 두는 것 | 무엇인가 |
|---|---|
| `<core>-<사람>.screens.txt` | 응시 화면에 **실제로 서는 글자**. 화면이 부르는 함수를 그대로 불러 적는다 |
| `.web.txt` | 웹 결과 쪽의 그려진 글자 |
| `.pdf` · `.txt` | 종이와 쪽마다 다시 꺼낸 글자(`pdftotext`) |
| `.judgment.json` | **판정 지문.** 채점 스냅샷과 결과 모델에서 판본과 응시번호만 뺀 값 |

**사람 셋은 받은 규격 §2 의 세 처지를 그대로 적은 답하는 규칙이다.**
Core 와 무관하게 같은 규칙이라, Core 사이의 결과 차이가 사람 차이에서
오지 않는다.

| | 어떻게 답하는가 |
|---|---|
| A | 관심 2 · 경험 없음 · 보기 넷의 첫 자리 · 근거 0개 |
| B | 관심 4 · 경험 1~2회 · 받아 씀(문제 정의와 직접 판단만 수행) · 근거 1개 |
| C | 관심 5 · 경험 3회 이상 · 직접 수행(직접 판단과 산출물은 직접 정함) · 근거 2개 · 산출물 2 · 검증 2 |

등록부의 열두 벌(`personas.json`)을 쓰지 않은 까닭은 그쪽이 **판정 회귀**가
쓰는 자리이고(golden 지문), 여기서 묻는 것은 카피이기 때문이다. 판정 불변은
그 열두 벌이 따로 센다(F절).

## B. 자동 검사 둘을 남겼다

한 회차의 감사로 끝나면 다음 원고에서 그대로 돌아온다.

| 명령 | 묻는 것 |
|---|---|
| `npm run v3:items:copy` | **문항이 학생의 말로 적혀 있는가.** 능력 단정 · 성향 단정 · 보고서 문체 · 번역투 · AI식 추상 · 빈도 부사 · 명사화 과다 · 용어 받침 · 빈도 척도 · 은행 머리 |
| `npm run v3:content:audit` | **떠 둔 실제 출력이 상용 기준을 넘는가.** §8 첫 화면 · §10 되풀이 · §11 종이 첫 쪽 · §12 본문 차례 · §13 쪽 채움 · §16 Core 차별성 · §17 광고 말투 |

`v3:items:copy` 는 `v3:all` 과 `core:all` 사슬에 들어갔다. `v3:content:audit`
은 떠 둔 자리를 읽으므로 하네스를 돌린 뒤에 쓴다.

**거짓 경보를 내는 검사는 그 다음부터 아무도 보지 않는다.** 만들면서 다섯
규칙을 좁혔다: `자주 멈춘 자리`(설비를 가리키는 빈도)와 `전자파 적합성`(그
전공의 말)과 `최적점`(실험의 말)과 활용형이 한 Core 에만 있다는 까닭으로
남의 말이 된 자리와, 표의 칸 이름이 되풀이된다고 걸린 자리다.

## C. 찾은 것과 고친 것

### P0 — 뜻이 틀린 자리

**① 경험이 없는 응시자에게 `완전히 비어 있는 축은 없습니다` 가 나갔다.**
빈자리가 0 인 까닭이 둘인데(다 채운 사람 · 빈자리를 셀 만큼 해 본 일이 아직
없는 사람) 한 문장으로 적고 있었다. 바로 위 절은 같은 사람에게 `지금 바로
꺼내 쓸 경험은 아직 없습니다` 를 적는다 — 한 종이에서 두 문장이 서로를
부순다. 까닭은 결과 모델이 이미 들고 있다(`first_move`). 여기서 다시
판정하지 않고 그 값을 읽는다.

**② `지금 할 일` 칸이 할 일을 적지 않았다.** 빈자리가 있는 응시에서 그
칸이 들고 있던 것은 빈자리의 **이름**이었다(`경영전략·기획 · 어디까지 직접
정했는지`). 그러면 첫 화면 넷 가운데 셋이 비어 있는 것을 적고 **행동을 적는
칸이 한 자리도 없다.** 그 빈자리에 붙은 할 일은 모델이 이미 들고 있다
(`gap.action_id`).

**③ 문항 은행 열여덟 벌이 남의 Core 의 은행이라고 적고 있었다.**
`biz-v1-items.json` 의 `core` 칸이 `EE_CORE_V1` 이었다(EE 머리를 베껴 쓴
자리다). 읽는 코드가 없어 아무 일도 일어나지 않지만, **되짚을 때 그 파일이
남의 Core 의 은행이라고 말한다.** 같은 파일의 안내문도 `CORE=EE_CORE_V1 npm
run v3:wording` 을 가리키고 있었다 — 그대로 치면 다른 Core 를 센다.

### P1 — 읽기 어렵거나 되풀이되는 자리

**④ 그 전공의 말에 받침이 없었다**(§5). 문항 232자리가 `불확도` 와 `중재` 와
`양생` 처럼 낱말 하나를 모르면 해 본 사람도 `해 본 적 없음` 을 고르게 되는
말을 받침 없이 들고 있었다. **용어를 빼지 않았다**: 전공자가 읽는 글이라
제자리에 쓰는 것이 맞고, 일반어로 풀어 적으면 오히려 얕게 읽힌다.

받침은 **말마다** 적는다(`content/me-v3-terms.json`, 18 Core · 63개). 문항
마다 적으면 같은 말이 여덟 자리에 서는데 여덟 번 따로 적게 되고, 그 가운데
하나가 어긋난다. **문항 은행을 한 글자도 고치지 않는 자리라** 동결된 기계공학
은행도 받침을 받는다. 화면에서 문항 아래 한 줄로 선다(산업팩이 전부터 쓰던
`gloss` 와 같은 길이다).

**⑤ 보기 2·3·4 의 경계가 갈리지 않았다**(§6). 뜻풀이만으로는 `조건이나
결과를 받아서 썼습니다` 와 `그 일을 직접 했습니다` 사이가 갈리지 않는다는
지적이 들어왔다. 뜻 뒤에 **그 자리에서만 맞는 장면**을 하나씩 붙였다. 뜻은
`scoring/ownership.ts` 가 유일한 출처이고(측정 동결) 장면은 화면이 든다.

**⑥ 되풀이 아홉 자리**(§10). 같은 결과지 안에서 같은 문장이 2~7번 섰다.
고친 자리는 아래 D절의 표다. **정보를 지우지 않았다**: 묶거나, 긴 문장을
한 자리에만 두고 다른 자리에는 칸의 말을 적었다.

**⑦ 경험이 없는 응시자의 결과가 전공과 무관한 말로 끝났다**(§16).
`수업이나 교내 과제 가운데 하나를 골라 짧게 해 본 뒤에 다시 보세요` 는 어느
전공에나 붙는 말이다. 어디에서 해 보면 되는지를 적는다 — 그 이름은 **결과
모델이 이미 들고 있는 것**(고르신 산업과 이어지는 영역)이고 새로 판정하지
않는다.

**⑧ 경험 빈도의 첫 칸이 응시 화면과 어긋났다**(§7). 응시할 때 읽은 척도는
`없음 · 1~2회 · 3회 이상` 인데 결과지가 `해 본 적 없음 · 1~2회 · 3회 이상`
을 적었다. 같은 값을 두 이름으로 적으면 읽는 사람이 둘을 다른 척도로 읽는다.

**⑨ 번역투 두 자리**(ARCH · VISUAL). `가를 자리에 있어 그것을 정한 경험이
있다` → `가르는 자리에서 그것을 정한 경험이 있다`.

**⑩ 한 칸에 같은 항목이 두 번 섰다**(§10). 산출물 축을 직접 정한 사람의
영역 카드에서 `지형도` 가 `직접 정한 것` 과 `남긴 것` 에 나란히 섰다. 둘 다
맞는 말인데, 바로 아래 줄이 그것을 제 이름으로 다시 적는다. **스무 Core 의
사람 C 에서 영역 80자리 · 항목 160개**가 그 모양이었다. 고르는 것은 어느
줄에 적을지뿐이고 결과 모델은 그대로다.

**⑪ 산업 절과 직무 절이 같은 문장으로 열었다**(§10). 두 다리 문장이 모두
`확인된 것 → 이 자리에서 모자란 것` 으로 서는데, 앞엣것이 같은 영역을
가리키면 **첫 문장이 글자까지 같다.** 뒤에 서는 절에서 이미 적은 줄만
걷는다.

**⑫ 첫 화면이 적은 할 일이 두 자리에 더 섰다**(§10). 같은 한 줄이 첫
화면과 `앞으로 채울 것` 과 `다음에 할 일` 에 세 번 섰다. 가운데 자리는
**어디에 있는지**를 적는다: 지우면 그 칸이 왜 비었는지 읽는 사람이 알 수
없다.

### 고치지 않고 적어 두는 것

**ME_CORE_V3 의 문항 은행은 건드리지 않았다.** 받은 규격이 기계공학을 회귀
기준선으로 두라고 했고(§2), 그 은행은 `ME_V3_MEASUREMENT_FREEZE_1` 이 덮는
파일이다. 기계공학의 용어 받침은 **은행을 고치지 않는 말 표**로 들어갔다.

## D. Before / After

`개선했습니다` 로 적지 않는다(§19). 떠 둔 실제 출력에서 그대로 꺼낸 글자다.

### 응시 화면

| 자리 | 전 | 후 |
|---|---|---|
| 문항 아래 용어 받침 (EE) | (없음) | `도움말: 커패시터 — 전기를 잠깐 담아 두는 부품(콘덴서) · 이득 — 들어온 신호가 몇 배로 커져 나오는지` |
| 문항 아래 용어 받침 (NURSING) | (없음) | `도움말: 중재 — 상태를 보고 간호사가 직접 하는 처치나 교육` |
| 문항 아래 용어 받침 (CIV) | (없음) | `도움말: 침하 — 지반이나 구조물이 아래로 내려앉는 일` · `도움말: 기준점 — 측량에서 좌표를 재는 출발이 되는 점` |
| 보기 셋째의 펼침 한 줄 | `그 일을 직접 했습니다. 정하는 자리에 함께 있었다면 여기입니다` | 같은 뜻 뒤에 `예: 조건은 함께 정했고 실제 작업과 계산은 제가 했습니다.` |
| 보기 넷째의 펼침 한 줄 | `조건이나 기준을 직접 정했고 그 결과가 다음 작업에 쓰였습니다` | 같은 뜻 뒤에 `예: 어느 값을 쓸지와 합격 기준을 제가 정했고, 그 결정대로 다음 작업이 진행됐습니다.` |

위의 넷은 **사람 셋이 실제로 지나간 화면에서 꺼낸 것**이다. 말 표의 63개
가운데 그 셋의 길에 서지 않는 말(`양생` 처럼 심화에서만 묻는 영역의 말)은
여기 적지 않는다 — 떠 두지 않은 화면을 보고 적는 것이 이 회차가 피하려던
일이다.

**문항 문면은 한 글자도 바뀌지 않았다.** 받침은 말 표가 들고 예시는 화면이
든다. 측정 동결이 덮는 파일에 손이 닿지 않는 자리다.

### 웹 결과

|---|---|---|

| 영역 카드의 산출물 (CIV C · 조사·측량) | `직접 판단한 것: … · 지형도` · `남긴 결과: 측량 성과표` | `직접 판단한 것` 은 판단 셋 · `남긴 결과: 지형도 · 측량 성과표` |
| 영역 카드의 묶음 설명 | `직접 정한 것과 남긴 결과물이 함께 확인됐습니다.` 4번 | 1번 — 같은 묶음이 잇따르면 머리에 한 번 |
| 빈자리의 까닭 | `해 본 것은 확인됐습니다. 지원서에서는…` 가 빈자리마다 | 같은 까닭은 한 번만 (BIZ C 4 → 1) |
| 여덟 축의 칸 | `조건과 기준값을 직접 정했습니다` (문장) | `조건과 기준값을 직접 정함` (칸의 말) |
| 빈자리 한 줄 | `경영전략·기획 · 요구 해석 경험은 확인됐고, 어디까지 직접 정했는지가 덜 적혔습니다` | 첫 화면에서는 칸의 말로 `어디까지 직접 정했는지` |
| 산업·직무 다리 | 다리 문장 끝에 할 일이 한 번 더 붙었다 | 할 일은 그 절의 `다음에 만들 근거` 에만 선다 |
| 경험이 없는 응시자의 첫 걸음 | `수업이나 교내 과제 가운데 하나를 골라 짧게 해 본 뒤에 다시 보세요.` | `기구·제품 설계 · 열·유체 시스템 가운데 하나를 수업이나 교내 과제로 짧게 해 본 뒤에 다시 보세요.` |
| 경험 빈도의 첫 칸 (선별 등급의 영역 한 자리) | `해 본 적 없음` | `없음` — 응시 화면과 같은 척도 |
| 고르신 자리 | 본문 가운데 | 닫는 부록으로 내려가 한 덩이로 움직인다 |

**경험 빈도 한 줄은 떠 둔 60벌에 서지 않는다.** 그 칸은 여덟 축을 묻지
않은 응시(선별 등급)의 영역 한 자리이고 하네스는 PRO 로 돈다. 그래서 이 한
줄만 소스에서 꺼냈고, 그 사실을 적어 둔다.

| 산업·직무 절 | 다리 문장 + 같은 할 일 두 번 | 다리 문장 + `다음에 만들 근거` 한 번 |
| 할 일 절 | 영역마다 한 줄 | 같은 틀의 할 일은 영역 이름을 모아 한 줄 |
| 마지막 쪽 | 네 벌이 13~16% (하한 20% 아래) | **0벌** — 가장 낮은 자리가 43% |

## E. 종이 상용 감사

재는 자는 글자의 아래쪽 좌표다(`pdftotext -bbox`). 쪽마다 글자 수로는 이
질문에 답할 수 없다: 활자가 큰 첫 쪽은 글자가 적어도 꽉 차 있다.

| | 전 | 후 |
|---|---|---|
| §11 첫 쪽에 있어야 할 것 | 0 | 0 |
| §12 본문 차례 | 0 | 0 |
| §13 걸림 | 8 (네 벌이 13~16%) | **0** |
| §13 마지막 쪽 20~45% (보고) | 11벌 | 41벌 |
| §13 본문 쪽 채움 | 459쪽 · 80~100% · 평균 96% | 452쪽 · 53~100% · 평균 95% |

**마지막 쪽이 20% 아래인 자리를 없앤 길을 적어 둔다.** 닫는 부록
(`.rs-fine`)에 `break-inside: avoid` 를 걸고 `고르신 자리` 를 그 안으로
옮겼다. 한 덩이로 움직이므로 쪽 경계에서 쪼개지지 않고, 가장 심했던 일곱
벌이 43% 로 올라오고 한 벌은 쪽이 하나 줄었다. **Core 별 CSS 를 두지
않았고 PDF 엔진을 고치지 않았다**(§13).

**보고가 11 에서 40 으로 늘어난 까닭도 적어 둔다.** 되풀이를 걷어 문서가
짧아지면서 쪽 경계가 움직였고, 20% 아래였던 자리가 20~45% 구간으로 올라온
대신 전에 45% 를 넘던 자리 일부가 그 구간으로 내려왔다. 본문 쪽이 평균
95% 로 차 있는 문서에서 **마지막 쪽에 남는 것은 나머지**이고, 그 양은 문서
길이가 쪽 경계에 어디쯤 떨어지는가로 정해진다. 공통 규칙 하나로 스무 Core
의 그 자리를 함께 고를 수는 없다 — 이 회차에 변형 둘을 더 재어 봤고 둘 다
다른 자리를 깨뜨렸다(`.rs-fine` 앞에서 끊으면 2~9% 쪽이, `#region` 앞에서
끊으면 11~13% 쪽이 생긴다). 그래서 **20% 를 걸림으로, 45% 를 보고로** 둔다.

## F. 판정이 바뀌지 않았다는 증거

§20 이 요구한 것은 하나다: 같은 persona 를 다시 돌려 **판정 객체가 같은가.**
넷으로 보였다.

1. **판정을 만드는 모듈이 한 바이트도 바뀌지 않았다.**
   `git diff --stat -- src/lib/me-v3/scoring src/lib/me-v3/result/build.ts
   src/lib/me-v3/result/model.ts src/lib/me-v3/response-count.ts` 가 비어 있다.
2. **등록부의 사람 열두 벌 × Core 20 의 golden 지문이 그대로다**
   (`npm run v3:scoring`, Core 마다 확인 31가지). 문항 은행 열여덟 벌을 고친
   뒤에도 `GOLDEN=update` 없이 통과한다.
3. **측정 동결이 기록을 다시 적지 않은 채로 통과한다**
   (`npm run v3:freeze:measure`).
4. **하네스의 판정 지문 60벌이 전후로 같다.** 고치기 전후의 지문을 글자로
   견주었고(`var/content-qa-final` ↔ `var/content-qa-after2`), 달라진 것은
   판본 칸뿐이다.

**지문에서 응시번호를 뺀 까닭을 적어 둔다.** 처음에는 채점 스냅샷을 그대로
해시했는데, 그 안의 `attempt_id` 는 DB 가 매기는 수라 **같은 응답을 다시
돌릴 때마다 달라진다.** 아무것도 바뀌지 않은 Core 의 지문이 달라진 것으로
읽혔고, 그 상태로는 §20 의 질문에 답할 수 없다.

## G. 아직 아닌 것

- **운영 배포본에서 확인하지 않았다.** 네트워크 정책이
  `app.careermatri.com:443` 을 막는다(HTTP 000). 위의 모든 결과는 이 기계에서
  운영과 같은 배치로 띄워 돌린 것이다.
- **전공자 검토는 기계가 대신하지 못한다.** 용어 받침 63개가 그 전공에서
  맞는 말인지와, 받침이 더 필요한 자리가 어디인지는 그 전공을 아는 분이 본다.
- 규준도 인지 면접도 없으므로 `검증된 검사` 로 팔지 않는다.

| 판정 모듈 git diff | 빈 줄 (`scoring/` · `result/build.ts` · `result/model.ts` · `response-count.ts`) |
| 하네스 판정 지문 60벌 | **60 / 60 글자까지 같다** · 다섯 벌(`final` ↔ `after2` ↔ `after3` ↔ `after4` ↔ `after5`) |

**하네스의 판정 지문이 재는 것을 적어 둔다.** 이 지문은 **문장을 고치는
동안 판정이 흔들리지 않는가**를 센다. 다섯 벌을 글자로 견주었고, 그 사이에
결과지 문장이 세 번 실제로 바뀌었다(할 일 되풀이 · 칸 되풀이 · 다리 문장). 고치기 전 기준선(`var/content-qa-before`)은
**지문에 응시번호가 들어 있던 때라** 그 수와는 견줄 수 없고, 그 자리의
증거는 위의 세 줄이다.
