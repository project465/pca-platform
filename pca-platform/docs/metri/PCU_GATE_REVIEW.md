# PCU 학생 제품 Gate 검수

실제 화면을 사람이 읽고 **PASS 또는 FAIL 둘 중 하나로만** 적는다.
중간 표현(`거의 PASS` · `Ready 에 가까움` · `Visual Ready`)을 쓰지 않는다.

검수에 쓴 그림은 `docs/metri/shots/polish/{biz,nursing,pubadm}/` 와
`docs/metri/shots/gate/{cs,ee,media}/` 와 `docs/metri/shots/polish/interest-*.png`
이고, 손전화 쪽은 그림만 보지 않고 360 · 390 · 430px 에서 실제로 재었다
(`scripts/lab/interest-metrics.ts`).

## B. §14 이전 회차에서 고쳤는데 다시 FAIL한 항목

세 FAIL 은 전부 이전 회차에서 이미 한 번 고친 자리다. 그래서 문구나 CSS 를
바로 다시 고치지 않고 네 가지를 먼저 적는다.

### 1. 이전 수정에서 무엇을 바꿨는가

- **Result Language**(직전 회차 §2): `근거가 선 영역` → `지금 설명할 재료가
  있는 영역`, `요구 해석`·`직접 판단` → `받은 요청을 바꾼 조건`·`직접 정한
  기준`. 축 코드와 묶음 판정은 그대로 두고 **이름만** 바꿨다.
- **Action**(BF2 회차 §8): 한 문장에 눌러 담던 할 일을 `경험 → 행동 →
  결과물` 두 문장으로 끊었다.
- **Cross-Core**(QA4 §16): Core 마다 영역 이름·산업·역할이 갈리는 것을
  확인하고 통과로 적었다.

### 2. 왜 실제 화면에서는 문제가 남았는가

바꾼 것이 **문자열**이고 구조가 아니었다.

- 축마다 학생이 읽는 문장이 **Core 를 모르는 상수 하나**다
  (`AXIS_NEED_KO` · `OWN_KO` · `FILL_KO` · `ZONE_TITLE_KO`).
- 그 상수 가운데 **영역 사전의 재료를 붙일 수 있는 축에만** 재료가 붙어
  있었다(J3 의 `먼저 정하는 것` · J5 의 `남기는 것` · J6 의 `무엇과
  견주는가`). 나머지 축(J1 · J2 · J4 · J7 · J8)은 재료가 없어 **문장이
  축 이름을 풀어 쓴 말로 끝난다.**
- 그래서 ① 그 말이 상담 자리의 말이 아니고(Result Language) ② 남길
  결과가 없고(Action) ③ Core 를 갈아 끼워도 영역 이름만 바뀐다(Cross-Core).

### 3. 증상 말고 공통 원인

**학생이 읽는 문장을 Core 를 모르는 축 단위 상수 하나로 적어 두고, 영역
사전의 재료를 붙일 수 있는 축에만 붙였다.** 한 결정이 세 Gate 에서 서로
다른 증상으로 나온다. 문구를 다시 쓰면 그 회차만 좋아지고 다음 Core 에서
같은 모양으로 돌아온다.

### 4. 이번 수정 뒤에 무엇으로 검증하는가

`npm run v3:result:copy` 에 **세는 줄 셋**을 더한다. 눈으로 읽어 고치는
자리를 기계가 대신 세게 한다.

1. **남길 결과.** Core 20 × 축 8 의 할 일 문장이 전부 그 Core 의 영역
   사전에 적힌 결과물 이름으로 끝나는가. 0건이면 걸림.
2. **Cross-Core 같은 문장.** 축마다, 영역 이름을 지운 할 일 문장이 두
   Core 사이에서 글자까지 같으면 걸림.
3. **우리 쪽 비유.** `재료` 처럼 학생 화면의 첫 줄로 쓰지 않기로 한 말이
   묶음 이름과 축 이름씨에 들어 있으면 걸림.

되돌려 넣어 셋이 실제로 걸리는 것까지 본 뒤에 통과로 적는다.

## C. 고친 것: 증상 셋을 따로 고치지 않고 공통 원인 하나를 고쳤다

**읽는 층만 고쳤다.** 채점 · 문항 은행 · 소유 판정 · 묶음 규칙 · 결과
모델 · 등록부 · DB 스키마 · `open_to_students` 를 한 줄도 건드리지
않았고, 측정 동결이 **기록을 다시 적지 않은 채로** 통과한다.

### 1. 축 문장이 Core 의 재료를 들고 끝난다 (Gate 6 · Gate 9)

`OWN_KO` 와 `FILL_KO` 의 열여섯 줄이 전부 **그 영역 사전에 적힌 결과물
이름**으로 끝난다. 재료를 꺼내는 자리는 `keep(m, i, alt)` 하나이고, 축마다
다른 자리를 집어 한 결과지에서 같은 이름이 되풀이되지 않게 한다.

```
전  최근 재무·투자 판단 과제 하나를 골라보세요. … 왜 그 방법을 골랐는지
    다른 선택과 나란히 적어두세요.                      ← 남길 결과가 없다
후  최근 재무·투자 판단 과제 하나를 골라보세요. … 왜 그 방법을 골랐는지
    다른 선택과 나란히 민감도 표에 적어 두세요.
```

**이름을 지어내지 않는다.** 영역 사전에 결과물이 적혀 있지 않으면
`정리한 문서` 로 내려간다. 그래서 Core 를 갈아 끼우면 이 자리가 함께
바뀐다. 그것이 Cross-Core 에서 영역 이름만 바뀐 같은 문장으로 읽히던
원인이었다.

### 2. 묶음 이름과 축 이름씨를 상담 자리의 말로 (Gate 4)

| 전 | 후 |
|---|---|
| 지금 설명할 재료가 있는 영역 | 지원서에 쓸 수 있는 경험이 있는 영역 |
| 해 봤고 설명할 재료가 더 필요한 영역 | 해 봤고 아직 정리가 덜 된 영역 |
| 아직 이야기할 재료가 적은 영역 | 아직 해 본 일이 적은 영역 |
| 받은 요청을 바꾼 조건 | 받은 요구를 어떤 조건으로 옮겼는지 |

`재료` 는 우리 쪽 비유이고 `받은 요청을 바꾼 조건` 은 관형절이 겹쳐 한
번 읽어 뜻이 서지 않는다. **가리키는 묶음과 축과 판정 조건은 한 줄도
바뀌지 않았다**: 안쪽 코드도, 되짚는 자리에서 쓰는 긴 말도 그대로다.
`받은 요구를 어떤 조건으로 옮겼는지` 는 같은 축의 빈자리 문장
(`AXIS_GAP_KO.J2`)과 상태 문장(`AXIS_SENT_KO.J2`)이 이미 쓰던 말이라,
한 결과지 안에서 같은 축이 세 가지 이름으로 불리던 것도 함께 닫힌다.

### 3. 되돌이 검사 셋 (`npm run v3:result:copy`)

| 줄 | 세는 것 | 되돌려 본 결과 |
|---|---|---|
| 할 일마다 그 영역에서 남길 결과가 적혀 있다 | Core 20 × 축 8 × 2 | J7 을 옛 문장으로 돌리니 Core 18자리가 걸린다 |
| 축 문장이 Core 마다 갈린다 | 축 8 × Core 20 | 고치기 전 상태에서 걸렸다 |
| 묶음 이름과 축 이름씨에 우리 쪽 비유가 없다 | 줄 13개 | `재료` 를 되돌리니 그 줄이 걸린다 |

**세는 자리가 제품과 같은 재료를 받게 했다.** 처음에는 흐름을 빈 값으로
넘겼는데, 그러면 문장이 늘 기본 가지로 떨어져 **제품이 내보내는 문장이
말고 그 가지만** 세게 된다. `build.ts` 와 같은 자리(영역 사전의 흐름
3·4·6·8번)를 꺼내 쓴다.

### 4. 고치지 않고 적어 두는 것

`MEDIA` · `STYLE` · `VISUAL` 세 Core 의 **첫 영역 사전이 같은 결과물
이름을 적고 있다**(`기획서` · `받는 사람을 적은 한 장` · `접은 주제와 그
까닭` · `조사 기록`). 그래서 그 셋 사이에서는 축 문장 다섯 쌍이 글자까지
같다. 고칠 자리는 틀 쪽이 아니고 **그 Core 의 영역 사전**이며, 그 파일은
문항 은행 지문이 덮는 자리라 §12 Freeze 안에 있다. 그래서 이 회차에서
고치지 않고 `v3:result:copy` 가 **보고**로 적는다. Cross-Core Gate 가
견주는 여섯(BIZ · NURSING · PUBADM · CS · EE · MEDIA) 안에는 겹치는 쌍이
없다.

## F. 다음 걸음 (§16)

Student Product Experience 아홉 Gate 가 전부 PASS 이므로 **학생 화면
polish 를 더 하지 않는다.** 이미 PASS 한 화면을 다시 열지 않는다. 다음은
University Operations 이거나 Production Canary 이고, 둘 다 운영 배포본과
학교 담당자 쪽이라 이 회차에서 시작하지 않았다.

**고치지 않고 적어 두는 것 둘.**

1. `MEDIA` · `STYLE` · `VISUAL` 의 첫 영역 사전이 같은 결과물 이름을
   쓴다(위 C-4). §12 Freeze 안이라 건드리지 않았다.
2. `v3:delta` 의 `장문 절이 둘 연속으로 서지 않는다` 가 부록의
   `전체 기술영역`(985px)과 `지역·기관`(862px)에서 걸린다. 둘을 나란히
   세운 것은 직전 회차의 핵심·부록 분리이고 이번 회차의 diff 는
   `result/page.tsx` 를 한 줄도 건드리지 않았다. 고치려면 결과지 절
   차례를 바꿔야 해서 `RESULT_UI_VERSION` 을 올릴 별도 회차다.
