# BIZ Evidence — 표현 구조를 처음부터 다시 세웠다 (R8)

데이터는 그대로이고 표현 구조만 버렸다. 문항 은행 · 채점 · 소유 판정 ·
묶음 규칙 · 결과 모델 · 등록부 · `student_open` · DB 스키마를 한 줄도
건드리지 않았고 `v3:freeze:measure` 가 **기록을 다시 적지 않은 채로**
통과한다. 고친 자리는 근거 절(Gate 4)의 DOM 과 CSS 와 그 절이 읽는
문장 resolver 뿐이다.

제출 그림은 `docs/metri/shots/review-loop/r8-evidence/` 여섯 장이다.

---

## A. 왜 덧칠을 멈췄는가

앞 회차까지 이 절은 **같은 크기의 흰 카드 둘**이었다. 둘이 같은 내부
차례와 같은 label 자리와 같은 cyan 활용 묶음을 들고 나란히 서면, 색과
둥글기를 바꿔도 읽는 사람은 그것을 `AI 가 한 경험씩 정리해 준 카드 두
장`으로 읽는다. 그래서 padding 과 radius 를 고치는 대신 wrapper 와
grid 와 DOM 차례를 버렸다.

## B. 큰 cyan 면을 없앴다 (§1)

전에는 지원서·면접이 **두 경험 모두에서** 같은 cyan 패널에 담겨 있었고,
그 면이 한 경험에서 가장 큰 덩이라 결과가 답변 카드로 읽혔다.

지금 색이 서는 자리는 셋이다.

- 손에 남은 것 한 줄의 teal 글자
- 먼저 쓸 이야기의 2px teal 눈금 둘
- 같이 쓸 이야기의 작은 teal 이름표 둘

둥근 면은 **한 화면에 하나**다(먼저 쓸 이야기의 `--r-sunk` inset,
radius 16). 같이 쓸 이야기는 금 한 줄로만 갈리고 면이 없다. §3 이 요구한
`강한 둥근 container 최대 1~2개` 가 1개다.

## C. 두 경험이 같은 틀의 변형이 아니다 (§2)

|  | 먼저 쓸 이야기 | 같이 쓸 이야기 |
|---|---|---|
| 가르는 것 | 없음(절의 첫 덩이) | 금 한 줄 |
| 이야기 활자 | clamp 19~23px bold | 한 단 작게 |
| 면 | `--r-sunk` inset 한 벌 | 없음 |
| 이름표 | 문장 **왼쪽** · 2px teal 눈금 | 문장 **위** · teal 소문자 |
| 데스크톱 | `1fr / 20rem` 두 단 | 오른쪽 들여쓰기 · `46rem` |

**50:50 격자를 두지 않는다**(§10): 둘이 같은 무게로 서면 어느 쪽을 먼저
쓰라는 것인지 화면에 없다.

## D. 학생에게 없는 경험을 암시하지 않는다 (§5)

`끝난 뒤 달성률까지 봤다면 …` 은 조건을 달아도 **결과지가 새 행동을
제안하는** 자리가 된다. 근거 절이 적는 것은 이미 한 것이고 새 행동은 할
일 절이 든다. 지원서·면접 문장을 고르신 답 안에서만 세운다: 그 영역에서
먼저 정하는 자리 · 고르신 체크리스트 · 남긴 산출물 · 견준 자리.

## E. 스크롤 차례 (§7)

내가 한 일 → 뭐가 남았는지 → 지원서 → 면접. 이름표는 11px 이고 이야기
활자가 23px 이라 **내용이 label 보다 먼저 읽힌다**.

## F. 재어 본 값

| 자리 | 데스크톱 | 손전화 390 |
|---|---|---|
| 먼저 쓸 이야기 | 168px | 304px |
| 같이 쓸 이야기 | 253px | 345px |

손전화에서 먼저 쓸 이야기가 **한 화면(844px)에 든다**(§13 F).

## G. 자가 질문 A~G

| | 물음 | 답 |
|---|---|---|
| A | cyan 묶음이 아직 ChatGPT 답변 카드처럼 보이는가 | NO — 큰 cyan 면 0개 · 색 자리 셋 |
| B | 경험 1 과 2 가 같은 component 의 변형인가 | NO — C 표 |
| C | label 이 내용보다 먼저 읽히는가 | NO — 11px vs 23px |
| D | 지원서·면접 문장이 실제 근거에서 왔는가 | YES — 고르신 답 넷에서만 |
| E | 상담자가 말할 수 있는 말투인가 | YES — 종결 여덟 가지 |
| F | 손전화에서 경험 1 이 한 화면에 이해되는가 | YES — 304px |
| G | 데스크톱이 손전화를 늘린 것인가 | NO — 비대칭 두 단 |

## I. 고치지 않고 적어 두는 것

`v3:result:copy` 가 보고로 올리는 **영역 사전이 같은 결과물 이름을 쓰는
Core 쌍 여섯**(HEALTH=PUBADM · MEDIA=STYLE · MEDIA=VISUAL …)은 문항 은행
지문이 덮는 자리라 이 회차의 수정 금지 구역 안에 있다. 종이 보고 셋
(마지막 쪽 38~39%)도 같은 까닭으로 그대로 둔다.
