# 장기 확장성 검사 · 엔진을 뜯지 않고 Core 를 더할 수 있는가

## 1. 합격선

> 전기전자와 재료와 화학공학과 경영학과 경제학 Core 를 나중에 더할 때
> **기존 엔진을 뜯지 않고 모듈 추가만으로 확장되는가.**
> 한국에서는 경상과 인문·사회까지 열리고, 글로벌에서는 STEM 만 노출되는가.

말로 답하지 않고 **가짜 Core 둘을 만들어 같은 코드를 그대로 돌렸다.**
`npm run v3:extend` 가 매번 그것을 다시 한다.

## 2. 검사가 하는 일

1. 내용 폴더를 임시 자리에 베낀다.
2. 전기전자(STEM · 영역 **6**개 · 역할 7 · 조직 7)와 경영학(BUSINESS ·
   영역 **5**개 · 역할 6 · 조직 5) Core 를 **데이터로만** 만든다.
3. 등록부에 줄 둘을 더한다.
4. `v3:build` 와 `v3:domains` 와 `v3:items` 를 **한 글자도 고치지 않고**
   돌린다.
5. 시장 정책이 새 Core 를 제대로 가리는지 본다.
6. Core 를 모르게 짜야 하는 파일에 Core 이름이 박혀 있지 않은지 본다.
7. 저장소의 내용 파일이 한 줄도 안 바뀐 것을 지문으로 확인한다.

**영역 수와 역할 수와 조직 수를 일부러 다르게 잡았다.** 열둘과 일곱과
일곱을 코드가 못 박고 있으면 그 자리에서 터진다.

## 4. 깨질 뻔한 자리 셋

검사를 만들면서 실제로 걸린 것이다. 셋 다 고쳤다.

### 4-1. 검사가 파일 이름을 못 박고 있었다

1~4단계 검사가 `me-v3-taxonomy.json` 처럼 이름으로 읽고 있었다. 그대로
두면 두 번째 Core 를 올리는 날 검사를 베껴 쓰게 되고, **베낀 검사 가운데
하나는 반드시 뒤처진다.** 등록부(`src/lib/me-v3/core-registry.ts`)를
만들어 네 검사를 전부 그쪽으로 돌렸다.

그리고 **그 자리가 다시 막히지 않게 금지 낱말 검사를 두었다.** Core 를
모르게 짜야 하는 다섯 파일에서 `me-v3-` 와 `ME_CORE` 와 `TD0x` 와
`ME_V3_DOMAIN` 을 찾는다. 주석은 걷어 내고 본다. 설명에 적는 것은 괜찮고
코드가 읽는 자리에 있으면 안 된다.

### 4-2. 열둘과 일곱을 코드가 못 박고 있었다

`v3:domains` 가 `TD 12 · RF 7 · OC 7` 을 상수로 세고 있었다. 전기전자
Core 는 영역이 여섯이고 경영학은 다섯이라 그대로면 둘 다 걸린다. 세는
기준을 **등록부의 `domain_count` 와 그 Core 의 taxonomy 길이**로 바꿨다.
경계 쌍도 `10 이상` 에서 `영역 수의 80%` 로 바꿨다.

### 4-3. 생성물을 계약에서 먼저 찾고 있었다

처음에는 계약 확인을 빌드보다 먼저 돌려서 `checklists 파일이 없다` 로
걸렸다. **체크리스트는 생성물이라 빌드 전에는 없는 것이 맞다.** 없다고
걸면 거짓 경보가 되고, 거짓 경보를 내는 검사는 그 다음부터 아무도 안 본다.
순서를 바꿨다.

## 5. 이 구조가 보장하는 것과 보장하지 않는 것

| 보장한다 | 보장하지 않는다 |
|---|---|
| Core 를 데이터로만 더할 수 있다 | 그 Core 의 **내용이 좋은가** |
| 영역 수와 역할 수가 달라도 돈다 | 다른 전공의 영역 경계가 맞는가 |
| 시장 정책이 계열을 가린다 | 그 시장에서 팔리는가 |
| 산업팩과 역할팩이 곱으로 늘지 않는다 | 산업 자료가 정확한가 |
| 모듈마다 따로 판본을 올린다 | 올린 판본이 전 판본과 비교 가능한가 |

**마지막 줄이 다음 회차의 숙제다.** Core 판본을 올리면 옛 판본은 읽기
전용으로 잠기고, 두 판본의 결과를 합치지 않는다. 비교가 필요하면 그것은
새로 설계할 일이지 자동으로 되는 일이 아니다.

## 6. Core 를 더할 때 사람이 하는 일

코드는 고치지 않지만 **쓸 것이 많다.** 그 양을 적어 둔다.

| 쓰는 것 | 기계공학 기준 |
|---|---|
| 기술영역과 책임지는 판단 | 12줄 |
| 역할기능과 조직환경 | 7 + 7 |
| 영역 × 축의 수행·소유 조건 | 96칸 |
| 영역별 업무 흐름 여덟 걸음 | 96칸 |
| 영역 × 조직의 성과 이름 | 84칸 |
| 공고 직무명 별칭 | 24줄 |
| 직무 경계 쌍과 구분 질문 | 10쌍 |
| 영역 × 축 체크리스트 | 245 |
| 문항 자리 | 113 |
| 산업팩과 역할팩 | 8 + 7 |

**Core 하나가 작은 일이 아니다.** 구조가 보장하는 것은 그 일이 코드가
아니라 자료 쓰기라는 것뿐이다. 전공을 늘리는 속도는 그 전공을 아는 사람이
쓸 수 있는 속도다.
