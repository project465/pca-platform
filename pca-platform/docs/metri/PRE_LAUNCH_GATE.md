# 출시 전 마지막 점검

학교 담당자에게 열기 전에 닫은 것과, 운영에서 사람이 직접 눌러 봐야
하는 것을 가른다. 이 회차는 새 기능을 만들지 않았고 Item Bank · 채점 ·
소유 판정 · 묶음 · ResultModel · 굳은 결과 · 검사 문항 · 현재 상태
계산 · 다음 행동 · 경험 · 가격 · 이용권 · **DB 스키마**를 한 줄도
건드리지 않았다.

## 1. 상표

`public/brand/careermatri/mark.svg` 하나만 고쳤다. 앞 판본은 고리
하나를 조각내고 한쪽을 비운 모양이라 작게 줄이면 알파벳 C 로 읽혔다.
지금 모양은 가운데를 둘러싼 잎 넷이고, 이웃한 두 잎이 겹치는 자리에만
한 단 짙은 파랑을 두어 포개져 있다는 것을 보인다.

정한 값은 파일 안의 주석에 그대로 적어 두었다. 잎 가운데를 중심에서
32.5 떨어진 대각 네 자리에 두고 반지름 26.5 로 그려서, 잎 끝이 59 까지
나가고 이웃한 두 잎 사이는 36.2 까지만 들어온다. 이 굴곡이 네잎클로버로
읽히게 하는 자리다. 굴곡이 얕으면 둥근 덩이 하나가 되고, 너무 깊으면
잎 넷이 서로 떨어져 네 점으로 흩어진다. 가운데 빈자리는 반지름 11 이라
24px 에서도 메워지지 않는다.

테두리도 stroke 도 바깥 원도 그림자도 두지 않았다. 24 · 32 · 48 ·
128px 과 어두운 바탕 · 흰 바탕 · 회색 바탕에서 뽑은 그림은
`docs/metri/shots/brand/mark-sizes.png` 다.

`npm run v3:brand` 가 세는 것을 바꿨다. 앞서 `<path>` 수를 넷으로 못
박고 있었는데, 그러면 겹친 자리를 그리는 줄을 더하는 날 멀쩡한 상표가
걸린다. 지금 세는 것은 잎이 넷인가 · 겹친 자리가 넷인가 · stroke 를
두지 않았는가다.

## 2. 로그인 시도 제한

없던 것을 더했다. 같은 계정에 틀린 비밀번호를 열 번 잇따라 넣어도 열 번
다 받아 주고 있었다.

| 자리 | 파일 |
|---|---|
| 세고 막는 규칙 | `src/lib/login-throttle.ts` |
| 막는 자리 | `src/lib/auth.ts` 의 `authorize()` |
| 사람에게 하는 말 | `src/app/login/actions.ts` |
| 회귀 검사 | `npm run auth:check` 16절 아홉 가지 |

**막는 자리가 서버다.** 화면에서 단추를 꺼 두는 것은 안내이고,
`POST /api/auth/callback/credentials` 를 직접 두드리는 쪽은 그 화면을
거치지 않는다. 그래서 세고 막는 일을 `authorize()` 안에서 하고, 로그인
화면은 같은 모듈에 물어서 말만 고른다.

**선.** 창은 15분이고 한 아이디에 다섯 번 틀리면 1분, 여덟 번이면 5분,
열두 번이면 15분을 잠근다. 한 자리(IP)에서 쉰 번이면 10분, 백 번이면
30분이다. IP 쪽을 한 사람의 실수로는 닿지 않는 자리에 둔 까닭은 학교
실습실이 한 IP 를 서른 명이 나눠 쓰기 때문이다. 먼저 조이면 그 수업이
통째로 잠긴다.

**계정이 있는지 없는지로 세지 않는다.** 없는 아이디로 틀려도 똑같이
세고 똑같이 막는다. 있는 계정에서만 잠기면 "잠겼다" 는 응답 자체가 그
아이디가 있다는 답이 된다. 아이디와 IP 는 이어 붙여 sha256 로만 들고
있어서 이 과정의 메모리에 누가 언제 틀렸는지가 남지 않는다.

**맞히면 그 아이디의 셈을 지운다.** IP 쪽 셈은 지우지 않는다. 한 사람이
들어왔다는 것이 같은 자리에서 아이디를 바꿔 가며 찍던 일을 없던 것으로
만들지는 않고, 들어온 사람은 이미 지나갔으므로 막히지도 않는다.

**DB 스키마를 바꾸지 않았다.** 셈이 이 프로세스의 메모리에 있다. 앱을
두 벌로 늘리면 두 벌이 따로 세고 다시 띄우면 셈이 0 이 된다. 지금
배포본이 한 벌이라 그대로 두었고, 늘리는 날에는 공용 저장소로 옮긴다.
표를 지금 만들지 않은 까닭은 로그인 실패마다 쓰기가 한 번 늘고, 그
쓰기가 느려지는 날 로그인이 같이 느려지기 때문이다.

**실제로 눌러 본 결과**(떠 있는 배포본에 HTTP 로 직접 보냈다).

| 보낸 것 | 받은 것 |
|---|---|
| 맞는 비밀번호 | 로그인됨 |
| 틀린 비밀번호 일곱 번 | 전부 거절 |
| 잠긴 동안 맞는 비밀번호 | 거절 |
| 잠긴 동안 같은 자리의 다른 계정 | 로그인됨 |
| 없는 아이디 · 있는 아이디+틀린 비밀번호 | 두 응답이 글자까지 같다 |
| 65초 뒤 맞는 비밀번호 | 로그인됨 |

## 3. 운영에서 Owner 가 확인할 열다섯

이 컨테이너의 네트워크 정책이 `app.careermatri.com:443` 을 막아서
배포본을 밖에서 한 번도 열지 못했다. 아래는 사람이 브라우저로 직접
밟아야 하는 차례다. 하나라도 어긋나면 그 줄에서 멈추고 무엇이 어떻게
달랐는지를 적는다.

| # | 자리 | 정상이라면 |
|---|---|---|
| 1 | `https://app.careermatri.com` 접속 | 공개 홈이 뜨고 상표가 네잎클로버다 |
| 2 | 학생 계정으로 로그인 | 작업공간(`/me`)으로 떨어진다 |
| 3 | Home | 현재 상태 · 지금 할 일 · 최근 변화가 선다 |
| 4 | 검사 시작 | 학업 단계를 고른 뒤 첫 문항이 뜬다 |
| 5 | 문항 선택 | 고른 칸이 눌린 채로 남는다 |
| 6 | 이전 · 다음 | 앞 화면의 답이 그대로 있다 |
| 7 | 새로고침한 뒤 돌아오기 | 답이 그대로 있고 풀던 자리로 간다 |
| 8 | 끝까지 풀고 제출 | 완료 화면이 뜨고 두 번 눌러도 결과가 한 벌이다 |
| 9 | 결과 첫 화면 | 지금 확인된 것 · 지금 할 일 · 먼저 채울 것이 선다 |
| 10 | 결과 상세 | 접힌 절이 눌러서 펴지고 내부 코드가 보이지 않는다 |
| 11 | PDF 내려받기 | 종이가 실제로 떨어지고 첫 쪽이 비어 있지 않다 |
| 12 | 작업공간으로 돌아오기 | 결과 기록에 방금 응시가 한 줄로 선다 |
| 13 | 로그아웃 | 계정 화면에서 나가지고 뒤로 가기로 돌아가지지 않는다 |
| 14 | 손전화 390px 실기기 | 가로로 밀리지 않고 아래 띠가 단추를 덮지 않는다 |
| 15 | 틀린 비밀번호 다섯 번 | 여섯 번째에 기다리라는 말이 뜨고 1분 뒤 정상 로그인된다 |

14번은 iPhone Safari 실기기 확인이 남아 있다. 이 컨테이너에서 WebKit 을
내려받지 못해 크로뮴에 iOS 화면과 터치를 씌워서만 봤다.

## 4. 지금 건드리지 않고 적어 두는 것

| 자리 | 무엇 |
|---|---|
| Home 아래 여백 | 마지막 묶음 아래가 한 뼘 넓다 |
| PDF 생성 안내 문구 | 안내 줄과 단추 사이 간격이 다른 자리와 다르다 |
| 상표 동결 | `mark.svg` 자체는 어느 동결 목록에도 없다. 지키는 것은 `v3:brand` 가 실제 렌더에서 세는 쪽뿐이다 |
