# ME_V3 문항 설계 · 읽는 순서

6단계에서 쓴 것은 **실제 문항 문면**이다. 앞 단계(`53_v3_*` · `54_arch_*`)가
자리와 축과 결과 배선을 정했고, 여기서 그 자리에 들어갈 문장을 썼다.

**문항 은행은 `sites/pca-platform/content/me-v3-items.json` 하나다.**
문서의 표는 거기서 읽어 온 것이고, 고칠 곳은 은행이다.

| 문서 | 무엇 |
|---|---|
| `55_items_01_bank.md` | 최종 문항 수와 구성 · 자리 113개와의 대응 · 등급별 구조 |
| `55_items_02_domain_qa.md` | **기술영역 열둘의 수동 검토표.** `npm run v3:qa` 가 만든다 |
| `55_items_03_packs.md` | 산업 여덟 · 역할 일곱의 추가 문항과 그 문항이 하는 일 |
| `55_items_04_routing.md` | 학위와 계열에 따라 실제로 받는 문항 |
| `55_items_05_qa_result.md` | 자동 검사 스물셋과 사람 여덟 벌의 결과 |
| `55_items_06_open.md` | 전공자 검토가 필요한 자리와 다음 구현 단계 |
| `56_me_v3_expert_review.md` | **전공자 검토용 묶음.** 문항 백여든아홉과 검토 칸 |
| `57_v3_scoring_00_index.md` | 다음 단계. 이 문항을 판단으로 바꾸는 엔진 |

보고 항목과 문서의 대응이다.

| 항목 | 자리 |
|---|---|
| A 최종 문항 수와 구성 | `01_bank` 1절 |
| B 문항 자리 113개와 문항의 대응 | `01_bank` 2절 |
| C 등급별 구조 | `01_bank` 3절 |
| D 기술영역 열둘 표 | `02_domain_qa` 전체 |
| E 산업팩 여덟 | `03_packs` 1절 |
| F 역할팩 일곱 | `03_packs` 2절 |
| G 학위별 routing 예시 | `04_routing` |
| H 자동 QA 결과 | `05_qa_result` 1절 |
| I 사람 여덟 벌 결과 | `05_qa_result` 2절 |
| J 전문 검토가 필요한 문항 | `06_open` 1절 |
| K 다음 구현 단계 | `06_open` 2절 |

```bash
npm run v3:wording   # 문면 스물일곱 가지
npm run v3:persona   # 사람 열두 벌 · 확인 열여섯 가지
npm run v3:qa        # 검토표와 팩 문서와 전공자 검토 묶음을 다시 만든다
```

2026-10-07 에 **동결 전 품질검사**를 돌렸다. 문면 일흔넷을 다시 쓰고
문항 셋을 나누고 체크리스트 마흔다섯을 더했다. 고친 자리와 까닭은
`55_items_05_qa_result.md` 2절이다.

**이 단계에서 하지 않은 것.** 결과지 renderer 와 V3 채점 코드와 홈페이지
구현을 시작하지 않았고, UI 를 손대지 않았고, 공고 자동수집과 구독과 월간
리포트와 반복결제도 그대로 두었다. 문항 검토가 끝난 뒤에 넘어간다.
