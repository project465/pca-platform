# 결과지 엔진

점수는 산식이 만들고 문장은 따로 만든다는 원칙(설계 원칙 6)을 결과지 쪽에
그대로 세운 구조다. 받은 규격 두 벌을 코드로 옮긴 것이고, 옮기면서 **이
플랫폼에서 지킬 수 없는 부분은 지키지 않는 이유와 함께 적어 뒀다.**

- `CareerMetri Master Writing & Interpretation Specification v2.0`: 문체와 해석
- `CareerMetri Global STEM Report Engine Master Spec v4.0`: 구조와 깊이

---

## 1. 흐름

```
응답
  ↓  assets/engine.js          채점. 손대지 않았다
  ↓  assets/result-json.js     한 가지 모양으로 옮긴다. 점수를 만들지 않는다
  ↓  assets/stage.js           학위 단계가 질문을 바꾼다
  ↓  assets/country.js         목표 국가가 나라별 칸을 연다
  ↓  assets/research.js        연구 수행 근거 (석사 이상)
  ↓  assets/writing.js         문장을 만든다. 레벨은 깊이만 바꾼다
  ↓  app.js · report.js        그린다
  ↓  scripts/writing-check.mjs 금지어·과잉 단정·반복·행동성·등급
     scripts/golden-check.mjs  깨지면 제품을 못 파는 것들
```

**채점은 한 줄도 고치지 않았다.** `engine.js` 의 `CONFIG` 와 산식이 그대로이고,
그래서 전에 응시한 사람의 점수가 달라지지 않는다. 바뀐 것은 그 숫자를 읽는
쪽이다.

## 2. 결과 JSON (`result-json.js`)

화면과 긴 결과지가 **같은 객체**를 읽는다. 둘이 따로 계산하면 같은 응시에
대해 서로 다른 말을 하게 되고, 그 순간 둘 다 못 믿는다.

세 가지를 특히 갈라 뒀다.

**적합도·경험·학습의향을 합치지 않는다.** 셋은 서로 다른 문항에서 온다.
업무 방식 유사도는 250문항, 경험은 증거 문항, 학습의향은 FUTURE 문항이다.
평균을 내면 "커리어 점수" 하나가 남는데 그 숫자로는 아무것도 못 한다.
갈릴 때가 오히려 쓸모 있다. **방식은 가까운데 해본 적이 없으면 지금 할 일은
지원이 아니고 작게 한 번 해보는 것이다.**

**측정 오차와 정보량은 다른 칸이다.** `measurement_error` 는 문항으로 잰
통계값(±12.6 / ±11.7 / ±11.3)이고, `information_coverage` 는 응시자에 대해
우리가 얼마나 아는가다. 한 칸에 담으면 "자료가 적어서 넓은 구간" 과 "문항이
적어서 넓은 구간" 이 구별되지 않는다. 지금은 경험·도구·수강 과목을 묻지
않으므로 정보량이 늘 `low` 로 나오고, 그 사실이 결과지에 그대로 적힌다.

**국적은 담지도 않는다.** 받지 않고, JSON 의 `citizenship_country` 는 늘
비어 있다. 목표 국가만 나라별 칸을 열고, 그것도 확인된 자료가 있을 때만이다.

## 3. 문장 엔진 (`writing.js`)

세 상품이 같은 함수를 부르고 `report_level` 만 다르게 넘긴다. 상품마다 문체를
따로 두면 세 벌을 따로 고치게 되고, 그러면 한 벌은 반드시 뒤처진다.

문장은 네 조각이다.

| 조각 | 무엇 | BASIC | STANDARD | PRO |
|---|---|---|---|---|
| `fact` | 채점에서 그대로 읽히는 것 | ○ | ○ | ○ |
| `interp` | 그 사실이 말할 수 있는 범위까지 | | ○ | ○ |
| `msg` | 가져갈 한 줄 | ○ | ○ | ○ |
| `action` | 지금 할 수 있는 일 | ○ | ○ | ○ |
| `more` | 더 깊은 층 | | | ○ |

조각을 고르는 표가 `PICK` 한 곳에 있다. **레벨 분기를 문장 안에서 하지 않는
것**이 요점이다. 문장마다 `if (level === ...)` 를 넣으면 레벨이 하나 늘 때
모든 문장을 다시 봐야 한다.

### 지키는 것

- 검사가 잰 것만 말한다. 적합·강점·역량 보유·합격 가능성을 쓰지 않는다
- 성향을 사람의 유형으로 규정하지 않는다. 어느 쪽 응답이 많았는지로 쓴다
- 낮은 점수를 능력 부족으로 읽지 않는다. 이번 응답에서 덜 골랐다고 적는다
- 묻지 않은 경험·성과·도구·학위 요건을 지어내지 않는다
- 조언은 셀 수 있는 행동으로 끝낸다

## 4. 학위 단계 (`stage.js`)

같은 점수라도 학부 2학년과 학위 후 연구자에게 할 말이 다르다. 그렇다고
'학생' 을 '연구자' 로 바꿔 끼우면 같은 글이다. 그래서 **질문 자체를 갈랐다.**

| 단계 | 붙들고 있는 질문 |
|---|---|
| 학부 | 어떤 자리를 먼저 시험하고, 졸업 전에 무엇을 남길 것인가 |
| 석사 | 전공과 학위 연구를 어느 자리로 옮길 것인가 |
| 박사 | 연구 깊이가 값을 받는 자리는 어디인가 |
| 학위 후 | 지금 가진 연구 경력을 무엇으로 내세울 것인가 |

단계마다 **값이 되는 근거**와 **무게를 두지 않아도 되는 것**을 따로 적었다.
학부생에게 논문 편수를 묻지 않고, 박사후연구원을 자동으로 선임급으로 읽지
않는다. 직급은 기관과 시장이 정한다.

화면은 다섯 단계(UNDERGRAD·EARLY·MS·PHD·RESEARCH)를 쓰고 규격은 넷을 쓴다.
EARLY 를 bachelor 로, RESEARCH 를 postdoc 으로 접었고, JSON 에는 둘 다 담는다.

## 5. 연구 수행 근거 (`research.js`)

석사 이상에게 "연구 역량이 우수합니다" 는 아무 말도 아니다. 실제로 갈리는
것은 이것이다.

```
RP0 참여      과제에 들어가 있었다
RP1 과업 수행  정해진 기술 과업 하나를 혼자 끌고 갔다
RP2 과제 덩어리 한 덩어리를 맡아 안팎을 맞췄다
RP3 설계 참여  연구계획서 단계부터 들어가 봤다
RP4 총괄      과제 전체나 큰 부분을 끌고 갔다
```

**학위로 이 칸을 짐작하지 않는다.** 박사라서 RP2, 박사후연구원이라서 RP3 로
두면 그 줄은 아무것도 재지 않은 줄이 된다. 사다리와 과제 카드만 내놓고
어느 칸인지는 응시자가 자기 과제를 놓고 고른다.

연구비(B0~B5)와 사람(T0~T4)도 같은 이유로 사다리다. **총액을 아는 것과 쓸
곳을 정해 본 것은 다르고, 인원수는 그 자체로 아무것도 말하지 않는다.**

성과지표·중간 점검·결과물 셋을 가르는 표를 넣었다. 면접에서 이 셋을 바꿔
말하면 과제를 맡아 본 적이 없다는 쪽으로 읽힌다.

**이 값은 직무 적합도에 들어가지 않는다.** 연구 수행 근거와 심리측정은 다른
자리에 있어야 하고, 섞이면 둘 다 못 믿게 된다.

## 6. 직무군과 나라 (`career-families.json` · `country.js`)

내부 id 는 어느 나라 이름에도 기대지 않는다(`ME_DESIGN_PRODUCT`). 거기에
한국어 이름, 영문 이름, **공고에서 찾을 때 쓰는 이름**이 붙는다. "당신의
직함은" 말고 "찾아볼 이름" 으로 내보낸다.

O\*NET SOC 과 ISCO 코드를 적어 뒀지만 `confidence` 가 low~medium 이고,
공식 crosswalk 파일로 대조하기 전까지 **결과지 본문에 코드를 내보내지
않는다.** 대충 맞춘 코드를 숫자로 내보내면 정확해 보이기 때문이다.

규격은 열여섯 갈래를 들었는데 지금 문항이 가르는 것은 여덟 갈래다. 나머지는
`not_yet_covered` 에 적어 두고 화면에 내보내지 않는다. **없는 것을 켜 두지
않는다**(CLAUDE.md 와 같은 규칙).

목표 국가는 아직 묻지 않는다. 그래서 늘 "확인된 자료가 없어 나라별 내용을
넣지 않았다" 가 나간다. 임금·비자·면허를 지어내면 그걸 믿고 움직이는 사람이
생긴다.

## 7. 검사 두 벌

```bash
npm run writing:check   # 금지어·과잉 단정·반복·행동성·등급·지어낸 사실
npm run golden:check    # 깨지면 제품을 못 파는 것들
```

`copy:audit` 과 겹치지 않는다. 저쪽은 **기계가 쓴 냄새**를 센다(대시·대구·
토막 문단). `writing:check` 는 **검사가 재지 않은 것을 단정했는가**를 본다.
"강점을 발휘합니다" 는 한국어로 자연스러워서 `copy:audit` 을 그냥 통과하지만,
재지 않은 역량 보유를 단정하므로 여기서 걸린다.

**부정문은 지나간다.** 규격이 막는 것은 결론이지 그 결론을 막는 문장이
아니다. "합격 가능성을 잰 값이 아닙니다" 까지 세면 고치는 쪽이 경고문을
지우게 된다.

`golden:check` 가 보는 아홉은 전부 한 번씩 깨져 본 적이 있거나 깨지면 제품을
못 파는 것들이다.

| 확인 | 왜 |
|---|---|
| 적합도를 합격 가능성으로 쓰지 않는다 | 이 한 줄이 제품의 법적·윤리적 선이다 |
| 국적을 받지 않고 담지도 않는다 | 받으면 언젠가 쓰이게 된다 |
| 학부와 박사가 다른 질문·다른 절을 받는다 | 같으면 단계 엔진이 있다는 말이 거짓이 된다 |
| 오차 안의 직무만 1군에 든다 | 없는 정밀도를 파는 것을 막는다 |
| 낸 적 없는 경험을 지어내지 않는다 | 가장 비싼 고장이다 |
| 오차와 정보량을 따로 담는다 | 섞이면 둘 다 못 읽는다 |
| 나라 자료가 없으면 주장하지 않는다 | 임금·비자·면허는 틀리면 사람이 손해를 본다 |
| STANDARD 가 BASIC 에 없는 절을 더한다 | 길이만 늘린 상품을 막는다 |
| JS 오류 없음 | |

## 8. 아직 못 한 것

규격이 요구하는데 지금 구조로는 안 되는 것들이다. **되는 척하지 않으려고
적어 둔다.**

**경험을 받는 화면이 없다.** 프로젝트·연구·인턴·도구·수강 과목·논문을 묻지
않아서 `evidence` 가 전부 빈 배열이다. 그래서 규격의 증거 지도(B08·B09·S05·
P04·P05)와 연구 과제 카드(§63~§94)가 **채워진 표가 아니라 빈 양식**으로
나간다. 빈 양식도 쓸모는 있지만 규격이 말한 물건은 아니다. 이걸 켜려면 응시
뒤에 경험 입력 화면이 하나 필요하고, 그 값은 **적합도에 넣지 않는다**는
배선을 같이 해야 한다.

**목표 국가를 묻지 않는다.** 그래서 나라별 층은 전부 "자료 없음" 이다.
켜려면 나라마다 확인된 자료와 확인 날짜가 먼저 있어야 한다.

**직무군이 여덟이다.** 열여섯으로 늘리려면 문항이 그만큼 갈라야 한다. 문항
없이 이름만 늘리면 응시자가 결과지에서 본 이름으로 공고를 찾았을 때 우리가
설명할 것이 없다.

**외부 분류 crosswalk 가 눈대중이다.** O\*NET·ISCO 공식 파일로 대조하지
않았다. 그래서 코드를 화면에 내보내지 않는다.

**영문 결과지가 없다.** `writing.js` 는 한국어 문자열을 들고 있다. 규격 49장이
말한 "개념을 먼저 두고 언어를 뒤에" 구조로 가려면 문장 조각을 개념 id 로
바꾸는 작업이 따로 필요하다. 지금은 영문 금지어만 미리 세고 있다.
