# 결과지 ↔ 입력 Gap Report

날짜 2026-10-08 · **구현 전 설계**

결과지를 버리지 않는다. **거꾸로 읽는다**: 결과지의 문장 하나하나를 보고
`이 문장을 말하려면 어떤 입력이 반드시 있어야 하는가` 를 묻는다.

규칙 둘.
- **입력 없이 만들어지는 절은 없앤다.**
- **문항은 있는데 결과에서 안 쓰는 입력도 없앤다.**

---

## 1 · 결과지 절마다

| 결과 절 | 필요한 입력 | 지금 받는 입력 | 부족한 입력 | 새 문항 |
| --- | --- | --- | --- | --- |
| **첫 화면 · 먼저 볼 영역** | 영역별 관심 · 해 본 정도 | 격자 INT · EXP | 없다 | 아니다 |
| **첫 화면 · 그렇게 본 까닭** | 그 영역을 올린 응답 | 격자 응답 | 없다 | 아니다 |
| **첫 화면 · 지금 해볼 것** | 빈자리 하나 또는 할 일 하나 | 선별 넷 · 심화 여덟 | 없다 | 아니다 |
| **먼저 볼 영역 카드** | 관심 · 해 본 정도 · 배울 뜻 · 영역 워크플로 · 산출물 | 격자 셋 + 영역 사전 | 없다 | 아니다 |
| **열두 영역 묶음** | 영역마다 상태 | 격자 또는 Z1~Z4 | 없다 | 아니다 |
| **여덟 축** | J1~J8 축 수준 | 심화 여덟 | 없다 | 아니다 |
| **근거 · 직접 정한 것** | J3 응답 + 체크리스트 | 있다 | 없다 | 아니다 |
| **근거 · 해 본 일** | J4 응답 | 있다. **다만 도구 사용만 묻는 문항이 넷** | 그 방법에서 무엇을 정했는가 | **REWRITE 4** |
| **근거 · 남긴 것** | J5 응답 + 산출물 칩 | 있다 | 없다 | 아니다 |
| **근거 · 비교한 것** | J6 응답 + 검증 대상 칩 | 있다 | 없다 | 아니다 |
| **채울 것 · 무엇이 비었나** | 축 수준 | 있다 | 없다 | 아니다 |
| **채울 것 · 왜 필요한가** | `GapWhy` 넷 | `REQUIRED_FOR_DOMAIN` · `BLOCKS_EVIDENCE` 만 | **`NEEDED_BY_INDUSTRY` 와 `NEEDED_BY_ROLE` 를 채울 입력이 없다** | **산업·직무를 앞으로 옮기고 BASIC·STANDARD 도 받게 한다** |
| **채울 것 · 다음에 무엇을** | 영역 자료 | 있다 | 없다 | 아니다 |
| **산업 절 · 이 산업이 보는 축** | 고른 산업 + `axis_emphasis` | PRO 만 | **BASIC·STANDARD 에 없다** | 아니다. 자리만 옮긴다 |
| **산업 절 · 내 근거가 어떻게 읽히는가** | 산업 `evidence_reading` + 내 근거 | PRO 만 · 산업당 3줄 | 읽는 규칙이 산업당 3줄뿐 | **산업마다 8~12줄** |
| **산업 절 · 비어 있는 축** | 산업 전문 판단 응답 | PRO 6문항 | **판단 차원 12 가운데 절반이 비었다** | **산업마다 +4~6** |
| **직무 절 · 이 직무가 보는 축** | 고른 직무 + `core_ref` | PRO 만 | **BASIC·STANDARD 에 없다** | 아니다. 자리만 옮긴다 |
| **직무 절 · 같이 놓고 볼 직무** | `compare_with` | 있다 | 없다 | 아니다 |
| **직무 절 · 설비·보전** | RF5 직무팩 | **없다** | **팩 자체가 없다** | **새 팩 7문항** |
| **번역 절** | 열 단계 응답 + 영역 태깅 | PRO 만 | 없다 | 아니다 |
| **다음에 할 일** | 빈자리 또는 영역 `next` | 있다 | **할 일이 0 이 되는 응답이 있다** | 아니다. 결과 모델에서 이미 메웠다 |
| **응답 품질** | 역문항 · 강제 선택 · 일관성 짝 · 체크리스트 어긋남 | 있다 | **역문항이 하나뿐**(CJ_ASSUME_REV) | **영역마다 역문항 하나를 검토** |

## 2 · 받는데 결과에서 안 쓰는 입력

| 입력 | 수 | 지금 쓰임 | 어떻게 할 것인가 |
| --- | --- | --- | --- |
| 일하는 방식 4문항 | 4 | 응답 품질에만 | 둘은 영역 J1·J6 으로 흡수 · 하나는 버림 · 역문항 하나만 남김 |
| **역할 선호 7문항** | 7 | **쓰이지 않는다** | 고르기 2개로 접고 **직무 고르기의 기본값**으로 쓴다 |
| **조직 선호 7문항** | 7 | **쓰이지 않는다** | 고르기 2개로 접고 **결과지 조직 성과 문장**에 쓴다 |
| 학위 분기 4~8문항 | 4~8 | 축 수준만 | 영역에 묶어 근거로도 읽게 한다 |
| 목표 3문항 | 3 | 산업·직무 절 머리말 | **맨 앞으로 옮겨** 장면을 바꾸는 입력으로 쓴다 |

**합 25~29문항이 받고 거의 쓰이지 않는다.** 그 가운데 14개(역할·조직
선호)는 결과지 본문에 한 글자도 나가지 않는다.

---

## 3 · 결과지에서 고쳐야 하는 자리

**결과 UI 는 유지한다.** 다만 세 자리는 입력이 바뀌면 같이 바뀐다.

| 자리 | 왜 |
| --- | --- |
| 산업 절과 직무 절이 PRO 전용인 것 | 산업·직무를 앞으로 옮기면 BASIC·STANDARD 에도 절이 선다. **다만 BASIC 은 `고른 산업` 과 `그 산업이 보는 축` 까지이고 내 근거를 그 말로 읽어 주는 것은 STANDARD 부터다** |
| `GapWhy` 의 `NEEDED_BY_INDUSTRY` | 지금 코드에 있는데 채울 입력이 없어 쓰이지 않는다. 산업을 앞으로 옮기면 그제야 쓰인다 |
| 조직 성과 문장 | 조직 선호를 받아 두고 쓰지 않는다. 받은 값으로 `그 조직에서 이 경험이 무엇으로 읽히는가` 한 줄을 쓴다 |

---

## 4 · 되짚어 확인할 규칙

구현에 들어가기 전에 이 둘을 검사로 세운다.

1. **문항 자리마다 결과 절이 적혀 있고, 그 절이 실제로 그 입력을 읽는다.**
   지금 `v3:items` 가 blueprint 에서 `받고 쓰지 않는 자리 0` 을 세는데,
   **세는 대상이 blueprint 의 메모이지 결과 모델의 코드가 아니다.** 결과
   모델이 실제로 읽는 칸과 대조하도록 고친다.
2. **결과 절마다 입력이 있고, 입력이 없으면 절이 서지 않는다.**
   이번에 `다음에 할 일` 이 머리글만 서는 것을 눈으로 찾았다. 같은 검사를
   모든 절에 건다.
