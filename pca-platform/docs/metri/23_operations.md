# 23. 밤에도 도는 구조

사람이 자는 동안 돈이 들어오려면 네 가지가 사람 없이 돌아야 한다.

1. **팔린다** — 결제나 코드 교환이 승인을 기다리지 않는다
2. **열린다** — 산 사람에게 좌석이나 결과지가 그 자리에서 생긴다
3. **알려진다** — 창을 닫고 간 사람이 결과지가 열린 것을 안다
4. **막힌 것이 눈에 띈다** — 아침에 한 장을 읽으면 무엇이 멈췄는지 안다

1·2 는 이미 있었다(`settlePayment`·`redeemCode`·`openFreeOrder`). 이 문서는
3·4 와, 그것을 어디에 올리는가다.

---

## 한 줄로 무엇이 도는가

```
사람 없이 도는 것                       사람이 필요한 것
─────────────────────────────────      ──────────────────────────
결제 승인 → 좌석·결과지                 PG 가맹점 심사
코드 교환 → 좌석                        환불 송금 (판정은 코드가 한다)
채점 → 결과지                           승인제 회차의 공개 버튼
알림 대기열 → 메일                      응시권 코드를 찍는 일
재고 경고                               도메인
```

오른쪽을 왼쪽으로 옮기는 것이 다음 일이고, 지금 옮길 수 없는 것은
**브리핑에 뜨게 해서 늦어도 하루 안에 사람이 알게** 했다.

---

## 알림은 돈길 옆에 둔다

`src/lib/outbox.ts`. 화면은 **한 줄 적고 지나간다.** 메일 서버가 느린 날
결제가 같이 느려지면, 알림이 매출을 붙드는 셈이다.

- `enqueue()` 는 **던지지 않는다.** 못 적었으면 안 나가는 것으로 끝난다.
  알림 하나 때문에 가입이나 결제가 되돌아가면 안 된다
- **본문을 표에 저장하지 않는다.** 보낼 때 만든다(`compose`). 결과지
  내용이 메일 표로 복사되면 파기가 반쪽이 된다
- **링크에 결과지 번호를 담지 않는다.** 받는 사람이 로그인해서 자기
  목록에서 고른다. 메일은 전달 과정에서 남의 눈에 띌 수 있다
- **세 번 실패하면 포기한다.** 죽은 주소에 매달리면 그 뒤에 줄 선 것이
  안 나간다. 포기한 것은 `failed` 로 남아 브리핑에 뜬다
- 자격증명이 없으면 `held` 로 세고 **그대로 둔다.** 붙는 날 순서대로
  나간다. 보낼 곳이 없어서 접은 `skipped` 와 다른 값이다

적히는 자리 넷.

| 종류 | 언제 | 같은 일로 두 번 안 쌓이는 열쇠 |
|---|---|---|
| `signup` | 가입 직후 | `signup:{user}` |
| `report_ready` | 채점 뒤, **결과지가 실제로 열린 때** | `report_ready:{attempt}` |
| `upgrade_done` | 업그레이드 결제 확정 | `upgrade_done:{order}` |
| `code_low` | 코드 재고가 `CODE_STOCK_MIN` 아래 | `code_low:{상품}:{날짜}` |

### 채점과 공개는 같은 순간이 아니다

개인 결제는 채점이 곧 공개다. 승인제 회차는 담당자가 누를 때까지
학생에게 `"pending"` 이 간다. 채점 직후에 보내면 그 학생은 메일을 받고
들어와 빈 화면을 본다.

그래서 `notifyReportReady(attemptId)` 가 **열렸는지 먼저 확인하고** 적는다.
두 곳에서 부른다 — 제출 직후(승인제면 여기서 접힌다)와 담당자가 공개를
누를 때(`releaseSession` → `notifySessionReleased`). 열쇠가 같아서 두 번
쌓이지 않는다.

### 대기열이 고장 나도 결제는 확정된다

`npm run metri:outbox` 4절이 표를 통째로 치워 놓고 결제를 한 번 돌린다.
여기서 결제가 실패하면 알림이 **새 고장점**이 된 것이고, 그건 자동화가
아니라 고장을 하나 늘린 것이다.

## 밤 당번 둘

**손** — `POST /api/ops/tick`. 몇 분에 한 번 밖에서 두드리면 쌓인 것을
내보내고 코드 재고를 센다. `OPS_TOKEN` 이 16자 미만이면 **그 주소는 열리지
않는다.** 비어 있을 때 통과시키는 쪽으로 기울면, 채우는 것을 잊은 날 그대로
열린 채 운영된다.

앱 안에서 타이머를 돌리지 않는 것은 일부러다. 앱을 두 개로 늘리면 타이머도
둘이 되어 같은 메일이 두 번 나간다. 두드리는 쪽은 `docker-compose.yml` 의
`tick` 컨테이너이고, 클라우드 스케줄러로 바꿔도 코드는 그대로다.

**눈** — 두 벌이다. 화면 `/admin/ops`(운영사 관리자)와 터미널
`npm run metri:ops`. **같은 함수(`src/lib/ops.ts`)를 부른다** — 두 곳에서
따로 세면 숫자가 갈리고, 갈리는 순간 둘 다 못 믿는다.

화면은 **여는 것만으로 아무것도 보내지 않는다.** 새로고침 한 번이 발송
한 번이 되면 안 되기 때문이다. 내보내는 일은 밤 당번이 한다.

```
npm run metri:ops        어제 하루
npm run metri:ops -- 7   최근 7일
```

화면은 `/admin/ops?days=1|7|30`.

담는 것: **사람이 할 일**(맨 위다. 이 화면을 여는 이유가 그것이다) ·
들어온 사람 · 돈(0원 주문은 빼고 센다) · **막힌 것** · 재고 · 대기열 ·
팔 수 있는 상태인가.

| 무엇 | 왜 급한가 |
|---|---|
| 확정 안 된 결제 (1시간 초과) | 이탈이거나 웹훅 누락. 뒤쪽이면 **돈은 들어왔는데 좌석이 없다** |
| 결제됐는데 열린 것이 없는 주문 | 배선 사고. 가장 급하다 |
| 공개를 기다리는 회차 | 학생은 다 풀었고 담당자만 안 눌렀다 |
| 코드 재고 | 떨어지면 밤사이 구매가 **조용히** 멈춘다 |

**다 쓴 상품이 표에서 사라지면 안 된다.** 안 쓴 코드만 세면 마지막 한 장까지
팔린 상품은 행이 없어져 경고도 없이 조용해진다. 재고가 0인 그때가 가장 급한
때다. 그래서 한 번이라도 코드를 찍은 상품을 전부 세고 그중 살아 있는 장수를
센다.

**가짜로 열려 있는 것이 닫혀 있는 것보다 위험하다.** `PAYMENTS_PROVIDER` 가
`portone` 이 아니면 브리핑이 "돈은 들어오지 않는다" 를 붙이고 할 일에 올린다.

## 어디에 올리는가

```
docker compose up -d
docker compose exec -T db psql -U metri metri < db/schema.sql
docker compose exec -T db psql -U metri metri < db/schema_metri.sql
```

- `Dockerfile` — 빌드와 실행을 나눈 두 층. 루트로 돌리지 않고,
  `/api/health` 가 **DB 까지 물어본다.** 프로세스만 떠 있고 DB 가 끊긴
  채 트래픽을 받으면 사는 사람이 결제 직전에 오류를 만난다
- `HOSTNAME=0.0.0.0` 을 못 박는다. 도커는 이 값을 컨테이너 ID 로 채워
  두는데 standalone 서버가 그것을 바인딩 주소로 읽는다
- DB 는 밖으로 열지 않고, 앱은 `127.0.0.1:3000` 에만 붙인다. 도메인과
  인증서는 앞단이 맡는다
- `.env.example` 에 **값을 지어내지 않았다.** 비어 있으면 그 기능이 꺼진다 —
  `PORTONE_*` 가 비면 결제 버튼을 그리지 않고, `MAIL_*` 가 비면 쌓아만 둔다

`docker build` 는 이 작업 환경에 도커 데몬이 없어 돌려 보지 못했다. 대신
`npm run build` 로 나온 standalone 서버를 직접 띄워 `/api/health` 와
`/api/ops/tick`(토큰 없음 401 · 틀린 토큰 401 · 맞는 토큰 200)을 확인했다.

## 아직 사람이 하는 것

| 무엇 | 막는 것 | 하면 열리는 것 |
|---|---|---|
| PG 가맹점 심사 | 개인 카드 결제 전부 | `checkoutReady()` 가 참이 된다 |
| 도메인 | 사이트·플랫폼 배포 | `docs/metri/20_domains.md` 의 두 줄 |
| 환불 송금 | 판정은 코드가 하고 송금만 남았다 | PG 취소 API |
| 메일 자격증명 | 알림이 쌓이기만 한다 | 채우는 순간 순서대로 나간다 |

**앞의 둘이 없어도 오늘 돈을 받는 길은 둘 있다** — 학교 계약(좌석을
계약으로 만든다. 결제가 아예 없다)과 응시권 코드(쇼핑몰에서 팔고 `/redeem`
에서 좌석으로 바꾼다). 둘 다 밤에도 돈다.
