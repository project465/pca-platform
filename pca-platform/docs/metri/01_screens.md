# 화면 설계

프리뷰: `prototypes/metri/index.html` — 아래 화면을 실제로 눌러 볼 수 있게 만들어 두었다.

디자인 토큰은 기존 `mockups/*.html` 을 따른다. 어두운 바탕 + 금색 강조가 플랫폼 정체성이고,
**결과지만 흰 문서로 띄운다** (기존 `CLAUDE.md` 확인된 사실 표).

---

## 0. 전체 지도

```
                         ┌─ 학생 ─────────────────────────────────────┐
로그인 ─→ 트랙 판별 ─→   │  S1 시작   S2 프로필   S3 검사   S4 결과지  │
  │      (계정에 박힘)   │                          S5 Skill Gap       │
  │                      │                          S6 공고·기업       │
  │                      │                          S7 실행 계획       │
  │                      └────────────────────────────────────────────┘
  │
  ├─→ 학과 담당자 ─→  D1 회차   D2 진행현황   D3 단체 리포트(500명 흐름)   D4 처방
  │
  ├─→ 기업 ────────→  C1 인재풀   C2 후보 상세   C3 공고 등록
  │
  └─→ 운영사 관리자 ─→ A1 기관   A2 문항   A3 Skill Graph   A4 JD 파이프라인   A5 검수 큐
```

기존 `CLAUDE.md` 의 화면 목록 12개를 지우지 않는다. 여기 있는 것은 그 위에 붙는 METRI 화면이다.

## 1. 학생 — 공통 앞단

### S1 시작

계정에 트랙이 이미 박혀 있으므로 **학생이 트랙을 고르지 않는다.**
기관이 명단을 올릴 때 학교 유형·학년이 같이 들어오고, 거기서 트랙이 정해진다.
개인 가입자만 여기서 한 번 고른다.

```
┌──────────────────────────────────────────────┐
│  기계공학과 3학년 김○○ 님                      │
│                                               │
│  이번 검사는 38분 걸립니다.                    │
│  중간에 나가도 이어서 볼 수 있습니다.          │
│                                               │
│  1  나에 대한 정보          약 6분  ○         │
│  2  일하는 방식 문항 140개  약 26분 ○         │
│  3  해 본 것 입력           약 6분  ○         │
│                                     [시작]    │
└──────────────────────────────────────────────┘
```

세 단계를 미리 보여주는 이유 — 140문항을 예고 없이 던지면 중도이탈이 난다.

### S3 검사

기존 `mockups/01_test_screen.html` 을 그대로 쓴다. **문항마다 즉시 저장**(설계 원칙),
`responses.elapsed_ms` 를 같이 남긴다(응답 품질 판정용, 3장).

## 2. 학생 — 갈라지는 곳

**검사지는 두 벌뿐이다.** 고교판 하나, 대학판 하나.
아래 네 절은 화면이 네 개라는 뜻이 아니라, 같은 검사지 위에서 결과지가 어떻게 갈리는지다.

### 2-1. 고교 · 진학형 (`HS` + `goal=univ`) — 주로 일반계고

**S2 프로필** — 물어보는 것이 대학생과 다르다.

| 묻는 것 | 왜 |
|---|---|
| 학년, 계열(문·이과 아님 — 선택과목 기준) | 규준 집단 |
| **지금까지 들은 과목과 앞으로 들을 수 있는 과목** | 처방의 단위가 이것이다 |
| 좋아한 수업·싫었던 수업 | 활동 선호의 교차검증 |
| 관심 가는 사물·현상 (택 5) | 산업 선호의 대용 |
| 살고 싶은 지역 | 정주 지표 앞단 |

성적은 **묻지 않는다.** 고1 성적으로 공학 적합을 판정하면 그 결과지는 성적표의 재탕이 되고,
학교가 사지 않는다.

**S4 결과지 — 고교판**

```
┌─ 나에게 맞는 공학 계열 ─────────────────────────┐
│                                                  │
│  기계공학      ████████████░░░░  적합 높음        │
│  전기·전자공학 ██████████░░░░░░  적합 높음        │
│  산업공학      ███████░░░░░░░░░  보통             │
│                                                  │
│  * 점수가 아니라 구간입니다. 지금은 검사 응답만  │
│    있고 아직 해 본 것이 적어서, 숫자로 못 박으면  │
│    틀립니다.                                     │
├─ 왜 기계공학인가 ───────────────────────────────┤
│  설계·구상  ████████████  상위 12%               │
│  해석·계산  ██████████░░  상위 24%               │
│  제작·실험  █████████░░░  상위 30%               │
│  → 이 셋이 높은 사람이 기계공학에서 잘 버팁니다  │
├─ 그래서 무슨 과목을 들어야 하나 ────────────────┤
│  ● 반드시   미적분 · 물리학 · 기하                │
│  ● 권장     역학과 에너지 · 전자기와 양자         │
│  ● 차별화   인공지능 기초 · 데이터 과학           │
│  (학교에 개설 안 된 과목은 공동교육과정 안내)     │
├─ 3년 뒤 이 전공은 어디로 가나 ──────────────────┤
│  기계설계 · CAE · 생산기술 · 로봇 ...             │
│  ↳ 실제 채용공고 1,240건에서 뽑은 직무입니다      │
└──────────────────────────────────────────────────┘
```

마지막 칸이 핵심이다. **고등학생 결과지에 실제 채용공고 통계를 보여준다.**
"이 전공이 좋아요" 가 아니라 "이 전공으로 이런 데를 간다, 근거는 공고 1,240건" 이라고 말한다.
이게 기존 진로검사와 갈리는 지점이다.

### 2-2. 고교 · 취업형 (`HS` + `goal=job`) — 주로 마이스터고·특성화고

**검사는 진학형과 똑같은 문항을 푼다.** 갈리는 곳은 결과지 뒷부분뿐이다.
3년 뒤 취업하는 학생이라 처방의 단위가 다르다.

| 다른 점 | 내용 |
|---|---|
| 직무 후보 | `job_cluster_tracks.track_code='HS'` 인 **고졸 채용이 실제로 있는 직무만** 보여준다 |
| 처방 단위 | 과목이 아니라 **NCS 능력단위 + 국가기술자격** |
| 기업 | 지역 기업을 먼저 보여준다. 대기업 공고를 위에 두면 결과지가 남 얘기가 된다 |
| 선택지 | 취업 경로와 **선취업 후진학 경로를 같이** 보여준다 |

```
┌─ 지금 준비하면 갈 수 있는 자리 ─────────────────┐
│  생산기술·제조엔지니어링   적합 높음             │
│  ↳ 우리 지역 공고 34건 · 고졸 채용 21건          │
│                                                  │
│  반도체·디스플레이 장비    적합 높음             │
│  ↳ 우리 지역 공고 18건 · 고졸 채용 11건          │
├─ 졸업 전에 채워야 할 것 ────────────────────────┤
│  1. 컴퓨터응용가공산업기사   ← 공고 21건 중 14건이 요구
│  2. PLC 프로그래밍 (NCS 1902010305_16v3)          │
│  3. GD&T 도면 해독                               │
│  * 공고에 실제로 적혀 있던 빈도순입니다          │
├─ 두 갈래 ───────────────────────────────────────┤
│  [바로 취업]  위 3개 → 3학년 1학기 현장실습      │
│  [선취업 후진학] 취업 후 기계공학과 → 설계·CAE   │
└──────────────────────────────────────────────────┘
```

### 2-3. 대학생 (`UNIV_LOW` / `UNIV_HIGH`)

**S2 프로필** — 여기서 증거를 받는다. 입력 부담이 이 제품의 최대 이탈 지점이므로 세 가지로 줄인다.

1. **성적표 붙여넣기** — 텍스트로 붙이면 과목 코드/명·학점·성적을 파싱해 `learner_evidence` 로 만든다
2. **소프트웨어 체크** — 전공별로 미리 뽑아둔 목록에서 체크. 자기보고라 신뢰도 0.6
3. **프로젝트·자격·인턴** — 한 개당 3필드(제목·역할·기간)만. 서술형 강요하지 않는다

> 성적표 파싱이 안 되는 학교가 나온다. 그때는 학과가 수강 데이터를 CSV 로 주는 경로를 쓴다
> (기존 명단 업로드와 같은 화면). 학생 한 명이 20분 걸릴 일을 학과가 5분에 끝낸다.

**S4 결과지 — 대학판.** 기존 `mockups/02_student_report.html` 을 확장한다.

```
┌─ 가장 가까운 직무 ──────────────────────────────┐
│  구조·유동 해석 (CAE)        80 (±6)             │
│  항공우주·방산 R&D           73 (±6)             │
│  기계설계                    73 (±6)             │
│                              [▾ 왜 80점인가]     │
│  ┌ 펼치면 ─────────────────────────────────┐    │
│  │ 성향·활동  A 0.786 × 0.30 = 23.6         │    │
│  │ 역량 충족  S 0.818 × 0.40 = 32.7         │    │
│  │ 선호 일치  P 0.803 × 0.15 = 12.0         │    │
│  │ 이력 방향  C 0.800 × 0.15 = 12.0         │    │
│  │                    합계 = 80.3 → 80      │    │
│  └──────────────────────────────────────────┘    │
├─ 채워야 할 것 5개 ──────────────────────────────┤
│  ANSYS Mechanical  보유 2 / 요구 4  ███░░ 필수   │
│  ↳ 공고 132건 중 89건이 요구 (67%)               │
│  ↳ 다음 학기 「전산구조해석 ME412」 로 채운다     │
│  ...                                             │
├─ 지금 지원 가능한 공고 ─────────────────────────┤
│  ○○중공업 구조해석 신입     매칭 84  [지원요건 ✓]│
│  △△모빌리티 CAE            매칭 79  [영어 미달] │
└──────────────────────────────────────────────────┘
```

**"왜 80점인가" 를 반드시 펼칠 수 있게 만든다.** 이유는 두 가지다.
학생이 납득하지 못하면 결과지를 덮고, 학과 담당자가 설명 못 하면 재계약이 없다.

### 2-4. 졸업예정·대학원 (`GRAD`)

직무 적합도는 뒤로 밀고 **공고 단위**로 앞에 낸다. 화면 중심이 S6 이다.
공고별로 `missing_must` 를 먼저 보여주고, 서류에 쓸 문장과 예상 면접 질문을 붙인다.

## 3. 학과 담당자 — D3 단체 리포트

물어본 흐름을 그대로 한 화면에 세로로 쌓는다. **이 화면이 학과가 돈을 내는 이유다.**

```
기계공학과 2026-1학기 · 응시 487 / 대상 500 (97.4%)

① Career Profile 분포     ② 직무 분포              ③ 희망 산업
   설계·구상  ▇▇▇▇▇▇         기계설계      118명       자동차   31%
   해석·계산  ▇▇▇▇▇          CAE           94명        반도체   22%
   제작·실험  ▇▇▇▇           생산기술      81명        방산     12%
   현장·설비  ▇▇▇            품질·신뢰성   64명        ...
   구현·코딩  ▇▇▇▇           로봇·자동화   57명
                              ...                     ⚠ 희망 산업과
                                                      ② 직무의 어긋남
                                                      → 반도체 희망 22%인데
                                                        장비 직무 적합 9%

④ 학과 전체가 모자란 역량 (상위 5)
   GD&T              충족 31%  ← 요구 직무 6개 중 5개가 필수로 요구
   ANSYS Mechanical  충족 38%
   PLC               충족 24%
   기술영어          충족 41%
   Python            충족 52%

⑤ 기업 수요 (공고 1,240건 · 최근 6개월 · 대전권 184곳)
   요구 빈도 상위:  CAD 78%  GD&T 67%  FEA 54%  PLC 48%
   ⚠ ④와 겹치는 칸이 진짜 갭이다 → GD&T, PLC

⑥ 그래서 학과가 할 일
   ● 교과  「기하공차 실무」 미개설 → 2학기 개설 검토 (해당 학생 372명)
   ● 비교과 PLC 3일 캠프 (대상 118명, 지역 A사 장비 대여 협의)
   ● 개인  학생 372명에게 처방 자동 발송
```

설계에서 중요한 것 세 가지.

1. **④와 ⑤를 나란히 놓는다.** 학생이 모자란 것과 기업이 원하는 것이 겹치는 칸만 진짜 갭이다.
   따로 보여주면 담당자가 스스로 교차해야 하고, 안 한다
2. **②와 ③의 어긋남을 경고로 띄운다.** "희망은 반도체인데 적합은 기계설계" 가 학과의 진짜 문제다
3. **5명 미만 칸은 공개하지 않는다** (`cohort_reports.min_cell`). 익명 집계가 개인 식별로 바뀌는 순간
   학생이 응답을 왜곡하고 데이터가 죽는다

### D4 처방 발송

⑥의 각 줄에서 대상 학생 명단을 뽑아 개인 결과지에 처방을 밀어 넣는다.
**집계에서 개인으로 되돌아가는 이 경로가 있어야 흐름이 닫힌다.**

## 4. 기업 — C1 인재풀

```
검색: 직무[구조·유동 해석] 지역[대전·충남] 졸업[2027-02] 필수[ANSYS ≥3]
──────────────────────────────────────────────────
후보 A  매칭 88  기계공학 4학년  ANSYS 4 · ABAQUS 3 · GD&T 4
        정주 의향 ○   프로젝트 3   [열람 요청]
후보 B  매칭 84  ...
```

**개인정보는 열람 요청 → 학생 동의 → 공개** 순서로만 연다.
이름·연락처를 검색 결과에 바로 띄우면 대학이 계약을 끊는다. 기업 매출보다 대학 채널이 크다.

## 5. 운영사 관리자 — A3 · A4 · A5

- **A3 Skill Graph 관리** — 역량·직무·요구 수준·동의어. `data/metri/*.json` 을 화면에서 고치는 것과 같다
- **A4 JD 파이프라인** — 소스별 수집 현황, 실패 건, 라이선스 표시
- **A5 검수 큐** — `skill_candidates`. 공고에 자주 나오는데 사전에 없는 말을 주 1회 사람이 판정한다.
  **이 화면이 없으면 온톨로지가 2년 안에 낡는다**

## 6. 화면별 우선순위

| 순위 | 화면 | 이유 |
|---|---|---|
| 1 | D3 단체 리포트 | 계약을 만드는 화면 |
| 2 | S4 대학 결과지 | 학생이 납득해야 재계약이 된다 |
| 3 | S2 프로필 입력 | 여기서 이탈하면 나머지가 다 무의미 |
| 4 | S5 Skill Gap | 차별화 지점 |
| 5 | A5 검수 큐 | 없으면 데이터가 늙는다 |
| 6 | 고교 결과지 | 시장은 나중, 데이터는 지금 |
| 7 | C1 기업 인재풀 | 학생 수가 임계에 닿기 전에는 팔 게 없다 |

## 7. B2C 전용 화면

학과 계약 없이 들어온 개인 학생이 지나는 길이다. **B2B 화면과 컴포넌트를 공유한다.**

### P1 무료 간이 진단 (12문항 · 5분)

```
┌──────────────────────────────────────────────┐
│  전공만 고르면 5분 안에 방향이 나옵니다        │
│  [기계공학] [전기·전자] [컴퓨터] [고등학생]    │
└──────────────────────────────────────────────┘
        ↓ 12문항
┌─ 결과 ───────────────────────────────────────┐
│  당신에게 가장 가까운 직무                     │
│                                               │
```

설계 의도 세 가지.

1. **1위 직무는 공짜로 다 준다.** 맛보기를 흐리게 가리면 신뢰를 잃는다.
   가리는 것은 "더 있다" 는 것이지 "이것도 못 본다" 가 아니다
2. **잠긴 칸에 숫자를 적는다.** "공고 34건" 처럼 실제 수치를 보여줘야 결제로 넘어간다
3. **학과 계약 경로를 같은 화면에 둔다.** 학교가 이미 계약했는데 학생이 3만 원을 내면 환불 요청이 온다

### P2 결제

카드·간편결제 단건. 구독 아니다. 좌석 차감 모델(`seats`)과 섞지 않고
개인 결제는 `contracts` 없이 `seats` 를 1개 발급하는 형태로 흡수한다 — 테이블을 새로 만들지 않는다.

### P3 개인 마이페이지

`learner_profiles` 하나가 계속 살아 있는 화면. 학기마다 성적표를 다시 붙이면
Skill Profile 이 갱신되고, 변화가 그래프로 남는다.
**이 화면이 재방문을 만든다.** 검사는 한 번이지만 프로파일은 계속 자란다.

### B2C 전환 흐름

```
무료 진단 (12문항)  →  유료 리포트 29,000원  →  마이페이지 재방문
      ↑                                              ↓
학과 계약 학생 500명 ─────────────────────────→ 졸업 후에도 남는 계정
```

**학과 계약이 곧 B2C 획득 채널이다.** 광고로 학생을 사지 않는다.
