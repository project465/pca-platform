# 배재대학교 실제 운영 오픈. 지금 어디까지 왔는가

이 문서가 묻는 것은 `콘텐츠가 다 섰는가` 가 아니다. **실제 학생과
담당자가 지금 쓸 수 있는 상태인가**다. 둘은 다른 질문이고, 이 회차의 답은
한 줄로 갈린다: **자료는 다 섰고 운영에서 확인하지 못했다.**

---

## 0. 상용화 필수 4가지

| | 묻는 것 | LOCAL | 운영 |
|---|---|---|---|
| 1 | 학과 선택 → 검사 시작 | **PASS** | **UNVERIFIED** |
| 2 | 검사 제출 → 해당 전공 결과 | **PASS** | **UNVERIFIED** |
| 3 | PDF 에 학교·학과·전공 | **PASS** | **UNVERIFIED** |
| 4 | 관리자 응시·완료 집계 | **PASS** | **UNVERIFIED** |

**넷 다 운영에서 `UNVERIFIED` 다.** 이 세션의 네트워크 정책이
`app.careermatri.com:443` 을 막는다(게이트웨이가 CONNECT 에 403, 두
호스트 모두 HTTP 000). Railway Shell 권한도 없다. 그래서 운영 DB 와 운영
배포본을 **한 번도 열지 못했다.**

**`FAIL` 로 적지 않는다.** 못 본 것과 깨진 것은 다른 상태이고, 섞으면
둘 다 쓸모가 없어진다(`ops:check` 가 `UNKNOWN` 을 `BLOCKED` 와 가르는
것과 같은 까닭이다). LOCAL 결과는 운영과 같은 배치로 띄워 돌린 것이지만
**운영에 대한 답이 아니다.**

## 1. Production deployment

| 항목 | 값 |
|---|---|
| SHA | `d21a54202456830cfcff3d1cb576d3de5f0330bb` |
| GitHub | 있다. `origin/claude/amazing-thompson-w3f2o2` 가 포함한다 |
| Railway 배포 상태 | **UNKNOWN** |
| DB migration | 이번 commit 에는 스키마 변경이 없다 |

**배포 상태를 모르는 까닭**은 둘이다. 이 세션의 GitHub 도구에
Deployments 를 읽는 자리가 없고, 배포본 주소가 막혀 있어 **밖에서
두드려 확인할 수도 없다.** 그래서 `배포됐다` 고도 `안 됐다` 고도 적지
않는다.

**불필요한 migration 을 돌리지 않았다.** 다만 **이전 배포에서 필요한
migration 이 아직 적용되지 않았을 수 있다**: 이 저장소는 그 모양으로 한 번
깨졌다(`career_profiles` 가 운영에 선 적이 없었다). 운영 컨테이너에서
한 줄로 본다.

```bash
npm run db:verify     # 핵심 표 7/7 · ME_V3 표 5/5 · 내 CareerMatri 5/5
```

세 줄 가운데 하나라도 모자라면 `npm run db:upgrade` 를 한 번 치고 다시
본다. 그 둘은 **운영 이미지 안의 스크립트**이고 저장소 쪽 것과 다르다.

**`ASSESSMENT_READY` 가 `열렸다` 는 뜻이 아니다.** 그 값이 말하는 것은

전부 `false` 다.

**어느 Core 도 `validated` 가 아니다.** 이번 공개의 뜻은
`ASSESSMENT_READY` 이고, 학술적 신뢰도·타당도 검증은 별도다. 규준도
percentile 도 적합도 % 도 합격 가능성도 내지 않는다.

## 3. Campus 정책: PRO ONLY

개인 B2C 는 BASIC·STANDARD·PRO 셋을 그대로 판다. 학교 진입만 다르다.

| 재는 것 | 결과 |
|---|---|
| 서버 함수에 BASIC·STANDARD·PRO 를 넣는다 | 셋 다 **PRO 로 열린다** |
| 개인 응시는 받은 등급이 그대로인가 | 셋 다 **그대로다** |
| 주소에 `?tier=BASIC` · `?tier=STANDARD` | **PRO 응시가 만들어진다** |
| 폼에 숨은 칸 셋(`tier`·`upgrade`·`product_code`) | **PRO 응시가 만들어진다** |
| 시작 화면이 학생에게 등급을 적는가 | **적지 않는다** |
| 학교 종이에 등급 선택 구조가 드러나는가 | Core 열아홉 벌 **0건** |

막는 자리는 `openAttempt()` 하나다(설계 원칙 10). 화면에서 고르는 칸을
없앤 것으로는 모자라다: 폼이나 주소로 넣는 길이 남아 있으면 어느 날 학교
응시 하나가 선별 등급으로 열리고, **그 학생의 결과는 같은 학과의 나머지와
한 표에서 읽히지 않는다.**

## 4. 가장 중요한 안전 조건: 검사가 등록부를 쓰지 않는다

앞 회차에 `pcu:coverage` 가 `open_to_students` 를 잠시 `true` 로 쓰고
되돌리다 **열린 칸을 열여섯 Core 에 남긴 일**이 있었다. 더 나쁜 것은 그
창이 열려 있던 몇 초 동안 **학생에게도 열려 있었다**는 점이다.

**여는 일을 파일에서 환경변수로 옮겼다.**

| | 전 | 지금 |
|---|---|---|
| Core 개방 | `major-cores.json` 을 쓰고 되돌린다 | `V3_PREVIEW_OPEN` (운영에서 거절) |
| 확인용 학교 | `campus-universities.json` 을 쓰고 `.walkbak` | `V3_CAMPUS_FIXTURE` (운영에서 거절) |
| 끝에서 세는 것 | `되돌렸는가` | **`한 바이트도 쓰지 않았는가`** |

걷은 자리 여섯: `core-walk` · `pcu-coverage` · `v3-pdf-audit` ·
`v3-pcu-flow` · `v3-provenance-check` · `campus-walk`.

**한 번 걷는 것으로는 돌아온다.** `v3:majors` 가 `scripts/` 에서 두
모양을 센다: 두 등록부에 쓰는 줄과 `open_to_students` 에 **대입하는**
줄. 되돌려 넣어 보고 둘 다 걸리는 것까지 확인했다.

## 5. PCU Organization

| 항목 | 이 DB (LOCAL) | 운영 |
|---|---|---|
| `organizations` code=`PCU` | **없다** | **UNKNOWN** |
| PCU 담당자(`org_admin`) | **없다** | **UNKNOWN** |

**학생 흐름은 기관 줄 없이도 돈다**: `/campus/pcu` 로 들어온 응시는
`v3_attempts.university_code` 로 묶인다. 기관 줄이 필요한 쪽은 **담당자
화면**이고, 거기서 `organizations.code` 가 `PCU` 여야 그 학생들이 잡힌다.
아니면 담당자가 빈 화면을 보고 **`아직 아무도 안 쳤다` 로 읽는다.**

**운영에서 할 일 둘.** 이 검사가 운영에 만들어 주지 않는다: 담당자
열쇠는 사람이 받는 것이고 그 자리에서 한 번만 보여야 한다.

1. `organizations` 에 `code='PCU'` 한 줄
   (`org_type='university'` · `country='KR'` · `is_demo=false` ·
   `name='배재대학교'`)
2. 그 기관에 `role='org_admin'` membership 하나. **비밀번호는 그 자리에서
   만들어 한 번만 보여 주고 해시만 남긴다**(`make:admin` 과 같은 규칙)

**비밀번호와 credential 을 저장소에 적지 않는다.** 이 문서에도 없다.

## 8. Admin (LOCAL)

`pcu:ops` 20 / 20. 담당자 계정으로 로그인해 `/org/v3` 를 열고 본다.

- 학생 응시의 학교·단과대학·학과·갈래가 **등록부와 맞는다**
- 학교 응시가 **전부 PRO**
- `검사를 시작한 학생` 수가 **DB 와 같다**
- 단과대학 · 학과 · Core 묶음이 선다
- **5명 규칙의 양쪽**: 여섯 명인 학과는 그 수를 내고, 세 명인 학과는
  숫자를 내지 않으며 **0 으로 적지도 않는다**
- 담당자 화면에 **안쪽 코드 0건** · 브라우저 오류 0
- `줄을 세우지 않습니다` 와 `합격 가능성` 을 내지 않는다고 적는다

**세우는 수를 손으로 적지 않는다.** 처음에는 여섯 명을 넣고 화면에 6 이
서는지 봤는데, 그 학과에 앞서 돌린 검사의 응시가 한 줄 남아 있어 화면이
7 을 적었다. **멀쩡한 화면이 걸렸다.** 세는 것은 **DB 의 수와 화면의 수가
같은가**다. 넣은 수는 거기서 아무것도 말하지 않는다.

## 9. 운영에서만 드러날 자리

| | 자리 | 왜 여기서 못 보는가 |
|---|---|---|
| 1 | 배포본이 이 SHA 를 들고 있는가 | 주소가 막혔고 Deployments 를 읽는 도구가 없다 |
| 2 | 운영 DB 가 지금 코드까지 올라와 있는가 | Shell 권한이 없다 |
| 3 | PCU 기관과 담당자 계정 | 운영 DB 를 못 본다 |
| 4 | 종이가 운영 컨테이너에서 뽑히는가 | 운영 chromium 경로는 `[v3-pdf]` 로그 한 줄로만 확정된다 |
| 5 | 쿠키 접두사(`__Secure-`) 아래의 PDF | https 에서만 나는 자리다 |
| 6 | iPhone Safari 실기기 | 이 컨테이너에 WebKit 이 없다 |

## 10. 공개 정책

`open_to_students: true` 는 **운영 smoke 가 PASS 한 Core 부터** 열 수
있다. 이 세션은 운영을 열지 못했으므로 **한 Core 도 열지 않았다.**
배재대 자리를 가리키는 Core 열아홉 벌이 전부 `false` 로 남는다.
자율전공 둘은 기존 전공 탐색 route 그대로다.

## 11. 최종 판정

```
PCU PRODUCTION OPEN BLOCKED
```

막는 것 셋이고 전부 이 세션 밖이다.

1. **네트워크 정책이 `app.careermatri.com:443` 을 막는다.** 운영
   배포본을 한 번도 열지 못했다(게이트웨이 403 / HTTP 000). 푸는 길은
   환경의 Network access 설정이다 —
   https://code.claude.com/docs/en/cloud-environments#network-access
2. **Railway Shell 권한이 없다.** 운영 DB 가 지금 코드까지 올라와
   있는지와 PCU 기관·담당자가 있는지를 **모른다**. 깨진 것이 아니고
   못 본 것이다.
3. **그래서 §10 의 공개 조건을 못 채운다.** 운영 smoke 가 PASS 한 Core
   가 0개이므로 `open_to_students` 를 올릴 근거가 없다.

**`PCU PRODUCTION READY / ALL MAJORS OPEN` 을 적지 않는다.** 운영을
확인하지 못했고 학생 공개가 안 됐다.

사람이 셋을 하면 그 자리에서 판정이 바뀐다: 운영 컨테이너에서
`db:verify` 와 `ops:check` 를 한 번 치고, 밖의 브라우저로 `/campus/pcu`
에서 학과 하나를 골라 종이까지 눌러 보고, PCU 기관과 담당자 계정을
만든다.
