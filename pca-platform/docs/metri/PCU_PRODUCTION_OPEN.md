# 배재대학교 실제 운영 오픈. 지금 어디까지 왔는가

이 문서가 묻는 것은 `콘텐츠가 다 섰는가` 가 아니다. **실제 학생과
담당자가 지금 쓸 수 있는 상태인가**다. 둘은 다른 질문이고, 이 회차의 답은
한 줄로 갈린다: **자료는 다 섰고 운영에서 확인하지 못했다.**

---

## 0. 상용화 필수 4가지

| | 묻는 것 | LOCAL | 운영 |
|---|---|---|---|
| 1 | 학과 선택 → 검사 시작 | **PASS** | **UNVERIFIED** |
| 2 | 검사 제출 → 해당 전공 결과 | **PASS** | **UNVERIFIED** |
| 3 | PDF 에 학교·학과·전공 | **PASS** | **UNVERIFIED** |
| 4 | 관리자 응시·완료 집계 | **PASS** | **UNVERIFIED** |

LOCAL 쪽은 **열린 Canary 자리 하나로** 다시 밟은 값이다(§10). 넷 다
운영에서 `UNVERIFIED` 다. 이 세션의 네트워크 정책이
`app.careermatri.com:443` 을 막는다(게이트웨이가 CONNECT 에 403, 두
호스트 모두 HTTP 000). Railway Shell 권한도 없다. 그래서 운영 DB 와 운영
배포본을 **한 번도 열지 못했다.**

**`FAIL` 로 적지 않는다.** 못 본 것과 깨진 것은 다른 상태이고, 섞으면
둘 다 쓸모가 없어진다(`ops:check` 가 `UNKNOWN` 을 `BLOCKED` 와 가르는
것과 같은 까닭이다). LOCAL 결과는 운영과 같은 배치로 띄워 돌린 것이지만
**운영에 대한 답이 아니다.**

| 항목 | 값 |

| GitHub | 있다. `origin/claude/amazing-thompson-w3f2o2` 가 포함한다 |

**배포 상태를 모르는 까닭**은 둘이다. 이 세션의 GitHub 도구에
Deployments 를 읽는 자리가 없고, 배포본 주소가 막혀 있어 **밖에서
두드려 확인할 수도 없다.** 그래서 `배포됐다` 고도 `안 됐다` 고도 적지
않는다.

**불필요한 migration 을 돌리지 않았다.** 다만 **이전 배포에서 필요한
migration 이 아직 적용되지 않았을 수 있다**: 이 저장소는 그 모양으로 한 번
깨졌다(`career_profiles` 가 운영에 선 적이 없었다). 운영 컨테이너에서
한 줄로 본다.

```bash
npm run db:verify     # 핵심 표 7/7 · ME_V3 표 5/5 · 내 CareerMatri 5/5
```

세 줄 가운데 하나라도 모자라면 `npm run db:upgrade` 를 한 번 치고 다시
본다. 그 둘은 **운영 이미지 안의 스크립트**이고 저장소 쪽 것과 다르다.

## 2. PCU Student Open

| 항목 | 수 |
|---|---|
| 고르는 자리 | 117 |
| 자료가 다 선 자리 | **115** (Assessment Ready 114 + 열린 자리 1) |
| Routing Major (전공 탐색) | **2** |
| 자료가 없어 준비 중인 실제 전공 | **0** |
| 미매핑 | **0** |
| 학생 화면에서 `준비 중` 으로 서는 자리 | **116** (아직 열지 않았다) |
| 학생에게 열린 자리 (`statusOf = READY`) | **1** (Canary) |
| 학생에게 열린 Core | **1** (`BIZ_CORE_V1`) |

`자료가 다 선 자리` 115 는 `Assessment Ready` 114 와 **열린 자리 1** 을
더한 수다. `readinessOf` 가 열린 자리를 `RESULT_READY` 로 한 칸 올려
적어서, 한 자리를 열면 앞엣수가 115 에서 114 로 줄어든다. 그대로 적으면
**자료가 하나 무너진 것으로 읽힌다.**

**`ASSESSMENT_READY` 가 `열렸다` 는 뜻이 아니다.** 그 값이 말하는 것은
**그 Core 의 파일이 다 섰다**까지다.

**여는 칸이 둘이다.** 하나로 두면 **Core 하나를 여는 일이 그 Core 를
가리키는 모든 학과를 한꺼번에 여는 일**이 된다. 경영 Core 하나가 배재대
자리 스물넷을 가리키므로, Core 만으로 열면 smoke 를 돌리려고 스물넷을
동시에 여는 셈이 된다.

| 파일 | 칸 | 정하는 것 |
|---|---|---|
| `major-cores.json` | `open_to_students` | 이 Core 를 팔 수 있는가 |
| `campus-universities.json` | `student_open` | 이 학교의 **어느 자리**에서 여는가 |

`mode: "LEAF"` 면 `leaves` 에 적힌 자리만 열리고, 없거나 `"CORE"` 면 전과
같다. **적지 않은 학교는 전과 같게 둔다**: 그러지 않으면 학교를 더하는
사람이 이 칸을 모르고 모든 자리가 조용히 닫힌다. **미리보기는 이 목록을
보지 않는다.** 그 문은 운영에서 거절되고, 자리 목록까지 요구하면 눌러
보는 검사가 밟을 자리가 없어진다.

**어느 Core 도 `validated` 가 아니다.** 이번 공개의 뜻은
`ASSESSMENT_READY` 이고, 학술적 신뢰도·타당도 검증은 별도다. 규준도
percentile 도 적합도 % 도 합격 가능성도 내지 않는다.

## 3. Campus 정책: PRO ONLY

개인 B2C 는 BASIC·STANDARD·PRO 셋을 그대로 판다. 학교 진입만 다르다.

| 재는 것 | 결과 |
|---|---|
| 서버 함수에 BASIC·STANDARD·PRO 를 넣는다 | 셋 다 **PRO 로 열린다** |
| 개인 응시는 받은 등급이 그대로인가 | 셋 다 **그대로다** |
| 주소에 `?tier=BASIC` · `?tier=STANDARD` | **PRO 응시가 만들어진다** |
| 폼에 숨은 칸 셋(`tier`·`upgrade`·`product_code`) | **PRO 응시가 만들어진다** |
| 시작 화면이 학생에게 등급을 적는가 | **적지 않는다** |
| 학교 종이에 등급 선택 구조가 드러나는가 | Core 열아홉 벌 **0건** |

막는 자리는 `openAttempt()` 하나다(설계 원칙 10). 화면에서 고르는 칸을
없앤 것으로는 모자라다: 폼이나 주소로 넣는 길이 남아 있으면 어느 날 학교
응시 하나가 선별 등급으로 열리고, **그 학생의 결과는 같은 학과의 나머지와
한 표에서 읽히지 않는다.**

## 4. 가장 중요한 안전 조건: 검사가 등록부를 쓰지 않는다

앞 회차에 `pcu:coverage` 가 `open_to_students` 를 잠시 `true` 로 쓰고
되돌리다 **열린 칸을 열여섯 Core 에 남긴 일**이 있었다. 더 나쁜 것은 그
창이 열려 있던 몇 초 동안 **학생에게도 열려 있었다**는 점이다.

**여는 일을 파일에서 환경변수로 옮겼다.**

| | 전 | 지금 |
|---|---|---|
| Core 개방 | `major-cores.json` 을 쓰고 되돌린다 | `V3_PREVIEW_OPEN` (운영에서 거절) |
| 확인용 학교 | `campus-universities.json` 을 쓰고 `.walkbak` | `V3_CAMPUS_FIXTURE` (운영에서 거절) |
| 끝에서 세는 것 | `되돌렸는가` | **`한 바이트도 쓰지 않았는가`** |

걷은 자리 여섯: `core-walk` · `pcu-coverage` · `v3-pdf-audit` ·
`v3-pcu-flow` · `v3-provenance-check` · `campus-walk`.

**한 번 걷는 것으로는 돌아온다.** `v3:majors` 가 `scripts/` 에서 두
모양을 센다: 두 등록부에 쓰는 줄과 `open_to_students` 에 **대입하는**
줄. 되돌려 넣어 보고 둘 다 걸리는 것까지 확인했다.

## 5. PCU Organization

| 항목 | 이 DB (LOCAL) | 운영 |
|---|---|---|
| `organizations` code=`PCU` | **없다** | **UNKNOWN** |
| PCU 담당자(`org_admin`) | **없다** | **UNKNOWN** |

**학생 흐름은 기관 줄 없이도 돈다**: `/campus/pcu` 로 들어온 응시는
`v3_attempts.university_code` 로 묶인다. 기관 줄이 필요한 쪽은 **담당자
화면**이고, 거기서 `organizations.code` 가 `PCU` 여야 그 학생들이 잡힌다.
아니면 담당자가 빈 화면을 보고 **`아직 아무도 안 쳤다` 로 읽는다.**

**운영에서 할 일 둘.** 이 검사가 운영에 만들어 주지 않는다: 담당자
열쇠는 사람이 받는 것이고 그 자리에서 한 번만 보여야 한다.

1. `organizations` 에 `code='PCU'` 한 줄
   (`org_type='university'` · `country='KR'` · `is_demo=false` ·
   `name='배재대학교'`)
2. 그 기관에 `role='org_admin'` membership 하나. **비밀번호는 그 자리에서
   만들어 한 번만 보여 주고 해시만 남긴다**(`make:admin` 과 같은 규칙)

**비밀번호와 credential 을 저장소에 적지 않는다.** 이 문서에도 없다.

같은가**다. 넣은 수는 거기서 아무것도 말하지 않는다.

## 10. 공개 정책과 Canary

**`운영 smoke → open_to_students` 순서가 성립하지 않는다.** 운영에서는
`V3_PREVIEW_OPEN` 이 **설계상 거절**되므로(`appEnv() === "production"` →
빈 목록) 닫힌 Core 는 학과 화면이 `준비 중` 으로 서고 서버가 시작 폼도
거절한다. 닫힌 Core 로는 운영 smoke 를 돌릴 수 없다.

그래서 사업주 결정으로 **자리 하나만** 먼저 연다.

| 항목 | 값 |
|---|---|
| Canary Core | `BIZ_CORE_V1` |
| Canary 자리 | `PCU26_BIZ` (현재 재학생 편제 · 경영대학 · **경영학과**) |
| 검사 가능한 자리 | **1** |
| 같은 Core 의 나머지 자리 | **23 전부 준비 중** |
| 다른 Core | **18벌 전부 `false`** |
| 전공 탐색 | 2 (그대로) |

**2027 편제의 경영학과(`PCU27_BIZ`)도 준비 중이다.** `자리 하나만` 을
글자 그대로 지켰다. 기본 편제가 `PCU_CUR` 이라 실제 학생이 닿는 자리가
열린 쪽이고, 2027 로 판별된 학생은 그 자리를 `준비 중` 으로 본다.

**어느 Core 도 `validated` 가 아니다.** 여는 것이 말하는 것은
`ASSESSMENT_READY` 까지이고, 학술적 신뢰도·타당도 검증은 별도다. 규준도
percentile 도 적합도 % 도 합격 가능성도 내지 않는다. 전공자 검토 묶음은
`docs/metri/BIZ_CORE_V1_REVIEW.md` 이고 **그 판정은 아직 돌아오지
않았다.**

### 되돌리는 길은 한 줄이다

운영 네 걸음 가운데 하나라도 걸리면 `campus-universities.json` 의
`student_open.leaves` 에서 `PCU26_BIZ` 를 뺀다. 그 자리만 닫히고
**나머지 116 자리에는 닿지 않는다.** 그래도 안 되면 Core 의
`open_to_students` 를 `false` 로 내린다.

### 막는 자리는 하나다

학과 목록 · 학과 상세 · 시작 폼 · `openAttempt` 로 가는 길이 전부
`statusOf` 를 지난다(설계 원칙 10). 주소를 손으로 쳐도 폼을 직접 보내도
열리지 않는다.

### Canary smoke (LOCAL · 미리보기 문을 쓰지 않았다)

`var/.serving-preview` 가 **비어 있는** 서버에서 열린 그 한 자리를
끝까지 밟았다. 확인 25가지 · 통과 25 · 걸림 0.

| 걸음 | 결과 |
|---|---|
| 학과 목록에서 검사 가능 | 그 한 자리만 |
| 학과 상세 · 시작 화면 | 학교와 학과 이름 정상 · 안쪽 코드 0 |

**첫 회차에서 한 줄이 걸렸고 그것이 진짜였다.** `자료가 다 서 있다` 가
`ASSESSMENT_READY` 만 받고 있어서, 열린 자리에서 **멀쩡한 자료가
걸렸다.** 운영 공개를 넓힐 때마다 여는 자리마다 같은 자리에서 걸릴
줄이라 둘 다 받게 고쳤다.

### 운영에서 사람이 치고 누를 것

재배포가 먼저다. 고친 것이 전부 이미지 안으로 들어가는 파일이다.

```bash
npm run db:verify     # 핵심 표 7/7 · ME_V3 5/5 · 내 CareerMatri 5/5
npm run pcu:org       # 읽기만. 없으면 APPLY=yes 로 만든다
npm run pcu:open      # 검사 가능이 1자리인지 (변경 후 확인)
npm run pcu:students  # 읽기만. 명단은 `import <파일>` · 실제 발급은 APPLY=yes
npm run pcu:diag      # 읽기만. 종이와 작업공간이 왜 깨졌는지 한 장에
APPLY=yes ROTATE=yes npm run pcu:students rotate <아이디>   # 열쇠만 다시
```

운영 Canary 를 사람이 밟고 남은 넷(학생 신분 · 종이 · 작업공간 · 담당자
집계)은 `docs/metri/PCU_CANARY_P0.md` 에 따로 적었다.

그다음 밖의 브라우저로 네 걸음이다.

| | 누를 것 | 정상이라면 | FAIL 기준 |
|---|---|---|---|
| 1 | `/campus/pcu` → 경영학과 → 검사 시작 | 시작 단추가 서고 응시가 열린다 | `준비 중` 으로 서거나 폼이 거절된다 |
| 2 | 끝까지 답하고 제출 | 경영 영역 이름이 적힌 결과가 선다 | 다른 전공 이름이 서거나 결과가 비어 있다 |
| 3 | 결과에서 종이 받기 | 학교·학과·전공과 응답일이 정상 | 404 · `pdf failed` · 칸이 빈다 |
| 4 | 담당자 계정으로 `/org/v3` | 그 응시가 응시·완료에 잡힌다 | 0 으로 선다 |

**넷 다 PASS 하기 전까지 전체 공개를 하지 않는다.** PASS 하면 BIZ 를
가리키는 자리를 먼저 넓히고(`leaves` 에 열한 자리를 더하거나 `mode` 를
`CORE` 로), 다시 빠르게 확인한 뒤에 PCU 전체 `ASSESSMENT_READY` 자리를
연다.

## 11. 최종 판정

```
PCU PRODUCTION OPEN BLOCKED
```

막는 것 셋이고 전부 이 세션 밖이다.

1. **네트워크 정책이 `app.careermatri.com:443` 을 막는다.** 운영
   배포본을 한 번도 열지 못했다(게이트웨이 403 / HTTP 000). 푸는 길은
   환경의 Network access 설정이다 —
   https://code.claude.com/docs/en/cloud-environments#network-access
2. **Railway Shell 권한이 없다.** 운영 DB 가 지금 코드까지 올라와
   있는지와 PCU 기관·담당자가 있는지를 **모른다**. 깨진 것이 아니고
   못 본 것이다.
3. **그래서 운영 네 걸음을 여기서 밟을 수 없다.** Canary 자리 하나는
   열었지만(§10) 그 자리를 **운영에서** 눌러 본 사람이 아직 없다.

**`PCU PRODUCTION READY / ALL MAJORS OPEN` 을 적지 않는다.** 운영을
확인하지 못했고 학생 공개가 안 됐다.

**다만 막는 성격이 바뀌었다.** 전에는 `닫힌 Core 로는 운영 smoke 를
돌릴 수 없다` 가 함께 막고 있었고 그 자리는 열렸다. 지금 남은 것은
**운영 접근**뿐이다: 재배포하고 §10 의 세 명령을 치고 네 걸음을 누르면
그 자리에서 판정이 바뀐다.
