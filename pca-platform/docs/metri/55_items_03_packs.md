# 산업팩 여덟 · 역할팩 일곱

`npm run v3:qa` 가 만든다. **직접 고치지 말고 팩 원본을 고친다**
(`industry-packs.json` · `role-packs.json`).

**팩은 점수를 바꾸지 않는다.** 하는 일은 셋이다: 그 산업이나 역할이
더 보는 축을 **먼저 설명하고**, 비어 있는 축을 그 분야의 말로 다시
읽어 주고, 견줄 직무를 좁힌다. 축 수준과 영역 묶음과 확인된 축의
개수에는 들어가지 않고, 그것을 `v3:arch` 가 팩 전체에서 `weight` 와
`가중치` 와 `score_delta` 와 `multiplier` 를 찾아 센다.

**한 응시에 산업 하나와 역할 하나까지다.** 그래서 더해지는 응답이
최대 열둘이고, 쉰여섯 조합마다 문항 세트를 만들지 않는다.

## 2. 역할팩 일곱

**역할팩은 기술영역이 아니다.** 역할은 `core_ref` 로 Core 의 영역과
역할기능을 가리키고, 새 축을 만들지 않는다. PM 을 열셋째 기술영역으로
두지 않는 까닭이 그것이다: PM 이 쓰는 판단은 요구 분해(TD11)와 기준
적합(TD10)이고, 역할팩이 더 묻는 것은 **그 자리에서 가진 권한과
범위**다.
