# J. 앞 설계에서 바뀌는 항목 · ME_V2 보존 · 홈페이지 원칙

## 1. `52_rebuild_*` 에서 고쳐지는 자리

앞 회차 설계안은 폐기하지 않는다. 아래 줄만 이번 파일로 갈린다. 적어 두는
까닭은 구현할 때 두 문서가 다른 말을 하면 코드를 쓰는 쪽이 고르게 되기
때문이다.

| 앞 문서 | 그 줄 | 이번에 어떻게 | 왜 |
|---|---|---|---|
| `52_..._06_measurement.md` 2절 | 측정 축 M1~M11 | 판단 축 J1~J8 과 관심·경험·학습 셋으로 재정렬 | 지시 3번의 여덟 가지와 이름을 맞춘다. M10 반복·재사용은 J5 의 L3 조건으로 접었다 |
| 같은 문서 3-1절 | 근거 G 를 0~8 한 가지로 | **S4 와 S8 두 척도로 가른다** | BASIC 에서 네 축만 묻는데 8분모로 적으면 적은 입력이 많이 확인된 것처럼 보인다 |
| 같은 문서 3-2절 | Z1 조건을 `G ≥ 4` 로 | `G8 ≥ 4` **이고 영역별 필수 축 둘이 L2 이상** | 개수만 보면 필수 축이 빈 사람이 Z1 에 들어간다 |
| `52_..._08_tiers.md` 2절 | BASIC 선별 36문항 고정 | `공통 핵심 + 학위·계열 분기` 구조. 응답 54~58 | 지시 2번 |
| 같은 문서 2절 | BASIC 이 Z1~Z4 를 전부 낸다 | **BASIC 에 Z1 을 두지 않는다** | 선별 네 축으로 근거가 섰다고 말할 수 없다 |
| `52_..._09_region.md` 3-1절 | 표 다섯 | **표 여섯**(`industries` 를 더한다) | 산업을 축으로 올리지 않으면 지역과 영역을 바로 이어 자료 없는 교차를 지어낸다 |
| 같은 문서 3-2절 | 판정 넷 | **판정 다섯**(`범위 밖` 을 더한다) | 이동할 수 있는 사람과 못 하는 사람이 같은 안내를 받았다 |
| `52_..._12_plan.md` 3절 | 구현 열 단계 | **열세 단계** | 전공계열 분기와 파일럿 schema 와 보존 잠금이 들어왔다 |
| 같은 문서 1-4절 | 열어 둔 것 여섯 | 셋을 닫았다(심화 영역 수 · 번역 facet 수 · 공통 판단 문항 수) | 이번 파일에서 정했다 |

**그대로 가는 것**도 적어 둔다. 기술영역 열둘과 역할 일곱과 조직 일곱,
별칭표 스물넷, 경계표 열 쌍, 92문항 감사의 판정 일곱, 결과지 절 열 가지,
유지·교체·폐기 목록, 멈추는 선이다.

## 2. ME_V2 를 읽기 전용으로 잠그는 방법

문서에 적는 것으로는 지켜지지 않는다. 넷을 둔다.

| 장치 | 무엇 |
|---|---|
| 지문 대조 | `assessment/ME_V2/*.json` 여덟 벌의 sha256 을 `assessment/ME_V2/FROZEN.json` 에 적고, 검사가 매번 대조한다. 한 글자 바뀌면 실패 |
| 판본 분리 | 새 응시는 `assessment_version = 'ME_V3_DOMAIN_2026'`. 판매 중 상품은 한 판본만 가리킨다 |
| 결과지 경로 분리 | ME_V2 스냅샷은 옛 렌더러로 열린다. 새 렌더러가 옛 결과 객체를 읽지 않는다 |
| 상품 분리 | ME_V2 상품 여섯을 `active = false` 로 내리고 행은 지우지 않는다. 산 사람의 주문이 그 행을 가리킨다 |

검사 이름은 `v2:frozen` 으로 둔다. 실패 문면에 **왜 잠겨 있는지**를 적는다.

> `items-core.json` 이 바뀌었습니다. ME_V2 는 보존 판본이고 이미 응시한
> 분의 결과가 달라지면 안 됩니다. 고칠 곳은 ME_V3 입니다.

### 2-1. 두 판본이 같은 사람에게 가지 않게

| 자리 | 어떻게 |
|---|---|
| 가격표 | ME_V3 상품만 보인다 |
| 이용권 | `entitlements` 가 상품을 가리키고 상품이 판본을 가리킨다 |
| 응시 열기 | 이용권의 판본으로만 연다. 화면이 판본을 넘기지 못한다 |
| `/my` | 옛 응시는 옛 결과지로, 새 응시는 새 결과지로 |
| 재응시 | ME_V2 응시가 있는 사람이 ME_V3 를 사면 **새 응시**다. 결과를 합치지 않는다 |

**두 판본의 결과를 합치지 않는 까닭**은 축이 다르기 때문이다. 직무군
열여섯과 기술영역 열둘 사이에 1 대 1 사상이 없으므로, 합치면 어느 쪽도
아닌 값이 나온다.

## 3. 홈페이지 원칙

2026-10-07 에 내린 것을 다시 넣지 않는다. 목록을 못 박아 둔다.

| 다시 넣지 않는 것 | 왜 |
|---|---|
| 역량 138개 | 실제 자료는 148이고 제품이 그 수를 쓰지 않는다 |
| 직무군 24개를 제품 범위로 | 세 전공 합이고 문항은 기계뿐이다 |
| 채용공고 428건 대조 | `jd_postings` 가 0줄이다 |
| 적합도 100점과 1군·2군 | ME_V3 는 점수와 차례를 내지 않는다 |
| 검증되지 않은 신뢰도·타당도 | 인지 면접과 파일럿 전이다 |
| 지역 기업 수와 적합도 정렬 | `companies` 가 0줄이고 정렬 기능이 없다 |
| 상위 몇 퍼센트 | 규준이 없다 |
| 합격 가능성과 취업 확률 | 재지 않는 값이다 |

### 3-1. ME_V3 가 실제로 내놓는 것만 적는다

홈페이지가 쓸 수 있는 말은 결과 항목 아홉에서 나온다.

| 쓸 수 있는 말 | 근거 |
|---|---|
| 기술영역 열둘 가운데 어디부터 볼지 묶어 드립니다 | 결과 항목 A · B · C |
| 그 영역에서 직접 정하신 것을 이름으로 적어 드립니다 | 결과 항목 E |
| 비어 있는 판단 축의 이름과 채우는 조건을 드립니다 | 결과 항목 G |
| 연구와 프로젝트 경험을 그 영역의 판단으로 옮겨 드립니다 | 결과 항목 H |
| 30일 안에 만들 것 하나를 조건까지 적어 드립니다 | 결과 항목 I |
| 같은 응답이면 같은 결과가 나옵니다 | 재현성 검사 |
| 어느 문항에서 그 판정이 나왔는지 되짚어 보실 수 있습니다 | 되짚기 부록 |

### 3-2. 숫자를 적을 때의 규칙

영역 열둘과 판단 축 여덟은 **제품이 실제로 들고 있는 수**다. 그래서 적을
수 있다. 다만 둘을 곱해 `96가지를 봅니다` 로 적지 않는다. 한 사람이
확인받는 축은 심화 영역 셋에서 스물넷이고, 곱셈으로 늘린 수는 제품이
한 사람에게 하는 일이 아니다.

`claims:check` 에 새 규칙을 더한다.

| 새 금지 | 왜 |
|---|---|
| `영역 \d+ *× *축 \d+` 꼴의 곱셈 | 한 사람이 받는 양이 아니다 |
| `직무 12` · `직무군 12` | 영역 열둘을 직무 열둘로 적으면 공고 직무명과 섞인다 |
| `자리 \d+ *개` 꼴의 지역 일자리 수 | 지역 layer 가 자리 수를 약속하지 않는다 |
| `적성` · `유형 진단` | 이 제품이 내놓는 판정이 아니다 |

## 4. 사업주가 확인해 주실 것 여섯

이번 설계에서 제가 정한 값이고, 바꾸시면 설계가 따라 움직이는 자리다.

| 결정 | 제 안 | 바꾸면 따라 움직이는 것 |
|---|---|---|
| 전공계열 셋으로 충분한가 | 이공계 · 인문·사회·경상 · 기타·융합 | 분기 블록 수와 번역 모듈 수 |
| 인문·사회·경상계열을 1차에 넣을 것인가 | **번역 모듈만** 넣는다. 그 계열의 선별 문항은 다음 판 | 파일럿 집단 구성과 상품 쪽 문면 |
| BASIC 에 Z1 을 두지 않는 것 | 두지 않는다 | 무료 결과의 체감과 전환율 |
| 심화 영역 기본 셋 | 셋. 넷째는 추가 결제 없이 연다 | 소요 시간과 결과지 분량 |
| ME_V1(253문항)의 거취 | 학과 계약이 쓰는지 확인 후 결정. 쓰지 않으면 읽기만 남긴다 | 홈페이지의 학과 결과지 예시 |
| 파일럿을 ME_V2 로 돌리는 것 | 돌린다. ME_V3 구현을 기다리지 않는다 | 파일럿 일정과 분석 축 |

다섯째가 홈페이지와 맞물린다. 지금 홈페이지의 학과 계약 결과지 예시가
ME_V1 의 산출물이라 그대로 두었는데, ME_V1 을 접으면 그 절도 내려야 한다.
