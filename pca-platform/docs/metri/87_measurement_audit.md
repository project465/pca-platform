판본 `ME_V3_2` · 문항 은행 `ME_V3_ITEM_BANK_V2.4` · 판단 `me-v3-scoring.5`

이 회차는 UI 를 다듬는 회차가 아니다. **응답을 받는 방식과 그 응답을 판단으로
바꾸는 방식과 그 판단을 문장으로 내보내는 방식**을 한 묶음으로 다시 보고,

## A. 현재 검사 측정 구조 총평

측정 구조는 **세 층으로 서 있고 그 층이 섞이지 않는다.** 태도(관심·배울
뜻)는 다섯 칸 척도로, 행동(해 본 정도)은 세 칸으로, 소유(누가 정했는가)는
보기 넷으로 받고, 근거(무엇이 남았는가)는 고르기로 받는다. 네 입력이 서로
다른 자가 필요한 신호라서 **한 총점으로 합치는 자리가 코드에 없다**:
스냅샷에 `total` 과 `fit` 과 `overall` 과 `composite` 가 없는지 `v3:scoring`
이 매번 센다.

가장 중요한 구조는 **소유가 응답 하나로 서지 않는다**는 것이다. 보기 넷의
맨 위(`내가 정하고 그 결과가 쓰였다`)를 골라도, 그 축에서 고른 근거가
둘 미만이면 `확인` 까지만 올라간다(`OWNED_EVIDENCE_MIN = 2`). 이것이 자기
보고 검사와 갈리는 자리이고, 실제로 막는지 사람 열세 벌로 돌려 확인했다
(K 절).

이 회차에 찾은 결함은 넷이고, 둘은 고쳤고 둘은 STOP GATE 로 올렸다.

| 결함 | 어디서 찾았나 | 처리 |
|---|---|---|
| 격자 다섯 칸의 말이 한 차원이 아니었다 | 문면과 화면 대조 | 고쳤다 |
| 근거는 있고 관심이 낮은 사람에게 `재료가 모이지 않았다` 고 적었다 | `v3:gaming` C 벌 | 고쳤다 |
| 영역 밖 판단 열둘이 축 여덟으로 접혀 응답 하나가 결과에 안 나왔다 | `v3:measure` MASKED | 고쳤다 |
| `CJ_GIVEN_REV` 의 문면과 보기가 어긋난다 | `v3:measure` 보고 | STOP GATE |
| 산업팩 문항 셋이 그 산업의 조건을 들고 있지 않다 | `v3:measure` DIFFERENT_PACK | STOP GATE |

## C. 다섯 칸 척도를 쓴 영역

**스물넷뿐이고 전부 태도 신호다**: 영역 열둘의 관심 열둘과 배울 뜻 열둘.
보기 문면은 양끝과 가운데가 같은 차원으로 적혀 있다.

```
관심     전혀 관심 없다 / 별로 관심 없다 / 보통이다 / 관심 있다 / 매우 관심 있다
배울 뜻   전혀 배우고 싶지 않다 / 별로 배우고 싶지 않다 / 보통이다 / 배우고 싶다 / 매우 배우고 싶다
```

**격자 칸에 적는 줄인 말을 이 회차에 고쳤다.** 열두 줄 × 다섯 칸에 긴
문장이 들어가지 않아서 칸에는 줄인 말을 적는데, 그 말이
`전혀 · 별로 · 보통 · 관심 · 매우` 였다. **양끝과 가운데는 정도를 말하는데
넷째 칸만 재는 것의 이름**을 말한다. 배울 뜻 격자도 같은 자리가
`배우고 싶음` 이었다. 다섯 칸을 동의 정도 한 차원으로 다시 적었다.

```
전혀 아니다 / 별로 아니다 / 보통이다 / 그렇다 / 매우 그렇다
```

고친 까닭이 하나 더 있다. **좁은 화면에서는 격자 머리의 가운데 셋을
감춘다**(`assessment.css` 의 `visibility: hidden`). 그러면 손전화에서
읽히는 말이 칸의 줄인 말뿐이라, 거기서 품사가 섞이면 응시자가 칸마다 다른
자를 읽는다. 문항 은행의 문면과 저장되는 값(1~5)과 `band()` 가 읽는 법은
한 글자도 바뀌지 않았다.

## D. 다섯 칸 척도를 쓰지 않은 이유

| 신호 | 쓰는 입력 | 다섯 칸을 쓰지 않는 까닭 |
|---|---|---|
| 해 본 정도 | 없다 · 한두 번 · 여러 번 | 횟수이고 수준이 아니다. 다섯으로 늘리면 `expLabel` 이 둘 이상을 한 이름으로 묶으므로 **받고 쓰지 않는 값이 둘 생긴다** |
| 소유 | 없다 · 남이 한 것을 받아 썼다 · 내가 했다 · 내가 정하고 그 결과가 쓰였다 | 네 칸이 **역할의 질적 차이**다. `받아 썼다` 와 `내가 했다` 사이에 중간이 없다 |
| 근거 | 고르기(복수) | 점수를 받지 않고 **무엇이 실제로 남았는가**를 받는다. 해석 모델 · 시험 보고서 · 설계 변경 기록 · 비교 기준 · 측정 결과 가운데 고른다 |
| 산출물·검증 | 보기 넷 + 고르기 | `얼마나 잘합니까` 를 묻지 않는다. 남은 것을 고르고 그것을 누가 정했는지를 보기 넷이 받는다 |
| 기술 판단 | 보기 넷 | 자기평가 다섯 칸을 두지 않는다. 문면이 **그 영역의 실제 장면**을 적고 보기가 소유를 받는다 |

`v3:measure` 가 이 선을 코드로 센다: 다섯 칸을 태도 밖에서 쓰는 문항 0개 ·
경험·소유·산출물·검증에 다섯 칸 0개 · 보기 넷의 문면이 은행 한 자리에서
오는 문항 314개.

## E. `잘 모르겠다` 처리 방식

**수가 아니다.** 문항 은행의 `option_values` 에서 그 자리가 `null` 이라
보기 목록 안에 수가 없고, 어떤 코드도 그것을 가운데 값으로 쓸 수 없다.
`normalize.ts` 의 `read()` 가 `ANSWERED_UNKNOWN` 으로 받고, 빈 것의 뜻
다섯 가운데 하나로 남는다.

세 자리에서 갈리는 것을 실제로 돌려 확인했다.

| 재는 것 | 관심 = 3 | 관심 = 잘 모르겠다 |
|---|---|---|
| 남는 상태 | `NONE_MISSING` | `ANSWERED_UNKNOWN` |
| routing 정렬 열쇠 | 3 | 없음(0 으로 떨어진다) |
| 결과 모델 | 갈린다 | 갈린다 |

**화면에서도 같은 줄에 두지 않는다.** 다섯 단계는 한 줄에 붙여 세우고
`잘 모르겠다` 는 그 뒤에 작게 둔다. 같은 줄에 나란히 두면 `별로 관심 없다`
와 `잘 모르겠다` 가 같은 축의 이웃처럼 읽힌다.

## F. Experience · Ownership 구조

영역마다 셋을 따로 받는다.

```
A 태도    관심(1~5) · 배울 뜻(1~5)
B 행동    해 본 정도(0~2) · 보기 넷(없다 → 받아 썼다 → 내가 했다 → 내가 정했다)
C 근거    고른 체크리스트 · 고른 산출물 · 고른 검증 대상
```

**합치는 자리가 없다.** `관심 5 / 경험 없음` 과 `관심 2 / 근거 충분` 을
사람 두 벌로 돌려 확인했다.

| | 관심 | 묶음 | 머리글 |
|---|---|---|---|
| B 관심만 높다 | 5 | 근거가 선 영역 0개 | 관심 있는 쪽은 또렷하고, 해 본 일이 아직 적습니다 |
| C 근거는 있고 관심이 낮다 | 2 | 관심 낮음 묶음 12개 | 경험 근거는 있고, 지금 관심 우선순위가 낮습니다 |

**C 의 머리글이 이 회차의 고침이다.** 머리글을 정하는 함수가 Z1 과 Z2 와
관심만 보고 **Z3(근거는 있고 관심이 낮은 영역)을 건너뛰어서**, 직접 판단과
산출물과 검증이 전부 확인되고 관심만 낮은 사람이 `아직 판단할 재료가
모이지 않았습니다` 를 받았다. 그 사람에게 가장 틀린 문장이다. 관심과 근거를
합치지 않는다는 원칙이 머리글 한 자리에서 깨져 있었다. 첫 걸음도
`지금 해볼 것` 에서 `먼저 정할 것` 으로 갈랐다: 이미 해 본 사람에게 더
해 보라고 적지 않는다.

보기 넷의 뜻은 `scoring/ownership.ts` 한 자리에 있고, 화면 문면은
`해본 적 없음 · 주어진 조건으로 수행 · 직접 수행 · 조건·기준까지 직접 정함`
이다. **판정에 쓰는 것은 자리 번호뿐**이라 글자를 고쳐도 같은 응답이 같은
수준이다.

## G. 교차검증 구조

확인된 자리는 **종류가 다른 신호 둘 이상**이 받친다.

```
A 응답       `조건·기준까지 직접 정함` 을 골랐다                  보기 넷
B 무엇을 정했나  그 축의 체크리스트에서 실제로 고른 항목               고르기
C 무엇이 남았나  산출물(도면 · 해석 모델 · 시험 결과 · 보고서)          고르기
D 무엇과 견줬나  검증 대상(손계산 · 시험값 · 규격 · 선행 제품)         고르기
```

`axes.ts` 의 `evidenceFor()` 가 세는 근거의 출처가 넷이다: 그 축의 체크리스트 ·
그 영역의 산출물(J5 에서만) · 그 영역의 검증 대상(J6 에서만) · 한 칸에 문항이
둘인 자리에서 둘 다 확인인 경우. **A 하나로는 소유가 서지 않는다.**

실제로 돌려 확인한 것 넷:

- 보기 넷의 맨 위를 전부 고르고 근거를 하나도 고르지 않으면 **근거가 선 영역
  0개 · 소유 축 0칸**
- 근거를 채우면 근거가 선 영역이 생긴다 (막는 것만 세면 산 사람도 막는다)
- 근거가 선 영역마다 갈래 둘 이상이 받친다 (12개 영역 전부)
- 등급을 올려도 같은 응답의 묶음이 오르지 않는다

**산업팩과 역할팩이 하는 일은 다시 읽기다.** 같은 (영역·축)을 그
산업과 직무의 말로 한 번 더 묻고, Core 판정에는 들어가지 않는다. 결과지는
`Core 와 팩이 둘 다 확인한 자리` 를 따로 적는다: 한 경험을 두 쪽 언어로
설명할 수 있는 자리라 지원서에서 먼저 쓴다.

## H. 가짜 교차검증 발견 여부

**닮음 0.5 이상인 쌍 41개를 전수로 분류했다.**

| 갈래 | 쌍 | 뜻 |
|---|---|---|
| EXACT_DUPLICATE | 0 | |
| SEMANTIC_DUPLICATE | 0 | |
| CONSISTENCY_PAIR | 1 | `CN_1A`~`CN_1B`. 같은 뜻을 장면만 바꿔 묻는다 |
| NECESSARY_CROSSCHECK | 0 | |
| DIFFERENT_PACK | 3 | 산업팩이 달라 한 응시에서 같이 서지 않는다 |
| DIFFERENT_CONTEXT | 37 | 영역 격자의 한 줄에 세 어미(관심·해 본 정도·배울 뜻) |

**가짜 교차검증은 0개다.** 다만 적어 둘 것이 둘 있다.

**첫째, 일관성 짝은 교차검증이 아니다.** `CN_1A`(학교 과제)와
`CN_1B`(학교 밖 작업)는 같은 판단을 장면만 바꿔 묻는다. 이것이 하는 일은
응답 품질 표시이고(짝이 2칸 이상 벌어지면 `INCONSISTENT`), 축 수준은 **낮은
쪽**을 쓴다. 근거로 세지 않는다. 이 문서가 이것을 교차검증으로 세지 않은
까닭이 거기 있다.

**둘째, 역방향 문항은 하나뿐이고 그 규칙이 돌지 않는다.** `quality.ts` 의
역방향 짝 규칙이 짝을 `CJ_PROBLEM` 으로 글자로 적어 두고 있었는데 그 번호는
어느 판본의 은행에도 없다. 그래서 `REVERSE_PAIR_AGREED` 가 **한 번도 서지
않았다.** 짝을 은행에서 찾게 고쳤고, ME_V3_2 에는 같은 묶음·축의 정방향
문항이 없어서 규칙은 여전히 돌지 않는다. 그 문항의 척도를 정하는 것이 STOP
GATE 이므로 여기서 짝을 만들지 않았다.
**이 저장소에서 같은 탈이 두 번째다**(앞서 `DEEP-J8`·`PROBE-J4` 가 for 문의
몸통을 영원히 건너뛰게 만들었다). 그래서 `v3:measure` 가 이제 **채점 코드가
글자로 적어 둔 문항 번호가 은행에 있는지**를 센다(파일 37개 · 번호 603개).

## I. Dead item 목록

**받고 쓰지 않는 문항 0개.** 적어 둔 값(`result_section`)을 믿지 않고 실제로
돌려서 셌다. 두 방향으로 센다: 바닥에서 한 칸 올려 결과 모델이 달라지는가 ·
천장에서 한 칸 내려 달라지는가.

| 판정 | 문항 | 뜻 |
|---|---|---|
| LIVE | 368 | 두 방향 다 결과가 달라진다 |
| MASKED | 1 | 올리면 달라지고 내려도 그대로다 |
| DEAD | 0 | 어느 방향으로도 결과가 같다 |

**처음에는 MASKED 가 23개였다.** 천장에서 한 칸만 내리는 방식으로 셌더니
공통 판단 여섯과 학위 묶음 여섯이 전부 걸렸다. 까닭은 결과 모델이 그 열둘을
**축 여덟의 `owned`·`confirmed` 두 불린으로 접고** 있었기 때문이다. 한 축에
문항이 둘인 자리에서는 짝이 가려 응답 하나가 결과지에 한 글자도 돌아오지
않았고, **그 열두 문항이 박사와 포닥이 가장 많이 답하는 자리다.**

고친 자리는 읽는 층이다. `CommonView.items` 에 문항별 소유 수준을 담고
(스냅샷이 이미 들고 있던 값이다) `COMMON_ITEM_KO` 스물아홉으로 사람이 읽는
이름을 붙여 결과지가 고르신 판단을 그대로 되돌려 준다.

```
직접 정하고 그 결과가 쓰였다고 답하신 것
  · 다룰 연구 문제를 직접 좁히기
  · 실험이나 해석의 조건을 직접 정하기
  · 내 결과를 다른 방법으로 얻은 값과 대조하기
```

**축 수준도 영역 묶음도 Z1~Z4 조건도 한 글자 바뀌지 않았다.**
`v3:scoring` 의 사람 열두 벌 지문이 글자까지 같다.

남은 MASKED 하나는 `CJ_GIVEN_REV` 이고 **일부러 문장으로 적지 않는다**:
문면은 선호를 묻는데 보기는 소유 사다리 넷이라, 고른 보기를 문장으로 옮기면
응시자가 하지 않은 주장을 우리가 하게 된다. 축 불린에서는 빼지 않았다
(빼면 판정이 달라지고 그것이 STOP-1 이다).

## J. 중복 위험 문항

H 절의 표가 전부다. **이 회차에 문항을 지우지 않았다.**

주목할 자리는 `DIFFERENT_PACK` 셋이다. 한 응시에서 같이 서지 않으므로
응시자가 같은 질문을 두 번 받는 일은 없지만, **셋 다 어느 산업에 두어도
맞는 일반 기계공학 문장**이라 그 산업의 말로 다시 읽어 주는 자리가 한 칸
빈다. 산업 경력자 검토가 필요해서 STOP-2 로 올렸다.

영역 격자의 37쌍은 중복이 아니다. 한 줄(`요구를 보고 부품의 형상과 치수와
재질과 공차를 정하는 일`)에 어미 셋(`해 보고 싶다` · `해 본 적이 있다` ·
`지금 배우고 싶다`)이 붙은 구조이고, **그것이 태도와 행동과 배울 뜻을
가르는 자리**다. 줄이 같은 것이 설계다.

## N. BASIC 가치

**YES.** 무료 응시자가 `내가 어디부터 탐색할지 알겠다` 고 말할 수 있다.

BASIC 이 내놓는 것: 영역 열둘의 관심 구간 · 해 본 정도 · 배울 뜻 · 네
묶음(지금 해볼 것 · 먼저 볼 것 · 배워 둘 것 · 아직 고르지 않은 것) · 다음
할 일 · 영역 밖에서 확인된 판단.

**근거가 확인됐다는 표현을 두지 않는다.** `allows_evidence_established:
false` 이고 `deep_axes: false` 라서 결과지가 여덟 축 절과 근거 두 층과
비어 있는 자리 절을 세우지 않는다. 등급 안내가 `이 결과는 어느 쪽부터
살펴볼지를 정하는 데까지입니다. 경험을 자세히 확인하는 질문은 아직 받지
않았습니다.` 로 그 사실을 적는다.

**정직하게 적어 둘 한계.** 사람 열두 벌로 돌려 보니 BASIC 에서 서로 다른
할 일 문장이 **5개**다(STANDARD·PRO 는 37개). 네 축만 묻는 등급의 자연스러운
천장이다. 영역 이름이 들어가므로 사람마다 다르게 나오지만, 문장의 꼴은
`짧게 한 번 해보세요` 와 `수업이나 교육을 하나 들어보세요` 둘로 수렴한다.
**12분에 그 이상을 말하려면 근거를 물어야 하고, 그것이 STANDARD 다.**

## O. STANDARD 가치

**YES.** ₩14,900 을 낸 사람이 `내 경험 중 실제로 무엇을 취업 근거로 쓸 수
있고 무엇이 부족한지 알겠다` 고 말할 수 있다.

BASIC 에 없고 STANDARD 에 있는 것: 여덟 축의 이름과 상태 · 근거가 선 영역
판정 · 지원서에 연결할 수 있는 경험 두 층(지금 쓸 수 있는 것 / 설명 재료가
모자란 것) · 비어 있는 자리와 그 자리가 왜 필요한지 · 할 일 37갈래.

경험 → 근거 → 공백의 차례로 읽힌다. 영역 절이 **그 사람이 고른 항목을
그대로 돌려준다**: 직접 정한 것 · 해 본 일 · 남긴 것 · 비교한 것 넷으로
나눠 적어서, 우리가 쓴 해석보다 그 사람의 답이 큰 자리를 차지한다.

비어 있는 자리는 빨간 목록이 아니다. 무엇이 비었는가 · 왜 그 자리가
필요한가 · 다음에 무엇을 하면 메워지는가가 한 묶음이고, 할 일의 재료를
그 영역의 자료(`verify_targets` · `artifacts` · `workflow`)에서 가져온다.

## P. PRO 가치

**YES.** ₩21,900 을 낸 사람이 `내 경험을 원하는 산업·직무의 언어로 바꾸고
지원서/면접 준비 방향까지 잡았다` 고 말할 수 있다.

STANDARD 에 없고 PRO 에 있는 것: 경험 번역 열 단계 · 지원서 초안 문장 ·
고른 산업의 판단으로 다시 읽기 · 고른 직무의 권한과 범위로 다시 읽기 ·
Core 와 팩이 둘 다 확인한 자리 · 목표 직무·산업·조직 입력.

**장식을 얹은 STANDARD 가 아니다.** 한 흐름이다: 내 경험 → 기술 판단 →
직무 언어 → 산업 언어 → 지원서 서사 → 다음 준비. 번역 열 단계는 문제 →
요구 → 내가 정한 것 → 결과를 보고 정한 것 → 방법 → 한 일 → 남은 것 →
견준 것 → 고친 것 → 쓰인 자리 차례로 읽히고, 그 차례가 지원서와 면접에서
말하는 길이다.

**할 일 문장 수는 STANDARD 와 같다**(37갈래). PRO 가 더 파는 것은 할 일의
수를 늘리는 것이 아니다. **같은 경험을 더 깊게 번역하는 것**이고, 그것을 늘리는 자리가
번역 절과 팩 절이다.

## Q. Result explainability

Focus Domain 마다 `왜 이 영역이 나왔나요` 를 되짚을 수 있다. 결과지가
적는 것이 전부 **그 사람의 응답에서 온 값**이다.

| 묻는 것 | 결과지가 적는 자리 |
|---|---|
| 어느 관심 응답에서 | 영역 절의 관심 구간 · 첫 화면 먼저 볼 영역 |
| 어느 경험 응답에서 | 영역 절의 해 본 정도 |
| 어느 소유 수준에서 | 여덟 축 상태(해 본 적 없음 / 참여 / 확인 / 직접 결정) |
| 어느 판단축에서 | 축 이름과 그 축이 묻는 것 |
| 어느 근거에서 | 그 축에서 **고른 항목을 글자 그대로** |
| 어느 산출물에서 | 남긴 것 목록 |
| 어느 검증에서 | 무엇과 견주었는가 목록 |
| 조직 활용 | J8 축 상태와 영역 밖 판단 절 |
| 떨어진 까닭 | 확인된 축이 적음 · 필수 축이 빔 · 산출물이 빔 |

**내부 코드가 한 글자도 나가지 않는다.** `v3:result` 가 사람이 읽는 문장
전부에서 `TD\d\d` · `J[1-8]` · `Z[1-4]` · 밑줄 꼴 식별자를 찾아 0개임을
센다. 번역 열 단계와 영역 밖 판단 스물아홉에 전부 사람이 읽는 이름이 있는
것도 센다.

**굳은 결과를 고치지 않는다.** 결과지는 제출할 때 적어 둔 모델을 그대로
꺼내 그린다. 이 회차에 모델에 칸을 더하면서 **그 전 판본으로 응시한 사람의
결과지가 500 으로 떨어지는 것을 `v3:loop` 가 잡았다.** 없는 칸을 견디게
고치고, `v3:result` 에 **새 칸을 하나씩 지워 보는 검사**를 두었다. 되돌려
보고 실제로 걸리는 것까지 확인했다.

## S. UI 개선 결과

측정에 닿는 자리만 고쳤다.

1. **격자 다섯 칸의 줄인 말을 한 차원으로** (C 절). 문항 은행과 판정은
   그대로다.
2. **영역 밖 판단을 문항별로 세운다** (I 절). 결과지 영역 절 끝에
   `직접 정하고 그 결과가 쓰였다고 답하신 것` 과 `직접 해 보셨다고 답하신 것`
   두 줄이 선다. 줄로 세운 까닭은 문장이 길어서다. 칩은 낱말을 담는 그릇이다.
3. **근거는 있고 관심이 낮은 사람의 머리글과 첫 걸음** (F 절).

캡처로 확인한 것: 검사 화면 98자리 · 결과지 36자리 · 작업공간 21곳 × 폭 셋 ·
폭 열하나 × 확대 셋. 가로 스크롤 0 · 내부 코드 0 · 브라우저 오류 0 ·
가장 낮은 글자 대비 4.78:1 · 누르는 자리 40px 이상.

## V. 인간 전문가 검토가 필요한 것

기계가 셀 수 없는 자리다. 문항 문면이 현실적인가는 응답 분포로도 알 수 없고,
사람이 읽어야 한다.

1. **기계공학 실무자가 볼 때 문항 장면이 현실적인가.** 영역 열둘 × 축 여덟
   96개 문면과 심화 48개. `docs/metri/56_me_v3_expert_review.md` 가 묶음이다
2. **학부·석사·박사·포닥 넷이 같은 문항을 자기 장면으로 읽는가.**
   `stage_wording` 이 붙은 문항에서 네 장면이 다 자연스러운가
3. **보기 둘·셋·넷이 실제로 구분되는가.** `조건이나 기준은 정해져 있었고 그
   안에서 수행했습니다` 와 `직접 수행했고 과정에서 판단에도 참여했습니다` 를
   응시자가 가르는지는 인지 면접에서만 나온다
4. **근거 고르기가 충분하지만 과하지 않은가.** 축 하나에 항목이 둘에서
   여덟까지 있다. 다 읽히는가, 고르기 피로가 어디서 시작되는가
5. **특정 산업 출신에게 편향되지 않는가.** 산업팩 여덟의 문면 여든. 특히
   STOP-2 의 셋은 그 산업의 조건을 들고 있지 않다
6. **문항이 원하는 답을 암시하지 않는가.** `직접 정해 본 적이 있다` 꼴이
   296번 되풀이된다. 그 꼴 자체가 `직접 정했다` 를 권하는지
7. **`CJ_GIVEN_REV` 의 척도**(STOP-1). 선호 문항으로 돌릴지 소유 문항으로
   다시 쓸지
8. **BASIC 의 할 일 다섯 갈래가 받는 사람에게 쓸모 있는가**(N 절)
