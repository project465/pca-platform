# 26. 홈페이지 — 코드로 만든 판과 아임웹으로 옮기는 순서

2026-09-18. 원고는 `sites/imweb/copy.md`, 이미지는 `sites/imweb/media/`.

**코드로 만든 판이 `sites/careermetri/index.html` 이다.** 아임웹 에디터로
옮기지 않고 그대로 배포할 수 있는 한 장이고, 원고는 위 파일과 같은 것이다.
정체성은 CLAUDE.md 를 따랐다 — 딥네이비 바탕에 금색 강조, 결과지만 흰
문서로 띄운다. 화면 캡처 셋(`sites/careermetri/img/`)은 우리 플랫폼에서
실제로 뽑은 기계공학 결과지·학과 리포트·응시 화면이다.

아임웹으로 옮길지, 이 판을 그대로 올릴지는 고르는 문제다. 이 판은 도메인만
붙이면 되고 요금제가 없다. 아임웹은 문의 폼과 결제가 붙어 있다.

아임웹 요금제는 Starter · Pro · Global 셋이고, 개인 도메인은 Starter
이상, 전자결제(PG) 설정도 유료 플랜이다. 상품 수 제한 없이 파는 것은
Pro 다. **수수료율은 확인하지 못했다. 지어내지 않는다.**

## 1. 순서

아임웹은 **기본 도메인(`○○.imweb.me`)으로 먼저 사이트를 만들 수 있다.**
그래서 도메인 구매를 기다리지 않고 페이지부터 짠다. 개인 도메인 연결은
Starter 이상이고, 사이트 개설 시 유료 요금제를 14일 체험할 수 있다.

### 0. 먼저 정할 것 둘 (원고를 붙이기 전에)

원고를 두 번 고치지 않으려면 이 둘이 먼저다.

| 무엇 | 지금 상태 |
|---|---|
| 이름 | 코드는 커리어메트리, 제안서는 METRICAREER |
| 결과지 절 | 제안서 8섹션, 플랫폼 7절 |

가격은 정할 것이 아니었다. 두 값이 서로 다른 것을 가리키고 있었다 (2절 끝).

### 0-0. 제안서 PDF 를 반영했다 (2026-09-18)

`METRICAREER____.pdf` 23쪽을 읽어 사이트에 없던 것 일곱을 넣었다. 앞서 본
docx 보다 내용이 많았다.

| 넣은 것 | 어디에 |
|---|---|
| 추천 대상 3종과 응시 시기 3단 | `14-target` (새 파일) |
| 결과지 8개 섹션의 제목과 담는 것 | `05-result` 슬라이더 |
| 의뢰 기관 리포트 6구성에 "담당자가 쓰는 곳" 열 | `06-cohort` |
| 정주 문항 5개 전문과 지표 3종 | `07-survey` |
| 이공계 14개 학과의 계열·검사명·대상 학과 | `08-majors` |
| 검증 체계 5행 (내용·구성·준거 타당도·신뢰도·측정 동등성) | `11-evidence` |

문항 예시와 결과 예시, 대전광역시 적합도 5행(경영·전략 학생 기준)은 전부
비이공계라 설계 원칙 7 에 걸린다. 학과 표에는 한 줄로만 적었다.

**응시 시간을 제안서 쪽으로 돌렸다.** 앞 절에서 "253문항이니 약 30분" 으로
고쳤는데, 제안서는 같은 문항 구조(직무영역 1개 25문항 × 10)에 15~20분으로
적고 있다. 고객에게 나간 문서가 그쪽이므로 사이트도 약 15~20분으로 맞췄다.
**`marketing/src/content/kr.ts` 는 세 곳에서 "약 30분" 이라고 말한다** — 같은
검사지를 두 값으로 말하고 있으니 한쪽을 정해야 한다.

**www.hari.re.kr.** 제안서 모든 쪽 아래에 이 주소가 있다. 사이트에는 넣지
않았다. 커리어메트리와 어떤 관계인지(같은 주소를 쓸지, 새 도메인으로 갈지)
정해지지 않았다.

### 0-1. 비즈니스 홍보 템플릿을 골랐으면 바탕을 밝게 쓴다

이 템플릿은 머리글과 하단이 밝다. 거기에 어두운 본문을 얹으면 페이지가
밝고 어두운 띠로 번갈아 끊겨 보인다. 그래서 `sites/careermetri/imweb/` 의
CSS 를 밝은 바탕으로 다시 세웠다 — 딥네이비는 활자로 쓰고, 어두운 띠는
`01-hero` 한 장만 남겼다.

글자 대비를 재서 골랐다. 본문 `#0F1B2D` 17.3:1, 보조 `#4F6076` 6.4:1.
**금색 `#C9A227` 은 흰 바탕에서 2.4:1 이라 글자로 쓸 수 없다.** 채움과
괘선에만 쓰고, 글자로 쓸 때는 `#7A6214`(5.9:1) 를 쓴다. 이전 CSS 는 금색을
글자로 쓰고 있었고, 학과 표의 "운영 중" 에는 인라인으로 박혀 있었다.

기계로 쓴 듯한 판을 셋 걷었다.

- 절마다 똑같던 `mono·대문자·자간·화면 끝까지 늘어나는 괘선` 머리 →
  이름 위에 30px 금색 괘선 한 줄로 바꿨다. 열두 번 반복되면 그 자체가 틀로
  읽힌다. 한글에 `text-transform:uppercase` 는 애초에 아무 일도 안 했다
- **순서가 아닌 것에 붙은 번호를 뗐다.** `02-problem` 의 01~04 는 나란히
  있는 과제였고, `09-region` 의 "기준 01~03" 은 아래 제목과 이름이 겹쳤다.
  번호는 `운영 절차` 에만 남았다 — 거기서는 순서가 뜻을 갖는다
- 한 절 안의 둘째 머리를 `cm-sublabel` 로 내렸다. 절 머리와 같은 모양이면
  위아래가 같은 단으로 읽힌다

셋은 눈으로 본 것이 아니라 렌더해서 잡았다: 숫자 칸 머리글이 자기 칸과
어긋나 있었고, 절차 설명이 이름 길이만큼 들쭉날쭉했고, 히어로에서 금색으로
강조한 말이 줄 끝에서 쪼개졌다.

`index.html` 은 어두운 채로 남겼다. 혼자 서는 한 장이라 맞출 상대가 없다.

### 0-2. 어투를 기관 문서로 바꿨다

먼저 만든 판은 스타트업 랜딩페이지였다. 읽는 사람은 대학 취업지원팀·RISE
사업단 담당자인데, 그 사람은 읽고 팀장에게 넘길 자료를 찾는다. 기계로 쓴
티는 활자가 아니라 짜임에 있었다.

- 절마다 `작은 라벨 → 큰 문장형 제목 → 한 줄 리드 → 칸 그리드` 가 열두 번
  똑같이 반복됐다
- 제목이 전부 수사였다. "검사는 했는데 그 다음이 없습니다" · "두 개의 자로
  잽니다" · "학생에게 한 권, 학과에 한 장"
- 히어로에서 한 구절만 금색으로 물들이는 판, 인용구, 큰 숫자 타일(19/42/13,920)

셋을 걷고 명사형 제목과 사양 표로 바꿨다. 숫자 타일은 표로 내렸다 — 담당자는
숫자를 크게 보는 것보다 출처와 기준일이 붙은 줄을 원한다.

### 0-3. 모서리는 규칙으로 섞는다

**금색이 닿는 면과 선은 각지게, 회색 선으로 둘러싼 그릇은 둥글게.** 섞는 것을
규칙으로 두면 취향이 아니라 짜임이 된다.

### 0-4. 옆으로 넘기는 판

`05-result`(결과지 8섹션)와 `16-screens`(주요 화면 3장)에 넣었다. 배선은 Head
Code 에 한 번만 있고 위젯에는 마크업만 있다. `scroll-snap` 이라 스크립트가
죽어도 손가락으로는 넘어가고, `MutationObserver` 로 아임웹이 늦게 심는 위젯도
잡는다. 브라우저에서 단추를 눌러 `scrollLeft 0 → 290` 과 점 이동까지
확인했다.

### 0-5. 약관 셋을 썼다 (2026-09-18)

아임웹 `기본 설정 > 약관 설정하기` 칸이 비어 있었다. 기본 템플릿은 일반
쇼핑몰용이라 우리 상황(검사 결과지, 무료 시용 구간, 응시 응답이라는 민감한
자료)에 맞지 않는다. `sites/careermetri/legal/` 에 셋을 썼다.

| 파일 | 담은 것 |
|---|---|
| `01-terms.md` | 16조. 결과의 성질(제6조)·5명 미만 비공개(제7조)·무료 구간(제11조)·환불선(제12조) |
| `02-privacy.md` | 수집 항목을 **실제 스키마에서 뽑았다.** 파기는 "사람을 떼어낸다" 는 `erasure.ts` 의 방식 그대로 |
| `03-refund.md` | 상품별 선과 회사 사유 환불, 3영업일 처리 |

**사업자 정보는 지어내지 않았다.** 대괄호로 남겨 두고 `npm run metri:legal`
이 몇 종이 비었는지 센다. 같은 검사가 **약관과 코드가 같은 말을 하는지도
본다** — `WINDOW_DAYS = 7` 과 규정의 7일, `report_grants.first_viewed_at` 과
"처음 연 때", 위약금 없음 셋을 대조한다. 한쪽만 고치면 남은 쪽이 거짓말이
된다.

### 0-6. 원고를 한 벌로 줄였다

`sites/imweb/copy.md` 가 위젯과 같은 글을 두 번째로 갖고 있었다. 위젯을 다시
쓴 뒤로는 두 벌이 어긋났고, 사이트에 남는 것은 안 고쳐진 쪽이다. 그래서
copy.md 를 **아임웹 설정 원고**로 바꿨다 — 사이트 이름, 페이지별 SEO 제목,
메뉴, 폼 칸, 하단 필수정보처럼 위젯으로 만들 수 없고 설정 화면에 사람이
직접 타이핑하는 값만 남겼다. 절 원고는 위젯 파일이 유일한 원본이다.

### 0-7. 응시 시간을 네 언어에서 맞췄다

`marketing/src/content/` 의 kr 세 곳, global 두 곳, tr 한 곳, kz 한 곳이 모두
"약 30분" 이었다. 제안서는 같은 문항 구조에 15~20분으로 적고 그 문서가
고객에게 나가 있다. 일곱 곳을 15~20분으로 맞췄다. 같은 검사지를 두 값으로
말하는 상태는 끝났다.

### 1. 아임웹 가입, 기본 도메인으로 사이트 개설

템플릿은 **비즈니스 홍보** 묶음에서 고른다. 쇼핑몰 묶음은 상품 목록과
장바구니가 기본으로 깔려 있어 지울 것이 더 많고, 응시권 판매는 PG 심사
뒤에 페이지만 더하면 된다. **섹션이 단순하게 쌓인 밝은 바탕**을 고른다.
색과 활자는 우리 CSS 가 덮으므로 화려한 것보다 비어 있는 것이 낫다.

14일 체험 시계가 여기서 돌기 시작한다. **원고가 준비된 다음에 가입한다.**
원고는 `sites/imweb/copy.md` 에 다 있다.

### 2. Head Code 를 먼저 붙인다

`sites/careermetri/imweb/00-head-code.html` 을 통째로 복사해
`환경설정 > SEO > 고급 설정 > 공통 코드 삽입` 의 **Head Code** 칸에 넣는다.
**이것이 먼저 들어가야** 나머지 위젯이 제 모양으로 나온다. 폰트 링크가
여기 들어 있다.

### 3. 페이지 다섯을 만들고 코드 위젯을 얹는다

섹션마다 코드 위젯을 하나 놓고 `sites/careermetri/imweb/01~13` 을 붙인다.
어느 페이지에 무엇을 붙이는지는 `sites/careermetri/imweb/README.md` 표에
있다. **셀렉터를 전부 `cm-` 으로 감쌌으니** 아임웹 테마는 안 바뀐다.

### 4. 이미지를 올린다

`sites/imweb/media/` 의 `plat-*.png` 다섯 장이 본문용이다. 제안서 그림은
부록 표에 쓸 수 있는 것만 적어 뒀다(결과 예시 그림은 경영학과라 쓰지 않는다).

### 5. 도메인을 산다 (앞 단계와 같이 해도 된다)

`careermetri.co.kr` 과 `careermetri.com` 을 등록대행자에서 조회하고 산다.
아임웹 안에서 사도 되고 타사에서 산 것을 연동해도 된다. **DNS 가 조용한
것은 비어 있다는 뜻이 아니다.**

### 6. Starter 이상으로 올리고 도메인을 연결한다

`환경설정 > 도메인`. 무료 플랜에서는 개인 도메인이 붙지 않는다.

### 7. 푸터와 문의 폼을 채운다

전자상거래법 제10조의 일곱 칸. **비어 있으면 "확인 필요" 라고 찍어 둔다.**
값을 지어내지 않고, 빈칸으로도 두지 않는다. 문의 폼 알림 수신 주소도
같은 값이 필요하다(`LAUNCH.md` 2-2 · 아직 없다).

### 8. 공개

**여기까지가 문의를 받는 홈페이지고, 결제 없이 된다.** 1순위 매출인
학과 계약은 계약으로 좌석이 생기므로 PG 도 통신판매업 신고도 필요 없다.

---

개인 결제를 열 때만 아래가 붙는다.

### 9. PG 를 신청한다

유료 플랜에서 전자결제(PG)를 설정한다. 계약이 되면 **구매안전서비스
(에스크로) 이용확인증**이 나온다. 이것이 아임웹을 쓰는 실익이다.

### 10. 통신판매업 신고 (관할 구청 / 정부24, 3~5일)

사업자등록증 + 에스크로 확인증 + **웹사이트 주소**. 도메인이 여기서
필요하다.

### 11. 응시권 상품을 올리고 코드를 넣는다

```
npm run metri:codes -- --product REPORT_UNIV --count 50 --batch imweb-2026-10 --days 365
```

CSV 가 나오면 주문 완료 자동발송에 붙인다. 평문은 이때 한 번만 보인다.
**올릴 수 있는 것은 응시권뿐이다** — 업그레이드는 어느 응시를 여는지가
코드에 담기지 않아 발행이 거절된다(`21_imweb.md` 7절).

상품 설명에 교환 주소를 적는다. 코드만 주고 어디에 넣는지 안 적으면
문의가 전부 거기서 온다.

## 3. 원고를 만들면서 걸린 것 셋

**제안서의 예시 화면이 전부 경영학과다.** 개인 리포트 22장과 기관 리포트
3장이 "한국대학교 경영학과" 로 만들어져 있다. 이공계부터 연다고 정한
상태에서 그걸 홈페이지에 올리면, 담당자가 경영학과 검사를 요청할 때
내줄 문항이 없다. 그래서 **우리 플랫폼에서 기계공학 결과지와 기관
리포트를 실제로 뽑아** `plat-*.png` 로 넣었다.

처음 뽑은 것은 못 썼다. 시연 응답을 기계적으로 만들었더니 열 계열이
전부 동점이 되어 결과지가 "10개 계열이 1군" 이라고 찍혔다. 엔진이
정직하게 답한 것이지만 예시로는 쓸 수 없어서, 응시자마다 끌리는 영역을
둘씩 달리 주고 다시 채점했다.

**제안서 결과지는 8섹션, 지금 결과지는 7절이다.** 홈페이지에 8섹션을
적고 학생이 7절을 받으면 그 차이를 담당자가 먼저 발견한다. `copy.md`
3-1 에 고르는 길 셋을 적어 뒀다.

**가격이 두 벌인 줄 알았는데 두 상품이었다.** 제안서의 인당 19,800원은
**기관이 학과나 학년을 통째로 계약하는 단가**이고, 코드의 29,000원
(`UNIV_UPGRADE`)은 **개인이 혼자 와서 무료로 풀고 나머지 절을 여는 값**이다.
스키마가 34절에 이미 적어 둔 대로 "학과 계약 좌석은 상품을 거치지 않는다".
그래서 한쪽으로 맞출 일이 아니었고, `products` 표는 그대로 둔다.

맞춰야 했던 것은 **어느 쪽인지 말하지 않은 화면**이다. 단가표만 보고 온
개인이 결제창에서 29,000원을 보면 속았다고 느낀다. 그래서 가격 절에 두
줄을 넣었다: 패키지 위에 "기관이 계약할 때의 인당 단가", 단가표 아래에
"개인으로 오신 경우" 와 무료 구간·29,000원. `marketing/src/content/kr.ts`
가 두 언어로 이미 하던 말과 같다.
