## A. 운영 데이터 영향 확인

**판정: `PRODUCTION DATA IMPACT UNKNOWN`.**

운영 DB 연결 문자열이 이 컨테이너에 없고(`DATABASE_URL` 은
`127.0.0.1:5432/cmqa07` 로 개발 DB 를 가리킨다), `app.careermatri.com:443`
은 네트워크 정책에 막혀 HTTP 000 이고(`curl` 종료코드 56), Railway Shell
권한이 없다. **그래서 운영 응답 수를 적지 않는다.** `0건` 이라고 적으면
그 줄은 확인한 적 없는 사실이 된다.

대신 **운영에서 사람이 한 번 치면 답이 나오는 질의**를 읽기 전용으로
만들어 이미지 안에 넣었다. `/app/db` 는 이미 이미지에 들어가므로 파일을
더하는 것 말고 할 일이 없다.

```
# 운영 컨테이너에서 (Railway → 서비스 → ⋯ → Shell)
psql "$DATABASE_URL" -f /app/db/checks/v3_measurement_impact.sql
```

**`select count(*) from v3_responses` 한 줄로는 답이 안 나온다.** 전체
수가 0 이 아니어도 전부 시연 계정이면 고친 것이 아무에게도 닿지 않고,
반대로 전체 수가 적어도 굳은 결과가 걸려 있으면 그것은 손님의 결과지다.
그래서 다섯을 따로 센다: 전체 · 시연 · 실제 · 완료된 응시 · 굳은 결과.
**쓰는 문장이 한 줄도 없다**: INSERT 도 UPDATE 도 DELETE 도 DDL 도 없다.

이 기계의 개발 DB 에서 같은 질의를 돌린 값은 아래와 같다. **이것은
운영에 대한 답이 아니다.**

| | 값 |
|---|---|
| ME_V3 응답 전체 | 1,097 |
| 그 가운데 `CJ_GIVEN_REV` | 12 |
| 시연 계정 | 12 |
| 실제 사용자 | 0 |
| 완료된 응시 | 8 |
| 굳은 결과가 걸린 응시 | 8 |
| 판매 중인 ME_V3 상품 | 0 / 3 (`active = false`) |

같은 질의가 **굳은 결과가 적고 있는 판본**도 찍는다. 이 기계에는 문항
은행 판본 셋(`ME_V3_ITEM_BANK_V2` · `V2.4` · `V2.5`)에 걸친 결과 여덟
줄이 있고, **셋 다 지금도 그대로 열린다.** 아래 C 의 셋째 조건이 말로
적은 것이 아니라는 증거가 그것이다.

## B. 하위호환 넷

운영 응답이 있는 경우를 가정하고 넷을 확인했다. **응답이 있다는 것만으로
결함이 아니다.** 결함은 저장된 값의 뜻이 달라지거나 굳은 결과가 다시
계산될 때 생긴다.

### ① 저장된 값의 자리와 뜻이 그대로다

`CJ_GIVEN_REV` 에서 바뀐 것은 문면과 학위 장면과 역방향 표시뿐이다.

| 칸 | 고치기 전 | 고친 뒤 |
|---|---|---|
| `response_scale` | `L0~L3` | `L0~L3` |
| `options` | 보기 넷 | 같은 보기 넷 |
| `option_values` | `null` | `null` |
| `evidence_axis` | `J3` | `J3` |
| `module` | `CORE-JUDGE` | `CORE-JUDGE` |

자리 번호 0~3 의 뜻(`없다` · `받아 썼다` · `내가 했다` · `내가 정하고 그
결과가 쓰였다`)이 그대로이므로 **migration 이 필요하지 않다.**

### ② 새 문면으로 과거 응답을 다시 해석해도 충돌이 없다

이것을 말로 적지 않고 **구조로** 보였다. 채점과 결과 모델 어디에도
문항 문면을 읽는 줄이 없다.

```
npm run v3:freeze:measure
  통과  채점과 결과 모델이 문항 문면을 읽지 않는다 — 문면을 읽는 줄 0
```

`read()`(`scoring/normalize.ts`)가 보는 것은 `kind` 와 `index` 와
`value` 뿐이고, `reverse_flag` 는 값을 뒤집는 데 쓰이지 않는다(쓰는 곳은
`quality.ts` 의 역방향 짝 규칙 하나이고, 지금 은행의 역방향은 0개라
그 규칙은 설계대로 잠들어 있다). **문면을 고쳐도 같은 응답이 같은 판정으로
간다.**

**남는 것은 측정 타당도 쪽의 한 줄이고, 그것은 적어 둔다.** V2.4 문면은
선호를 묻는 꼴(`~편이 편하다`)이었고 지금은 겪은 장면을 묻는다. 그래서
그 판본에서 받은 응답과 지금 판본에서 받을 응답을 **Wave 0 분석에서 한
표에 두지 않는다.** 제품 동작의 문제가 아니라 자료를 묶는 규칙이다.

### ③ 굳은 결과가 다시 계산되지 않는다

결과지는 `v3_snapshots.result_model` 에 적힌 것을 꺼내 그린다. 읽는
자리 둘(`/v3/[attemptId]/result` · `/me/results`) 가운데 채점 엔진을
들여오는 줄이 하나도 없고, 그것을 동결 검사가 센다.

```
  통과  결과지가 채점 엔진을 다시 부르지 않는다 — 읽는 쪽 2곳
```

그리고 A 에서 적었듯 이 기계의 굳은 결과 여덟 줄이 **판본 셋**에 걸쳐
있는데 셋 다 열린다.

### ④ 기존 사용자의 현재 상태와 결과가 저절로 바뀌지 않는다

현재 상태(`career_profiles`)는 **사람이 `반영하기` 를 누를 때만** 다시
선다. 판본이 올라간다고 돌지 않는다. 사람 열두 벌의 Core 판정을 기준선과
글자로 견주어 차이가 0 인 것도 같은 자리에서 센다.

**넷이 다 성립한다.** 다만 ①~④ 는 **코드와 이 기계의 자료에 대한
확인**이고, 운영에 무엇이 쌓여 있는지는 A 대로 `UNKNOWN` 이다.

## C. Measurement Freeze

**선언: `ME_V3_MEASUREMENT_FREEZE_1`.**

얼린 판본은 넷이다.

| | 판본 |
|---|---|
| Major Core | `ME_CORE_V3` |
| 문항 은행 | `ME_V3_ITEM_BANK_V2.5` |
| 판단 규칙 | `me-v3-scoring.5` |
| 결과 모델 | `me-v3-result-model.5` |

지키는 자리는 `npm run v3:freeze:measure` 하나이고 `v3:all` 사슬에
들어갔다(39묶음). **열네 가지를 센다.**

| | 세는 것 |
|---|---|
| 1 | 측정 판본 넷이 동결 기록과 같다 |
| 2 | 측정 층 파일 열아홉 벌의 지문이 그대로다 |
| 3 | 보기 넷의 문면과 수가 그대로다 |
| 4 | 소유 네 단계의 이름이 그대로다 |
| 5 | 사람 열두 벌의 Core 판정이 기준선과 같다 (실제로 다시 돌린다) |
| 6 | 팩 문항 136개를 바닥에서 천장까지 바꿔도 Core 판정이 같다 |
| 7 | 산업을 갈아 끼워도 Core 판정이 같다 |
| 8 | 문면을 고친 문항의 보기와 척도와 축이 그대로다 |
| 9 | 채점과 결과 모델이 문항 문면을 읽지 않는다 |
| 10 | construct 가 적히지 않은 문항이 없다 (369 / 369) |
| 11 | 코드가 글자로 적은 문항 번호가 전부 은행에 있다 (산 번호 603개) |
| 12 | 결과지가 채점 엔진을 다시 부르지 않는다 |
| 13 | **UI 동결 파일과 측정 동결 파일이 겹치지 않는다** |
| 14 | dead item 과 사람 벌을 세는 명령이 사슬에 남아 있다 |

**열셋째가 이 파일을 두는 가장 큰 까닭이다.** 한 파일이 두 동결에 걸려
있으면 홈의 카드 하나를 옮긴 날 측정 동결이 같이 흔들리고, 그러면 사람이
`UI 때문이니 다시 적자` 로 넘긴다. 한 번 넘기면 그 동결은 아무것도 막지
않는다. 그래서 **만들자마자 걸렸다**: `result/model.ts` 와
`result/build.ts` 가 측정 동결과 결과지 UI 동결 양쪽에 들어 있었다. 결과
모델 둘을 UI 동결 목록에서 빼고 측정 동결이 들게 했다. **판본은 여전히
양쪽에 적힌다**: `result-lock.json` 의 `versions` 에
`result_model_version` 이 그대로 있다.

**여기서 세지 않는 것을 적어 둔다.** 받고 쓰지 않는 문항(dead item 0)과
꾸며 낸 응답 여덟 벌과 고르게 답한 넷은 `v3:measure` 와 `v3:gaming` 이
센다. 그 판정을 여기서 다시 하면 같은 판정이 두 곳에 생기고 어느 날
갈린다. 열넷째 줄이 세는 것은 **그 명령이 아직 사슬에 있는가**뿐이다.

**검사가 실제로 걸리는지 되돌려 확인했다.** `scoring/axes.ts` 에 주석 한
줄을 넣고 돌리니 둘째 줄이 걸렸고(`바뀜 src/lib/me-v3/scoring/axes.ts`),
되돌리니 열넷이 다 지나갔다.

### 동결 뒤에 금지되는 것

문항 scoring · `band()` · 묶음 규칙 · 소유 해석 · ResultModel 로직 ·
근거 확정 로직 · Core 영역 계산 · Major Core 구조 · Industry Pack 과
Core 의 관계 · Role Pack 과 Core 의 관계 · 기존 스냅샷 해석.

**UI 때문에 scoring 을 고치지 않는다.** 필요하면 STOP GATE 로 올린다.
이 회차의 Phase 1 작업은 그 선을 한 번도 넘지 않았고, 모든 UI 작업이
끝난 뒤 동결 검사가 열넷 가운데 열넷을 통과했다.

## E. `/me` 홈

첫 화면에 서는 것이 넷이다: **현재 상태 → 지금 할 한 가지 → 최근 변화 →
최근 기록.** 세로 차례가 곧 중요도다.

- **같은 크기의 카드 예닐곱을 세우지 않는다.** 상태마다 다른 화면을
  내고, 자료가 없는 묶음은 아예 그리지 않는다
- **`최근 기록` 이 한 묶음에 두 줄까지다**(전에는 셋씩). 나머지는
  `경험 모두 보기` · `지원 기록 모두 보기` 뒤에 있다. 셋씩 세우면 홈의
  꼬리가 몸통보다 길어진다
- **`관심 산업과 직무` 칸을 걷었다.** 그 칸은 넷의 어느 것도 아니고
  바꾸는 자리가 왼쪽 띠의 `산업·직무` 와 `지역·기관` 이라, 홈에 두면
  바꿀 수 없는 칸이 하나 늘고 넷의 차례가 다섯으로 읽힌다. 값은 그 두
  쪽에 그대로 있다
- **주된 단추는 늘 `지금 할 일` 이다.** 검사 전과 진행 중만 갈린다

## F. Assessment UI

### 다섯 칸 척도를 밝혀 적는다

격자 머리에 **번호와 온전한 말**이 선다.

```
관심        1 전혀 관심 없음 · 2 관심 적음 · 3 보통 · 4 관심 있음 · 5 매우 관심 있음
배울 뜻     1 전혀 배우고 싶지 않음 · 2 별로 배우고 싶지 않음 · 3 보통
            · 4 배우고 싶음 · 5 매우 배우고 싶음
```

칸 안에는 **번호가 위, 줄인 말이 아래**다. 번호를 넣은 까닭은 둘이다:
`적음` 과 `보통` 사이가 몇 칸인지 눈으로만 세지 않게 하고, 좁은 화면에서
격자 머리의 가운데 셋이 접혀도 고르는 칸의 자리를 알 수 있게.

**`모르겠다` 는 척도 밖이다.** 다섯 칸 뒤에 작게 서고 저장되는 값은
`null` 이며 `ANSWERED_UNKNOWN` 으로 읽힌다. 가운데 값으로 두면 아직
모르는 사람이 보통 관심으로 판정된다.

**문항 은행과 저장되는 값과 `band()` 는 한 글자도 바뀌지 않았다.** 은행의
`options`(`전혀 관심 없다` …)와 `option_values`(1~5·null)가 그대로이고,
바뀐 것은 화면이 그것을 어떻게 적는가뿐이다. 측정 동결이 그대로 통과한
것이 그 증거다.

### 소유 네 단계

문면과 도움말이 그대로다. 도움말은 보기마다 **한 줄 안짝**이다.

```
해본 적 없음        경험 없음
주어진 조건으로 수행  조건은 정해져 있었음
직접 수행           실제 작업을 내가 수행
조건·기준까지 직접 정함  기준까지 내가 정함
```

넷이 넓은 화면에서 한 행에 서고 좁은 화면에서 네 칸으로 쌓인다. 긴
뜻풀이는 `보기가 어떻게 갈리나요` 안에 있다. **번호를 붙이지 않는다**:
이 넷은 누가 정했는가의 단계라 번호를 붙이면 `1점 · 2점` 으로 읽힌다.

### 전환 화면 감사

다섯 가운데 **셋을 걷고 둘을 남겼다.**

| 자리 | 담고 있던 것 | 처리 |
|---|---|---|
| 영역 훑기 완료 | `이제 실제 경험을 확인합니다` + 영역 이름 목록 | 걷고 맥락 한 줄로 |
| 실제 경험 완료 | `같은 영역을 조금 더 묻습니다` + 영역 이름 목록 | 걷고 맥락 한 줄로 |
| 산업 장면 안내 | `이 산업에서 달라지는 판단을 묻습니다` | 걷고 맥락 한 줄로 |
| 대학원 경험 확인 | 왜 묻는지 + 무엇을 묻는지 넷 | **남겼다** |
| 경험 번역 안내 | 하나의 경험을 네 화면에 나눈다 | **남겼다** |

걷은 셋은 **영역 이름이 바로 다음 화면의 머리말에 다시 적혀 있어서**
읽을 것이 없었다. 지금은 묶음의 **첫 질문 위에 한 줄**로 선다. 남긴 둘은
한 줄로 줄이면 뜻이 사라진다: 앞엣것이 없으면 응시자가 그 질문을 자기를
걸러내는 것으로 읽고, 뒷엣것이 없으면 네 화면에서 서로 다른 경험을
떠올려 적는다.

**`계속` 을 세 번 덜 누른다. 응답은 한 개도 줄지 않았다.**

```
화면  26 / 46 / 66  →  25 / 44 / 63
응답  46 / 84 / 110  →  46 / 84 / 110   (그대로)
```

| **산업·직무 연결** | 고르신 산업과 직무, 그리고 지금 이어지는 영역 |

**넷째 칸이 이번에 붙었다.** 앞의 셋은 Core 안에서 끝나는 말이라, 첫
화면이 `그래서 어디에 쓰는가` 에 답하지 않고 끝났다. 고르지 않으셨으면
그 사실을 적는다.

### 영역 기본 보기가 다섯 줄이다

```
영역명 · 현재 상태 한 줄 · 가장 강한 근거 둘셋 · 부족한 것 하나 · 다음 행동 하나
```

**여덟 축은 기본으로 펼치지 않는다.** `상세 근거 보기` 안에 있고, 전체
목록(직접 정한 것 / 해 본 일 / 남긴 것 / 비교한 것)과 확인된 판단의
수도 그 안으로 내렸다. 전에는 **넓은 화면에서만 늘 펼쳐져 있었고**, 그
목록이 영역 한 자리에서 가장 큰 덩이라 읽는 사람이 자기 상태를 여덟
개의 판정으로 읽었다.

**서버가 내놓는 첫 모양은 펼친 쪽이다**: 자바스크립트가 꺼져 있어도
내용이 다 보여야 하고 종이로 뽑는 길이 그 모양을 읽는다.

### 숫자를 점수처럼 보이게 하지 않는다

`확인된 판단 24 · 직접 정한 것 12 · 고르신 근거 60` 은 **`자세한 내용
보기` 의 회색 곁줄**이다. 영역 이름 옆에 있던 `확인된 판단 5 · 직접 정한
것 2` 도 상세 안으로 내렸다. **CareerMatri 는 점수와 순위를 내는 제품이
아니다.**

## H. 결과 문장

쓰지 않기로 한 말을 **검사가 센다**(`v3:result:copy` 일곱째 줄).

| 쓰지 않는다 | 대신 |
|---|---|
| 검증됐다 · 검증되었다 | 현재 응답에서 확인된 |
| 적합하다 · 적합합니다 | 설명할 수 있는 |
| 강점이다 · 강점입니다 | 확인된 경험 |
| 높은 가능성 | 확인된 경험 |
| 바로 쓸 수 있다 | 설명할 수 있다 |
| 확정됐다 · 확정되었다 | 확인된 |

**부정문은 지나간다.** 이 저장소의 `writing:check` 과 같은 규칙이다:
막는 것은 결론이고 그 결론을 막는 문장이 아니다. 결과지는
`합격 가능성이나 순위를 내지 않습니다` 를 적고 있고, 그 줄을 세면 지켜
주려던 문장을 지우라고 요구하게 된다.

이 검사를 만들면서 실제로 두 자리가 걸렸고 고쳤다:
`정리해두면 바로 쓸 수 있는 경험` → `지원서에서 설명할 수 있는 경험`,
`지원서에서 바로 쓸 수 있는 근거가 아직 잡히지 않았습니다` →
`지원서에서 설명할 수 있는 근거가 아직 잡히지 않았습니다`.

**되돌려 확인했다**: 문장 하나를 `이 영역은 강점입니다` 로 바꿔 넣으니
`P01 첫 줄: 강점입니다 → 확인된 경험` 으로 걸렸다.
