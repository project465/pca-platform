# 상용화 Gate: 지금 무엇이 공개를 막는가 (2026-10-13)

코드를 고치기 전에 **지금 시스템 기준으로** 학생 공개를 막는 것만 적는다.
전부 이 기계에서 운영과 같은 배치(`stage-serve.sh 3100`)로 띄워 실제
브라우저와 실제 DB 로 확인한 값이다. **운영 배포본은 네트워크 정책이 막아
한 번도 열지 못했다.**

판정: **COMMERCIALIZATION BLOCKED**

## 0. 오늘 배재대 학생이 겪는 것

```
/campus/pcu            200 · 단과대학 여섯이 선다
→ 학과 상세            200 · "이 학과는 지금 응시할 수 없습니다"
→ 검사 시작            ✗ 단추가 없다
```

배재대 선택 자리 **117개** 가운데 Core 를 가리키는 자리가 48개이고
(BIZ 12 · CS 9 · EE 3 · 아직 쓰지 않은 Core 24), **지금 응시할 수 있는
Core 는 `ME_CORE_V3` 하나**인데 **배재대에는 기계공학 자리가 0개**다.
그래서 오늘 이 학교에서 시작할 수 있는 검사가 **0개**다.

로그인·가입 길은 막혀 있지 않다. 비로그인 상태로 `이 전공으로 검사 시작`
을 누르면 `/login?next=/v3/start` 로 가고, 거기서 가입하면 `/v3/start` 로
돌아온다(고른 학과는 쿠키에 남아 있다). 가입은 303 으로 끝난다.

## 가장 먼저 고쳐야 할 다섯

1. **결과지·작업공간의 전공 이름을 응시의 Core 에서 읽는다** (P0-2).
   `/v3/start` 가 이미 그렇게 한다(`coreEntry(core).name_ko`). 같은 자리를
   결과 쪽과 `/me/*` 가 읽게 한다.
2. **PDF 1쪽에 메타 줄을 세운다** (P1-1): 전공 · 등급 · 응답일 ·
   학교·학과(학교 진입이면).
3. **PDF 정보 구조를 규격 §3 의 여섯 쪽으로 다시 묶는다** (P1-3~7):
   되풀이되는 8축 표를 접고, 같은 까닭을 한 번만 적고, 빈 표는 한 줄로
   줄이고, 끊기는 자리를 막는다.
4. **담당자 화면 라벨** (P1-2): `Cell.label` 을 그대로 쓰게 한다.
5. **배재대 기관 줄과 담당자 계정** + Human Review 를 마친 Core 부터
   `open_to_students: true` (P0-3 · P0-1).
