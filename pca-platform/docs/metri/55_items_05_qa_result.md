**보고 한 줄은 고치지 않았다.** 보기 목록이 긴 문항 여섯 개가 있다.
TD02_J6 의 "손계산이나 시험값이나 기존 결과 가운데 하나와 견주어" 처럼,

검사가 처음에 다섯 쌍을 잡았고 전부 문면을 고쳐서 풀었다.

## 2. 사람 여덟 벌 (`npm run v3:persona`)

**여기 든 산식은 제품 채점기가 아니다.** 설계 문서의 규칙을 그대로 옮긴
검산이고, 7단계에서 채점기를 쓰면 그쪽이 같은 값을 내놓아야 한다. 검산을
먼저 두는 까닭은 문면을 쓰고 나서 **그 문면으로 규칙이 오판을 내는지**를
채점기 전에 알아야 하기 때문이다.

| 사람 | 등급 | 근거가 선 영역 | 관심은 있고 근거가 얕은 영역 |
|---|---|---|---|
| A 경험 거의 없는 3학년 | BASIC | 없음 | TD01 · TD02 |
| B 캡스톤 설계 경험자 | STANDARD | TD01 | TD08 |
| C 구조해석 석사 | STANDARD | TD02 | TD01 · TD07 |
| D 열유체 석사 | STANDARD | TD03 | 없음 |
| E 재료·파손 박사 | PRO | TD06 · TD07 | TD10 |
| F 생산기술 경험자 | STANDARD | TD08 | TD09 · TD10 |
| G 자동차 연구 박사 | PRO | TD02 · TD04 | TD03 |
| H 산업을 모르는 포닥 | PRO | 없음 | TD02 · TD03 |

확인 열두 가지가 전부 통과다.

| 센 것 | 결과 |
|---|---|
| 학위를 바꿔도 축 수준과 묶음이 같다 | 같다 |
| 계열을 바꿔도 결과가 같다 | 같다 |
| 관심만 높은 사람에게 근거가 선 영역이 없다 | Z1 0개 · 확인된 선별 축 0 |
| 남이 한 것을 받아 쓴 응답(L1)을 확인으로 세지 않는다 | 전부 L1 이면 확인 0 |
| 근거가 하나면 소유(L3)로 올리지 않는다 | L2 로 내려간다 |
| 산업을 바꿔도 Core 결과가 같다 | 같다 |
| 역할팩을 바꿔도 Core 결과가 같다 | 같다 |
| 첫 쪽에 올린 영역이 근거 조건을 지킨다 | 지킨다 |
| 근거가 선 영역이 없으면 얕은 쪽을 먼저 보여 준다 | A 는 TD01 · TD02 |
| BASIC 에 근거가 섰다는 판정이 없다 | 없다 |
| 연구 축이 높고 산출물이 비면 근거가 서지 않는다 | H 의 Z1 이 0개 |
| 산출물만 빈 영역을 아직 판단할 수 없다고 적지 않는다 | H 는 TD02 · TD03 을 먼저 본다 |

### 열한째 줄에서 설계 구멍 하나가 나왔다

처음 돌렸을 때 **H 가 걸렸다.** 문제 정의와 직접 판단과 방법과 비교·검증이
L2 이상이어서 확인된 축이 다섯이고, 구조해석의 필수 축 둘도 만족한다.
그런데 산출물이 L1 이고 조직 활용이 L0 이다. 그 상태가 `근거가 선 영역` 에
들어가 있었다.

**남은 것이 없는 사람에게 지원서에 쓸 근거가 섰다고 말하는 셈이다.** 앞
판본의 `APPLICATION_EVIDENCE_AVAILABLE` 이 이미 `산출물 이상 하나` 를
요구하고 있었으므로, 같은 선을 Z1 조건에 더했다(`J5` 가 L2 이상).

그리고 떨어뜨리는 것만으로는 모자랐다. 조건에서 떨어진 영역이
`아직 판단할 수 없는 영역` 으로 가서 앉는데, 그러면 많이 답한 사람에게
응답이 모자란다고 말하게 된다. 모자란 것은 응답이 아니라 **남은 것**이다.
그래서 Z2 조건에 산출물 미확인을 더해서, 영역 이름과 함께 비어 있는 축이
산출물이라는 것과 그것이 다음 할 일이라는 것을 적는다. 고친 자리는
`53_v3_05_result_trace.md` 4절과 `53_v3_11_z1_spec.md` 1절이다.

## 3. 다시 돌리는 명령

```bash
npm run v3:wording   # 문면 스물세 가지
npm run v3:persona   # 사람 여덟 벌 · 확인 열두 가지
npm run v3:items     # 자리 113개 열한 가지
npm run v3:domains   # 1~3단계 데이터 열세 가지
npm run v3:arch      # 일곱 층 스무 가지
npm run v3:extend    # 엔진을 뜯지 않고 core 를 더할 수 있는가 열네 가지
npm run v3:qa        # 수동 검토표와 팩 문서를 다시 만든다
```
