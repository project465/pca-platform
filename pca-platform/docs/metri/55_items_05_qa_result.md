## 2. 문면 감사에서 고친 것

### 2-0. 일곱 기준으로 아흔아홉 문항을 본 결과

| 기준 | 걸린 문항 | 어떻게 했나 |
|---|---|---|
| 현장에 실제로 있는 행동인가 | 4 | TD05 J3 · TD09 J3 · TD12 J3 · TD04 J4 를 다시 썼다 |
| 도구 사용과 기술 판단을 섞지 않았는가 | 0 | 도구는 J4 축에만 있고 판단은 J3 와 J6 가 받는다 |
| 학부생이 겪지 않았다고 불리해지지 않는가 | **74** | 문면이 소유를 요구하던 자리다. 2-1절 |
| 참여만 하고 소유로 읽히지 않는가 | 0 (장치를 더했다) | 보기 읽는 법 한 줄을 화면에 둔다. 2-6절 |
| 확인과 소유의 차이가 또렷한가 | **8** | 요구사항 해석 축이 수동이던 자리다. 2-2절 |
| 다른 영역과 사실상 같지 않은가 | 2 | 2-4절 |
| 읽고 자기 경험 하나가 떠오르는가 | 3 | 한 칸에 둘로 나눴다. 2-3절 |

세 번째 줄과 다섯 번째 줄이 겹친다. 같은 규칙 하나를 어겨서 생긴 것이고,
고친 뒤 **아흔아홉 문항이 전부 확인 기준 쪽에 가깝다.**


### 2-1. 문면이 소유를 요구하던 자리 일흔넷

가장 비싼 발견이다. 축의 `l3` 를 문면에 적어 둔 문항이 많았고, 그러면
**그 행동을 한 사람이 `없다` 로 떨어진다.**

| 자리 | 앞 문면 | 무엇이 문제였나 |
|---|---|---|
| TD01 J5 | 내가 그린 부품도나 조립도가 **제작으로 나간** 경험 | 캡스톤에서 도면을 그린 학부생의 산출물 축이 L0 이 된다. 산출물이 비면 Z1 이 안 서므로 영역 하나를 통째로 잃는다 |
| 열두 영역 J8 | 내 결과로 ~가 **바뀐·결정된** 경험 | 보고까지 한 사람이 `없다` 로 떨어진다. 채택 여부는 보기 넷째가 받을 일이다 |
| TD01 J4 | **손계산으로** 확인해 반영한 경험 | 그 축의 확인 기준은 3차원 모델 작업인데 문면이 소유 기준을 요구했다 |
| TD07 J3 | 측정 지점과 **샘플 수와 판정 기준**을 정한 경험 | 측정 지점을 정한 사람이 떨어진다. 샘플 수는 체크리스트가 받는다 |

고친 규칙은 하나다. **문면은 `l2` 행동을 묻고, 소유는 보기 넷이 가르고,
`l3` 는 체크리스트 근거가 받쳐야 결과지에 적는다.** 규칙을 지키는지는
문면과 두 정의의 닮음을 재어 센다.

### 2-2. 요구사항 해석 축이 수동이던 자리 여덟

여덟 영역의 J2 확인 기준이 `요구를 수치로 받았다` 였다. **받은 것은 판단이
아니다.** 받아 쓴 자리는 보기 둘째가 이미 가리므로, 사양서를 받아 본 사람이
J2 확인으로 세어지고 있었다. 확인 기준을 `옮겨 적었다` 로 올리고, 소유
기준은 `규격이 없는 항목의 기준을 근거를 들어 세웠다` 쪽으로 옮겼다.

### 2-3. 한 칸에 문항을 둘로 나눈 자리 셋

| 자리 | 나눈 까닭 |
|---|---|
| TD04 J4 | 모달 해석으로 구하는 것과 가속도계로 재는 것 |
| TD05 J4 | 시퀀스를 구현한 것과 응답을 보고 이득을 맞춘 것 |
| TD09 J4 | 지금 상태를 보는 것과 이력으로 앞을 내다보는 것 |

셋 다 심화 축이라 BASIC 응답 수는 그대로다. 축 수준은 **높은 쪽**을 쓰고
둘 다 L2 이상이면 근거 둘로 센다.

### 2-4. 영역 사이에 사실상 같던 문항 둘

`TD08_J5` 와 역할팩 생산기술의 산출물 문항이 **글자까지 같았다.** 역할팩은
그 자리에서 가진 권한을 더 묻는 자리라 `내 이름으로 작업 표준을 내고 개정
까지 맡은 경험` 으로 고쳤다. `TD06_J8` 과 `TD07_J8` 도 0.77 로 닮아 받는
사람과 산출물을 갈랐다.

### 2-6. 참여를 소유로 적는 것을 막는 장치

보기 넷은 그대로 두고 **읽는 법 한 줄을 화면에 둔다.**

> 남이 정한 조건으로 돌리기만 한 것은 두 번째 보기입니다. 조건이나 기준을
> 내가 정했고 그 결과가 다음 작업에 쓰였을 때만 네 번째입니다.

보기를 다섯으로 늘리는 쪽은 택하지 않았다. `지시받은 범위에서 내가 했다` 를
따로 두면 캡스톤에서 스스로 정한 학생이 어느 칸에도 못 들어간다. 장치는
넷이다: 이 한 줄과, 소유는 근거 둘 이상일 때만 올라가는 규칙과, 같은 축을
학교 장면과 실무 장면에서 묻는 일관성 짝과, 응답과 체크리스트의 어긋남이다.

**이 줄이 실제로 듣는지는 파일럿에서만 안다.**

### 2-5. 체크리스트가 하나뿐이던 칸 열넷

소유는 근거 둘 이상일 때만 올라가므로, 항목이 하나인 칸에서는 **소유가
구조적으로 못 선다.** 열넷을 메워 이제 모든 칸이 둘 이상이다.

## 3. 사람 열두 벌 (`npm run v3:persona`)

**여기 든 산식은 제품 채점기가 아니다.** 설계 문서의 규칙을 그대로 옮긴
검산이고, 7단계에서 채점기를 쓰면 그쪽이 같은 값을 내놓아야 한다.

| 사람 | 등급 | 근거가 선 영역 | 근거가 덜 선 영역 |
|---|---|---|---|
| A 경험 거의 없는 3학년 | BASIC | 없음 | TD01 · TD02 |
| B 캡스톤 설계 경험자 | STANDARD | TD01 | TD08 |
| C 구조해석 석사 | STANDARD | TD02 | TD01 · TD07 |
| D 열유체 석사 | STANDARD | TD03 | 없음 |
| E 재료·파손 박사 | PRO | TD06 · TD07 | TD10 |
| F 생산기술 경험자 | STANDARD | TD08 | TD09 · TD10 |
| G 자동차 연구 박사 | PRO | TD02 · TD04 | TD03 |
| H 산업을 모르는 포닥 | PRO | 없음 | TD02 · TD03 |
| I 관심만 높고 남은 것이 없는 학생 | STANDARD | 없음 | TD03 |
| J 판단은 많고 남은 것이 없는 사람 | STANDARD | 없음 | TD08 |
| K 산출물은 있고 판단은 적은 사람 | STANDARD | 없음 | TD01 |
| L 판단·산출물·검증이 다 있는 사람 | STANDARD | TD02 | 없음 |

확인 열여섯 가지가 전부 통과다. 네 유형(I · J · K · L)이 Z1 과 Z2 를 고친
뒤의 회귀 검사다.

| 센 것 | 결과 |
|---|---|
| 학위를 바꿔도 축 수준과 묶음이 같다 | 같다 |
| 계열을 바꿔도 결과가 같다 | 같다 |
| 관심만 높은 사람에게 근거가 선 영역이 없다 | Z1 0개 |
| 남이 한 것을 받아 쓴 응답(L1)을 확인으로 세지 않는다 | 전부 L1 이면 확인 0 |
| 근거가 하나면 소유(L3)로 올리지 않는다 | L2 로 내려간다 |
| 산업을 바꿔도 Core 결과가 같다 | 같다 |
| 역할팩을 바꿔도 Core 결과가 같다 | 같다 |
| 첫 쪽에 올린 영역이 근거 조건을 지킨다 | 지킨다 |
| 근거가 선 영역이 없으면 덜 선 쪽을 먼저 보여 준다 | A 는 TD01 · TD02 |
| BASIC 에 근거가 섰다는 판정이 없다 | 없다 |
| 연구 축이 높고 산출물이 비면 근거가 서지 않는다 | H 의 Z1 이 0개 |
| 산출물만 빈 영역을 아직 판단할 수 없다고 적지 않는다 | H 는 TD02 · TD03 을 먼저 본다 |
| **관심만 높고 남은 것이 없으면 근거가 서지 않는다** | I · 확인 1 |
| **판단이 많아도 남은 것이 없으면 근거가 서지 않는다** | J · 확인 6 · 산출물이 비어 있다 |
| **산출물만 있고 직접 판단이 비면 근거가 서지 않는다** | K · 필수 축 J3 가 비어 있다 |
| **판단과 산출물과 검증이 다 있으면 근거가 선다** | L · 확인 4 · 필수 축 둘과 산출물이 L2 이상 |

**`근거가 섰다` 와 `경험은 있으나 아직 근거가 완성되지 않았다` 가 갈린다.**
J 는 확인된 축이 여섯이고 L 은 넷인데 근거가 선 쪽은 L 이다. 조건이 개수가
아닌 필수 축과 산출물이기 때문이고, 그것이 이 묶음의 뜻이다.

## 4. 다시 돌리는 명령

```bash
npm run v3:wording   # 문면 스물일곱 가지
npm run v3:persona   # 사람 열두 벌 · 확인 열여섯 가지
npm run v3:items     # 자리 113개 열한 가지 + 응답 수
npm run v3:domains   # 1~3단계 데이터 열다섯 가지
npm run v3:arch      # 일곱 층 스무 가지
npm run v3:extend    # 엔진을 뜯지 않고 core 를 더할 수 있는가 열네 가지
npm run v3:qa        # 검토표와 팩 문서와 전공자 검토 묶음을 다시 만든다
```
