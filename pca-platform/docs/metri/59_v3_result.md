# 59. ME_V3 결과지

응답을 판단으로 바꾸는 일은 `57_v3_scoring_*` 이 끝냈다. 여기는 그 판단을
**사람이 읽는 차례로 다시 묶어 화면과 종이로 내보내는** 자리다.

```
scoring snapshot → result model → 한국어 → 웹 · PDF
```

**결과 엔진은 새로운 판단을 하지 않는다.** 묶음도 축 상태도 까닭 코드도
스냅샷이 정한 것을 그대로 쓴다. `npm run v3:result` 가 매번 글자까지
대조한다: 모델의 묶음과 확인된 축과 소유와 까닭이 스냅샷과 같지 않으면
걸린다.

## 왜 모델을 따로 두는가

렌더러가 스냅샷을 직접 읽으면 화면을 고칠 때마다 판정에 손이 간다. 그리고
웹과 PDF 가 각자 읽으면 어느 날 둘이 갈리고, 갈린 날 상담 자리에서 다른
종이를 들고 앉는다.

| 층 | 파일 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 판단 | `scoring/engine.ts` | 묶음과 축과 까닭 | 한국어 · 차례 |
| 모델 | `result/build.ts` | 읽는 차례로 다시 묶기 | 판정 · 한국어 |
| 번역 | `result/text.ko.ts` | 문장 | 판정 · 차례 |
| 화면 | `v3/[attemptId]/result` | 배치 | 판정 · 계산 |

**모델 코드에 한국어가 없다.** 응시자가 고른 항목만 한국어이고 그건 그
사람이 고른 글자다. 검사가 두 가지를 센다: 모델 파일에 사람이 읽는 한국어가
있는지와 모델이 번역표를 읽는지.

## 모델의 칸

`overview` · `domains` · `evidence` · `gaps` · `actions` ·
`industry_context` · `role_context` · `translation` · `response_quality` ·
`provenance`.

**`provenance` 가 되짚는 자리다.** 축마다 어느 문항에서 왔는지(`from`)와
어떤 항목이 근거였는지(`picks`)를 들고 다닌다. 화면에는 문항 번호를 내보내지
않고, 고른 항목만 그 사람의 말로 돌려준다.

## 왜 그런 결과인지

CareerMatri 가 다른 검사와 갈리는 자리가 여기다. `구조·내구 분야가
적합합니다` 로 끝내지 않고 **그 사람이 고른 항목을 그대로 돌려준다.**

```
직접 정한 것   어떤 하중 조건과 현상을 볼지 정했다 · 시험 규격의 하중 이력을
               해석 입력으로 바꿨다 · 요구 수명과 허용 응력을 해석 조건으로 옮겼다
해 본 일       가정 정리 · 경계 조건과 하중 · 해석 모델 · 결과 해석
남긴 것        해석 모델 · 해석 보고서
비교한 것      선행 해석 · 손계산
```

**우리가 쓴 해석보다 그 사람이 고른 항목이 큰 자리를 차지한다.** 읽는 사람이
자기 답을 알아보는 것이 먼저고, 해석은 그 위에 얹는다.

## 비어 있는 자리를 빨간 목록으로 만들지 않는다

세 칸이 한 묶음으로 선다: **무엇이 비었는가 · 왜 그 자리가 필요한가 ·
다음에 무엇을 하면 되는가.** 세 번째가 없으면 결과지가 시험지가 된다.

막연한 할 일을 쓰지 않으려고 **그 영역의 자료에서 재료를 가져온다.**
`verify_targets` 와 `artifacts` 가 그 자리다.

```
Gap     구조·내구 해석 · 무엇과 비교해 확인했는지가 비어 있습니다
왜      이것이 없으면 해 본 일을 다른 사람에게 보여줄 방법이 없습니다
다음에  다음에는 결과를 손계산이나 선행 해석과 한 번 비교하고,
        차이가 난 이유를 적어보세요.
```

검사가 `역량을 강화하세요` · `경험을 쌓으세요` · `전문성을 높이세요` 를 센다.

## 등급은 쪽수로 갈리지 않는다. 해석의 깊이로 갈린다

| 등급 | 보여 주는 것 | 두지 않는 것 |
|---|---|---|
| BASIC | 관심 · 경험 · 배울 뜻 · 먼저 살펴볼 영역 · 열두 영역의 상태 | 근거가 섰다는 판정 · 축별 상태 · 비어 있는 자리 |
| STANDARD | 여덟 축 상태 · 지금 쓸 수 있는 근거 · 비어 있는 자리 · 다음에 할 일 | 산업·역할 해석 · 연구 번역 |
| PRO | 위의 전부 · 연구·프로젝트 열 단계 번역 · 산업과 역할에서 다시 읽기 | |

**여덟 축을 묻지 않은 응시에서 축이 비었다고 적지 않는다.** 안 물어본 것을
`확인되지 않았습니다` 로 적으면 응시자가 자기가 빠뜨린 줄 안다. BASIC 의
영역 한 자리는 받은 것만 적는다: 관심과 해 본 횟수와 배울 뜻.

## 산업과 역할은 읽는 층이다

`반도체 적합도 92%` 같은 숫자를 만들지 않고 적합·부적합을 적지 않는다.
하는 일은 **같은 근거를 그 분야의 말로 다시 읽는 것**과 그 분야가 특히 자주
묻는 자리 가운데 비어 있는 것을 적는 것이다. 고르지 않은 나머지는
`부적합` 이 아니라 **아직 보지 않은 것**이다.

`v3:result` 가 산업팩을 바꿔 돌려 Core 판정이 글자까지 같은지 본다.

## 없는 숫자를 그리지 않는다

레이더 차트도 도넛도 백분율도 없다. 여덟 축은 **네 상태를 세 칸 눈금**으로
적고, 칸 수가 곧 상태다(아직 없음 · 받아서 수행 · 직접 수행 · 직접 결정).
**비율을 만들지 않는다**: `8축 중 5축`을 62.5% 로 바꾸면 그 소수점이
근거처럼 보인다.

## 굳혀 둔 결과를 다시 만들지 않는다

제출할 때 판단과 결과 모델을 **같은 줄에 적는다**(`v3_snapshots.payload` 와
`result_model`). 읽는 쪽은 다시 만들지 않고 그 줄을 꺼낸다. 엔진이 바뀌어도
그때 낸 결과지가 조용히 달라지지 않는다.

적히는 판본은 여섯이다: core · 문항 은행 · 판정 · 산업팩 · 역할팩 · 결과
모델. **화면에는 판본 코드를 적지 않는다**: 응시자에게 필요한 것은 이
결과가 고정돼 있다는 사실이지 `me-v3-scoring.1` 이 아니다.

## 종이

웹과 PDF 가 **같은 쪽을 읽는다.** 따로 그리지 않고 인쇄 매체로 열어 접는다.

- BASIC 4쪽 · STANDARD 8쪽 · PRO 10쪽 (A4, 여백 16/14mm)
- 영역 한 자리와 비어 있는 자리와 할 일 묶음은 쪽 가운데에서 잘리지 않는다
  (`break-inside: avoid`)
- **A4 의 글 폭은 690px 안팎이라** 좁은 화면 규칙(719px)이 종이에서도
  걸린다. 인쇄 규칙에서 되돌리지 않으면 인쇄본이 손전화 화면이 된다

만들면서 한 번 잘못 뽑혔다. 좁은 화면에서 접는 자리를 `<details>` 로
두었더니 **뽑기 직전에 브라우저가 쪽 폭을 좁히면서 `matchMedia` 가 다시
울려 접혔고**, 여덟 축이 통째로 사라진 종이가 나왔다. 접는 상태를 우리가
들고, 인쇄에서는 펴도록 고쳤다.

## 모바일은 데스크톱을 줄인 것이 아니다

- 첫 화면의 네 칸이 한 단으로 서고 그 차례가 읽는 차례다
- 영역 한 자리에서 **여덟 축은 접어 둔다**. 펴는 단추가 44px 이다
- 머리띠의 자리 이동은 한 줄로 두고 옆으로 민다. 두 줄로 접히면 브랜드
  줄을 덮는다
- 320px 에서 가로로 밀리지 않는다

## 아직 사람이 판단해야 하는 것

**할 일 문장이 실제로 할 만한가.** 재료는 영역 자료에서 왔지만, 그 문장이
학부생에게도 포닥에게도 똑같이 읽히는지는 파일럿에서만 나온다.

**비어 있는 자리의 차례.** 필수 축 → 산출물 → 비교로 두었는데, 이 차례가
사람이 느끼는 급한 차례와 같은지는 자료가 없다.

**근거가 하나도 없는 사람의 첫 화면.** 지금은 그 사실을 적고 한 걸음을
권하는 데까지다. 그것이 충분한지는 그 처지의 응시자에게 물어야 한다.

```bash
npm run v3:result          # 결과 모델 열다섯 가지
npm run v3:result:shots    # 결과지 화면 (데스크톱 · 모바일 · 320px)
npm run v3:result:pdf      # A4 세 벌
```
