# PCU HUMANIZATION + REFERENCE EXPERIENCE PASS

판정은 셋이고 **이 회차가 그 셋을 하나도 바꾸지 않았다**: `LOCAL PASS` ·
`PRODUCTION UNVERIFIED` · `PCU CANARY BLOCKED`. production 에 배포하지
않았고, `student_open` 과 `open_to_students` 를 한 줄도 건드리지 않았으며
(열린 Core 0개), 실제 PCU 학생에게 아무것도 공개하지 않았다. 운영 Canary
아홉 걸음은 `docs/metri/PCU_CANARY_FINAL.md` 그대로 사람이 밖에서 밟을
일로 남아 있다.

바꾸지 않은 것: scoring · threshold · Core · Domain · item id · item
count · Result decision · Evidence decision · Gap decision · Registry
mapping · DB schema. **문항의 측정 의미도 바꾸지 않았다**: 보기 넷의 뜻과
수와 저장되는 값과 `band()` 가 그대로다.

## A. 무엇을 쟀는가

`문구가 AI 같다` 를 눈으로 고치면 다음 회차에 그대로 돌아온다. 그래서 이
회차는 먼저 **세는 자**를 만들었다(`npm run v3:human`, 열 줄). 재는 것은
PCU 가 실제로 쓰는 **Core 열아홉**의 학생이 읽는 문장과, 제품과 같은 길로
떠 둔 화면 60벌·결과 60벌이다.

BEFORE 는 운영 Canary 기준선 커밋(`2448e43`)을 별도 worktree 에 세워 **그
자리의 콘텐츠로** 돌린 값이다. 짐작으로 적은 수가 한 줄도 없다.

`DUMP=var/content-qa-hm npm run v3:human` 그대로다.

**한도를 0 으로 둔 말**(①)은 기준선에서도 여섯 자리뿐이었다. 그래서 이
회차의 실제 결함은 금지어가 아니라 다섯이었다: 종결 꼴이 한 틀에 쏠린 것 ·
직장 경력을 전제한 문장 · 질문과 보기 사이에 예시가 없는 것 · 한 결과지에
같은 판정문이 일곱 번 서는 것 · **영역 훑기 열두 줄이 한 틀로 끝나는 것.**

**⑩ 은 사람이 그림을 읽고 나서 더한 줄이다.** 격자를 찍어 놓고 보니 EE 의
열두 줄이 전부 `…정하는 일` 이었는데, ④ 는 **사다리 문항만** 세고 격자
줄을 보지 않아 그 자리를 한 번도 보지 못했다. 자를 먼저 고치고 나서
일곱 Core 의 줄을 다시 썼다(L 절).

## B. 문항 Humanization — 묻는 말로

**검사 문항은 수정하지 않고 판본을 올린다**(설계 원칙 4). 그래서 고친 것은
문면이고, 그것이 측정에 닿지 않는다는 것을 아래 F 절에서 값으로 보인다.

고친 갈래가 넷이다.

- **종결 꼴.** `…본 적이 있다` 가 Core 마다 13~33% 였다. 묻는 말로 바꾸고
  (`…봤나요?` · `…적 있나요?`) 같은 꼬리가 5% 를 넘으면 뜻이 같은 둘째
  꼴로 갈랐다. 가장 쏠린 자리가 4.8% 이고 종결 꼴 종류가 Core 마다
  41~59 에서 **69~126** 으로 늘었다.
- **직장 경력 전제.** `발주처` · `사내` · `부서` · `고객사` · `결재선` 처럼
  소속이 있어야 쓰는 말이 211자리였다. 학생이 떠올릴 자리의 말로 바꿨다
  (`맡긴 쪽` · `내부` · `팀` · `의뢰한 쪽` · `승인 절차`). 지금 0자리다.
- **권한 꼴.** `…ㄹ 권한을 가지고 그것을 정한 경험이 있다` 는 그 권한이
  있는 자리에 있어야 답할 수 있는 문장이다. `…는 몫을 맡아서 직접
  정했나요?` 로 바꿨다(188자리).
- **영역 훑기 줄의 한 틀.** 일곱 Core 에서 열두 줄의 끝맺음이 한 꼴에
  쏠려 있었고 EE·ARCH·VISUAL 은 **열두 줄이 전부** 같았다. 쉰 줄을 그
  영역이 실제로 하는 일의 말로 다시 썼다(L 절 ④).

바뀐 문면을 칸마다 세면 이렇다(기준선 `2448e43` 과 글자로 대조).

| 칸 | 바뀐 수 / 전체 |
|---|---|
| `wording` (문항 문면) | 5,934 / 7,639 |
| `stage_wording` (학위 장면) | 11,656 / 13,618 |
| `grid_row` (영역 훑기 줄) | **150 / 7,639** — 이번 회차에 더함 (고유 50줄 × 척도 3) |
| 합계 | 17,740 |

**단어만 치환해 통과시키지 않았다.** 그 증거가 둘이다. 하나는 종결을
줄이면서 드러난 **문항끼리의 뜻 겹침**이다: 12 Core 에서 모듈을 건너뛴
겹침이 걸리고 EE 한 쌍은 1.00(글자까지 같음)이었다. 33 문항을 그 산업과
역할의 조건으로 **다시 썼다**. 또 하나는 이 표를 뜨면서 찾은 조사 오류다:
`부서가` → `팀가`, `고객사가` → `의뢰한 쪽가` 처럼 **기계적으로 바꾼
자리의 조사가 깨져 있었다**(스물일곱 자리). 받침을 보고 고쳤고, 그래서
`v3:items:copy` 와 `v3:wording` 이 전부 통과한다.

## C. 질문 UX — 질문 → 짧은 예시 → 선택

- **예시가 한 줄도 없었다**(0자리). 보기 넷으로 받는 문항마다 그 영역
  체크리스트나 산업팩의 쉬운 말 풀이에서 한 줄을 뽑아 질문 바로 아래에
  세운다(`src/lib/me-v3/runtime/examples.ts` · 화면의 `예` 줄).
  **지어낸 예시가 아니다**: 그 Core 가 이미 들고 있는 자료다.
- **문항마다 장면을 붙이지 않았다.** 처음에는 문항마다 학생 장면을 넣어
  봤는데 `간호 동아리에서 줄 약을 처방과 대조했다` 같은 조합이 나왔다.
  장면은 묶음의 첫 질문 위에 **한 줄**로 서고(`sceneHint`), 담긴 자리는
  `content/me-v3-student-scenes.json`(Core 20 × 장면 6)이다.
- **설명문이 질문보다 세지 않게 했다.** 183자리가 걸렸는데 그 가운데 63이
  **용어 받침**이었다. 받침과 도움말은 하는 일이 달라서(앞엣것은 낱말의
  뜻, 뒤엣것은 답하는 법) 칸을 `term` 으로 갈라 `예` 줄과 같은 꼴로
  받친다. 나머지 120은 영역 훑기의 안내 둘이고 한 줄로 줄였다.
- **어긋나는 안내 한 줄을 고쳤다.** 훑기 안내가 `잘 모르는 줄은 가운데를
  고르면 됩니다` 였는데, 보기에는 `잘 모르겠다` 가 따로 있다. 그대로 두면
  **아직 모르는 사람이 `보통`(3)으로 적힌다** — 그 값은 그 사람이 고른 값이
  아니다.

## E. Result Humanization — 상담자의 말로

- **판정문 되풀이를 줄였다.** 한 결과지에 `확인되지 않았습니다` 가 여섯에서
  여덟 번, `확인됐습니다` 가 다섯 번 섰다. 빈자리를 **축마다 그 축의
  말**로 갈랐고(`AXIS_GAP_KO`), 빈자리마다 따라오는 까닭 줄
  (`scoring/text.ko.ts` 의 `REASON_KO`)과 산업·직무 절을 여는 줄도 고쳤다.

  정했는지가 덜 적혔습니다` 처럼 **무엇은 있고 무엇이 아직인지 같이**
  적는다. 그 모양을 `pcu:spec` 의 §6 이 여섯 까닭 전부에서 센다.

## F. Action — 대상 + 행동 + 남길 결과물

`관련 경험을 더 쌓아보세요` 류를 막는 자리는 글로 적어 두는 것으로는

## J. 이 회차에 찾은 것 — 잠근 척하고 아무것도 세지 않던 자리

**아홉 Core 의 문항 은행 동결이 빈 기록이었다**(`files: {}`). 그래서 BT ·
EDU · FOOD · HEALTH · LANG · LAW · NURSING · PSY · SPORTS 의 문면을 고쳐도
어느 검사도 걸리지 않았다. 까닭은 지문을 다시 적는 코드가 **셀 파일 목록을
그 기록에서 읽고** 있던 것이다: 비어 있으면 `BANK=update` 를 몇 번 돌려도
영원히 빈 기록이다.

목록을 등록부(그 Core 의 파일 넷 + 보탠 것 + 산업·역할팩)에서 만들게
고쳤다. 열아홉 Core 가 전부 **11벌**을 세고, 산업팩 한 파일에 줄바꿈 하나를
더해 **실제로 걸리는 것까지** 확인한 뒤 되돌렸다.

곁들여 ARCH 를 포함한 여섯 Core 의 동결이 **그 Core 의 산업·역할팩을 세지
않고 있던 것**도 같이 닫혔다(9벌 → 11벌).

## L. 찍어 놓고 사람이 읽어 고친 넷

자동 검사가 녹색인 것과 화면이 괜찮은 것은 다른 값이다. 아래 넷은 **그림을
사람이 읽어서** 나왔고, 넷 가운데 셋은 그 자리에서 **자를 먼저 고쳤다.**

**① 결과 상세 그림 여섯 장이 요약과 바이트까지 같았다.** 찍는 쪽이
`details` 의 속성만 세우고 있었는데, 본문을 접는 자리는 React 상태
(`Detail` · `Disclose` · `Fold`)라 **단추를 눌러야** 열린다. 더 나쁜 것은
그 그림이 `shoot()` 을 지나지 않아 **같은 그림을 거르는 줄에도 걸리지
않은 것**이다(156 / 156 통과). 눌러서 펴고, 펴졌는지를 지문과 글자 수로
센다. 고친 뒤 상세가 230KB 에서 1MB 가 됐다.

접는 자리가 **셋**이라는 것도 그때 드러났다. 처음에는 앞의 둘만 눌러
가장 안쪽 한 자리가 접힌 채 남았고, 그 자리는 닫힌 부모 안이라 크기가
0×0 이어서 `click` 이 2초를 기다리다 포기했다. 지금은 라운드마다 DOM 의
`click()` 으로 닫힌 단추를 전부 누르고 **남은 자리가 0 인지**를 센다.

**② 보기 읽는 법이 한 화면에 두 번 섰다.** 보기 넷 아래 줄글과, 바로 위
접힌 `보기가 어떻게 갈리나요` 가 같은 말을 한다. 줄글을 그 접는 자리
안으로 옮겼다(규격: 긴 안내는 접거나 제거). 문항 은행과 보기 문면은 한
글자도 바뀌지 않았고, 그 화면의 높이가 947px 에서 **900px** 이 됐다.

**③ 첫 화면의 `더 채울 부분` 이 한 줄로 이어 붙어 있었다.** 두 자리를
`영역 · 축` 으로 만들어 다시 `·` 로 이으니 같은 영역이 두 번 서고
가운뎃점이 넷이 됐다(`인사·조직 · 요구 해석 · 인사·조직 · 직접 판단`).
영역으로 묶어 한 번만 적는다(`인사·조직에서 요구 해석 · 직접 판단`).

**④ 영역 훑기 열두 줄이 한 틀로 끝났다.** EE·ARCH·VISUAL 은 **열두 줄이
전부** 한 끝맺음이었다(`…정하는 일` · `…가리는 일`). 격자는 응시자가 가장
먼저 읽는 화면이고 열두 줄이 한눈에 서므로, 그러면 진단이 아니라 **한 틀을
열두 번 찍은 표**로 읽힌다. 일곱 Core 의 줄 쉰 개를 그 영역이 실제로 하는
일의 말로 다시 썼다(EE·ARCH·VISUAL 각 10 · CS 6 · STYLE 6 · BT 5 ·
MEDIA 3).

**한도를 0 으로 두지 않았다.** 격자는 나란히 읽는 자리라 줄끼리 꼴이
비슷해야 훑어진다. ⑩ 이 재는 것은 한 끝맺음이 **절반을 넘는가**이고,
지금 가장 쏠린 자리가 열두 줄 가운데 다섯이다.

## M. 여섯 Core Human Review — 검사 → Result → PDF → "/me"

밟는 차례 그대로 찍고, **그림과 종이의 글자를 사람이 읽어** 적었다. 자동
확인은 같은 길에서 **168가지 · 통과 168 · 걸림 0** 이다.

|---|---|---|---|---|---|---|
| 경영 (경영학과) | 통과 | 통과 | 통과 | 0회 | 7쪽 · 표지에 학교·학과 | 지금 할 일이 첫 칸 |
| 컴퓨터·소프트웨어 (컴퓨터공학전공) | 통과 | 통과 | 통과 | 0회 | 7쪽 | 같음 |
| 전기전자공학 (전기공학과) | 통과 | 통과 | 통과 | 0회 | 7쪽 | 같음 |
| 간호 (간호학과) | 통과 | 통과 | 통과 | 0회 | 7쪽 | 같음 |
| 행정 (행정학과) | 통과 | 통과 | 통과 | 0회 | 7쪽 | 같음 |
| 미디어·광고홍보·공연 (광고사진영상학과) | 통과 | 통과 | 통과 | 0회 | 7쪽 | 같음 |

읽은 것을 그대로 적는다.

- **격자 줄이 그 전공의 일로 적혀 있다.** 미디어는 `무엇을 어떤 빛과
  앵글로 담을지 가리는 일`, 전기전자는 `증폭과 필터와 전원 회로의 소자값을
  정하는 일` 이다. 명사만 쌓은 줄이 한 줄도 없다.
- **문항 → `예` 한 줄 → 보기 넷** 차례가 여섯 Core 에서 같다. 보기 넷의
  말은 규격 그대로(`해본 적 없음 · 주어진 기준에 맞춰 해봄 · 방법을
  선택해 직접 해봄 · 기준부터 직접 정해봄`)이고 그 아래 네 글자 꼬리표가
  붙는다.
- **Result 첫 화면**이 스크롤 전에 여섯을 든다: 학교·학과·갈래 · 응답일과
  등급 · 핵심 해석 한 줄 · 확인된 경험 · 남길 근거 · 더 채울 부분 · 지금
  할 일. 종이는 표지에 같은 신분과 세 장의 차례를 적는다.
- **종이 일곱 쪽에서 `확인되었습니다`·`미확인입니다`·`보완이 필요합니다`·
  `근거가 있습니다` 가 0회**이고, `기계공학`·`역량을 강화`·`경험을 쌓아`
  도 0회다(여섯 Core 전부 `pdftotext` 로 셌다).
- **"/me" 의 첫 칸이 `지금 할 일`** 이고 그 아래 현재 상태 · 최근 변화 ·
  최근 기록(결과 보기 · PDF)이 선다.

**이 일곱 쪽은 이 길로 답한 사람의 종이다.** 끝까지 눌러서 제출한 응답이
얇아 쪽이 적고, 열두 영역을 두루 답한 사람의 종이는 `v3-pdf-audit` 이
재는 대로 **학교 Core 11~12쪽**이다(22벌 · 걸림 0).

## O. 아직 아닌 것

- **ChatGPT 1~8 Reference 이미지를 받지 못했다.** 받으면 그 기준으로 다시
  한 바퀴 돈다.
- 네트워크 정책이 `app.careermatri.com:443` 을 막아 **운영 배포본을 밖에서
  한 번도 열지 못했다**(HTTP 000). 그래서 판정은
  `LOCAL PASS / PRODUCTION UNVERIFIED` 이고 `PCU CANARY BLOCKED` 가
  그대로다. **운영에 배포하지 않았고** 학생 공개도 한 자리도 늘리지
  않았다(`BIZ_CORE_V1` 하나는 이 회차 전부터 열려 있던 Canary 자리다).
- 문항 5,953개가 그 전공에서 자연스럽게 읽히는지와, 보기 둘·셋·넷을
  응시자가 실제로 가르는지는 **그 전공을 아는 분과 파일럿이** 답한다.
  규준이 없으므로 `검증된 검사` 로 팔지 않는다.
- 종이 스물두 벌 가운데 셋은 **마지막 쪽이 25~43% 만 찬다**(ME STANDARD ·
  PSY PRO · EDU PRO). 걸림이 아니라 보고이고, **이 회차 전부터 있던
  자리**다: 쪽 높이가 고정이라 마지막 쪽의 채움은 문서 길이가 쪽 경계에
  어디쯤 떨어지는가로 정해지고, 한 자리를 올리면 다른 자리가 내려간다.
  **담긴 글을 깎아 맞추지 않는다.**
- iPhone Safari 실기기 확인이 남아 있다.
- 고친 것이 전부 이미지 안으로 들어가는 파일이라 **재배포가 먼저다.**
