# 글로벌 영어판 — 무엇을 옮겼고 무엇을 옮기지 않았는가

Phase 2.1 의 1~7번(ME_V2 영어 현지화 · 영문 결과지와 PDF · 두 언어 패리티 ·
지역화 덮임 검사)의 결과다.

## 0. 한 줄

**엔진을 두 벌로 나누지 않았다.** 채점도 판정도 한 벌이고, 갈리는 것은
화면에 나가는 글자뿐이다. 그래서 같은 응답이 두 언어에서 같은 직무·같은
결정 상태·같은 증거 범위를 낸다.

## 1. 사전의 열쇠가 한국어 원문이다

짧은 키(`rp.gap.title`)를 따로 지으면 이름 짓기에서 다투고, 결과지를
고칠 때마다 키와 글이 따로 놀다 어긋난다. 원문을 열쇠로 쓰면 **한국어는
사전을 거쳐도 그대로 나온다**: 한국어 쪽 회귀가 구조적으로 불가능하다.

```
T('아직 확인되지 않음')
  ko → '아직 확인되지 않음'   (받은 것을 그대로 돌려준다)
  en → 'Not confirmed yet'    (사전에 있으면 그것, 없으면 원문 + 샌 것으로 셈)
```

사전 1,987가지(`content/report-i18n.json`). 생성물은
`data/report-i18n.js` 이고 직접 고치지 않는다.

## 2. 사전과 **맞추기 어휘**는 다른 파일이다

| | 사전 `report-i18n.json` | 어휘 `match-glossary.json` |
|---|---|---|
| 무엇 | 화면에 나갈 **글자**를 바꾼다 | 응시자가 적은 글에서 **찾을 말**을 늘린다 |
| 방향 | 한국어 → 영어 하나 | 한국어 하나 → 영어 여럿 |
| 언어 | 지금 언어에 따라 갈린다 | **갈리지 않는다. 늘 양쪽을 함께 찾는다** |
| 크기 | 1,987가지 | 835가지 · 영어 낱말 1,030개 |

섞으면 둘 다 깨진다. 사전을 검색어에 들이대면 '요구조건' 을 찾을 때
`requirements` 로 바뀌어 **한국어로 적어 주신 분의 경험이 안 걸리고**,
어휘를 화면에 들이대면 낱말이 뜻 없이 흩어진다.

**이 어휘가 없을 때 무슨 일이 있었나.** 증거 지도의 검색어 786가지와
준비도 신호 매처 115가지가 전부 한국어였다. 같은 내용을 영어로 적은
응시자는 걸리는 신호가 적어 공백이 더 생기고, 그 공백이 되묻는 말을 더
띄워서 **영어 결과지가 등급마다 한 장씩 길어졌다.** 조판 탈로 보였던
것의 뿌리가 이것이다.

`npm run i18n:parity` 가 네 번째 항목으로 **어휘가 한국어로 적어 주신
분의 결과지를 건드리지 않는지**를 본다: 같은 입력을 어휘를 켜고 · 끄고
그려서 한 글자도 다르지 않아야 한다.

## 3. 올리는 순서가 번역보다 먼저다

엔진 파일들은 올라오는 순간 `PCAI18N.T` 를 붙들어 둔다.

```js
var T = window.PCAI18N ? window.PCAI18N.T : function (s) { return s; };
```

사전이 **뒤에** 오면 그 파일들은 번역 없는 함수를 평생 들고 있게 되고,
**그 파일이 그리는 자리만** 한국어로 나간다. 화면으로는 "거기만
한국어" 라서 눈에 잘 띄지 않는다. 실제로 학위 단계 이름이 영어판에서
`학부 ·` 로 나왔고, 까닭이 `v2.html` 이 `i18n.js` 를 `stage.js` 뒤에
올리고 있었기 때문이다.

그래서 **싣는 순서를 검사로 만들었다**(`global:check`). 사전이 엔진보다
먼저 오는지를 세 틀에서 본다: 정적 결과지(`v2.html`) · 플랫폼 결과지
틀(`report-host.html`) · 경험 입력 틀(`evidence-host.html`).

## 4. 굳는 표를 풀었다

모듈이 올라올 때 한 번 도는 자리에서 `T()` 를 부르면 그때의 언어로
굳는다. 고친 모양 둘이다.

```js
// 표는 한국어로 두고 **꺼낼 때** 옮긴다
function TX(tbl, key, dflt) {
  var v = tbl && tbl[key];
  return (typeof v === 'string' && v) ? T(v) : (dflt === undefined ? '' : dflt);
}

// 묶음으로 오는 데이터는 **쓰는 자리에서** 통째로 옮긴다
function DEEP(v) { return window.PCAI18N ? window.PCAI18N.deep(v) : v; }
```

**표를 내보낼 때 옮기지 않는다.** `ORG_TYPES: DEEP(ORG)` 처럼 내보내는
줄에서 옮기면 두 가지가 틀어진다: 파일을 읽을 때 한 번 돌아 그때의
언어로 굳고, 묶음을 통째로 옮기므로 **별칭·검색어·과목 목록까지 영어가
되어** 응시자가 적은 글과 견주는 쪽이 조용히 깨진다.

## 5. 응시자가 적은 글은 옮기지 않는다

경험·과제 제목·도구 이름은 그 사람의 글이다. 영어 결과지에서도 그대로
남는다. 패리티 검사가 한국어 과목 이름 하나(`재료역학`)를 일부러 섞어
두고 **그 글자가 영어 결과지에 살아 있는지**를 본다. 이 이름은 사전에도
들어 있는 낱말이라(전공지식 갈래 이름과 같다), 사전을 아무 데나 들이대면
`Mechanics of materials` 로 바뀌어 버린다.

고르기형 문항도 같은 규칙이다. **담기는 값은 한국어 그대로이고 보기
글자만 갈린다**: 값까지 갈리면 같은 응답이 언어마다 다른 답으로 저장되고,
그러면 영어로 푼 사람과 한국어로 푼 사람을 같은 자로 못 잰다.

## 6. 문항은 사전을 거치지 않는다

문항 본문·보기·척도는 **문항 은행이 두 언어로 들고 있다**
(`en-US` · `options-en` · `points-en` · `stage-variants` 의 `en`).
사전에 넣으면 문체 규칙이 문항을 다듬게 되고, 그 순간 문항이 바뀐다
(설계 원칙 4). 직무군 이름도 같은 이유로 `family-names.json` 의
`names-en` 짝이다.

## 7. 화면 하나를 그려 보는 것으로는 덮임을 알 수 없다

직무군이 열여섯이고 조직 유형이 일곱이라, 응시자 하나를 그리면 데이터
파일의 일부만 지나간다. 나머지는 **다른 응시자가 왔을 때 처음 샌다** —
그러면 그 사람이 첫 발견자가 된다.

`npm run i18n:coverage` 는 화면을 그리지 않고 데이터 파일에서 사람이
읽는 칸만 뽑아 사전과 대조한다. 처음 돌렸을 때 1,447칸 가운데 293칸이
비어 있었다. 운영 화면 `/admin/localization` 이 **같은 함수**를 부른다.

**맞추기에만 쓰는 칸은 넣지 않는다**: 별칭·검색어·과목 목록을 번역하면
맞추기가 조용히 깨진다.

## 8. 영어가 더 긴 것은 조판으로 맞춘다

PRO 가 처음에 한국어 17장 · 영어 23장이었다. **글을 깎아서 맞추지
않았다**: 영어판에서 문장을 덜어내면 두 언어가 다른 제품이 되고, 어느
쪽이 덜 받았는지는 받은 사람만 안다.

맞춘 것은 조판이다(`html[lang="en"]` 블록). 라틴 글자는 한글보다 작은
호수에서도 읽히므로 본문을 한 호수 내리고 줄 간격을 좁혔다. 한국어 쪽
선택자에는 걸리지 않아 **한국어 조판은 한 줄도 바뀌지 않았다.**

`npm run v2:pdf` 가 **두 언어 × 두 입력**을 센다. 입력을 둘로 두는 것은
쪽수가 언어 때문에 늘었는지 적어 주신 양 때문에 늘었는지 가르기
위해서다. 많이 적어 주신 응시자에게는 규격 장수를 들이대지 않고 두
언어가 같은 장수인지만 본다.

지금 열두 벌이 전부 12 / 14 / 17장으로 같다.

## 9. 검사 넷

```bash
npm run i18n:parity     # 같은 응답이 두 언어에서 같은 판정을 내는가 (+ 한국어 회귀)
npm run intake:i18n     # 응시 화면과 경험 입력 화면의 두 언어 (+ 한국어 회귀)
npm run i18n:coverage   # 데이터 파일이 다 덮였는가 (화면을 그리지 않는다)
npm run global:check    # 결제부터 PDF 까지 실제 DB·실제 브라우저로 영어 한 바퀴
```

앞의 둘은 **한국어 해시를 들고 있다.** 지역화 공사가 한국어를 한 글자라도
건드리면 거기서 떨어진다. 실제로 그 해시가 회귀를 두 번 잡았다.

## 10. 아직 아닌 것

- **인지 면접과 파일럿 200명을 돌리지 않았다.** 영어 문항이 한국어 문항과
  같은 것을 재는지는 확인되지 않았다. "검증된 영어판" 이라고 팔지 않는다
- **영문 약관·개인정보 처리방침이 없다.** 구조는 다 되어 있고 본문만
  넣으면 된다. 지금은 한국어 본문이 기준이라고 영어로 적는다
  (`docs/metri/38_commercial_readiness.md`)
- 튀르키예어·카자흐어는 켜지 않았다. 승인되지 않은 번역을 지어내지 않는다
