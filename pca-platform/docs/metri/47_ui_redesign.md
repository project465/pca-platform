# 47. 화면을 한 벌로 다시 짠다

> 2026-10-05. 운영 배포 직전에 시각 체계를 손봤다. **장사 논리는 한 줄도
> 건드리지 않았다**: 가격·이용권·결제 검증·Evidence·결과 엔진은 그대로고,
> 바뀐 것은 그 값을 어떤 모양으로 내보내는가다.

---

## 0. 왜 지금인가

운영 화면이 덜 다듬어져 보인다는 지적이 들어왔다. 쪽마다 공을 덜 들였기
때문이라고 보고 쪽을 하나씩 고치려 했는데, 세어 보니 원인이 따로 있었다.

```
globals.css  (옛 시안 토큰)   22쪽
surface.css  (sf- 토큰)       38쪽
둘을 섞어 쓰는 쪽               7쪽
```

**같은 제품이 바탕색 두 가지와 경계선 두 가지로 서 있었다.** 로그인은
`#EBEEF0` 바탕에 `#C9D2D8` 선이고, 개인 첫 화면은 `#f6f8fb` 바탕에
`#e3e8f0` 선이었다. 한 쪽씩 보면 둘 다 멀쩡하고, 이어서 누르면 다른
서비스로 넘어간 것처럼 보인다.

그래서 쪽을 고치지 않고 **토큰을 한 벌로 합쳤다.**

---

## 1. 값은 한 곳에만 있다

`surface.css` 의 `:root` 가 정본이고, `globals.css` 의 옛 이름은 그것을
가리키는 별명이다.

```css
/* globals.css */
--field: var(--sf-bg);
--paper: var(--sf-surface);
--ink:   var(--sf-ink);
--rule:  var(--sf-line);
--muted: var(--sf-ink-3);
--met:   var(--sf-ok);   --partial: var(--sf-part);   --gap: var(--sf-warn);
```

사용자 정의 속성은 **쓰는 순간에 풀린다.** 그래서 `globals.css` 가 먼저
실려도 뒤에 오는 `surface.css` 의 값을 읽는다. 색을 고치는 자리가 하나다.

규격 §55 가 적어 둔 것을 토큰으로 세웠다: 둥글기 셋(8·12·16), 여백
여섯(4·8·16·24·32·48), 글 폭 둘(읽는 자리 760 · 견주는 자리 1180),
활자 다섯(H1 32 · H2 24 · H3 18 · 본문 15 · 메타 13). **13px 과 15px 이
섞이면 줄이 안 맞는다.**

**보조 글자 색을 올렸다.** `--sf-ink-3` 가 `#78879c` 였고 흰 바탕에서
3.9:1 이라 규격 §44 의 AA(4.5)를 못 넘겼다. `#64748b` 로 바꿔 4.7:1 이다.
메타 글자는 작아서 가장 먼저 안 보이는 자리다.

---

## 2. 운영 메뉴가 두 벌이었다

`/admin` 은 왼쪽 띠(`NAV_ADMIN`)를 쓰고, 나머지 열 쪽은
`admin-shell.tsx` 안의 평평한 열다섯 줄을 썼다. 메뉴가 늘면서 그 띠가 두
줄로 접혔고, 지금 어디인지가 접힌 줄 아래로 밀렸다.

`admin-shell.tsx` 에서 메뉴를 들어냈다. 목록은 `NAV_ADMIN` 한 곳이고 그
파일은 옛 호출부(`user` · `current`)를 껍데기에 넘기기만 한다. **쪽 열
개의 TSX 를 고치지 않았다.**

묶음은 **누가 그 줄을 보는가**로 갈랐다. 쪽수가 아니라 묻는 때가 다르다.

| 묶음 | 줄 | 언제 보는가 |
|---|---|---|
| 오늘 | 한눈에 · 운영 당번 · 사고 | 아침에 연다 |
| 켜기 전에 | 런칭 준비 · 상용화 준비 · 지역화 덮임 · 사업자 표시 | 켜기 전에 한 번 |
| 손님과 돈 | 퍼널 · 주문 · 환불 요청 · 기관 · 계약 · 사용자 | 손님이 생긴 뒤 |
| 검사와 자료 | 상품 · 응시 현황 · 보고 | 자료를 볼 때 |
| 시스템 | 사이트 · 국가 · 감사 기록 | 가끔 |

**쪽이 없는 자리는 메뉴에 두지 않는다.** 예전 메뉴에 있던 `검사 문항` ·
`매핑 데이터` 는 쪽 자체가 없어서 눌러도 404 였다. 자리를 잡아 둔 것과
없는 것은 다르다. 쪽은 있고 자료가 없는 자리만 `soon` 으로 흐리게 둔다.

---

## 3. 옛 markup 을 새 껍데기 안에서 그린다

운영 화면 열 쪽이 `.panel` · `.sub` 와 맨 `h1` 으로 짜여 있다. 껍데기만
바꾸면 그 머리글이 브라우저 기본값(2em)으로 떠서 쪽마다 글자 크기가
달라진다. `surface.css` 끝에 다리를 한 벌 놓아 한 번에 맞췄다.

```css
.sf-wrap > h1 { font-size: var(--t-h2); ... }
.sf-wrap .panel > h2 { font-size: 15px; ... }
.sf-table input { border-radius: var(--r-sm); ... }
```

**장사 논리가 걸린 파일을 시각 작업으로 건드리지 않는 것**이 이번 작업의
선이다.

---

## 4. 고치다 드러난 것

화면을 다시 그리면 값이 틀리던 자리가 같이 드러난다. 이번에는 다섯이다.

**`--sf-r` 이라는 토큰은 없었다.** 상품 쪽 · 가격표 · 파일럿의 카드 일곱
자리가 `border-radius: var(--sf-r)` 로 적혀 있었고, 없는 토큰이라 전부
각진 사각형으로 떴다. CSS 는 모르는 변수를 조용히 넘긴다.

**결제 단추에 클래스가 없었다.** `className="btn solid lg"` 인데 `.btn`
규칙이 어느 CSS 에도 없다. **돈을 받는 쪽의 가장 중요한 단추**가 브라우저
기본 회색 단추로 서 있었다. `act solid full` 로 바꿨다.

**결제 화면이 금액에 `원` 을 박아 두고 있었다.**
`product.amount.toLocaleString("ko-KR") + "원"` 이라, `$14.99` 짜리
글로벌 상품이 `1499원` 으로 나갔다. `products.amount` 는 통화의 최소 단위
정수이므로 통화를 보고 적어야 한다(`src/lib/money.ts`). 한국만 열어 두면
안 보이고 글로벌을 여는 날 드러난다.

**플랫폼이 아직 옛 철자를 쓰고 있었다.** 소개 사이트는 `careermatri` 로
맞췄는데 `src/` 안의 사람이 읽는 글 45자리가 `Careermetri` 였다. 로그인
화면 머리글이 그중 하나다. 파는 쪽과 들어온 쪽이 다른 이름을 띄우면 같은
회사로 안 읽힌다.

**손전화에서 쪽이 가로로 밀렸다.** 로그인 전 띠가 390px 에 안 들어가
8px 넘쳤다. 한 줄을 지키려고 밀어내면 글이 왼쪽으로 잘린다. 아래로
접는다.

## 5. 색으로 좋고 나쁨을 칠하지 않는다 (규격 §39)

머리글 색을 `h1, h2, h3, h4` 에 한 번에 주려다 **어두운 바탕 위의 머리글이
바탕과 같은 색**이 됐다. 개인 첫 화면의 큰 칸과 결과지 표지가 흰 글씨를
물려받고 있었기 때문이다. 공통 규칙에는 굵기와 줄바꿈만 두고 색은 쓰는
자리에서 준다.

상태는 색 말고 **글자와 모양이 먼저 읽힌다**: `READY` · `WARNING` ·
`BLOCKED` 가 알약 안에 글자로 적히고 색이 거든다.

---

## 6. 무엇을 안 했는가

- **채점과 결과지 엔진에 손대지 않았다.** `sites/pca-platform/assets/` 는
  한 글자도 바뀌지 않았고, `i18n:parity` 의 한국어 해시 셋이 그대로다
- **문구를 고치지 않았다.** 바뀐 것은 배치와 크기와 색이다
- **새 그래프를 넣지 않았다.** 규격 §37 그대로 레이더·파이·도넛·게이지는
  없다
- **없는 것을 켜지 않았다.** 쪽이 없는 메뉴는 지웠고, 자료가 없는 쪽은
  여전히 '아직 열려 있지 않습니다' 를 적는다

## 7. 확인한 것

```
copy:audit · v2:check · golden:check · value:check · evidence:check
writing:check · domains:audit · i18n:parity · intake:i18n · ui:shots
```

`i18n:parity` 와 `intake:i18n` 의 **한국어 해시가 그대로**인 것이 이번
작업의 합격선이다. 화면을 다시 짰는데 결과지 글자가 한 자라도 달라졌다면
엔진을 건드린 것이다.
