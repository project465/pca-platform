# PCU 학과 콘텐츠 완성 — 학과마다 제 전공의 말로

**묻는 것은 `모든 학과가 Core 에 붙어 있는가` 가 아니다.** 그것은
`campus:check` 가 전부터 센다. 여기서 묻는 것은 **배재대 학생이 자기
학과로 검사했을 때 문항과 결과와 근거와 빈자리와 할 일과 산업과 직무와
종이가 그 학과의 말로 읽히는가**다.

읽는 순서: A 고정한 기준 · B 다시 만들지 않는 것 · C 자리마다의 판정 ·
D Wave 별 결과 · E 남은 것.

---

## A. PCU Content Standard — 상용 콘텐츠 QA 에서 확정한 것을 그대로 쓴다

앞 회차(`docs/metri/PCU_COMMERCIAL_CONTENT_QA.md`)가 확정한 아홉을
**학과 콘텐츠의 기준으로 고정한다.** 학과마다 새 문체나 새 결과 구조를
만들지 않는다.

| | 고정한 것 | 지키는 검사 |
|---|---|---|
| 문항 문체 | 능력·성향 단정 0 · 보고서 문체 0 · 번역투 0 · AI식 추상 0 | `v3:items:copy` |
| 용어 난이도 | 그 전공의 말은 쓰되 **받침을 말 표로 단다** | `v3:items:copy` · `me-v3-terms.json` |
| 보기 설명 | 넷의 뜻은 `ownership.ts` 하나 · 경계는 장면 하나씩 | `v3:copy` |
| 결과 문체 | 첫 화면 넷이 10초에 읽힌다 · 광고 말투 0 | `v3:content:audit` §8 · §17 |
| Evidence 표현 | 해석보다 **그 사람이 고른 항목**이 큰 자리를 찬다 | `v3:result:copy` |
| Gap 표현 | 무엇이 비었는가 · 왜 필요한가 · 다음에 무엇을 | `v3:result` |
| Action 표현 | 무엇을 · 어떻게 · 무엇으로 남길지가 보인다 | `v3:result:copy` |
| 종이 정보 차례 | 지금 확인된 것 → 할 일 → 모자란 것 → 산업·직무 | `v3:content:audit` §11 · §12 |
| AI 티 | 금지 낱말 열넷 · 되풀이 3번 이상 | `v3:content:audit` §10 · §17 |

## B. 다시 만들지 않는 것

```
PCU 실제 학과/전공 → Canonical Core → Specialization → 공통 CareerMatri Engine
```

**학과마다 검사 엔진을 만들지 않는다.** 이 회차에 한 줄도 건드리지 않은
것: scoring · threshold · Result model logic · routing · 판단축 · Core
구조 · PCU Registry 구조 · `student_open` · `open_to_students` · auth ·
DB 스키마.

**갈래가 조정하는 것은 다섯 층뿐이다**(등록부의 `specialization_contract`):
설명 차례 · 산업 mapping · 직무 mapping · 사례 · 근거와 할 일. 채점과 축
수준과 묶음 규칙과 문항 은행과 결과 모델에는 닿지 않는다.

## C. 자리마다 셋으로 가른다 (`npm run pcu:content`)

| 판정 | 뜻 |
|---|---|
| COMPLETE | 그 학과 학생이 그대로 쓸 수 있다 |
| THIN | Core 는 붙었는데 그 학과의 맥락이 얕다 |
| GENERIC | 같은 Core 의 다른 자리와 **학생에게 보이는 글이 거의 같다** |

재는 것은 그 자리가 받는 다섯 층이다. **갈래가 없으면 Core 가 들고 있는
것을 받는다**: 학과 하나가 쓰는 Core(간호 · 생명공학 · 심리상담)에서
갈래를 따로 두는 것은 같은 말을 두 자리에 적는 일이다. 갈래는 **한 Core 를
여러 학과가 나눠 쓸 때** 그 차이를 적는 자리다.

선은 이렇다: 강조 영역 3 · 장면 3 · 산출물 예시 3 · **학생이 낼 수 있는
근거 5** · 할 일 첫째와 다음 · 산업 2 · 직무 2. 가리키는 산업과 직무
코드가 그 Core 의 팩 안에 있는지도 함께 본다.

**Catalog 쌍둥이를 둘로 세지 않는다.** 2026 과 2027 에 같은 이름으로 선
자리는 같은 학과이고, 그것을 둘로 세면 학과 하나가 쓰는 Core 까지 갈래를
요구하게 된다.

**GENERIC 은 코드가 아니라 글로 센다.** 같은 Core 안의 두 자리가 학생에게
보이는 글(장면 · 산출물 · 근거 · 할 일)을 세 글자 묶음으로 견주어 0.6 을
넘으면 둘 다 GENERIC 이다. 코드만 다르고 글이 같으면 그것은 같은 결과다.

## E. 아직 아닌 것

- **갈래의 다섯 층이 결과지에 아직 닿지 않는다.** 지금 결과지가 읽는 것은
  갈래의 **이름**뿐이다(`result/meta.ts`). 등록부에 적어 둔 사례와 근거와
  할 일을 읽는 층은 다음 걸음이다. 받고 쓰지 않는 자리를 그대로 두지
  않는다.
- 운영 배포본을 밖에서 열지 못했다. 학생 공개 상태를 바꾸지 않았다.
