# PCU 학과 콘텐츠 완성 — 학과마다 제 전공의 말로

**묻는 것은 `모든 학과가 Core 에 붙어 있는가` 가 아니다.** 그것은
`campus:check` 가 전부터 센다. 여기서 묻는 것은 **배재대 학생이 자기
학과로 검사했을 때 문항과 결과와 근거와 빈자리와 할 일과 산업과 직무와
종이가 그 학과의 말로 읽히는가**다.

읽는 순서: A 고정한 기준 · B 다시 만들지 않는 것 · C 자리마다의 판정 ·
D Wave 별 결과 · E 갈래가 닿는 자리 · F 학과 결과 대조 · G 최종 제출 ·
H 남은 것.

---

## A. PCU Content Standard — 상용 콘텐츠 QA 에서 확정한 것을 그대로 쓴다

앞 회차(`docs/metri/PCU_COMMERCIAL_CONTENT_QA.md`)가 확정한 아홉을
**학과 콘텐츠의 기준으로 고정한다.** 학과마다 새 문체나 새 결과 구조를
만들지 않는다.

| | 고정한 것 | 지키는 검사 |
|---|---|---|
| 문항 문체 | 능력·성향 단정 0 · 보고서 문체 0 · 번역투 0 · AI식 추상 0 | `v3:items:copy` |
| 용어 난이도 | 그 전공의 말은 쓰되 **받침을 말 표로 단다** | `v3:items:copy` · `me-v3-terms.json` |
| 보기 설명 | 넷의 뜻은 `ownership.ts` 하나 · 경계는 장면 하나씩 | `v3:copy` |
| 결과 문체 | 첫 화면 넷이 10초에 읽힌다 · 광고 말투 0 | `v3:content:audit` §8 · §17 |
| Evidence 표현 | 해석보다 **그 사람이 고른 항목**이 큰 자리를 찬다 | `v3:result:copy` |
| Gap 표현 | 무엇이 비었는가 · 왜 필요한가 · 다음에 무엇을 | `v3:result` |
| Action 표현 | 무엇을 · 어떻게 · 무엇으로 남길지가 보인다 | `v3:result:copy` |
| 종이 정보 차례 | 지금 확인된 것 → 할 일 → 모자란 것 → 산업·직무 | `v3:content:audit` §11 · §12 |
| AI 티 | 금지 낱말 열넷 · 되풀이 3번 이상 | `v3:content:audit` §10 · §17 |

## B. 다시 만들지 않는 것

```
PCU 실제 학과/전공 → Canonical Core → Specialization → 공통 CareerMatri Engine
```

**학과마다 검사 엔진을 만들지 않는다.** 이 회차에 한 줄도 건드리지 않은
것: scoring · threshold · Result model logic · routing · 판단축 · Core
구조 · PCU Registry 구조 · `student_open` · `open_to_students` · auth ·
DB 스키마.

**갈래가 조정하는 것은 다섯 층뿐이다**(등록부의 `specialization_contract`):
설명 차례 · 산업 mapping · 직무 mapping · 사례 · 근거와 할 일. 채점과 축
수준과 묶음 규칙과 문항 은행과 결과 모델에는 닿지 않는다.

## C. 자리마다 셋으로 가른다 (`npm run pcu:content`)

| 판정 | 뜻 |
|---|---|
| COMPLETE | 그 학과 학생이 그대로 쓸 수 있다 |
| THIN | Core 는 붙었는데 그 학과의 맥락이 얕다 |
| GENERIC | 같은 Core 의 다른 자리와 **학생에게 보이는 글이 거의 같다** |

재는 것은 그 자리가 받는 다섯 층이다. **갈래가 없으면 Core 가 들고 있는
것을 받는다**: 학과 하나가 쓰는 Core(간호 · 생명공학 · 심리상담)에서
갈래를 따로 두는 것은 같은 말을 두 자리에 적는 일이다. 갈래는 **한 Core 를
여러 학과가 나눠 쓸 때** 그 차이를 적는 자리다.

선은 이렇다: 강조 영역 3 · 장면 3 · 산출물 예시 3 · **학생이 낼 수 있는
근거 5** · 할 일 첫째와 다음 · 산업 2 · 직무 2. 가리키는 산업과 직무
코드가 그 Core 의 팩 안에 있는지도 함께 본다.

**Catalog 쌍둥이를 둘로 세지 않는다.** 2026 과 2027 에 같은 이름으로 선
자리는 같은 학과이고, 그것을 둘로 세면 학과 하나가 쓰는 Core 까지 갈래를
요구하게 된다.

**GENERIC 은 코드가 아니라 글로 센다.** 같은 Core 안의 두 자리가 학생에게
보이는 글(장면 · 산출물 · 근거 · 할 일)을 세 글자 묶음으로 견주어 0.6 을
넘으면 둘 다 GENERIC 이다. 코드만 다르고 글이 같으면 그것은 같은 결과다.

## D. Wave 별 결과

| 단과대학 | 자리 | COMPLETE | THIN | GENERIC |
|---|---|---|---|---|
| 인문사회대학 | 16 | 16 | 0 | 0 |
| 경영대학 | 12 | 12 | 0 | 0 |
| 생명보건대학 | 14 | 14 | 0 | 0 |
| AI·SW창의융합대학 | 18 | 18 | 0 | 0 |
| 문화예술대학 | 30 | 30 | 0 | 0 |
| 아펜젤러공유대학 | 27 | 25 | 0 | 0 |
| **합계** | **117** | **115** | **0** | **0** |

남은 둘은 **자율전공학부**다. 전공을 고르는 자리라 Core 를 붙이지 않는다:
붙이면 아직 전공을 고르지 않은 학생이 **남의 전공의 자로 재어진다.** 고르면
전공 목록으로 돌려보내는 것이 맞는 동작이고, 세는 자리에서 뺀다.

**채운 것은 갈래 콘텐츠 마흔둘과 Core 층 셋이다.**

| | 한 일 |
|---|---|
| 갈래 42벌 | 학생이 낼 수 있는 근거를 **갈래마다 여섯 줄**씩 적었다(수업 · 과제 · 팀 프로젝트 · 실습 · 캡스톤 · 동아리 · 공모전 · 현장실습에서 나온다) |
| 새 갈래 넷 | `SPEC_EE_GENERAL` · `SPEC_FOOD_NUTRITION` · `SPEC_HEALTH_GENERAL` · `SPEC_LANG_KOREAN` — 한 Core 를 여러 학과가 나눠 쓰는데 갈래 없이 서 있던 자리 |
| Core 층 셋 | 간호 · 생명공학 · 심리상담은 **학과 하나가 쓰는 Core** 라 다섯 층을 Core 가 든다 |

**현업 경력자만 가능한 근거를 적지 않았다**(§9). 마흔두 갈래의 근거 252줄이
전부 수업과 과제와 실습과 동아리에서 나올 수 있는 것이다.

## E. 갈래가 결과지에 닿는 자리 (읽는 층만)

**등록부에 적어 두고 결과지가 읽지 않으면 그것은 적어 두지 않은 것과
같다.** 이 회차 전까지 결과지가 읽는 것은 갈래의 **이름**뿐이었다
(`result/meta.ts`). 그래서 같은 Core 를 쓰는 학과 둘이 머리말의 학과 이름만
다르고 나머지가 글자까지 같은 결과를 받았다.

닿는 자리를 둘로 두었다(`result/spec-view.ts`).

| 자리 | 무엇이 달라지는가 |
|---|---|
| 이어 볼 산업·직무 | **읽는 차례**를 그 학과의 `lead` 로 세운다. 걸린 자리는 응답이 정한 그대로이고 **빼거나 더하지 않는다** |
| 꺼내 쓸 경험이 없는 사람 | **그 학과 학생이 낼 수 있는 근거** 셋을 적는다. `없습니다` 만 적으면 무엇을 하면 적히는지가 종이 어디에도 없다 |

**판정에 닿지 않는다.** `spec-view.ts` 는 채점 모듈을 하나도 들여오지
않고, 축 수준과 묶음과 빈자리와 할 일은 결과 모델이 정한 그대로다.

## F. 학과 이름만 바꾸면 같은 결과인가 (`npm run pcu:generic`)

같은 Core 를 쓰는 **서로 다른 학과** 둘에 **똑같은 응답**을 넣고 결과 쪽을
받아 글자로 견준다. 열네 짝 전부 통과다.

**쪽 전체의 겹침이 0.91~0.93 인 것은 그대로 적어 둔다.** 같은 Core 에
같은 응답이면 묶음과 축 상태와 빈자리와 할 일이 **같은 것이 맞다** — 그것이
§0 이 요구한 판정 불변이다. 그래서 겹침의 선(0.97)은 `학과 이름만 바뀐
결과` 를 잡는 자리이고, 함께 세는 것이 **달라야 하는 자리가 실제로
달라졌는가**다.

경찰학전공과 법학전공이 받은 글의 차이가 그 예다.

| | 경찰학전공 | 법학전공 |
|---|---|---|
| 낼 수 있는 근거 | `사건 하나를 놓고 시간 차례로 사실관계를 적어 본 일` | `판례를 읽고 쟁점이 무엇인지 한 줄로 뽑은 일` |
| 이어 볼 산업 | 경찰·수사 → 교정·보호·출입국 | 기업 법무·준법 → 교정·보호·출입국 |
| 이어 볼 직무 | 수사·조사 → 사건·과제 관리 | 심사·판정 → 사건·과제 관리 |

## G. 최종 제출 (받은 §20 형식)

### College Coverage

D절의 표가 그것이다. 자리 117 · COMPLETE 115 · THIN 0 · GENERIC 0 ·
전공을 고르는 자리 2.

### Specialization Coverage

갈래마다 여섯을 센다: 강조 영역 3 · 장면 3 · 산출물 예시 3 · **학생이 낼 수
있는 근거 5** · 할 일 첫째와 다음 · 산업 2 · 직무 2. **PCU 가 가리키는 갈래
42벌이 전부 PASS** 이고, 가리키는 산업·직무 코드가 그 Core 의 팩 안에 없는
자리가 0 이다.

### PRO Result QA

`npm run pcu:coverage` 가 자리 115 를 끝까지 밟는다(학교 진입은 PRO 뿐이라
BASIC·STANDARD 를 만들지 않는다). 자리마다 응시 줄의 Core 와 학교와 학과와
갈래가 맞는지 · 결과 쪽이 학교와 학과와 갈래를 적는지 · 내부 코드가 새지
않는지를 본다.

### PDF QA

갈래마다 한 자리씩 종이를 뽑고 **쪽수만 세지 않는다.** 글자를 꺼내 학교와
학과와 갈래와 절 넷(먼저 볼 영역 · 지원서에 연결할 수 있는 경험 · 앞으로
채울 것 · 다음에 할 일)이 있는지와 **남의 전공 말이 섞였는지** 본다.

### Cross-Major Leakage

**검사가 제 몫을 했다.** 첫 판에서 건축학과 종이에 `수업 설계`(교육 Core 의
영역 이름)가 섞여 걸렸다 — 이 회차에 쓴 `수업 설계 과제에서…` 가 그
자리였다. `설계 수업 과제에서…` 로 고쳤고, 어문 갈래의 산출물
`수업 설계 한 벌` 도 `수업 계획 한 벌` 로 바꿨다. 지금 0건이다.

**거짓 경보 넷도 그 자리에서 좁혔다**: `수업 운영`(교육)은 어문의
`수업 운영·평가` 안에, `인사·조직`(경영)은 행정의 `인사·조직 관리` 안에
그대로 들어 있다. 짧은 이름이 긴 이름 안에 드는 자리는 남의 말이 아니다.

### Generic Result

F절의 표가 그것이다. 열네 짝 전부 통과.

### Regression

| 재는 것 | 결과 |
|---|---|
| 측정 동결 | 기록을 다시 적지 않은 채로 통과 (`v3:freeze:measure` 14가지) |
| Core 구조 | `v3:arch` 248가지 · `v3:extend` 14가지 통과 |
| 등록부 | 자리 115 를 밟는 동안 **한 바이트도 쓰지 않았다**(지문 그대로) |
| 학생 공개 상태 | **19개 그대로** |
| 판단 모듈 | 이 회차에 바뀐 파일 0 |

## H. 아직 아닌 것

- 운영 배포본을 밖에서 열지 못했다. **학생 공개 상태를 바꾸지 않았다.**
- 갈래 42벌의 근거 예시가 그 전공에서 실제로 나오는 경험인지는 **그 전공을
  아는 분**이 읽어야 한다. 기계가 센 것은 수와 겹침까지다.
- 자율전공학부 두 자리는 전공을 고른 뒤에 그 전공의 자리로 간다.
