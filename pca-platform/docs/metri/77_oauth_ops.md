# 77. 소셜 로그인 운영: 꽂는 값과 **애플 열쇠 갱신**

> **이 문서에 실제 값을 적지 않는다.** 적는 것은 환경변수 **이름**과
> 어디서 받아 오는지와 어디에 꽂는지다. 값이 문서에 들어오면 그 문서를
> 읽을 수 있는 사람 전부가 로그인 공급자를 쓸 수 있게 된다.

## 0. 지금 상태

`npm run oauth:ready` 가 답한다. **그 명령은 구글·애플에 붙지 않는다**:
코드가 준비됐는가와 이 배포본에 값이 있는가까지다. 실제 로그인은 사람이
브라우저에서 한 번 눌러 봐야 확인된다.

```bash
# 컨테이너 안에서 (Railway → 서비스 → ⋯ → Shell)
npm run oauth:ready
```

읽는 법은 `ops:check` 와 같다.

| | 뜻 |
|---|---|
| `READY` | 값이 꽂혀 있다. **공급자 콘솔 등록은 사람이 확인한다** |
| `BLOCKED` | 배포본 안인데 값이 없다. 손님 화면에 그 단추가 서지 않는다 |
| `UNKNOWN` | **배포본 밖이라 값을 안 들고 있다.** 운영이 비었다는 뜻이 아니다 |

**값이 비면 단추를 그리지 않는다.** 꽂히지 않은 공급자를 화면에 세우면
누른 사람이 공급자 쪽 `invalid_client` 화면에서 끝나고, 그 화면에는
돌아올 길이 없다. 그래서 **반만 꽂힌 것도 꺼진 것으로 센다.**

## 1. 꽂는 값 넷

| 이름 | 어디서 | 성격 |
|---|---|---|
| `AUTH_GOOGLE_ID` | Google Cloud Console → 사용자 인증 정보 | 공개값 |
| `AUTH_GOOGLE_SECRET` | 같은 자리 | **비밀** |
| `AUTH_APPLE_ID` | Apple Developer → Identifiers → **Services ID** | 공개값 |
| `AUTH_APPLE_SECRET` | 아래 3절에서 **만든다** | **비밀 · 만료 있음** |

꽂는 자리는 Railway → 서비스 → Variables 하나다. `.env.example` 에는
**이름만** 있고 값은 비어 있다(`npm run secrets:check` 가 센다).

## 2. 돌아올 주소

공급자 콘솔에 **글자 그대로** 등록한다. 한 글자 다르면 공급자가 거절하고,
그 거절은 우리 로그에 남지 않는다.

```
https://app.careermatri.com/api/auth/callback/google
https://app.careermatri.com/api/auth/callback/apple
```

- 주소의 앞부분은 `PLATFORM_URL` 과 같아야 한다. 메일 링크와 결제 콜백이
  이미 그 값을 쓴다(`src/lib/app-domain.ts`)
- **공개 전 배포본 주소를 등록하지 않는다.** 그 주소는 바뀌고, 바뀐
  다음에 등록해 둔 줄은 조용히 안 맞는다
- 구글은 `승인된 리디렉션 URI`, 애플은 `Return URLs` 다. 애플은
  **App ID 가 아니라 Services ID** 를 설정한다

## 3. 애플 `AUTH_APPLE_SECRET` 은 **만료되는 열쇠다**

구글의 secret 은 지우지 않으면 계속 산다. 애플은 다르다. 애플이 요구하는
client secret 은 **우리가 만들어 넣는 JWT** 이고, 애플이 받아 주는 최대
수명이 **6개월(180일)** 이다.

**그래서 아무것도 고치지 않아도 어느 날 애플 로그인만 멈춘다.** 비밀번호
로그인과 구글은 그대로 돌고, 멈춘 쪽은 애플 단추를 누른 사람뿐이라
운영 화면에서 눈에 띄지 않는다.

### 3-1. 만드는 데 필요한 것 셋

| | 어디서 |
|---|---|
| Team ID | Apple Developer → Membership |
| Key ID | Apple Developer → Keys → **Sign in with Apple** 용 키 |
| `.p8` 개인키 | 그 키를 만들 때 **한 번만** 내려받는다 |

`.p8` 는 다시 내려받을 수 없다. 잃으면 키를 새로 만든다. **저장소에 두지
않는다**: `npm run oauth:ready` 가 추적되는 파일에 `.p8` 가 있으면 걸린다.

### 3-2. 만드는 명령

```bash
# 이 저장소에 스크립트를 두지 않는다. 만드는 자리가 저장소 안에 있으면
# 그 자리가 .p8 를 찾게 되고, 결국 누군가 .p8 를 여기에 둔다.
# 사업주 기계에서 한 번 돌리고 결과 글자만 Railway 에 꽂는다.
npx -y apple-signin-auth-cli  # 또는 손으로: ES256 JWT
```

손으로 만들 때의 내용이다. **값 자리에는 받은 값을 넣는다.**

```
header   { "alg": "ES256", "kid": "<Key ID>" }
payload  {
  "iss": "<Team ID>",
  "iat": <지금>,
  "exp": <지금 + 15552000>,   # 180일. 더 길면 애플이 거절한다
  "aud": "https://appleid.apple.com",
  "sub": "<AUTH_APPLE_ID, 즉 Services ID>"
}
서명     .p8 개인키 (ES256)
```

### 3-3. 갱신 절차

1. 새 JWT 를 만든다 (3-2)
2. Railway → 서비스 → Variables → `AUTH_APPLE_SECRET` 을 **덮어쓴다**
3. 재배포가 끝나면 컨테이너에서 `npm run oauth:ready` → `apple` 이
   `READY` 인지 본다
4. **브라우저에서 애플로 한 번 들어가 본다.** 3번은 값이 꽂힌 것까지만
   말한다. 애플이 그 JWT 를 받아 주는지는 눌러 봐야 안다
5. 만료일을 달력에 적는다. **열쇠 자체에는 적지 않는다**

### 3-4. 저절로 갱신하지 않는 까닭

이 저장소는 **자동 갱신을 만들지 않는다.** 만들려면 `.p8` 개인키를 앱이
읽을 수 있는 자리에 둬야 하고, 그러면 그 키가 앱이 깨진 날 같이 샌다.
애플 로그인 하나를 편하게 하려고 **Sign in with Apple 의 뿌리 열쇠**를
서버에 두는 거래는 손해다.

여섯 달에 한 번 사람이 2분 쓰는 쪽을 고른다. 대신 **잠기지 않게** 해
둔다: 애플이 멈춘 날에도 비밀번호와 구글이 그대로 돌고
(`npm run auth:check` 의 15절 ⑦), 비밀번호를 정하면 그 사실이 계정 화면에
올라간다(같은 절 ②).

## 4. 멈췄을 때 어디를 보는가

| 보이는 것 | 거의 늘 이것이다 |
|---|---|
| 애플 단추가 아예 없다 | `AUTH_APPLE_ID` 나 `AUTH_APPLE_SECRET` 이 비었다 |
| 애플 쪽에서 `invalid_client` | Services ID 가 틀렸거나 secret 이 만료됐다 |
| 돌아오다 `redirect_uri` 오류 | Return URLs 에 등록한 주소가 한 글자 다르다 |
| 들어왔는데 `oauth_profile` | 공급자가 `sub` 을 안 줬다. 범위 설정을 본다 |
| `이미 계정이 있습니다` | **고장이 아니다.** 같은 주소의 계정이 있어 멈춘 것이다 |

마지막 줄이 설계다. 이메일이 같다고 자동으로 합치지 않는다. 합치면 남의
주소를 공급자에 등록한 사람이 남의 계정을 가져간다. 멈춘 자리
(`/login/link`)가 셋을 가리킨다: 그 계정으로 로그인 · 비밀번호 찾기 ·
고객지원.

## 5. 아직 아닌 것

- **실제 구글·애플로 한 번도 로그인하지 않았다.** 자격증명이 어디에도
  없고, 있어도 사람이 브라우저에서 눌러야 한다
- 공급자 콘솔에 돌아올 주소를 등록했는지 **코드가 알 수 없다.** 등록은
  콘솔 쪽 상태이고, 틀렸다는 것은 누른 사람만 본다
- `auth_accounts` 표가 운영에 섰는지는 `npm run db:verify` 가 답한다.
  이 문서의 어떤 줄도 그것을 대신하지 않는다
