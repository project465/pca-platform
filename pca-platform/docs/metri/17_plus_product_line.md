# 17. 메트리 플러스는 무엇을 파는가 — 무료 구간과 유료 구간

2026-09-12. 이 문서는 **"지표로 팔까, 다른 것으로 팔까"** 라는 질문에 대한 답과,
그 답을 코드에 어떻게 넣었는지를 적는다.

---

## 0. 질문

메트리(대학)는 지표검사다. 응시하면 지표가 나오고 그게 상품이다.

메트리 플러스는 다르다. 중·고등학생에게 필요한 것은 "너는 기계공학 89점"
이 아니라 **"그래서 다음 학기 과목 신청서에 무엇을 적는가"** 다. 그러면
파는 것도 지표여야 하는가?

## 1. 답 — 지표는 무료로 열고, 사슬을 판다

**지표를 팔지 않는다. 사슬과 과목 처방을 판다.**

이유 세 가지다.

**첫째, 지표에는 아직 규준이 없다.** 115문항으로 8계열 적합을 내지만
한국 중·고등학생 표본이 없어서 **"상위 몇 %" 를 말할 수 없다.** 원점수를
변환한 0–100 값이 있을 뿐이다. 규준 없는 점수를 19,000원에 파는 것은
설계 원칙 6("설명 못 하는 점수는 팔리지 않는다")에 정면으로 어긋난다.
규준은 실제 학생 수백 명이 풀어야 생기고, 그 학생들을 데려오는 가장
빠른 길이 무료다. **무료는 할인이 아니라 규준 수집이다.**

**둘째, 지표 층은 이미 공짜다.** 커리어넷·워크넷이 진로흥미검사를 무료로
준다. 거기와 같은 층을 유료로 놓으면 "왜 돈을 내는가" 에 답할 말이 없다.

**셋째, 사슬은 지금 당장 팔 수 있다.** 직무 16개 × 현장요구 48개 ×
과목연결 103개는 **점수의 정확도와 무관하게 참이다.** 구조해석
엔지니어가 하중 조건을 세우는 일을 한다는 것은, 그 학생의 적합도가
89점이든 71점이든 똑같이 사실이다. 규준을 기다릴 필요가 없는 유일한
자산이 사슬이다.

그래서 경계는 여기다.

| | 무료 | 유료 (19,000원) |
|---|---|---|
| 문항 | 115문항 · 약 15분 | (다시 풀지 않는다) |
| 계열 적합 | ○ 구간과 묶음 | |
| 공학 활동 8축 | ○ | |
| 응답 신뢰도 | ○ | |
| 업무 성향 6축 | | ○ |
| 현장 사슬 | | ○ |
| 과목 처방 | | ○ |
| 대학 권장과목 대조 | | ○ |

**성향 6축을 유료에 둔 이유.** 계열까지는 "무엇을 좋아하는가" 이고,
성향은 "같은 계열 안에서 어느 자리인가" 다. 과목 처방과 같은 층이라
같이 두는 쪽이 맞다. 무료 구간만 봐도 진로 방향은 잡히고, 유료 구간이
답하는 것은 **다음 학기 신청서**다.

## 2. 코드에서 경계가 사는 곳 — `src/lib/entitlement.ts`

경계를 화면에서 판단하면 화면이 늘어날 때마다 판단이 복사된다. 복사된
판단 중 하나가 틀리면 유료 내용이 새거나 산 사람이 못 본다. 그래서
**등급을 정하는 곳은 한 파일 한 함수다.**

```
reportLevel(attemptId) → "free" | "full" | null
```

우선순위는 네 단계고, 순서 자체가 결정이다.

1. `report_grants` 에 줄이 있으면 `full` — 업그레이드 결제로 열린 것
2. 좌석이 계약에 붙어 있으면(`seats.contract_id`) `full` — **학교가 사는 것이 사슬이다**
3. 주문 상품의 `products.report_level`
4. 그 외는 `free`

**4번이 기본값인 것이 일부러다.** 결제 경로를 잘못 배선하면 둘 중 하나가
일어난다 — 산 사람이 못 보거나, 안 산 사람이 본다. 앞쪽은 학생이 곧
항의해서 그날 고쳐진다. 뒤쪽은 아무도 항의하지 않아서 몇 달 간다.
그래서 모르면 덜 준다.

**2번이 학교 계약의 전부다.** 학교는 결제창을 거치지 않는다. 계약으로
좌석이 생기고, 계약 좌석이면 결제 기록이 없어도 `full` 이다. PG 가맹점
심사와 통신판매업 신고가 끝나기 전에도 매출이 나는 경로가 이것이다.

## 3. 가리지 않고 빼낸다

`buildReport` 가 무료 응시에 대해 **성향·사슬·과목 처방을 아예 조회하지
않는다.** CSS 로 흐리거나 자물쇠를 덮지 않는다.

```ts
const paid = level === "full";
const traits = paid ? indicators.filter((i) => i.kind === "trait") : [];
```

화면에서 가리면 HTML 에 그대로 들어 있다. 개발자 도구를 여는 중학생은
생각보다 많고, 한 번 새면 "돈 내면 열린다" 는 말이 거짓이 된다.
`prescribe()` 와 `careerChain()` 도 `paid` 일 때만 부른다 — 부르지 않는
쿼리는 샐 수 없다.

무료 구간이 끝나는 자리에는 **무엇이 남았는지 항목으로 적는다**
(`repLockItem1..4`). "전체 결과지를 보세요" 는 무엇을 사는지 모르게 한다.

## 4. 두 결제는 결과가 다르다

| | 새 응시권 | 업그레이드 |
|---|---|---|
| 상품 | `HS_FREE`(0원) · `REPORT_HS` | `HS_UPGRADE` |
| 만드는 것 | 좌석 | `report_grants` 한 줄 |
| 완료 화면 | "지금 바로 시작하실 수 있습니다" → `/test` | "남은 절이 열렸습니다" → `/report/{id}` |

**업그레이드에 좌석을 주면 안 된다.** 좌석 하나 = 응시 하나이므로 좌석이
하나 더 생기면 학생이 115문항을 또 풀 수 있게 되고, 같은 사람의 응답이
두 벌 쌓여 **규준이 오염된다.** 지금 없는 그 규준이 이 제품의 다음
자산이다.

그래서 `orders.upgrades_attempt_id` 가 어느 응시를 여는 결제인지 들고
다닌다. **"가장 최근 응시" 로 추측하지 않는다** — 두 번 본 학생이면 어느
쪽인지 알 수 없고, 틀린 쪽을 열면 돈을 받고 아무것도 주지 않은 셈이다.
남의 응시 번호를 넣어도 `startCheckout` 이 본인 것인지 확인한다.

`settlePayment` 는 `upgradedAttemptId` 를 돌려준다. 완료 화면이 그 값으로
문장과 링크를 고른다 — 업그레이드한 사람에게 "지금 바로 시작하실 수
있습니다" 를 띄우면 시작할 것이 없는 사람을 검사 화면으로 보낸다.

## 5. 무료도 같은 길을 탄다

0원이라고 PG 를 태울 것은 없다. 그런데 **좌석·회차·응시는 유료와 똑같은
길을 타야 한다.** 그래서 `openFreeOrder` 는 0원 주문을 만들어 바로
`status='paid'` 로 확정하고 좌석을 발급한다. 무료 전용 경로를 따로 파면
유료만 고치고 무료를 잊는 일이 생긴다.

**무료는 한 사람에 한 번이다.** 무한히 받을 수 있으면 — 유료를 살 이유가
사라지는 것이 아니라, 한 사람의 응답이 여러 벌 쌓여 규준이 오염된다.
두 번째부터는 이미 만든 무료 주문을 그대로 돌려준다.

다 풀고 채점까지 끝낸 사람이 무료 버튼을 다시 누르면 **이미 받은
결과지로 간다.** `currentAttempt` 는 `status <> 'scored'` 라서 끝낸
사람에게 `null` 을 주는데, 그 `null` 을 "좌석이 없다" 로만 읽으면
자기 결과지가 있는데도 결제 안내를 보게 된다. `lastScoredAttempt` 가
그 자리를 메운다.

## 6. 매출이 나는 순서

1. **학교 학년 단위 계약 — 지금 된다.** 계약이므로 PG 가맹점 심사도
   통신판매업 신고도 필요 없다. 학생은 결제 없이 전부 열린다.
   **무료 구간도 오늘 된다** — 0원 주문은 PG 를 거치지 않는다. 그 상태에서
   결과지는 "남은 절 열기" 버튼을 그리지 않는다(`checkoutReady()`) —
   누르면 오류 화면이 나오는 버튼은 안내가 아니다
2. **개인 19,000원 — PG 심사와 사업자 정보가 채워진 다음.**
   전자상거래법 제10조 표시(상호·대표자·주소·전화·이메일·사업자등록번호·
   통신판매업 신고번호)가 푸터에 있어야 결제를 받을 수 있다. 값은 지어내지
   않았고, 비어 있으면 금색 "확인 필요" 로 찍힌다
3. **재검 — 규준이 생긴 다음.** 무료로 모은 응답이 규준이 되면
   "지난해보다 어디가 움직였는가" 를 말할 수 있고, 그때 재검이 상품이 된다

## 7. 확인하는 방법

```bash
npm run metri:tier
```

여섯 절을 실제 DB 로 돌린다.

1. 무료 응시에 성향·사슬·과목 처방이 **오지 않는가** (가려진 것이 아니라)
2. 결제하면 **같은 응시가** 열리는가 · 결제가 점수를 바꾸지 않는가
3. 무료는 한 번인가 · 다시 눌러도 새 문항이 열리지 않는가
4. 학교 계약 좌석은 결제 없이 `full` 인가
5. 업그레이드 결제가 **좌석을 늘리지 않는가** · 웹훅 재수신에도 그대로인가
6. 등급을 못 가리는 응시는 `free` 로 떨어지는가

## 8. 아직 아닌 것

- **규준.** 무료 응답이 쌓이기 전까지 "상위 몇 %" 를 쓰지 않는다
- **개인 결제.** PG 가맹점 심사와 사업자 정보가 먼저다 (`LAUNCH.md`)
- **사슬 현직자 검수.** 48개 현장요구는 채용공고와 직무기술서에서 뽑은
  것이고 현직자 확인을 받지 않았다. 유료로 파는 것이므로 이것이 가장
  먼저 채워야 할 빈칸이다
