# 직무 일곱 · 무엇을 다르게 판단하는가

날짜 2026-10-08 · **구현 전 설계**

일곱을 유지한다. 다만 지금 구조에 결함이 둘 있어 먼저 적는다.

---

## 0 · 지금 구조의 결함 둘

**첫째, 역할 일곱과 직무팩 일곱이 다른 집합이다.**

| taxonomy 의 역할기능 | 가리키는 직무팩 |
| --- | --- |
| RF1 설계·개발 | ROLE_DESIGN_V1 |
| RF2 해석·예측 | ROLE_CAE_V1 |
| RF3 시험·검증 | ROLE_TEST_V1 **· ROLE_QUALITY_V1** |
| RF4 공정·양산 | ROLE_MFG_V1 |
| **RF5 운전·보전** | **없다** |
| RF6 통합·조정 | ROLE_PM_V1 |
| RF7 탐색·연구 | ROLE_RND_V1 |

RF5(운전·보전)를 가리키는 팩이 없고 RF3 를 가리키는 팩이 둘이다. 그래서
`설비기술` 을 보는 사람이 고를 자리가 없다. **품질·신뢰성을 RF3 에 묶은
것도 틀렸다**: 시험·검증은 `한 건의 판정` 이고 품질·신뢰성은 `양산 내내`
라서 taxonomy 의 경계표가 이미 둘을 가르고 있다.

**고치는 쪽**은 둘이다. 하나는 taxonomy 에 `RF8 품질·신뢰성` 을 세워
역할기능을 여덟로 늘리는 것이고, 다른 하나는 역할기능 일곱을 그대로 두고
**RF5 를 가리키는 설비·보전 팩을 새로 만드는 것**이다. 뒤엣것을 권한다.
역할 축을 늘리면 선호 문항과 결과지 절이 같이 늘어난다.

**둘째, CAE 팩과 R&D 팩 열두 문항에 영역이 없다.**

`technical_domain: null` 이라 그 응답이 **어느 영역의 근거로도 읽히지
않는다.** CAE 는 TD02·TD03·TD04 가운데 응시자가 깊게 본 영역에 묶고,
R&D 는 응시자가 고른 영역에 묶는다.

## 1 · 일곱 직무가 다르게 판단하는 것

각 직무를 `무엇을 정하는가` 한 줄로 못 박는다. 이 한 줄이 그 팩 문항이
전부 덮어야 하는 자리다.

### 설계 (RF1)

> **요구조건을 형상·치수·재질·공차로 바꾸는 판단.**

| 판단 차원 | 묻는 것 |
| --- | --- |
| 요구 우선순위 | 부딪히는 요구 가운데 무엇을 먼저 지킬지 |
| 치수 결정 권한 | 그 치수를 바꿀 권한이 내게 있었는가 |
| 공차 배분 | 누적을 어디에 몰아주고 어디를 조정으로 흡수할지 |
| 안전 여유 | 여유의 근거가 규격인가 해석인가 경험인가 |
| 제조성 | 만들 수 있는 안인지 누가 언제 확인했는가 |
| 변경 | 간섭이나 파손 뒤 무엇을 바꾸고 무엇을 지켰는가 |
| 채택 | 내 안이 검토를 지나 제작으로 갔는가 |

### CAE·해석 (RF2)

> **모델·가정·경계조건·검증 기준을 정하는 판단.**

| 판단 차원 | 묻는 것 |
| --- | --- |
| 이상화 수준 | 무엇을 단순화하고 무엇을 남겼는가 |
| 경계조건 | 구속과 하중을 누가 정했는가 |
| 재료·물성 모델 | 어느 모델을 왜 골랐는가 |
| 수렴·민감도 | 격자나 시간 간격을 어디까지 확인했는가 |
| 검증 대상 | 무엇과 견주어 맞다고 했는가 |
| 가정과 한계 | 보고서에 한계가 적혀 있는가 |
| 설계 반영 | 내 해석으로 설계가 바뀌었는가 |

### 시험·검증 (RF3)

> **무엇을 어떻게 재고 어떤 기준으로 통과를 판정할지 정하는 판단.**

| 판단 차원 | 묻는 것 |
| --- | --- |
| 시험 목적 | 이 시험으로 무엇을 확정하려 했는가 |
| 측정 지점·조건 | 어디를 어떤 조건에서 쟀는가 |
| 판정선 | 합격선을 무엇에서 가져왔는가 |
| 측정 체인 | 교정과 분해능을 따졌는가 |
| 산포 | 반복 측정과 불확도를 어떻게 다뤘는가 |
| 재현 | 다른 사람이 같은 값을 얻을 수 있게 적었는가 |
| 판정의 효력 | 내 판정으로 승인이나 변경이 결정됐는가 |

### 생산기술 (RF4)

> **반복 생산이 되게 공정 조건과 치공구·설비 조건을 정하는 판단.**

| 판단 차원 | 묻는 것 |
| --- | --- |
| 공법 선정 | 왜 그 공법인가 |
| 조건창 | 관리 범위를 어디까지 열어 두었는가 |
| 실험 설계 | 인자와 수준을 어떻게 골랐는가 |
| 공정능력 | 도면 공차를 공정이 지킬 수 있는지 숫자로 봤는가 |
| 치공구·설비 | 무엇을 새로 만들거나 고쳤는가 |
| 표준화 | 내 이름으로 표준이 나가고 개정까지 맡았는가 |
| 양산 이관 | 내 조건으로 라인이 돌았는가 |

### 품질·신뢰성 (지금 RF3 · 가를 것)

> **문제의 원인을 분리하고 재발을 막는 기준을 정하는 판단.**

| 판단 차원 | 묻는 것 |
| --- | --- |
| 관리 특성 | 무엇을 관리하기로 정했는가 |
| 관리 한계 | 한계를 무엇에서 가져왔는가 |
| 발생과 유출 | 둘을 갈라 각각의 대책을 세웠는가 |
| 가속 조건 | 가속이 실사용을 대표한다는 근거 |
| 수명 분포 | 어느 분포를 왜 썼는가 |
| 시정조치 | 조치가 재발을 막았는지 확인했는가 |
| 출하 판단 | 내 판단으로 출하가 결정됐는가 |

### 설비·보전 (RF5 · **새 팩**)

> **멈추지 않게 점검 항목과 주기와 교체 기준을 정하는 판단.**

| 판단 차원 | 묻는 것 |
| --- | --- |
| 대상 선정 | 어느 설비를 먼저 볼지 어떻게 정했는가 |
| 고장 모드 | 어떤 모드를 보기로 했는가 |
| 점검 항목·주기 | 주기를 무엇에서 가져왔는가 |
| 진단 신호 | 어떤 값을 전조로 쓰는가 |
| 교체 기준 | 언제 바꿀지의 근거 |
| 재발 | 같은 고장이 또 났을 때 무엇을 바꿨는가 |
| 효과 | 가동률이나 고장 간격이 어떻게 달라졌는가 |

### PM·기술기획 (RF6)

> **요구·일정·기술위험·인터페이스를 조정하는 판단.**

| 판단 차원 | 묻는 것 |
| --- | --- |
| 요구 분해 | 상위 요구를 어디까지 쪼갰는가 |
| 할당 | 누구에게 어떤 근거로 맡겼는가 |
| 검증 배정 | 요구마다 검증 방법을 정했는가 |
| 상충 조정 | 부딪히는 요구의 우선순위를 누가 정했는가 |
| 기술 위험 | 무엇을 위험으로 보고 무엇을 먼저 쳤는가 |
| 변경 영향 | 변경이 어디까지 번지는지 따졌는가 |
| 효력 | 내가 정한 범위대로 다른 팀이 움직였는가 |

### 탐색·연구 (RF7)

> **아직 답이 없는 것을 좁히는 판단.**

| 판단 차원 | 묻는 것 |
| --- | --- |
| 문제 좁히기 | 사양이 없는 상태에서 다룰 문제를 어떻게 정했는가 |
| 방법 선택 | 쓸 수 있는 방법이 둘 이상일 때 무엇을 기준으로 골랐는가 |
| 가정 | 무엇을 고정하고 무엇을 변수로 뒀는가 |
| 선행 대조 | 무엇과 견주어 새롭다고 했는가 |
| 재현 | 재현이 안 됐을 때 어디를 좁혔는가 |
| 산출물 | 논문·특허·시작품·방법 가운데 무엇이 남았는가 |
| 이전 | 결과가 과제나 제품으로 넘어갔는가 |

## 2 · 직무가 바꾸는 것과 바꾸지 않는 것

산업과 같다. **Core 판정을 바꾸지 않는다.** 직무가 바꾸는 것은 설명하는
차례와 비어 있는 축의 이름과 비교할 직무와 결과 문장이다.

**직무팩은 새 축을 만들지 않는다.** `core_ref` 로 Core 의 영역과
역할기능을 가리킬 뿐이다. PM 을 열셋째 기술영역으로 두지 않는다.
