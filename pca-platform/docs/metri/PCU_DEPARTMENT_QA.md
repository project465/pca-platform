# PCU 전 학과 콘텐츠 최종 QA (115 학과)

학과 수를 늘리지 않았다. 배재대 **전체 선택 자리 117 · Assessment 대상
115 · 자율전공 Routing 2** 구조를 그대로 두고, 그 115 자리의 **검사 문항
맥락 · 결과 · Evidence · Gap · Action · 산업과 직무 연결**이 그 학과의 말로
읽히는지 전수로 재고 고쳤다.

**측정과 판정에 한 줄도 닿지 않았다.** scoring · threshold · item id ·
item count · Core architecture · Domain definition · Result decision ·
Evidence decision · Gap decision · registry structure · `student_open` ·
`open_to_students` · DB schema 를 건드리지 않았고
`npm run v3:freeze:measure` 가 **기록을 다시 적지 않은 채로** 통과한다.

## A. §1 Coverage (개수만 세지 않고 학과 이름까지)

```
전체 선택 자리        117
Assessment 대상       115
전공 고르는 자리        2   자율전공학부(2026) · 자율전공학부(2027)
Core 없음(고장)         0
(Core · 갈래) 묶음     62   (앞 회차 60 → 갈래 둘을 새로 쓰고 62)
```

**전공을 고르는 자리는 콘텐츠를 받는 자리가 아니다.** 자율전공학부는 고르면
전공 목록으로 돌려보낸다. 거기 Core 를 붙이면 아직 전공을 고르지 않은
학생이 **남의 전공의 자로 재어진다.** 그래서 `Core 없음` 이 맞는 상태이고,
115 자리에서 뺀다.

**학년도마다 다른 묶음을 가리키는 학과는 0 이다.** 2026 과 2027 에 같은
이름으로 선 자리는 같은 학과이고, 두 Catalog 가 같은 (Core · 갈래) 를
가리킨다.

**이름이 바뀐 같은 학과를 둘로 세지 않는다.** 뒤의 여섯은 한 학과가 두
Catalog 에서 다른 이름으로 선 것이라 같은 묶음을 쓰는 것이 맞다. 앞의 둘은
**같은 Catalog 안에 서 있는 서로 다른 두 학과**였고, 그래서 학과 이름만
바뀐 같은 결과를 받았다.

- `SPEC_BIZ_GLOBAL_MGMT`(글로벌경영). 보는 것이 **한국 조직의 일하는

  전달 정확성**이고 값은 그 뒤다. 관광경영은 남은 수량과 값으로 판단한다.

## C. 받고 쓰지 않던 층 넷을 읽는 자리에 세웠다

**적어 두고 읽지 않으면 적어 두지 않은 것과 같다.** 갈래 계약의 아홉 층
가운데 학생이 읽는 자리에 닿는 것이 셋뿐이었다.

| 층 | BEFORE | AFTER |
|---|---|---|
| 검사 경험 예시 `examples.scene` | 한 자리도 읽지 않는다 | 검사 시작 안내 |
| Domain 설명 `domain_emphasis.lead` | 한 자리도 읽지 않는다 | 결과지 `경험·근거 분포` |
| 확인된 경험 설명 `examples.artifacts` | 한 자리도 읽지 않는다 | 결과지 `내가 이미 가진 근거` |
| Evidence 예시 `examples.evidence` | 읽는다 | 그대로 |
| 산업 · 직무 `*_mapping.lead` | 읽는다 | 그대로 |
| Action `evidence_action.first/next` | **읽는 층이 내놓지 않는다** | 결과지 `다음에 할 일` |
| 지원서·면접 `application` | **읽는 층이 내놓지 않는다** | 결과지 `다음에 할 일` |

**위의 할 일을 덮지 않는다.** 결과 모델이 낸 할 일은 응답이 가리킨 영역에서
나온 것이고, 새로 선 묶음은 **그 학과라면 어디에서 무엇을 정하고 무엇을
남기면 되는지**다. 둘을 한 자리에 섞으면 어느 것이 내 응답에서 나온 말인지
읽는 사람이 가를 수 없어서, 묶음을 따로 두고 머리에 전공 이름을 적는다.

**면접 답을 적어 주지 않는다.** 적는 것은 무엇을 묻는 자리인가까지이고,
거기 들어갈 말은 그 사람이 고른 항목에서 나온다.

## D. 검사 자신이 틀린 답을 낸 자리 넷

**거짓 경보를 내는 검사는 그 다음부터 아무도 안 본다.** 이 회차에 고친
검사 쪽 자리를 전부 적어 둔다.

**① 종이의 절 이름을 옛 이름으로 세고 있었다.** `pcu:coverage` 의
`PAPER_NEEDS` 가 `지원서에 연결할 수 있는 경험` 을 찾는데, 그 절은 결과 첫
화면을 다시 짜면서 `내가 이미 가진 근거` 로 **이름이 바뀌었다**(`d2acdf7`
이후). 그 뒤로 이 줄은 종이에 그 절이 서 있어도 늘 걸리는 줄이었고, 사람이
그것을 `pdftotext 가 없어 못 읽었다` 와 구별할 수 없었다. **절이 사라진
것과 이름이 바뀐 것은 다른 일이다.**

**② 갈래 없는 자리를 모자란 것으로 셌다.** 학과 하나가 쓰는 Core(간호 ·
생명공학 · 심리상담)에서 갈래를 따로 두는 것은 **같은 말을 두 자리에 적는
일**이고, 그 자리의 머리말은 Core 이름만으로 그 학과를 가리킨다. 세는 것을
`그 Core 를 학과 여럿이 나눠 쓰는가` 로 바꿨다.

**③ 상황을 걸음마다 요구했다.** `먼저` 와 `다음` 은 한 Action 의 두 걸음이고
같은 자리에서 일어난다. 걸음마다 `수업 과제에서` 를 요구하면 같은 말이 두 번
서고, **그 되풀이가 바로 §13 이 막는 모양이다.** 어디에서 하는 일인지는
묶어서 한 번만 센다. 행동과 기준과 남기는 것은 걸음마다 센다.

**④ 기준을 가리키는 낱말이 너무 좁았다.** `적용할 조문의 문면` 과 `식재
지침의 간격 규정` 과 `틀어짐 허용 범위` 는 전부 대어 볼 자를 이름으로 적은
것이다. 반대로 `골라` 와 `고른` 은 넣지 않았다: 그 말은 **어느 경험을
적을지 고른다**는 뜻으로 거의 모든 문장에 들어 있어서, 넣으면 그 줄이
아무것도 세지 않는다.

**그 자리를 넓힌 뒤에도 23 묶음이 남았고, 그 스물셋은 글을 다시 썼다.**
검사를 느슨하게 해서 통과시킨 자리가 0 이다.

## E. 쓰는 class 이름이 CSS 에 있는지, 열두 번째

검사 시작 안내의 새 묶음에 `qs-scene` 이라는 이름을 지으려다 멈췄다. 그
이름은 **산업 장면 화면이 이미 쓰고 있어서** 격자 규칙이 함께 걸린다.
`.btn` · `--sf-r` · `.lg` · `empty` · `industries` · `OC*` · `.qs-steps` ·
`.cm-snap` · `.sf-kpis` · `sf-scroll` · `.sf-btn is-primary` 에 이어
열두 번째다. **CSS 는 모르는 이름을 조용히 넘기고 아는 이름은 조용히
가져간다.** 쓴 이름은 `qs-major` 다.

## H. 아직 아닌 것

**기계가 셀 수 있는 것은 여기까지다.** 갈래 62벌의 근거 예시와 할 일과
지원서·면접 재료가 그 전공에서 실제로 나오는 경험인지는 **그 전공을 아는
분이 읽어야** 한다. 그 자리가 G 절의 묶음이다.

규준도 백분위도 적합도 비율도 내지 않으므로 `검증된 검사` 로 팔지 않는다.

**학생 공개 상태를 바꾸지 않았다.** 네트워크 정책이
`app.careermatri.com:443` 을 막아 운영 배포본을 밖에서 열지 못했고, 운영
Canary 는 별개라 `PCU CANARY BLOCKED` 가 그대로다. DB 스키마를 한 줄도
바꾸지 않았으므로 마이그레이션은 필요 없고, 고친 것이 전부 이미지 안으로
들어가는 파일이라 **재배포가 먼저다.**
