# R9 — BIZ 근거 절을 다시 세웠다 (사람이 읽는 커리어 결과 경험)

범위는 **BIZ Evidence 한 절**이다. 측정과 채점과 Evidence 데이터의 뜻을
한 줄도 건드리지 않았고, 바꾼 것은 그 값을 어떤 차례와 어떤 꼴로
내보내는가다. 다른 Core 로 넓히지 않았다(§14): 읽는 층이 Core 를 모르게
짜여 있어 같은 틀이 스무 Core 에 그대로 서지만, **콘텐츠를 더 쓰거나
Core 쪽 자료를 고치지 않았다.**

제출 캡처는 `docs/metri/shots/review-loop/r9-evidence/` 여섯 장이다.

## 1 · 기존 구조에서 버린 것

- **경험마다 같은 네 칸을 세우던 틀.** `rs-ev-x` 하나에 `.is-lead` ·
  `.is-sub` 를 붙여 **같은 DOM 을 무게만 달리** 그리고 있었다. 담는 그릇을
  바꿔도 안의 차례가 같으면 두 경험이 한 틀의 변형으로 읽힌다.
- **칸마다 붙던 설명문.** `~적었어요` · `~정했어요` · `~만들어 뒀어요` ·
  `~쓰면 돼요` · `~말해보세요` 다섯 꼴이 경험마다 되풀이됐다.
- **들머리 두 문장**(`여기 있는 건 전부 직접 하신 일이에요. 지원서 쓸 때
  여기서 꺼내 쓰면 돼요.`).
- **닫는 안내 한 줄**(`문장으로 옮길 때는 아래 … 같이 펼쳐 두면 좋아요.`).
  아래 절이 이미 하는 말이다.
- **나머지 영역 한 문장**(`…에서도 직접 정한 내용이 남아 있어요.`).
  남은 영역의 **이름**이 곧 그 사실이다.
- CSS 로는 `.rs-ev-intro` · `.rs-ev-x` · `.rs-ev-of` · `.rs-ev-say` ·
  `.rs-ev-story` · `.rs-ev-line` · `.rs-ev-kept` · `.rs-ev-use` ·
  `.rs-ev-p` 아홉 묶음을 통째로 지웠다(화면·좁은 화면·종이 세 벌).

## 2 · 새 구조의 핵심

차례 자체를 갈랐다. **한 경험이 한 이야기**이고 둘은 서로 다른 이야기다.

```
경험 1   작은 eyebrow
         큰 한 마디          근거를 들어 여러 방법 중 하나를 골라 본 경험
         짧은 보조           목표가 애매한 부분은 가정을 세워 적었다.
         ── 금 ──
         남은 결과(가운데)   목표·지표 정리표 / 사업계획
         ── 금 ──
         지원서에 꺼낼 포인트 / 면접에서 받을 질문   (이름표가 **위**)

경험 2   ── 금 ──
         eyebrow             마케팅·시장에서 남은 것
         큰 한 마디          채널별 성과 비교표 / 캠페인 기획서   ← **결과물이 머리**
         평서문 한 줄        무엇을 알릴지 범위를 좁혀 적었고, 고객을 나누는
                             기준도 직접 정했다.
         지원서 / 면접        (이름표가 **앞**, 두 칸으로 눕는다)
```

돌려주는 다섯 토막의 **꼴이 서로 다르다**(`evidenceStoryKo`):
이어 주는 말 한 토막 · 이름씨로 닫는 큰 한 마디 · 이름씨 둘 · 이름씨 ·
물음표. 한 묶음이 전부 `~요` 로 닫히지 않는 까닭이 이것이다.

**둥근 면을 한 화면에 하나도 쓰지 않는다.** 가르는 것은 여백과 활자와
금뿐이고, 색은 eyebrow 와 남은 결과와 이름표에만 선다.
중심축이 **왼쪽 → 가운데 → 오른쪽으로 들인 왼쪽**으로 한 번 꺾인다.

## 3 · 삭제한 AI 티 문장

| 지워진 줄 | 자리 |
|---|---|
| `여기 있는 건 전부 직접 하신 일이에요. 지원서 쓸 때 여기서 꺼내 쓰면 돼요.` | 들머리 → `전부 직접 하신 일` |
| `목표가 애매한 부분은 가정을 세워 적었어요.` | 보조 → 평서문 한 줄 |
| `여러 방법 중 하나는 직접 정했어요.` | 큰 한 마디 → `… 골라 본 경험` |
| `목표와 지표를 정리한 표, 사업계획을 만들어 뒀어요.` | 남은 결과 → 이름씨 둘 |
| `하지 않을 것과 먼저 할 것, 이걸 어떻게 잡았는지부터 쓰면 돼요.` | 지원서 → `… 나눈 기준` |
| `전사 목표와 견줘 본 이야기로 이어서 말해보세요.` | 면접 → `“전사 목표와 어떻게 맞췄나요?”` |
| `채널별 성과 비교표를 왜 그렇게 만들었는지 적어보세요.` | 지원서 → `채널별 예산 배분을 정한 근거` |
| `채널별 예산 배분을 어떻게 정했는지 설명해볼 수 있어요.` | 면접 → `“고객을 나누는 기준은 어떻게 정했나요?”` |
| `영업·사업개발과 재무·투자 판단에서도 직접 정한 내용이 남아 있어요.` | → `그 밖에  영업·사업개발 / 재무·투자 판단` |
| `문장으로 옮길 때는 아래 … 같이 펼쳐 두면 좋아요.` | 통째로 지웠다 |

**`합니다 → 해요` 로 바꾼 것이 아니다.** 바꾼 것은 그 자리가 **무엇을
말하는 자리인가**이고, 그래서 열 줄 가운데 일곱이 문장에서 이름씨나
질문으로 성격이 갈렸다.

## 4 · `~요` 반복을 줄인 방법

자리의 **역할로 말투를 갈랐다**(§2).

- 경험 — 그 사람이 한 일이므로 **평서문** 한 줄(`… 적었다.`)
- 결과물 — 손에 남은 것이므로 **이름씨**(`목표·지표 정리표 / 사업계획`)
- 지원서 — 꺼낼 포인트이므로 **이름씨구**(`… 나눈 기준`)
- 면접 — 받을 말이므로 **물음표**(`“전사 목표와 어떻게 맞췄나요?”`)

같은 응답에서 **`~요` 로 닫히던 줄이 13줄에서 0줄**이 됐다. 세 블록이
잇따라 `~요` 로 닫히는 자리는 구조적으로 설 수 없다: 이어지는 네 토막의
꼴이 서로 다르게 정해져 있다.

## 5 · 마침표를 줄인 방법

**모든 UI 텍스트가 완전한 문장일 필요가 없다**(§1)를 자료 쪽에서 지켰다.
이름씨로 끝나는 토막(큰 한 마디 · 남은 결과 · 지원서 포인트 · 그 밖에)은
애초에 문장이 아니라 마침표를 붙일 자리가 없고, 질문은 물음표로 닫힌다.
남은 마침표는 **경험 하나에 한 개씩, 모두 두 개**다.

| | R8 | R9 |
|---|---|---|
| 마침표 | 14개 | **2개** |
| `~요` 로 닫는 줄 | 13줄 | **0줄** |

## 6 · 첫 노출 텍스트량

같은 응답(BIZ · 사람 C)에서 **펼치기 전에 읽는 글자**만 세었다(공백 제외).

```
R8  340자      R9  224자      66%
```

눈으로 재지 않았다. 앞 판본의 `text.ko.ts` 를 그 커밋(`e665968`)에서
그대로 들여와 같은 스냅샷으로 두 벌을 만들어 세었다. **그 임시 사본과
재는 스크립트는 세고 나서 지웠다**: 저장소에 옛 판본 사본을 남겨 두면
다음 사람이 어느 쪽을 고쳐야 하는지 모른다.

## 7 · 경험 1 과 경험 2 의 구조 차이

| | 경험 1 | 경험 2 |
|---|---|---|
| 큰 한 마디 | **직접 정한 판단**(`… 본 경험`) | **남은 결과물 이름** |
| 보조 | 큰 한 마디 **뒤** | 큰 한 마디 **뒤**, 평서문 한 줄 |
| 남은 결과 | **금 둘 사이에 가운데로 띄운다** | 머리로 올라가서 따로 세우지 않는다 |
| 이름표 | 글 **위** (지원서에 꺼낼 포인트 / 면접에서 받을 질문) | 글 **앞** (지원서 / 면접) |
| 넓은 화면 | 두 단 (글 `1fr` · 쓰는 자리 `17rem` · 왼쪽 금) | 오른쪽으로 들여 `44rem` · 쓰는 자리 두 칸 |
| 가르는 선 | 남은 결과 위아래 가는 금 | 묶음 위 금 한 줄 |
| 세로 길이 | 252px · 손전화 324px | 159px · 손전화 198px |

지원서 줄과 면접 줄이 **드는 재료도 갈린다**: 경험 1 은 그 영역이 일하는
차례(먼저 정하는 자리)와 견준 자리를 들고, 경험 2 는 고르신 판단 둘을
나눠 든다(지원서가 하나, 면접이 다른 하나). 그래서 `DB schema 가 같고
값만 다른` 인상이 서지 않는다.

## 고치지 않고 적어 두는 것

- **`요구 해석`**(축 이름)이 결과 쪽의 접힌 자리(`전체 보기`)에 그대로
  선다. `gate34-audit` 의 §12 가 16 Core 에서 잡는데, **이 회차가 만든
  것이 아니다**: 더 이른 완전한 떠 둔 글(`var/content-qa-pp`)에도 같은
  자리에 있다(앞 회차의 `content-qa-r8` 은 Core 가 46벌만 떠 있어 셋만
  잡혔다). 고칠 자리가 Gate 3·열두 영역 쪽이라 이번 범위 밖이다.
- **BIZ = PUBADM 으로 글자까지 같은 줄** 넷이 남는다. 두 Core 의 영역
  사전과 체크리스트가 같은 문장을 적어 둔 자리이고, 그 파일은 문항 은행
  지문이 덮는다(§12 수정 금지). 승인받고 고친다.
- 종이 보고 셋(ME STANDARD 38% · CS PRO 39% · SPORTS PRO 39%)은 R8 과
  같은 셋이다. 쪽 높이가 고정이라 이 자리는 제로섬이다.
