# Productization Phase 2 — 경험에서 현재 상태를 거쳐 다음 행동까지

이번 회차가 한 일은 하나다. **검사를 끝낸 사람이 경험을 하나 적고, 그
경험이 현재 상태를 어떻게 움직였는지 보고, 거기서 다음 행동으로 이어지는
길**을 끊기지 않게 만든 것이다.

```
홈 → 경험 추가 → 저장 → 반영 여부 확인 → 현재 상태 갱신
   → 달라진 점 확인 → 다음 행동 갱신 → 홈의 최근 변화
```

측정은 `ME_V3_MEASUREMENT_FREEZE_1` 에 그대로 머문다. 문항 은행과 채점과
결과 모델과 소유 판정과 묶음 규칙을 한 줄도 건드리지 않았고, 굳은
스냅샷도 그대로다. 아래 A 절에 그것을 어떻게 확인했는지 적는다.

---

## A. 건드리지 않은 것 (규격 §0)

| 잠근 것 | 확인한 방법 | 결과 |
|---|---|---|
| `ME_V3_MEASUREMENT_FREEZE_1` | `npm run v3:freeze:measure` | 14 / 14 |
| 문항 은행 `ME_V3_ITEM_BANK_V2.5` | 위 동결 검사의 파일 지문 19벌 | 그대로 |
| 채점 `me-v3-scoring.5` | 같은 자리 + 사람 12벌 Core 지문 | 그대로 |
| 결과 모델 `me-v3-result-model.5` | 같은 자리 | 그대로 |
| 소유 네 단계의 뜻 | `v3:scoring` 31가지 | 그대로 |
| 묶음(Z1~Z4) 규칙 | `v3:scoring` · `v3:gaming` | 그대로 |
| 산업·직무가 Core 를 바꾸지 않음 | `v3:result` 의 팩 교체 대조 | 그대로 |
| 굳은 결과 스냅샷 | `v3:product-loop` 7절 (전후 지문) | 글자까지 같다 |
| BASIC·STANDARD·PRO 가격과 권한 | 상품 표를 건드리지 않았다 | 그대로 |
| `APP_ENV` · `publicCommerceGate` · 결제 차단 | 건드리지 않았다 | 그대로 |

**경험 기능 때문에 검사 결과를 다시 쓰지 않는다.** 쓰는 자리가
`career_profiles` 와 `v3_actions` 뿐이고 `v3_snapshots` 은 읽기만 한다.
그 사실을 말로 적지 않고 지문으로 센다: 경험을 셋 더하고 반영을 세 번
누른 뒤에도 굳은 결과의 sha256 이 그대로였다.

## B. 이미 있던 연결 (규격 §1)

**새 기능을 만들기 전에 이미 있는 연결을 먼저 찾았다.** 아래가 그
추적표이고, 이번 회차가 새로 만든 것은 마지막 칸이 `끊김` 이던 두
자리뿐이다.

| 걸음 | route | 서버 함수 | 읽는 표 | 쓰는 표 | 끊긴 자리였나 |
|---|---|---|---|---|---|
| 경험 저장 | `/me/experience/new` | `saveExperience` → `addExperience` | `me-v3-2-*` 체크리스트 | `v3_experiences` · `career_events` | 아니오 |
| 반영 예고 | `/me/recompute` | `previewRecompute` | `v3_snapshots` · `v3_experiences` | 없음(읽기만) | 아니오 |
| 반영 | 같은 쪽의 폼 | `runRecompute` → `applyRecompute` | 위와 같음 | `career_profiles` · `v3_actions` · `career_events` | 아니오 |
| 현재 상태 | `/me/state` | `currentState` | `v3_snapshots` + `career_profiles` | 없음 | 아니오 |
| 다음 할 일 | `/me/next` | `actionsOf` · `importActions` | `v3_actions` | `v3_actions` | 아니오 |
| 홈의 최근 변화 | `/me` | `currentState` | 위와 같음 | 없음 | **끊김** |
| 결과지의 `지금 할 일로 담기` | `/v3/{id}/result` | 없었다 | 없음 | 없음 | **끊김** |
| 경험 목록 | `/me/experience` | `experiencesOf` | `v3_experiences` | 없음 | 아니오 |
| 결과 기록 | `/me/results` | `resultHistory` | `v3_snapshots` + `career_profiles` | 없음 | 아니오 |

끊겨 있던 둘은 이렇다.

**`지금 할 일로 담기` 가 아무것도 담지 않았다.** 그 단추는 `Link` 였고
`/me/next` 로 옮기기만 했다. 누른 사람은 그 쪽에서 `결과의 할 일 담기` 를
한 번 더 찾아 눌러야 했다. 단추의 말이 약속한 일이 일어나지 않으면 그것은
막다른 길보다 나쁘다. 읽는 사람은 담긴 줄 알고 떠난다.

**홈의 `최근 변화` 가 수만 적었다.** `판단 2개가 올라갔고 영역 1곳이
달라졌습니다` 로 끝나서, 읽는 사람이 **무엇이** 달라졌는지 알려면 다른
쪽을 열어야 했다.

## C. 네 가지를 흐리지 않는다 (규격 §2)

| 개념 | 어디에 사는가 | 화면에서 부르는 이름 | 바뀌는가 |
|---|---|---|---|
| Frozen Result | `v3_snapshots.result_model` | 검사 당시 결과 (`고정됨`) | 바뀌지 않는다 |
| Current State | `career_profiles` | 현재 상태 | 경험을 더하면 바뀐다 |
| Experience | `v3_experiences` | 경험 | 사람이 적는 입력이다 |
| Next Action | `v3_actions` | 다음 할 일 | 현재 상태의 빈자리에서 나온다 |

화면이 그 차이를 말로 적는 자리가 셋이다. 현재 상태 쪽의
`검사 당시 결과와 지금` 묶음, 그 아래의 `두 값은 서로를 덮지 않습니다`,
그리고 저장 직후 화면의 `검사 당시 결과는 그대로 남습니다` 다.

## D. 경험 추가를 세 걸음으로 (규격 §3·§4)

```
1단 무슨 경험이었나    제목 · 종류 · 때
2단 어떤 기술 판단이었나  기술영역 · 문제 · 직접 정한 것
3단 무엇이 남았나       결과물 · 확인 · 쓰인 자리 · 보완 설명
```

**DB 구조를 한 줄도 바꾸지 않았다.** 받는 칸과 저장 함수가 전과 같고,
바뀐 것은 그 칸을 한 번에 보여 주던 것을 세 판으로 나눈 것뿐이다.
세 판이 전부 폼 안에 그대로 있고(`hidden` 으로 가린다) **저장은 끝에서 한
번**이다. 걸음마다 저장하면 둘째에서 닫은 기록이 반쪽으로 남고, 그 반쪽이
판정에 들어간다.

고른 영역의 항목만 띄우는 규칙은 그대로다. 열두 영역의 항목을 다 펼치면
쓸 일 없는 칸이 이백 개 보이고 거기서 닫는다.

**두 자리를 규격과 다르게 두었고 까닭을 적는다.**

하나. **한 줄 설명을 필수로 만들지 않았다.** 그 칸(`note_text`)은 결과에
반영되지 않고 1년이 지나면 지우기로 되어 있다. 필수로 만들면 1년 뒤에
설명이 사라진 기록이 남는다. 제목이 이미 `무엇을 했는지 한 줄로` 를 받고
있어서 그 자리가 §3 의 한 줄을 든다.

둘. **`이 경험에서 무엇을 하셨나요` 축 체크박스를 걷었다.** 그 값
(`axis_codes`)은 표에 저장되지만 **어느 코드도 읽지 않는다.** 재계산은
고른 항목(문제·판단·결과물·확인·쓰인 자리)으로만 축을 정한다. 받고 쓰지
않으려면 묻지 않는 것이 맞다.

## E. 저장 직후에 다섯을 적는다 (규격 §5·§13)

```
저장됐다 → 이번 경험에서 새로 연결된 것 → 현재 상태에서 달라지는 것
         → 그다음에 할 일 → [현재 상태에 반영하기] [경험 기록으로 돌아가기]
```

**이번 경험으로 좁힌다.** 저장할 때 그 기록의 번호를 주소에 싣고
(`?new=`), 쌓인 경험 전부가 아니라 방금 적은 것이 만든 자리만 적는다.
번호가 없으면 어제 적은 경험이 올린 자리를 오늘 적은 것이 올린 줄로 읽는다.

전에는 이 쪽의 머리에 숫자 카드 셋(`올라가는 판단 2개` 같은)과 여섯 칸짜리
표가 먼저 섰다. 적은 사람이 묻는 것에 그 수가 답하지 않는다. 표는
`어느 경험이 어느 판단으로 갔는지 보기` 안으로 내렸다.

**달라지는 것이 없으면 그 사실과 까닭을 적는다**(규격 §13). 까닭을 셋으로
가린다.

| 까닭 | 화면이 적는 말 |
|---|---|
| 기술영역이나 항목을 고르지 않았다 | 기술영역과 그 영역의 항목을 함께 고르면 그 자리가 판단으로 들어갑니다 |
| 이미 확인된 범위였다 | 검사에서 이미 확인된 범위의 경험이라 더 올라갈 자리가 없었습니다 |
| 같은 자리의 근거가 아직 하나다 | 같은 자리에서 고른 항목이 둘이 되면 그때 확인으로 올라갑니다 |

## F. 저장과 반영의 구조 (규격 §6)

**구조 B 를 그대로 둔다.** 저장하면 무엇이 달라지는지 먼저 보여 주고,
사람이 누를 때 반영한다. 코드로 확인한 자리는 둘이다. `addExperience` 가
`career_events` 에 할 일 한 줄을 쌓고 끝나는 것, 그리고 `applyRecompute`
를 부르는 유일한 자리가 폼의 서버 액션(`runRecompute`)인 것이다.

자동 반영으로 바꾸지 않은 까닭이 둘이다. 계산이 깨진 날 저장까지 막히지
않게 하려는 것이 하나이고, 무엇이 달라지는지 먼저 보고 누르게 하려는 것이
둘이다.

**`보기` 라고 적힌 단추가 값을 바꾸지 않는다.** 규격 §5 는 주된 단추를
`현재 상태 보기` 로 적었는데, 그 단추가 하는 일은 지금 값에 적는 것이다.
말이 약속하지 않은 일을 하는 단추는 §16 이 막은 것과 같은 자리라
`현재 상태에 반영하기` 로 적고, 누르면 현재 상태로 보낸다. 반영할 거리가
없을 때만 `현재 상태 보기` 라는 평범한 링크가 선다.

## G. 현재 상태 첫 화면 (규격 §7·§8)

```
현재 상태 / 최근 반영 2026-10-10
① 지금 설명할 수 있는 영역 (최대 3)
② 최근 달라진 것 (실제 변화만)
③ 아직 부족한 것 (1~3)
④ 다음 행동 (1개)
⑤ 검사 당시 결과와 지금
그 아래가 세부: 전체 기술영역 · 자리별 근거 · 산업과 직무 · 지역
```

전에는 열두 영역이 묶음마다 칩으로 깔리고 그 아래 카드 여섯이 섰다.
그러면 읽는 사람이 자기 상태를 묶음 목록으로 읽고, **그래서 무엇을 하면
되는가**는 쪽 끝까지 내려가야 나왔다.

**점수처럼 견주지 않는다**(규격 §8). 두 칸을 나란히 두고 각 칸이 무엇인지와
서로를 덮지 않는다는 것을 적는다. `+1점` 도 `2 → 3` 도 쓰지 않고,
자동검사가 그 두 모양을 화면 글자에서 센다.

## H. 다음 할 일 (규격 §9·§10)

줄마다 넷이 붙는다.

| 칸 | 어디에서 오는가 |
|---|---|
| 무엇을 할지 | `v3_actions.body` (결과지와 같은 함수가 지은 문장) |
| 왜 필요한가 | 그 할 일이 가리키는 빈자리, 없으면 그 할 일을 고른 규칙 |
| 어느 자리 | 같은 빈자리의 이름 |
| 어떤 경험으로 | 굳은 결과가 든 재료, 없으면 그 영역의 산출물 목록 |

그리고 그 칸에 `경험에 추가` 가 붙는다. 할 일을 읽은 사람이 다음에 하는
일은 그것을 해 보고 경험으로 적는 것이라, 루프가 그 자리에서 이어진다.

**첫 화면에 하나만 강조한다**(규격 §10). 나머지는 `그 밖에 할 일 N가지`
안으로 접고, 거기에는 파란 단추를 세우지 않는다.

만들면서 한 자리를 고쳤다. **까닭을 빈자리에서만 찾으면 근거가 다 선
사람에게는 영원히 서지 않는다.** 그런 사람에게는 빈자리가 없고 할 일은
`정리` 다. 찾는 차례를 셋으로 두고(축까지 맞는 자리 → 굳은 결과가 적어 둔
번호 → 같은 영역의 첫 자리), 그래도 없으면 그 할 일을 고른 규칙이 말한
까닭을 적는다.

## I. 홈과 최근 변화 (규격 §11·§12)

홈의 넷이 전부 `currentState()` 한 자리에서 온다. 홈이 따로 요약을 짓지
않는다.

| 홈의 묶음 | 출처 |
|---|---|
| 현재 상태 | `currentState().zoneOf` · `gaps` |
| 지금 할 일 | `actionsOf()` 의 첫 줄 |
| 최근 변화 | `recentChangeKo(currentState())` |
| 기록 | `experiencesOf()` · `resultHistory()` |

**같은 변화를 세 화면이 한 말로 적는다**(규격 §12). 홈과 저장 직후와 현재
상태가 `src/lib/me-v3/change-text.ko.ts` 하나를 부른다. 따로 적으면 같은
변화가 서로 다른 말로 읽히고 어느 날 한 곳만 고쳐진다.

적는 모양이 이렇다.

```
구조·내구 해석에서 직접 정한 조건과 기준이 확인됐습니다
시험·계측에서 무엇과 비교해 확인했는지가 더해졌습니다
기구·제품 설계가 경험은 있지만 근거를 더 만들어야 하는 영역으로 옮겨 갔습니다
새 경험을 반영했고 현재 상태 판정은 그대로입니다
```

`경험이 추가되었습니다` 로 끝내지 않는다. 그 사실은 적은 사람이 이미 안다.

## J. 경험 목록과 고치기 (규격 §14·§15)

목록 한 줄이 다섯을 적는다. 제목 · 유형 · 날짜 · 연결된 기술영역 · 현재
상태 반영 여부다. 전에는 한 줄이 아홉 칸이었고 그중 다섯이 `문제 3개` 같은
**개수**였다. 개수는 훑는 사람에게 아무 말도 하지 않는다. 고른 항목은
`자세히 보기` 를 눌러서 본다.

**`반영됨` 을 경험 줄에 따로 저장하지 않는다.** 그 사실은 반영하는 자리가
이미 `career_events` 에 적고 있고, 두 곳에 두면 어느 날 한 쪽만 고쳐진다.
그리고 그 말의 뜻은 **그 경험이 지금 값을 셀 때 함께 세어졌다**까지다.
올라간 자리가 없는 것도 자료라서 그 사실은 현재 상태가 적는다.

**고치기는 이번 회차에서 만들지 않았다.** 규격 §15 가 삭제를 새로 만들
필요는 없다고 적었고, 지우기는 이미 있다. 고치기를 넣으려면 이미 반영된
근거를 되돌리는 규칙이 먼저 정해져야 하는데, 그것은 재계산 규칙을 바꾸는
일이라 측정 동결에 걸린다.

## K. 결과지의 CTA (규격 §16)

`지금 할 일로 담기` 가 폼이 됐고 담은 수를 주소에 싣는다
(`/me/next?taken=N`). **`0` 이 정상인 자리가 있다.** 담는 함수가 영역과
문장으로 보아 두 번 눌러도 늘지 않으므로, 이미 담아 둔 사람이 다시 누르면
0 이 맞는 답이다. 그 사실을 적지 않으면 누른 사람이 고장으로 읽는다.

담는 코드는 한 벌이다(`importActionRows`). 결과지 쪽과 할 일 쪽이 같은
함수를 부르므로, 어느 날 한 쪽만 고쳐질 자리가 없다.

## M. 빈 상태와 오류 상태 (규격 §18·§19)

아홉 가지를 실제로 눌러서 확인했다. 자리마다 **머리글만 있고 속이 빈 칸**이
없는지도 함께 센다.

| 상태 | 화면이 적는 것 | 확인 |
|---|---|---|
| 경험 0 | 적어 둔 경험이 없습니다 + 적는 길 | 통과 |
| 경험 1 | 그 줄과 반영 여부 | 통과 |
| 경험 다수 | 둘 다 서고 날짜로 정렬 | 통과 |
| 반영 전 | 아직 반영하지 않은 경험이 N건 | 통과 |
| 반영 후 | 최근 반영 날짜와 달라진 문장 | 통과 |
| 변화 있음 | 올라간 자리와 옮겨 간 영역을 문장으로 | 통과 |
| 변화 없음 | 그 사실과 까닭 셋 가운데 하나 | 통과 |
| 할 일 있음 | 하나만 강조하고 넷을 붙인다 | 통과 |
| 할 일 없음 | 담아 둔 할 일이 없습니다 + 담는 길 | 통과 |

오류는 둘로 가른다(규격 §19).

| 어디서 | 화면이 적는 것 | 다음 길 |
|---|---|---|
| 경험을 저장하지 못했다 | 적어 주신 내용은 아직 저장되지 않았습니다 | 그 화면에서 다시 |
| 경험은 저장했고 다시 계산하지 못했다 | 기록은 그대로 있으니 다시 적지 않으셔도 됩니다 | `다시 계산하기` |

한 문장으로 적으면 뒤엣사람이 처음부터 다시 적고, 그러면 같은 기록이 두 벌
쌓인다. **까닭은 버리지 않는다.** 화면에는 무엇을 할 수 있는지만 적고, 왜
틀어졌는지는 `oplog` 가 한 줄 남긴다(개인정보는 적지 않는다).

## O. 자동검사 (규격 §22·§26)

`npm run v3:product-loop` 가 규격 §26 의 열 가지를 실제 브라우저와 실제
DB 로 센다. `v3:loop` 가 묻는 것은 `그 쪽에서 다음 쪽으로 갈 수 있는가`
이고 여기가 묻는 것은 **`누른 일이 실제로 저장되고 그 저장이 다음 화면의
글자를 바꿨는가`** 다. 쪽이 전부 200 이고 링크가 전부 살아 있으면서
아무것도 저장되지 않을 수 있다.

```bash
npm run v3:product-loop   # 열 가지 · 확인 41가지 · 통과 41
npm run v3:loop:shots     # 캡처 13장 · 확인 44가지 · 통과 44
npm run v3:all            # 마흔 묶음 · 통과 668 · 걸림 0 · 보고 2
```

`v3:all` 의 `보고 2` 는 적어 둔 두 가지이고 걸린 것이 아니다. 하나는
`역방향 문항이 0개다` 이고(그 자리를 막는 것은 소유가 응답과 고른 근거
둘을 함께 보는 규칙이라 `v3:gaming` 이 센다), 하나는 화면 카피 검사가
사람 판단을 기다리는 자리다.

**`v3:gate` 가 걸렸다가 고쳐졌다.** 그 검사도 경험 폼을 제 줄로 적고
있었고, 세 걸음이 된 뒤로 가린 판의 칸을 누르지 못해 **아무것도 골리지
않은 기록**을 만들었다. 공통 바탕을 쓰게 고쳤다. 이것이 O 절의 마지막
문단이 말한 그 모양이고, 실제로 그렇게 깨졌다.

**만들자마자 셋을 잡았고 셋 다 화면이 200 으로 멀쩡히 뜨는 자리다.**

하나. **2단의 `다음` 이 폼을 보냈다.** 같은 자리에 `<button>` 둘을
삼항으로 두면 React 가 DOM 노드를 재사용하면서 `type` 만 `button` →
`submit` 으로 고친다. 클릭 처리기가 돌아 3단으로 넘어간 뒤, 브라우저가 **그
순간의 `type`** 으로 기본 동작을 정해 폼을 보낸다. 누른 사람에게는 3단을
건너뛰고 저장된 것으로 보이고, **결과물과 쓰인 자리가 통째로 빈 기록이
쌓인다.** `key` 를 갈라 노드를 새로 만들게 하고 한 겹 더로
`preventDefault()` 를 걸었다.

둘. **`당시 판본 보기` 가 `ME_CORE_V3` 를 그대로 적었다.** 접혀 있던 자리라
아무 검사도 보지 못했다. 새 검사는 접힌 자리를 펴고 본다. 뜻이 없는 전공
코드만 이름으로 바꾸고 나머지 판본 글자는 그대로 둔다. 그 묶음이 있는
까닭이 되짚는 것이고, 고객지원에 적어 보낼 값이어야 한다.

셋. **`왜 필요한가` 가 서지 않는 사람이 있었다.** H 절에 적은 자리다.

그리고 **같은 바탕을 세 자리가 따로 들고 있었다.** 사람을 만들고 끝낸
응시를 베껴 오고 세 걸음짜리 폼을 적는 일이 전부 같은데, 따로 적어 두면
폼이 세 걸음으로 바뀐 날 한 곳만 고쳐진다. 실제로 그 모양으로 깨질
자리였다. 가린 판의 칸은 눌리지 않아서, 걸음을 넘기지 않고 고르면 아무것도
골리지 않은 채로 저장되고 **검사가 끊긴 루프를 통과시킨다.**
`scripts/_loop-fixture.ts` 하나로 모았다.

**운영 배포본을 밖에서 열지 못했다.** 이 컨테이너의 네트워크 정책이

회차의 확인 범위는 로컬이고, 운영에서 같은 열세 걸음을 사람이 한 번 눌러야
확정된다.

없다. 영어판은 한 줄도 쓰지 않았다. 규준이 없으므로 `검증된 검사` 로 팔지
않는다.
