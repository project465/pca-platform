# HEALTH_CORE_V1 — 보건·의료복지 (2026-10-13)

PHASE 2 의 여덟 번째 Core 다. `src/` 아래에서 바뀐 파일이 **한 벌**이고 그것도
더하기만 했다(`result/chains.ts` · 영역 열둘의 작성 차례 · 판정 로직 0줄).
채점과 결과 판정과 Workspace UI 와 DB 스키마가 한 줄도 바뀌지 않았고 앞 열한
Core 의 지문이 그대로다.

```
영역 12 · 문항 369 (Core 233 · 팩 136) · 산업팩 8 · 역할팩 8 · 갈래 2
배재대 자리 65 → 69
```

## 돌봄 성향을 재지 않는다

이 Core 가 가장 쉽게 적성검사로 미끄러지는 자리다. 묻는 것은 `사람을 돕는
일이 좋다` 나 `어르신과 이야기하는 것이 편하다` 가 아니라 **무엇을 직접 정했고
그것이 어디까지 갔는가**다. 문서에 적는 것으로는 지켜지지 않으므로 둘이
막는다: 짝 표(`src/lib/me-v3/measurement/registry.ts`)가
`PREFERENCE × OWNERSHIP_4` 를 거절하고, 문항마다 primary construct 를 적어
두어(`health-v1-constructs.json`) 추론으로 지나갈 수 없다.

**평가·사정과 질 관리를 나눈 까닭**은 앞엣것이 하기 전에 그 사람의 상태를 보는
일이고 뒤엣것이 한 것이 기준에 들었는지 보는 일이어서다. 같은 까닭으로 현장
운영과 감염·안전을 나눴다: 앞엣것은 사람이 모자란 날 그래도 돌리는 쪽을 보고
뒤엣것은 **그래도 지킬 선을 세운다.** `사람을 돌보는 마음` 은 영역으로 두지
않았다 — 그것은 성향이고 이 Core 는 재지 않는다.

**필수 축을 영역의 성질에서 골랐다.** 교육 운영과 현장 운영은 실패·수정이
걸린다 — 그 일은 계획대로 안 되는 날이 많고 그 자리에서 고치는 것이 실력이다.
기록과 감염·안전과 법규 쪽은 산출물이 걸린다: **기록이 남지 않은 판정은 판정이
아니다.**

## 계열을 `HUMANITIES_SOCIAL` 로 둔 까닭

이름에 `보건` 이 들어 있어 STEM 으로 읽히기 쉽지만, 이 Core 가 재는 것은 사업과
제도와 기록과 청구와 사례를 가르는 판단이고 생명과학 실험대의 판단은 BT Core 가
든다. **계열은 어느 상품인가이고 시장 정책이 가리는 값이라** 재는 것에 맞춰
둔다.

## 축과 역할기능과 조직환경은 같은 코드다

J1~J8 과 RF1~RF8 과 OC1~OC7 이 기계공학 Core 와 **같은 코드**다. 이름은
보건·의료복지계열의 말로 바꿨다: 도면 자리에 **사업계획서와 사정 결과와 심사
의견과 인계 노트**가 선다. 공통 판단 여섯과 학위 묶음 스물넷의 문항 번호도 같게
둔다 — 결과지가 그 번호로 사람이 읽는 이름을 찾고 그 표는 Core 를 모른다.

## 산업팩 여덟

병원·의료기관 · 보건소·공공보건 · 요양·장기요양 · 복지관·지역복지 ·
심사·인증기관 · 보건의료정보 · 재활·치료지원 · 산업보건·직업건강.

**`공공기관` 을 산업으로 두지 않는다.** 그것은 소속의 성격이지 하는 일이
아니고, 같은 공공기관 안에서 보건소와 심사기관과 복지관이 서로 다른 판단을
묻는다. 병원과 요양기관을 따로 둔 까닭은 앞엣것은 재원일수와 환자 안전이,
뒤엣것은 등급과 입소율과 사고 없음이 기준을 정하기 때문이다.

## 역할팩 여덟

사업·제도 기획 · 평가·사정 · 청구·심사 판정 · 기록·정보 관리 · 현장 운영 ·
사례·행정 관리 · 조사·연구 · 감염·안전 규정 관리. 여덟이 역할기능 여덟과
하나씩 맞물리고, 묻는 것은 기술영역이 아니라 **그 자리에서 가진 권한과
범위**다.

## 갈래 둘

| 코드 | 이름 | 가리키는 자리 |
|---|---|---|
| `SPEC_HEALTH_LIFECARE` | 라이프케어 | 그 사람의 하루가 돌아가게 하는 쪽 |
| `SPEC_HEALTH_SOCIALWELFARE` | 사회복지·상담 | 여러 기관의 결정을 한 계획으로 묶는 쪽 |

**쓰이지 않는 갈래를 미리 적어 두지 않는다.** 보건행정 갈래와 의료정보 갈래는 그
자리를 가리키는 학과나 트랙이 생기는 날 그 전공을 아는 분이 쓴다.

**`간호학과` 와 `물리치료학과` 와 `작업치료학과` 는 별칭에 넣지 않았다.** 그
이름들이 묻는 판단은 그 사람에게 직접 손을 대는 쪽이고 이 Core 가 묻는 것은
사업과 기록과 청구와 사례를 가르는 쪽이다. `심리상담학과` 도 PSY Core 가 들고
있고, `사회복지학과` 는 `SOC_CORE_V1` 이 들고 있다. **한 학과 이름이 두 Core 로
갈리면 그 학과 학생이 어느 자로 재어졌는지 아무도 모른다.**

다만 배재대 `사회복지상담전공` 자리는 이 Core 로 보냈다: 사정과 연계와 자원
조정이 이 Core 안에 있고 `SOC_CORE_V1` 은 아직 내용이 없다. **전공군 이름 쪽은
갈라 둔 채로 두었고** 옮기는 판단은 두 Core 를 다 아는 분이 한다.

## 자동 검사가 잡은 자리 다섯

눈으로는 다섯 다 멀쩡해 보인다.

- **TD01 과 TD03 의 둘째 J7 문항이 글자까지 같았다**(1.00). 둘 다 `조건을 바꿔
  참여가 늘어난 것을 본 적이 있다` 였다. 참여가 늘어난 자리는 TD03 이 들고,
  TD01 은 **사업이 집행되지 않은 자리**(예산과 인력과 시기)를 묻게 고쳤다
- **산업팩 둘이 같은 말로 묻고 있었다**(0.73): 보건소와 산업보건이 둘 다 `건강이
  어떤지 묻는 말을 지표로 옮겨 적은` 이었다. 산업보건 쪽을 **부서와 작업
  단계로 갈라 세는** 쪽으로 다시 썼다
- **산업팩 셋이 Core 문항과 같은 꼴이었다**(0.52 · 0.67 · 0.44). 팩이 Core 의
  칸을 다시 읽는 것은 설계지만 같은 말로 묻는 것은 **응시자가 같은 질문을 두 번
  받는 일**이라 그 팩이 파는 것이 사라진다. 셋 다 그 산업의 조건을 들게 고쳤다

## 사람 열두 벌에서 고른 자리

영역을 고를 때 **필수 축이 무엇인지를 보고 골랐다.** 산출물이 빈 자리를 그리려면
산출물이 필수인 영역(TD10 · `J5`·`J7`)이 필요하고, 산출물만 비는 자리를 그리려면
산출물이 필수가 아닌 영역(TD11 · `J2`·`J6`)이 필요하다. 검증만 비는 자리는
**비교·검증이 필수가 아닌 영역**(TD08 · `J3`·`J5`)이어야 한다 — 필수면 까닭이
둘이 되어 근거가 서지 않는다.
