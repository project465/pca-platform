# BIZ FINAL COMMERCIAL SIGN-OFF

기준은 하나였다. **배재대학교 담당자에게 실제 화면을 보여줬을 때 `테스트
화면` 도 `AI 가 만든 진단 결과` 도 아닌 완성된 대학용 CareerMatri
상품으로 보이는가.**

구조를 바꾸지 않았다. 규격 §1 이 막은 아홉(Assessment 구조 재설계 ·
Interest pagination · 문항 은행 대량 수정 · Result section 추가 ·
신규 chart · 신규 기능 · 관리자 기능 · 115개 학과별 rewrite)에 손대지
않았고, 115개 자리는 regression 으로만 돌렸다.

측정은 `ME_V3_MEASUREMENT_FREEZE_1` 에 그대로 머문다: 문항 은행 · 채점 ·
소유 판정 · 묶음 규칙 · 결과 모델 · 등록부 · `open_to_students` · DB
스키마를 한 줄도 건드리지 않았고 그 동결이 **기록을 다시 적지 않은 채로**
통과한다(확인 14가지 · 걸림 0).

## A. 고친 자리

### §2 Result Hero 를 한 단계 더 개인화했다

머리글이 `지원서에서 정리해볼 만한 근거가 있는 영역이 있습니다` 처럼
**상태의 이름**을 적고 있었다. 담당자 앞에서 그 줄이 먼저 읽히면 결과지
전체가 그 말투로 읽힌다. 지금은 실제로 근거가 선 영역의 이름을 그대로
들고 말한다:

```
경영전략·기획과 마케팅·시장 쪽에서 지원서에 꺼내 쓸 경험이 있습니다
```

**가짜 개인화를 하지 않는다.** 이름을 뽑는 자리(`headlineDomains`)는
**그 머리글을 만든 묶음에 실제로 들어 있는 영역**만 본다
(`HEADLINE_ZONE`). 묶음이 그 영역을 하나도 들고 있지 않으면 이름 없는
기본 머리글로 떨어지고, 이름이 길어 42자를 넘으면 하나만 적는다.
`EVIDENCE_LOW_INTEREST` 는 관심이 낮은 쪽 차례를 본다: 근거가 선 쪽과
관심이 높은 쪽을 섞으면 그 줄이 다른 것을 가리킨다.

### §3 Hero 아래 설명을 한 문장으로

다섯 묶음의 lead 를 전부 다시 적었다. 가장 긴 것이 40자이고, 적는 것은
**왜 이 결론이 나왔는지**까지다. `해 본 일과 그때 직접 정한 것이 함께
확인됐습니다.` 장문 해석을 쓰지 않는다.

### §4 `확인된 경험` 을 한 문장으로 합쳤다

전에는 고르신 항목을 가운뎃점으로 이어 적어 데이터 나열로 읽혔다.
`pickSentenceKo` 가 둘까지 모아 **어미만 바꿔**(`~다` → `~고` ·
`~습니다`) 한 문장으로 잇는다. **새로운 사실을 만들지 않는다**: 담는 것은
confirmed evidence 로 들어온 항목 그대로이고, 어미가 다르면 합치지 않고
가운뎃점으로 둔다.

### §5 `지금 할 일` 에 이유 한 줄을 이었다

할 일 아래에 **그렇게 적어 두면 어디서 쓰이는지** 한 줄이 선다
(`actionWhyKo`). 아홉 할 일마다 다르고 전부 **Evidence → 지원서 구조가
이미 들고 있는 것**까지만 적는다. 합격이나 적합을 말하지 않는다.
`/me` 홈 Hero 도 같은 함수를 읽어 두 화면이 같은 말을 한다(설계 원칙 10).

**종이에서는 그 줄을 칸 밖으로 내린다**(`.rs-outcome-print`). 네 칸이
나란히 선 종이에서 한 칸의 글 폭이 230px 쯤이라 이 줄이 세 줄로 접히고,
그 11mm 가 문서 끝에서 쪽 하나를 더 열었다. **담긴 글을 한 줄도 덜어내지
않고** 글 폭 전체를 쓰는 자리로 옮겨 한 줄에 담는다.

### §7 Result 카드 넷의 무게를 다시 세웠다

카드 수를 늘리지 않았다. 위 줄에 `확인된 경험` 과 `지금 할 일` 이 서고
아래 줄에 `남긴 근거` 와 `더 채울 부분` 이 한 단 옅은 면으로 선다.
**카드 ② 가 카드 ① 과 같은 말을 하고 있었다**: 둘 다 영역 이름을 적어서
읽는 사람이 같은 칸을 두 번 읽었다. 지금은 실제로 남긴 산출물
(`artifacts`)을 먼저 적고, 그것이 없을 때만 영역 이름으로 내려간다.

### §8 Evidence 4단계와 빈 단계

네 단계는 그대로이고 각 단계가 이름표와 실제 내용 한 줄까지다. **빈
단계에 `아직 없음` 만 적지 않는다**: 비어 있는 칸의 이름을 들어 다음에
무엇을 적으면 한 문단이 되는지로 잇는다.

```
위의 직접 정한 것과 남아 있는 결과 칸을 채우면 한 문단이 됩니다
```

조사를 글자로 박지 않는다(`}을 채우면` 은 `v3:result:copy` 2번에
걸린다). 이름 뒤에 `칸` 을 두어 받침과 무관하게 선다.

### §9 내부 용어를 첫 문장에서 걷었다

`직접 판단한 것` → `직접 정한 것` · `판정 기준으로` → `기준으로` ·
`산출물을 남이 읽고 쓸 수 있게` → `만든 것을 남이 읽고 쓸 수 있게`.
`요구 해석` 과 `직접 판단` 같은 축 이름은 전 회차에 이미 읽는 자리에서
내렸다. **기계공학 말과 전공 말은 걷지 않는다**(`판정 기준` 은 그 분야의
뜻이다).

### §10 Interest Mobile 최종 tune

구조와 interaction 을 다시 뜯지 않았다. 재어서 고친 자리만이다
(`scripts/lab/interest-metrics.ts`, 360 · 390 · 430):

| | 360 | 390 | 430 |
|---|---|---|---|
| 가로 넘침 | 없음 | 없음 | 없음 |
| 보기 한 칸 높이 | 48~51px | 48~51px | 48~51px |
| 바닥 띠에 가린 보기 | 0 | 0 | 0 |
| `모르겠다` | 척도 밖 · 왼쪽 정렬 | 같음 | 같음 |

**질문과 제 보기 사이가 질문끼리의 거리보다 멀었다.** 한 질문이 길게
느껴지던 까닭이 그것이고, 묶음 사이를 벌리고 질문과 보기 사이를 좁혔다.

### §12·§13 종이 제목과 쪽 차례

모든 section 을 갈아엎지 않고 모호한 제목만 고쳤다. `같은 것을 그림으로`
→ `내 경험은 어느 단계까지 와 있는가` · `어디에서 찾을지` → `이 경험을
쓸 곳은 어디에 있는가`.

Page 2 는 머리글 → 카드 넷 → 산업·직무 한 줄 띠 차례이고, 그림 묶음은
**차례 → 막대 → 막대 설명 → 레이더 → 레이더 설명**이다. 설명이 그림보다
먼저 서는 자리가 0 이다.

### §14 Radar

키우지 않았다. 화면 260px · 종이 46mm 그대로이고, 적성·역량 순위·직무
적합도가 아니라는 경고가 범례 아래에 그대로 선다.

### §15 `/me`

구조를 바꾸지 않았다(Workspace 승인). Hero 가 두 층이고(행동 + 왜),
설명이 두 줄이며, 그 두 줄이 결과지의 `지금 할 일` 과 **같은 함수**에서
온다.

## B. 종이. CS PRO 열세 쪽을 닫았다

앞 회차에서 CS PRO 만 열세 쪽이었다(허용 10~12). 쪽 열둘이 58% 에서
끝나고 닫는 부록이 46% 라 104% 가 되어 들어가지 않았다.

고친 자리가 둘이고 **담긴 글을 한 줄도 덜어내지 않았다.**

1. **까닭 한 줄을 종이에서 칸 밖으로 내렸다**(위 §5). 230px 짜리 칸에서
   세 줄로 접히던 것이 글 폭 전체에서 한 줄이 된다.
2. **읽는 기준 넷을 한 줄에 세웠다**. 세 칸이면 두 줄이고 네 칸이면 한
   줄이라 닫는 부록이 46% 에서 39% 로 낮아진다. 칸 하나가 7.5pt 로 세 줄
   남짓이라 그대로 읽힌다.

곁들여 `#nearby` · `#fourkeys` 의 줄 간격을 2px 씩 줄였다(58% → 56%).

```
CS_CORE_V1 PRO   13쪽 → 12쪽 · 마지막 쪽 46% → 98%
PDF 22벌 · 걸림 0벌 · 보고 1벌
```

보고 한 줄은 `PSY_CORE_V1 PRO 마지막 쪽 39%`(목표 45%)다. 쪽 높이가
고정이고 종이에 세로 균형을 잡는 수단이 없어서, 마지막 쪽이 얼마나
차는가는 **문서 길이가 쪽 경계에 어디쯤 떨어지는가**로 정해진다. 한
자리를 올리면 다른 자리가 내려간다. 걸림으로 두지 않고 보고로 두는 까닭이
그것이고, 이 회차가 CS 를 닫으면서 PSY 가 46% 에서 39% 로 내려갔다.

**사인오프 학생의 종이는 열세 쪽이다.** 감사의 fixture 보다 근거를 많이
적은 사람이라 담는 글이 더 많다. **빈 쪽도 밀린 덩이도 없다**: 열세 쪽이
전부 89~99% 로 차 있고 마지막 쪽이 90% 다. 쪽수 범위는 감사의 사람 벌을
기준으로 잡은 예산이고, 근거를 더 많이 적은 학생의 종이가 길어지는 것은
조판 결함이 아니다.

## D. §18 Human Sign-off A~E

열두 장을 읽고 적는다.

**A. 학교 담당자에게 그대로 보여줘도 되는가: YES.**
쪽마다 `배재대학교 · 경영학과 · 경영 일반` 이 서고 안쪽 코드가 한 자리도
없다. 종이는 표지와 쪽 머리까지 학교 이름을 들고 나간다. 점수도 등급도
`PRO` 라는 상품 이름도 학생 화면에 서지 않는다.

**B. 학생이 별도 설명 없이 사용할 수 있는가: YES.**
시작 화면이 묻는 것 · 답하는 법 · 걸리는 시간 셋을 먼저 적는다. 손전화
세 폭에서 가로 넘침 0 · 바닥 띠에 가린 보기 0 · 보기 한 칸 48px 이상
이다. `모르겠다` 가 척도 밖에 서서 다섯 칸과 섞이지 않는다.

**C. AI 가 만든 결과물처럼 보이지 않는가: YES.**
결과 첫 줄이 그 사람의 영역 이름을 들고 말하고, 네 칸이 전부 **그 사람이
고른 항목**을 돌려준다. 재지 않은 것을 단정하는 말 열 가지가 0 건이고
(`v3:result:copy` 7번 · 문장 1,509줄), 기계로 쓴 냄새를 세는 자가
baseline 그대로다(`copy:audit` 44).

**D. 일반 진로검사보다 차별점이 보이는가: YES.**
Evidence 4단계가 `내가 한 일 → 내가 직접 정한 것 → 남아 있는 결과 →
지원서·면접에서 쓸 부분` 으로 선다. 비어 있는 칸이 보이고, 그 칸의
이름이 그대로 다음 할 일이 된다. 적성 유형도 백분위도 적합도 %도 없다.

**E. 다음 행동이 명확한가: YES.**
첫 화면 네 칸 가운데 `지금 할 일` 이 위 줄 오른쪽에 짙은 면으로 서고,
그 아래 한 줄이 **왜 그것을 하는지**를 적는다. 그 할 일을 그대로 담는
단추가 같은 화면에 있고, `/me` 홈 Hero 가 같은 문장을 든다.

**다섯 다 YES.**

## F. §20 판정

```
BIZ COMMERCIAL PRESENTATION READY   (유지)
PCU SCHOOL DEMO VISUAL READY        (이 회차에 선언)
PRODUCTION UNVERIFIED               (유지)
PCU CANARY BLOCKED                  (유지)
```

**운영은 이 세션에서 한 번도 열지 못했다.** 네트워크 정책이
`app.careermatri.com:443` 을 막고(HTTP 000) Railway Shell 권한이 없다.
위의 결과는 전부 이 기계에서 운영과 같은 배치로 띄워 돌린 것이다.
실제 학생 Pilot 은 `test001` Production Canary 가 끝난 뒤에 판단한다.

**학생 공개 상태를 바꾸지 않았다**: 열린 Core 는 운영 Canary 의
`BIZ_CORE_V1` 하나뿐이고 등록부 지문이 그대로다. DB 스키마를 한 줄도
바꾸지 않았으므로 마이그레이션은 필요 없고, 고친 것이 전부 이미지 안으로
들어가는 파일이라 **재배포가 먼저다.**
