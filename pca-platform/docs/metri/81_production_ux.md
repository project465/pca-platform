# 81 · Production UX 전면 정리

이 회차의 기준은 `기능이 도는가` 가 아니다. **들어와서 이어서 눌렀을 때
하나의 완성된 제품으로 읽히는가**다. 새 기능을 만들지 않았고, 채점과
문항 은행의 뜻과 ResultModel 과 상품 구조와 굳은 스냅샷을 건드리지
않았다. 보기 수를 늘린 자리 하나는 먼저 `docs/metri/80_scale_gate.md`
의 STOP GATE 를 지났다.

---

## A · App Shell 통합

**사용자 화면의 껍데기가 하나가 됐다.** `/my/*` 다섯 쪽이 쓰던
`components/sf/shell` 을 걷고 작업공간의 `CmShell` 로 모았다.

| 전 | 후 |
|---|---|
| `/me/*` 는 `CmShell`, `/my/*` 는 `sf/Shell` | 둘 다 `CmShell` |
| 띠가 두 벌 · 브랜드 글자와 머리띠가 다름 | 한 벌 |
| 개인 메뉴 아홉 줄이 `sf/nav.ts` 에 따로 | 띠는 `src/app/me/nav.ts` 하나 |

`sf/Shell` 은 Campus 와 Admin 이 계속 쓴다. 저쪽은 파는 제품의 화면이
아니라 **일하는 화면**이고 메뉴가 열다섯 줄이라 같은 띠에 담기지 않는다.
`NAV_INDIVIDUAL` 은 지웠다.

## B · 공개 전 시험 배포 문구

손님 화면에서 띠를 걷고 **운영자 화면(`/admin/*`)에만** 세웠다.
`APP_ENV` · `publicCommerceGate` · 실제 결제 차단 · 자물쇠를 한 줄도
건드리지 않았다.

가짜 결제를 진짜로 읽는 것을 막는 자리는 그대로 셋이다.

1. 공개 전 배포본은 `STAGING_BASIC_AUTH` 뒤에 있다(아는 사람만 연다)
2. 가짜 결제창이 제 머리글에 그것이 가짜라고 적는다
3. 운영에서는 `ALLOW_MOCK_PAYMENTS` 를 꽂아도 거절한다

띠는 그 셋 가운데 하나가 아니었다. 확인은 임시 운영자를 만들어 실제로
눌러서 했다: `/admin` 과 `/admin/ops` 에 띠가 서고 `/cores` ·
`/pricing` · `/sample` · `/v3/start` 에 없다. `staging:check` 의
판정을 `보인다` 에서 `손님 화면에 없다` 로 뒤집었다.

## C · Home 카드 구조

`/me` 가 **지금 상태 · 다음 한 가지 · 최근 변화** 셋으로 시작한다.
나머지는 `기록` 묶음으로 내렸다.

- **빈 카드를 세우지 않는다.** 점선 테두리에 `아직 없습니다` 를 적은
  칸이 넷까지 섰다. 자료가 없는 묶음은 그리지 않는다
- 단추를 같은 쪽으로 가는 것끼리 묶어 줄였다(§21)
- 최근 변화는 반영한 적이 있을 때만 선다

## D · Sidebar

묶음 넷이다: **지금 · 내 커리어 · 탐색 · 기타**. 줄마다 적던 한 줄
설명을 걷었다(아홉 줄이 열여덟 줄로 읽혔다). Track 한 줄만 `준비 중`
을 단다.

## E · Account 통합

`/my` 가 작업공간 띠의 `기타 · 계정` 줄이 됐고 쪽도 같은 껍데기 안에서
선다. 로그인 방법 · 주문 · 표시 언어 · 옛 검사 기록 · 계정 설정과 탈퇴.

## F · Interest 3 → 5

STOP GATE 를 먼저 지났다(`docs/metri/80_scale_gate.md`). **결론은
`새 mapping 이 필요 없다` 였다.** `band()` 가 처음부터 다섯 값을 받는
자였고(1~2 낮음 · 3 가운데 · 4~5 높음) 화면이 셋만 내놓고 있었다.
옛 응답은 같은 값으로 남아 같은 묶음으로 간다. `npm run v3:scale` 이
열두 가지로 그것을 센다.

## G · Learning Intent 3 → 5

같은 자로 같이 바꿨다. 읽는 자리도 `band()` 하나다.

## H · Experience scale

**늘리지 않았다.** `expLabel` 이 `2 이상` 을 한 이름(`SEVERAL`)으로
묶고 `touched()` 가 `>= 1` 만 본다. 다섯으로 늘리면 **받고 쓰지 않는
값이 둘** 생기고, 이 저장소는 그것을 금지하며 `v3:migrate` 가 센다.
차례만 적은 쪽부터로 돌렸다(`없다 · 한두 번 · 여러 번`).

## I · Ownership 넷

**유지했다.** 네 단계의 뜻이 판정 규칙과 묶여 있고(`ownership.ts`),
화면은 이미 네 글자 꼬리표(`경험 없음 · 조건은 주어짐 · 직접 수행 ·
직접 결정`)와 접어 둔 도움말(`보기가 어떻게 갈리나요`)을 쓰고 있다.
보기 문면은 문항 은행이 유일한 출처라 화면에서 바꾸지 않는다.

## M · 대학원 분기

전환 화면의 **번호 붙은 칸 셋**을 걷었다(안쪽 routing 차례가 그대로
화면이 됐다). 묶는 틀도 학위마다 다른 말로 갈랐다: 수업과 과제에서
무엇을 직접 하셨는지 · 연구에서 무엇을 직접 정하셨는지 · 문제와 가정을
어떻게 세우셨는지 · 어디까지 맡아서 끌고 가셨는지.

## N · Evidence chooser

- 묶음 이름을 **고르는 사람의 말로**(§16): `문제 정의` → `무엇을
  문제로 잡았는지`, `조직 활용` → `그 결과가 쓰인 자리`
- 넓은 화면에서 **두 칸**으로 세워 쪽 길이를 반으로 줄였다
- **접지 않았다.** 접으면 고르는 수가 줄고, 고른 항목이 소유 판정의
  근거라서 접는 쪽이 판정을 바꾼다. 가리지 않고 짧게 만드는 쪽을 골랐다

## O · 조직 유형 문구

## Q-1 · PDF 가 운영에서만 실패하던 까닭

https 에서 Auth.js 는 쿠키 이름에 접두사를 붙인다
(`@auth/core/lib/utils/cookie.js`).

```
로그인  __Secure-authjs.session-token
CSRF    __Host-authjs.csrf-token
```

`__Secure-` 와 `__Host-` 가 붙은 쿠키는 **secure 가 켜져 있어야만**
브라우저가 받는다. 그런데 PDF 를 그리는 브라우저에 쿠키를 넘기는 자리가
`domain` + `path` 모양이었고, 거기에는 secure 를 적을 자리가 없었다.
크로뮴은 그 줄 하나만 버리지 않는다. **묶음 전체를 거절한다.**

그 자리에서 https 서버를 띄워 눌러 봤다.

```
옛 모양 (domain + path)
  addCookies  거절: Protocol error (Storage.setCookies): Invalid cookie fields
  서버가 받은 것  (없음)
새 모양 (url)
  addCookies  넣었다
  서버가 받은 것  __Secure-authjs.session-token=abc123
```

쿠키가 없으면 그리는 브라우저는 로그인하지 않은 사람이고, 결과 쪽 대신
로그인 쪽을 받는다. 그래서 운영 로그에는 `step=render` 로만 남았고,
읽는 사람은 결과지를 뒤졌다. **로컬은 http 라 접두사가 붙지 않아 이
탈이 나지 않는다.**

고친 것 셋이다.

1. 넣는 모양을 `url` 로 바꿨다. 주소의 scheme 에서 secure 가 따라오고
   `__Host-` 의 조건(도메인 없음 · path `/`)도 같이 맞는다
2. 걸음에 `cookie` 와 `auth` 를 더했다. 쿠키를 못 넣은 것과 로그인
   쪽으로 떨어진 것이 이제 로그 한 줄로 갈린다
3. `npm run v3:owner` 가 넣는 모양을 글자로 지킨다. 이 기계는 http 라
   그 탈을 재현할 수 없으므로 **모양을 센다**

**운영에서 실제로 뽑히는 것은 아직 확인하지 못했다.** 이 컨테이너에서
`app.careermatri.com` 을 열 수 없다. 재배포 뒤에 한 번 눌러 보면
`[v3-pdf]` 줄이 있는지 없는지로 끝난다.

## 아직 아닌 것

- 운영 배포본을 밖에서 브라우저로 열지 못했다(네트워크 정책이
  `app.careermatri.com:443` 을 막는다). 운영에서 PDF 가 실제로 뽑히는
  것은 **재배포 뒤에 사람이 한 번 눌러야** 확정된다
- Railway Shell 권한이 없어 운영 로그를 읽지 못했다. PDF 의 원인은
  코드 경로와 쿠키 이름 규칙에서 **재현해 확인한 것**이고 운영 로그
  한 줄로 확인한 것이 아니다
- iPhone Safari 실기기 확인이 남아 있다(이 컨테이너는 WebKit 을
  내려받지 못해 크로뮴에 iOS 화면을 씌운다)
