# CareerMatri Workspace 재설계 보고

2026-10-09. 앞 회차의 전수 감사(`69_platform_audit.md`)와 목표 정보구조
(`70_workspace_ia.md`)를 코드로 옮긴 결과다. 이 문서는 무엇을 했고 무엇이
남았는지를 A부터 V까지 적고, 마지막에 사업주가 직접 눌러 볼 길을 적는다.

**검사의 판단 원리는 한 줄도 바꾸지 않았다.** 문항 은행 · 채점 · 소유
판정 · 묶음 판정 · Evidence 판정 · 등급 논리 · 결과 모델의 핵심 판단이
그대로이고, 작업공간은 그 위에 올라가는 사용자 경험 층이다. 그것을 말로
적어 두지 않고 검사로 막았다(`npm run v3:workspace` 가 작업공간 파일에서
채점 모듈을 들여오는 줄을 센다).

---

## A. 한 줄 진단

전에는 개인 화면이 둘이었고 로그인이 틀린 쪽으로 떨어졌다. `/my` 는 옛
표(`attempts` · `report_snapshots` · `evidence_profiles`)를 읽고 `/me` 는
V3 표를 읽는데, `homePathFor('student')` 가 앞쪽을 가리켰다. 그래서
기계공학 V3 를 끝낸 사람이 로그인하면 `아직 응시한 검사가 없습니다` 를
읽었고, 그 화면의 주된 단추는 옛 검사로 보냈다. **자료는 멀쩡히 있었고
읽는 자리가 틀렸다.**

## B. 고친 P0 셋

| 번호 | 무엇이었나 | 고친 자리 |
|---|---|---|
| P0-1 | 로그인이 옛 작업공간으로 떨어진다 | `roles.ts` · `rbac.ts` · 공개 쪽 열다섯 자리의 `/my` 링크 |
| P0-2 | 그 화면의 주된 단추가 옛 검사로 간다 | `/my` 와 `/my/assessments` 의 `/test` · `/free` 단추를 걷었다 |
| P0-3 | `/my/results` 가 V3 결과를 못 읽는다 | 쪽을 옛 기록으로 표기하고 `/me/results` 를 새로 세웠다 |

세 가지 모두 **표를 하나도 바꾸지 않고** 고쳤다. 읽는 자리를 옮기는
일이었기 때문이고, 그래서 이 회차는 자료 이전이 없다.

## C. 두 영역으로 가른 것

작업공간(`/me/*`)은 쌓이는 자리다. 검사와 결과와 경험과 지금 상태와 할
일이 여기 모인다. 계정(`/my/*`)은 한 번씩 들르는 자리다. 로그인과 주문과
파기, 그리고 옛 검사 기록이다. **두 벌을 한 띠에 섞으면** 쌓이는 자리와
들르는 자리가 같은 무게로 읽힌다.

`/my` 의 맨 위가 내 CareerMatri 로 돌아가는 길이고, 작업공간 띠의 맨
아래가 계정으로 가는 길이다. 들어온 사람이 나가는 길을 못 찾으면 로고를
누르는데, 로고는 면을 넘지 않는다.

## D. App Shell

넓은 화면은 왼쪽에 늘 보이는 띠고 손전화는 아래 띠와 서랍이다. 띠의 줄을
넷으로 묶었다.

| 묶음 | 줄 |
|---|---|
| 지금 | 홈 · 검사 |
| 내 기록 | 결과 기록 · 내 경험 · 지금 상태 · 다음 할 일 |
| 넓게 보기 | 산업과 직무 · 지역과 기관 · 지원한 곳 |
| 준비 중 | Track |

손전화는 아래 띠 넷(홈 · 검사 · 경험 · 상태)에 다섯째가 서랍이다.
`details` 하나로 열어서 자바스크립트가 꺼져 있어도 열리고, 쪽을 옮기면
저절로 닫힌다. **사이드바를 좁혀 넣지 않았다**: 열한 줄을 56px 띠에 밀어
넣으면 글자가 접혀 어디를 누르는지 알 수 없다.

쪽을 다섯 곳 옮겨 보며 띠가 열한 줄로 그대로 서고 지금 자리가 한 곳만
켜지는 것을 검사가 센다.

## E. Workspace Home

상태 여섯으로 화면을 가른다: 검사 전 · 진행 중 · BASIC 끝 · STANDARD
끝 · PRO 끝 · 경험 반영함. 전에는 검사 전인 사람과 경험까지 반영한 사람이
같은 카드 아홉 칸을 받았다. **빈 카드를 줄줄이 세우면 읽는 사람은 자기
결과가 덜 만들어진 줄 안다.**

어느 상태에서도 주된 단추가 하나다. 그리고 **숫자 dashboard 를 만들지
않았다**: `82점` 과 `완료율 67%` 는 이 제품이 계산하지 않는 값이고, 세는
수는 문장 안에서 보조로만 선다.

## F. 결과 기록

굳은 기록과 지금 값을 **생김새로 가른다.** 검사 당시 결과는 흰 카드에
왼쪽 날짜 띠와 `고정됨` 표시, 지금 상태는 꺼진 바탕에 점선과 `이 줄은
경험을 더하면 바뀝니다` 다. 전에는 홈의 카드 한 줄에 둘이 나란히 있어서
날짜만 다른 같은 값으로 읽혔다.

당시 판본은 접어 두고, 열쇠 이름을 사람의 말로 적는다(`core_version` →
전공 Core). **응시자에게 필요한 것은 결과가 고정돼 있다는 사실이다.**

결과 PDF 는 평범한 `a` 로 걸었다. `Link` 로 두면 Next 가 화면에 들어온
링크를 미리 불러오면서 머리 없는 브라우저를 띄워 종이를 한 벌씩 만든다.

## G. 지금 상태

비어 있는 자리마다 셋을 함께 적는다: 무엇이 비었는가 · 왜 그 자리가
필요한가 · 무엇을 하면 채울 수 있는가. 목록만 나열하면 읽은 사람이
무엇부터 할지 모른다. 그리고 축 코드와 소유 코드는 한 글자도 나가지
않는다.

머리에 적히는 기준 날짜가 둘로 갈린다. 경험을 반영한 적이 있으면 반영한
날이고, 없으면 검사한 날이다. 같은 자리에 `아직 새 경험을 반영한 적이
없어 검사 당시 결과와 같습니다` 가 선다.

## H. 다음 할 일

급한 차례가 아니라 **할 수 있는 때**로 묶는다. `30일 안` 은 읽는 사람에게
마감으로 읽히는데 이 값은 마감이 아니다. 지금 앉아서 할 수 있는 것과 맡는
일이 생겨야 하는 것은 준비가 다르다.

문장을 여기서 짓지 않는다. 결과지가 쓰는 함수(`actionKo`)를 그대로 불러
옮기므로, 상담 자리에서 다른 종이를 들고 앉지 않는다.

## I. 경험과 반영

적는 칸 열두 개 앞에 **왜 적는지**를 적었다. 지원서에서 설명할 근거가 한
줄 늘어난다는 것, 비어 있던 판단축이 채워지면 다음 할 일이 달라진다는
것, 검사 당시 결과는 그대로 남는다는 것 셋이다.

**점수가 오른다고 쓰지 않는다.** 경험으로 올라갈 수 있는 가장 높은 자리는
`직접 수행` 까지이고 `직접 결정` 은 검사에서만 받는다. 적합도나 직무 추천
순위가 오른다는 말은 어느 화면에도 없다.

`재분석` 이라는 말을 손님 화면에서 걷었다. 그 말은 우리가 무엇을 다시
계산하는가를 가리키는데, 누르는 사람이 하는 일은 적어 둔 경험을 지금
상태에 반영하는 것이다. 지금은 `새 경험 반영하기` 다.

## J. 계정 영역

`/my` 가 하는 일이 셋이다: 로그인한 계정을 보여 주는 것 · 주문과 결제로
가는 길 · 옛 검사 기록을 찾을 수 있게 두는 것. 옛 쪽 셋
(`/my/assessments` · `/my/results` · `/my/evidence`)은 지우지 않았다.
전에 응시한 분의 기록이 그 표에 있고 주소가 적힌 메일도 나가 있다. 대신
맨 위에 한 줄을 세워 지금 검사의 결과와 경험이 어디 있는지 적는다.

**빈 목록을 조용히 두면 읽는 사람은 자기 결과가 사라진 줄 안다.**

## K. 검사 진입

`/cores` 에 `검사는 시작점입니다` 네 줄을 세웠다: 검사에서 받는 것 · 그
뒤에 쌓는 것 · 등급 차이 · 중간에 멈춰도 되는 것. 전에는 전공 카드만
세워서 읽는 사람이 CareerMatri 를 검사 한 벌로 읽고 결과 PDF 를 받는
데까지로 생각했다.

**등급을 문항 수로 가르지 않는다.** 가르는 것은 판단의 종류다: 어디부터
볼지 · 영역끼리 비교하기 · 경험을 직무 언어로 옮기기.

`/v3/start` 는 전부터 목적과 문항 수와 시간과 등급과 저장과 이어하기를
적고 있어서 그대로 두었다.

## L. 용어

| 안쪽 이름 | 손님 화면 |
|---|---|
| Evidence | 설명할 수 있는 경험 |
| Gap | 아직 비어 있는 자리 |
| Action | 다음 할 일 |
| recompute | 새 경험 반영하기 |
| Result history | 결과 기록 |
| Current state | 지금 상태 |
| Industry/Role Pack | 산업과 직무 |
| Region | 지역과 기관 |

`Track` 은 그대로 두었다. 저것은 안쪽 용어가 아니라 파는 것의 이름이다.

`npm run v3:copy` 가 쪽 스물넷에서 이것을 센다. 돌려서 셋을 잡았다:
`견주기`(설계 문서의 말) · `고르신 것만`(높임이 겹친다) ·
`판정에 들어가지 않습니다`(이 검사의 결과를 가리키는 안쪽 용어).

## M. 판단이 한 자리에서만

작업공간이 읽는 자리는 `currentState(userId)` 하나다. 굳은 결과
(`v3_snapshots.result_model`)를 먼저 꺼내고, `recomputed_at` 이 있을 때만
`career_profiles` 의 세 칸을 그 위에 얹는다. 얹는 값은 `applyRecompute`
가 만든 것이라 **여기서 새로 판정하지 않는다.**

비어 있는 자리의 뜻과 차례는 늘 굳은 결과에서 온다.
`career_profiles.gaps` 는 `{영역 · 축 · 종류}` 만 들고 있어서 왜 필요한지와
무엇을 하면 되는지를 말할 수 없다.

같은 판단을 UI 를 위해 새로 만드는 길은 검사가 막는다. 작업공간 파일에
채점 모듈을 들여오는 줄이 있으면 `v3:workspace` 가 걸린다.

## N. 가짜 자료가 없다

지어낸 숫자도 가짜 공고도 가짜 기관 수도 없다. 자료가 없으면 빈 상태이고,
빈 상태는 넷을 적는다: 지금 없는 것 · 그 까닭 · 대신 할 수 있는 것 ·
들어오면 무엇이 달라지는가.

기관 수와 공고 수는 그대로 0줄이다. 공고는 저작권과 이용약관 검토 전이고,
기관 수를 짐작으로 채우면 그 수가 근거처럼 읽힌다.

## O. 주소의 처분

**404 로 버린 주소가 없다.** `/me/gap` 은 `/me/state#gaps` 로 넘기고,
`/me/jobs` 는 쪽을 남긴 채 Track 안의 자리로 돌렸다. `/my/*` 다섯과 옛
결과지와 옛 PDF 와 옛 응시 주소는 전부 그대로 열린다.

## P. 상태 화면

| 상태 | 어디 |
|---|---|
| 검사 전 | `/me` · `/me/results` · `/me/state` · `/me/next` |
| 진행 중 | `/me` · `/cores` |
| 결과 하나 | 여섯 카드 |
| 경험 0개 | `/me` 최근 경험 카드 · `/me/experience` |
| 반영할 거리가 쌓임 | `/me` 와 `/me/experience` 의 안내 |
| 반영한 뒤 | `/me` 의 무엇이 달라졌는지 · `/me/results` 의 지금 상태 |
| 할 일 0개 | `/me/next` |
| 비어 있는 자리 0곳 | `/me/state` |
| 고른 산업과 직무 없음 | `/me` 의 보고 있는 자리 카드가 서지 않는다 |
| 자료가 0줄인 자리 | `/me/jobs` · `/me/track` · `/me/region` |

## Q. 접근성

누르는 자리를 40px 로 올렸다. 목록 안 단추가 32px 이고 접는 자리가 24px
이었다. 초점 표시는 띠의 줄과 접는 자리와 고르는 칩에 있고, 320px 에서 쪽
열여섯 곳이 가로로 밀리지 않는다.

찍는 검사가 그것을 센다. 세는 그림을 한 번 고쳤다: `.cm-chip` 을 넣어
두었더니 읽는 이름표 서른 자리가 미달로 걸렸다. **거짓 경보를 내는 검사는
그 다음부터 아무도 안 본다.**

## R. 동결

`CAREERMATRI_WORKSPACE_UI_V1` 과 `careermatri-workspace-copy.1` 이다.
판본이 넷으로 따로 간다: 검사 화면 · 결과지 화면 · 판단 규칙 · 작업공간.
한 판본으로 묶으면 홈의 카드 하나를 옮긴 날 이미 응시한 사람의 결과를
다시 계산해야 하는지 묻게 된다.

`npm run v3:workspace` 가 파일 스물아홉 벌의 지문을 대조하고 두 가지를 더
센다. 화면이 채점을 직접 부르지 않는 것과, **쓰는 class 이름이 CSS 에
있는 것**이다. 뒤엣것은 이 저장소에서 같은 탈이 여섯 번 났기 때문에
두었다(`.btn` · `--sf-r` · `.lg` · `empty` · `industries` · `OC*`).

응시 스냅샷의 판본이 열하나에서 열둘이 됐다. 작업공간 판본은 **판정에
쓰이지 않는다**: 결과를 받은 뒤 어느 작업공간으로 들어갔는지를 되짚는
자리다.

## S. 계측 여덟 열쇠

`analytics_events` 를 그대로 쓴다. 표를 하나 더 만들면 같은 질문에 답하는
자리가 둘이 된다. 퍼널 걸음과는 섞지 않는다: 저쪽이 묻는 것은 방문이
결제가 되는가이고 여기가 묻는 것은 결과를 받은 사람이 다시 들어오는가다.

작업공간 열기 · 검사 이어하기 · 결과 열기 · 경험 추가 시작 · 경험 저장 ·
지금 상태에 반영 · 할 일 열기 · 할 일 저장. 여덟이고 더 둘 수 없다.

**이어하기만 폼이다.** `Link` 로 두면 Next 가 미리 불러오면서 누르지 않은
사람까지 세어진다. 그리고 침습적인 수집이 없다: 화면 녹화도 키 입력도
마우스 자취도 없고 어느 절을 얼마나 읽었는지도 재지 않는다.

읽는 자리도 함께 세웠다(`/admin/funnel`). 전에 이 표가 넉 달 동안 빈
표였던 까닭이 적는 코드가 없는 것이었고, 이번에는 읽는 자리가 없는 것이
같은 모양의 탈이 된다.

## T. 캡처

자리 스물한 곳 × 폭 셋(1440 · 390 · 320) 예순세 장이
`docs/metri/shots/workspace` 에 있다. 손전화 서랍 한 장이 더 있다.

**두 사람으로 찍었다.** 한 사람에게는 검사 전과 검사 뒤가 같이 있을 수
없고, **빈 상태가 상태 가운데 하나**라 안 찍으면 그 다섯 쪽이 어떻게
서는지 아무도 모른다(`w18`~`w22`). 계정 영역도 학생 계정으로만 열린다.

**그림만 남기지 않는다.** 자리마다 다섯을 같이 센다: 열리는가 · 내부
코드가 보이는가 · 가로 스크롤이 생기는가 · 브라우저 오류가 나는가 ·
누르는 자리가 40px 이 되는가. 처음 돌렸을 때 걸린 셋이 전부 진짜였고 Q·U
절에 적었다.

## U. 캡처가 잡은 세 가지

**하나. 경험을 적어 넣으면 저장이 거절됐다.** `input type="month"` 가
`2025-03` 을 보내는데 `started_on` 이 `DATE` 칸이라 PostgreSQL 이
`invalid input syntax for type date` 로 끊었다. 저장 단추를 누른 사람이
오류 화면을 본다. 달만 받는 것은 일부러이므로 꼴을 맞추는 자리를 쓰는 자리
하나에 두었다.

**둘. 끝낸 일 목록이 React `#418` 로 멈췄다.** `p` 안에 `form` 을 두면
브라우저가 그것을 밖으로 끌어내고, 서버가 보낸 것과 브라우저가 세운 것이
달라진다. 화면은 멀쩡해 보이고 눌리는 것만 안 된다.

**셋. 지금 상태와 지역 화면에 `OC1` 이 그대로 섰다.** 이름이 겹친 자리의
뒤처리다. `orgLabel()` 이 못 찾으면 코드를 그대로 돌려주고 있었다. 고쳐
쓰지 않고 비웠다: 옛 줄의 `OC1` 을 기관 유형으로 바꿔 적으면 그 사람이
고르지 않은 것을 고른 것으로 만든다.

## V. 회귀

| 검사 | 결과 |
|---|---|
| `npm run v3:all` (서른세 묶음) | 전부 통과 |
| `npm run v3:freeze` | 검사 화면 판본 그대로 · 지문만 다시 적었다 |
| `npm run v3:result:freeze` | 결과지 판본 그대로 · 지문만 다시 적었다 |
| `npm run v3:workspace` | 작업공간 동결 OK · 쓰는 이름 쉰일곱 개가 전부 CSS 에 있다 |
| `npm run v3:result:copy` | 통과 |
| `npm run v3:result:pdf` | BASIC 5쪽 · STANDARD 9쪽 · PRO 12쪽 · 빈 쪽 없음 |
| `npm run db:migration` | 칸 1002개 · 제약 484개 · 인덱스 255개 · 코드가 부르는 칸 523개 |
| `npm run v3:isolation` | 열한 가지 통과 (A 는 열리고 B 는 막힌다) |
| `npm run v3:owner` | 열여덟 가지 통과 |
| `npm run v3:smoke` | 스물네 자리 전부 200 |
| `npm run copy:audit` · `npm run v3:copy` | 통과 |

`v3:owner` 의 두 줄은 이 회차에 맞춰 고쳤다. 이어하기 단추가 폼이 되어
`href` 로 찾을 수 없게 됐고(글자로 찾아 실제로 누른다), 굳은 값과 지금
값을 가르는 자리가 홈에서 결과 기록으로 옮겨 갔다. 뒤엣것은 글자 둘만
보지 않고 생김새가 실제로 갈렸는지도 센다.

## 3. 무엇이 보여야 정상인지

1. **로그인 뒤 떨어지는 자리가 작업공간이다.** 왼쪽에 띠가 있고 `님의
   CareerMatri` 가 보인다
2. 검사를 끝낸 적이 있으면 카드 여섯이 선다. 끝낸 적이 없으면 받는 것
   셋만 서고 주된 단추가 `기계공학 검사 시작` 이다
3. `결과 기록` 에서 **검사 당시 결과는 흰 카드에 날짜 띠와 `고정됨`**,
   지금 상태는 점선 테두리에 `경험을 더하면 바뀝니다` 다
4. `지금 상태` 의 비어 있는 자리마다 `왜 필요한가` 와 `무엇을 하면` 이
   함께 있다
5. `다음 할 일` 이 세 칸으로 나뉘고 칸마다 언제 할 수 있는지가 적혀 있다
6. 경험을 저장하면 목록에 한 줄이 서고 `반영할 거리가 N건` 이 뜬다
7. 반영한 뒤 `지금 상태` 의 머리에 반영한 날이 적히고, **검사 당시 결과는
   글자 하나도 달라지지 않는다**
8. 손전화에서 아래 띠가 넷이고 다섯째 `메뉴` 를 누르면 서랍이 올라온다

## 4. 무엇이 이상하면 FAIL 인지

1. 로그인 뒤 `아직 응시한 검사가 없습니다` 가 보이면 FAIL. 그 문장은 옛
   화면의 것이고, 보인다면 `db:upgrade` 가 안 돌았거나 배포가 옛 판본이다
2. 어느 화면이든 `TD03` · `J5` · `OC1` · `Z1_EVIDENCE_ESTABLISHED` 같은
   코드가 보이면 FAIL
3. 검사 당시 결과와 지금 상태가 **같은 생김새**로 서면 FAIL. 날짜만 다른
   같은 값으로 읽힌다
4. 경험을 저장했는데 `점수가 올랐습니다` 나 `적합도가 올랐습니다` 가
   보이면 FAIL. 그 말은 이 제품이 하지 않는 약속이다
5. 경험을 반영한 뒤 **검사 당시 결과의 글자가 바뀌면 FAIL**
6. 지어낸 숫자가 보이면 FAIL. 기관 수와 공고 수는 0이어야 하고, 자리는
   `아직 모으지 않았습니다` 로 서야 한다
7. 손전화에서 쪽이 가로로 밀리면 FAIL
8. 단추를 눌렀는데 아무 일도 안 나면 FAIL. 특히 `끝냈습니다` 와
   `되돌리기` 를 눌러 보십시오
9. 어느 주소든 404 가 뜨면 FAIL. 옛 주소도 전부 열리거나 넘어가야 한다
