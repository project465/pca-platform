# 결과지(책) 글쓰기 규칙

학생 한 사람이 혼자 펴 보는 책이다. 상담 담당자가 옆에서 풀어 주지 않아도 읽혀야 한다.
모든 Core · 모든 기관의 책이 같은 틀(`src/lib/me-v3/report-long/*`)을 쓰므로, 여기 규칙은
틀과 공용 사전에서 지키고 `npm run report:long` 의 검사가 매번 센다.

## 1. 누구에게 하는 말인가

- 읽는 사람은 **학생 본인**이다. "이 학생", "학생 말로", "상담 40분", "상담 담당자와 함께"처럼
  제3자에게 하는 말을 쓰지 않는다. 상담 진행표 · 상담 기록지 같은 쪽을 책에 넣지 않는다.
- 부르는 말은 "○○ 님"과 "나"(내 결과, 내 경험)다.

## 2. 안쪽 이름을 쓰지 않는다

설계 문서에서 쓰는 이름(묶음 · 판단 여덟 가지 · 깊게 묻지 않음 · 근거 갖춤 · 축 · 칸 · Core · 갈래 ·
번역 · 소유 · 확인됨)을 학생에게 보이는 글에 쓰지 않는다. 학생에게 보이는 이름은 아래 하나뿐이다.

| 안쪽 값 | 책에 쓰는 이름 | 한 줄 뜻 |
|---|---|---|
| Z1 | 강점 영역 | 직접 정한 일과 남긴 결과물이 둘 다 있는 영역 |
| Z2 | 키워 가는 영역 | 해 본 일은 있는데 결과물이나 비교한 기록이 아직 적은 영역 |
| Z3 | 해 봤지만 관심이 낮은 영역 | 해 본 일은 있는데 지금은 관심이 낮다고 답한 영역 |
| Z4 | 관심은 높고 경험이 적은 영역 | 관심은 높은데 아직 해 본 일이 적은 영역 |
| NOT_EXPLORED | 관심·경험만 본 영역 | 관심과 해 본 횟수까지만 물어본 영역 |
| 단계 0 | 해 본 적 없음 | |
| 단계 1 | 시킨 대로 해 봄 | 다른 사람이 정한 조건 안에서 해 봤음 |
| 단계 2 | 직접 해 봄 | 스스로 맡아 해 봤음 |
| 단계 3 | 기준까지 직접 정함 | 기준을 직접 정했고 그 근거도 골랐음 |

이름은 `derive.ts` 의 `ZONE_WORD` · `STEP_WORD` 와 `charts.ts` 의 `LEVEL_KO` 한 곳에서만 정한다.
쪽마다 다시 적지 않는다.

## 3. 문장 끝

- 같은 끝(…니다.)이 한 문단에서 **세 번 이어지지 않게** 쓴다. 두 문장은 연결어미(…고, …는데,
  …라서, …면)로 잇고, 할 일은 "…해 보세요"로, 목록은 이름씨로 끝낸다.
- 한 문단은 두세 문장까지. 그보다 길면 목록이나 표로 나눈다.
- 문단을 잠언처럼 닫지 않는다("…이 출발점입니다", "…가 전부입니다", "…하는 이유입니다").
- 금지: 대시(—), "A가 아니라 B" 대구 남발, `견줍니다 · 섭니다 · 세웁니다 · 확정합니다` 같은
  설계 문서 동사, 번역투(…를 가지고 있다 · …에 있어서 · …를 통해), 과장(혁신 · 핵심은).

## 4. 그래프

- 그래프마다 바로 아래(또는 옆)에 **읽는 법**을 붙인다: 가로·세로가 무엇인지, 색 하나하나가
  무엇인지, 숫자·점·막대 길이가 무엇을 센 것인지. `kit.ts` 의 `howto()` 를 쓴다.
- 장 첫 쪽의 장식 그림에도 숫자나 색 구분이 있으면 같은 읽는 법을 단다. 뜻 없는 장식은 쓰지 않는다.
- 점수 · 백분율 · 순위 · 합격 가능성은 그리지 않는다(재지 않는 값이다).

## 5. 내용

- 한 쪽은 "무엇이 나왔나 → 왜 그렇게 나왔나(내 응답·고른 항목) → 그래서 무엇을 하면 되나" 차례다.
- 영역 이름이나 판단 이름을 늘어놓기만 하는 문장을 쓰지 않는다. 내 응답에서 나온 장면을 하나 붙인다.
- 전공 사전에서 온 일반 안내와 내 응답에서 나온 말을 섞지 않는다(머리말에 어느 쪽인지 적는다).
