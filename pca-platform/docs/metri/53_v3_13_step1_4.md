# 0~4단계 결과 · 데이터 작업

2026-10-07. 0단계(판본 잠금)와 1~4단계(데이터 작업)를 끝냈다. **V3 채점
코드와 결과지 렌더러와 홈페이지 구현은 시작하지 않았다.**

이 회차의 기준은 문항 수가 아니고 **영역마다 문제와 판단과 산출물과 검증을
가를 수 있는가**다. 그래서 세는 자리를 둘 두었다: `v3:domains` 열두 가지와
`v3:items` 열한 가지다.

## A. 최종 taxonomy

```
기술영역 TD01~TD12  ×  역할기능 RF1~RF7  ×  조직환경 OC1~OC7
```

| 축 | 개수 | 데이터에 들어간 것 |
|---|---|---|
| 기술영역 TD | 12 | 코드 · 이름 · **책임지는 판단** · 하위 갈래 · 필수 축 둘 |
| 역할기능 RF | 7 | 코드 · 이름 · 한 줄 · 산출물의 성격 · 성공의 모양 |
| 조직환경 OC | 7 | 코드 · 이름 · 무엇이 성과인가 · 같은 영역에서 달라지는 점 |
| 공고 직무명 별칭 | 24 | 조합(TD·RF·OC)과 **가르는 한 마디** |
| 직무 경계 쌍 | 10 | 공통점 · 양쪽의 차이 · **구분 질문 둘** |

**순위를 만드는 축이 하나도 없다.** 영역 이름을 `책임지는 판단` 으로 적은
것이 이 파일의 요점이다. 무엇을 다루는지보다 무엇을 정하는지가 영역을
가른다.

별칭 24줄이 전부 조합으로 풀리고(`v3:domains` 2번), 경계 열 쌍마다 구분
질문이 둘 다 있다(3번). 구분 질문은 문항의 씨앗이라 비어 있으면 4단계에서
문항을 쓸 수 없다.

## B. 영역별 workflow

영역마다 **여덟 걸음**이다. 걸음 이름을 고정해 두었으므로 영역을 늘려도
같은 모양으로 읽힌다.

```
문제가 들어오는 모양 → 받는 입력 → 먼저 정하는 것 → 쓰는 방법
→ 쓰는 도구 → 내놓는 산출물 → 무엇과 견주는가 → 틀렸을 때
```

| 센 것 | 수 |
|---|---|
| 흐름 걸음 | 96 (영역 12 × 8) |
| 쓰는 도구 | 58 |
| 산출물 종류 | 61 |
| 검증 대상 | 66 |
| 판단 축 칸 (수행·소유 조건) | 96 |
| 조직환경별 성과 이름 | 84 (영역 12 × 조직 7) |

**조직은 유형까지만 적는다.** 기관 이름이 들어가지 않았는지를 검사가
본다(`v3:domains` 8번). 같은 열전달 지식이 완성품 기업에서는 제품 냉각
성능이고 출연연에서는 과제 산출물인데, 거기에 특정 기관의 평가 지표를
적으면 그 줄은 지어낸 값이 된다.

## C. 증거 199개 재배치 결과

**고아가 0 이다.** 199개 전부 자리를 받았다(`v3:domains` 9번).

| 버킷 | 유지 | 병합 | 분리 | 승격 | 이동 | 삭제 | 합 |
|---|---|---|---|---|---|---|---|
| TD 기술영역 | 94 | 15 | 9 | 12 | 9 | 0 | **139** |
| COMMON 공통 판단 | 0 | 6 | 0 | 5 | 16 | 0 | **27** |
| RF 역할기능 | 0 | 0 | 0 | 0 | 14 | 0 | **14** |
| OC 조직환경 | 0 | 0 | 0 | 0 | 4 | 0 | **4** |
| DROP 흡수 | 0 | 0 | 0 | 0 | 0 | 15 | **15** |
| 합 | 94 | 21 | 9 | 17 | 43 | 15 | **199** |

세 가지가 이 표의 요점이다.

**첫째, 영역에 붙지 않는 것이 60개다.** 연구 과정(`RND_*`)과 컨설팅
(`CS_*`)과 연구자 역할(`RS_*`)은 기술영역이 아니고 **공통 판단**이거나
**역할**이거나 **조직환경**이다. 옛 표가 그것을 직무군 자리에 두어서 축이
섞였다. 공통 27개가 번역 layer 의 입력이 된다.

**둘째, 도구 이름만 재던 열다섯을 흡수했다.** `MD_TOOL` · `CAE_TOOL` ·
`MF_CAM` · `AU_ROBOT_BRAND` · `DG_TOOL` 같은 항목이다. 지우는 것이 아니고
**J4 방법·도구의 L1 정의로 들어간다**: 도구 이름만 적은 사람이 L1 이고
그 도구로 무엇을 정했는지 적은 사람이 L2 다.

**셋째, 해석 아홉 항목을 세 영역으로 분리했다.** `CAE_*` 가 구조(TD02)와
열유체(TD03)와 진동(TD04)에 같은 축 구조로 들어간다. 사람도 도구도 검증
방법도 갈리는데 한 칸에 있었다.

재배치만으로는 **빈 칸이 스물한 자리** 남았고 그중 하나가 필수 축이었다
(TD06 의 비교·검증). 그래서 새 체크리스트 항목을 썼다.

| 체크리스트 | 199에서 온 것 | 새로 쓴 것 | 합 |
|---|---|---|---|
| 영역 × 축 | 180 | 65 | **245** |
| 공통 판단 | 27 | 5 | **32** |

새로 쓴 항목은 **파일을 따로 두었다.** 199개에서 온 것과 섞으면 다음
사람이 어디까지가 기존 자산인지 모른다.

`PR_INDUSTRY` · `AU_ROBOT_BRAND` · `TF_RENEWABLE` · `PM_PORTFOLIO` ·

### F-2. 병합한 스물하나

생산기술(`MF_*`)과 공정기술(`PR_*`)을 TD08 한 영역으로 합쳤다. 회사마다
경계가 반대라서 문항으로 가를 수 없고, 가르는 것이 응시자에게 주는 정보도
없다. 신제품 이관과 양산 유지의 차이는 역할축(RF4)에서 본다.

연구자 역할(`RS_*`)의 여섯은 연구 과정(`RND_*`)과 같은 것을 묻고 있어서
공통 판단으로 합쳤다.
