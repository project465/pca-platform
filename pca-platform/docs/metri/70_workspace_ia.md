# CareerMatri Workspace 정보구조

> 지시의 `68_workspace_ia.md` 자리다. 68 은 앞 회차가 쓰고 있어 번호만 70 으로
> 밀었다. 짝은 `69_platform_audit.md`.

**검사는 기능이고, 결과지는 한 시점의 보고서이며, Workspace 가 본체다.**

---

## 1. 두 영역

| 영역 | 주소 | 목적 | 껍데기 |
|---|---|---|---|
| 로그인 전 | `/start` `/pricing` `/product` `/sample` `/legal/*` `/login` `/signup` | 무엇을 하는 제품인지 알고 검사를 시작한다 | 공개 (`sf-` + 꼬리말) |
| **Workspace** | `/me/*` `/cores` `/v3/*` | 내 커리어 상태를 계속 관리한다 | `cm-` |
| 계정 | `/my/*` `/support` | 비밀번호, 주문, 이용권, 파기, 옛 검사 기록 | `sf-` |

**로그인 전 사용자는 Workspace 메뉴를 보지 않는다.** `/me/*` 전부가
`requireUser()` 뒤에 있고, 비로그인은 `/login` 으로 간다.

**로그인한 개인은 `/me` 로 떨어진다.** `homePathFor('student')` 를 `/my` 에서
`/me` 로 옮긴다. 기관 담당자는 `/org`, 운영자는 `/admin` 그대로다.

## 2. Workspace sidebar

평평한 목록을 묶음 넷으로 나눈다. 묶음 이름이 §54 의 section context 다.

```
CareerMatri                     ← 누르면 /me
기계공학                         ← 지금 어느 전공인지 (§57)

지금
  홈                  /me
  검사                /cores

내 기록
  결과 기록            /me/results
  내 경험              /me/experience
  지금 상태            /me/state
  다음 할 일            /me/next

넓게 보기
  산업과 직무           /me/explore
  지역과 기관           /me/region
  지원한 곳            /me/apply

준비 중
  Track               /me/track

────────
계정                   /my
```

**메뉴 이름을 왜 이렇게 골랐는가.**

| 내부 이름 | 화면 이름 | 까닭 |
|---|---|---|
| Result history | **결과 기록** | `이력` 은 서류 느낌이고 `기록` 은 쌓이는 느낌이다 |
| Experience | **내 경험** | `경험` 만 두면 남의 경험 모음처럼 읽힌다 |
| Current state | **지금 상태** | `현재 상태` 보다 짧고 말로 쓴다 |
| Evidence | **설명할 수 있는 경험** | 지원서와 면접에서 쓸 수 있다는 뜻이 그대로 들어간다 |
| Gap | **아직 비어 있는 자리** | `부족한 것` 은 사람을 깎는 말이다 |
| Action | **다음 할 일** | 그대로가 가장 짧다 |
| Recompute | **새 경험 반영하기** | §11. `재분석` 은 기술 용어다 |
| Industry/Role Pack | **산업과 직무** | 팩이라는 말을 쓰지 않는다 |
| Region layer | **지역과 기관** | 추천이 아니라 고르는 자리다 |

**지금 상태와 다음 할 일을 나눈 까닭.** 전에는 `/me/gap` 한 쪽에 둘이 있었다.
읽는 사람이 묻는 것이 서로 다르다: 상태는 `나는 지금 어디인가`, 할 일은
`무엇부터 하면 되는가`. 한 쪽에 두면 긴 목록 둘이 세로로 쌓인다.

**Track 을 따로 묶은 까닭.** 메뉴에 두면서도 지금 되는 것과 섞이지 않게
한다. 묶음 이름이 `준비 중` 이라 들어가기 전에 안다. 뱃지를 쓰지 않는다(§21).

**손전화.** 사이드바를 좁히지 않는다. 아래 띠에 넷(홈 · 검사 · 지금 상태 ·
내 경험)을 세우고 다섯째 칸이 `메뉴` 서랍이다. 서랍은 `<details>` 하나라
자바스크립트가 꺼져 있어도 열린다.

## 4. Workspace Data Source Map

**판단 엔진을 새로 만들지 않는다.** Workspace 가 보여 주는 값은 전부
이미 있는 자리에서 온다. 같은 뜻을 두 번 계산하는 코드를 두지 않는다.

| 사용자 화면 정보 | Source | Frozen / Current | 변경 주체 |
|---|---|---|---|
| 검사 당시 결과 (아홉 절) | `v3_snapshots.result_model` | **Frozen** | 제출(`submit`)뿐 |
| 결과 기록 목록 | `resultHistory()` → `v3_snapshots` + `career_profiles` | Frozen + Current | 제출 · 반영 |
| 응시 진행 상태 | `v3_attempts.status` · `current_screen` | Current | 응시 화면 |
| 이용 가능한 등급 | `v3Grants()` → `entitlements` | Current | 초대 · 결제 |
| 지금 축 수준 | `career_profiles.axis_levels` | **Current** | `applyRecompute` |
| 지금 영역 묶음 | `career_profiles.zones` | **Current** | `applyRecompute` |
| 지금 비어 있는 자리 | `career_profiles.gaps` 로 걸러 낸 `result_model.gaps` | Current (뜻은 Frozen) | `applyRecompute` |
| 설명할 수 있는 경험 | `result_model.evidence.ready` / `.partial` | Frozen | 제출 |
| 다음 할 일 | `v3_actions` | Current | 결과에서 가져오기 · 직접 적기 · 반영 |
| 내 경험 | `v3_experiences` | Current | 경험 추가 · 지우기 |
| 산업 · 직무 맥락 | `result_model.industry_context` / `.role_context` | Frozen | 제출 |
| 관심 산업 · 직무 | `career_profiles.target_industry` / `.target_role` | Current | 탐색 화면 |
| 지역 · 기관 유형 | `career_profiles.home_region` / `.move_range` / `.target_org` | Current | 지역 화면 |
| 번역 (PRO) | `result_model.translation` | Frozen | 제출 |
| 반영할 거리 | `career_events` 의 `queued`/`failed` 수 | Current | 경험 저장 |

**읽는 함수를 하나로 둔다.** `currentState(userId)` 가 굳은 결과를 먼저
꺼내고, 반영한 적이 있으면 `career_profiles` 의 세 칸을 그 위에 얹는다.
얹는 값은 **`applyRecompute` 가 만든 것**이라 여기서 새로 판단하지 않는다.
영역 이름과 축 이름과 Gap 의 뜻은 늘 굳은 결과에서 온다.

## 5. `/me` Workspace 홈

**5초 안에 셋을 알아야 한다**: 나는 지금 어떤 상태인가 · 지금 가장 중요한
것은 무엇인가 · 다음에 무엇을 해야 하는가.

**숫자 dashboard 를 만들지 않는다**(§55). `82점` 이나 `73%` 나 `완료율`
같은 칸을 두지 않고, 수는 문장 안에서 보조로만 선다.

### 상태 여섯 (§56)

| 상태 | 무엇으로 아는가 | 홈의 주된 단추 |
|---|---|---|
| A. 검사 전 | 응시 0 | **기계공학 검사 시작** |
| B. 진행 중 | `status='in_progress'` | **검사 이어하기** |
| C. BASIC 완료 | 최신 결과 `tier='BASIC'` | **먼저 볼 영역 보기** |
| D. STANDARD 완료 | `tier='STANDARD'` | **지금 상태 보기** |
| E. PRO 완료 | `tier='PRO'` | **산업·직무 언어로 보기** |
| F. 경험 반영 뒤 | `recomputed_at` 이 있다 | **무엇이 달라졌는지 보기** |

### 화면 차례

```
머리   안녕하세요, {이름}님            ← 환영문구는 한 줄까지
      기계공학 · 마지막 분석 2026-10-08

1. 지금 확인된 것        기술영역 둘에서 셋. 점수 없이 상태 문장
2. 지금 가장 먼저 할 것   할 일 하나 + `이 행동 자세히 보기`
3. 현재 채울 부분        비어 있는 자리 하나에서 셋
4. 최근 경험            최근 셋 + `경험 추가하기`
5. 최근 결과            최신 검사 당시 결과 + `검사 당시 결과 보기`
6. 변화                 반영한 적이 있을 때만. 상태 변화만. 그래프 없음
```

상태 A 에서는 1~6 이 서지 않고 **무엇을 받는지 셋**과 시작 단추만 선다.
상태 B 에서는 이어하기 한 칸과 `지금까지 답한 것` 한 줄만 선다.
**빈 카드를 줄줄이 세우지 않는다.**

## 6. 결과 기록 `/me/results`

**검사 당시 결과와 지금 상태를 같은 카드 모양으로 그리지 않는다**(§51).

| | 검사 당시 결과 | 지금 상태 |
|---|---|---|
| 카드 | 흰 바탕 · 왼쪽에 날짜 띠 · 자물쇠 표시 | 연한 바탕 · 테두리 점선 · `바뀔 수 있습니다` |
| 적는 것 | 검사 날짜 · 등급 · 전공 · 당시 주요 영역 · 판본 | 마지막 반영 날짜 · 무엇이 올라갔는지 |
| 단추 | `결과 보기` · `PDF` | `지금 상태 보기` |
| 성격 | 고정된 기록 | 변하는 상태 |

판본은 접어 둔다(`당시 판본 보기`). 응시자에게 필요한 것은 **결과가
고정돼 있다는 사실**이고 판본 코드 자체는 아니다.

## 7. 내 경험 `/me/experience`

**왜 적는지를 맨 위에 적는다.** `새로 한 프로젝트·연구·인턴·업무 경험을
적으면 지금 상태를 다시 볼 수 있습니다.`

받는 것 일곱. 전부 **고르는 칸**이고 적는 칸은 제목과 한 줄뿐이다.

```
어떤 종류        수업 · 과제 · 캡스톤 · 연구 · 인턴 · 업무 · 동아리 · 공모전 · 그 밖
어떤 영역        기술영역 열둘에서 고른다 (고르면 아래 넷이 그 영역 것으로 바뀐다)
어떤 문제        그 영역의 체크리스트
직접 정한 것      그 영역의 체크리스트
남긴 것          그 영역의 산출물 목록
검증한 것         그 영역의 검증 대상 목록
쓰인 자리         팀 · 다음 사람 · 제품 · 논문 · 보고서
```

**검사의 보기 넷과 어긋나지 않는다.** 경험으로 올라갈 수 있는 가장 높은
자리는 `직접 수행` 까지다. `직접 결정` 은 검사에서만 선다. 그 선을
`v3:recompute` 가 매번 센다.

## 8. 지금 상태 `/me/state`

```
1. 기술영역                 열두 영역의 지금 묶음. 경험으로 올라간 축에 표시
2. 설명할 수 있는 경험        지원서와 면접에서 바로 쓸 수 있는 것
3. 더 붙이면 좋은 근거        경험은 있고 설명 재료가 모자란 것
4. 아직 비어 있는 자리        무엇이 · 왜 필요한가 · 무엇을 하면 (셋이 한 묶음)
5. 보고 있는 산업과 직무      고른 산업·직무에서 그 근거가 어떻게 읽히는가
6. 관심 지역과 기관 유형      고른 것만. 기관 수를 적지 않는다
```

**Gap 하나는 늘 셋이 붙는다**(§14). 목록만 나열하면 읽은 사람이 무엇부터
할지 모른다. 그리고 **축 코드와 소유 코드를 내보내지 않는다**: `J3` 도
`OWNED` 도 화면에 없다.

## 9. 다음 할 일 `/me/next`

세 층을 그대로 둔다(§15).

```
지금            오늘 앉아서 시작할 수 있습니다
다음 과제에서     맡는 일이 생겨야 합니다
나중에          앞의 둘이 끝난 뒤입니다
```

할 일이 많으면 홈에는 **가장 먼저 할 하나**만 세운다.
`결과에서 가져오기` 로 결과지의 할 일을 옮겨 오고, 직접 적을 수도 있다.

## 10. Track `/me/track`

구조적 자리만 둔다. 기능을 구현하지 않는다(§32).

지금 받는 것은 **켜지면 알려 달라는 표시** 하나뿐이고, 기능마다 왜 아직
아닌지가 적힌다(`공고 자료 검토 전` · `자동 반영 전` · `메일 연결 전`).
`/me/jobs`(공고)를 이 쪽 아래로 옮겨 사이드바에서 뺀다.

## 11. 계정 `/my`

Workspace 와 섞지 않는다(§30).

```
/my              계정 홈. 맨 위에 `내 CareerMatri 로 돌아가기`
├ 로그인과 비밀번호
├ 주문과 이용권
├ 옛 검사 기록      ME_V1 · V2 를 응시한 사람만 줄이 있다
└ 파기
```

**옛 검사 기록을 지우지 않는다.** `/my/results` · `/my/assessments` ·
`/my/evidence` 가 그대로 열리고, 제목에 **옛 검사**임을 적는다. V3 결과가
있는 사람에게는 맨 위에 `지금 검사의 결과는 결과 기록에 있습니다` 한 줄과
`/me/results` 로 가는 길을 둔다.

## 13. 결과지를 Workspace 안에서 열 때

결과지의 기존 레이아웃(`.rs`)은 보존한다. 다만 **머리에 돌아가는 길**을
둔다: `← 내 CareerMatri`. 종이는 독립 문서라 그 줄을 찍지 않는다.

app shell 을 결과지에 씌우지 않는 까닭은 둘이다. 결과지는 **읽는 문서**라
사이드바가 글 폭을 깎고, 종이와 웹이 같은 쪽을 읽어야 해서 껍데기가
갈리면 인쇄 규칙이 두 벌이 된다.

## 14. 상태 화면 (§60)

정상 화면만 그리지 않는다.

| 상태 | 무엇을 적는가 |
|---|---|
| 불러오는 중 | 뼈대만. 숫자 자리에 `0` 을 넣지 않는다 |
| 결과 없음 | `아직 완료한 검사가 없습니다` + `기계공학 검사 시작` |
| 경험 없음 | `아직 추가한 경험이 없습니다` + `첫 경험 추가` |
| 검사 미완료 | `풀던 검사가 있습니다` + `이어하기` |
| 결과 생성 실패 | 무엇이 실패했는지와 다시 만드는 길. 참조 번호 |
| PDF 실패 | 웹 결과지는 열려 있다는 것부터 적는다 |
| 권한 없음 | `찾을 수 없습니다`. 남의 것이 있다는 것조차 알리지 않는다 |
| 초대 링크 만료 | 다시 받는 길 |
| 반영할 거리 없음 | `다시 계산할 거리가 아직 없습니다` + 경험 추가 |
| 네트워크 실패 | 개발자 오류 글자를 그대로 내보내지 않는다 |

## 15. Workspace UI 판본

검사와 결과지 판본과 **따로** 간다.

```
CAREERMATRI_WORKSPACE_UI_V1
```

담는 파일은 `src/app/me/**` 와 `src/app/cores/page.tsx` 와
`src/lib/me-v3/platform.ts` 의 읽는 함수들이다. 지문은
`sites/pca-platform/assessment/ME_V3/workspace-lock.json` 에 적고
`npm run v3:workspace` 가 대조한다.

**파일럿에서 `어떤 Workspace 화면을 본 사용자였는가` 를 되물을 수 있어야
한다.** 그래서 `v3_snapshots.module_versions` 에 한 칸을 더한다.

## 16. Analytics (§64)

새 시스템을 만들지 않는다. 지금 있는 `analytics_events` 를 그대로 쓰고
열쇠 여덟만 더한다.

```
workspace_opened · assessment_continue_clicked · result_opened
experience_add_started · experience_added · current_state_updated
action_opened · action_saved
```

**사람으로 센다.** 그리고 화면 녹화와 키 입력 수집은 하지 않는다.

## 17. 이 문서가 바꾸지 않는 것

검사 문항 · 채점 · 보기 넷의 뜻 · 영역 묶음 기준 · 소유 판정 · Evidence
판정 · 산업과 직무가 Core 를 바꾸지 않는 원칙 · 등급 구조 · routing ·
ResultModel 의 판단 · 굳은 스냅샷 · 과거 결과 · 반영 규칙 · 가격.

**Workspace 는 그 위에 올라가는 사용자 경험 층이다.**
