# 직무가 바라는 증거를 얼마나 넓게 확인했는가

증거 사다리는 경험 하나가 **얼마나 깊은가**를 본다. 여기 나오는 것은 그
직무에서 확인해야 할 영역을 **얼마나 넓게 덮었는가**다.

```
깊이  캡스톤 하나가 활동 → 판단 → 산출물 → 성과까지 갔다        E3
범위  CAE 가 보고 싶어 하는 아홉 영역 가운데 넷이 확인된다      4 / 9
```

**둘을 합치지 않는다.** 곱하거나 평균 내면 숫자 하나가 남고, 그 숫자로는
무엇을 더 해야 할지 알 수 없다. 깊은데 좁은 사람과 얕은데 넓은 사람이
같은 숫자를 받으면 둘 다 틀린 다음 걸음을 밟는다.

**점수로 바꾸지 않는다.** 아홉 칸 가운데 넷이면 넷이라고 적는다. 44 로
바꾸는 순간 비교할 자가 없는 숫자가 하나 생기고, 나머지 다섯이 무엇인지가
가려진다.

## 1. 증거 지도

직무군 열여섯에 영역 199개를 적어 뒀다(`content/me-evidence-map.json`).

| | 영역 수 |
|---|---|
| 핵심 | 99 |
| 뒷받침 | 67 |
| 선택 | 33 |

**핵심**은 그 직무를 설명할 때 반드시 확인돼야 하는 것, **뒷받침**은 있으면
설명이 단단해지는 것, **선택**은 산업과 회사와 세부 직무에 따라 갈리는
것이다. **선택이 비어 있다고 불리하게 보지 않는다.**

영역 하나는 이렇게 생겼다.

```json
{
  "evidence_id": "CAE_VALIDATION",
  "label": "검증",
  "importance": "core",
  "evidence_types": ["project", "research", "internship", "work", "..."],
  "minimum_depth": "E3",
  "description": "결과를 시험값·이론·다른 방법과 견주어 맞는지 본 것",
  "match": { "keywords": ["검증", "실험값", "오차", "..."],
             "courses": [], "tool_categories": [], "tool_only_ok": false },
  "gap_kind": "validation"
}
```

**직무군 이름만 바꾼 복붙을 만들지 않았다.** 가장 많이 겹치는 두 직무군의
영역 이름이 8% 겹친다. 기계설계는 요구사항 해석과 공차와 제조성이고, CAE 는
경계 조건과 격자 독립성과 검증이며, 생산기술은 공정 조건과 작업 표준이다.

## 2. 확인 · 부분 · 아직

| 상태 | 뜻 |
|---|---|
| 확인 | 걸린 경험이 그 영역이 바라는 칸까지 올라와 있다 |
| 부분 | 관련 경험은 있는데 판단·산출물·검증 가운데 비어 있다 |
| 아직 | 지금 적어 주신 것에서 확인되지 않는다 |

**'아직' 은 못 한다는 뜻이 아니다.** 화면 문구도 그렇게 쓴다: `아직 확인되지
않음`. 색으로만 가르지도 않는다. 기호와 머리말이 먼저 읽히고 색은 거드는
자리다. 빨강으로 칠하면 결과지가 시험지가 된다.

## 3. 도구 하나가 핵심을 채우지 않는다

`keywords` 는 **응시자가 직접 적은 글**에서만 찾는다. 도구 갈래는
`tool_only_ok` 가 켜진 영역에서만 센다. 그래서 ANSYS 이름만 적으면 이렇게
된다.

```
해석 도구 사용   확인
문제 정의        아직
모델 생성        아직
경계 조건        아직
검증             아직
설계 판단 연결   아직
```

CAE 핵심 아홉 가운데 확인은 0 이다. 규격 16장이 말한 그대로다.

## 4. 지원서에서 설명할 수 있는가

`READY_TO_APPLY` 를 **뺐다**. '지원 준비' 가 합격 가능성으로 읽혔고, 문항과
신호만으로는 그 말을 할 수 없다. 대신 들어간 것이
`APPLICATION_EVIDENCE_AVAILABLE` 이고 그 뜻은 **지원서와 면접에서 이 직무를
설명할 재료가 일부 모였다**까지다.

넷을 모두 본다. 하나라도 비면 아직이다.

1. 핵심 영역이 여럿 확인됐다
2. 산출물(E2) 이상이 하나 이상 있다
3. 기준과 견준 경험(E3) 이 하나 이상 있다
4. 직접 정한 것(E1) 이 있다

**임의의 숫자를 과학적 기준처럼 쓰지 않는다.** '여럿' 을 핵심의 절반으로
잡은 것은 운영상의 선이고, 파일럿 뒤에 다시 본다. 그 선을 결과지에 점수로
내보내지 않는다.

상태는 아홉 가지다.

```
COMPARE_ROLES                    직무 비교 단계
APPLICATION_EVIDENCE_AVAILABLE   설명할 근거 있음
TARGETED_PREPARATION             한 군데만 채우기
TEST_FIRST                       먼저 해보기
BUILD_EVIDENCE                   근거 만들기
EXPLORE_FIRST                    먼저 살펴보기
ADJACENT_OPTION                  곁에 두기
DEPRIORITIZE_FOR_NOW             지금은 뒤로
INSUFFICIENT_DATA                자료 부족
```

문항이 낸 판정을 범위로 한 번 더 거른다. **올리는 쪽으로만 거르고** 내리는
판정은 건드리지 않는다. **경험을 안 적으신 분은 깎지 않는다**: 범위가 없는
것과 좁은 것은 다르다. 다만 경험을 적으셨는데 핵심이 하나도 안 걸리면 비교
단계로 두지 않는다. 비교는 꺼낼 것이 있을 때 쓸모 있는 말이다.

## 5. 비어 있는 자리는 고르기로 채운다

커리어메트리는 주관식을 받아 모델이 읽는 서비스가 아니다. 그래서 되묻는
말을 전부 보기로 냈다(`content/followups.json`). 다섯 갈래 열 문항 일흔다섯
보기다.

```
결과를 무엇과 비교하셨습니까
  설계 기준 · 실험값 · 기존 제품 · 다른 설계안 · 이론값
  다른 해석 방법 · 규격·표준 · 비교하지 않았습니다

결과가 어떤 판단에 쓰였습니까
  설계안 선택 · 치수 변경 · 재질 변경 · 조건 변경 · 시험 조건 결정
  원인 분석 · 계속할지 접을지 결정 · 판단에 직접 쓰이지는 않았습니다
```

**'비교하지 않았습니다' 와 '남은 것이 없습니다' 를 보기에 둔다.** 그 답도
자료다. 그 칸을 없애면 아무거나 고르게 된다. 자유 입력은 '그 밖에' 한 칸만
둔다.

## 6. 계획이 비어 있는 자리에서 나온다

30일은 가장 큰 핵심 공백 하나만, 90일은 그것을 결과물과 기준 비교까지,
365일은 조직에 맞는 묶음으로. 거기에 학위 단계 문장이 붙는데 **학위명만
바꾼 같은 문장을 쓰지 않는다.**

| | 30일 |
|---|---|
| 학사 | 수업이나 동아리 안에서 작게 한 번 끝까지 해봅니다 |
| 석사 | 학위 연구에서 쓴 방법 가운데 직무로 옮겨 갈 것을 추려 적습니다 |
| 박사 | 내가 직접 정한 것과 받은 것을 과제별로 갈라 적습니다 |
| 포닥 | 맡아서 끌고 간 범위를 과제별로 적고 근거를 붙입니다 |

BASIC 은 30일만, STANDARD 는 30·90, PRO 는 30·90·365 를 낸다.

## 8. 다음에 붙일 자리

특정 기관을 붙일 칸을 비워 두고 모양만 만들어 뒀다.

```json
{ "target_organization": null, "target_role": null,
  "organization_specific_evidence": [] }
```

기관별 요구사항이 생기면 그 직무의 영역 목록에 얹기만 하면 된다. **지금은
기관 자료가 없으므로 비워 둔다.**

## 9. 검사

```bash
npm run coverage:check   # 범위 엔진 서른셋 (브라우저 없이)
npm run v2:flow          # 실제 브라우저로 끝까지
```

규격이 요구한 T1~T12 가 전부 들어 있다. 도구 이름만 → 핵심 아홉이 전부 아직 /
모델+해석 → 모델 생성과 해석 수행 확인, 검증은 아직 / 실험 검증 → 검증 확인 /
CAD 만 → 산출물이 일부에 머묾 / 캡스톤 전체 → 핵심 여섯 확인 / 박사 논문 다수 →
연구는 오르고 제품 설계는 0 / 깊이 하나만 → 설명할 근거 있음 금지 / 핵심 여럿 +
산출물 + 판단 → 설명할 근거 있음 / 조직을 바꿔도 범위 동일 / 상관없는 도구를
더해도 범위 불변 / 경험을 지우면 아직으로 돌아감 / 능력 부족으로 읽히는 말 없음.

## 10. 아직 안 한 것

- **특정 기관 요구사항.** 칸만 만들어 뒀다
- **다른 전공.** 영역 199개가 전부 기계공학이다
- **Global Country Layer.** 이번에도 손대지 않았다. 나라 자료 없이 나라
  화면을 먼저 만들지 않는다
- **고른 보기를 경험에 되쓰기.** 지금은 보기를 보여 주고 '경험 보완하기' 로
  보내는 데까지다. 고른 값이 바로 경험 칸을 채우게 하는 것은 다음이다
- **영역 가중치.** 핵심·뒷받침·선택 세 갈래까지만 두고 영역마다 무게를
  달리하지 않았다. 파일럿 전에는 그 무게를 정할 자료가 없다
