# 21. 결제는 밖에서, 응시는 여기서 — 응시권 코드

2026-09-14. "아임웹으로 구축한다면?" 에 대한 답과, 그래서 무엇을 만들었는지.

---

## 0. 답

**소개 사이트는 아임웹으로 되고, 검사 플랫폼은 안 된다.** 그래서 셋으로
나눈다.

| | 어디서 | 왜 |
|---|---|---|
| 소개·설득 | 지금 사이트 | 결과지 샘플 탭 12개와 차트가 설득의 핵심인데 에디터로 재현이 안 된다 |
| 결제 | 쇼핑몰(아임웹) | PG·에스크로·통신판매 신고가 한 묶음으로 빨리 열린다 |
| 응시·채점·결과지 | 이 플랫폼 | 화면 24개, 서버 로직 5,000줄, 테이블 81개 |

## 1. 왜 플랫폼은 안 되는가

빌더로 못 만드는 것이 목록으로 있다.

- 253문항을 **한 문항 고를 때마다 저장**하고 이어보기
- 채점 산식을 테이블에서 읽어 계산(배포 없이 학과별 가중치 변경)
- 결과지 18페이지를 **서버에서 SVG 로** 그려 인쇄 가능하게
- 명단 엑셀 업로드 → 계정 일괄 발급 → 임시 비밀번호 1회 표시
- 익명 집계에서 **5명 미만 칸 마스킹**
- 무료·유료 경계(유료 데이터를 조회조차 하지 않는다)
- 익명화 파기(users 행을 남기고 이름·이메일만 지운다)

그리고 아임웹 개발자센터는 **"특정 고객 또는 사이트만을 위한 서비스" 를
승인하지 않는다.** 우리만 쓰는 앱을 그 위에 올릴 수 없다.

## 2. 왜 API 가 아니라 코드인가

주문 API 로 이으려면 승인이 필요하고, 승인 요건이 위와 같다. **코드 교환은
승인이 필요 없다.** 쇼핑몰이 아임웹이든 스마트스토어든 네이버폼이든
"주문이 끝나면 코드를 보낸다" 는 똑같고, 이쪽 표는 그대로다.

파는 곳을 바꿀 때 고칠 코드가 없다는 것이 이 설계의 값이다.

## 3. 만든 것

```
npm run metri:codes -- --product REPORT_HS --count 50 --batch imweb-2026-09 --days 365
npm run metri:redeem      # 코드가 한 번만 좌석이 되는지 확인
```

- `db/schema_metri.sql` 32절 — `redemption_codes`
- `src/lib/redeem.ts` — 발행·교환·묶음 취소
- `src/app/redeem/` — 학생이 코드를 넣는 화면(결제 화면·무료 화면과 나란한 세 번째 문)
- `scripts/metri/make-codes.ts` — 쇼핑몰에 붙여 넣을 CSV
- `scripts/metri/redeem-check.ts` — 일곱 가지 확인

### 지켜야 하는 것 넷

**코드를 평문으로 두지 않는다.** sha256 만 저장하고 만들 때 한 번 보여준다.
다시 보여주기는 없고 새로 찍는 것만 있다 — 임시 비밀번호와 같은 규칙이다.
DB 가 새도 그대로 공짜 좌석이 되지는 않는다.

**금액은 0 으로 적는다.** 돈은 쇼핑몰 장부에 있다. 이쪽에 19,000 을 또
적으면 같은 매출이 두 번 잡힌다. 무엇으로 팔렸는지는
`orders.redemption_code_id` 가 들고 다닌다.

**두 번 쓰이지 않는 것은 UPDATE 가 보장한다.** 먼저 읽고 판단한 뒤 쓰면
같은 코드로 두 사람이 동시에 눌렀을 때 둘 다 통과한다.
`WHERE used_at IS NULL` 을 UPDATE 조건에 넣어 이긴 쪽만 줄을 가져간다.
검사 4절이 실제로 동시에 눌러 본다.

**왜 안 되는지를 이유마다 다르게 적는다.** 없는 코드·이미 쓴 코드·기간
지난 코드·취소된 코드가 각각 다른 문장을 받는다. "코드가 올바르지
않습니다" 하나로 뭉개면 **이미 돈을 낸 사람이 자기 잘못인 줄 알고 문의조차
못 한다.** 이미 쓴 코드는 본인이면 결과지로 가는 문을 같이 준다.

### 글자판

`ACDEFGHJKMNPQRTUVWXY34679` 22자. **0/O, 1/I/L, 8/B, 5/S, 2/Z 를 뺐다** —
종이에서 옮겨 적는 코드라 헷갈리는 글자가 그대로 오타가 된다.
`XXXX-XXXX-XXXX` 12자리면 찍어서 맞히는 것은 논외다.
입력은 하이픈·공백·소문자를 흡수한다.

## 4. 그런데 순서는 이게 아니다

**지금 1순위 매출인 학교 계약은 결제가 필요 없다.** 계약으로 좌석이 생기고
학생은 그냥 들어온다. PG 도 통신판매업 신고도 없이 오늘 된다.

개인 결제는 2순위다. 코드 교환을 만들어 둔 것은 **그때가 오면 하루 만에
열려고**지, 지금 이것부터 하자는 뜻이 아니다. 순서는 그대로다.

1. 도메인 잡고 지금 사이트 배포 (`docs/metri/20_domains.md`)
2. 학교 한 곳 시범 도입 — 매출과 실제 응답이 같이 나온다
3. 개인 결제가 급해지면 쇼핑몰에 응시권 상품을 올리고 코드를 찍는다

## 5. 아직 아닌 것

- **쇼핑몰 계정.** 아임웹 요금제는 확인하지 못했다 — 지어내지 않았다
- **자동 발송.** 지금은 CSV 를 받아 쇼핑몰 쿠폰이나 자동발송 문구에 사람이
  넣는다. 주문 수가 늘면 그때 자동화한다
- **환불.** 쓴 코드를 되돌리는 길은 만들지 않았다. 쇼핑몰에서 환불하고
  `voidBatch` 로 안 쓴 코드를 막는 것까지가 지금 되는 일이다
