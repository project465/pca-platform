# 운영환경 검증 보고 (Wave 0 직전)

새 기능을 만들지 않고 **실제 운영환경 검증**만 한 회차다. 기준선은
`ME_V3_ITEM_BANK_V2.3` · `me-v3-scoring.5` · `ME_V3_2_ASSESSMENT_UI_V2` ·
`ME_V3_RESULT_UI_V3.1` 이고, 문항과 채점과 결과 모델은 한 줄도 바꾸지
않았다.

**판정 표시 셋을 섞지 않는다.**

| 표시 | 뜻 |
|---|---|
| `AUTOMATED PASS` | 이 기계의 공개 전 배포본에서 검사가 돌아 통과했다 |
| `EXTERNAL BROWSER PASS` | 배포본을 밖에서 브라우저로 열어 눈으로 확인했다 |
| `OWNER ACTION REQUIRED` | 여기서 할 수 없고 조건희가 직접 해야 한다 |

**이 회차에 `EXTERNAL BROWSER PASS` 는 한 줄도 없다.** 이 컨테이너의
네트워크 정책이 바깥 HTTPS 를 막아 `app.careermatri.com` 을 열지 못했다.
자동 검사가 통과한 것을 밖에서 확인했다고 적지 않는다.

## A. Railway DB migration

**상태: 미실행 — 조건희가 Railway Shell 에서 실행 필요.**

Railway Shell 에 들어갈 권한이 없고 바깥 네트워크가 막혀 있다.
**돌렸다고 적지 않는다.**

붙여 넣을 한 줄이다.

```bash
npm run db:upgrade && npm run db:verify && npm run ops:check
```

| 무엇 | 지금 |
|---|---|
| 들어가는 자리 | Railway → 프로젝트 → 서비스 → `⋯` → Shell |
| `db:upgrade` 가 하는 일 | 빠진 칸과 표를 세운다. 여러 번 돌려도 같은 자리에 선다 |
| 안 돌리면 | `/v3/start` 에서 500. `column ... does not exist` 가 뜬다 |
| 이 기계에서 대신 확인한 것 | `npm run db:migration` 6가지 통과. 옛 판본 DB 를 세워 지금 `db:upgrade` 를 두 번 돌리고, 빈 DB 에 새로 세운 것과 칸·제약·인덱스를 글자까지 대조했다 |

**이 회차에 그 검사의 구멍 하나를 메웠다.** 칸 이름을 뽑는 자리가 쉼표
앞에 낱말 경계를 요구하고 있어서, 앞엣것이 따옴표인 자리
(`SET state='done', updated_at=now()`)의 칸이 통째로 안 세어졌다.
`v3_actions` 에 없는 `updated_at` 을 쓰는 줄이 그렇게 지나갔고, 재분석을
누르는 자리에서 500 이 났다. 고치고 나니 세는 칸이 508개에서 523개로
늘었고, 되돌려 보니 그 줄을 집어낸다.

| 그 배포의 상태 | GitHub Deployments 가 `success` | AUTOMATED PASS |
| 배포본을 밖에서 열어 보기 | **못 했다.** `curl` 이 `(56) CONNECT tunnel failed, response 403` | OWNER ACTION REQUIRED |

**403 은 이 컨테이너의 네트워크 정책이고 사이트가 죽었다는 뜻이 아니다.**
프록시 상태가 `connect_rejected`(`gateway answered 403 to CONNECT,
policy denial`)로 그 사실을 적는다.

**시작 주소**는 `https://app.careermatri.com/cores` 다. 거기서 기계공학을
고르면 `/v3/start` 로 간다. `careermatri.com` 은 소개 사이트이고 앱이
아니다.

**이 회차의 커밋은 아직 배포되지 않았다.** 밀어 넣으면 Railway 가 같은
가지를 받아 새로 굽는다. **main 병합은 필요하지 않다.**

**이 회차에 고친 것 둘.**

하나는 **같은 문장이 종이에 두 번 나간 것**이다. `이 결과는 응시하신 시점의
문항과 판정 기준으로 고정되어 있습니다` 가 `읽는 법` 절과 닫는 안내에 각각
있었다. 화면에서는 닫는 안내가 접혀 있어 겹침이 안 보이고, 종이에서는 둘 다
펴진다. 닫는 안내에서 뺐다.

둘은 **종이에서 눌릴 수 없는 길**이다. `내 CareerMatri로` 링크가 마지막
쪽에 혼자 서 있었다. 화면에만 둔다.

**쪽수 범위를 옮겼다.** `3~4 · 6~8 · 8~10` 은 결과지가 일곱 절이던 때에
적어 둔 값이라 아홉 절이 된 뒤로 세 등급 모두 넘고 있었다. **본문을 깎아
옛 범위에 맞추지 않았다**: 늘어난 두 절은 일부러 더한 것이다. 지금 뽑히는
`4~5 · 8~9 · 11~12` 로 옮겼다.

**마지막 쪽은 결과 기준 안내 한두 줄만 들고 선다.** 빈 쪽이 아니고 어느
문서든 마지막 쪽은 남은 만큼만 찬다. 종이를 보시고 거슬리면 닫는 안내를
본문 마지막 절 안으로 넣는 것이 다음 수정이고, 쪽수를 맞추려고 본문을
깎는 일은 하지 않았다.

**§14 Result History 구분. 이번에 메웠다.**

검증하면서 **구멍 하나**를 찾았다. `/my/results` 는 옛 표
(`attempts` · `report_snapshots`)만 읽어서 V3 를 끝낸 사람에게 빈 목록을
보여 주고, `/me` 는 가장 최근 결과 하나만 걸고 있었다. 그래서 **응시를 두
번 한 사람의 앞 결과는 어느 화면에서도 닿지 않았고**, 화면에서 `검사 당시
결과` 와 `지금 상태` 가 날짜로 갈리지 않았다.

`/me` 에 **결과 이력** 카드를 세웠다. 줄마다 기준과 날짜가 갈린다.

```
경험 추가 후 현재 상태 · 2026-10-08
검사 당시 결과 · 2026-10-08 · PRO · 결과 보기
검사 당시 결과 · 2026-09-30 · BASIC · 결과 보기
```

`결과 보기` 는 그날의 스냅샷을 그대로 연다. **지금 값이 과거 결과를
덮지 않는다**: 굳은 줄은 `v3_snapshots` 에 있고 지금 값은
`career_profiles` 한 줄이라 표가 다르다. `지금 상태` 줄은 재분석을 한 번
이라도 돌린 뒤에만 선다(안 돌린 사람에게 같은 값이 두 줄로 보이지 않게).

## J. User A · User B 격리

두 계정을 이 자리에서 만들어(열쇠는 과정 안에서만 만들고 저장소·문서·
로그에 남기지 않는다) 각자 응시를 끝내고, A 에만 경험을 적고 재분석을
돌린 뒤 B 로 A 의 주소를 열어 봤다.

**막히는 것만 세지 않는다.** 전부 막는 코드는 이 검사를 통과하면서 산
사람도 못 보게 하므로, 자리마다 **A 는 열리고 B 는 막힌다**를 짝으로 센다.

| 자리 | A | B | 판정 |
|---|---|---|---|
| Attempt (`/v3/<번호>`) | 열림 | 막힘 404 | **PASS** |
| Result (`/v3/<번호>/result`) | 열림 | 막힘 404 | **PASS** |
| PDF (`/v3/<번호>/result/pdf`) | 열림 | 막힘 404 | **PASS** |
| Experience (`/me/experience`) | 내 경험이 보인다 | 남의 경험이 안 보인다 | **PASS** |
| Result History (`/me`) | 내 결과가 걸린다 | 남의 결과가 안 걸린다 | **PASS** |
| Admin (`/admin/v3-pilot`) | — | 막힘 → `/my` | **PASS** |

화면이 거르는 것과 질의가 거르는 것은 다른 일이라 서버 함수도 따로 봤다
(`experiencesOf(B)` 가 A 의 줄을 돌려주지 않는다). A 의 재분석으로 B 의
스냅샷이 늘지 않는 것도 확인했다.

**대규모 보안감사로 넓히지 않았다.** 본 자리는 §7 이 적어 둔 여섯이다.

| admin 에서 participant 확인 불가 | 표에 가명과 진행이 선다 | 아니다 |

**막는 것은 하나다: A 의 `db:upgrade`.** 그 줄을 돌리고 `docs/metri/
66_owner_test.md` 를 끝까지 PASS 로 채우면 Wave 0 를 시작할 수 있다.

Wave 0 는 2~3명이고 **학부 1 · 석사 이상 1 · 경험 많은 사람 1** 이다.
**이 회차에서 실제 참가자에게 링크를 보내지 않았다.**

## M. 지금 판본 목록

응시 하나가 스냅샷에 적고 다니는 판본이다. **이 회차에 다섯 가지를 더
적게 했다**: 전에는 여섯뿐이어서, 어느 화면으로 어느 문장을 읽고 답했는지가
남지 않았다. 파일럿이 끝난 뒤에는 되물을 수 없는 값이다.

| 무엇 | 값 |
|---|---|
| core | `ME_CORE_V3` |
| item bank | `ME_V3_ITEM_BANK_V2.3` |
| scoring | `me-v3-scoring.5` |
| assessment ui | `ME_V3_2_ASSESSMENT_UI_V2` |
| assessment copy | `me-v3-2-assessment-copy.4` |
| result model | `me-v3-result-model.4` |
| result copy | `me-v3-result-copy.5` |
| result ui | `ME_V3_RESULT_UI_V3.1` |
| industry pack | 고른 팩의 판본 (예: `INDUSTRY_SEMICON_V2.v2`) |
| role pack | 고른 팩의 판본 (예: `ROLE_CAE_V2.v2`) |
| region layer | `null` (자료가 없다) |

결과지 판본 둘을 올렸다: 문장 하나를 빼고 인쇄 규칙을 고쳤으므로
`me-v3-result-copy.5` 와 `ME_V3_RESULT_UI_V3.1` 이다. **채점과 결과 모델
판본은 올리지 않았다**: 판정이 한 줄도 바뀌지 않았고, 올리면 이미 응시한
사람의 결과를 다시 계산해야 하는지 묻게 된다.

**검사 화면 판본은 올리지 않고 지문만 다시 적었다.** 바뀐 파일은
`runtime/session.ts` 한 벌이고 바뀐 자리는 **스냅샷에 판본을 적는 줄**이다.
묻는 것도 답하는 길도 그대로다.

## N. 아직 실제가 아닌 기능

**준비 중이라고 적혀 있고, 되는 것처럼 보이지 않는다.**

| 무엇 | 지금 | 화면이 적는 말 |
|---|---|---|
| 자동 재분석 | 할 일만 쌓인다. 사람이 누를 때 돈다 | `자동 재분석 전` |
| 공고 수집 | 줄이 0개. 저작권·이용약관 검토 전 | `공고 자료 검토 전` |
| 산업 요구역량 변화 | 표본과 근거 등급이 없다 | `표본과 근거 등급 필요` |
| 월간 Career Report | 메일 연결 전 | `메일 연결 전` |
| Track 구독 결제 | 반복결제가 없다 | `값과 켜는 날은 정해지지 않았습니다` |
| 지역 기관 수 | `region_industry` · `org_registry` 가 0줄 | 숫자를 짓지 않는다 |
| 전공 Core 아홉 | 등록만 돼 있다 | `준비 중` 과 그 까닭 |
| 영어판 | 한 줄도 없다 | 내놓지 않는다 |

**§16 확인**: Track 화면의 단추는 `켜지면 알려주세요` 이고 결제가 아니다.
반복결제 · 자동 공고 수집 · 월간 리포트 · 자동 재분석 · 알림을 되는 것처럼
적은 자리가 없다.

**§15 확인**: `추천 지역` · `취업 가능성이 높은 지역` · `수요 높은 지역` ·
`취업률 높은 지역` 네 가지가 저장소의 화면과 자료에 **0회**다. 지역 화면은
`이 선택은 기술영역 결과에 반영되지 않습니다` 를 머리에 적는다. 지역
자료 작업은 하지 않았다.

**§24 확인**: 물었는데 결과 어디에도 안 쓰이는 문항 0 · 결과에 나오는데
입력이 없는 항목 0 (`v3:migrate` 와 `v3:result` 의 차등 도달 검사).

**§25 확인**: 산업과 역할 팩을 바꿔도 Core 판정의 지문이 글자까지 같다
(`v3:runtime` · `v3:scoring`).

| 번호 | 무엇 | 누가 | 막는가 |
|---|---|---|---|
| 1 | Railway Shell 에서 `db:upgrade` | 조건희 | **Wave 0 를 막는다** |
| 2 | 배포본을 밖에서 브라우저로 한 바퀴 (`66_owner_test.md`) | 조건희 | **Wave 0 를 막는다** |
| 3 | iPhone Safari 실기기 확인 | 조건희 | 막지 않는다. 적어 둔다 |
| 4 | 저장소의 개발용 시드 비밀번호 열세 파일 | 판단 필요 | 막지 않는다 |
| 5 | `platform.ts` · `recompute.ts` 가 기계공학 하나에 묶여 있다 | 파일럿 뒤 | 막지 않는다 |

**4번을 적어 두는 까닭.** §6 은 비밀번호를 저장소에 두지 말라고 한다.
지금 저장소에는 개발용 시드 비밀번호가 열세 파일에 있다
(`scripts/v3-shots.mjs` 등 캡처·검사 스크립트). **운영 비밀번호가 아니고**
`scripts/seed.ts` 가 개발 DB 에 심는 값이며, 운영에서는 시드가 거절되고
운영자 계정은 `make:admin` 이 그 자리에서 만들어 한 번만 보여 준다.
글자 그대로 지키려면 환경변수로 옮겨야 하는데, 열세 파일을 고치는 일은
기준선 동결(§1) 아래에서 할 일이 아니라 손대지 않았다.
**이 회차에 새로 적은 비밀번호는 없다**: 새 검사 둘은 열쇠를 과정 안에서
만들어 쓰고 해시만 DB 에 남긴다.

5번은 `docs/metri/67_arch_debt.md` 에 적어 두었다.

## 조건희가 직접 해야 하는 것

개발 용어 없이 적는다. 위에서 아래로 한 번만 내려가면 된다. 자리마다 자세한
정상 조건과 체크 칸은 `docs/metri/66_owner_test.md` 에 있다.

### 1. DB 를 최신으로 올린다

- **접속 주소**: Railway → 프로젝트 → 서비스 → `⋯` → `Shell`
- **입력할 것**: `npm run db:upgrade && npm run db:verify && npm run ops:check`
- **정상일 때 보이는 것**: 오류 없이 끝나고 표와 칸을 센 줄이 나온다
- **PASS / FAIL**: 빨간 오류가 없으면 PASS. `column ... does not exist`
  가 보이면 FAIL

### 2. 앱이 열리는지 본다

- **접속 주소**: `https://app.careermatri.com/cores`
- **누를 것**: 목록에서 `기계공학`
- **정상일 때 보이는 것**: 기계공학만 열려 있고 나머지 아홉은 `준비 중`
- **PASS / FAIL**: 500 이나 빈 쪽이 뜨면 FAIL

### 3. 테스트 계정을 만든다

- **접속 주소**: `https://app.careermatri.com/signup`
- **입력할 것**: 아이디와 비밀번호를 직접 정한다. **비밀번호는 따로
  적어 두고 저에게 보내지 않는다**
- **정상일 때 보이는 것**: 가입하면 바로 로그인된 상태로 내 화면이 열린다
- **PASS / FAIL**: 로그인 화면으로 되돌아오면 FAIL

### 4. 그 계정에 운영자 권한을 준다

- **접속 주소**: Railway Shell
- **입력할 것**: `npx tsx scripts/make-admin.ts <3번 아이디> <이메일> <이름>`
- **정상일 때 보이는 것**: 비밀번호가 한 번만 화면에 뜬다. 옮겨 적는다
- **PASS / FAIL**: `/admin/v3-pilot` 이 열리면 PASS

### 5. 등급 세 개를 돈 없이 연다

- **접속 주소**: `https://app.careermatri.com/admin/v3-pilot`
- **누를 것**: `초대 자리 만들기` 칸에서 wave 를 `Wave 0`, 등급을 고르고
  단추를 누른다. `BASIC` · `STANDARD` · `PRO` 각각 한 번씩
- **입력할 것**: 없다. 고르기만 한다
- **정상일 때 보이는 것**: 주소가 줄로 나온다. **새로 고치면 다시 볼 수
  없으니 바로 메모장에 옮긴다**
- **PASS / FAIL**: 결제창이 뜨면 FAIL. 돈은 한 푼도 움직이지 않아야 한다

### 6. BASIC 을 끝까지 풀어 본다

- **접속 주소**: 5번에서 받은 BASIC 주소를 브라우저에 붙여 넣는다
- **누를 것**: 등록을 끝내고 검사를 끝까지 푼다 (12분 안팎)
- **정상일 때 보이는 것**: 마지막에 무엇을 확인했는지 네 줄과 `결과 보기`
- **PASS / FAIL**: 중간에 `다음` 이 안 눌리거나 같은 화면이 반복되면 FAIL

### 7. 중간에 닫고 이어해 본다

- **누를 것**: 푸는 중에 탭을 그냥 닫고, `https://app.careermatri.com/me`
  에서 `검사 이어하기`
- **정상일 때 보이는 것**: 처음 화면이 아니라 **멈췄던 자리**가 열리고
  앞에 고른 답이 그대로 선택되어 있다
- **PASS / FAIL**: 처음부터 다시 물으면 FAIL

### 8. 휴대전화에서 같은 계정으로 이어해 본다

- **접속 주소**: 휴대전화 브라우저로 `https://app.careermatri.com/me`
- **정상일 때 보이는 것**: 컴퓨터에서 멈춘 자리와 **같은 자리**가 열린다
- **PASS / FAIL**: 처음부터 시작되면 답이 그 컴퓨터에만 저장된 것이고 FAIL

### 9. 결과지와 종이를 본다

- **접속 주소**: 결과 보기 → 아래로 끝까지 → `결과 PDF 저장`
- **정상일 때 보이는 것**: 첫 화면 세 칸이 바로 읽히고, 종이가 내려오고,
  글자가 네모로 깨지지 않았고, 아무것도 없는 쪽이 없다
- **PASS / FAIL**: `TD01` `J3` `Z1` `TR_TAG_1` 같은 코드가 보이면 FAIL

### 10. STANDARD 와 PRO 도 같이 해 본다

- **접속 주소**: 5번에서 받은 나머지 두 주소. **계정을 새로 만들어** 각각
  들어간다
- **정상일 때 보이는 것**: STANDARD 는 묶음이 더 열리고, PRO 는 경험 번역
  열 단계가 나온다. 종이는 9쪽과 12쪽
- **PASS / FAIL**: PRO 에서 번역 표가 안 나오면 FAIL

### 11. 경험을 하나 적고 다시 계산한다

- **접속 주소**: `https://app.careermatri.com/me/experience/new`
- **입력할 것**: 종류와 제목을 적고 **기술영역을 고른다.** 그러면 그 영역의
  문제·판단·산출물·검증 목록이 뜨니 묶음마다 둘씩 고른다
- **그다음**: `/me/recompute` 에서 표를 읽고 `지금 값에 반영하기`
- **정상일 때 보이는 것**: 어느 경험이 어느 판단으로 가는지 줄마다 적혀
  있고, `그때 낸 결과지는 달라지지 않습니다` 가 보인다
- **PASS / FAIL**: 경험만으로 `직접 결정` 까지 오르면 FAIL

### 12. 과거 결과와 지금 상태가 갈리는지 본다

- **접속 주소**: `https://app.careermatri.com/me`
- **볼 것**: `결과 이력` 카드
- **정상일 때 보이는 것**: `검사 당시 결과 · 날짜 · 등급 · 결과 보기` 와
  `경험 추가 후 현재 상태 · 날짜` 가 서로 다른 줄로 서 있다
- **PASS / FAIL**: `결과 보기` 를 눌렀을 때 경험을 더한 뒤의 숫자가 들어가
  있으면 FAIL

### 13. 남의 결과가 열리는지 본다 (가장 중요하다)

- **접속 주소**: 10번에서 만든 다른 계정으로 로그인한 상태에서, 주소창에
  6번 계정의 응시 번호를 넣는다.
  `https://app.careermatri.com/v3/<남의 번호>/result` 와
  `https://app.careermatri.com/v3/<남의 번호>/result/pdf`
- **정상일 때 보이는 것**: 둘 다 `찾을 수 없습니다`
- **PASS / FAIL**: 남의 결과지나 종이가 열리면 FAIL 이고, **그 자리에서
  Wave 0 를 멈춘다**

### 14. 운영 표에서 참가자가 보이는지 본다

- **접속 주소**: `https://app.careermatri.com/admin/v3-pilot`
- **정상일 때 보이는 것**: 참가자가 `V3-A0001` 모양의 가명으로 서 있고
  등급과 진행 상태가 적혀 있다. 이름과 전공명은 없다
- **PASS / FAIL**: 참가자가 안 보이면 FAIL

**13번이 FAIL 이면 다른 줄이 다 PASS 여도 Wave 0 를 시작하지 않는다.**
