# PCU COMMERCIAL PRODUCT COMPLETION

배재대학교가 학생 수백 명에게 배포하고, 학생은 별도 설명 없이 쓰고, 학교
담당자는 개발자나 콘솔 없이 운영할 수 있는 상태인가. 그것을 **말로 적지
않고 세는 자리**를 만들고, 세어서 걸린 것을 고친 회차다.

측정은 `ME_V3_MEASUREMENT_FREEZE_1` 에 그대로 머문다: scoring · threshold ·
item id · item count · item wording · Core architecture · Domain definition ·
Result / Evidence / Gap decision · routing engine · PCU Registry structure ·
existing specialization mapping · DB schema · `student_open` ·
`open_to_students` 를 한 줄도 건드리지 않았다.

---

## A. `됩니다` 를 선언으로 쓰지 않는다

이 회차의 출발점이 §0 이다. **한 자리에서 되는 것을 전체의 PASS 로 적지
않는다.** 그래서 먼저 지금 코드에 대고 §3~§36 을 전수로 세고, 그 셈이
드러낸 것만 고쳤다.

세는 자리를 둘 새로 만들었다.

- `npm run pcu:cli` 는 **학교 담당자의 일마다 끝내는 자리와 들어가는 길**
  (§24 · §52). 묻는 것은 `그 쪽이 서는가` 가 아니라 **담당자가 로그인한
  뒤 눌러서 그 일을 끝낼 수 있는가**다
- `npm run pcu:routing` 은 **자율전공학부 학생이 쓸 수 있는가**(§32 · §33).
  담당자가 계정을 발급하는 자리부터 밟는다
- `npm run pcu:readiness` 는 **여섯 축 점수를 손으로 적지 않는다**(§53).
  이미 서 있는 검사들을 실제로 돌려 그 출력의 통과·걸림을 센다
- `npm run pcu:review` 는 **사람이 눈으로 볼 묶음**(§58)을 만든다. 자리 19 ×
  데스크톱·손전화를 밟는 차례 그대로 뜬다

## B. 찾은 자리 넷. 셋은 화면이 200 으로 멀쩡히 뜨는 자리다

### B-1. 담당자가 학생 명단을 열 수 없었다 (P0)

`/org/v3/students` 가 **500** 이었다. 까닭은 서버 컴포넌트가 학과 이름을
푸는 **함수를 클라이언트 컴포넌트로 넘기고** 있었던 것이고, Next 는 그것을
직렬화하지 못한다.

```
Error: Functions cannot be passed directly to Client Components
  {rows: ..., deptName: function dept}
```

**이 쪽은 학교 운영의 중심이다.** 계정 발급과 비밀번호 재발급과 재응시
열어 주기와 미응시 좁혀 보기가 전부 그 쪽에 붙어 있어서, 그 500 이 서 있는
동안 담당자가 화면에서 할 수 있는 일이 집계 읽기와 내려받기뿐이었다.

**왜 몇 회차 동안 조용했는가**가 더 중요하다. 이 쪽을 여는 검사가 한 개도
없었다. `campus:export` 는 집계와 CSV 와 PDF 를 보고, `pcu:ops` 는 집계의
수를 DB 와 견주고, 찍는 검사들은 다른 자리를 돈다. **쪽이 서는가와 그 쪽에서
일을 끝낼 수 있는가는 다른 질문이고, 뒤엣것을 보는 검사가 없었다.**

고친 것은 넘기는 값 하나다. 넘어가는 것이 **그 묶음에 쓸 이름뿐**이다.
이름을 푸는 자리는 그대로 등록부 하나다(`campusNames`).

### B-2. 자율전공학부 학생에게 계정이 나갈 길이 없었다 (P0)

명단을 올리는 자리가 그 학과를 **거절**하고 있었다
(`전공을 정한 뒤에 고르는 자리입니다`). 그래서 자율전공학부 명단은 줄마다
오류가 나고, 그 학부 학생은 계정을 받을 수 없었다.

화면만 눌러 보면 드러나지 않는다: 그 학부 카드는 눌리고 전공 목록도 선다.
**전공을 고르는 자리라는 것은 `어느 전공의 자로 재는가` 를 아직 모른다는
뜻이다. `학생이 아니다` 라는 뜻으로 읽으면 안 된다**(§32).

고친 구조는 이렇다.

```
명단       자율전공학부로 계정이 나간다 (소속은 등록부 그대로)
맥락       core_code 를 비워 둔다 (routingContextOf)
시작 화면  검사 시작이 아니라 `전공 고르기` 로 보낸다
응시       학과·단과대학은 등록된 줄 · Core 와 갈래는 고른 전공
```

**자동으로 배정하지 않는다**(§32). 고르지 않았으면 그 자리로 되돌려 보내고,
학부 이름만 보고 특정 Core 로 짐작하지 않는다. **`당신은 이 전공입니다` 로
정해 주지도 않는다**(§33). 적는 것은 `고른 전공이 정합니다` 까지다.

**소속을 고친 전공으로 덮지 않는다.** 덮으면 담당자 명단에서 그 학부가 비고,
**아직 전공을 고르지 않은 학생을 셀 자가 없어진다.** 고른 전공은 이 응시의
자이고 소속은 그대로 남는다. DB 스키마를 바꾸지 않았다. `v3_attempts` 가
학과와 Core 와 갈래를 따로 들고 있다.

### B-3. 하나만 답하고 `다음` 을 누르면 무엇이 비었는지 몰랐다 (P1)

한 화면에 질문이 둘인 자리가 검사의 절반이다. 거기서 하나만 답하고 `다음`
을 누르면 바닥 띠에 `답을 고른 뒤 다음으로 넘어가세요` 한 줄이 떴는데, 그
줄은 **어느 질문이 비었는지 말하지 않는다.** 답한 사람은 자기가 답했다고
알고 있으므로 그 줄을 고장으로 읽는다.

지금은 비어 있는 질문에 금을 하나 긋고 그 자리에 한 줄을 적고, 띠에는 몇
개가 남았는지 적는다. **단추를 끄지 않는다.** 끄면 왜 못 넘어가는지가
화면에서 사라진다.

### B-4. 검사 둘이 거짓으로 걸렸다

`pcu:campus` 의 바늘 둘이 `학교에서 안내받은 계정` 을 찾고 있었는데, 학교
전용 로그인의 문면은 승인된 회차에서 `학교에서 발급받은 계정` 으로 바뀌었다.
**절이 사라진 것과 이름이 바뀐 것은 다른 일이다**(`pcu:coverage` 에서 같은
자리를 한 번 겪었다). 그리고 같은 검사가 `domcontentloaded` 직후에 눌러서,
하이드레이션 전에 떨어진 클릭을 **`학교 로그인으로 가지 않는다` 로 거꾸로
적었다**(서버 쪽이 303 을 내는 것은 따로 확인했다).

예행이 두 문항 화면에서 멈춘 것도 같은 종류였다: 둘째 묶음의 한 칸이 안
눌리면 그 자리에서 그만두고 **`검사가 끝까지 가지 않는다` 로 적는다.** 같은
묶음의 다른 보기를 차례로 더 눌러 보게 고쳤다. **고른 값의 뜻은 그대로다.**

## D. §8 재응시 정책 — 이미 있고, 그대로 UI 에 서 있다

임의로 정하지 않았다. 코드가 들고 있는 정책은 이렇다.

- **기본은 한 번이다.** 끝낸 사람이 `/v3/start` 를 다시 열면 새 응시가
  열리지 않고 지난 결과로 간다. 막는 자리는 서버다
- **담당자가 한 번 열어 준다.** 여는 방법은 이용권 한 줄이라 DB 스키마를
  바꾸지 않는다. 단추를 두 번 눌러도 열리는 것은 한 번이다
- **이전 결과는 보존된다.** 굳은 줄은 `v3_snapshots` 이고 지금 값은
  `career_profiles` 라 표가 다르다
- **최신 Result 는 그 응시의 굳은 줄**이고, 작업공간의 `결과 기록` 이
  기준과 날짜를 줄마다 적는다

그래서 §8 은 P1 gap 이 아니다.

## E. §53 상용 준비도 점수

점수를 손으로 매기면 그 숫자는 그날의 기분을 적은 값이 된다.
`npm run pcu:readiness` 가 이미 서 있는 검사 열여덟을 **실제로 돌려** 그
출력의 통과와 걸림을 세어 여섯 축으로 묶는다. 축마다 가중치가 있고 합이
100 이다.

| 축 | 묻는 것 | 세는 검사 | 통과 | 걸림 | 점수 |
| --- | --- | --- | --- | --- | --- |
| A 학생 Journey | 계정 발급에서 결과와 종이와 작업공간까지 사람 개입 없이 간다 | `pcu:campus` · `pcu:routing` · `v3:product-loop` · `v3:usability` | 154 | 0 | 20 / 20 |
| B 학교 운영자 자립 | 담당자가 개발자나 콘솔 없이 화면에서 일을 끝낸다 | `pcu:cli` · `campus:export` · `pcu:ops` | 125 | 0 | 20 / 20 |
| C 측정 불변 | 상품성 고도화가 재는 자를 한 눈금도 건드리지 않았다 | `v3:freeze:measure` · 동결 넷 | 23 | 0 | 15 / 15 |
| D 개인정보·권한 경계 | 남의 결과가 열리지 않고 담당자가 개별 응답을 보지 못한다 | `v3:isolation` · `auth:check` · `secrets:check` | 64 | 0 | 15 / 15 |
| E 학과 콘텐츠 | 자리 115 가 제 전공의 말로 읽히고 종이까지 닿는다 | `pcu:dept` · `pcu:content` · `pcu:generic` · `pcu:coverage` | 134 | 0 | 20 / 20 |
| F 오류 복구·배포 | 오류를 삼키지 않고 옛 DB 가 한 줄로 최신까지 온다 | `errors:check` · `routes:check` · `db:chain` | 26 | 0 | 10 / 10 |

**합계 100 / 100** (통과 526 · 걸림 0).

규칙 셋이 이 점수를 믿을 수 있게 한다.

- **못 센 축을 초록으로 적지 않는다.** 어느 검사가 셀 수 있는 줄을 내놓지
  않으면 그 축은 `못 봄` 이고, 못 봄이 하나라도 있으면 총점을 선언하지
  않는다(`ops:check` 가 `UNKNOWN` 과 `BLOCKED` 를 가르는 것과 같은 까닭이다)
- **종료 코드를 무시하지 않는다.** 통과 수만 세면 중간에 터져서 몇 줄만
  찍고 끝난 검사가 만점으로 읽힌다
- **걸림의 문면을 그대로 모아 적는다.** 수만 내놓으면 무엇을 고쳐야 하는지가
  어디에도 없고, 그러면 다음 사람이 처음부터 다시 찾는다

**이 점수는 내부 QA 점수이고 학생 결과와 무관하다**(§53). 측정에 닿지 않고,
어느 Core 의 학생 공개 상태도 바꾸지 않는다.

**90 을 넘었다고 상용 선언을 하지 않는다.** 이 점수가 재는 것은 이 기계에서
운영과 같은 배치로 띄워 돌린 결과이고, 운영 배포본을 밖에서 열어 본 자리가
한 줄도 없다(아래 G 절).

## F. §54 P0 · P1 · P2

**P0 는 최종 0 이어야 한다.** 이 회차가 찾은 P0 둘은 고쳤고, 코드 쪽에 남은
P0 가 0 이다.

| 급 | 자리 | 지금 |
| --- | --- | --- |
| P0 | 담당자가 학생 명단을 열 수 없었다(B-1) | 고쳤다 |
| P0 | 자율전공학부 학생에게 계정이 나갈 길이 없었다(B-2) | 고쳤다 |
| P1 | 하나만 답하고 `다음` 을 누르면 무엇이 비었는지 몰랐다(B-3) | 고쳤다 |
| P1 | 검사 둘이 거짓으로 걸렸다(B-4) | 고쳤다 |
| P1 | 전공 말 넷이 우리 쪽 비유로 세어졌고 옛 판본 결과지를 고치라고 했다 | 고쳤다 |
| P1 | 학교 학생이 쿠키 없이 `/v3/start` 를 직접 치면 개인 응시가 열린다 | 사업주 확인 대기 |
| P1 | 자율전공 학생이 고른 전공을 기억하는 칸 | DB schema 변경이라 승인 대기(§55) |
| P1 | 갈래 콘텐츠 62벌의 근거 예시와 할 일이 그 전공에서 실제로 나오는가 | 전공자 검토 대기 |
| P2 | 교육 Core 종이의 마지막 쪽이 29% 다 | 공통 템플릿으로는 한 자리를 올리면 다른 자리가 내려간다 |
| P2 | 경험에 파일 업로드가 없다 | 저장 구조가 아직 없다 |
| P2 | iPhone Safari 실기기 확인 | 이 컨테이너에서 WebKit 을 내려받지 못한다 |
| P2 | 영어판 학생 화면과 결과지 | 한 줄도 쓰지 않았다 |

**운영 쪽 둘은 판정이 `UNKNOWN` 이다.** 운영 종이(PDF)와 운영 담당자 집계는
운영에서 사람이 한 번 눌러야 답이 나온다. 네트워크 정책이
`app.careermatri.com:443` 을 막아(HTTP 000) 그 자리를 열지 못했다.
**`BLOCKED` 로 적지 않는다**: 설정이 틀린 것이 아니고 내가 못 본 것이다.
섞으면 둘 다 쓸모가 없어진다. 그래서 그 둘이 PASS 가 되기 전까지
**`PCU CANARY BLOCKED` 를 유지하고 전체 학생 공개를 하지 않는다**(§60).

## G. 하지 않은 것과 그 까닭

- **운영 배포본을 밖에서 열지 못했다.** 네트워크 정책이
  `app.careermatri.com:443` 을 막는다(HTTP 000). 그래서 이 회차의 모든
  판정은 이 기계에서 운영과 같은 배치로 띄워 돌린 것이고, **운영 PASS 로
  적지 않는다**
- **학생 공개 상태를 바꾸지 않았다.** `open_to_students` 가 그대로이고,
  미리보기는 `V3_PREVIEW_OPEN` 을 들고 띄운 서버만 열며 운영에서는 어떤
  값으로도 열리지 않는다
- **학교 학생이 쿠키 없이 `/v3/start` 를 직접 치면 개인 응시가 열린다.**
  등록된 학생에게는 개인 시작 단추가 서지 않지만, 폼을 직접 보내는 길은
  남아 있다. 이것을 늘 학교 응시로 적을지는 **집계와 등급이 함께 바뀌는
  결정**이라 사업주 확인을 받는다(P1, 전 회차부터 적어 둔 자리)
