# R19. BIZ 결과지를 Personal Career Operating System 의 입구로

받은 지시 두 묶음을 한 회차로 돌렸다. 앞 묶음은 `REPORT → PRODUCT`,
뒤 묶음은 **Workspace reference 를 시각 참고가 아니라 PRODUCT SYSTEM
REFERENCE 로 읽으라**는 것이다. 뒤 묶음의 마지막 줄이 앞 묶음을 덮으므로
이 회차의 기준은 뒤 묶음이다.

**BIZ 하나만 다뤘다.** NURSING · PUBADM · 115개 학과로 넓히지 않았고,
읽는 층이 Core 를 모르게 짜여 있어 같은 틀이 스무 Core 에 그대로 서지만
**콘텐츠를 더 쓰거나 Core 쪽 자료를 고치지 않았다.**

---

## A. 무엇을 건드리지 않았는가 (FROZEN LOGIC · 앞 묶음 §19)

measurement · scoring · item bank · assessment question · answer meaning ·
Core/Domain mapping · result/evidence/gap decision · registry ·
DB schema · `student_open` · `open_to_students` 를 **한 줄도 건드리지
않았다.** `npm run v3:freeze:measure` 가 **기록을 다시 적지 않은 채로**
통과한다(확인 14가지 · 걸림 0).

바뀐 것은 presentation / interaction / result information architecture 와
**읽는 함수 하나의 인자**뿐이다.

---

## B. 받은 reference 를 무엇으로 읽었는가

Result 쪽 reference 이미지는 이 세션에 도착하지 않았다. 저장소에 있는
것은 **Workspace Home 시안** 하나다
(`docs/metri/shots/reference/reference-home-desktop.png`). 그 그림이
뒤 묶음 §1 이 적은 것과 글자까지 맞는다: 왼쪽 띠 · 지금 할 일 · 현재
상태 · 최근 변화 · 최근 기록 · 눌러서 가는 자리 · 상태와 행동이 한
화면에.

그래서 이 회차는 **그 그림의 product system 을 결과지로 옮겼다**:
색과 둥글기를 베끼지 않았고(결과지는 제 팔레트를 그대로 쓴다) 가져온
것은 **한 화면에 무엇이 어떤 차례로 서는가**다.

**Result 쪽 reference 이미지는 받지 못했으므로 `Reference Match PASS`
를 적지 않는다.**

## E. 가짜 수를 만들지 않았다 (뒤 묶음 §5·§6·§10)

센 수 셋은 전부 결과 모델이 이미 들고 있는 목록의 길이다.

| 화면에 적는 말 | 어디서 오는가 |
|---|---|
| 손에 남은 것 N | `focus` 영역들의 `artifacts` 합집합 길이 |
| 설명할 영역 N | `overview.focus` 의 길이 |
| 채울 자리 N | `model.gaps` 의 길이 |
| 타일의 `확인된 판단 N · 남긴 것 N` | 그 영역의 `confirmed` · `artifacts` 길이 |
| 이미 담아 둔 할 일 N개 | `openActions()` 가 돌려준 **표에 담긴** 줄 수 |
| 경험 N개 모두 보기 | `experiencesOf()` 가 돌려준 줄 수 |

**점수 · 퍼센트 · 적합도 · 순위 · 완료율이 0건이다.** 담아 둔 줄이
없으면 `0` 을 적지 않고 그 줄을 세우지 않는다: 0 을 적으면 담지 않은
사람에게 담았다고 말하는 꼴이 된다.

**없는 backend 를 가짜로 세우지 않았다.** 최근 변화(recompute diff)는
결과지에서 읽지 않는다: 그 값은 `career_profiles` 에 반영된 뒤에만
뜻이 있고, 결과를 막 받은 사람에게는 늘 비어 있다. 그 자리는
`/me` 와 `/me/state` 가 든다.

### 왜 15 를 FAIL 로 적는가

작업공간에는 손전화 아래 띠가 있는데 **결과지에는 없다.** 그래서
결과지를 보던 사람은 다음 자리로 가려면 끝까지 내려가거나 머리의
`내 CareerMatri` 를 눌러야 한다. 뒤 묶음 §1 이 적은 `명확한
navigation` 이 결과지에서 반만 서 있다. 고치는 일은 결과지에 작업공간
띠를 들이는 것이라 **두 동결(결과지 · 작업공간)을 함께 건드린다.**
사업주 판단을 받고 다음 회차에 한다.

### 왜 16 을 FAIL 로 적는가

손전화 전체가 창의 6.7배다. 접은 자리를 더 늘리면 학생이 자기 근거를
못 보고 닫는다(그 자리는 전에 한 번 겪었다). 줄이는 길은 **부록 넷을
한 자리로 묶는 것**인데 그것은 읽는 차례를 다시 짜는 일이라 이 회차의
범위를 넘는다.

**붙어 있는 머리띠가 한 자리를 뜨는 그림을 가린다.** `#plan` 을 한
자리로 뜨니 `position: fixed` 인 머리띠가 그 자리의 맨 윗줄 위에 얹혀
찍혔고, **적는 차례의 번호 넷이 통째로 가려졌다.** 그 그림을 보고
`번호가 서지 않는다` 로 읽어 CSS 를 두 번 들여다봤다. 뜨는 쪽이 그
띠를 잠시 감춘다.

**격자에 자리를 못 박지 않으면 꺾쇠가 맨 왼쪽으로 간다.** 영역 타일의
네 조각을 자동 배치로 두었더니 꺾쇠가 빈 칸을 찾아 1열로 가고 이름이
오른쪽으로 밀렸다. 찍어 놓고 읽어서 알았다.

**한글에 자간을 벌리지 않는다**(두 번째). `현 재  상 태` 와
`지 금  할  일` 이 그 자리다.
