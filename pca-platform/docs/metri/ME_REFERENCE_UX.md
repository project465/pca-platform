# 기계공학을 기준 UX 로 마감했다 (2026-10-12)

다른 전공으로 넓히기 전에 **기계공학 하나를 다른 Major Core 가 베껴 쓸 수
있는 상태**로 닫았다. 새 기능을 만들지 않았고, 고친 것은 받은 일곱 자리뿐이다.

**측정은 `ME_V3_MEASUREMENT_FREEZE_1` 에 그대로 머문다.** 채점 · 문항 은행 ·
ResultModel · Evidence 판정 · 현재 상태 계산 · Industry/Role 관계 자료 · DB
스키마 · 가격 · 이용권 · Multi-Core runtime 을 한 줄도 건드리지 않았고,
`npm run v3:freeze:measure` 가 **기록을 다시 적지 않은 채로** 통과한다.

## 1. 경험 빈도. 화면 말만 공통으로 잠갔다

`없다 · 한두 번 · 여러 번` 이 `없음 · 1~2회 · 3회 이상` 이 됐다. 전공이
늘어도 이 세 낱말은 그대로다: 전공마다 빈도 척도를 따로 만들면 같은 `1` 이
전공에 따라 다른 뜻이 되고, 그러면 두 전공을 같은 자 위에 놓을 수 없다.

**문항 은행을 고치지 않았다.** 여기서 한 번 갈렸다. 화면이 적는 말을 은행의
`options` 에서 고치면 §1(표시 통일)은 되지만 §8(Item Bank 변경 금지)이
깨진다. 그래서 어느 쪽이 실제로 화면에 서는지를 먼저 봤다: 격자의 경험 칸은
`response_scale: "3보기"` 로 들어와 `menus.ts` 의 `shortOf`/`fullOf` 를
거치고, 그 둘이 은행의 낱말을 그대로 돌려주고 있었다. 돌려주는 자리를
`EXPOSURE` 표로 바꿨다. `FULL_SCALE5` 가 다섯 칸 척도에 이미 하고 있는
일을 세 칸에 똑같이 한다. **자리는 `option_values` 가 정한다**: 낱말을
차례로 늘어놓으면 은행의 보기 차례가 바뀌는 날 뜻이 어긋난다.

그래서 `ME_V3_ITEM_BANK_V2.5` 와 `bank-lock.json` 과 저장된 응답(`0 · 1 ·
2`)의 뜻이 그대로다. `npm run v3:scale` 12가지와 측정 동결 14가지가 통과한다.

## 2. 경험 날짜. `[연도] [월]` 과 `아직 진행 중`

브라우저 기본 달 고르기(`input type="month"`)를 걷었다. 그 창은 기기와
브라우저마다 다르게 뜨고(크로뮴은 달력, 사파리는 바퀴, 안드로이드는 전체
화면) CareerMatri 의 활자도 색도 쓰지 않는다. 한 화면 안에서 그 칸만 다른
제품으로 보이고, **그 어긋남은 누를 때만** 드러난다.

- 받는 것은 `연도` 와 `월` 고르기 둘이다(`MonthPick`, `me/ui.tsx`)
- **날은 받지 않는다.** 전과 같다: 경험이 몇 월이었는지까지만 쓴다
- 끝난 달 자리에 `아직 진행 중` 이 선다. 고르면 그 칸을 치운다
- **DB 스키마도 전에 적어 둔 기록도 한 줄도 바뀌지 않았다.** `monthOf()`
  가 `연도-월` 로 합치고 `asDate()` 가 `YYYY-MM-01` 로 넣는다. `아직 진행
  중` 은 `ended_on` 을 비우는데, 비어 있는 것이 전부터 `아직 안 끝났다` 를
  뜻했다(`ended_on IS NULL`). **칸을 하나 더 만들지 않았다**
- 한쪽만 고른 값은 받지 않는다. 연도만 고르고 월을 비운 것을 `2025-01` 로
  메우면 그 사람이 고르지 않은 달이 기록에 남는다

## 3. 현재 상태의 `0개`

설명할 수 있는 영역이 0개인데 아래 `최근 달라진 것` 에는 올라간 축이 적혀
있는 날, 두 칸이 서로 어긋난 말을 하는 것으로 읽힌다. 축이 올라간 것과
영역이 설명할 수 있는 상태로 선 것은 다른 일이라, 그 사이를 한 줄로 잇는다.

> 변화는 생겼지만 아직 설명할 수 있는 기준까지는 올라오지 않았습니다.

**판정 기준은 그대로다.** 세는 값도 묶음 조건도 한 줄도 바뀌지 않았고, 바뀐
것은 그 0 을 어떻게 적는가뿐이다. 최근 변화가 없는 사람에게는 전과 같은
문장이 선다.

## 4. 산업과 직무

- 위에 서는 둘셋은 **고른 것이 먼저**다. 그 사람이 응시에서 직접 고른
  산업과 직무는 다시 찾아보려고 들어오는 자리다. 그다음이 `relations` 의
  `중심` 으로 걸린 확인된 영역이 있는 쪽이고, 나머지는 줄로 눕는다
- **새 점수도 순위도 만들지 않았다.** 묶는 기준이 둘(고름 · 중심 겹침)이고
  묶음 안에서는 사전의 차례 그대로다
- `고르셨습니다` 딱지를 걷었다. 고른 것이 셋이면 그 말이 셋 서고, 읽는
  사람은 자기가 고른 것을 이미 안다. 고른 상태는 **칸 자체**가 든다: 테와
  면이 갈리고 이름 옆에 표시가 하나 선다. **색으로만 말하지 않는다**:
  읽어 주는 자리에는 `고른 산업` 이 글자로 간다
- 찍어 보고 둘을 더 고쳤다. 위에 서는 것이 하나면 세 칸 격자에 **큰 빈
  면**이 남아서 칸 수를 담긴 수에 맞췄고, 목록 머리의 `여덟` 이 일곱 줄
  위에 서 있어서 실제 줄 수를 적는다

## 5. 지역과 기관

기관 유형 일곱은 **어느 지역에서나 같은 일반론**인데 큰 카드 일곱으로 세 칸
격자에 서 있었다. 위의 `이 지역에서 함께 볼 곳` 이 비어 있는 날 이쪽이 이
쪽의 본문처럼 읽힌다. 머리글을 `기관 유형별 일의 방식` 으로 한 단 내리고
`참고` 선 아래 줄로 눕혔다.

**지우지 않았다.** 확인된 기관 자료가 들어오면 위 묶음이 그대로 메인으로
올라서고 이쪽은 보조로 남는다. 그때 고칠 것이 없다.

## 6. 결과 첫 줄

`아직 판단할 재료가 모이지 않았습니다` 로 열면, 결과지를 연 사람이 처음
읽는 줄이 자기가 모자란다는 말이고 그 아래 할 일까지 그 틀에서 읽힌다.

> 지금은 먼저 해볼 영역부터 확인할 수 있습니다.
> 현재 응답에서는 영역 사이의 차이가 아직 크지 않습니다. 어디부터 한 번 해
> 보면 되는지를 아래에 적었습니다.

**좋게 꾸미지도 않았다**: 적합도도 강점도 말하지 않고, 지금 이 응답으로 할
수 있는 말만 적는다. `npm run v3:j3` 의 사람 열두 벌에서 달라진 칸이 **P01
의 머리글 한 자리뿐**이고(Core 지문 · 응답 품질 · 첫 걸음 · 빈자리와 할 일
수는 열두 벌 모두 글자까지 같다), 그 기준선을 그 사실과 함께 다시 적었다.

## 7. 종이 첫 두 쪽

담긴 것을 한 줄도 덜어내지 않았다. 바꾼 것은 같은 네 칸을 어떤 크기와 어떤
면으로 세우는가다.

- 머리글이 한 단 크다(19pt → 20.5pt)
- 네 칸 가운데 `지금 확인된 것` 과 `먼저 해볼 것` 만 면이 한 단 짙다.
  나머지 둘은 흰 면에 남아 **무엇을 먼저 읽는지가 면의 짙기로** 읽힌다
- 칸 머리에 색 표시가 하나 선다. **뜻을 갖지 않는다**: 넷을 한 덩이로 읽지
  않게 갈라 주는 자리이고, 무엇의 칸인지는 그 옆 글자가 든다
- 절 머리 위에 금이 하나 그어진다. 여백은 금 위아래로 나눠 가진다

**화면은 그대로다.** 화면에서 색을 더 쓰지 않기로 한 것은 강조색이 누르는
자리와 겨루기 때문이고 종이에는 누를 자리가 없다. 그래서 색조는
`@media print` 블록 안에만 있다.

**쪽수에서 하나를 배웠다.** 네 칸 묶음에 `break-inside: avoid` 를 걸었더니
그 묶음이 첫 쪽에 다 안 들어가는 날 통째로 다음 쪽으로 밀렸다. 쪼개지면
뜻이 사라지는 것은 칸 하나지 네 칸 전체가 아니다.

**STANDARD 의 쪽수 범위를 9~10 으로 옮겼다.** 이번 회차가 늘린 쪽이 아니다:
726c7cf 를 그대로 뽑아 재어 열 쪽이고 **쪽별 글자 수가 글자까지 같다**
(551/571/597/662/536/547/540/553/306/268). 앞 회차에서 산업·직무 절과 지역
절이 더해진 뒤로 열 쪽이었는데 범위만 아홉에 남아 있었다. 마지막 두 쪽도
비어 있지 않다(빈 쪽 선은 120 · 40자). **본문을 깎아 옛 범위에 맞추지
않았다.**

## 검사

```bash
npm run v3:scale            # 저장값과 판정이 그대로인가 12가지
npm run v3:freeze:measure   # 측정 동결 14가지 (다시 적지 않은 채로 통과)
npm run v3:j3               # 사람 열두 벌 · 달라진 칸이 머리글 하나뿐
npm run v3:gate             # 달까지만 받는 고르기 둘 · `아직 진행 중`
npm run v3:product-loop     # 제품 루프 51가지
npm run v3:result:pdf       # 종이 3벌
npm run major:kit           # Kit 이 적어 둔 구조가 실제와 같은가 6가지
```

검사 자신도 세 자리 고쳤다. 폼을 채우는 공통 바탕(`_loop-fixture.ts`)과
`v3:gate` 가 **없어진 `input[name="started_on"]`** 을 찾고 있었고,
`major:kit` 이 빈도 라벨을 문항 은행에서 읽고 있었다(화면에 서는 말은
`menus.ts` 가 든다). `routes:check` 의 표에는 앞 회차에 더한 `/intro` 와
`/done` 두 줄이 빠져 있었다.

  띄워 돌린 것이다

  둔다**

- DB 스키마를 한 줄도 바꾸지 않았으므로 마이그레이션은 필요 없고, 고친 것이
  전부 이미지 안으로 들어가는 파일이라 **재배포가 먼저다**
