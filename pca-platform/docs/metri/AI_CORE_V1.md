# AI_CORE_V1 — 인공지능 (2026-11-02 · 초안)

사업주가 1순위로 부른 자리다(`전주대는 인공지능학과를 최우선으로 진행해`). 지금
전주대 인공지능학과(`JJU26_AI`)는 `CS_CORE_V1` 에 갈래 `SPEC_CS_AI` 를 얹어 잰다.
그 갈래가 바꾸는 것은 **설명하는 차례**뿐이라, 인공지능학과 학생이 컴퓨터공학과
학생과 같은 열한 영역을 차례만 바꿔 읽는다. 이 Core 는 그 자리에 쓸 **인공지능
전용 영역 사전의 초안**이고 **어느 학과 자리에도 붙이지 않았다**: 붙일지와 어디에
붙일지는 사업주가 정한다.

```
영역 12 · 문항 369 (Core 233 · 팩 136) · 산업팩 8 · 역할팩 8 · 갈래 4
학교 자리 0 (open_to_students: false · FOUNDATION)
```

`src/` 아래에서 바뀐 파일은 셋이고 셋 다 Core 를 열쇠로 둔 자료 표에 **줄을
더하기만 했다**(`result/chains.ts` · `student/copy.ts` · `student/common.ts` · 판정
로직 0줄). 채점과 결과 판정과 측정 엔진과 DB 스키마가 한 줄도 바뀌지 않았고 앞
스무 Core 의 은행 지문이 그대로다.

## 왜 CS 의 갈래가 아니라 Core 인가

갈래로 묶는 기준은 이름이 비슷한가가 아니라 **같은 영역 사전을 읽는가**다
(`core-registry.ts` 의 `specializations` 설명). 컴퓨터 Core 에서 인공지능은 열한
영역 가운데 하나(`TD09 기계학습·데이터 분석`)이고, 그 한 칸에 라벨링 기준과 분할과
모델 선택과 평가와 배포와 경량화와 윤리가 **함께 뭉친다.** 그래서 인공지능학과
학생은 직접 정한 판단이 여럿이어도 한 영역의 근거로만 세어지고, 서버·API 와
네트워크와 그래픽스 칸이 그 학생의 빈칸으로 남는다. 이 Core 는 그 한 칸을 열둘로
편다.

## 무엇을 재고 무엇을 재지 않는가

**코딩 솜씨와 모델 점수의 높이를 재지 않는다.** 묻는 것은 `딥러닝을 좋아한다` 나
`정확도 95% 를 냈다` 가 아니라 **무엇을 맞힐지와 무엇으로 잴지와 무엇을 버릴지를
누가 정했고 그것이 어디까지 갔는가**다. **써 본 도구와 모델 이름도 묻지 않는다**:
이름은 해마다 바뀌고 이름을 아는 것이 판단을 한 것이 아니다. 수학·통계 영역도
푼 문제의 수를 묻지 않고 **결과를 믿어도 되는지 가정을 확인하고 판정한 경험**을
묻는다. 짝 표가 선호 문항에 소유 사다리를 붙이는 길을 막고, 문항마다 primary
construct 를 적어 두었다(`ai-v1-constructs.json`).

**시험팀이 낸 열두 후보를 그대로 받았고 이름만 줄였다.** 긴 이름(`피지컬 AI(로봇·
센서·임베디드)` · `데이터 수집·라벨링 기준`)이 결과 책자의 사분면 그림과 90일
달력에서 잘려 `피지컬 AI…` 로 섰다. 뜻은 `subareas` 와 영역 설명이 든다.

**수집·라벨링과 정제·분할을 나눈 까닭**은 앞엣것이 무엇을 모으고 어떤 정답을 달지
정하는 일이고 뒤엣것이 모은 것을 고치고 나누는 일이어서다. **모델 선택과 평가도
나눴다**: 앞엣것은 점수를 올릴 모델을 고르고 뒤엣것은 그 점수를 믿을 수 있는지
판정한다. **배포와 경량화도 나눴다** — 앞엣것은 올리는 길을, 뒤엣것은 모델 자체를
줄이는 일을 가른다.

**필수 축을 영역의 성질에서 골랐다.** 라벨링 기준과 정제·분할과 자연어·생성과
비전과 배포는 산출물이 걸린다 — 안내서와 분할 명세와 지시문 판본과 설정 파일이
남아야 다음 사람이 같은 자료와 같은 모델을 다시 만든다. 문제 정의와 모델 선택과
평가와 경량화와 윤리·안전은 비교·검증이 걸린다: 고른 지표와 모델과 줄인 모델과 쓴
자료는 **실제 목표나 기준 모델이나 원래 모델이나 법과 지침에 대어 보기 전까지
근거가 아니다.** 피지컬 AI 와 통계 근거는 실패·수정이 걸린다 — 실물과 표본은
처음에 어긋나는 것이 흔하고 까닭을 좁히는 것이 그 일이다. 필수 축의 분포는 앞 Core
들과 같은 모양(J1 셋 · J5 여섯 · J6 여섯 · J3 셋 · J2 둘 · J4 둘 · J7 둘)이라 사람
열두 벌의 판정 자리가 그대로 선다.

## 산업팩 여덟 · 역할팩 여덟

산업: 제조 AI·스마트팩토리 · 의료 AI · 금융 AI · 플랫폼·추천 · 모빌리티·자율주행 ·
공공·행정 AI · 콘텐츠·생성 AI · 로봇·피지컬 AI. **`IT` 를 산업으로 두지 않는다**:
같은 분류 모델을 놓고 제조와 의료와 금융이 서로 다른 판단을 묻는다.

역할: ML 엔지니어(RF1) · 데이터 사이언티스트(RF2) · AI 평가·검증(RF3) · MLOps
엔지니어(RF4) · 데이터 라벨링 PM(RF5) · AI 서비스 기획(RF6) · AI 연구원(RF7) · AI
안전·책임(RF8). 역할팩은 역할기능 여덟과 하나씩 맞물려야 해서(`v3:wording`)
**비전 엔지니어와 NLP·LLM 엔지니어는 역할팩으로 두지 않았다**: 둘은 같은 `모델
개발` 기능을 다른 영역에서 하는 이름이라 직무 별칭(`ai-v1-taxonomy.json`)과 갈래가
든다. 직무 안내(`data/report-gm/role-guide/AI_CORE_V1.json`)도 함께 썼다.

## 별칭

`인공지능학과` 와 `데이터사이언스학과` 는 넣지 않았다: 지금 `CS_CORE_V1` 의 별칭이고
**한 학과 이름은 한 Core 만 맡는다**(`v3:majors`). 옮길지는 사업주가 정한다.

## 학교 자리를 붙이지 않은 것과 그 값

`core:walk` 는 배재대(PCU) 등록부에서 그 Core 를 가리키는 자리를 하나 골라 학생처럼
밟는다. 이 Core 를 가리키는 자리가 없으므로 그 검사는 `AI_CORE_V1 를 가리키는 학교
자리가 없습니다` 로 선다. **자리를 만들려고 학과를 옮기지 않았다.** 붙일 수 있는
자리: 전주대 인공지능학과(`JJU26_AI`) · 첨단산업인재양성부트캠프 AI(피지컬 AI) ·
고려대 데이터계산과학 · 고려대 빅데이터사이언스 · 배재대 2027 인공지능전공.

## 동결 기록을 다시 적은 자리

학생 말 사전(`student/copy.ts` · `student/common.ts`)과 작성 차례(`result/chains.ts`)가
결과지·작업공간 동결의 파일 목록에 들어 있다. 새 Core 의 줄을 더하면 그 지문이
바뀌므로 `RESULT_FREEZE=update` · `WORKSPACE_FREEZE=update` · `CORE_UI_FREEZE=write`
로 다시 적었다. **판본은 올리지 않았다**: 바뀐 것은 닫힌 Core 의 줄뿐이고 앞 스무
Core 의 학생이 읽는 글자는 그대로다. 산업·직무·조직 카드의 짧은 설명(`tier-text.ts`)
은 검사 화면 동결에 걸려 있어 **쓰지 않았다** — 카드는 팩의 첫 줄과 조직의
`differs` 로 선다.

## 확인한 것

```bash
CORE=AI_CORE_V1 npm run core:all     # core:walk 앞까지(아래 표)
CORE=AI_CORE_V1 npm run core:qa      # 검토표 셋
CORE=AI_CORE_V1 npm run core:review  # 전공자 검토 묶음
```

## 아직 아닌 것

학생에게 열지 않았다(`open_to_students: false` · `FOUNDATION`). 전공자 검토와 인지
면접과 실제 응답 기반 신뢰도·타당도 검증을 하지 않았으므로 `검증된 검사` 로 팔지
않는다. 용어 받침 표(`me-v3-terms.json`)는 검사 화면 동결에 걸려 있어 이 Core 의
말(증강 · 양자화 · 미세조정)을 아직 적지 않았다 — 문항이 `같은` 과 예시로 받친다.
