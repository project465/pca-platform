# PCU PRODUCT COMPLETION PASS — 배재대 운영 기능 마감

받은 기준은 `예쁜 데모` 가 아니라 **배재대학교가 학생 수백 명에게 배포하고,
학교 담당자가 개발자 도움 없이 운영할 수 있는 상용 CareerMatri Campus
제품**이었다. 이 회차가 한 것은 그 운영 기능을 메우는 일이고, **측정은 한
눈금도 건드리지 않았다.**

---

## 0. 가장 먼저 — 바꾸지 않은 것

`ME_V3_MEASUREMENT_FREEZE_1` 이 **기록을 다시 적지 않은 채로** 통과한다.
scoring · threshold · item id · item count · item wording · Core 구조 ·
Domain 정의 · Result 판정 · Evidence 판정 · Gap 판정 · routing engine ·
PCU registry 구조 · `student_open` · `open_to_students` · 기존 assessment
logic 의 diff 가 0 이다.

**DB 스키마를 한 줄도 바꾸지 않았다.** 재응시도 계정 상태도 감사 기록도
이미 있는 칸으로 들어간다(`entitlements` 한 줄 · `users.status` ·
`audit_logs.action`). 그래서 마이그레이션이 필요 없고, 바뀐 것이 전부
이미지 안으로 들어가는 파일이라 **재배포가 먼저다.**

**한 자리만 적어 둔다.** `openAttempt()` 가 **개인 회원이 고른 Core 를 받는
칸**을 하나 더 든다(아래 3절). 바뀐 것은 `어느 전공의 자로 재는가를 고른
사람이 정한다` 는 것뿐이고, 문항 routing 과 채점과 판정은 그대로다: 같은
응답이면 같은 결과이고 측정 동결이 기록을 다시 적지 않은 채로 통과한다.
학교 진입은 전과 같이 **쿠키의 학과를 명단에 맞춘 값**이 정하고 늘 먼저다.

## 2. 세 Journey

### A. 학생 (§33 Student journey)

`/campus/pcu` → 학과 선택 → 학교 로그인 → 시작 안내 → 응시 → 중간 저장과
이어하기 → **제출 전 검토** → 제출 → 완료 → 결과 → 종이 → `/me` → 경험
추가 → **경험 고치기** → 현재 상태 → 다음 할 일.

`npm run v3:product-loop` **63 / 63**, `npm run v3:launch` 가 폭 셋에서
같은 길을 밟는다.

### B. 대학 담당자 (§33 Operator journey)

로그인 → 집계 → **좁혀 보기(기간·단과대학·학과)** → 학생 명단 → CSV 일괄
등록 → 비밀번호 재발급 → 미응시 목록 → **리마인드 대상 CSV** → 학과별 집계
CSV → **운영 요약 PDF**.

`npm run campus:export` **49 / 49**(실제 브라우저 · 실제 파일).

### C. CareerMatri 운영자

`/admin/incidents` 를 그대로 쓴다. **새 monitoring platform 을 만들지
않았다**: 운영 요약 PDF 가 못 뽑힌 자리는 `job_failures` 에
`org-pdf-<걸음>-<학교>` 로 적히고 그 표가 이미 그 쪽에 선다.

## 3. 이 회차가 찾아낸 것

**`return page.pdf(...)` 가 종이를 못 뽑게 하고 있었다.** 기다리지 않고
돌려주면 `finally` 가 그리는 동안 브라우저를 닫고, 크로뮴이
`Printing failed` 로 거절한다. 밖에서 보면 **브라우저가 못 뜬 것과
구별되지 않는다.**

**담당자 화면이 두 모집단을 나란히 세우고 있었다.** 집계는 시연·검사
계정을 거르는데(`campusV3`) 명단 쪽만 그 줄을 빠뜨려서, 같은 화면에
`대상자 0명` 과 `아직 시작하지 않은 학생 63명` 이 함께 섰다.

**집계 화면의 링크가 명단 화면에서 좁혀지지 않았다.** 저쪽이 `department`
를 달고 오는데 이쪽이 `dept` 로만 읽어서, 눌러 넘어온 담당자가 전체 목록을
그 학과의 수로 읽는다.

**`.sf-btn is-primary` 는 어느 CSS 에도 규칙이 없는 이름이었다.** 쓰는
이름이 CSS 에 없는 자리가 이 저장소에서 열한 번째다.

**빈 표를 까닭 없이 내보내고 있었다.** 좁혀 본 범위에 든 학생이 다섯이 안
되면 집계가 아래 칸을 아예 만들지 않는데, 표만 비워서 보내면 받은 담당자가
내려받기가 깨진 줄로 읽고 다시 누른다.

**전공을 고르지 않은 학생에게 계정 쪽이 500 이었다**(§4 · §21). `/my` 가
지금 상태를 읽으려고 `currentState()` 를 부르고, 그 함수는 Core 를 모르면
던진다. 전공이 **하나만** 열려 있던 동안에는 그 수가 곧 답이라 가려져
있었는데, 운영 Canary 로 경영학을 열어 **열린 전공이 둘**이 된 날부터 학교가
나눠 준 계정으로 처음 들어온 학생이 `계정` 을 누르면 그 화면을 받았다.
거기서 Core 로 읽는 것은 `지금 검사의 결과가 있는가` 한 줄뿐이고 **그 답은
전공을 고르지 않은 사람에게 늘 `없다`** 다. 묻기만 하는 자리
(`coreIfAny()`)를 두어 모르면 묻지 않는다. **고르는 자리로 보내지도
않는다**: 계정은 비밀번호와 로그아웃을 찾으러 들어오는 자리라, 거기서 전공
목록으로 튕기면 나가는 길이 사라진다.

**전공 목록에서 고른 전공이 응시에 적히지 않았다**(§20). `/cores` 의 카드가
전부 같은 `/v3/start` 를 가리키고, 그 쪽과 `openAttempt()` 는 **고른 값을
받을 칸이 없어** `sellableCores[0]` 과 `defaultCore()` 를 썼다. 전공이 하나
열려 있던 동안에는 그 값이 곧 고른 전공이었지만, 둘이 열린 날부터는 **경영학
카드를 누른 사람의 응시가 기계공학으로 열렸다.** 고른 것과 다른 자로 재는
것이라 결과를 되돌릴 수 없다. 카드가 `?core=` 로 들고 가고 폼이 한 칸으로
넘기며 **믿는 자리는 `openAttempt()` 하나다**: 그 시장에서 응시할 수 있는
Core 가 아니면 버리고, **학교 맥락이 늘 먼저다**(쿠키의 학과를 명단에 맞춘
값이라 학생이 고친 칸으로 덮이지 않는다). `campus:walk` 이 폼에 다른 전공을
꽂아 보고 그 성질을 센다.

**학교가 발급한 계정이 개인 회원의 길로 검사를 시작할 수 있었다.** 전공
목록의 `검사 시작` 은 개인 회원의 길이고, 그 길로 열린 응시에는 학교와
학과가 적히지 않으며 등급도 학교 계약이 정한 것이 아니다. 그러면 **담당자
화면이 그 학생을 세지 못하고** 그 결과가 같은 학과의 나머지와 한 표에서
읽히지 않는다. 가입 쪽에서 이미 막아 둔 것과 같은 자리다(`startFromCampus`
가 개인 가입으로 보내지 않는 까닭). 지금은 등록된 학생에게 **학교가 적어 준
학과로 가는 길 하나**가 서고 개인 회원의 시작 단추는 서지 않는다. **여기서
짐작해 적지 않는다**: 응시에 학교를 적는 자리는 전과 같이 `openAttempt()`
하나이고, 그 자리가 보는 것도 전과 같이 **명단이 적어 준 줄**이다.

**재분석의 줄 닫기 실패가 조용했다**(§4). `finish()` 를
`.catch(() => undefined)` 로 싸 두어, 닫기가 실패하면 그 줄이 `running`
으로 남아 화면이 `돌고 있습니다` 로 서는데 **까닭이 어디에도 없었다.**
`errors:check` 가 그 자리를 MUST FAIL 구역으로 적어 두고 세고 있었다.
줄 하나를 남긴다(`opFail`). **던지지 않는다**: 5분이 지나면 `claim()` 이
그 줄을 다시 집어 저절로 풀리고, 던지면 다시 셀 일 하나가 사람의 화면을
오류로 만든다. **돌려주는 것은 전과 같이 `failed` 이고 굳은 결과는 어차피
바뀌지 않는다.**

**새 쪽을 route 소유 표에 적지 않고 있었다.** 이 회차에 만든 경험 고치기
(`/me/experience/[id]/edit`)가 `ROUTE_TABLE` 에 없어서 `routes:check` 가
걸렸다. 그 검사가 그렇게 서 있는 까닭은 **표를 고치기 전까지 걸리게** 하려는
것이다: 쪽을 하나 더해 놓고 표를 안 고치면, 신규 사용자가 옛 검사로 갈
길이 생겼는지 아무도 세지 않는다.

**검사(`v3:gate`)가 열린 전공 수를 보지 않아 거짓 경보를 냈다.** 전공을 아직
고르지 않은 학생이 로그인해서 가는 자리는 그 수가 정한다: 하나면 작업공간 첫
화면이고, 둘 이상이면 고르는 자리(`/cores`)이며 **둘 다 작업공간 안이고 둘 다
맞는 상태다.** 그런데 그 검사는 `/me` 하나만 요구해서, 경영학을 연 날부터
멀쩡한 배포본을 걸었다. **느슨하게 하지 않았다**: 띄운 쪽이
`var/.serving-preview` 에 적어 둔 값으로 열린 전공 수를 세어 **어느 쪽을
요구할지 못 박고**, 그 뒤에 제품의 길로 전공을 골라(`/cores` → 검사 시작)
**고른 뒤에는 늘 `/me` 인 것**과 **고른 전공이 그 응시 줄에 적히는 것**을
따로 센다. 고르는 카드는 **기본 전공이 아닌 자리**를 누른다: 첫 카드는
`defaultCore()` 와 같아서 고른 값을 들고 가지 않아도 열리고, 그러면 그 줄이
아무것도 세지 않는다. 확인 열여섯에서 **스물다섯**이 됐다.

## 4. 개인정보와 권한 (§18·§19·§23)

- **개별 학생 답변 raw export 가 없다.** 명단 CSV 의 칸은 일곱이고 문항
  번호도 응답 값도 결과 묶음 코드도 들어 있지 않다. 검사가 그 모양을
  **받은 글자에서** 센다
- **5명 미만 칸은 수가 만들어지지 않는다.** 가리는 자리를 CSV 와 PDF 에
  따로 두지 않고 집계 함수가 `null` 로 돌려준 것을 그대로 적는다
- **담당자가 학생 결과를 열 수 없다.** 담당자 계정으로 결과 쪽과 종이를
  두드려 404 를 확인했고, 명단 화면에 답한 내용이 서지 않는 것도 함께 센다
- **비밀번호 평문을 저장하지 않는다.** 재발급은 그 자리에서 한 번만 보여
  주고 해시만 남으며 감사에 적힌다
- **메일·문자 발송 기능을 만들지 않았다**(§17). 없는 기능을 단추로 두면
  누른 담당자가 보낸 줄로 읽고 학생은 아무것도 받지 않는다. 받는 학생
  명단을 CSV 로 내려받는다

## 7. 아직 아닌 것

- **운영 배포본을 밖에서 한 번도 열지 못했다.** 네트워크 정책이
  `app.careermatri.com:443` 을 막는다(HTTP 000). 그래서 이 회차의 판정은
  `LOCAL PASS / PRODUCTION UNVERIFIED` 이고 **`COMMERCIAL READY` 라고
  적지 않는다**
- **학생 공개 상태를 바꾸지 않았다**(`open_to_students` 그대로). 운영
  Canary 는 별개라 `PCU CANARY BLOCKED` 가 그대로다
- 경험에 **파일 업로드를 더하지 않았다**(§9). 기존 storage 구조가 없고,
  이번 P0 에서 억지로 더하지 않는다
- **쿠키 없이 들어온 학교 학생의 응시에 학교를 적지 않는다.** 지금 정책은
  `학교 쪽 문으로 들어온 응시만 학교 응시` 이고 `campus:walk` 이 그것을
  센다(`일반 응시는 학교 칸이 비어 있다`). 이 회차는 그 정책을 바꾸지 않고
  **그 길로 들어가지 않게** 전공 목록에서 학교 쪽 문으로 보냈다. 등록된
  학생의 응시를 **쿠키와 무관하게** 늘 학교 응시로 적을지는 집계와 등급이
  함께 바뀌는 정책 결정이라 **사업주 확인을 받는다**
- 자율전공 학생의 **고른 전공을 기억해 두지 않는다.** 고를 때마다 그
  전공으로 시작하고, 기억해 두는 칸을 만드는 일은 DB 변경이라 따로
  승인받는다
- iPhone Safari 실기기 확인이 남아 있다
