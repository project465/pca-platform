# ME_V2 결정 검사

규격 `ME-V4.0` 이 준 새 검사다. **옛 검사를 덮지 않고 나란히 둔다.**

```
ME_V1              120문항 · 지금 돌고 있는 검사. 손대지 않았다
ME_V2_DECISION_2026  92문항 · 새 검사. BASIC 48 · STANDARD 68 · PRO 92
```

전에 응시한 사람의 점수는 그대로다. 저장 키도 전역 이름도 따로다.

---

## 1. 문항은 규격이 준 그대로다

Q1~Q92 전부 규격 본문에 적혀 있던 문장을 **한 글자도 고치지 않고** 옮겼다.
붙인 것은 구성개념·척도·직무군 가중치뿐이다. 그래서 `copy:audit` 에 넣지
않았다. 문체 규칙으로 문항을 다듬으면 그 순간 문항이 바뀐다.

```
assessment/ME_V2/
  items-core.json      Q1~Q48   관심16 경험10 결정소유8 업무방식6 학습6 맥락2
  items-standard.json  Q49~Q68  직무현실8 증거의질6 경로4 제약2
  items-pro.json       Q69~Q92  복합결정8 과제소유12 시장의도4
  stage-variants.json  Q77~Q88 × 학부·석사·박사·학위후
  response-scales.json 척도 일곱
  decision-rules.json  판정 여덟 · 띠 경계 · 바꾼 말
```

**가중치를 숨기지 않는다.** 문항마다 `career_family_weights` 가 드러나 있어
"왜 이 직무가 나왔는가" 를 문항 번호까지 되짚을 수 있다(규격 18장).

---

## 2. 다섯을 합치지 않는다

```json
{
  "actual_work_interest": {},
  "exposure": {},
  "decision_ownership": {},
  "work_mode": {},
  "learning_intent": {},
  "research_project_evidence": {},
  "evidence_quality": {},
  "career_path_preferences": {}
}
```

평균을 내면 '커리어 점수' 하나가 남는데 그 숫자로는 무엇을 할지 알 수 없다.
**갈리는 자리가 쓸모 있다.** 관심이 높고 경험이 없으면 지금 할 일은 지원이
아닙니다. 작게 한 번 해보는 쪽이다.

`v2:check` 가 합쳐 놓은 키가 없는지 매번 확인한다.

---

## 3. 업무 방식에 숫자를 붙이지 않는다

두 문항으로 잰 축에 83.7 을 붙이면 그 정밀도가 있는 것처럼 읽힌다. 검증
전까지 **가까움 · 혼합 · 먼 편** 세 마디로만 말한다(규격 12장).

V1 의 FIT 숫자는 그대로 둔다. 그쪽은 120문항에 표준오차를 재서 붙인 값이고,
V2 의 6문항짜리 업무 방식과는 다른 물건이다. 섞어 쓰지 않는다.

---

## 4. 결정 상태

직무군마다 다섯 값을 보고 **지금 무엇을 할 자리인가**를 정한다. 좋고 나쁨이
아니고 다음 행동이 다르다는 뜻이다.

| 상태 | 언제 |
|---|---|
| READY_TO_APPLY | 관심·경험·근거가 함께 있다 |
| READY_TO_COMPARE_JOBS | 관심과 경험이 있다. 이제 산업·회사를 비교할 때 |
| BUILD_EVIDENCE | 해봤는데 보여 줄 형태로 남은 것이 적다 |
| TEST_FIRST | 관심은 높고 경험이 없고 배울 뜻이 있다 |
| EXPLORE_FIRST | 아직 이 일이 무엇인지 볼 단계 |
| ADJACENT_OPTION | 경험은 있는데 관심이 낮다 |
| DEPRIORITIZE_FOR_NOW | 지금은 뒤로 |
| INSUFFICIENT_DATA | 답한 범위로는 말할 것이 적다 |

규칙은 `decision-rules.json` 에 있고 **순서가 곧 우선순위**다. 코드에
if 를 쌓지 않는다.

---

## 5. 첫 화면은 막대가 아니라 표다

규격 22장. 다섯 칸이 각각 다른 것을 재고 마지막 칸이 할 일을 적는다.

| 직무군 | 업무방식 | 관심 | 경험 | 학습 | 증거 | 지금 할 것 |
|---|---|---|---|---|---|---|
| 기계설계·제품개발 | 가까움 | 높음 | 보통 | 높음 | 보통 | 직무 비교 단계 |
| CAE·해석 | 가까움 | 높음 | 낮음 | 높음 | 낮음 | 먼저 해보기 |

**순위를 매기지 않는다.** 관심 순으로 늘어놓되 1위라는 말을 쓰지 않는다.

---

## 6. 직무군이 여덟에서 열여섯으로

V1 은 문항이 여덟 갈래만 갈라서 여덟이었다. V2 는 Q1~Q16 이 열여섯 갈래를
하나씩 묻기 때문에 열여섯을 그대로 쓴다. 시험·검증, 자동화·로봇,
열·유체·에너지, 재료·파손, 기술지원·현장, 기술 컨설팅, 연구원·학술 연구,
엔지니어링 데이터가 새로 들어왔다.

**이름만 늘리지 않았다.** 그 갈래를 묻는 문항이 실제로 있어서 늘렸다.

---

## 7. 학위는 묻는 장면을 바꾸고 점수를 바꾸지 않는다

Q77~Q88 은 같은 구성개념을 단계마다 다르게 묻는다.

> 학부: 과제나 캡스톤의 요구사항을 읽고 내가 해야 할 목표를 구체적으로 정리한 경험이 있다.
> 포닥: 연구공고·제안서·프로젝트 목표를 검토해 새로운 연구과제나 work package의 목표를 구체화한 경험이 있다.

같은 답을 넣으면 석사와 박사의 소유 점수가 **같다**(`v2:check` T3). 학위가
올라간다고 칸이 자동으로 오르지 않는다.

## 8. 검사

```bash
npm run v2:check
```

| 확인 | 왜 |
|---|---|
| T1 관심≠경험 | 관심만 높은데 지원 단계로 보내면 사람을 헛되게 움직인다 |
| T2 경험≠관심 | 경험만 많은 직무를 앞세우면 하고 싶지 않은 길로 민다 |
| T3 학위≠소유 | 학위로 점수를 주면 그 줄이 아무것도 재지 않는다 |
| T4 국적 중립 | 묻는 문항 자체가 없어야 한다 |
| T5 목표 국가 중립 | 나라를 바꿔도 핵심 값이 같아야 한다 |
| T6 근거 없는 포닥 | 근거 없이 RP3·RP4 를 주지 않는다 |
| T7 없는 정밀도 | 업무 방식에 소수점을 붙이지 않는다 |
| T8 BASIC 값 | 48문항만으로 순서·까닭·다음 행동이 나와야 한다 |

더해서 문항 수 48/68/92, 합쳐 놓은 점수 없음, 옛 판 보존을 확인한다.

## 9. 아직 못 한 것

**검증 전이다.** 규격 13장이 요구한 인지 면접 10~20명과 파일럿 200명 이상을
아직 돌리지 않았다. 그래서 `work_mode` 를 `work_mode_profile` 로만 내보내고
숫자를 붙이지 않는다. **"과학적으로 검증된" 이라고 팔지 않는다.**

**화면에 붙이지 않았다.** 지금은 엔진과 데이터와 테스트까지다. 응시 화면이
V2 문항을 내고 결과지가 결정 표를 그리는 배선은 다음 단계다. 그 배선을 할
때 V1 응시자가 V2 화면으로 새지 않도록 `assessment_version` 으로 갈라야 한다.

**V1 과 V2 를 섞어 비교하지 않는다.** 두 검사는 문항이 다르므로 점수를 나란히
놓을 수 없다. 같은 사람이 둘 다 보더라도 각각 자기 버전 안에서만 읽는다.

**조직 가치 다리(규격 29~64장)와 나라 층(65~118장)은 아직이다.** 조직 가치
쪽은 바로 이어서 할 수 있고, 나라 층은 공식 출처와 확인 날짜가 붙은 자료가
먼저 있어야 한다. 규격 99·100장이 "자료 없이 나라 선택기만 두면 글로벌이
아니다" 라고 못 박았고, 그 말이 맞다.
