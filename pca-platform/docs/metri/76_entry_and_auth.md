# 공개 진입 동선 정상화 · Workspace UX · Google/Apple 로그인

2026-10-09. 앞 회차의 감사 결과를 승인받아 고친 회차다.

**판단 엔진을 한 줄도 바꾸지 않았다.** 채점 · 문항 은행 · ResultModel ·
소유 판정 · 묶음 판정 · 산업과 역할이 Core 를 바꾸지 않는 원칙 · 굳은
스냅샷이 그대로다. 고친 것은 **사람이 제품으로 들어오는 길**이다.

## 0. 이 회차의 한 문장

> ME_V3 와 CareerMatri Workspace 는 만들어져 있는데, **공개 진입·구매·무료
> 동선의 상당 부분이 아직 ME_V1 / ME_V2 로 연결돼 있었다.**

그 연결을 끊고, 끊긴 자리를 **지금 판본**이나 **아직
판매를 열지 않았습니다** 로 가게 했다.

## 1. 판본을 코드에 적는 자리가 하나다

`src/lib/engine-entry.ts` 가 생겼다.

```
CURRENT_ASSESSMENT = "ME_V3_2"      ← 새 판본을 여는 날 이 한 줄만 바뀐다
startPathFor(assessment_version)    ← 산 것이 다음에 여는 자리
resumePathFor(assessment_version)   ← 옛 판본으로 이미 응시한 분의 이어하기
```

전에는 네 자리가 주소를 **글자로** 들고 있었다.

| 자리 | 전 | 후 |
|---|---|---|
| `/checkout/complete` | `/assessment/start` (ME_V2) | `startPathFor(산 상품)` |
| `/free-start` | `/assessment/start` (ME_V2) | 〃 |
| `/free` | `/test` (ME_V1 253문항) | 〃 |
| `/redeem` | `/test` (ME_V1) | 〃 |

**`startPathFor` 가 옛 판본에는 주소를 돌려주지 않는다.** 돌려주면 그것이
곧 신규 진입 동선이 된다. 이어하기는 `resumePathFor` 로 따로 갈라 뒀다.
하나로 두면 "이어하기" 를 살리려다 "새로 사기" 까지 옛 검사로 열린다.

### 공개 가격표가 지금 판본만 내놓는다

`catalogFor()` 가 `assessment_version = CURRENT_ASSESSMENT` 로 좁혔다.
**옛 상품을 지우지 않았다**: 그 상품으로 산 분의 주문과 이용권과 결과지가
남아 있어야 한다. 파는 자리에서만 뺐다.

지금 ME_V3_2 상품 셋은 `active = false` 라 가격표가 비어 있고,
`아직 판매를 열지 않았습니다` 가 선다. **그것이 맞는 상태다**: 잘못된 옛
검사로 보내는 것과 판매를 아직 열지 않는 것은 다른 일이고, 뒤엣것이 맞다.
켜는 일은 사업 결정이라 이 회차에서 건드리지 않았다. `db:verify` 가 그
상태를 한 줄로 적는다.

## 2. 등급을 문항 수로 팔지 않는다

`tiers.ts` 가 앞 판본(ME_V2)의 결과지를 팔고 있었다: `먼저 볼 직무 묶음` ·
`직무 둘 이상을 나란히 견주는 표` · `조직 유형 성과 기준` ·
`30·90·365일 계획`. **넷 다 지금 결과지에 없는 절이다.** 없는 절을 적어
두면 산 사람이 결과지를 열고 그것을 찾는다.

다시 쓴 셋은 `scoring/engine.ts` 의 `limitsFor()` 와 짝이 맞는다.

| 코드가 가르는 것 | BASIC | STANDARD | PRO |
|---|---|---|---|
| `allows_evidence_established` | ✗ | ✓ | ✓ |
| `allows_axis_names` | ✗ | ✓ | ✓ |
| `deep_axes` | ✗ | ✓ | ✓ |
| `allows_translation` | ✗ | ✗ | ✓ |

**가격 카드에서 문항 수를 뺐다.** 거기 적히던 48 · 68 · 92 는 ME_V2 의
수라 지금 받는 것과도 달랐다(`itemsFor()` 를 읽고 있었다). 남긴 것은
시간 하나이고, 그 값은 `estimate()` 가 실제 계획을 세워 센 것이라 시작
화면과 갈리지 않는다(`src/lib/tier-minutes.ts`).

```
BASIC 12~13분 · STANDARD 20~21분 · PRO 30~32분   (npm run v3:length)
```

## 3. 견본은 옛 판본이라 권하지 않는다

`/sample` 안에서 도는 것이 `PCAV2Report.render` 다. **사기 전에 받지 않을
결과지를 보여 주면 그것이 약속이 된다.** 가격표와 상품 소개에서 견본
단추를 걷었고, 쪽은 그대로 열린 채 `견본을 준비하고 있습니다` 를 적는다.

옛 판본 견본을 그대로 보려면 `SAMPLE_LEGACY_V2=yes` 다. 기본값은 꺼짐이다.

**ME_V3 합성 견본을 지어내지 않았다.** 만들려면 합성 응시 하나를 실제
엔진으로 끝까지 돌려 그 결과 모델을 떠 두어야 하고, 그 전까지는 비어
있다고 적는 것이 맞다.

## 4. 한 route 가 남의 메뉴를 켜고 있었다

`/me/apply` 가 쪽에서 `active="/me/jobs"` 를 넘기고, `nav.ts` 의 별칭이
`/me/jobs → /me/track` 으로 다시 접어서 **`지원한 곳` 을 열면 `Track` 이
켜졌다.** `/me/region` 도 같은 모양으로 `산업과 직무` 를 켰다.

둘 다 제 줄을 넘기게 고쳤고, **다시 생기지 않게** 둘을 뒀다.

```
ALIAS_OK     별칭의 왼쪽은 메뉴에 제 줄이 없는 주소여야 한다
navKnown()   쪽이 넘기는 active 는 메뉴나 별칭에 있는 주소여야 한다
```

`npm run v3:workspace` 가 매번 세고, **쪽의 주소와 넘긴 `active` 가 둘 다
메뉴에 있는데 서로 다르면** 걸린다.

## 5. `준비 중` 안에 되는 기능 셋이 섞여 있었다

Track 목록에 관심 산업·직무 바꾸기 · 지원한 곳 관리 · 지원 직무별로 모아
보기가 `지금 열기` 단추를 달고 서 있었다. **준비 중 묶음 안에서만 닿는
기능은 사용자에게 없는 기능이고**, 같은 목록에 되는 것과 안 되는 것이
같은 모양으로 서면 묶음 이름이 거짓말을 한다.

셋을 제자리(`산업과 직무` · `지원한 곳`)로 보내고, Track 에는 아직 없는
여섯만 남겼다. **없는 기능에 `지금 열기` 를 달지 않는다.**

## 6. 홈이 세부 쪽을 대신하고 있었다

`/me` 가 묶음마다 셋씩(최대 여섯 줄)과 비어 있는 자리 셋을 들어서,
`지금 상태` 와 `다음 할 일` 을 눌러 들어갈 이유가 없었다. 홈은 **상태 셋 ·
비어 있는 자리 하나 · 할 일 하나**이고 나머지는 세부 쪽이다.

그리고 **결과 기록이 서랍 안에 있었다.** 검사를 끝낸 사람이 가장 자주
돌아오는 자리인데 손전화 띠에 없었다. 띠를 여섯 칸으로 늘리지 않고
(320px 에서 글자가 두 줄로 접힌다) `지금 상태` 와 자리를 바꿨다. 그쪽은
홈의 첫 카드가 요약을 들고 있다.

## 7. Google · Apple 로그인

**새 인증 시스템을 하나 더 만들지 않았다.** 이 저장소는 전부터
NextAuth(Auth.js) v5 를 쓰고 있고, 늘어난 것은 그 안의 공급자 둘이다.
세션도 쿠키도 그대로고, **비밀번호 로그인을 지우지 않았다.** 학과가
발급한 학번 계정은 소셜이 없고, 그 계정이 지금 돌고 있는 계약의 전부다.

### 사람을 둘로 가르지 않는 것이 전부다

로그인 방법을 하나 더 여는 일에서 가장 비싼 실수는 로그인이 안 되는
것이 아니라 **같은 사람이 둘로 갈리는 것**이다. 갈리면 주문은 이쪽에,
응시와 결과지는 저쪽에 남고, 그 사람은 돈을 내고 아무것도 못 본다.

규칙 넷(`src/lib/auth-accounts.ts`).

1. **사람을 찾는 열쇠는 공급자의 `sub` 이다.** 이메일로 찾지 않는다:
   이메일은 바뀌고, 애플은 가려 준 주소를 주고, 같은 주소를 나중에 다른
   사람이 받을 수 있다.
2. **이메일이 같다고 자동으로 합치지 않는다.** 합치면 남의 주소를
   공급자에 등록한 사람이 남의 계정을 가져간다. 주소가 같으면
   `/login/link` 에서 멈추고, **그 계정으로 들어와서** 연결하게 한다.
   비밀번호를 아는 것이 소유를 증명하는 유일한 길이다.
3. **공급자가 확인하지 않은 이메일은 주소로 치지 않는다.**
4. **처음 들어온 사람은 동의를 받은 뒤에 만든다.** 가입 화면이 받는 필수
   동의를 소셜이라고 건너뛰면 동의 없는 계정이 생긴다.

되돌릴 수 있는 쪽으로만 틀린다: 못 들어오면 그날 문의가 오고, 남의
계정으로 들어가면 아무도 모른다.

### 애플의 가려 준 주소

애플은 사람이 고르면 `...@privaterelay.appleid.com` 을 준다. 그것은 기존
이메일 계정과 **다른 주소**이고, 그래서 같은 사람이어도 자동으로 합쳐지지
않는다(규칙 ① 그대로다). 합치는 길은 로그인한 뒤 계정 화면에서 연결하는
것뿐이고, 화면이 **가려 준 주소라는 것을 적는다.**

### 표 하나와 칸 하나

```sql
auth_accounts (user_id, provider, provider_account_id, email,
               email_verified, created_at, last_login_at)
  UNIQUE (provider, provider_account_id)
users.pw_login BOOLEAN NOT NULL DEFAULT true
```

**열쇠를 담지 않는다.** access token 도 refresh token 도 적지 않는다.
OAuth 를 쓰는 까닭은 **누구인지 확인하는 것** 하나뿐이고, 남의 서비스를
대신 부를 일이 없다. 담아 두면 그 줄이 새는 날 남의 메일함이 열린다.

`pw_login` 의 기본값이 `true` 인 것이 중요하다. **이미 있는 계정은 전부
비밀번호 로그인을 쓰고 있다.** 소셜로만 만든 계정에는 아무 비밀번호와도
맞지 않는 임의의 해시가 들어가고 이 칸이 `false` 다.

### 동의 한 걸음

콜백에서 바로 만들지 않는다. 신원을 **봉한 봉투**(AES-256-GCM, 10분)에
담아 `/signup/social` 로 보내고, 거기서 가입 화면과 **같은
`ConsentBlock`** 으로 동의를 받은 뒤에 만든다. 주소에 이름과 메일이
날것으로 실리지 않는다.

### 연결하기

`/my` 의 `로그인 방법` 이 지금 들고 있는 길을 적는다. 적지 않으면 구글로
가입하신 분이 비밀번호 찾기를 누르고 메일을 기다린다.

연결은 나갈 때 **봉한 쪽지**를 쿠키로 들려 보내고 돌아올 때 `signIn`
콜백이 읽어 **지금 이 사람에게** 붙인다. 쪽지는 공급자 이름까지 품고
있어서 구글용 쪽지가 애플 콜백에서 열리지 않는다.

**끊는 단추를 두지 않았다.** 마지막 하나를 끊으면 그 사람이 다시는 못
들어오고, 그 상태를 되돌릴 길이 화면에 없다. 끊기는 고객지원으로 보낸다.

### 꽂히지 않으면 단추를 띄우지 않는다

`enabledProviders()` 가 환경변수를 보고 정한다. 꽂히지 않은 공급자를
화면에 세우면 누른 사람이 공급자 쪽 오류 화면에서 끝나고, 등록만 해 두면
`/api/auth/signin/google` 이 열려 있다. 그래서 **NextAuth 에 등록도 하지
않는다.**

## 8. 캡처가 거짓말을 하고 있었다 (QA 의 P0)

작업공간 캡처 스물두 자리 가운데 일곱(파일 스물한 장)이 전부 같은
그림이었다: `/my` 와 **빈 상태 다섯 쪽**이 전부
`비밀번호를 정해주세요` 화면이었다.

까닭은 둘이다. 찍는 쪽이 비밀번호를 **다른 스크립트의 소스에서 정규식으로
긁어** 왔고(그 계정이 첫 로그인에 비밀번호를 바꿔야 한다는 것을 몰랐다),
로그인을 "주소가 `/login` 으로 시작하지 않으면 됐다" 로만 쟀다. 그 화면은
200 이고 내부 코드도 가로 스크롤도 없어서 **나머지 검사도 전부 통과했다.**

**상태 코드는 "서버가 뭔가를 돌려줬다" 까지만 말한다.** 그래서 그림을
남기기 전에 셋을 본다(`scripts/_shot-identity.mjs`).

```
① 주소        떨어진 자리가 노린 자리인가
② 큰 글씨     그 쪽의 머리글이 섰는가
③ 가르는 글자 그 쪽에만 있는 글귀가 있는가
```

③ 이 가장 중요하다. ①② 만으로는 비슷한 두 쪽을 바꿔 찍어도 지나간다.
그리고 **같은 그림이 두 이름으로 저장되면 걸린다**(sha256). 로그인 뒤
떨어지는 자리(`/login` · `/password/change` · `/start` …)에 떨어지면 그
자리에서 멈춘다.

준비 쪽이 계정을 **그 자리에서 만들고 열쇠를 함께 넘긴다.** 열쇠는 저장소에
적히지 않고 해시만 DB 에 남는다. 찍는 사람도 **학생 계정**으로 바꿨다.
전에 쓰던 `me-admin` 은 기관 담당자라 `homePathFor` 가 `/org` 로 보낸다.

고치고 나서 캡처 63장이 전부 통과했고 **같은 그림이 0 쌍**이다.

### 캡처가 찾아낸 진짜 탈 셋

- **`/product` 가 320px 에서 가로로 밀렸다.** 공개 머리띠에 `검사 시작` 을
  더하면서 네 칸이 안 들어갔다. 칸을 빼지 않고 접게 했다. 그 단추가
  검사로 들어가는 유일한 공개 길이다.
- **왼쪽 띠의 맨 아래 줄(`계정`)이 공개 전 띠에 가렸다.** `--stg-h` 를
  빼지 않아 문서가 창보다 그만큼 높았다. 운영에는 띠가 없어 드러나지 않는
  탈이라 캡처에서만 보인다.
- **`.sf-btn.sm` 이 34px 이었다.** 계정 쪽(`/my`)은 그 단추만으로 이루어진
  화면이다. 40px 로 올렸다.

## 10. 토큰을 합치지 않고 이름만 줬다

토큰이 네 벌이다(`--sf-*` · `--q-*` · `--r-*` · `--cm-*`). **합치지
않는다**: 세 면은 하는 일이 달라서 활자 단과 여백이 같을 이유가 없고,
억지로 합치면 세 쪽이 한꺼번에 틀어진다.

합치는 대신 **같아야 하는 것에만 이름을 줬다**(`--ui-*` 여덟). 값은 전부
`--sf-*` 를 가리키므로 **그리는 것은 한 픽셀도 없다.** 접두어를 `--ui-`
로 둔 것은 `--cm-` 을 이미 작업공간이 쓰고 있어서다. 이 저장소에서
이름이 겹친 것이 여섯 번 전부 버그였다.


## 12. 아직 아닌 것

- **실제 구글·애플에 한 번도 붙지 않았다.** 자격증명이 없고, 있어도
  사람이 브라우저에서 동의를 눌러야 한다. `auth:check` 가 재는 것은
  **공급자가 신원을 준 뒤에 우리가 하는 판단**이다.
- **운영 배포본을 밖에서 브라우저로 열지 못했다.** 이 컨테이너의 네트워크
  정책이 `app.careermatri.com:443` 을 막는다.
- **운영 DB 에 한 줄도 쓰지 않았다.** `db/schema_auth_oauth.sql` 은
  만들고 이 기계에서 돌려 봤을 뿐이다. 운영 적용은 OWNER ACTION 이다.
- ME_V3 합성 견본이 없다. ME_V3 상품은 꺼져 있다. Track 은 그대로 준비
  중이고, 다른 Major Core 는 등록만 돼 있다.
