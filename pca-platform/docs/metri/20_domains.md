## 0. 한 줄

**도메인보다 이름이 먼저 막힌다.** 한국에는 이미 **메트리(Metri)** 라는
온라인 검사 서비스가 있다. 그리고 코드가 가리키는 `metri.io` 도 우리
것이 아니다.

## 0-1. 2026-09-15: `metri.co.kr` 을 사려다 찾은 것

`metri.kr` 에 CloudFront 가 응답하던 것이 우리 것일 수도 있다고 4절에
적어 뒀는데, **아니었다.**

| | |
|---|---|
| 누구 | 테라블루테크놀로지 (정신건강의학과 소프트웨어) |
| 무엇 | **메트리(Metri)**: 온라인 척도검사 전자화. 검사 처방·판독·보관 |
| 어디 | `metri.kr` · `clinic.metri.kr` · `client.metri.kr` |
| 또 | 구글플레이 앱 이름이 **'메트리'** (`com.metri.metri_client_flutter`) |
| 문구 | 사이트 대문이 "설문지 처방의 새로운 시작, Metri" |

**같은 낱말을 쓰고 있다**: 검사, 처방, 온라인. 파는 곳이 병원이고
우리는 학교라 시장은 갈리지만, 한국에서 "메트리 검사" 를 찾는 사람에게는
갈려 보이지 않는다.

그래서 `metri.co.kr` 은 **살 수 있느냐보다 사도 되느냐가 먼저**다.
`.kr` 을 쓰는 곳이 `.co.kr` 을 방어 등록해 두는 것은 흔한 일이라, 애초에
비어 있지 않을 가능성도 있다.

### 무엇을 확인해야 하는가 (코드로는 못 한다)

이 컨테이너는 whois·rdap·KIPRIS·DoH 가 전부 **송신 차단**이라 등록 여부도
상표도 여기서 볼 수 없다. 밖에서 볼 것 둘.

1. **KIPRIS 에서 '메트리' 상표**: 등록돼 있는지, 몇 류인지.
   우리가 걸리는 것은 41류(교육·검사)와 42류(SaaS)다. 저쪽이 44류(의료)에만
   있으면 숨통이 트이고, 41·42 에 걸쳐 있으면 이름을 바꾸는 편이 싸다.
   **이건 변리사 확인 사항이다. 이 문단은 법률 자문이 아니다**
2. **등록대행자(가비아·후이즈·호스팅케이알)에서 `metri.co.kr` 조회**:
   실제로 비어 있는지. 30초면 된다

### 갈림길 셋

| 고르면 | 값 | 치르는 것 |
|---|---|---|
| 그대로 간다 | 원고·로고를 한 글자도 안 고친다 | 상표 위험을 떠안는다. 검색에서 저쪽과 섞인다 |
| 이름은 두고 도메인만 멀리 | `metricareer.co.kr` 처럼 | 섞이는 것은 그대로다 |
| 이름을 바꾼다 | 위험이 없어진다 | 로고·원고·문서 전부. **지금이 가장 싸다** |

**지금이 가장 싼 때다.** 아직 배포도 안 했고 고객도 없다. 학교 한 곳에
납품한 뒤에 바꾸면 그 학교 문서까지 따라 바뀐다.

## 1. 확인한 것

DNS 로 조회했다. 이 컨테이너에서는 whois·rdap 이 막혀 있어서 **등록
여부 말고 "지금 누가 서버를 띄워 두었는가" 만** 봤다.

| 주소 | 결과 | 코드에서 쓰는 곳 |
|---|---|---|
| `metri.io` | **남의 서버가 응답** (34.234.15.46) | 인터내셔널 사이트 도메인 |
| `app.metri.io` | 응답 없음 | **네 사이트의 "시작하기" 가 전부 여기로 간다** |
| `metri.co.kr` | 응답 없음 | 한국 사이트 도메인 |
| `metri.kr` | 쓰이는 중 (CloudFront) | 안 씀 |
| `metri.com` · `metri.app` · `metri.co` | 쓰이는 중 | 안 씀 |
| `metriplus.co.kr` · `metriplus.kr` | 조용함 | 안 씀 |

**"조용함" 은 "비어 있음" 이 아니다.** 등록만 해 두고 레코드를 안 건
도메인은 응답하지 않는다. 사기 전에 등록대행자에서 WHOIS 를 봐야 한다.

~~`metri.kr` 이 우리 것일 수 있다~~: **아니다.** 0-1절을 볼 것.
CloudFront 대역이 같았던 것은 그 뒤에 수많은 사이트가 있기 때문이다.

## 2. 왜 지금 문제인가

`marketing/src/content/global.ts` 의 `platformUrl: "https://app.metri.io"`
가 네 사이트의 "시작하기" 버튼이 가리키는 곳이다. `metri.io` 가 남의
것이면 그 아래 `app.` 도 우리가 만들 수 없다. **그 상태로 배포하면
버튼을 누른 학생이 남의 집 문 앞에 선다.**

지금은 아무 사이트도 배포돼 있지 않아서 실제 피해는 없다. 배포하는
날에 터진다.

## 3. 사야 하는 것

파는 범위가 **한국뿐**이므로(설계 원칙 9), 지금 필요한 것은 셋이다.

| 쓰임 | 후보 | 비고 |
|---|---|---|
| 한국 소개 사이트 | `metri.co.kr` | 코드가 이미 이 이름을 쓴다 |
| 플랫폼 (전 세계 하나, 설계 원칙 5) | `app.metri.co.kr` 또는 별도 도메인 | `metri.io` 를 못 쓰면 여기서 갈린다 |
| 메트리 플러스 | 한국 사이트 안의 경로로 둬도 된다 | 브랜드는 갈리되 도메인까지 나눌 필요는 없다 |

인터내셔널 사이트는 **파는 나라가 생긴 다음에** 정한다. 지금 `metri.io`
를 비싸게 사 오는 것보다, 한국 매출이 나고 나서 정하는 편이 싸다.

**`.co.kr` 은 국내 주소가 있어야 등록된다.** ACADEMIX 가 국내 법인이므로
요건은 맞고, KISA 가 인정한 등록대행자(가비아·후이즈 등)를 통해 등록한다.
등록비는 대행자마다 다르니 확인이 필요하다. 지어내지 않았다.

## 4. 사고 나서 고칠 곳

도메인이 정해지면 바꾸는 곳은 **두 줄**이다. 나머지는 이 두 값에서 나온다
(`sitemap.ts` · `robots.ts` · og:image 의 `metadataBase` 가 전부
`site.domain` 을 읽는다).

```
marketing/src/content/kr.ts       domain: "metri.co.kr"
                                  platformUrl: "https://app.…"
marketing/src/content/global.ts   같은 두 줄
```

플랫폼 주소는 `NEXT_PUBLIC_PLATFORM_URL` 로도 덮을 수 있어서, 배포 환경에서
먼저 시험해 보고 원고를 고쳐도 된다.

그리고 `regions` 목록의 `live: false` 를 살아 있는 나라만 `true` 로 바꾼다.
**아직 안 열린 나라를 열린 것처럼 두지 않는다.**

## 5. 아직 아닌 것

- **등록 자체.** 결제와 명의가 필요해서 코드에서 할 수 있는 일이 아니다
- **`metri.io` 소유자 확인.** whois 가 막혀 있어 이 컨테이너에서는 못 본다
- **`metri.co.kr` 등록 여부.** 같은 이유로 못 본다. DNS 가 조용한 것은
  비어 있다는 뜻이 아니다
- **'메트리' 상표.** KIPRIS 도 막혀 있다. 이름을 확정하기 전에 볼 것
- **호스팅.** 도메인이 정해져야 인증서와 DNS 레코드를 정한다

## 6. 2026-10-06: 공식 웹 구조를 확정했다

### 6-1. 역할

| 호스트 | 맡는 것 | 맡지 않는 것 |
|---|---|---|
| `careermatri.com` | 공식 홈페이지 · 서비스 설명 · 영업 | 회원가입 · 로그인 · 결제 · 검사 · 결과지 · PDF |
| `app.careermatri.com` | 가입 · 로그인 · 결제 · 검사 · 결과 · PDF · Evidence | 마케팅 원고 |

시장(KR / GLOBAL)은 **호스트로 갈리지 않는다.** 앱 안의 market 과 locale
로 갈린다. 그래서 `careermatri.co.kr` 은 KR 런칭의 필수 조건이 아니다.

`PLATFORM_URL=https://app.careermatri.com` 이 앱 도메인의 단일 원본이고
(`src/lib/app-domain.ts`), 홈페이지 주소는 `site_configs` 에서 읽는다
(`marketingHome()`, 소유가 확인된 것만).

### 6-2. 홈페이지 → 앱 (공개 단추)

돌리는 자리는 원고 네 벌이 아니라 **읽는 자리 한 곳**이다:
`marketing/src/lib/platform.ts` 의 `withAppLinks` 를 `getSite()` 가 한 번
부른다. `APP_PATHS` 에 적힌 경로(`/pricing` · `/login` · `/signup` ·
`/product` · `/start` · `/free` · `/support`)만 앱으로 돌아가고, 언어는
`?lang` 으로 들고 간다.

| 홈페이지 단추 | 가는 곳 |
|---|---|
| 머리띠 `시작하기` | `app.careermatri.com/pricing?lang=…` |
| 머리띠 `로그인` | `app.careermatri.com/login?lang=…` |
| 머리띠 `요금제` | `app.careermatri.com/pricing?lang=…` |
| 첫 화면 `무료로 시작하기` | `app.careermatri.com/pricing?lang=…` |
| `상품 자세히 보기` | `app.careermatri.com/product?lang=…` |
| 요금제 칸의 `바로 신청하기` (payable) | `app.careermatri.com/pricing?lang=…` |
| 개인/기관 문 고르기 `시작하기` | `app.careermatri.com/start?lang=…` |
| 기관·학과 단추 | 홈페이지 `/contact` (앱으로 보내지 않는다) |

`payable` 이 꺼진 요금제는 지금도 `/contact` 로 간다. 값만 적어 두고
접수는 문의로 받는 자리다.

### 6-3. 앱 → 홈페이지 (로고)

`src/components/sf/brand-home.tsx` 한 곳이 정한다.

| 상태 | 로고를 누르면 |
|---|---|
| 비로그인 | `https://careermatri.com` (`marketingHome()`; 없으면 `/start`) |
| 개인 | `/my` |
| Campus (`org_admin` · `instructor`) | `/org` |
| Admin (`superadmin`) | `/admin` |

`/my` · `/org` · `/admin` 안에서는 `Shell` 이 `HOME[surface]` 를 넘겨서
**면이 섞이지 않는다.** 공개 화면(`/pricing` · `/product` · `/sample` ·
`/legal/*`)에서는 세션을 읽어 그 사람의 첫 화면으로 간다.

**세션은 두 사이트가 나눠 쓰지 않는다.** 홈페이지는 로그인을 모르고,
넘어가는 것은 `?lang` 하나다. 이동은 같은 탭이다.

### 6-4. 2026-10-06: 홈페이지에서 결과지와 가격표를 걷어냈다

홈페이지가 결과지 뷰어와 요금 페이지를 따로 들고 있었다. **같은 것을 두
곳에서 들고 있으면 어느 날 갈리고, 갈린 날 사는 쪽은 둘 중 하나를 보고
결제한다.** 그래서 쪽을 지우고 들어오던 주소는 앱으로 넘긴다.

| 지운 것 | 어디로 | 왜 |
|---|---|---|
| `marketing/src/app/pca/` + `components/result-sheet.tsx` | `app.careermatri.com/sample` (301) | 결과지는 앱 하나다. 절 수와 구성이 두 곳에서 따로 자랐다 |
| `marketing/src/app/pricing/` | `app.careermatri.com/pricing` (301) | 가격 정본은 앱의 `products` 다 |
| 원고 네 벌의 `sheet.tabs[].blocks` | — | 결과지 본문을 홈페이지 원고가 품고 있었다 (22곳) |
| `SheetBlock` 타입 · `chrome.nextDiagnosis` | — | 쓰는 데가 없어졌다 |

**301 인 까닭.** 명함과 메일에 적혀 나간 주소가 404 로 끝나면 그 사람은
가격을 못 보고 닫는다. 301 이라 검색엔진이 옛 주소의 평가를 새 주소로
옮기고 다시 묻지 않는다. 표는 `marketing/next.config.ts` 한 곳이고 앱 쪽
언어는 빌드한 나라가 정한다.

**정적 내보내기(`STATIC=1`)에는 리디렉션이 없다.** 서버가 없어서 그 표를
쓰지 못한다. 미리보기용이고 운영 배포는 서버 빌드다.

`src/app/pca/[...path]/route.ts` 는 **옛 결과지가 아니다.** 채점 엔진
(`sites/pca-platform/assets/*.js`)을 앱이 같은 주소에서 내주는 자리이고
결과지와 PDF 가 그것을 불러 쓴다. 지우면 결과지가 선다.

### 6-5. 값은 한 곳에서 적는다

소개 사이트는 정적 빌드라 `products` 표를 못 본다. 그래서 적어 둘 수밖에
없는데, **원고 네 벌에 네 번 적어 두면 고칠 때 한 벌이 반드시 남는다.**
실제로 그렇게 남아서 승인된 값이 셋인데 홈페이지가 옛 단일 가격
29,000원을 적고 있었다. 지금은 `marketing/src/lib/prices.ts` 한 곳이다.

| 시장 | BASIC | STANDARD | PRO |
|---|---|---|---|
| 한국 | 무료 | 14,900원 | 21,900원 |
| 글로벌 | Free | $14.99 | $24.99 |

앱 값이 바뀌면 고칠 곳은 `db/schema_phase2_3.sql`(정본)과
`marketing/src/lib/prices.ts`(소개 사이트가 읽는 사본) 둘이다.

**쪽수와 문항 수를 값으로 적지 않는다.** "15–20페이지" · "18페이지" ·
"253문항" 이 공개 원고 스물여섯 자리에 있었다. 등급을 문항 수로 가르면
비싼 등급이 "문항이 더 많은 것" 으로 읽히고, 그러면 같은 값을 더 낼 이유가
없다(`src/lib/tiers.ts` 머리말과 같은 까닭이다). 위 등급이 파는 것은 같은
응답을 더 깊게 읽은 결과다.

눌러 봤다. 운영 판매 게이트는 일부러 막힌 채로 두었다.

진단 쪽에 `2024-대전유성-0234` 가 적혀 있었는데, 아직 확정하지 않으셨다고
확인받아 `확인 필요 (발급 전)` 로 비웠다. **다른 사이트에 적혀 있는 번호를
가져오지 않는다**: 신고증에 없는 번호를 적으면 그 표시 자체가 거짓이 된다.

| 보는 자리 | 지금 |
|---|---|
| `businessInfo()` 일곱 칸 | 여섯 칸 `settings` 에서 · `mailorder` 만 비어 있음 |
| 공용 꼬리말 | 열두 줄 전부 · 빈 칸은 `확인 필요` (금색) |
| `publicCommerceGate()` (production) | `{open:false, missing:["mailorder"]}` |
| `/pricing` · `/product` (production) | `아직 판매를 열지 않았습니다` |
| `/sample` · `/legal/*` (production) | 그대로 열림 |
| `launch:check` | 막힌 갈래 6 / 12 · `BUSINESS_INFO` 가 그 하나 |

**막는 것을 풀지 않았다.** 번호가 비어 있는 동안 유료 판매가 열리지 않는
것이 설계이고, QA 는 staging 에서 계속 돈다.

### 6-9. 그때 드러난 것 셋

**`P5` 검사가 승인 이후로 계속 빨갰다.** `phase2:check` 가 `kr[0]` 을 집어
"운영에서 안 팔려야 한다" 고 재고 있었는데, 값이 승인된 날부터 `kr[0]` 은
BASIC 이고 `FREE_APPROVED` 라 팔려도 맞는 상품이다. **승인된 무료를 막으면
전자상거래법 제17조 제6항이 요구하는 시용 장치가 사라진다.** 재는 것을
미승인 상품 하나로 좁히고, 승인된 무료가 운영에서도 열리는지를 한 줄 더
뒀다.

**검사 둘이 자물쇠 앞에서 멈췄다.** `phase2:report` 와 `global:check` 의
사전 점검이 맨 `fetch` 로 `/pca/v2.html` 을 두드려 401 을 받고 "서버를
띄우십시오" 를 적었다. 서버는 멀쩡히 떠 있었다. 같은 줄을 두 곳이 따로 들고 있어
한쪽만 고쳐질 자리라 `scripts/_engine-up.ts` 하나로 모았다.

**비밀번호 재설정이 보낸 척했다.** `MAIL_HOST` 가 비어 있어도 화면이
"재설정 링크를 보냈습니다" 로 끝나서, 기다리는 사람은 받은 편지함만
들여다본다. 메일이 붙어 있는지는 **배포본 설정 하나로 정해지고 계정과 무관하다.**
그것만 보고 다른 문장을 내므로, 계정이 있는지는 여전히 한 가지 답이다.

**`/support` 가 로그인 벽이었다.** 공개 꼬리말의 `고객지원` 이 이 주소를
가리키는데 비로그인은 `/login` 으로 튕겼다. 아직 사지 않은 사람이 묻고
싶던 것을 못 묻고 돌아간다. 번호가 붙는 자리(주문 · 환불 · 막힌 것)는
그대로 본인에게만 보이고, 사람에게 닿는 주소와 비밀번호 복구만 먼저
내놓는다.

### 6-11. 운영 배포본은 이 자리에서 못 두드린다

`npm run prod:check` 를 만들었다. DNS · HTTPS · 상태코드 · 리디렉션 ·
세션 쿠키 · 사업자 표시 · 꼬리말 · 가로 넘침 · 5xx 를 열한 쪽에서 한 번에
훑는다. **저장소 코드를 보지 않고 실제로 떠 있는 것만 두드린다**:
`launch:check` 는 "코드가 그렇게 짜여 있는가" 를 묻고 이것은 "거기서
그렇게 도는가" 를 묻는다.

세션 컨테이너에서는 막힌다. 프록시가 그대로 적어 준다:

```
403 Host not in allowlist: app.careermatri.com.
    Add this host to your network egress settings to allow access.
```

**운영이 죽은 것이 아니다.** 그래서 스크립트가 그 경우를 `프록시 막힘` 으로
따로 적는다. 모르는 것을 모른다고 적어야 다음 사람이 엉뚱한 데를 고치지
않는다. DNS 는 나가므로 A 레코드까지는 이 자리에서도 보인다
(`app.careermatri.com` → 69.46.46.89 · `careermatri.com` → 216.198.79.1).
