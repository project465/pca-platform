# 전공자 검토가 필요한 자리와 다음 구현 단계

## 1. 전공자가 봐 주셔야 하는 자리

문면을 쓴 사람이 기계공학 현업자가 아니다. 자동 검사는 **문면이 규칙을
지키는지**만 세고, 그 문장이 현장에서 실제로 쓰이는 말인지는 세지 못한다.
검토용 묶음은 `56_me_v3_expert_review.md` 다.

### 1-1. 지적받은 네 문항을 처리한 결과

| 문항 | 처리 | 지금 문면 |
|---|---|---|
| TD05 J3 모터·감속비 | 다시 썼다 | 부하와 관성을 따져 모터 용량과 감속비를 직접 정해 본 경험이 있다 |
| TD09 J3 예비품 보유 수준 | **확인 기준으로 내렸다** | 설비 점검 항목과 주기를 직접 정해 본 경험이 있다 |
| TD12 J3 판정 규칙 | **확인 기준으로 내렸다** | 자동화할 처리 절차를 직접 정해 본 경험이 있다 |
| TD04 J4 모달·가속도 | **둘로 나눴다** | 모달 해석으로 고유진동수와 모드 형상을 구해 본 경험이 있다 · 가속도계를 붙여 진동을 직접 측정해 본 경험이 있다 |

예비품 보유 수준과 판정 규칙은 그 축의 소유 기준이라 체크리스트로 내렸다.
문면에 두면 점검 주기를 정한 사람과 처리 절차를 정한 사람이 `없다` 로
떨어진다.

### 1-2. 두 영역의 보강 결과

| 영역 | 앞 | 지금 | 가장 얇은 축 |
|---|---|---|---|
| TD05 제어·메카트로닉스 | 15 | 32 | J2 세 항목 |
| TD09 설비·보전 | 16 | 30 | J1 세 항목 |

**문항 수를 늘리지 않고 체크리스트를 늘렸다.** 두 영역은 옛 증거 지도에서
온 항목이 이름표에 가까워서(`구동기·센서 선정`) 응시자가 `내가 정했다` 로
고를 문장이 적었다. 지시받은 관점을 축에 배정한 결과다.

| TD05 관점 | 어느 축에서 받는가 |
|---|---|
| 요구 응답과 성능 정의 | J2 정정 시간 · 오버슈트 · 정지 정확도 |
| 센서와 입력 | J3 피드백에 쓸 센서 종류와 설치 위치 |
| 구동기 | J3 부하와 관성과 마찰을 따진 모터 용량 |
| 전달계 | J3 감속비와 전달 방식 |
| 제어 대상 특성 | J1 부하 변화와 마찰 같은 변동 조건 |
| 제어 방식 선택 | J3 온오프와 PID 와 시퀀스 가운데 |
| 맞추기 | J4 이득과 가감속 곡선 조정 (문항을 따로 두었다) |
| 응답과 안정성 확인 | J6 정정 시간과 오버슈트 측정 |
| 실제 시스템 검증 | J6 실제 기계에 올려 설계값과 대조 |

| TD09 관점 | 어느 축에서 받는가 |
|---|---|
| 설비 요구조건 | J2 요구 가동률과 생산 계획 |
| 능력 | J2 요구 생산량에서 설비 능력과 여유 |
| 고장 모드 | J1 영향으로 순서 정하기 · J4 이력에서 고장 모드 분류 |
| 점검 | J3 일상 점검과 정기 점검을 갈라 주기 정하기 |
| 예방과 예지 보전 | J3 교체 기준 · J4 진단과 추세 예측 (문항을 따로 두었다) |
| 예비품 | J3 보유 수준과 발주 시점 |
| 멈춘 시간 | J6 수리 시간과 고장 간격 |
| 원인 분석 | J7 설계와 운전과 보전을 증거로 가르기 |
| 개선 | J5 점검표와 보전 계획 · J8 개조와 투자 검토 |
| 안전과 운영성 | J2 안전과 법정 점검 항목 |

### 1-3. 아직 사람이 봐 주셔야 하는 것

| 자리 | 묻는 것 |
|---|---|
| 영역 문항 아흔아홉 | 현장에 있는 행동인가 · 확인과 소유의 차이가 또렷한가 |
| 산업 용어 여덟 벌 | 그 산업 사람이 쓰는 말인가. 쉬운 말 풀이가 맞게 바꿔 적었는가 |
| 역할팩 문항 마흔둘 | 그 자리에서 가진 권한을 묻는 말이 맞는가 |
| 보기 넷의 문면 | `지시받아 했다` 와 `내가 정했다` 사이를 사람들이 실제로 가르는가 |

마지막 줄은 파일럿에서만 답이 나온다. 보기 읽는 법을 화면에 한 줄로
적었지만, 그 줄이 참여를 소유로 적는 것을 막는지는 응답을 받아 봐야 안다.

### 1-4. 아직 쓰지 않은 것

| 자리 | 상태 |
|---|---|
| 산업별 별칭 변형 | 비어 있다. 직무명이 산업마다 다르게 불리는 표가 없다 |
| 지역 요구 강도 | 공고 자료가 없어 비어 있다 |
| 영어판 | 한 줄도 쓰지 않았다. 한국어가 기준이다 |

## 2. 다음 구현 단계

**문항 동결 승인 전에는 시작하지 않는다.** 아래 순서는 승인 뒤의 순서다.

| 순서 | 할 일 | 왜 이 자리인가 |
|---|---|---|
| 1 | 검토 반영 | 전공자 표에서 나온 것을 은행에 넣고 검사를 다시 돌린다 |
| 2 | V3 채점 코드 | 축 수준 · 확인 개수 · 묶음 판정. `v3:persona` 의 검산과 **같은 값**이 나와야 한다 |
| 3 | 응시 화면 배선 | 격자 한 화면 · 보기 넷과 읽는 법 한 줄 · 학위 장면 · 이어보기 |
| 4 | 등급 올리기 | 같은 응시의 `tier` 를 올리고 추가 블록만 연다. 앞 응답을 다시 묻지 않는다 |
| 5 | 결과지 renderer | 결과 절 열 개. 자리마다 입력이 있는 것을 `v3:items` 가 이미 센다 |
| 6 | 팩 층 배선 | 산업 하나 · 역할 하나 · 설명 순서만 바꾼다 |
| 7 | 상품과 등급 | `products` 에 ME_V3 세 등급. ME_V2 는 읽기 전용 |
| 8 | 홈페이지 | V3 가 내놓는 것만 적는다 |
| 9 | 본 파일럿 | 일곱 가지를 잰다. 가장 큰 가정은 대학원 경험 번역의 정확도다 |

**2번과 3번 사이에 DB 작업이 하나 있다.** 석사 이상에 전공계열이 없으면
응시가 시작되지 않게 막는 제약이고, `db/schema_v3_arch.sql` 에 적어만
두었다.

**아직 하지 않는 것.** UI 전면 수술과 홈페이지 전면 개편, 공고 자동수집,
구독과 월간 리포트, 반복결제는 이 순서에 없다.
