# ME_V2 결과지 재설계 — 모듈 순서에서 읽는 순서로

ME_V2 를 플랫폼에 붙이기 전에 결과지를 먼저 다시 짰다. 지금 모양 그대로
플랫폼에 물리면 **잘못된 정보 구조와 PDF 구조가 플랫폼에 굳는다.**

이 작업에서 **점수와 판정은 한 줄도 건드리지 않았다.** ME_V1 · ME_V2 의
48/68/92 문항 · Interest · Experience · Decision Ownership · Work Mode ·
Learning Intent · Value Engine 의 사실 · Evidence Ladder 의 판정 ·
Role Evidence Coverage 의 판정 · Organization Value 의 사실은 그대로다.
바뀐 것은 **그 사실을 어떤 순서로, 몇 장에 담아 내보내는가**뿐이다.

## 1. 무엇이 문제였나

예전 결과지는 분석 모듈을 만든 순서대로 늘어놓았다. 그래서 한 직무가
결정 표에, 증거 범위에, 전공지식 사슬에, 격차 표에, 지원 자료 절에
**다섯 번** 나왔다. 읽는 사람은 같은 직무를 다섯 번 만나고도 그래서
무엇을 먼저 하라는 것인지 몰랐다.

PRO 기준 22개 절 · A4 로 뽑으면 스물다섯 장. 첫 화면에는 16개 직무가
전부 깔렸고, 검사 설명과 측정 방법과 문항 번호가 먼저 나왔다.

## 2. 읽는 순서가 곧 구조다

```
DECISION → WHY → EVIDENCE → ORGANIZATION VALUE → GAP → ACTION
```

쪽마다 핵심 메시지 하나. 인쇄에서 쪽이 갈리는 자리가 곧 이 규칙이다
(`.rpage { break-after: page }`).

### 등급마다 몇 장인가

| | 본문 | 찍힌 장수(표지·부록 포함) | 부록 | 규격 |
|---|---|---|---|---|
| BASIC | 5장 | 12장 | 8절 | 4~5 |
| STANDARD | 7장 | 14장 | 8절 | 6~8 |
| PRO | 10장 | 17장 | 8절 | 8~10 |

`npm run v2:pdf` 가 **장수를 세서 규격을 지킨다.** 등급별 본문 장수가
범위를 벗어나거나, 한 묶음이 종이 두 장을 먹기 시작하거나, 전체가 스무
장을 넘으면 실패로 떨어진다. "한 쪽에 메시지 하나" 를 눈으로 지키지
않고 숫자로 지킨다.

### 등급별 쪽 구성

규격이 등급마다 구성을 따로 적어 두었다(§14 BASIC · §15 STANDARD ·
§3·§16 PRO). 그대로 따랐다.

| 쪽 | BASIC | STANDARD | PRO |
|---|---|---|---|
| 1 DECISION 지금 먼저 보실 세 가지 | ○ | ○ | ○ |
| 2 DECISION 먼저 볼 직무를 견주면 | Top 3 | Top 3 + 곁에 둘 2 | Top 3 + 곁에 둘 2 |
| 3 WHY 배운 것이 실제 업무에서 어떻게 쓰이는가 | ○ | ○ | ○ |
| 4 EVIDENCE 지금 내가 가진 증거 | 경험 2건 + 공백 | 4건 + 도구 | 8건 + 도구 |
| 5 ORGANIZATION VALUE 같은 전공도 조직에 따라 | | ○ | ○ + 서류·면접 번역 |
| 6~8 WHY·EVIDENCE 〈직무 이름〉 | | | 3개 |
| 9 GAP 아직 확인되지 않은 것 | 4쪽에 포함 | ○ | ○ |
| 10 ACTION 다음에 만들 경험 하나 + 일정 | 30일 | 30·90일 | 30·90·365일 |

**직무 쪽(Role Deep Dive)은 PRO 만 받는다.** 규격 §9 가 "top 2–3 roles"
라고 적은 자리는 PRO 구성(§3)이고, §15 의 STANDARD 구성에는 직무 쪽이
없다. STANDARD 의 값은 "comparison depth" 다: 조직 비교와 공백 쪽이
STANDARD 에서 붙고, 직무 하나를 파고드는 쪽이 PRO 에서 붙는다. 한동안
STANDARD 에 직무 쪽 둘을 넣어 뒀다가 규격 쪽수(6~8)를 넘겼고, 등급 값도
흐려졌다.

BASIC 이 조직 비교 쪽을 받지 않는 것도 규격 §14 의 구성이다. BASIC 의
사슬에 "어느 조직 기준으로 적었다" 는 줄은 들어 있어서, 조직이 결과를
가른다는 말 자체가 빠지지는 않는다.

**세 상태(확인 · 일부 확인 · 아직 확인되지 않음)는 등급에 관계없이
본문에 글자로 적힌다.** 직무 쪽이 PRO 전용이 되면서 그 세 상태가
BASIC·STANDARD 본문에서 사라졌던 적이 있다. `직무별로 핵심 영역이
어디까지 확인되었나` 표가 칸 이름으로 세 상태를 적어 그 자리를 받는다.

## 3. 열 가지를 어떻게 고쳤나

| 받은 지적 | 고친 자리 |
|---|---|
| ① 첫 쪽에 16개 직무 전부 | 첫 쪽은 Top 3 카드만. 곁에 두실 후보 2개는 둘째 쪽. 16개 전부는 부록 |
| ② 첫 쪽이 검사 설명부터 | 첫 쪽 = Decision Summary. 검사 설명·측정 방법·문항 번호를 전부 부록으로 보냈다 |
| ③ 직무 정보가 다섯 군데 | 직무당 `roleDeepDive` **하나**. 왜/하는 일/전공지식/현재 증거/필요 증거/조직 결과/다음 행동을 한 자리에서 끝낸다 |
| ④ `확인 0 / 아직 8` 빈 쪽 | 요약 한 줄 + 미확인 두셋 + 다음 행동 하나. 빈 표를 그리지 않는다 |
| ⑤ 문항 번호가 본문에 | `whyPlain` 이 문항 문장을 사람이 읽는 이유로 줄인다. 번호는 부록의 되짚기 표 |
| ⑥ 조직 비교가 뒤에 | STANDARD·PRO 모두 본문 다섯째 쪽 |
| ⑦ Evidence Ladder 가 능력 부족처럼 보임 | 쪽 머리말이 "낮은 칸이 모자라다는 뜻이 아닙니다" 를 먼저 말한다. 상태는 색이 아니라 글자(확인·일부·아직)로 적는다 |
| ⑧ Untranslated Evidence | 이름을 붙여 유지. 웹은 `경험 보완하기` 단추, 종이는 같은 자리에 안내 한 줄(`.rponly`) |
| ⑨ Next Action 이 뒤에 | 첫 쪽 `지금 할 일` 한 줄이 가장 큰 공백에서 바로 나온다 |
| ⑩ Next Evidence Project 여러 개 | 하나만. `CR.nextEvidence(J, topId)` |

## 4. 중복으로 지운 것

- 둘째·셋째 직무의 **전공지식 사슬**: 아래 직무 쪽이 같은 말을 한다.
  사슬은 맨 앞 직무 하나만 그린다.
- 사슬 안의 **`다음에 확인할 것` 목록**: 할 일은 ACTION 쪽이 한 번만 말한다.
- 사다리 뒤의 **`낮은 칸이라는 뜻이 아니고…`**: 그 사다리를 싣는 쪽의
  머리말이 이미 같은 말을 한다.
- 직무 쪽의 **안내 문장**: 쪽 제목이 이미 직무 이름이고 상자마다 이름표가
  붙어 있다.
- 직무 쪽의 **확인된 칸 목록**: 셋까지만 적고 나머지는 "부록에 그대로
  있습니다" 로 넘긴다.

## 5. 합친 것

- `roleDeepDive` 하나가 예전 일곱 절을 받는다.
- GAP 과 ACTION 은 BASIC·STANDARD 에서 한 쪽(둘을 더해도 한 장에 들어가고,
  "아직 비어 있는 것 → 그래서 지금 이것" 이 한눈에 이어진다).
- PRO 의 서류·면접 번역 표는 ORGANIZATION VALUE 쪽으로 옮겼다.

## 6. 부록

본문에서 뺀 것이 전부 여기 있다. `.appendix { break-before: page }` 로
본문과 종이에서 갈린다.

직무군 열여섯 전부 · 어느 문항이 이 줄을 만들었는가 · 업무 방식 자세히 ·
한 번 낸 결과를 다시 쓸 수 있는가 · 직무별 증거 범위 전체 · 어떻게 만든
자료인가 · 한계 · 판본.

## 7. 인쇄를 따로 짠 이유

Web 과 PDF 는 **같은 semantic object** 를 쓰고 그리는 법만 다르다
(`assets/report-print.css` 의 `@media print`).

가장 크게 물렸던 것: **A4 글 폭은 688px 다.** 화면 반응형 분기점(860·900px)
보다 좁아서, 아무 것도 안 하면 인쇄에서 격자가 전부 한 줄로 쌓인다. 그러면
쪽수가 세 배로 부푼다. 처음 뽑은 PDF 가 BASIC 에서 22장이 나온 이유가
이것이었다. 인쇄는 폭이 고정이니 칸 수를 인쇄 규칙에서 직접 못 박는다.

그 밖에:

- 머리말·꼬리말·쪽 번호를 우리가 그린다(`scripts/v2-pdf.mjs` 의
  `displayHeaderFooter` + 우리 틀).
- 카드가 쪽을 넘어 쪼개지지 않게 `break-inside: avoid`.
- 표는 쪽마다 머리글을 다시 찍는다(`thead { display: table-header-group }`).
- 누를 수 없는 단추는 인쇄에서 감추고, 그 자리에 안내 한 줄을 남긴다.
- 바탕색을 쓰는 자리는 테두리로 바꾼다. 잉크를 아끼고 더 읽힌다.

**브라우저가 붙이는 주소와 날짜는 CSS 로 못 끈다.** 인쇄 대화상자의
'머리글과 바닥글' 설정이라, 화면에서 그 한 줄을 안내하고
(`assets/v2-app.js` 의 `.rp-act-n`), 제대로 된 A4 는 `npm run v2:pdf` 가
뽑는다.

## 7-b. 웹에서 옮겨 다니기

규격 §30 이 요구한 자리다.

- 머리에 붙는 띠(`.rpnav`) 하나. **쪽을 그린 뒤에 긁어모은다**: 등급마다
  없는 쪽(BASIC 의 조직 비교 같은 것)은 띠에도 나오지 않는다. 없는 데로
  데려가는 단추를 만들지 않는다.
- 부록은 `상세 분석 펼치기` 로 접혀 있다. **종이에서는 늘 펼친다.**
  인쇄본에서 접힌 자리는 없어진 자리와 같다. `<details>` 를 쓰지 않은
  이유가 이것이다(닫힌 `<details>` 는 인쇄 규칙으로 못 펼친다).
- 인쇄에서 띠와 단추는 사라진다. 종이에서 누를 수 없는 것을 남기지 않는다.

## 7-c. 첫 쪽을 만드는 객체 하나

규격 §37 이 요구한 모양이다.

```js
window.PCAV2Report.summary(J)
// { top_roles, key_findings, critical_gap, next_action, confidence_note }
```

**웹과 PDF 가 같은 객체를 받는다.** `window.PCA_V2_DECISION_SUMMARY` 로도
나가서, 검사와 플랫폼이 화면을 긁지 않고 같은 값을 읽는다. 여기서 점수를
만들지 않는다: 검사가 그 객체에 `score` 가 없는 것까지 센다.

## 7-d. 종이 규격

규격 §18·§19 가 못 박은 값이다.

| | 값 |
|---|---|
| 용지 | A4 세로 |
| 여백 | 18mm 위아래 · 16mm 좌우 (규격 16~20mm) |
| 글 들어가는 칸 | 178 × 261mm = 673 × 986px |
| 본문 | 11pt (규격 11~12pt) |
| 쪽 번호·머리말·꼬리말 | 우리가 그린다 |

10.5pt 로 두면 쪽수는 줄지만 종이에서 읽기가 나빠진다. 11pt 로 올리고
대신 쪽마다 들어가는 양을 줄였다.

## 8. 응시자가 적은 글을 거르는 자리

`assets/report-sanitize.js`. **그리기 직전에만 거른다**: 판정은 이미
끝났고 여기서 바꾸는 것은 화면에 나가는 글자뿐이다.

trim · 공백 정리 · HTML escape · 빈 값 확인 · 길이 한도(400자) ·
뜻 없는 입력 찾기(같은 글자 반복, `asdf` `ㅁㄴㅇㄹ` 같은 자리 두드림,
같은 토막 반복).

**뜻을 지어내지 않는다.** 걸러낼 것이 남지 않으면 그 자리를 비우고,
무엇을 의도했는지 추측해서 채우지 않는다. 걸린 입력은 본문에 내보내지
않고 `window.PCA_V2_INPUT_WARNINGS` 에 안쪽 경고로만 남긴다.

## 9. 검사

| 명령 | 세는 것 |
|---|---|
| `npm run report:30s` | 첫 쪽에서 서른 초 안에 넷을 답할 수 있는가. 3분 안에 넷을 더 알 수 있는가. 금지한 표현·권장 말투. 뜻 없는 입력이 본문에 새지 않는가. 웹 띠가 가리키는 쪽이 실제로 있는가. 첫 쪽이 객체 하나에서 나오는가 (31항목) |
| `npm run v2:pdf` | 등급별 본문 장수 · 한 묶음이 한 장인가 · 전체가 스무 장 안인가 |
| `npm run v2:flow` | 응시부터 결과지까지 (45항목) |
| `npm run v2:shots` | 쪽마다 화면 캡처 |
| `npm run copy:audit` | 문체 버릇 |

30초·3분 기준을 **눈으로 보고 됐다고 하지 않는다.** `scripts/report-30s.mjs`
가 첫 쪽에서 Top 3 직무 이름과 가장 큰 공백 이름과 지금 할 일 문장을
실제로 뽑아내 확인하고, 문항 번호와 측정 방법 설명이 첫 쪽에 없는 것까지
센다. 일부러 뜻 없는 입력(`ㅁㅁㅁㅁㅁ` · `asdf`)을 섞어 넣어, 그것이
본문에 새지 않고 안쪽 경고로만 남는지도 본다.

## 10. 아직 남은 것

- **기계공학 하나**다. 다른 전공으로 넓히지 않았다.
- **Global Country Layer 를 켜지 않았다.** 나라 자료가 없는 나라 UI 를
  만들지 않는다.
- **서버 `attempts` 에 붙이지 않았다.** 결과지는 아직 브라우저 안에서만
  만들어진다. 플랫폼 스키마도 이번에 넓히지 않았다.
- 쪽마다 글 높이가 A4 한 장(986px)에 **가깝게** 차 있다. 응시자가 아주
  긴 글을 적으면 한 쪽이 두 장으로 넘어갈 수 있고, `npm run v2:pdf` 가
  그때 실패로 알려 준다.
- 규격 §30 은 **사이드** 내비게이션을 적었는데 **머리에 붙는 띠**로
  만들었다. 결과지가 한 칼럼이라 옆에 띠를 세우면 글 폭이 좁아진다.
  옮겨 다니는 일은 같게 되지만 모양은 규격의 그림과 다르다.
- 브랜드 표기(`Careermetri` · 커리어메트리)와 도메인(`careermatri`)이
  아직 갈려 있다. 도메인은 2026-10-04 에 바로잡았고, 브랜드 쪽을 맞출지는
  따로 정할 일이다.
