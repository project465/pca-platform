# 58-2. 응시 화면이 하는 일 (STEP 6)

## 주소와 파일

```
/v3/start          검사 시작. 학업 단계와 계열을 받고 응시를 연다
/v3/[attemptId]    지금 화면 하나. ?s= 는 몇째인가
```

| 파일 | 하는 일 |
|---|---|
| `src/app/v3/start/page.tsx` | 받는 것과 걸리는 시간을 먼저 적는다 |
| `src/app/v3/start/actions.ts` | 응시를 연다. **등급은 이용권이 정한다** |
| `src/app/v3/[attemptId]/page.tsx` | 화면 하나를 서버에서 만든다 |
| `src/app/v3/[attemptId]/screen.tsx` | 고르기와 저장과 이동 |
| `src/app/v3/[attemptId]/actions.ts` | 서버에 쓰는 자리 일곱 |
| `src/lib/me-v3/runtime/menus.ts` | 응시 중에 정해지는 보기 메뉴 |

## 등급을 화면이 정하지 않는다

폼이 보낼 수 있는 것은 학업 단계와 전공계열뿐이다. 등급은
`v3Grants()` 가 읽은 이용권이 정하고, 이용권이 없으면 무료 등급 하나다.
받을 수 있게 두면 언젠가 주소로 등급을 올리는 길이 생긴다
(`openV2Attempt()` 가 등급을 인자로 받지 않는 것과 같은 설계다).

## 서버에 쓰는 자리

일곱이고 전부 `requireUser()` 와 `attemptOf(id, user.id)` 를 지난다.
**화면이 보낸 응시 번호를 믿지 않는다.** 남의 번호를 넣으면 아무것도
쓰이지 않고 거짓이 돌아온다. 끝난 응시에도 쓰지 않는다: 제출한 뒤에
쓰이면 그때 낸 판정과 응답이 어긋난다.

| 자리 | 하는 일 |
|---|---|
| `answerAction` | 응답 하나 |
| `noteAction` | 번역 단계의 한 줄 |
| `picksAction` | 축마다 고른 근거 |
| `packAction` | 깊게 볼 산업이나 역할. **없는 코드는 막는다** |
| `profileAction` | 학업 단계와 계열 고치기 |
| `cursorAction` | 이어보기 자리 |
| `finishAction` | 제출과 판정 한 줄 |

**응답을 되돌려 보내지 않는다.** 화면이 이미 들고 있고, 되돌려 보내면
늦게 도착한 응답 하나가 방금 고친 답을 덮는다. 돌려보내는 것은 들어왔는지뿐이다.

## 보기 메뉴

문항 은행에는 보기가 비어 있는 자리가 있고 거기에는 `보기 메뉴는 계열
module 이 정한다` 고 적혀 있다. 보기가 **응시 중에 정해지기** 때문이다.

| 문항 | 보기가 어디서 오는가 |
|---|---|
| 강제 선택 둘 | 격자에서 같은 값으로 묶인 두 영역 |
| 영역 태그 둘 | 열두 기술영역 |
| 목표 셋 | 지금 열려 있는 산업 여덟 · 역할 일곱 · 조직 유형 일곱 |
| 번역 열 단계 | 단계마다의 보기 넷에서 다섯, 그리고 한 줄 칸 |

이것을 문항 은행에 적어 두면 산업을 하나 더 늘리는 일이 **동결된 문항
은행을 고치는 일**이 된다. 그래서 `runtime/menus.ts` 에 둔다.

**보기 넷은 여기서 만들지 않는다.** `level_options` 는 은행이 유일한
출처이고 뜻은 `scoring/ownership.ts` 에 있다. 화면은 그 둘을 읽어 그대로
내놓는다. 다른 말로 바꿔 적으면 같은 응답이 다른 뜻이 된다.

## 한 화면에 한 문항

예외 둘만 둔다. 영역 격자는 한 영역의 관심과 경험과 학습 의향을 **함께
읽어야** 뜻이 서고, 역할·조직 선호 열넷은 서로 견주는 줄이라 한 자리에
세운다. 나머지는 문항 하나가 화면 하나다: 보기 넷을 빠르게 넘기면
오선택이 쌓인다.

**고른다고 다음 화면으로 넘어가지 않는다.** 넘어가면 잘못 누른 것을
고칠 자리가 없고, 그 오선택이 그대로 판정에 들어간다. 넘기는 것은
`다음` 을 누를 때다.

## 성능

문항이 294개인데 **지금 화면의 것만 내려보낸다.** 응시 화면의 클라이언트
묶음이 3.8KB 다. 팩 문항은 고르기 전에는 계획에 들어가지도 않는다
(`v3:ui` 11절이 센다).

## 검사

`npm run v3:ui` 열다섯 가지다. DB 없이 계획만으로 센다.

```
은행의 문항이 전부 어느 화면엔가 선다            294개
화면에 선 문항은 전부 보기를 받는다              294개
보기 넷은 문항 은행의 것을 그대로 쓴다
화면 문면에 내부 코드가 없다
한 화면에 한 문항이다                          격자와 선호만 예외
BASIC 에는 심화와 번역과 팩 화면이 없다
강제 선택은 묶였을 때만 서고 보기가 그 두 영역이다
역할 선호와 조직 선호가 모두 화면에 선다          역할 7 · 조직 7
산업 여덟과 역할 일곱 전부를 고를 수 있다
고르기 전에는 팩 문항이 화면에 없다
심화 영역은 여덟 축을 모두 받는다
```

첫 줄이 이 검사를 만든 까닭이다. 조직 선호 일곱이 **어느 화면에도 서지
않고 있었다**: 화면과 채점이 둘 다 `PR_OC` 로 찾고 있었고 은행의 번호는
`PO_OC` 다. 문항을 쓴 사람도 화면을 짠 사람도 눈으로는 못 찾는다.
