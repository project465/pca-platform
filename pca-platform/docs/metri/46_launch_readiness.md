# 런칭 준비 — 승인된 가격과 막힌 갈래

사업 결정이 들어왔다. 가격이 정해졌고 글로벌 도메인 소유가 확인됐다.
이 문서는 그것을 반영한 뒤 **무엇이 열렸고 무엇이 남았는지**를 적는다.

```bash
npm run launch:check     # 끝낸 것 31가지 · 막힌 것 11가지 · 막힌 갈래 7 / 12
npm run launch:e2e       # 결제·무료·환불·메일 47가지
npm run mail:check       # 대행사만 꽂으면 나가는가 11가지
npm run backup:restore   # 받고 · 붓고 · 세고 · 기록까지
npm run domains:verify   # 배포 뒤 DNS·인증서·리디렉션
```

## 1. 승인된 런칭 가격

| | BASIC | STANDARD | PRO |
|---|---|---|---|
| 한국 | 무료 | 14,900원 | 21,900원 |
| 글로벌 | Free | $14.99 | $24.99 |

**가격 정본은 `products` 하나다.** 새 표를 만들지 않았고, 화면과 주문과
검사가 전부 그 표를 읽는다. 바꿀 곳은 `db/schema_phase2_3.sql` 한 자리다.

**세 상태를 이름으로 가른다.**

| 상태 | 뜻 | 화면 |
|---|---|---|
| `PAID_APPROVED` | 값이 승인된 유료 | 금액 |
| `FREE_APPROVED` | **0 으로 정한 무료** | 무료로 시작하기 |
| `PRICE_NOT_APPROVED` | 아직 못 정했다 | 값이 정해지지 않았습니다 |

앞의 둘에 전부 `APPROVED` 가 들어간 것이 일부러다. `FREE` 라고만 적어
두었더니 코드를 읽는 쪽에서 그것이 승인된 값인지 기본값인지 매번 되짚어야
했다. **금액만 보고 열지 않는다**: 무료 길은 `FREE_APPROVED` 만 연다.

## 2. $14.99 를 14.99 로 저장하지 않는다

`products.amount` 가 `INTEGER` 라서 14.99 를 넣으면 **14 로 잘린다.**
그러면 $14.99 짜리가 $0.14 에 팔린다. 한국만 팔 때는 KRW 가 쪼개지지
않아 이 차이가 보이지 않고, 글로벌을 여는 날 드러난다.

그래서 금액을 **통화의 최소 단위 정수**로 들고 다닌다(`src/lib/money.ts`).

```
KRW 14900  →  ₩14,900
USD  1499  →  $14.99
```

쪼개지는 자릿수는 통화만 안다. 모르는 통화는 두 자리로 본다: 세상에서
그쪽이 훨씬 흔하다.

## 3. BASIC 무료 흐름

```
가격표 BASIC "무료로 시작하기"(POST)
  → 로그인 안 했으면 가입으로, 끝나면 돌아온다
  → 서버가 0원 주문과 이용권을 만든다
  → 응시
```

등급을 올리는 문이 되지 않게 셋으로 막는다.

1. 화면이 보낼 수 있는 것은 **상품 코드 하나**다. 등급은 보낼 수 없다
2. 그 상품이 `FREE_APPROVED` 가 아니면 거절한다. 유료 코드를 적어 넣어도
   여기서 걸린다
3. 등급은 상품이 정하고 이용권이 들고 간다. 주소의 `?tier=PRO` 는 여기까지
   오지 못한다

**중복은 DB 가 막는다.** 무료 주문의 번호가 사람과 상품으로 정해져 있어서
(`F<user><PRODUCT>`), 두 요청이 같은 순간에 들어와도 두 번째가 그 자리에서
거절되고 이미 있는 주문으로 간다. 읽고 나서 쓰면 둘 다 통과한다.
`launch:e2e` 가 세 번 동시에 눌러 보고 이용권이 하나인지 센다.

## 4. 도메인 (앞서 틀린 것을 바로잡았다)

`careermatri.com` 은 **우리 것이다.** 소유자가 확인해 주었고
`site_configs.ownership = 'confirmed'` 에 적혀 있다. 정규 주소는
`https://careermatri.com`.

앞서 이 저장소는 그 도메인을 제3자 소유라고 적었다. 모르는 IP 가
응답한다는 것만 보고 적었는데, **DNS 가 어디를 가리키는지와 도메인이
누구 것인지는 별개다.** 사 둔 도메인을 등록대행자의 주차 페이지나 CDN 에
걸어 두면 모르는 IP 가 응답한다.

판단하는 자리를 옮겼다.

| 무엇 | 누가 말하는가 |
|---|---|
| 소유 | 소유자. `site_configs.ownership` |
| 지금 그 주소에 떠 있는 것 | `npm run domains:check` (DNS) |
| 우리 운영이 떠 있는가 | `npm run domains:verify` (배포 뒤) |

**소유가 확인돼도 켤 수 있는 것은 아니다.** 배포한 뒤에 DNS 가 운영을
가리키는지 · 인증서 · `www` 리디렉션 · 정규 주소를 열어 봐야 안다.
`domains:verify` 가 그 넷을 보고, **모르는 것을 실패로 세지 않는다**:
배포 전에는 닿지 않는 것이 정상이다. 이 컨테이너는 프록시를 거치므로
4xx 를 모름으로 둔다(프록시의 403 을 도메인의 대답으로 읽고 한 번 틀렸다).

정규 주소를 읽는 자리를 한 곳으로 모았다(`src/lib/urls.ts`). 결제 콜백 ·
메일 링크 · 비밀번호 재설정 · 주소 확인이 전부 이 값을 쓴다. **요청
호스트를 그대로 쓰지 않는 까닭**은 받는 사람이 다른 날 다른 자리에서
그 링크를 열기 때문이다. 화면 안에서 끝나는 이동만 요청 호스트를 따른다.

`careermetri` 는 공식 브랜드 도메인으로 쓰지 않는다.

## 5. 사업자 표시를 운영 화면에서 넣는다

법이 요구하는 값이고 **사업자가 직접 넣는다.** 환경변수에만 두면 한 글자
고치는 데 배포가 필요하고, 그러면 런칭이 개발 일정에 묶인다.

`/admin/business` 에서 넣고, 읽는 자리는 하나다(`settings.get`): 표에
값이 있으면 그것을, 없으면 환경변수를, 둘 다 없으면 비어 있다고 말한다.
화면이 어느 쪽에서 온 값인지도 같이 적는다.

**비밀은 여기 담지 않는다.** 결제 열쇠와 메일 비밀번호는 환경변수에
남는다: 운영 화면에서 고칠 수 있게 두면 그 화면이 열쇠 보관함이 되고,
운영자 계정 하나가 새면 돈길이 통째로 열린다.

## 6. 막는 것을 갈래로 나눴다

규격 §9 가 적어 준 열두 갈래 그대로다.

```
DOMAIN  PAYMENT  EMAIL  LEGAL  BUSINESS_INFO  DATABASE
BACKUP_RESTORE  PRICE  LOCALIZATION  REPORT  PDF  SUPPORT
```

**갈래가 있어야 누가 고칠지 갈린다.** "열한 가지가 막혀 있다" 는 읽은
사람이 무엇부터 할지 모르고, `PAYMENT` 하나와 `BUSINESS_INFO` 하나는
전화 한 통과 서류 한 장으로 갈린다.

지금 열린 갈래: `PRICE` · `LOCALIZATION` · `REPORT` · `PDF` ·
`BACKUP_RESTORE`. **가격은 더 이상 막는 것이 아니다.**

## 7. 백업은 실제로 되돌려 봤다

`npm run backup:restore` 가 한 바퀴를 돈다.

```
받는다 → 읽어 본다 → 빈 DB 를 만든다 → 붓는다
→ 일곱 표의 줄 수를 운영과 대조한다 → 제약 여덟 가지가 살아 있는지 본다
→ 결과지가 실제로 열리는지 본다 → 기록을 남긴다
```

**제약을 세는 것이 중요하다.** 표만 돌아오고 제약이 안 돌아오면, 복구한
DB 에서 같은 결제가 두 번 적히고 미승인 가격에 금액이 붙는다. 그런 DB 는
되돌아온 것이 아니다.

**사람이 손으로 적는 날짜를 믿지 않는다.** 기록은 이 스크립트가 끝까지
돈 자리에서만 `site_settings` 에 생기고, 런칭 화면이 그것을 읽는다.
어느 DB 에서 해 봤는지도 함께 적어서, 개발 DB 에서 한 번 돌린 것을
운영 백업이 돌아온다는 말로 쓰지 않는다.

지금 상태: 절차는 돌았고(2026-10-05, 개발 DB), **운영 DB 에서는 아직**
이라 WARNING 이다.

## 8. 메일은 대행사만 꽂으면 나간다

말로 적지 않고 **실제로 보내 봤다.** `npm run mail:check` 가 가짜 SMTP
서버를 띄우고 거기로 보낸다. 네트워크 건너편만 가짜이고 나머지는 운영과
같은 길이다: 대기열에 쌓고 · 문면을 만들고 · nodemailer 로 보내고 ·
`sent` 로 표시한다.

열한 가지를 본다. 다섯 가지가 쌓이고 나가는가 · 받는 쪽에 도착하는가 ·
제목과 링크가 들어 있는가 · **열쇠가 든 메일이 표에 적히지 않는가** ·
자격증명이 없으면 보내지 않고 그대로 두는가 · 여섯 가지가 두 언어로 서는가.

## 9. 운영 조각을 나눴다

`deploy/docker-compose.prod.yml`. **각 조각이 서로 다른 이유로 죽는다**:
앱은 배포할 때, DB 는 디스크가 찰 때, 파일은 볼륨을 못 붙일 때, 메일과
결제는 남의 사정으로. 한 덩어리로 두면 어느 쪽이 죽었는지 로그를 다
뒤져야 안다.

| 조각 | 어디 |
|---|---|
| application | `app` |
| PostgreSQL | `db` (또는 관리형. 그러면 `db` 를 지운다) |
| report/PDF | 이름 붙인 볼륨 `reports` |
| email | 밖. SMTP 대행사 |
| payment | 밖. PortOne |
| secrets | `.env.production` 또는 호스팅의 비밀 관리 |
| logs | `json-file` 20MB × 5 |
| backup | `backup` 이 하루 한 번 |

**결과지 PDF 를 컨테이너 안에 두지 않는다**: 배포할 때마다 사라지고,
산 사람이 어제 받은 PDF 를 다시 못 받는다.

**받아 둔 백업을 같은 디스크에 두는 것은 임시다.** 디스크가 통째로 죽는
날 백업도 같이 죽는다. 밖으로 복사하는 것은 운영 담당이 정한다.

## 10. 아직 아닌 것

- 운영 인프라에 올리지 않았다. 이 자리의 DB 는 세션이 끝나면 사라진다
- 실제 PG 로 한 건도 결제하지 않았다. 심사 전이다
- 메일을 **바깥으로** 한 통도 보내지 않았다. 대행사가 없다
- 운영 DB 에서 복구를 해 보지 않았다
- `careermatri.co.kr` 의 소유가 확인되지 않았다
- 사업자 표시 일곱 칸이 비어 있다
- 영문 약관 본문이 없다
