# C. 새 기계공학 Career Taxonomy · E. 직무 경계 비교표

## 1. 왜 세 축인가

하나의 목록으로 기계공학 진로를 가르면 반드시 섞인다. 같은 사람을
가리키는 말이 셋이기 때문이다.

> 자동차 부품사 선행개발팀에서 브래킷 내구 해석을 하는 석사 2년차.

이 사람은 **무엇을 아는가**로 보면 구조·내구 해석이고, **무슨 기능을
맡는가**로 보면 해석·예측이고, **어디에서 일하는가**로 보면 부품사 선행
개발 조직이다. 세 질문의 답이 서로 독립이므로 축을 셋으로 둔다.

```
기술영역(TD) × 역할기능(RF) × 조직환경(OC)  =  하나의 자리
```

직무명은 이 조합의 **별칭**으로 둔다. 공고에 적히는 이름은 산업과 회사
규모에 따라 달라지므로, 별칭 표를 따로 들고 간다. 그래야 "구조해석" 과
"CAE" 와 "내구개발" 이 같은 자리를 가리킨다는 것을 제품이 안다.

## 2. 축 1. 기술영역 TD (열둘)

한 줄 정의는 **그 영역이 책임지는 판단**으로 적었다. 무엇을 다루는지보다
무엇을 정하는지가 영역을 가른다.

| 코드 | 이름 | 책임지는 판단 | 하위 갈래 | 공고에 적히는 이름 |
|---|---|---|---|---|
| TD01 | 기구·제품 설계 | 형상 · 치수 · 재질 · 공차 · 체결을 확정한다 | 기구설계 · 제품설계 · 금형·사출 설계 · 치공구 설계 | 기구설계, 제품설계, 기계설계, 금형설계 |
| TD02 | 구조·내구 해석 | 하중 아래에서 깨지는가 · 변형하는가 · 몇 번을 버티는가 | 선형·비선형 구조 · 피로·내구 · 충돌·좌굴 · 최적화 | 구조해석, CAE, 내구개발, 강도해석 |
| TD03 | 열·유체 시스템 | 열을 어디로 빼고 유량과 압력을 어떻게 맞추는가 | 열설계 · 공조·냉각 · 유동해석 · 에너지 시스템 | 열설계, 열해석, CFD, 공조설계, 에너지시스템 |
| TD04 | 동역학·진동·NVH | 어느 주파수에서 흔들리고 어디로 전달되는가 | 모달·진동 · 소음 · 다물체 동역학 · 승차감 | NVH, 진동해석, 동역학, 소음진동 |
| TD05 | 제어·메카트로닉스 | 어떤 구동과 제어로 요구 동작을 만드는가 | 서보·구동 선정 · 제어 설계 · 로봇·셀 통합 · 안전회로 | 제어설계, 메카트로닉스, 로봇엔지니어, 자동화설계 |
| TD06 | 재료·내구·파손 | 어떤 재질과 처리로 가고, 왜 깨졌는가 | 재질 선정 · 열처리·표면 · 파손해석 · 마찰·마모 | 재료개발, 파손분석, 금속재료, 신뢰성(재료) |
| TD07 | 시험·계측 | 무엇을 어떻게 재서 판정하는가 | 시험계획 · 지그·계측 · 환경·내구 시험 · 불확도 | 시험평가, 계측, 성능시험, 신뢰성시험 |
| TD08 | 생산·공정기술 | 어떤 공법과 조건으로 반복 생산하는가 | 공법 선정 · 가공·성형 조건 · 치공구·설비 도입 · 공정창·수율 | 생산기술, 공정기술, 제조기술, 양산기술 |
| TD09 | 설비·보전 | 설비를 어떻게 멈추지 않게 하는가 | 진단 · 보전계획 · 개조 · 예비품 | 설비기술, 설비보전, 유틸리티, 플랜트 정비 |
| TD10 | 품질·신뢰성 | 양산과 수명 내내 요구가 지켜지는가 | 공정품질(SPC·Cpk·8D) · 신뢰성(수명·가속·FMEA) · 규격·인증 | 품질보증, 품질관리, 신뢰성, 인증 |
| TD11 | 시스템·요구사항 | 요구를 어떻게 쪼개 누구에게 할당하고 추적하는가 | 요구 분해 · 인터페이스 · 검증 배정 · 형상·변경 관리 | 시스템엔지니어, 요구사항 엔지니어, 제품기획(기술) |
| TD12 | 엔지니어링 자동화·데이터 | 반복 계산과 판정을 어떻게 남겨 다시 쓰게 하는가 | 스크립트·자동화 · 해석 자동화 · 데이터 파이프라인 · 대리모델 | CAE 자동화, 엔지니어링 데이터, 시뮬레이션 자동화 |

### 왜 열둘인가

- **쪼갠 것**: CAE 한 칸을 TD02 · TD03 · TD04 로 갈랐다. 구조 해석자와
  열유동 해석자와 NVH 담당자는 쓰는 이론과 도구와 검증 방법이 다르고,
  채용도 따로 돈다.
- **병합한 것**: 생산기술과 공정기술을 TD08 한 칸으로 합쳤다. 회사마다
  경계가 반대라서 문항으로 가를 수 없고, 가르는 것이 응시자에게 주는
  정보도 없다. 신제품 이관과 양산 유지의 차이는 역할축에서 본다.
- **옮긴 것**: R&D · 연구원 · 컨설팅 · 현장지원을 TD 에서 뺐다. 그것들은
  영역이 아니고 역할과 조직환경이다.
- **더한 것**: TD04 동역학·진동·NVH. 기계진동이 학부 필수에 가깝고 자동차 ·
  가전 · 건설기계에 전담 조직이 있는데 자리가 없었다.
- **교차로 표기한 것**: TD12 는 다른 영역 위에 얹히는 수단이다. 혼자 설
  수도 있고(해석 자동화 전담), TD02 나 TD08 와 함께 설 수도 있다.

### 이번 범위에서 빼는 것

기계공학 공고에 있지만 이번 판에서 다루지 않는다고 적어 둔다. **없는 것을
있는 척하지 않는다.**

배관·플랜트 설계(배관 응력 · 코드 계산) · 조선·해양 구조 · 항공 구조 ·
의료기기 인허가 · 반도체·디스플레이 장비의 산업 특화 공정 · 기술영업과
제안 · 지식재산(특허) 실무.

## 3. 축 2. 역할기능 RF (일곱)

같은 기술영역 안에서 **무엇을 맡는가**를 가른다. 제품 수명 단계와 겹치지만
단계 이름을 쓰지 않는다. 사람이 맡는 기능으로 적는다.

| 코드 | 이름 | 한 줄 | 산출물의 성격 | 성공의 모양 |
|---|---|---|---|---|
| RF1 | 설계·개발 | 만들 것을 정한다 | 도면 · 사양 · 모델 | 만들 수 있고 요구를 만족하는 안 하나 |
| RF2 | 해석·예측 | 만들기 전에 안다 | 해석 보고 · 예측값 | 시험과 맞고 설계를 바꾼 근거 |
| RF3 | 시험·검증 | 만든 것이 맞는지 본다 | 시험성적 · 판정 | 판정이 재현되고 불확도가 적힌 결과 |
| RF4 | 공정·양산 | 반복해서 만들게 한다 | 공정도 · 작업표준 · 조건 | 수율과 택트가 목표 안 |
| RF5 | 운전·보전 | 멈추지 않게 한다 | 보전계획 · 고장 보고 | 가동률과 재발 없음 |
| RF6 | 통합·조정 | 여러 사람의 결정을 하나로 묶는다 | 요구·일정 · 변경 기록 | 요구 충족률과 일정 |
| RF7 | 탐색·연구 | 아직 답이 없는 것을 좁힌다 | 논문 · 특허 · 시작품 · 방법 | 질문이 좁혀지고 방법이 남음 |

**RF7 이 이전 판의 R&D 와 연구원을 흡수한다.** 그래서 "R&D 로 갈까 설계로
갈까" 라는 섞인 질문이 "어느 기술영역에서 탐색 기능을 맡을까" 로 바뀐다.

## 4. 축 3. 조직환경 OC (일곱)

기존 `org-types.json` 일곱을 그대로 쓰되 민간기업을 둘로 가른다. 완성품
회사와 부품·장비·소재 회사는 기계공학 전공자가 맡는 범위가 다르다.

| 코드 | 이름 | 무엇이 성과인가 | 같은 영역에서 달라지는 점 |
|---|---|---|---|
| OC1 | 완성품 기업 | 성능 · 원가 · 납기 · 필드 품질 | 요구를 받고 통합을 많이 한다 |
| OC2 | 부품·장비·소재 기업 | 고객 사양 충족 · 수율 · 단가 | 한 영역을 깊게 하고 고객 검증을 받는다 |
| OC3 | 엔지니어링·기술 서비스 | 기한 · 고객 결정에 쓰임 · 재의뢰 | 남의 문제를 받아 가정을 공개하고 답을 낸다 |
| OC4 | 출연연·국책연구 | 과제 목표 · 기술 수준 · 이전 가능성 | 과제 서식과 중간 평가가 일정을 정한다 |
| OC5 | 대학·연구실 | 새로움 · 재현성 · 학술 기여 | 방법의 타당성을 스스로 세워야 한다 |
| OC6 | 공공·규제·인증 | 기준 적합 판단과 그 근거 | 판단의 추적 가능성이 산출물이다 |
| OC7 | 스타트업·소규모 제조 | 작동하는 물건과 자금 소진 전 출시 | 한 사람이 여러 RF 를 겹쳐 맡는다 |

## 6. E. 직무 경계 비교표

`공통점 | 실제 차이 | 대표 업무 | 산출물 | 판단 | 구분 가능한 질문` 으로
적었다. **마지막 칸이 새 문항의 씨앗**이다. 구분 가능한 질문은 둘 중
어느 쪽을 했는지가 답으로 갈리게 만들었다.

### 6-1. 기계설계(TD01·RF1) 대 구조해석(TD02·RF2)

| | 기계설계 | 구조해석 |
|---|---|---|
| 공통점 | 하중과 재질로 치수를 따진다 | 같다 |
| 실제 차이 | **치수를 바꿀 권한**을 가진다 | **예측의 타당성**을 책임진다 |
| 대표 업무 | 공차 배분 · 체결 선정 · DFM 검토 | 이상화 · 경계조건 · 수렴 · 시험 대조 |
| 산출물 | 도면 · BOM · 설계계산서 | 해석 보고서 · 모델 · 수명 예측 |
| 판단 | 두께를 올릴지 리브를 넣을지 | 이 결과를 믿을 수 있는지 |
| 구분 질문 | **그 결과로 도면 치수가 바뀌었습니까** | **그 결과를 손계산이나 시험과 대조해 보셨습니까** |

### 6-2. 선행개발(RF7) 대 기계설계(RF1)

| | 선행개발 | 기계설계 |
|---|---|---|
| 공통점 | 형상과 사양을 만든다 | 같다 |
| 실제 차이 | **사양이 아직 없다.** 요구 자체를 만든다 | 사양을 받아 확정한다 |
| 대표 업무 | 개념안 여럿 · 가능성 실험 · 특허 검토 | 양산 가능한 한 안으로 수렴 |
| 산출물 | 개념안 비교 · 시작품 · 기술 보고 | 도면 · BOM · 변경 이력 |
| 판단 | 이 방향이 될 법한지 | 이 안으로 양산할 수 있는지 |
| 구분 질문 | **요구사항이 정해지지 않은 상태에서 시작한 과제였습니까** | **그 안이 도면과 부품표까지 갔습니까** |

### 6-3. 선행개발(RF7) 대 해석(RF2)

| | 선행개발 | 해석 |
|---|---|---|
| 공통점 | 모르는 것을 계산과 실험으로 좁힌다 | 같다 |
| 실제 차이 | **질문을 만든다** | 주어진 질문에 **수치로 답한다** |
| 대표 업무 | 가설 · 실험 설계 · 실패 해석 | 모델링 · 조건 설정 · 검증 |
| 산출물 | 결론과 다음 질문 | 예측값과 그 신뢰 범위 |
| 판단 | 무엇을 더 확인해야 하는지 | 모델이 현실을 얼마나 담는지 |
| 구분 질문 | **무엇을 확인할지 본인이 정했습니까** | **그 모델의 가정을 적어 두셨습니까** |

### 6-4. 생산기술 대 공정기술 (둘 다 TD08·RF4)

| | 생산기술(이관) | 공정기술(유지) |
|---|---|---|
| 공통점 | 공법과 조건을 정한다 | 같다 |
| 실제 차이 | **처음 흘린다.** 설비와 치공구를 들인다 | **흐르고 있는 것**의 조건과 수율을 지킨다 |
| 대표 업무 | 공법 선정 · 치공구 제작 · 초도 양산 | 조건 실험 · 공정창 · 수율 분석 |
| 산출물 | 공정도 · 작업표준 · 설비 사양 | 조건 변경 기록 · 관리 기준 · 수율 보고 |
| 판단 | 이 공법으로 만들 수 있는지 | 어느 인자를 건드려야 수율이 오르는지 |
| 구분 질문 | **새 제품이나 새 설비를 처음 흘려 본 경험입니까** | **이미 돌고 있는 공정의 조건을 바꿔 본 경험입니까** |

### 6-5. 시험·검증(TD07) 대 품질·신뢰성(TD10)

| | 시험·계측 | 품질·신뢰성 |
|---|---|---|
| 공통점 | 기준에 맞는지 본다 | 같다 |
| 실제 차이 | **재는 방법**을 책임진다 | **기준과 재발 방지**를 책임진다 |
| 대표 업무 | 지그 · 센서 · 샘플링 · 불확도 | 고장모드 · 수명 분포 · 시정조치 · 인증 |
| 산출물 | 시험계획 · 성적서 · 생데이터 | 관리계획 · 8D · 신뢰성 보고 |
| 판단 | 이 측정을 믿을 수 있는지 | 이 수준을 출하해도 되는지 |
| 구분 질문 | **측정값의 불확도나 반복성을 따져 보셨습니까** | **같은 불량이 다시 나지 않게 기준을 바꿔 보셨습니까** |

### 6-6. 시스템엔지니어링(TD11·RF6) 대 기술 PM(TD11·RF6)

둘을 같은 칸에 두면 안 되는 쌍이다. 영역은 같고 **책임의 대상**이 다르다.

| | 시스템엔지니어링 | 기술 PM |
|---|---|---|
| 공통점 | 여러 팀의 결정을 묶는다 | 같다 |
| 실제 차이 | **요구와 인터페이스**를 책임진다 | **일정 · 자원 · 위험**을 책임진다 |
| 대표 업무 | 요구 분해 · 할당 · 검증 배정 · ICD | 공정표 · 자원 배분 · 변경 승인 · 보고 |
| 산출물 | 요구사양서 · 추적표(RTM) · 검증계획 | 일정 · 리스크 등록부 · 회의 결정 기록 |
| 판단 | 이 요구가 어디서 검증되는지 | 무엇을 포기하고 무엇을 지킬지 |
| 구분 질문 | **요구와 검증을 짝지어 표로 관리해 보셨습니까** | **일정이 밀릴 때 무엇을 뺄지 정해 보셨습니까** |

### 6-7. 대학·출연연 연구원(OC4·OC5) 대 기업 선행개발(OC1·OC2)

| | 연구원 | 기업 선행개발 |
|---|---|---|
| 공통점 | 답이 없는 문제를 다룬다 | 같다 |
| 실제 차이 | **새로움과 재현성**이 성과다 | **제품이 될 가능성**이 성과다 |
| 대표 업무 | 선행연구 정리 · 방법 설계 · 논문 | 개념 검증 · 원가·양산성 선검토 · 특허 |
| 산출물 | 논문 · 학위 · 과제 보고 | 기술 보고 · 시작품 · 사양 초안 |
| 판단 | 이 방법이 타당한지 | 이것이 2년 뒤 제품에 들어갈 수 있는지 |
| 구분 질문 | **선행 연구와 비교해 무엇이 새로운지 적어 보셨습니까** | **원가나 양산성 때문에 방향을 바꿔 보셨습니까** |

### 6-8. 시스템엔지니어링(TD11) 대 선행개발(RF7)

| | 시스템엔지니어링 | 선행개발 |
|---|---|---|
| 공통점 | 사양을 만든다 | 같다 |
| 실제 차이 | **이미 정해진 상위 요구**를 쪼갠다 | 상위 요구를 **새로 제안**한다 |
| 대표 업무 | 할당 · 추적 · 변경 영향 분석 | 가능성 탐색 · 개념 비교 |
| 산출물 | 추적표 · 인터페이스 정의 | 개념안 · 실험 결과 |
| 판단 | 이 변경이 어디까지 번지는지 | 이 방향이 될 법한지 |
| 구분 질문 | **상위 요구를 하위 사양으로 쪼개 본 경험입니까** | **요구 자체를 제안해 본 경험입니까** |

### 6-9. 열·유체(TD03) 대 구조·내구(TD02) · 둘 다 해석일 때

| | 열·유체 해석 | 구조 해석 |
|---|---|---|
| 공통점 | 격자를 만들고 경계조건을 정하고 수렴을 본다 | 같다 |
| 실제 차이 | **난류와 상변화와 에너지 수지**가 쟁점 | **접촉과 재료 비선형과 피로**가 쟁점 |
| 대표 업무 | 난류 모델 선택 · y+ 관리 · 열저항망 · P-Q 작동점 | 이상화 · 접촉 · S-N 과 누적손상 |
| 산출물 | 온도·유속 분포 · 압력손실 곡선 | 응력 분포 · 수명 예측 |
| 판단 | 에너지 수지가 닫히는지 | 평가 기준을 무엇으로 둘지 |
| 구분 질문 | **난류 모델이나 열전달 계수를 고른 적이 있습니까** | **피로 수명이나 안전계수 기준을 적용한 적이 있습니까** |

### 6-10. 설비·보전(TD09) 대 생산·공정(TD08)

| | 설비·보전 | 생산·공정 |
|---|---|---|
| 공통점 | 설비 앞에서 문제를 푼다 | 같다 |
| 실제 차이 | **설비의 상태**를 책임진다 | **제품의 조건과 수율**을 책임진다 |
| 대표 업무 | 진동진단 · 보전계획 · 부품 교체 | 조건 실험 · 공정창 · 불량 분석 |
| 산출물 | 고장 이력 · 보전 주기 · 개조 | 작업표준 · 조건표 · 수율 보고 |
| 판단 | 지금 세울지 더 돌릴지 | 어느 인자를 바꿀지 |
| 구분 질문 | **설비를 세우거나 교체할 시점을 판단해 본 적이 있습니까** | **제품 조건을 바꿔 수율이나 품질을 움직여 본 적이 있습니까** |

## 7. 이 taxonomy 가 바꾸는 것

1. **동점이 구조적으로 줄어든다.** 열여섯을 한 줄로 세워 비교하지 않고,
   영역 열둘에서 묶음을 만들고 역할로 가른다.
2. **같은 사람이 여러 칸에 쪼개지지 않는다.** 선행개발 구조해석자는
   `TD02 × RF7 × OC2` 한 자리에 선다.
3. **공고와 말이 맞는다.** 별칭표가 공고 제목과 조합을 잇는다.
4. **없는 것을 없다고 말할 수 있다.** 범위에서 뺀 영역을 명시했다.
