# 학교 진입은 등급을 고르지 않는다. 늘 PRO 다 (2026-10-13)

추가 확정 1을 코드로 옮긴 기록이다. **개인 B2C 는 BASIC · STANDARD · PRO
셋을 그대로 판다.** 바뀐 것은 학교 계약으로 들어온 응시뿐이다.

```
/campus/pcu → 학과 → 검사 시작 → PRO → Result → PDF
```

## 막는 자리는 서버 하나다

`src/lib/me-v3/runtime/session.ts` 의 `openAttempt()` 가 학교 맥락이 선
응시의 등급을 **받은 값을 보지 않고** `PRO` 로 적는다. 등급을 정하는
자리가 하나여야 하기 때문이다(설계 원칙 10). 화면에서 고르는 칸을 없애는
것으로는 모자란다: 폼이나 주소로 등급을 넣는 길이 남아 있으면 어느 날
학교 응시 하나가 선별 등급으로 열리고, **그 학생의 결과는 같은 학과의
나머지와 한 표에서 읽히지 않는다.**

막는 자리를 `openAttempt()` 안에 둔 것은 그 함수가 학교 맥락을 이미 한 번
등록부로 맞춰 보기 때문이다. 그 시장에서 지금 응시할 수 있는 Core 가
아니면 맥락을 통째로 버리고, 그러면 등급도 올라가지 않는다. **학교 맥락이
섰다는 것과 PRO 로 연다는 것이 한 줄에서 결정된다.**

## 화면에서는 등급을 적지 않는다

- 시작 화면(`/v3/start`)의 등급 딱지와 `BASIC/STANDARD/PRO` 한 줄을
  학교 맥락에서는 세우지 않는다. 적는 문항 수와 분은 PRO 기준이다
- 결과지 머리의 등급 딱지와 머리 한 줄의 등급을 학교 응시에서는 걷는다.
  종이에 상품명처럼 서면 **사지 않은 등급 이름**으로 읽힌다
- 단추는 전과 같이 `검사 시작` 하나다. 고르는 칸은 애초에 없었다

**안쪽에는 PRO 가 그대로 남는다**: `v3_attempts.tier` 와 스냅샷의 판본
열두 칸이 그대로라, 나중에 어느 등급으로 쳤는지 되짚을 수 있다.

## 세는 자리

`npm run campus:walk` 이 여섯 줄을 더 센다.

- 학교 응시는 **이용권 없이도** PRO 로 열린다(화면이 넘긴 값은 `BASIC` 이다)
- 시작 화면이 학생에게 등급을 적지 않는다
- 서버 함수를 `BASIC` · `STANDARD` · `PRO` 로 직접 불러도 PRO 로 열린다
- 개인 응시는 셋이 그대로다

`scripts/v3-pdf-audit.ts` 도 같은 선을 든다: 학교 자리를 가리키는 Core 는
**PRO 한 벌만** 뽑는다. 그 Core 의 BASIC·STANDARD 종이는 제품에서 설 수
없는 상태다(학교 응시는 서버가 PRO 로 열고, 개인 B2C 는 그 Core 를 살 수
없다). 설 수 없는 조합의 종이를 세면 같은 종이를 세 번 세거나 제품에 없는
상태를 규격으로 굳히게 된다. 등급 셋은 **개인 B2C 가 실제로 파는 Core**
(학교 자리가 없는 쪽)에서 그대로 센다.

## QA 효율화

새 Core 마다 Campus 기준 필수 QA 는 **PRO 한 벌**이다: Assessment ·
Submit · Result · PDF · Workspace · Current State 끝까지. BASIC 과
STANDARD 는 개인 B2C 회귀에서만 유지한다.
