# C. ME_V3 최종 taxonomy 와 영역마다 확인할 판단 여덟 축

## 1. 축 셋을 확정한다

`52_rebuild_02_taxonomy.md` 의 세 축을 그대로 확정한다. 코드와 개수를
바꾸지 않는다.

```
기술영역 TD01~TD12  ×  역할기능 RF1~RF7  ×  조직환경 OC1~OC7
```

공고 직무명 스물넷은 이 조합의 별칭이고, 별칭표와 경계표 열 쌍도 그대로
간다. 이 파일이 더하는 것은 **영역마다 무엇을 어느 수준까지 확인해야
하는가**다. 앞 회차에 축 이름만 적어 두었던 자리다.

## 2. 판단 여덟 축

| 코드 | 이름 | 답하는 질문 |
|---|---|---|
| J1 | 문제 정의 | 무엇을 다룰지 누가 정했는가 |
| J2 | 요구사항 해석 | 요구를 수치와 제약으로 옮겼는가 |
| J3 | 직접 기술 판단 | 내가 정한 항목이 무엇인가 |
| J4 | 방법·도구 | 무엇으로 어떻게 했는가 |
| J5 | 산출물 | 무엇이 남았는가 |
| J6 | 비교·검증 | 무엇과 견주었는가 |
| J7 | 실패·수정 | 틀린 것을 어떻게 좁혔는가 |
| J8 | 조직 활용 | 누가 무엇에 썼는가 |

### 2-1. 수준 넷

| 수준 | 뜻 | 결과지 표기 |
|---|---|---|
| L0 | 없다 | 아직 확인되지 않음 |
| L1 | 접했다. 남이 한 것을 보거나 받아 썼다 | 일부 확인 |
| L2 | 수행했다. 내가 그 일을 했다 | 확인 |
| L3 | 소유했다. 내가 정하고 그 결과가 쓰였다 | 확인 · 직접 정함 |

**확인의 경계는 L2 다.** L1 을 확인으로 올리지 않는다. 도구 이름만 적은
사람이 L1 이고, 그 도구로 무엇을 정했는지 적은 사람이 L2 다.

### 2-2. 척도 둘

| 척도 | 축 | 어디서 쓰는가 |
|---|---|---|
| S4 선별 | J3 · J5 · J6 · J8 | BASIC. 참여와 소유를 가장 크게 가르는 넷이다 |
| S8 전체 | S4 + J1 · J2 · J4 · J7 | STANDARD 이상 |

**`4축 중 2개` 를 `8축 중 4개` 로 적지 않는다.** 둘은 다른 자이고, 비율로
바꾸면 적은 입력으로 많이 확인된 것처럼 보인다. BASIC 결과지는 `선별 네
축 가운데 둘` 로 적고, 유료에서 여덟 축으로 다시 센다.

## 3. 영역마다 확인 최소선

| TD | 이름 | 필수 축 둘 | 근거가 섰다고 말하는 조건 | 소유 신호 |
|---|---|---|---|---|
| TD01 | 기구·제품 설계 | J3 · J5 | S8 넷 이상 + 필수 둘 L2 이상 | 공차 배분이나 안전 여유를 기능 기준으로 정함 |
| TD02 | 구조·내구 해석 | J3 · J6 | 같다 | 이상화 수준과 재료 모델을 고르고 시험과 대조함 |
| TD03 | 열·유체 시스템 | J3 · J6 | 같다 | 난류 모델과 격자 전략을 고르고 실측과 대조함 |
| TD04 | 동역학·진동·NVH | J4 · J6 | 같다 | 전달경로를 가르고 대책 전후를 같은 조건으로 측정함 |
| TD05 | 제어·메카트로닉스 | J3 · J5 | 같다 | 제어 구조와 이득, 안전 범주를 정하고 장치가 돌아감 |
| TD06 | 재료·내구·파손 | J4 · J6 | 같다 | 손상 기구 후보를 증거로 배제해 하나로 좁힘 |
| TD07 | 시험·계측 | J3 · J5 | 같다 | 판정 기준과 샘플 수를 정하고 불확도를 적음 |
| TD08 | 생산·공정기술 | J3 · J6 | 같다 | 조건창을 정하고 공정능력으로 관리 상태를 확인함 |
| TD09 | 설비·보전 | J3 · J7 | 같다 | 교체 기준을 정하고 재발을 막는 변경을 함 |

| TD11 | 시스템·요구사항 | J2 · J5 | 같다 | 검증 방법과 담당을 요구마다 배정하고 추적함 |
| TD12 | 엔지니어링 자동화·데이터 | J5 · J8 | 같다 | 남긴 것을 다른 사람이 쓰고 있음 |

**개수만으로 판정하지 않는 까닭**이 이 표에 있다. 여덟 축 가운데 넷이
확인돼도 그 넷이 J1 · J2 · J4 · J7 이면, 구조해석에서 경계조건을 정한
적도 시험과 대조한 적도 없는 사람이 `근거가 선 영역` 에 들어간다. 그래서
영역마다 **빠지면 안 되는 축 둘**을 적어 둔다.

## 4. 영역별 축 열두 벌

각 영역에서 L2(수행)와 L3(소유)가 무엇인지 적는다. 이 표가 문항과
체크리스트와 결과지 문면의 원본이다.

### TD01 기구·제품 설계

| 축 | L2 수행 | L3 소유 |
|---|---|---|
| J1 | 주어진 사양으로 설계 범위를 적었다 | 사양이 없는 상태에서 만족할 기능과 제약을 세웠다 |
| J2 | 요구를 치수·하중·수명·조립 조건으로 옮겼다 | 부딪히는 요구(강성 대 중량, 조립성 대 밀폐)의 우선순위를 정했다 |
| J3 | 두께·단면·재질·체결 가운데 하나를 정했다 | 공차 배분과 안전 여유를 기능 기준으로 정했다 |
| J4 | 3D CAD 로 형상과 조립을 만들었다 | 체결력·베어링 수명·강성을 손계산으로 남겼다 |
| J5 | 조립도와 부품도를 냈다 | 도면이 제작에 나갔고 BOM 과 공차가 적혀 있다 |
| J6 | 설계안 둘 이상을 같은 기준으로 견주었다 | 간섭과 공차 누적을 검토하거나 시작품으로 확인했다 |
| J7 | 간섭이나 파손을 겪고 치수를 바꿨다 | 원인을 치수·재질·공정 가운데로 좁혀 재발을 막았다 |
| J8 | 설계 검토 회의에 올렸다 | 그 도면으로 제작이나 발주가 진행됐다 |

## 5. 이 표를 데이터로 두는 모양

표를 코드에 적지 않는다. 파일 하나에 둔다.

```
sites/pca-platform/content/me-v3-domains.json
  TD01 … TD12
    name_key, aliases[], required_axes[2],
    axes: { J1..J8: { l2, l3, checklist[], artifacts[], verify_targets[] } },
    org_outcomes: { OC1..OC7: "그 조직에서 성과로 불리는 이름" }
```

**체크리스트와 산출물 목록이 이 파일에서 나온다.** 문항과 결과지와
경험 입력이 같은 파일을 읽어야 축 이름이 세 곳에서 갈리지 않는다
(설계 원칙 10 과 같은 까닭이다).

기존 `me-evidence-map.json` 의 영역 199개를 이 파일의 `checklist` 로
재배치한다. 고아가 되는 영역이 0 인 것이 2단계 완료 조건이다.
