# 사업주가 직접 처음부터 끝까지 테스트하는 길

개발 작업 없이 바로 누를 수 있게 적었다. **실제 비밀번호와 열쇠는 여기 적지
않는다**: 적어 두면 저장소에 남고, 저장소에 남은 비밀번호는 비밀번호가 아니다.

---

## 0. 올리기 전에 한 번

배포본에 코드만 올라가고 DB 가 그대로이면 `/v3/start` 에서 500 이 난다.
**앱이 뜰 때 마이그레이션이 저절로 돌지 않는다**(배포 하나가 DB 를 바꾸면
되돌리기가 배포 되돌리기로 끝나지 않기 때문이다).

Railway → 서비스 → ⋯ → Shell 에서 한 번:

```bash
npm run db:upgrade    # 여러 번 돌려도 같은 자리에 선다
npm run db:verify     # 팔 수 있는 상태인가 (읽기만 한다)
npm run ops:check     # 볼륨 · DB · 도메인 · 메일 · 결제 열한 줄
```

`db:upgrade` 가 끝까지 돌면 이번 회차에 더해진 칸과 표가 전부 선다
(`v3_applications` · `career_profiles.target_org_context` ·
`v3_experiences.problems` · `.used_where` · `org_registry.role_code` …).

올라간 뒤 밖에서:

```bash
BASE=<배포본 주소> SMOKE_LOGIN=<아이디:비밀번호> npm run v3:smoke
```

열일곱 자리가 500 없이 열리는지 센다. 로그인 열쇠를 안 주면 뒤쪽 열한
자리는 `못 봄` 으로 적힌다.

---

## 1. 시작 URL

| 무엇 | 주소 |
|---|---|
| **전공 Core 고르기 (여기서 시작)** | `<배포본>/cores` |
| 검사 바로 시작 | `<배포본>/v3/start` |
| 내 CareerMatri | `<배포본>/me` |
| 운영 | `<배포본>/admin` |
| 파일럿 운영 | `<배포본>/admin/v3-pilot` |
| 가격표 | `<배포본>/pricing` |
| 견본 결과지 (로그인 없이) | `<배포본>/sample` |

공개 전 배포본에는 자물쇠(`STAGING_BASIC_AUTH`)가 걸려 있다. 브라우저가
한 번 묻고, 그 뒤로는 묻지 않는다.

---

## 2. 로그인 방식

셀프 가입이 열려 있다: `<배포본>/signup`. 테스트용 계정을 하나 만들어
쓰는 것이 가장 빠르다. **운영자 권한이 필요하면** 컨테이너 안에서:

```bash
DATABASE_URL=... npx tsx scripts/make-admin.ts <아이디> <이메일> <이름>
```

비밀번호는 그 자리에서 만들어 **한 번만 화면에 보여 주고** 해시만 남긴다.
다시 보여주기는 없고 재발급만 있다.

---

## 3. 등급별로 테스트하는 법

등급은 **이용권이 정한다.** 화면이 보낼 수 있는 것은 상품 코드 하나뿐이고,
주소로 등급을 올리는 길은 없다.

### BASIC

가격표에서 무료로 연다.

```
<배포본>/pricing → BASIC 의 `무료로 시작` → 바로 응시
```

무료 길은 `FREE_APPROVED` 인 상품만 열고, 같은 사람이 두 번 눌러도 주문
번호가 사람과 상품으로 정해져 있어 두 번째가 그 자리에서 거절된다.

### STANDARD · PRO

ME_V3 상품 셋은 **꺼 둔 상태**(`active = false`)다. 값이 아직 승인되지
않았으므로 가격표에 세우지 않는다. 테스트는 파일럿 초대로 연다.

```
<배포본>/admin/v3-pilot
  → `초대` 칸에서 wave 와 **등급(BASIC / STANDARD / PRO)** 을 고르고 만들기
  → 나온 링크를 그대로 브라우저에 붙여 넣는다
```

링크가 싣는 것은 한 번만 보여 주는 임의의 스물네 글자이고 해시만 저장된다.
**돈이 한 푼도 움직이지 않고**, 다시 눌러도 이용권이 늘지 않는다.

초대로 들어가면 그 등급 이용권이 한 줄 생기고 바로 응시가 열린다.

---

## 4. 새 응시를 만드는 법

```
<배포본>/cores → 기계공학 → 검사 시작
```

또는 `<배포본>/v3/start` 로 바로. 이미 풀던 응시가 있으면 `/me` 의
`검사 이어하기` 가 그 자리로 보낸다.

**같은 응시의 등급을 올릴 수 있다.** BASIC ⊂ STANDARD ⊂ PRO 라 앞 응답을
그대로 쓰고 추가 묶음만 연다(BASIC→STANDARD 34개 · STANDARD→PRO 15개).
올린 뒤에는 **새로 묻는 첫 화면**으로 옮긴다.

---

## 5. 기존 응시를 초기화하는 법

화면에서:

```
<배포본>/my/assessments → 그 응시 → 버리기 → 다시 `/v3/start`
```

운영자가 DB 에서 치워야 하면(테스트를 여러 벌 돌린 뒤) 컨테이너 안에서:

```sql
-- 한 사람의 ME_V3 응시를 통째로 치운다. **운영 손님에게 쓰지 않는다**
DELETE FROM v3_attempts WHERE user_id = <id>;
DELETE FROM career_profiles WHERE user_id = <id>;
DELETE FROM v3_experiences WHERE user_id = <id>;
DELETE FROM v3_actions WHERE user_id = <id>;
DELETE FROM career_events WHERE user_id = <id>;
```

응답과 스냅샷은 응시에 달려 있어 함께 사라진다.

## 6. 끝까지 한 바퀴: 눌러 볼 차례

1. `/cores` 에서 기계공학 고르기
2. 학업 단계와 전공계열: **석사 이상이면 학부 전공도 함께 고른다**
3. 관심 산업 둘 → 그 산업에서 기계공학자가 다루는 것 읽기
4. 영역 훑기 두 화면 (열두 영역 × 관심 · 해 본 적 · 배울 뜻)
5. 공통 판단 → 학위 묶음 → 선별 네 축
6. (STANDARD 이상) 심화 여덟 축 → 근거 고르기
7. 관심 직무와 선호 조직 → 역할 판단 → 산업 판단
8. (PRO) 경험 번역 열 단계 → 목표
9. 완료 화면에서 **`결과 보기`**
10. 결과 아홉 절을 끝까지: 첫 화면 세 칸이 바로 읽히는지
11. **`결과 PDF 저장`** (몇 초 걸린다)
12. `내 CareerMatri에 저장` → `/me`
13. `/me/experience/new` 에서 경험 하나: 기술영역을 고르면 그 영역의
    문제·판단·산출물·검증이 뜬다
14. `/me/recompute`: **어느 경험이 어느 판단으로 가는지** 보고 반영
15. `/me` 로 돌아와 Gap 과 할 일이 달라졌는지
16. `/me/explore` · `/me/region` 에서 산업 · 직무 · 권역 · 기관 유형 넷
17. `/me/apply` 에 지원한 곳 하나
18. `/me/track` 에서 Track 이 맡는 일

---

## 7. 보시면서 눌러 주실 자리

이 회차에 새로 서거나 크게 바뀐 자리다.

- **결과 첫 화면 세 칸**: 지금 확인된 것 · 비어 있는 것 · 지금 할 한 가지
- **산업 절과 직무 절**: `양쪽에서 확인된 경험` 과 `없다고 답하신 판단`
- **결과 8절의 `고르신 넷`**: 산업 × 직무 × 권역 × 기관 유형
- **`결과 PDF 저장`**: 웹과 같은 아홉 절이 종이로
- **`/me/recompute`**: 경험이 판단축으로 가는 길
- **`/me/apply`**: 지원한 곳을 직무로 묶어 보기
- **대시보드의 `다음에 할 일` 세 층**

## 8. 막히면

| 증상 | 먼저 볼 곳 |
|---|---|
| `/v3/start` 에서 500 | `npm run db:upgrade` 를 안 돌렸다 |
| 결과가 안 나온다 | `/admin/v3-pilot` 의 `결과가 안 나온 응시` |
| PDF 가 503 | 그 컨테이너에 Chromium 이 없거나 글꼴이 없다. `npm run ops:check` |
| 어느 쪽이 깨졌는지 모르겠다 | `BASE=... npm run v3:smoke` |
| 숫자가 이상하다 | `npm run v3:all` (검사 스물아홉 묶음) |
