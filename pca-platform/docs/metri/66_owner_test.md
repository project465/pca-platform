# 사업주 직접 테스트 체크리스트 (기계공학 V3 · Wave 0 직전)

조건희가 **배포 환경에서 직접 눌러 보는** 순서다. 개발 지식 없이 위에서
아래로 한 번만 내려가면 된다. 각 STEP 은 `접속 주소 · 할 일 · 정상 ·
체크` 넷으로 되어 있고, 한 자리라도 FAIL 이면 그 줄 번호를 적어 두면 된다.

**비밀번호와 초대 열쇠는 이 문서에 적지 않는다.** 적어 두면 저장소에 남고,
저장소에 남은 비밀번호는 비밀번호가 아니다. 테스트 계정은 STEP 1 에서
직접 만든다.

| 기호 | 뜻 |
|---|---|
| `<배포본>` | 실제 배포된 앱 주소. 기본값은 `https://app.careermatri.com` |
| 공개 전 자물쇠 | 브라우저가 아이디와 비밀번호를 한 번 묻는다. 한 번만 넣으면 그 뒤로는 묻지 않는다 |

## STEP 0 · 올리기 전에 한 번 (DB)

**접속 주소**: Railway → 프로젝트 → 서비스 → `⋯` → **Shell**

**할 일**: 아래 한 줄을 그대로 붙여 넣고 실행한다.

```bash
npm run db:upgrade && npm run db:verify && npm run ops:check
```

**정상**: `db:upgrade` 가 오류 없이 끝나고, `db:verify` 가 핵심 표와 내
CareerMatri 표를 세고, `ops:check` 열한 줄에 `BLOCKED` 가 DB 쪽에는 없다.

**정상이 아닐 때**: `/v3/start` 를 누르면 500 이 나고, `column ... does not
exist` 가 보이면 이 줄을 아직 안 돌린 것이다.

**체크** [ ] PASS [ ] FAIL

> **상태: 미실행 — 조건희가 Railway Shell 에서 실행 필요.**
> 이 세션에서는 Railway Shell 에 들어갈 수 없고, 바깥 네트워크가 막혀
> 배포본을 열어 보지도 못했다. **돌렸다고 적지 않는다.**

**할 일**: 쪽을 위에서 아래로 읽는다.

**정상**: 두 덩이가 **생김새로** 갈려 있다. 검사 당시 결과는 흰 카드에
왼쪽 날짜 띠와 `고정됨` 표시, 지금 상태는 꺼진 바탕에 점선과 `이 줄은
경험을 더하면 바뀝니다` 다. `결과 보기` 를 누르면 **그날의 결과지가
그대로** 열린다.

**둘이 같은 생김새로 서 있으면 FAIL.** 날짜만 다른 같은 값으로 읽힌다.
경험을 더한 뒤의 숫자가 굳은 쪽에 들어가 있으면 FAIL.
`당시 판본 보기` 를 펼쳤을 때 `core_version` 처럼 안쪽 열쇠가 보이면 FAIL.

**접속 주소**: `<배포본>/me/next`

**할 일**: `결과에서 할 일 가져오기` 를 누르고, 한 줄에서 `끝냈습니다` 를

**단추를 눌렀는데 아무 일도 안 나면 FAIL.** 할 일 문장이 결과지의 것과
다르면 FAIL.
