# 그 흐름은 한국만의 것인가 — 국가별 검증

물어본 흐름은 이것이다.

```
기계공학과 500명 → Career Profile → 직무 분포 → 희망 산업
                → 부족 Skill → 기업 수요 → 교육 프로그램
```

결론부터 쓴다.

> **흐름 자체는 전 세계 공통이다. 이미 다섯 나라에서 각기 다른 회사와 정부가
> 이 흐름의 조각을 팔고 있다. 한국만의 것은 흐름이 아니라 세 가지다 —
> ① 학과가 계약 주체가 될 수 있다는 것 ② 채용공고 원천 데이터가 공짜라는 것
> ③ 지역정주라는 지표가 대학 예산에 직접 걸려 있다는 것.**

그래서 전략은 "한국형을 만들어 나중에 번역한다"가 아니다.
**흐름을 공통 엔진으로 만들고, 나라마다 다른 것은 강제력·데이터 원가·계약 단위 세 개뿐이므로
그 셋만 Market Layer 로 갈아 끼운다.**

---

## 1. 흐름의 각 칸은 이미 세계 어디에나 있다

| 흐름의 칸 | 이미 이걸 하는 곳 | 어느 나라 |
|---|---|---|
| 개인 Skill Profile → 직무 매칭 | Cognavi (Skill Tree ↔ 기업 Technical Tree 정량 비교) | 일본·인도 |
| 교육과정 ↔ 노동시장 스킬 정렬 | Lightcast **Skillabi** (프로그램–직무 정렬 점수, 스킬 3.3만개 분류체계) | 미국 |
| 국가 표준 Skill Framework | **SkillsFuture** Skills Framework 38개 산업 + Jobs-Skills Insights | 싱가포르 |
| 공고 기반 실시간 수요 집계 | Cedefop **Skills-OVATE** (32개국 온라인 공고), Skills Forecast 2035 | EU |
| 고교 단계 진로–수요 정렬 | **Perkins V** — CTE 프로그램을 지역 고임금·고수요 직종에 정렬할 법적 의무 | 미국 |
| 졸업생 추적 | Eurograduate / EHESO 졸업생 추적, 영국 Graduate Outcomes | EU·영국 |

즉 "이 흐름이 통하느냐"는 물음의 답은 이미 나와 있다. 통한다.
**비어 있는 것은 칸이 아니라 칸을 잇는 선이다.** Lightcast 는 프로그램 단위라 학생 개인이 없고,
Cognavi 는 개인 단위라 학과 집계가 약하고, SkillsFuture 는 표준은 있으나 학생 진단이 없다.
개인에서 출발해 학과 집계까지 한 줄로 올라가는 제품은 아직 자리가 비어 있다.

---

## 2. 진짜 차이는 "왜 대학이 돈을 내는가"

흐름이 같아도 **대학이 지갑을 여는 이유**는 나라마다 다르다. 영업 논지가 여기서 갈린다.

| 나라 | 대학을 움직이는 강제력 | 우리 흐름이 먹히는 정도 | 계약 단위 |
|---|---|---|---|
| **한국** | 대학정보공시 취업률·유지취업률 + RISE→앵커 성과평가. 2026년 예산 2조 1,403억 중 약 4,000억이 성과 인센티브. 평가 항목에 **학생·인재 고려**가 들어 있고 성과지표 예시에 **지역정주 취업률** | ★★★★★ 그대로 먹힌다 | **학과**. 세계에서 드물게 학과장이 결재권을 갖는다 |
| **영국** | OfS **Condition B3** — 졸업 15개월 후 전문직 취업·대학원 진학 비율. 75% 위는 안심, 65~75% 우려, 65% 미만 중대 우려. 미달 시 재정 제재부터 학위수여권 박탈까지 | ★★★★★ 강제력은 한국보다 세다 | 학부(faculty)·대학 본부 |
| **미국** | Gainful Employment 소득 프리미엄 기준(2026 시행), 주별 성과기반 재정지원(웨스트버지니아는 졸업생 고용·소득에 예산 연동), 고교는 Perkins V | ★★★★ 먹히나 경쟁자가 이미 크다 | Career Services / Institutional Research. 학과 아님 |
| **싱가포르** | SkillsFuture 가 국가 표준. 프레임워크에 정렬된 교육과정만 "산업 적합" 으로 인정 | ★★★★ 단 **우리 온톨로지를 SF 에 매핑해야 입장 가능** | 정부 기관 + 대학 |
| **일본** | 취업 문화가 개인 단위(就職課)로 강하게 형성. 다만 **Cognavi 가 Skill Tree 매칭을 이미 선점** | ★★★ 앞단 진단으로만 비집을 수 있다 | 대학 취업과 |
| **EU** | 졸업생 추적 권고 + ESCO 표준. 데이터 규제(GDPR)가 무겁다 | ★★★ 표준 호환이 진입 조건 | 대학·정부 컨소시엄 |
| **독일** | 졸업생 실업률이 원래 낮고, employability 를 특정 직무가 아니라 문제해결 역량으로 본다. 기업 수요→교육 연결은 이미 이원화 교육과 상공회의소가 담당 | ★★ **압력이 약해 팔기 어렵다.** 후순위 | — |

**읽는 법.** 한국과 영국이 1군이다. 흐름을 바꿀 필요 없이 지표 이름만 바꿔 끼우면 된다.
미국은 시장은 크지만 Lightcast 가 프로그램 단위를 이미 먹었으므로 **"학생 개인에서 올라온 집계"** 라는
다른 각도로만 들어간다. 독일은 흐름이 안 통하는 게 아니라 **돈 낼 이유가 약한** 나라다. 후순위로 둔다.

## 3. 두 번째 차이 — 같은 흐름인데 원가가 다르다

흐름의 여섯 번째 칸 "기업 수요"는 채용공고 데이터로 채운다. **이 칸의 원가가 나라마다 열 배 넘게 다르다.**

| 나라 | 주 원천 | 비용 | 결과 |
|---|---|---|---|
| 한국 | 워크넷/고용24 Open API (공공데이터포털) | **무료**, 인증키 신청만. 단 OpenAPI 제공에 동의한 기업 공고만 | 1차 시장을 한국으로 잡는 진짜 이유 |
| 미국 | O*NET Web Services(직무–스킬 표준), USAJOBS(연방 공고), Adzuna(월 1,000콜 무료) | 표준·연방은 무료, **민간 공고 전량은 유료** (Lightcast·Coresignal·LinkUp 등) | 미국 진출 시 데이터 비용이 손익의 주요 변수 |
| EU | Cedefop Skills-OVATE 집계 | 집계는 공개, 원문은 아님 | 통계는 되고 개별 매칭은 어렵다 |

**설계에 미치는 영향.** JD 파이프라인은 처음부터 소스별 라이선스를 데이터로 들고 있어야 한다
(`jd_sources.license_note`, `redistributable`). 한국에서 되는 화면이 미국에서 그대로 되지 않는다 —
미국은 "공고 원문"이 아니라 "집계된 수요"만 보여주는 화면으로 축소된다.

---

## 4. 세 번째 차이 — 표준 코드 체계

같은 직무를 나라마다 다른 코드로 부른다. 이걸 우리 코드로 번역하는 표가 자산이다.

| 체계 | 쓰는 곳 | 우리 대응 |
|---|---|---|
| O*NET-SOC | 미국 | `job_clusters.onet_code` (이미 스키마에 있다) |
| ESCO | EU 27개국 | **ESCO↔O*NET 공식 크로스워크가 이미 있다.** ESCO 전 직업이 최소 1개 O*NET 직업에 연결돼 있으므로, 우리는 O*NET 만 붙들면 EU 가 딸려온다 |
| NCS | 한국 | 마이스터고·특성화고 교육과정의 언어. `ncs_competency_map` |
| Skills Framework | 싱가포르 | 진출 시 매핑 필요 |

**전략적 결론 하나.** 우리 직무군을 **O*NET 코드에 먼저 붙인다.**
ESCO 는 크로스워크로 따라오고, 한국 NCS 는 우리가 직접 잇는다.
이 순서를 뒤집으면 (한국 코드부터 만들고 나중에 번역) 글로벌 확장에서 전부 다시 해야 한다.

---

## 5. 한국에서만 성립하는 것 하나 — 학과 계약

이건 진짜로 한국 특수다. 다른 나라에서 500명 단위 계약은 학과가 아니라
대학 본부·Career Services 가 결정한다. **의사결정자가 다르면 제품이 달라진다.**

- 한국: 학과장이 산다 → 학과 대시보드가 곧 구매 이유. 화면 하나로 판다
- 영미: 본부가 산다 → 전 학과 비교, 기관 전체 KPI, SIS 연동이 구매 이유

그래서 학과 대시보드는 **처음부터 다학과 롤업이 가능한 구조**로 만든다
(`cohort_reports.org_id` 가 학과이고 `organizations.parent_id` 로 대학까지 올라간다 — 기존 스키마 그대로).
한국에서 학과 하나로 시작해도, 영국에 갈 때 화면을 새로 만들지 않는다.

---

## 6. 그래서 흐름은 이렇게 고쳐 쓴다

원래 흐름에 **국가 레이어**를 한 칸 끼운다.

```
       [ 전 세계 공통 엔진 ]                    [ 국가 레이어 ]
500명 → Career Profile → 직무 분포 → 희망 산업 → 부족 Skill
                                                    ↓
                                          기업 수요 ← 국가별 JD 소스·라이선스
                                                    ↓
                                       교육 프로그램 ← 국가별 제도·예산·지표
                                                    ↓
                                          성과 리포트 ← 한국: 정주 / 영국: B3 / 미국: 소득
```

앞의 네 칸은 국가를 안 탄다. 뒤의 세 칸만 갈아 끼운다.
**이 그림이 "언어만 바꾸는 게 아니라 Market Layer 를 붙인다"는 말의 실제 구현이다.**
