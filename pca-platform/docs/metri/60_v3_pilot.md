# ME_V3 본 파일럿 · 운영 런북

날짜 2026-10-08 · 대상 `ME_CORE_V3` · **모집 직전** · 기준선 동결됨

스무 명에서 서른 명이 한 시간씩 쓰는 일이다. **한 번만 할 수 있다.**
끝난 뒤에 `그 칸을 안 받고 있었다` 를 알면 다시 부를 수 없어서, 부르기
전에 받을 것과 지울 것과 볼 자리를 먼저 세워 두었다.

이 문서는 운영자가 **보면서 돌리는 글**이다. 설계 이유는 각 절의 들여쓴
문단에 있고, 눌러야 하는 것은 표와 목록에 있다.

고정한 기준선은 여섯이다. **wave 가 도는 동안 이 여섯 가운데 무엇도
고치지 않는다.**

| 무엇 | 판본 |
| --- | --- |
| 검사 화면 | `ME_V3_ASSESSMENT_UI_V1` |
| 결과지 화면 | `ME_V3_RESULT_UI_V1` |
| 문항 은행 | `ME_V3_ITEM_BANK_V1` |
| 판단 규칙 | `me-v3-scoring.1` |
| 결과 모델 | `me-v3-result-model.1` |
| 결과지 문장 | `me-v3-result-copy.1` |

## 1 · wave 넷

| wave | 몇 명 | 누구 | 무엇을 본다 | 끝내는 조건 |
| --- | --- | --- | --- | --- |
| 0 | 2~3 | 내부 | 링크부터 종이까지 끊기는 자리가 없는가 | 세 벌이 끊김 없이 돈다 |
| 1 | 5 | 실사용자 | 문항과 결과가 사람에게 통하는가 | 다섯이 결과를 열고 의견을 남긴다 |
| 2 | +10 (누적 15) | 실사용자 | wave 1 에서 고친 것이 먹히는가 | 열다섯 명분이 모인다 |
| 3 | 최종 20~30 | 실사용자 | 등급 사이의 값 차이가 갈리는가 | 서른 명이거나 모집이 끝난다 |

**wave 를 섞지 않는다.** 참가자 줄과 퍼널과 분석이 전부 `wave` 로
갈린다(`v3_pilot_participants.wave` · `analytics_events.props->>'wave'`).
wave 1 에서 문항을 고치고 wave 1 자료와 wave 2 자료를 합치면, 합친 평균은
두 제품의 평균이 된다.

**Wave 0 은 내부다.** 바깥 사람을 부르기 전에 끊기는 자리를 먼저 찾는다.
`npm run v3:pilot:dry` 가 그 자리를 자동으로 한 바퀴 돌지만, Wave 0 은
사람이 손으로 한 번 더 누른다. 기계는 `눌리는데 읽기 싫다` 를 못 센다.

## 2 · 참가자 한 사람을 만드는 길

```
초대 자리 만들기 → 링크 보내기 → 참가자가 누름 → 로그인·가입
→ 가명과 등급이 붙음 → 등록 폼 → 검사 → 결과 → 종이 → 의견
```

1. `/admin/v3-pilot` 을 연다(운영자 계정).
2. **초대** 칸에서 wave 와 등급과 몇 자리인지를 고르고 만든다.
3. 만든 즉시 나오는 목록을 **그 자리에서 옮겨 적는다.** 새로 고치면
   사라진다.
4. 참가자에게 그 주소를 보낸다. 한 사람에 한 주소다.

   **가명과 열쇠를 가른다.** 주소가 싣는 것은 한 번만 보여 주는 임의의
   스물네 글자이고, `V3-A0001` 은 운영자가 보는 이름이다. 다음 번호를
   주소에 넣어 봐도 아무 일이 없고, 열쇠는 해시만 저장하므로 DB 가 새도
   남의 자리에 들어갈 수 없다. 한 자리는 한 번만 쓰인다.

   **등급은 초대가 정한다.** 참가자가 고르게 두면 어느 등급을 시험하는
   wave 인지가 참가자 손에 넘어간다. 초대를 쓰면 그 등급 이용권이 한 줄
   생기고, 다시 눌러도 늘지 않는다. 이용권이 늘면 같은 사람이 한 번 더
   풀 수 있고, 스무 명짜리 표본에 같은 사람이 두 번 서면 규준이 오염된다.

5. 참가자는 링크를 누르고 로그인한 뒤 등록 폼 일곱 칸을 적는다.
   **이름·학교·학번·연락처는 받지 않는다.**

| 받는 칸 | 쓰는 곳 |
| --- | --- |
| 학위 | 문항 장면 · 분석 묶음 |
| 전공명 | 분석. **준식별자라 90일 뒤 지운다** |
| 전공계열 | 문항 routing · 분석 묶음 |
| 지금 상태 | 분석 묶음 |
| 지금까지 해 본 정도 | 분석 묶음 |
| 관심 있는 쪽 | 분석 묶음 |
| 가고 싶은 자리 | 분석. 자유입력이라 함께 지운다 |

**이 일곱 가운데 무엇도 Core 점수를 바꾸지 않는다.** 등급과 학위와
계열이 바꾸는 것은 묻는 말과 장면이고, 판정은 같은 응답에 같은 값을
낸다(`v3:scoring` 의 변형 검사가 매번 본다).

## 3 · 하루 운영 (10~15분)

아침에 `/admin/v3-pilot` 하나만 연다. 위에서 아래로 여섯이다.

1. **손볼 일이 있는 줄.** 거르기에서 `있는 줄만` 을 누른다. 한 줄이라도
   있으면 가명을 눌러 그 사람의 화면으로 들어간다.
2. **끝내지 못한 사람.** 거르기 `하는 중`. 이틀이 지나면 한 번 묻는다.
3. **응답 품질 flag.** `엇갈림` 이나 `차이 적음` 인 줄. 그 사람을
   의심하는 칸이 아니다. **문항이 갈리지 않은 자리**를 찾는 칸이다.
4. **결과가 안 맞는다고 적은 줄.** 가명을 눌러 그 응시를 열고, 적어 주신
   글과 그 사람의 묶음을 나란히 읽는다.
5. **새로 들어온 의견.** `의견` 칸이 `n / m` 으로 선다.
6. **기술 오류.** `결과가 안 만들어졌다` · `종이를 못 뽑았다`.

손볼 일 여섯 갈래는 이렇게 센다.

| 갈래 | 언제 붙는가 | 먼저 할 일 |
| --- | --- | --- |
| 결과가 안 만들어졌다 | 냈는데 스냅샷이 없다 | **가장 급하다.** 서버 기록을 보고 다시 만든다 |
| 응답이 엇갈린다 | 품질 판정이 `INCONSISTENT` | 그 사람의 응시를 열어 어느 축이 어긋났는지 본다 |
| 걸린 시간이 너무 짧거나 길다 | 등급별 선 밖 | 짧으면 눌러 넘긴 것, 길면 막힌 자리가 있다 |
| 깊게 본 영역이 없다 | 유료인데 `opened_deep` 이 0 | routing 이 잘못 걸렸을 수 있다 |
| 결과가 안 맞는다고 적었다 | 의견 척도가 4 이상 | 그 응시를 열어 읽는다 |
| 종이를 못 뽑았다 | PDF 주소가 503 을 냈다 | 그리는 브라우저가 죽은 자리다 |

### 중도 이탈

| 어디서 멈췄는가 | 무엇을 한다 |
| --- | --- |
| 링크만 열고 등록 안 함 | 하루 뒤 한 번만 다시 보낸다. 두 번은 보내지 않는다 |
| 등록했는데 검사 시작 안 함 | 이틀 뒤 한 번. 답이 없으면 그 자리를 비운 것으로 센다 |
| 검사 중간에 멈춤 | **이어서 할 수 있다는 것**을 알린다. 답한 것은 그대로 남아 있다 |
| 끝냈는데 결과를 안 열었다 | 결과 주소를 한 번 보낸다 |
| 결과는 봤는데 의견을 안 적었다 | 한 번만 묻고 더 묻지 않는다. **결과를 인질로 잡지 않는다** |

### 그만두겠다고 할 때

참가자 화면의 `그만두고 적은 것 지우기` 를 누르시면 그 자리에서 자유입력이
지워진다. 운영자가 대신 누르지 않는다. 그 단추가 참가자 화면에 있는 것이
그 사람이 언제든 멈출 수 있다는 뜻이다.

## 4 · wave 를 끝낼 때

1. 그 wave 의 분석을 먼저 찍는다.

   ```
   WAVE=1 OUT=docs/metri/61_pilot_wave1.md npm run v3:pilot:report
   ```

2. 고칠 자리를 고른다(리포트 6절의 표).
3. 고친다. **고치면 판본을 올린다**: 문항을 고치면
   `ME_V3_ITEM_BANK_V1` → `V2`, 결과지 문장만 고치면
   `me-v3-result-copy.1` → `.2`.
4. 동결을 다시 적는다.

   ```
   FREEZE=update npm run v3:freeze
   RESULT_FREEZE=update npm run v3:result:freeze
   ```

5. `npm run v3:all` 과 `npm run v3:pilot` 이 다 녹색인지 본다.
6. 다음 wave 의 초대를 만든다.

**wave 가 도는 동안에는 고치지 않는다.** 치명적인 버그면 그 wave 를
거기서 끝내고, 판본을 올리고, 다음 wave 로 넘긴다. 돌고 있는 wave 안에서
고치면 그 wave 의 앞뒤가 다른 제품이 되고, 둘을 합친 평균은 아무것도
말하지 않는다.

고쳐도 되는 것은 넷뿐이다: 명백한 버그 · 문장이 깨진 자리 · 내부 코드가
새는 자리 · 화면이 무너진 자리. `더 예뻐 보인다` 는 파일럿 뒤다.

## 5 · 분석

```
npm run v3:pilot:report                    # 전체
WAVE=1 npm run v3:pilot:report             # wave 하나
OUT=docs/metri/61_pilot_wave1.md ...       # 파일로
```

리포트가 여섯 절을 찍는다: 퍼널 · 문항과 화면 · 결과를 어떻게 읽었는가 ·
상품과 값 · 손볼 일 · 고칠 자리를 고르는 규칙.

지키는 규칙 넷은 리포트 머리에도 적혀 있다.

- 다섯 명이 안 되는 칸은 평균을 내지 않는다. **가려서 보여 주는 것이
  아니라 값을 만들지 않는다.** 값이 없어야 옮겨 적어도 새지 않는다.
- 여섯 지표를 한 숫자로 합치지 않는다.
- 비율의 바닥이 0 이면 비율을 만들지 않는다.
- **기계적인 통계 유의성 기준을 만들지 않는다.** 스무 명에서 서른 명이라
  그 선이 그럴듯해 보일 만큼의 정밀도가 없다.

**값에 대한 답은 짐작이다.** 세 등급 모두에게 14,900원과 21,900원을
보여 주고 받으므로, 받지 않은 등급에 대한 답은 치러 본 값이 아니다.
리포트가 그 문장을 자기 안에 적는다.

>
> 참가하실 분은 회신 주시면 개인 링크를 보내 드립니다.

쓰지 않는 말: `AI 가 분석` · `상위 몇 %` · `검증된` · `합격률` ·
`취업 보장` · `맞춤 추천`. 하나라도 적으면 그 순간 파는 것이 달라지고,
파일럿이 재려던 제품이 아니게 된다.

## 7 · 동의문 (참가 화면에 선다)

> **파일럿 참가 안내**
>
> 이것은 베타 테스트입니다. 정식 서비스가 아니고 화면과 문항과 결과지가
> 아직 바뀝니다.
>
> 모으는 것은 넷입니다. 진단에 답하신 내용 · 만들어진 결과 · 화면마다
> 걸린 시간 · 남겨 주신 의견. 이것을 검사와 결과지를 고치는 데만 씁니다.
>
> **이 결과는 채용 합격 가능성을 판정하지 않습니다.**
>
> 개인정보는 최소로 받습니다. 이름·학교·학번·연락처는 받지 않습니다.
> 운영 화면과 분석에는 `V3-A0001` 같은 참가자 이름만 나갑니다. 전공명과
> 가고 싶은 자리는 **90일 뒤에 지웁니다.**
>
> 언제든 그만두실 수 있습니다. 참가 화면의 `그만두고 적은 것 지우기` 를
> 누르시면 적어 주신 글을 그 자리에서 지웁니다.
>
> 다섯 명이 안 되는 묶음은 평균이나 비교를 내지 않습니다.

## 8 · 명령과 배포

```bash
npm run v3:pilot          # 사람을 부르기 전에 도는 검사 29가지
npm run stage:serve       # 공개 전 배포본을 이 기계에서 바르게 띄운다
npm run v3:pilot:dry      # 예행 세 벌 (실제 브라우저) 74가지
npm run v3:pilot:report   # 분석 골격
npm run v3:pilot:purge    # 기한이 지난 자유입력 (PURGE=yes 로 실제 삭제)
npm run v3:all            # 판본 잠금부터 파일럿까지 한 번에
```

**배포는 가지가 정한다.** Railway 가 `claude/amazing-thompson-w3f2o2` 를
그대로 굽는다. `main` 을 합쳐서 올리지 않는다. 합치는 것이 곧 배포라
이 회차에서 하지 않았다.

DB 를 올릴 때는 `db:init`(빈 DB) 이나 `db:upgrade`(그 다음)가
`schema_v3_runtime.sql` 과 `schema_v3_pilot.sql` 을 같이 붓는다.
`db:verify` 가 다섯 표를 세어 빠진 날을 그 자리에서 알려 준다.
**올리고 나서 `db:upgrade` 를 한 번 돌리기 전에는 V3 표가 없다.**

### 배포본에서 손으로 확인할 것

이 기계에서는 프록시가 `app.careermatri.com` 을 막아 밖에서 두드릴 수
없다. **운영이 죽은 것이 아니다. 여기서 안 보일 뿐이다.** 사람이 한 번
열어 다음 여덟을 본다.

| 자리 | 무엇을 본다 |
| --- | --- |
| `/api/health` | 200 이고 DB 까지 물어본 값인가 |
| `/login` | HTTPS 로 열리고 자물쇠가 걸려 있는가 |
| `/v3/pilot?t=<열쇠>` | 가명이 서고 등록 폼이 뜨는가 |
| `/v3/start` | 초대가 준 등급으로 서는가 |
| 검사 한 바퀴 | **`다음` 이 두 번째에도 눌리는가** |
| 닫았다 다시 | 답이 그대로 남아 있는가 |
| `/v3/{id}/result` · `/result/pdf` | 열리고 뽑히는가 |
| `/admin/v3-pilot` | 줄이 서고 전공명이 없는가 |

다섯째 줄을 굵게 적어 둔 까닭은 그것이 이 회차에 걸린 탈이고, 공개 전
배포본에서만 나기 때문이다.

## 9 · 아직 하지 않는 것

- 실제 참가자에게 초대 메시지를 보내지 않았다.
