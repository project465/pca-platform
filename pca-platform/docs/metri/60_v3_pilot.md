# ME_V3 본 파일럿 · 준비와 운영

날짜 2026-10-08 · 대상 `ME_CORE_V3` · 모집 전 상태

스무 명에서 서른 명이 한 시간씩 쓰는 일이다. **한 번만 할 수 있다.**
끝난 뒤에 `그 칸을 안 받고 있었다` 를 알면 다시 부를 수 없어서, 부르기
전에 받을 것과 지울 것과 볼 자리를 먼저 세워 두었다.

이 문서는 **모집 직전까지**다. 실제 모집과 실행은 이 문서 다음이다.

---

## 1 · 무엇을 재는가

파일럿이 답해야 하는 물음 넷이다.

| 묶음 | 물음 | 어디서 받는가 |
| --- | --- | --- |
| 문항 | 무엇을 묻는지 알겠는가 · 보기 2·3·4 를 가릴 수 있는가 · 얼마나 걸리는가 | 의견 1·2 · 응답 시각 |
| 결과 | 내 경험과 맞는가 · 왜 이 영역인지 설명할 수 있는가 · 다음 행동을 할 수 있는가 | 의견 3·4·5 |
| 상품 | 무료가 쓸모 있었는가 · 치른 값에 견주어 알맞았는가 | 의견 6 (등급별로 다른 문항) |
| 화면 | 어디가 어려웠는가 · 먼저 본 곳과 끝내 안 본 곳 | 의견 7 · 결과지 발자국 |

마지막 줄이 설문으로 못 받는 자리다. **사람은 자기가 안 읽은 자리를
기억하지 못한다.** 그래서 절이 화면에 올라온 적이 있는지만 적는다.

## 2 · 무엇을 받는가

| 칸 | 어디에 | 비고 |
| --- | --- | --- |
| 학위 · 전공계열 | `v3_attempts` · `v3_pilot_participants` | 응시가 이미 들고 있다 |
| 전공명 | `v3_pilot_participants.major_name` | **준식별자.** 90일 뒤 삭제 |
| 지금 상태 · 가고 싶은 쪽 | `v3_pilot_participants` | 가고 싶은 쪽도 자유입력이라 함께 삭제 |
| 등급 · 시작 · 완료 · 걸린 시간 | `v3_attempts` | 이미 있다 |
| 블록별 시간 | `v3_responses.answered_at` | **응시 화면을 건드리지 않는다** |
| 응답 품질 · 연 영역 | `v3_snapshots` · `v3_attempts.opened_deep` | 이미 있다 |
| 결과지 절 조회 · 할 일 누름·담기 | `v3_pilot_events` | 참가자에게만 적는다 |
| 의견 여덟 | `v3_pilot_feedback` | 척도 여섯 + 자유입력 둘 |

**이름과 학교와 학번과 연락처는 받지 않는다.** 분석에 쓰이지 않는 칸을
받아 두면 보관할 이유가 생기고, 보관하면 지울 일이 생긴다. `v3:pilot` 이
그 네 가지가 들어오지 않았는지 센다.

### 블록별 시간을 화면에서 재지 않는 까닭

응시 화면은 `ME_V3_ASSESSMENT_UI_V1` 로 굳혀 두었다. 시간을 재려고 거기에
코드를 심으면 둘이 깨진다. 참가자와 일반 응시자가 다른 화면을 받게 되고
(그러면 파일럿이 재는 것이 제품이 아니다), 동결 기록에는 `응시 화면이
바뀌었다` 가 남는다. 답이 찍힌 시각은 이미 `v3_responses.answered_at` 에
있고, 그것으로 블록 시간이 나온다. **답 사이가 20분을 넘으면 그 틈은 빼고
센다**: 창을 열어 둔 채 밥을 먹고 온 것을 `문항이 어려웠다` 로 읽으면 안
된다.

## 3 · 개인정보 · 지우는 날을 먼저 정한다

전공명은 그 자체로는 흔한 말이지만 **학위·계열과 함께 놓으면 사람이
좁혀진다**(`박사 후 연구원 · 이공계 · 정밀가공`). 그래서 셋을 지킨다.

1. **가명으로 다닌다.** 운영 화면과 내보내기에 서는 것은 `V3-XXXXX` 뿐이다.
   운영 화면은 전공명을 뽑는 질의조차 갖지 않는다(`purgeDue()` 한 곳에서
   있는지만 본다).
2. **받는 자리에서 기한을 박는다.** 등록할 때 `purge_after = 오늘 + 90일`
   이 함께 들어간다. 문서에만 적어 두면 담당이 바뀐 뒤 아무도 안 지운다.
3. **지우는 코드가 있다.** `npm run v3:pilot:purge` 가 기한이 지난
   전공명·가고 싶은 쪽·의견 자유입력을 지운다. 척도 응답과 응시 기록은
   남긴다. 그 둘로는 사람이 좁혀지지 않고, 결과를 되짚는 근거이기 때문이다.

**다섯 명이 안 되는 묶음은 평균을 내지 않는다.** 가려서 보여 주는 것이
아니라 값을 만들지 않는다(`cells()` 가 `mean: null` 을 돌려준다). 화면이
알아서 가려 주기를 바라면, 내보내기나 캡처에서 새어 나간다.

## 4 · 화면 셋

| 자리 | 주소 | 누가 |
| --- | --- | --- |
| 참가 등록 | `/v3/pilot` | 참가자 |
| 의견 여덟 | `/v3/{attemptId}/feedback` | 참가자 (결과를 본 뒤) |
| 한 표 | `/admin/v3-pilot` | superadmin |

**결과지를 설문으로 막지 않는다.** 결과를 먼저 보여 주고 거기서 가는 길만
둔다. 답하지 않아도 잃는 것이 없고, 빈칸으로 두신 문항은 그대로 빈칸으로
센다. 모두 필수로 만들면 아무 칸이나 눌러 넘기는 응답이 섞이고, 그 응답은
없는 것만 못하다.

운영 화면은 **한 표**다. 스무 명을 보는 자리에 검색과 필터와 내보내기를
달면 파일럿이 끝난 뒤 아무도 안 쓰는 화면이 하나 남는다. 여기서 답하는
물음은 넷뿐이다. 누가 끝냈는가 · 얼마나 걸렸는가 · 결과가 나왔는가 ·
의견을 적었는가.

## 5 · 운영 절차

### 모집 전 (지금까지)

```
psql --single-transaction -f db/schema_v3_pilot.sql
npm run v3:all            # 결과·카피·동결·파일럿 준비까지
npm run v3:pilot          # 받을 것·지울 것·다섯 명 규칙 열셋
node scripts/v3-pilot-shots.mjs <plan.json>   # 화면 셋을 눈으로
```

`v3:pilot` 이 푸르지 않으면 부르지 않는다.

### 하루 운영

1. 참가자가 `/v3/pilot` 에서 등록한다(네 칸).
2. `/v3/start` 에서 검사를 받는다. **평소 화면 그대로다.**
3. 결과를 읽고, 아래 `파일럿 의견 적기` 로 간다.
4. 운영자는 `/admin/v3-pilot` 한 표를 본다.

### 매일 아침 보는 것

- **결과가 안 나온 응시**: `결과 없음` 이 적힌 줄. 그날 안에 본다.
- **응답 품질**: `다시 볼 것` 과 `차이 적음` 이 몇인가. 셋을 넘으면 문항
  쪽을 의심한다.
- **걸린 시간**: 등급별 중앙값. 예상(BASIC 15분 · STANDARD 35분 ·
  PRO 55분)에서 1.5배를 넘으면 그 블록을 본다.
- **의견 수**: 끝낸 사람 가운데 몇이 적었는가. 절반을 밑돌면 가는 길이
  안 보이는 것이다.

### 끝난 뒤

```
PURGE=yes npm run v3:pilot:purge
```

기한이 지난 뒤에 돈다. 돌기 전에 무엇이 지워질지 먼저 찍어 준다.

## 6 · 아직 하지 않는 것

홈페이지 전면 개편 · 대규모 광고 · 공고 자동수집 · 구독과 반복결제 ·
해외 영어판 · 다른 Major Core. 파일럿이 답하기 전에는 어느 것도 시작하지
않는다.

## 7 · 모집 전에 남은 위험

| 위험 | 지금 상태 |
| --- | --- |
| 실제 사람의 응답이 한 벌도 없다 | 사람 열두 벌은 **우리가 만든 응답**이다. 보기를 어떻게 읽는지는 아직 모른다 |
| 걸린 시간 예상이 추정이다 | 블록 시간은 받을 수 있게 해 두었지만, 실제 중앙값은 파일럿이 처음 준다 |
| STANDARD·PRO 가치 차이가 자기보고다 | 의견 6 하나로 받는다. 실제 지불 행동은 파일럿에서 보지 않는다 |
| PRO 번역 초안이 응답 품질에 달려 있다 | 고른 보기를 잇는 것이라, 보기를 성의 없이 고르면 초안도 그렇게 된다 |
| 운영자가 한 명이다 | 하루 다섯 명을 넘기면 결과가 안 나온 응시를 그날 안에 못 본다 |
