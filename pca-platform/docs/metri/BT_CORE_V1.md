# BT_CORE_V1 — 바이오·생명공학 (2026-10-13)

PHASE 2 의 두 번째 Core 다. `src/` 아래에서 바뀐 파일이 **한 벌**이고 그것도
더하기만 했다(`result/chains.ts` · 영역 열둘의 작성 차례 · 판정 로직 0줄).
채점과 결과 판정과 Workspace UI 와 DB 스키마가 한 줄도 바뀌지 않았고 앞 다섯
Core 의 지문이 그대로다.

```
종이 PRO 9쪽 · 배재대 자리 46 → 48
```

**분석과 품질관리를 나눈다.** 앞엣것은 재는 방법과 그 값의 신뢰 범위를 잡고
뒤엣것은 그 값으로 합격인지 판정하고 기록을 남긴다. 보는 것과 남기는 것이
다르면 영역이 다르다. 같은 까닭으로 **발효와 스케일업을 나눴다**: 작은 규모에서
조건을 찾는 일과 규모를 올려도 같게 나오게 하는 일이 다른 판단이다.

**열둘은 앞 Core 들의 수를 맞춘 값이 아니다.** `실험 노트 쓰기` 와 `문헌 읽기`
같은 일하는 방식은 영역으로 두지 않았다. 그런 것은 열두 영역 전부에 걸쳐 있어서
영역으로 두면 같은 자리를 두 번 센다. 들어간 자리는 축(J4 방법·도구 · J5
산출물)과 역할팩이다.

**필수 축을 영역의 성질에서 골랐다.** 배양과 클로닝과 스케일업 쪽은 실패·수정이
걸린다. 그 일은 안 되는 날이 많고, 까닭을 좁히는 것이 실력이다. 분석과 진단과
발효 쪽은 비교·검증이 걸린다. 품질과 생물안전 쪽은 산출물이 걸린다: **기록이
남지 않은 판정은 판정이 아니다.**

## 축과 역할기능과 조직환경은 같은 코드다

J1~J8 과 RF1~RF8 과 OC1~OC7 이 기계공학 Core 와 **같은 코드**다. 같은 자 위에
서야 두 전공의 결과를 견줄 수 있고, 전공마다 자를 새로 만들면 같은 학교 안에서
비교가 끊긴다. 이름은 생명공학의 말로 바꿨다: 도면 자리에 **실험 기록과 공정
조건표와 검증 보고**가 선다.

공통 판단 여섯과 학위 묶음 스물넷의 **문항 번호도 같게 둔다**. 결과지가 그
번호로 사람이 읽는 이름을 찾고(`result/text.ko.ts` 의 `COMMON_ITEM_KO`) 그 표는
Core 를 모른다. 번호를 새로 지으면 생명공학 응시자의 결과지에서 그 서른이
이름 없이 축으로 접힌다.

## 산업팩 여덟

의약품·바이오의약품 · 위탁 개발·생산 · 진단·시약·장비 · 식품·발효·소재 ·
농업·종자·동물 · 환경·바이오에너지 · 화장품·기능성 소재 · 공공 연구·검정 기관.

**`바이오` 를 산업으로 두지 않는다.** 그것은 분야 이름이지 하는 일이 아니고,
같은 분야 안에서 의약품과 진단과 식품과 환경이 서로 다른 판단을 묻는다. 완제
의약품과 위탁 개발생산을 따로 둔 것도 같은 까닭이다: 앞엣것은 **허가 서류가**
기준을 정하고 뒤엣것은 **고객사 한 곳의 규격이** 기준을 정한다.

**용어를 모른다고 부적합으로 적지 않는다.** 여든 문항 전부에 그 판단을 일반
생명공학 말로 바꿔 적은 줄이 붙는다. `파티클` 을 몰라도 `오염이나 청정을 설계
조건으로 다룬 경험` 이면 같은 판단이다.

## 역할팩 여덟

연구개발 실험(RF1) · 생물정보·데이터 분석(RF2) · 시험·검증(RF3) ·
생물공정·생산(RF4) · 장비·시설 운용(RF5) · 과제·임상 운영(RF6) ·
탐색 연구(RF7) · 품질보증·규제(RF8). 역할기능과 하나씩 맞물린다.

묻는 것은 **그 자리에서 가진 권한과 범위**다. **임상 운영을 따로 두지 않고
과제·임상 운영 안에 둔다**: 임상 담당이 내리는 판단은 여러 사람의 결정을 하나로
묶는 일이고 그 권한과 범위가 과제 관리 쪽과 같은 자리에 있다. 별칭으로 적어 그
공고를 찾는 사람이 닿게 했다.

## 갈래를 두지 않았다

배재대 생명공학과는 두 Catalog 모두 트랙을 두지 않고 학과 하나로 선다.
**쓰이지 않는 갈래를 미리 적어 두지 않는다**: 이름만 있는 갈래는 그 학과를
`갈래 작성 필요` 로 세워 놓고 아무것도 조정하지 않는다.

## 한 학과 이름이 두 Core 를 가리키지 않는다

처음 적은 별칭에 `생명과학과` 와 `분자생물학과` 와 `미생물학과` 가 들어 있었고,
그 셋은 `BIO_CORE_V1`(생명과학)이 이미 들고 있었다. **한 이름이 두 Core 를
가리키면 그 학과 학생이 어느 자로 재어졌는지 아무도 모른다.** `npm run v3:majors`
가 그 자리에서 걸렸고, 셋을 BT 에서 뺐다. 어느 쪽인지는 그 학과를 아는 분이
정한다.

## 자동 검사가 잡은 자리 셋

눈으로는 셋 다 멀쩡해 보인다.

- **심화 문면 하나가 두 가지를 묻고 있었다.** `쓸 통계 방법을 골라 가정을
  확인하고 적용해 본 적이 있다`. 고르는 일과 확인하는 일은 다른 판단이다
- **다른 영역의 문장을 돌려 쓴 자리 둘.** 배양을 버릴지 가르는 일과 배치를
  버릴지 가르는 일이 묻는 꼴이 같아져 있었고(0.83), 클로닝 설계를 다시 잡는
  일과 연구 설계를 다시 잡는 일은 **문장이 글자까지 같았다**(1.00)
- **역할팩이 서로를 베낀 자리 넷.** R1 문항 넷이 `~을 바꿀 권한을 가지고 그
  자리에서 확정한 경험이 있다` 한 틀을 돌려 썼고, 그러면 역할을 고른 사람이
  다른 역할의 문항을 다시 받아 역할팩이 파는 것이 사라진다. 같은 (영역·축)에
  같은 말로 두 번 묻던 자리 둘도 함께 다시 썼다

## 확인한 것

```bash
CORE=BT_CORE_V1 npm run core:all                 # 그 Core 의 검사 스물한 묶음
UI_BASE=http://127.0.0.1:3100 CORE=BT_CORE_V1 npm run core:walk   # 학과에서 종이까지 26가지
UI_BASE=http://127.0.0.1:3100 CORES=BT_CORE_V1 npx tsx scripts/v3-pdf-audit.ts
UI_BASE=http://127.0.0.1:3100 npm run pcu:coverage   # 자리 48 · 확인 50가지
```

`core:walk` 가 학과 선택에서 종이까지 실제 브라우저로 밟는다(화면 44 · 응답
69). **등급은 이용권이 아니라 학교 맥락이 정한다**: 그 줄이 `PRO` 로 열리는
것을 같은 자리에서 센다. 끝나면 등록부를 글자까지 되돌리고 쓴 자료를 지운다.

## 아직 아닌 것

학생에게 열지 않았다(`open_to_students: false` · `FOUNDATION`). 전공자 검토와
인지 면접과 실제 응답 기반 신뢰도·타당도 검증을 하지 않았으므로 `검증된 검사`
로 팔지 않고 규준도 백분위도 적합도 비율도 내지 않는다. 검토 묶음은
`docs/metri/BT_CORE_V1_REVIEW.md` 와 같은 이름의 `.csv` 다.
