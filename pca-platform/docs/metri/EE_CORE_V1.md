# 전기전자 Core 를 실제로 만들었다 (EE_CORE_V1 · 2026-10-12)

기계공학 Core 의 **자를 그대로 쓰고** 그 전공의 자료만 새로 썼다. 채점 엔진과
결과 모델과 응시 화면과 결과지 화면은 한 줄도 바뀌지 않았다. **학생에게는
아직 열지 않았다.**

```
Market → Major Core(EE) → Industry Pack → Role Pack → Region Layer
       → Evidence/Gap → Career Action
```

---

## 1. 측정 영역과 역량 구조

받은 열 가지 후보를 그대로 쓰지 않고 **열둘**로 다시 끊었다. 쪼갠 자리와
합친 자리와 더한 자리를 적어 둔다.

| 영역 | 이름 | 꼭 보는 축 | 후보 목록에서 온 길 |
|---|---|---|---|
| TD01 | 아날로그 회로 설계 | J3 · J5 | `회로이론/전자회로` 에서 아날로그 쪽 |
| TD02 | 디지털·논리 설계 | J3 · J6 | `디지털 회로와 임베디드` 를 **둘로 쪼갠 앞쪽** |
| TD03 | 임베디드·펌웨어 | J3 · J7 | 같은 후보의 **뒤쪽** |
| TD04 | 신호처리 | J3 · J6 | `신호 및 시스템` |
| TD05 | 통신·네트워크 | J3 · J6 | **더했다.** 후보 목록에 없고 학부 필수에 가깝다 |
| TD06 | 전자기·고주파 | J4 · J6 | `전자기학` |
| TD07 | 반도체 소자·공정 | J3 · J6 | `반도체/전자소자` |
| TD08 | 전력전자 | J3 · J5 | `전력전자/에너지` 를 **둘로 쪼갠 앞쪽** |
| TD09 | 전기기기·전력시스템 | J2 · J3 | `전기기기/전력공학` |
| TD10 | 에너지·신재생 시스템 | J3 · J6 | 같은 후보의 **뒤쪽** |
| TD11 | 제어·자동화 | J3 · J7 | `제어/자동화` |
| TD12 | 계측·시험·전자파 적합성 | J6 · J7 | `계측·시험·분석` |

**후보 가운데 하나는 영역으로 두지 않았다.** `설계·시뮬레이션·실험` 은 열두
영역 전부에 걸쳐 있는 **일하는 방식**이라 영역으로 두면 같은 자리를 두 번
세게 된다. 그것이 들어간 자리는 축 둘(J4 방법·도구 · J6 비교·검증)과
역할팩 둘(해석·시뮬레이션 · 시험·검증)이다.

**역량은 축 여덟이고 기계공학과 같은 자다.** 그래야 같은 학교 안에서 두
전공의 결과를 견줄 수 있다. 영역 열둘 × 축 여덟 = **칸 96개**가 전부
채워져 있다(수행 조건과 소유 조건이 칸마다 따로 적혀 있다).

| 축 | 이름 | 묻는 것 |
|---|---|---|
| J1 | 문제 정의 | 무엇을 다룰지 누가 정했는가 |
| J2 | 요구사항 해석 | 요구를 수치와 제약으로 옮겼는가 |
| J3 | 직접 기술 판단 | 내가 정한 항목이 무엇인가 |
| J4 | 방법·도구 | 무엇으로 어떻게 했는가 |
| J5 | 산출물 | 무엇이 남았는가 |
| J6 | 비교·검증 | 무엇과 견주었는가 |
| J7 | 실패·수정 | 틀린 것을 어떻게 좁혔는가 |
| J8 | 조직 활용 | 누가 무엇에 썼는가 |

그 위의 두 층도 기계공학과 같은 코드를 쓴다: **역할기능 여덟**(설계·개발 ·
해석·예측 · 시험·검증 · 공정·양산 · 운전·보전 · 통합·조정 · 탐색·연구 ·
품질·신뢰성)과 **조직환경 일곱**(완성품 기업 · 부품·장비·소재 기업 ·
엔지니어링·기술 서비스 · 출연연·국책연구 · 대학·연구실 · 공공·규제·인증 ·
스타트업·소규모 제조). 갈리는 것은 내놓는 산출물의 종류다: 도면 자리에
회로도와 공정 조건표와 보호 설정표가 선다.

## 2. 문항 수와 문항 은행 수와 자리 수

**셋을 구분해 적는다.** 기계공학의 수를 복제하지 않고 지금 코드가 쓰는
구성 규칙으로 세었다.

| 세는 것 | 전기전자 | 기계공학 | 무엇인가 |
|---|---|---|---|
| 문항 자리(blueprint) | 101 | 101 | 자리와 쓰임만 정한 틀 |
| Core 문항 | 233 | 233 | 자리에 들어간 문면 |
| 팩 문항 | 136 | 136 | 산업 80 · 역할 56 |
| **문항 은행 전체** | **369** | 369 | 위 둘의 합 |
| 체크리스트 | 231 + 공통 17 | 256 + 공통 17 | 고를 수 있는 판단 문장 |
| 직무 별칭 | 32 | 28 | 공고에 적히는 직무명 |
| 경계 쌍 | 13 | 12 | 헷갈리는 두 자리를 가르는 물음 |
| 관계표 | 96 + 96 | 96 + 96 | 영역×산업 · 영역×역할 |

**한 사람이 실제로 받는 응답 수는 이것과 다르다.** 자리 수는 틀이고 응답
수는 routing 이 정한다.

| 등급 | 화면 | 응답 | 추정 | 넷째 영역이 열리면 |
|---|---|---|---|---|
| BASIC | 25 | 46 | 12분 | — |
| STANDARD | 44 | 84 | 20분 | 51화면 · 97응답 · 24분 |
| PRO | 63 | 110 | 30분 | 70화면 · 123응답 · 33분 |

타계열 대학원(학부가 전기전자)은 번역 맥락 넷이 더 붙어 50 · 88 · 114 다.

**중복 문항을 만들지 않았다.** 문면 369개를 서로 견주어(글자 삼중쌍 겹침)
0.72 넘는 짝이 0이고, 묶음을 건너뛰어 같은 말로 묻는 짝도 0이다. 한 사람이
한 칸(영역 × 축)에서 받는 문항이 가장 많은 자리가 **넷**이다.

## 3. 연결된 학과와 전공별 차이

배재대의 자리 셋이 이 Core 를 가리킨다. **이름이 셋이고 Core 는 하나다.**

| Catalog | 자리 | 학과 이름 | 갈래 | 매핑 |
|---|---|---|---|---|
| 2026 | `PCU26_EE` | 전기전자공학과 | 없음(Core 전체) | EXACT |
| 2027 | `PCU27_EE_POWER` | 전기공학과 | `SPEC_EE_POWER` 전기·전력 | EXACT |
| 2027 | `PCU27_PHYSAI_ELEC` | AI융합전자전공 | `SPEC_EE_ELEC` 전자·회로 | EXACT |

**전기와 전자의 차이를 채점으로 만들지 않았다.** 갈래가 조정하는 것은 다섯
층(영역 강조 · 산업 사상 · 역할 사상 · 예시 · 증거와 행동)이고, 채점과 축
수준과 묶음 규칙과 문항 은행과 결과 모델은 건드리지 않는다. 세 갈래를
이번에 적었다.

| 갈래 | 먼저 보는 영역 | 먼저 보는 산업 | 먼저 보는 역할 |
|---|---|---|---|
| 전기·전력 | TD09 · TD08 · TD10 | 전력·에너지 · 자동차 전동화 · 산업자동화 | 설계 · 보전 · 기획 |
| 전자·회로 | TD01 · TD02 · TD07 | 반도체 · 가전 · 의료기기 | 설계 · 공정 · 시험 |
| 정보통신 | TD05 · TD04 · TD06 | 통신 장비 · 방산 · 가전 | 설계 · 해석 · 시험 |

같은 응답에 갈래만 바꿔 돌리면 Core 판정의 지문이 글자까지 같다
(`v3:scoring` 변형 검사 B).

## 4. 산업·역할 Pack 연결

| 산업팩 | 문항 | 역할팩 | 역할기능 | 문항 |
|---|---|---|---|---|
| 반도체·디스플레이 | 10 | 회로·시스템 설계 | RF1 | 7 |
| 자동차 전장·전동화 | 10 | 해석·시뮬레이션 | RF2 | 7 |
| 통신·네트워크 장비 | 10 | 시험·검증 | RF3 | 7 |
| 전력·에너지·신재생 | 10 | 공정·양산기술 | RF4 | 7 |
| 가전·소비자 전자 | 10 | 설비 운전·보전 | RF5 | 7 |
| 산업자동화·로봇 | 10 | 기술 기획·통합 | RF6 | 7 |
| 의료기기·계측장비 | 10 | 선행 연구개발 | RF7 | 7 |
| 방산·항공우주 | 10 | 품질·신뢰성 | RF8 | 7 |

**역할기능과 역할팩이 하나씩 맞물린다.** 둘이 같은 기능을 가리키면 두 팩의
비교가 같은 축에서 서지 않는다.

**산업팩은 산업 상식 퀴즈가 아니다.** 문항 여든 전부에 그 판단을 일반
전기전자 말로 바꿔 적은 줄(`gloss`)이 있다. 용어를 모른다고 부적합으로
적지 않는다.

**팩을 구독으로 막지 않았다.** 여덟 산업과 여덟 역할 전부를 결과에서 볼 수
있고, 한 응시에 깊게 묻는 것은 산업 하나와 역할 둘까지다.

**팩이 Core 판정을 바꾸지 않는다.** 산업과 역할을 갈아 끼우며 돌려 Core
지문이 같은 것을 확인했다(`v3:scoring` 변형 검사 C·D·15절).

## 5. Evidence · Gap · Career Action 예시

사람 열두 벌 가운데 한 벌을 그대로 적는다(`P12` · 석사 · PRO).

| 자리 | 값 |
|---|---|
| 근거가 선 영역 | TD01 아날로그 회로 설계 · TD08 전력전자 |
| 소유까지 간 축 | TD08 의 J3 직접 기술 판단 · J5 산출물 |
| Evidence | 고른 체크리스트 `스위칭 주파수를 손실 계산으로 정했다` 와 산출물 `변환 회로도` |
| Gap | TD12 계측·시험의 J5 산출물이 비어 있다 |
| 그 Gap 의 까닭 | `MISSING_OUTPUT` — 남은 것이 없으면 지원서에서 설명할 재료가 없다 |
| Career Action | `BUILD_OUTPUT` · 다음 과제에서 그 영역의 산출물 하나를 남긴다 |
| 할 일의 재료 | TD12 의 `artifacts`(시험 계획서 · 측정 절차서 · 시험 성적서)에서 가져온다 |
| 조직별 차이 | 완성품 기업 `출하 판정과 품질 비용` · 출연연 `과제 산출물로서의 측정 자료` · 공공·인증 `규격 적합 판정과 그 근거` |

**근거가 없는 능력을 보유했다고 적지 않는다.** 소유(`OWNED`)는 응답의 소유
수준과 **그 축의 근거 둘**을 함께 봐야 선다. 보기 맨 위를 전부 고르고 근거를
하나도 고르지 않은 사람은 소유 0칸이고 확인 0칸이다(`v3:gaming`).

**관심이 높다고 수행 가능으로 올리지 않는다.** 관심만 올리고 돌리면 축 상태와
확인된 축과 소유한 축이 글자까지 같다(`v3:scoring` 변형 검사 E).

**경험이 없다고 관심을 깎지 않는다.** 관심이 높고 겪은 적이 없는 사람의 다음
걸음은 공부가 아니라 `TRY_SHORT_EXPERIENCE` 이고, 배울 뜻까지 높을 때만
`STUDY_NEXT` 가 붙는다.

## 6. 기계공학 Core 와 다른 점

| 자리 | 같다 | 다르다 |
|---|---|---|
| 축 여덟과 척도 둘과 수준 넷 | 같다 | — |
| 역할기능 여덟과 조직환경 일곱 | 코드와 이름이 같다 | 내놓는 산출물의 종류 |
| 채점 규칙과 묶음 조건 | 같다 | — |
| 결과 모델과 결과지 화면 | 같다 | — |
| 문항 자리 101과 묶음 구성 | 같다 | — |
| 공통 판단과 학위 묶음의 **번호** | 같다 | 문면의 장면 |
| 기술영역 열둘 | 수만 같다 | 이름과 내용이 전부 다르다 |
| 체크리스트 | 틀이 같다 | 231개 전부 새로 썼다 |
| 산업팩 여덟·역할팩 여덟 | 수와 틀이 같다 | 내용이 전부 다르다 |

**공통 판단과 학위 묶음의 문항 번호를 같게 둔 것이 일부러다.** 결과지가 그
번호로 사람이 읽는 이름을 찾고(`result/text.ko.ts` 의 `COMMON_ITEM_KO`) 그
표는 Core 를 모른다. 번호를 새로 지으면 전기전자 응시자의 결과지에서 공통
판단 여섯과 학위 묶음 스물넷이 **이름 없이 축으로 접힌다.**

### 실제 브라우저로 끝까지

`npm run ee:walk` 가 **학과 선택에서 결과지 PDF 까지 한 사람이 이어서**
밟는다. 자리를 주소로 열지 않는다.

```
학과 상세 → 이 전공으로 검사 시작 → 공통 시작 화면 → 학부 →
응시 63화면 → 제출 → 스냅샷 → 결과 첫 화면 → 상세 → 종이
```

| 등급 | 확인 | 결과 |
|---|---|---|
| PRO | 26가지 | 통과 26 · 걸림 0 (화면 41 · 응답 70 · PDF 200) |
| BASIC | 24가지 | 통과 24 · 걸림 0 |

같은 명령이 **열기 전에 닫혀 있는지**와 **끝난 뒤 다시 닫혔는지**를 함께
센다. 등록부 두 복사본의 지문이 글자까지 같은 것까지 확인하고, 쓴 자료는
지운다.

1440 에서 밟고 **390px 로 자리 넷을 다시 열어** 가로로 밀리지 않는 것을
확인했다(학과 목록 · 학과 상세 · 시작 화면 · 결과 첫 화면).

### 응답 유형별

| 유형 | 사람 | 결과 |
|---|---|---|
| 관심만 높음 | P02 | 모두 `Z4` · 다음 걸음이 `짧게 겪어 보기` + `공부` |
| 경험만 있고 관심 낮음 | P03 | `Z3` · 다음 걸음에 `방향 다시 보기` |
| 전부 최고로 답함 | P04 | 소유 0칸 · 응답 품질 `LOW_VARIANCE` + 과대 보고 어긋남 |
| 모두 같은 점수 | P01 · P04 | `LOW_VARIANCE_GRID` |
| 누락과 `모르겠다` | P09 | 빈 것의 뜻이 넷으로 갈린다 |
| 짝이 어긋남 | 변형 18절 | `INCONSISTENT` 이고 Core 판정은 그대로 |

**결정적 재현성.** 같은 응답을 두 번 돌려 같은 값이고, 응답을 넣은 순서를
뒤집어도 같고, 사람 열두 벌의 Core 지문이 고정돼 있다.

**들어가면 안 되는 넷이 안 들어간다.** 학위 넷 · 전공계열 넷 · 산업팩 넷 ·
역할팩 넷을 갈아 끼워도 Core 판정의 지문이 글자까지 같다.

## 9. 남은 오류와 고치지 않은 까닭

### ① BASIC 에서 선별 네 축이 다 확인된 사람에게 할 일이 0개다

`CORE=EE_CORE_V1 npm run v3:result` 의 한 줄이 여기서 걸린다(P04 · P05).

**전기전자 때문이 아니다.** 같은 응답을 기계공학 Core 로 돌려도 똑같다:
`actions=0 · first_move=TRY`. 기계공학의 사람 열두 벌이 이 처지에 걸리는
벌을 들고 있지 않아서 그쪽에서는 드러나지 않았다.

**까닭.** `result/build.ts` 의 `actionsOf` 가 빈자리를 `opened.deep` 인
영역에서만 세고(BASIC 은 깊게 묻지 않으므로 0), 스냅샷의 `next` 도 비고,
마지막 그물인 `if (!s.focus.length && !out.length)` 가 **먼저 볼 영역이
있으면 걸리지 않는다.**

**고치는 줄은 하나다**: 그 조건을 `if (!out.length)` 로 바꾸면 그 사람에게
`EXPLORE_BROADLY` 가 선다. 기계공학 사람 열두 벌은 할 일이 0인 벌이 없으므로
출력이 바뀌지 않는다.

**이번에 고치지 않았다.** `result/build.ts` 는 측정 동결이 덮는 파일이라
고치면 결과 모델 판본을 올리고 동결 기록을 다시 적어야 한다. 받은 지시가
`기존 채점 엔진을 변경하지 않는다` 이고 결과 모델을 올리는 일은 기계공학
응시에도 닿으므로, **승인받고 한다.**

### ② 응시 스냅샷의 문항 은행 판본이 기계공학 것으로 적힌다

`scoring/version.ts` 의 `ITEM_BANK_VERSION` 이 전역 상수 하나다. 그래서
전기전자 응시의 스냅샷이 `module_versions.item_bank_version` 자리에
`ME_V3_ITEM_BANK_V2.5` 를 적는다. `core_version` 은 `EE_CORE_V1` 로 맞게
적힌다.

**닿는 범위.** 판정에는 들어가지 않는다(축 수준과 묶음은 그 Core 의 은행과
영역 사전만 읽는다). 틀리는 것은 **되짚을 때 읽는 이름표**다.

**고치는 줄은 하나다**: `engine.ts` 가 전역 상수 대신 `loaded.bank
.item_bank_version` 을 적으면 된다. 같은 까닭으로 승인받고 한다.

### ③ 이용권이 Core 를 가리키지 않는다

`v3Grants` 가 거르는 칸이 엔진의 전역 판본이고 `product_code` 는 기계공학
쪽 상품 줄이다. 그래서 `ee:walk` 도 꺼 둔 기계공학 상품 줄로 등급을 받는다.
파는 줄을 새로 만들지 않았다(`active = false` 인 줄을 썼다). 이용권과 상품
구조를 건드리는 일이라 이번 범위 밖이다.

### ④ `recompute.ts:377`

전부터 있던 자리다. 재분석의 `catch` 안에서 줄을 닫는 `finish()` 가 삼켜져
있고, `claim()` 이 5분 지난 줄을 다시 집어 저절로 풀린다. 재분석은
`v3_snapshots` 에 한 줄도 쓰지 않아 결과에 닿지 않는다.

### ⑤ `v3:migrate` 가 이 Core 에 돌지 않는다

옛 문항 은행이 없는 1차 판본이라 `migration` 파일과 동결한 지난 판본이 둘
다 없다. 그 검사가 세는 가장 중요한 두 줄(받고 쓰지 않는 문항 0 · 입력이
없는 결과 절 0)은 `v3:items` 1·3절과 `v3:result` 의 실제 응답 검사가 센다.

## 10. 개방 가능 여부

**지금 학생에게 열려 있지 않다.** 등록부에 `open_to_students: false` 로
적혀 있고, 막는 자리는 `sellableCores` 하나다. 가격표와 `/cores` 와 학교
진입과 `openAttempt` 가 전부 그 함수를 읽는다.

**`status` 와 따로 둔 까닭.** 짓는 동안에도 `v3:*` 검사를 돌려야 하는데 그
검사들이 `building` 인 Core 를 집는다. 그래서 **짓는 것과 여는 것을 두 칸으로
갈랐다.** 전에는 상태를 올리지 않는 것으로 막았고, 그러면 짓는 쪽이 자기
자료를 검사할 방법이 없었다.

배재대의 자리 셋은 학생 화면에서 `준비 중` 이다. `campus:check` 가 두 줄로
센다: 결과지까지 서는 자리와 열린 자리가 같은 자리인가, 그리고 열지 않은
Core 를 가리키는 자리가 검사 가능으로 서지 않는가.

### 아직 하지 않은 검증

**자동 테스트 통과는 타당도 검증이 아니다.** 아래는 사람이 해야 하고
하지 않았다.

1. **전공자 검토.** 문항 369개가 현장 말인지, 보기 둘과 셋과 넷이 실제로
   갈리는지는 전기전자 전공자와 현업자가 읽어야 한다
2. **인지 면접.** 응시자가 문항을 우리가 뜻한 대로 읽는지
3. **실제 응답 기반 신뢰도·타당도.** 규준이 없고 응답이 0건이다. 그래서
   `검증된 검사` 로 팔지 않는다
4. **산업팩 여덟의 용어.** 그 산업 경력자가 읽어 주셔야 한다
5. **지역 층.** 기관 자료가 0줄이라 유형까지만 적는다

### 운영

**운영 배포와 학생 공개를 하지 않았다.** 이 기계에서 운영과 같은 배치로
띄워 돌린 결과이고, 네트워크 정책이 `app.careermatri.com:443` 을 막아 운영
배포본을 열어 보지 못했다. **운영 배포 PASS 로 적지 않는다.**

DB 스키마를 한 줄도 바꾸지 않았으므로 마이그레이션은 필요 없다.

```bash
npm run ee:all     # 전기전자 Core 열네 묶음 (끝의 한 줄이 9절 ①)
npm run ee:walk    # 학과에서 결과지 PDF 까지 한 사람이 이어서
npm run ee:qa      # 영역 검토표 · 문항 추적표 · 팩 문서를 다시 만든다
```

생성물 셋은 `EE_CORE_V1_DOMAINS.md` · `EE_CORE_V1_ITEMS.md` ·
`EE_CORE_V1_PACKS.md` 다. 문항 추적표에 문항 369개가 **무엇을 재는가 ·
어떻게 받는가 · 어느 영역 · 어느 축 · 어느 산업·역할 · 어느 결과 절**로
한 줄씩 적혀 있다.
