# 58-3. 검사 화면 1차 디자인 (STEP 7)

화면 그림은 `docs/metri/shots/v3/` 에 있고 `npm run v3:shots` 가 실제
브라우저로 다시 찍는다. 자리마다 데스크톱과 모바일 두 장이다.

## 무엇을 노렸는가

전문적이고 차분하고 읽기 쉬운 쪽이다. 대학생부터 박사후연구원까지 같은
화면을 보고, 그 가운데 누구에게도 어색하지 않아야 한다. 심리검사
사이트처럼도, 취업포털 설문처럼도 보이지 않게 한다.

지킨 것 다섯이다.

**질문이 화면에서 가장 크다.** 머리띠와 단추와 진행 표시가 질문보다 눈에
먼저 들어오면 응시자는 읽기를 멈추고 누르기 시작한다.

**카드를 쌓지 않는다.** 한 화면에 한 가지를 묻는데 그것을 또 상자에 넣으면
상자만 보인다. 테두리는 보기 줄에만 돌린다.

**고른 자리를 색 하나로 말하지 않는다.** 테두리와 바탕과 동그라미가 함께
바뀐다. 색만으로 가르면 색을 못 가리는 사람에게는 아무것도 안 바뀐다.

**누르는 자리를 작게 만들지 않는다.** 보기 줄은 56px 이상이고 다섯 칸
척도도 48px 이다.

**무료라고 덜 만들지 않는다.** BASIC 과 PRO 가 같은 화면을 쓴다. 갈리는
것은 묻는 깊이이고 화면의 품질이 아니다.

색과 활자와 여백은 `surface.css` 의 토큰을 그대로 쓴다. 검사 화면만 따로
색을 들면 같은 제품이 두 가지 색으로 서고, 그 어긋남은 한 쪽씩 볼 때는
안 보이고 이어서 누를 때만 보인다.

## 정보 계층

한 화면에서 읽는 차례를 그대로 크기로 옮겼다.

```
작게    기구·제품 설계                 지금 보고 있는 영역
중간    산출물                        무엇을 묻는 자리인가
크게    연구 산출물로 부품도나 조립도를    질문
        내 손으로 그려 낸 경험이 있다
도움말  수업과 캡스톤과 인턴을 모두 포함   필요할 때만 한 줄
보기    없다 / 남이 한 것을 받아 썼다 /   보기마다 짧은 뜻
        내가 했다 / 내가 정하고 …
읽는 법 남이 정한 조건으로 돌리기만 한    보기 넷의 경계
        것은 두 번째 보기입니다
```

셋을 한 줄에 몰면 가장 작은 글씨가 가장 많은 것을 말하게 된다. 그래서
영역과 축을 갈라 올렸다.

**내부 코드는 한 글자도 나가지 않는다.** 문항 번호와 영역 코드와 축
코드가 화면에도 주소에도 없다. 주소에는 몇째인가만 적는다. 캡처 스크립트가
찍을 때마다 본문 글자에서 그 모양을 찾는다.

## 진행 표시

두 수준이다. 큰 단계는 **이름**으로 적고, 지금 묶음 안에서만 수를 적는다.

```
기본 정보 · 기본 탐색 · 기술영역 확인 · 경험 심화 · 경험 번역 ·
산업 탐색 · 역할 탐색 · 완료
                               3 / 13
```

`42 / 107` 만 적으면 그 수가 routing 으로 달라진다는 것을 말하지 않는다.
심화 영역이 하나 더 열리면 분모가 늘고, 그러면 응시자는 진행률이 거꾸로
간다고 읽는다. 좁은 화면에서는 단계 이름 여덟이 세 줄로 접히므로 지금
단계 하나만 남긴다.

## 쉬는 지점

묶음 사이에 전환 화면을 둔다. 짧고, 칭찬하지 않는다.

```
기본 탐색이 끝났습니다
겪어 보신 영역을 조금 더 봅니다
기구·제품 설계 · 구조·내구 해석 · 생산·공정기술
```

영역 이름을 머리글에 이어 붙이지 않는다. 가운뎃점으로 묶은 이름 셋에
조사를 붙이면 앞말에 따라 조사가 틀리고 줄이 두 줄로 접힌다.

## 반응형

1440 · 390 · 320 에서 본다. 세 폭 모두 가로 스크롤이 없다
(`v3:shots` 가 `scrollWidth > innerWidth` 를 버그로 센다).

- 글 폭은 680px 한 줄이고 양옆 여백은 16px 아래로 내려가지 않는다
- 다섯 칸 척도는 320px 에서도 한 줄에 들어간다. 칸마다 숫자와 말이 함께 선다
- 단계 이름 여덟은 720px 아래에서 지금 단계 하나로 줄어든다
- 근거 고르기는 720px 위에서 두 칸, 아래에서 한 칸이다
- 바닥 단추띠는 `env(safe-area-inset-bottom)` 만큼 더 띄운다

## 접근성

- 보기는 진짜 라디오와 체크박스다. 같은 `name` 이라 화살표로 옮겨진다
- 초점 표시가 보인다(`:has(input:focus-visible)` 로 줄 전체에 테두리)
- `fieldset` 과 `legend` 로 묶음 이름을 읽어 준다. 다섯 칸 척도는
  칸마다 `aria-label` 에 줄 이름과 보기 말이 함께 들어간다
- 진행 막대에 `role="progressbar"` 와 값이 붙는다
- 고른 자리를 색만으로 말하지 않는다
- 움직임을 줄이는 설정이면 전환을 끈다

`v3:shots` 가 한 자리에서 키보드만으로 보기에 닿아 고르고, 그때 초점
표시가 실제로 그려지는지까지 본다.

## 아직 UX 판단이 필요한 자리

**보기 넷의 경계를 사람들이 가르는가.** 화면에는 보기마다 짧은 뜻을
붙이고 아래에 읽는 법 한 줄을 두었다. 그래도 `내가 했다` 와 `내가 정하고
그 결과가 쓰였다` 를 응시자가 실제로 가르는지는 파일럿에서만 나온다.

**근거 고르기가 길다.** 영역 하나에 묶음 열이고 항목이 스무 개를 넘는
자리가 있다. 지금은 전부 펼쳐 두었다. 접어 두면 고르는 사람이 줄고,
고른 항목이 소유 판정의 근거라서 **접는 쪽이 판정을 바꾼다.**

**번역 단계의 한 줄 칸.** 보기를 고르면 단계가 서고 줄은 선택이다. 적는
사람이 적으면 결과지가 그 사람의 말을 옮길 재료가 없다.

**추정 시간.** 다섯 단위로 올려 적고 `안팎` 을 붙였다. 실측이 아니다.

**완료 화면에서 더 갈 데가 없다.** 결과지 화면이 아직 없어서 `결과를
만들었다` 에서 멈춘다. 다음 회차에서 이 자리가 결과로 이어진다.
