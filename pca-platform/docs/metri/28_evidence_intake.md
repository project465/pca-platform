# 경험 입력

규격 v4 의 `evidence` 와 `research_project` 를 응시자가 실제로 채우는 화면이다.
전에는 두 칸이 늘 비어 있어서 증거 지도와 과제 카드가 **빈 양식**으로 나갔다.

---

## 1. 첫째 규칙

**경험은 적합도에 들어가지 않는다.**

채점은 `engine.js` 가 문항 응답만 보고 하고, 경험은 그 뒤에 붙는다. 경험을
고치거나 지워도 FIT 은 한 점도 바뀌지 않는다. 그래서 저장도 따로 둔다.

```
pca_session_v1    응답과 점수       손대지 않는다
pca_evidence_v1   경험
pca_research_v1   연구 과제
pca_target_v1     목표 국가 · 산업 · 직무
```

이 분리가 지켜지는지는 `npm run evidence:check` 1번 항목이 매번 확인한다.
같은 응답이면 같은 점수가 나와야 학과 담당자가 재계산해 볼 수 있다.

흐름은 이렇다.

```
검사 응답 → 채점 → 결과 JSON → 경험 입력 → evidence · research_projects 결합
         → stage · country · research 해석 → writing.js → 자체검수 → 출력
```

---

## 2. 화면

세 걸음이고, **고른 것만 묻는다.**

| 걸음 | 무엇 | 시간 |
|---|---|---|
| 1 | 어떤 경험이 있나요 (복수 선택) | 30초 |
| 2 | 고른 종류의 폼만 | 3~5분 |
| 3 | 연구 과제와 목표 (선택) | 선택 |

2단계까지만 하고 나가도 결과지가 달라진다. 폼을 전부 펼쳐 두면 쓸 일 없는
칸이 스무 개 보이고, 거기서 사람이 닫는다.

**학위 단계가 묻는 것을 바꾼다.** 학부생에게 연구비와 공고 해석을 필수로
묻지 않는다. 겪은 사람만 열어 적는다.

| 단계 | 먼저 묻는 것 | 연구 과제 상세 |
|---|---|---|
| 학부 | 수강과목 · 프로젝트 · 인턴 · 공모전 · 도구 | 열어 두되 필수가 아님 |
| 석사 | 수강과목 · 프로젝트 · 연구 · 도구 · 논문 | 발주 기관 · 기간 · 팀 · 목표 · 방법 |
| 박사 | 연구 · 프로젝트 · 논문 · 특허 · 도구 · 지도 | 위 + 예산 · 기획 · 규정 |
| 학위 후 | 연구 · 논문 · 특허 · 지도 · 도구 | 위와 같음 |

---

## 3. 모르는 것을 쓰게 하지 않는다

빈칸의 뜻이 셋이라 따로 담는다.

```
unknown         있었는데 내가 모른다 (총 연구비 같은 것)
not_supplied    아직 안 적었다
not_applicable  그런 것이 없었다
```

**비웠다고 불리해지지 않는다.** 준비 정도는 걸린 신호만 세고, 안 적은 칸을
감점으로 쓰지 않는다. 그리고 비워 둔 칸은 결과지에서도 비워 둔다. 총
연구비를 안 적으면 금액이 한 줄도 나오지 않는다(`evidence:check` 5번).

---

## 4. 한 일과 고른 것을 가른다

프로젝트 폼에서 `what_i_did` 와 `decisions_i_made` 를 따로 받는다.

> 한 일: 하중 경로를 나누고 형상 세 안을 비교했습니다
> 고른 것: 가공비가 덜 오르는 쪽으로 리브 배치를 골랐습니다

서류와 면접에서 읽히는 쪽은 뒤엣것이다. 앞엣것만 적으면 누구의 경험이든
비슷하게 읽힌다.

**도구도 이름만 받지 않는다.** 카테고리, 이름, 쓴 수준, 무엇을 하려고 썼는지를
함께 받는다. 프로그램 이름 하나로는 무엇을 할 줄 아는지 말할 수 없어서,
결과지도 그렇게 쓰지 않는다(`evidence:check` 7번).

---

## 5. 준비 정도

직무군마다 '이 자리를 보려면 무엇이 있어야 하는가' 를 신호로 적어 두고
(`content/evidence-rules.json`), 응시자의 경험이 거기 걸리는지만 본다.

```json
{
  "career_family_id": "ME_CAE_SIM",
  "level": "high",
  "supported_by": ["수강: 유한요소해석", "메시 민감도", "시험 비교"],
  "missing": ["해석 결과를 설계 판단으로 옮겨 본 것"]
}
```

**숫자를 먼저 만들지 않는다.** 검증된 모형이 없는 상태에서 가중 평균을 내면
그 소수점이 근거처럼 보인다. 지금은 걸린 것과 안 걸린 것을 세고, 무엇
때문에 걸렸는지를 같이 들고 다닌다. 자료가 쌓이면 그때 수치로 바꾼다.

같은 경험 한 벌로 여덟 직무군을 돌리면 이렇게 갈린다.

```
ME_DESIGN_PRODUCT   high    5/6   도구: SolidWorks | 수강: 기계요소설계
ME_CAE_SIM          high    5/6   수강: 유한요소해석 | 메시 민감도
ME_RND              low     0/6
ME_MANUFACTURING    low     0/6
```

전부 같은 레벨이 나오면 신호가 안 걸린 것이고, 그건 규칙 쪽을 고칠 자리다.

---

## 6. 연구 수행 성숙도

**학위로 배정하지 않는다.** 적어 주신 과제에서 근거를 찾아 올린다.

```
RP0 참여 → RP1 과업 수행 → RP2 과제 덩어리 → RP3 설계 참여 → RP4 총괄
```

한 칸을 올리려면 그 칸의 근거가 **둘 이상** 있어야 한다. 하나로 올리면 칸
하나를 채운 사람과 끌고 간 사람이 같아진다. 왜 그 칸인지와 다음 칸으로
가려면 무엇이 필요한지를 같이 적는다.

네 단계의 예시 응시자로 돌린 결과다. 학위가 아니라 **적은 내용**이 칸을
정하는 것이 보인다.

| 응시자 | 적은 것 | 나온 칸 |
|---|---|---|
| 석사 | 산학 과제 참여, 내 목표와 방법 | RP1 과업 수행 |
| 박사 | 위 + 공고 검토, 세부 과제, 중간 점검, 결과물 | RP3 설계 참여 |
| 학위 후 | 위 + 예산 산정, 세부과제 책임, 계획 변경 | RP4 총괄 |

공고를 확인하지 않은 사람에게 확인했다고 쓰지 않는다(`evidence:check` 6번).

---

## 7. 경험이 결과지에서 쓰이는 곳

받기만 하고 안 쓰는 칸은 만들지 않았다.

| 절 | 무엇을 쓰는가 |
|---|---|
| 이미 가지고 계신 것 | 해본 것 · 배운 것 · 써 본 도구 · 남은 결과물, 그리고 비어 있는 것 |
| 이 자리에 쓸 근거가 얼마나 되는가 | 상위 세 직무의 준비 정도와 걸린 근거 |
| 적어 주신 연구 과제 | 과제 카드. 비운 칸은 비운 채로 |
| 연구를 어떻게 수행해 왔는가 | RP 사다리와 지금 칸 |
| 다음 이레 동안 할 것 | 비어 있는 신호 가운데 하나를 집는다 |
| 정보량 | 경험이 들어오면 `low` 에서 올라간다 |

STANDARD·PRO 의 긴 결과지에는 위 칸들이 맨 앞 안내와 함께 붙는다.

---

## 8. 처음 온 사람과 전에 응시한 사람

경험이 없어도 오류가 나지 않고, 결과지 맨 위에 안내가 붙는다.

> 지금 등록된 프로젝트·연구·인턴 경험이 없어 경험을 바탕으로 한 분석은
> 제한적으로만 나갑니다. **[경험 추가하기]**

**빈 상태를 조용히 두지 않는 것**이 요점이다. 적지 않으면 할 수 있는 말이
줄어드는데, 그 사실을 적지 않으면 읽는 사람은 이 검사가 원래 그 정도인 줄
안다.

## 9. 검사

```bash
npm run evidence:check
```

| 확인 | 왜 |
|---|---|
| 경험 입력 전후 FIT 동일 | 이 하나가 깨지면 나머지가 다 의미 없다 |
| 경험을 넣으면 준비 정도만 생긴다 | 문항으로 잰 준비도는 그대로여야 한다 |
| 학사에게 연구기획을 필수로 묻지 않는다 | 못 적는 칸을 필수로 두면 거기서 닫는다 |
| 박사·포닥은 연구 과제를 적고 결과지에서 받는다 | 받기만 하고 안 쓰면 입력이 헛수고다 |
| 연구비 미입력 시 금액을 만들지 않는다 | 지어낸 금액은 면접에서 바로 갈린다 |
| 공고 미확인을 확인했다고 쓰지 않는다 | 같은 이유 |
| 도구 이름으로 숙련을 단정하지 않는다 | 프로그램을 썼다는 것과 할 줄 안다는 것은 다르다 |
| 프로젝트 결과 숫자를 지어내지 않는다 | 가장 비싼 고장이다 |
| 지운 경험은 남지 않는다 | 지웠는데 남으면 지웠다는 말이 거짓이 된다 |
| 경험 없는 응시자도 열리고 안내가 뜬다 | 전에 응시한 사람이 오류를 만나면 안 된다 |

---

## 10. 아직 못 한 것

**목표 국가를 받되 쓰지 못한다.** 3단계에서 국가를 받지만 확인된 나라별
자료가 아직 없어서 결과지는 "자료가 없어 넣지 않았다" 를 그대로 낸다.
나라마다 출처와 확인 날짜가 붙은 자료가 들어와야 열린다.

**서버에 저장하지 않는다.** 정적 배포라 전부 브라우저 안에만 있다. 기기를
바꾸면 다시 적어야 한다. 운영 배선에서는 `career_evidence`·
`research_projects` 테이블로 가야 하고, 그때도 **FIT 계산 경로에서 이 표를
읽지 않는 것**을 테스트로 묶어 둬야 한다.

**규칙이 기계공학 하나다.** `content/evidence-rules.json` 의 신호 목록은
기계공학 여덟 직무군만 있다. 전공을 늘릴 때마다 그 전공의 신호를 따로
적어야 하고, 기계공학 것을 그대로 쓰면 안 된다.
