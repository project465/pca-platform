# P. 유지·교체·폐기 목록 · Q. 구현 순서 · 자기 점검

## 1. P. 네 갈래로 가른다

과거 개발량 때문에 나쁜 구조를 살리지 않는다. 판단 기준은 하나다.
**그것이 틀린 모형 위에 서 있는가.**

### 1-1. 그대로 유지

| 자산 | 왜 |
|---|---|
| 로그인과 세션, `users` · `memberships` · `organizations` | 모형과 무관하다 |
| 주문 · 결제 · 환불 표와 어댑터 계약, 금액·통화 대조 | 돈길은 검사 모형과 독립이다 |
| 등급을 정하는 한 함수(`entitlement.ts`) | 설계 원칙 10 이 지켜지고 있다 |
| PDF 생성 경로(머리 없는 브라우저 · 한글 글꼴 · 볼륨 · 본인 확인) | 엔진 내용과 무관한 배관이다 |
| 사전 구조와 두 언어 대조 검사 | 원고가 바뀌어도 틀은 그대로 쓴다 |
| 메일 대기열과 아홉 갈래 발송 | 같다 |
| 운영 점검 묶음(`ops:check` · `launch:check` · `db:verify` · 복구) | 같다 |
| 화면 토큰과 세 면의 구조(`surface.css`) | 같다 |
| 홈페이지와 앱의 경계, 시장·언어 분리 | 같다 |
| 파일럿 설문과 5명 규칙 | 새 모형을 재는 데 그대로 쓴다 |
| 퍼널 계측과 사고 화면 | 같다 |

### 1-2. 구조는 유지하고 내용을 교체

| 자산 | 유지하는 것 | 교체하는 것 |
|---|---|---|
| 문항 은행 JSON 스키마 | 문항마다 구성개념 · 척도 · 가중치를 데이터로 드러내는 방식 | 문항 전체와 영역 키 |
| 엔진 모듈 경계(채점 → 결과 JSON → 결과지) | 네 파일로 갈라 둔 구조 | 채점 산식과 판정 규칙 |
| 증거 지도(영역 199개) | 현업 용어로 적힌 영역 목록과 `minimum_depth` | 직무 열여섯에서 기술영역 열둘로 재배치. 매칭을 체크리스트 주도로 |
| 가치 사슬(`me-value-paths.json`) | 전공지식 → 업무 → 판단 → 산출물 → 성과 사슬 | 고정 텍스트를 응답에 따라 고르는 구조로 |
| 학위별 문면 메커니즘(`stage-variants.json`) | 같은 구성개념을 단계별 장면으로 묻는 방식 | 문항 범위를 번역 열 단계로 확장 |
| 되묻는 말(`followups.json`) | 빈 칸을 선택지로 채우는 방식 | 영역 열둘 기준으로 다시 쓴다 |
| 증거 사다리 E0~E5 | 깊이 개념과 칸 건너뛰기 금지 | 표시 이름을 고객 말로 |
| 결과지 렌더러 | 쪽 구조와 인쇄 규격 검사 | 절 구성과 첫 쪽 |
| 경험 입력 화면 | 고른 것만 묻는 세 걸음 | 판단 체크리스트를 중심으로 재배치 |

### 1-3. 폐기

| 폐기 | 왜 |
|---|---|
| 직무군 열여섯 목록과 그 이름표 | 축이 섞여 있다 |
| 관심 하나로 정렬하는 `table()` | 차례를 만드는 권한을 한 축에 주었다 |
| 상태 아홉 개와 그 격자 규칙 | interest × exposure 격자에 기술 내용이 없다 |
| 업무 방식 세 축 여섯 문항과 `mode-fit.json` | 두 문항으로 성향 축을 가르고, 판정에 쓰이지 않는다 |
| 공통 임계값 62 · 38 | 뜻이 다른 척도에 같은 경계를 쓴다 |
| 증거 신호 표의 여덟 직무 한정 | 판정 경로가 직무에 따라 갈린다 |
| 48 · 68 · 92 분할 | 구성개념으로 자른 분할이라 등급 값과 어긋난다 |
| 홈페이지의 공고·역량 수치 | 제품이 계산하지 않는 값이다 |
| 맥락 문항 열셋을 받고 쓰지 않는 구조 | 받고 쓰지 않으려면 묻지 않는다 |

### 1-4. 검증 후 결정

| 열어 둔 것 | 무엇으로 결정하는가 |
|---|---|
| 옛 검사 ME_V1(253문항)을 계속 둘지 | 학과 계약이 그것을 쓰는지. 쓰지 않으면 읽기만 남긴다 |
| 공통 결정 소유 문항을 몇 개 남길지 | 영역별 판단 문항과 겹치는 정도를 파일럿에서 본다 |
| 연구 번역 facet 열둘 전부 쓸지 | 응답 분포를 보고 줄인다 |
| 결과지 분량 | 지원서 쓸 때 실제로 펴는 쪽 수를 파일럿에서 묻는다 |
| STANDARD 와 PRO 의 경계 | 가치 차이 문항과 전환율 |
| 지역 layer 의 공고 자료 확보 방법 | 저작권과 이용약관 검토 결과 |

## 2. 새 검사를 어떻게 올리는가

**지금 문항을 고치지 않고 판본을 올린다**(설계 원칙 4). 새 검사지 키를
`ME_V3_DOMAIN_2026` 으로 두고 ME_V2 와 나란히 둔다.

| | ME_V2 | ME_V3 |
|---|---|---|
| 문항 | 92, 그대로 보존 | 선별 36 + 심화 24 + 번역 12 |
| 영역 키 | 직무군 16 | 기술영역 12 × 역할 7 × 조직 7 |
| 응시 기록 | 읽기만 | 새 응시는 전부 이쪽 |
| 결과지 | 옛 판 그대로 열린다 | 새 절 구성 |

이미 응시한 사람의 결과지가 바뀌지 않는다. 그리고 두 판본을 같은 사람이
보는 일이 생기지 않게, 판매 중 상품은 한 판본만 가리킨다.

## 3. Q. 구현 순서

열 단계다. 각 단계에 **끝났다고 말할 조건**을 붙인다. 앞 단계가 끝나기
전에 다음으로 가지 않는다.

| 순서 | 무엇 | 끝났다고 말할 조건 |
|---|---|---|
| 1 | 기술영역 열둘과 역할 일곱과 조직 일곱을 데이터 파일로 확정 | 별칭표 24줄이 조합으로 풀리고, 경계표 열 쌍의 구분 질문이 전부 문항 후보로 적혀 있다 |
| 2 | 영역별 workflow 열 가지를 데이터로 옮긴다 | 열두 영역 전부에 판단 목록 · 산출물 목록 · 검증 대상 목록 · 성과 이름이 OC 일곱 별로 적혀 있다 |
| 3 | 증거 지도 199영역을 열두 영역으로 재배치 | 영역마다 판단 축 여덟에 하나 이상 걸리고, 고아가 된 영역이 0 |
| 4 | 문항 72개를 쓴다(선별 36 · 심화 24 · 번역 12) | 역채점 셋 포함. 중복 검사 통과. 문항마다 어느 결과 절로 가는지 적혀 있다 |
| 5 | 채점과 판정을 다시 짠다 | 영역별 I · G · L 과 네 묶음이 나오고, 같은 응답이면 같은 결과가 나온다 |
| 6 | 경험 입력을 체크리스트 중심으로 바꾼다 | 자유입력 없이도 판단 축이 확인되고, 서술은 추가 근거로만 쓰인다 |
| 7 | 결과지 절 열 가지를 그린다 | 본문에 내부 이름이 0개. 인쇄 규격 통과. 되짚기 부록에 문항 번호가 남는다 |
| 8 | 번역모델과 지원서 문장 초안 | 연구 입력만으로 영역 둘 이상에 근거가 붙고, 빈 단계는 빈 채로 적힌다 |
| 9 | 등급 경계와 상품 원고 | 등급마다 판단의 종류가 다르고, 검사가 그것을 센다 |
| 10 | 지역 layer 와 홈페이지 | 자료 없는 교차가 `자료 없음` 으로 적히고, 홈페이지에서 확인되지 않은 수치가 0 |

**1번에서 3번까지가 데이터 작업이고 코드가 거의 없다.** 그 자리를 먼저
끝내야 문항과 결과지가 같은 축 위에 선다. 지금 제품이 어긋난 자리가 바로
거기다.

### 병행해도 되는 것

| 병행 | 왜 |
|---|---|
| 파일럿 20~30명 (지금 제품으로) | 새 모형의 가정을 재는 자료가 된다. 특히 이해도와 표현 지적 |
| PG 내부 확인과 메일 연결 | 검사 모형과 독립이다 |
| 운영 인프라 확인 | 같다 |

### 멈추는 선

| 신호 | 멈추고 다시 보는 것 |
|---|---|
| 1~3 단계에서 영역 경계가 열 쌍 가운데 셋 이상 애매하다 | 영역 수를 줄인다(열둘에서 아홉으로) |
| 4 단계에서 선별 36문항이 15분을 넘는다 | 영역 경험 문항을 빼고 24로 줄인다 |
| 5 단계에서 묶음이 응답에 거의 반응하지 않는다 | 확인 조건을 다시 본다 |
| 6 단계에서 체크리스트가 길어 응시자가 닫는다 | 영역마다 판단 항목을 다섯으로 줄인다 |

## 4. 자기 점검 · 기계공학 대학원생이 아직 지적할 자리

마지막 판단 기준을 스스로 적용한다. **아래 여덟 가지는 이 설계에도 남아
있다.** 남아 있다고 적는 것이 지금 할 수 있는 일이고, 넷은 이번 설계
안에서 완화했다.

| 남은 약점 | 왜 남는가 | 이번 설계에서 한 것 |
|---|---|---|
| 1. 산업 특화 깊이 | 같은 TD02 가 자동차와 반도체 장비와 조선에서 다른 말을 쓴다 | 별칭표에 산업 변형 칸을 두었지만 1차 자료는 비어 있다 |
| 2. 공고 수요 자료가 없다 | 어느 영역이 어디서 사람을 뽑는지 자료가 없다 | 지역 layer 의 `industry_role_demand` 를 `근거 약함` 으로 표시하고 내보낸다 |
| 3. 자기보고의 한계 | 판단 체크리스트도 자기보고다 | 한 줄 근거를 함께 받고, 같은 축을 두 장면에서 물어 일관성을 본다. **객관 평가가 아니라는 것을 결과지에 적는다** |
| 4. 규준이 없다 | `8개 중 5개` 가 많은지 적은지 말할 수 없다 | 개수와 이름으로만 말하고 비율과 등급을 쓰지 않는다. 파일럿 뒤 분포를 붙인다 |
| 5. 숙련도를 재지 않는다 | 해봤다와 잘한다는 다르고, 제품은 뒤를 재지 않는다 | 척도 이름과 결과지에 그 경계를 적는다 |
| 6. 세부 깊이가 영역마다 고르지 않다 | 공차와 GD&T, 용접, 금형은 체크리스트가 더 쪼개져야 한다 | 2단계 데이터 작업으로 미뤘고 그 사실을 적는다 |
| 7. 학부 저학년에게는 얕다 | 2학년이 고를 판단이 적다 | 대상을 3학년 이상으로 적고, 저학년에게는 수업 기반 경로를 따로 적는다 |
| 8. 조직환경 자료가 유형까지다 | 기관별 평가 지표를 지어내지 않는다 | 유형까지만 적고 기관 이름을 적지 않는다 |

### 이번 설계가 없앴다고 말할 수 있는 자리

| 없앤 것 | 근거 |
|---|---|
| 직무 하나를 문항 하나가 대표하는 구조 | 선별 2문항 + 심화 8문항 |
| 관심이 차례를 정하는 구조 | 묶음은 확인된 판단 축 수로 만든다 |
| 대학원 경험이 측정되고 버려지는 구조 | 번역 열 단계가 영역에 근거를 꽂는다 |
| 해본 사람에게 안 했다고 말하는 매칭 오류 | 체크리스트 주도, 키워드는 보조 |
| 축이 섞인 분류 | 기술영역 · 역할 · 조직환경 세 축 |
| 결과에 쓰이지 않는 문항 | 문항마다 어느 결과 절로 가는지 적는 것이 4단계의 완료 조건 |
