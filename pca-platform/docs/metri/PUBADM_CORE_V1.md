# PUBADM_CORE_V1 — 행정 Core (2026-10-13)

행정계열 Core 를 **콘텐츠만으로** 더했다. `src/` 아래에서 바뀐 파일이 한
벌이고 그것도 더하기만 했으며(`result/chains.ts` · 영역 열둘의 작성 차례 ·
판정 로직 0줄), 채점과 결과 판정과 Workspace UI 와 DB 스키마가 한 줄도
바뀌지 않았다. 네 Core(기계공학 · 전기전자 · 컴퓨터 · 경영)의 지문이 그대로다.

**열둘은 앞 Core 들의 열둘을 맞춘 수가 아니다.** 행정이 실제로 내리는
판단을 세어 보니 열둘이고, `문서 작성` 과 `보고` 같은 **일하는 방식**은
영역으로 두지 않았다. 그런 것은 열두 영역 전부에 걸쳐 있어서 영역으로
두면 같은 자리를 두 번 센다. 들어간 자리는 축(J5 산출물 · J8 조직 활용)과
역할팩이다.

**예산과 회계를 갈랐다.** 앞엣것은 앞으로 쓸 돈을 추계해 가르고 뒤엣것은
이미 나간 돈을 증빙과 맞춘다. 보는 것과 남기는 것이 다르다.

## 3. 산업팩 여덟과 역할팩 여덟

산업은 중앙행정 · 지방행정 · 복지보건 · 재난소방안전 · 도시교통환경 ·
산업경제진흥 · 교육문화 · 공공기관공기업이다. **`공무원` 을 산업으로 두지
않는다**: 그것은 신분이지 하는 일이 아니고, 같은 신분 안에서 중앙과 지방과
규제와 재난이 서로 다른 판단을 묻는다.

역할은 역할기능 여덟과 **하나씩 맞물린다**: 정책 기획(RF1) · 예산·재정(RF2) ·
심사·감사(RF3) · 재난·안전 관리(RF4) · 민원·현장(RF5) · 사업관리·조달(RF6) ·
조사·분석(RF7) · 인사·제도(RF8). **법무를 따로 두지 않고 심사·감사 안에
둔다**: 법무 담당이 내리는 판단은 요건이 맞는지를 가리는 일이고 그 권한과
범위가 감사 쪽과 같은 자리에 있다. 공고를 찾는 사람이 닿게 별칭으로 적었다.

## 4. 갈래 둘

`SPEC_PUBADM_GENERAL` 일반행정은 정책·예산·민원을 먼저 읽고,
`SPEC_PUBADM_FIRE` 소방행정은 재난·안전과 민원과 법령을 먼저 읽는다. 배재대
행정학과의 두 트랙과 하나씩 맞물린다. **갈래는 Core 판정을 바꾸지 않는다**:
조정하는 다섯 층 밖으로 나가지 않는다.

**문면을 쓰다 네 자리가 걸렸고 넷 다 고쳤다.** 심화 문면 셋이 소유(`l3`)를
적고 있었고(기획안을 `다른 사람이 읽을` 문서로 · 검토 의견을 `다른 사람이
읽을` 문서로 · 기준을 `협의 자리에서 설명해`), 역할팩 여덟이 역할기능과
하나씩 맞물리지 않았고, 산업팩 둘이 같은 정산 문장을 돌려 썼고, 산업팩 넷이
영역 문항과 같은 말로 묻고 있었다.

## 6. 아직 아닌 것
