Staging · `app.careermatri.com` · `pcu.ac.kr` 가 CONNECT 403 이라 Next 를 빌드할 수 없고 운영을 열 수 없다. 그래서 브라우저 쪽은
전부 **NOT VERIFIED** 이고, 아래 PASS 는 **서버 함수 · 실제 로컬 PostgreSQL · 실제 PDF 렌더(Chromium)** 기준이다.

## Track A · 남은 것

- 유사도 0.85 이상 6쪽: 2 · 77 · 78쪽은 구조가 같아야 맞는 쪽, 28 · 29 · 36쪽은 같은 회사의 공시·지역 자료가 중심이라 닮는다.
- POOR 의 6개월 계획 ‘결과물 3건을 포트폴리오로 묶기’ 는 `report3.ts` 문장이라 이번 범위 밖(고른 결과물 0건이라 오해 소지).
- 면접 질문 쪽에서 질문과 붙는 ‘내가 정한 것’ 이 어긋나 보이는 자리가 있다(예: 숫자 목표 질문 ↔ 예산 항목 나누기). 다음 회차.
- 사람이 눈으로 읽은 쪽은 약 25쪽. 직무 문장의 적합성은 현직자 검토(R12).

## Track B · 남은 것

- 공식 2026/2027 학과 원문을 이 환경에서 열지 못해 `verified_at` 이 비어 있다(`SECONDARY_EVIDENCE`).
- 전공 고르기 자리 2(자율전공)는 학생이 고른 전공으로 열리는 길이라 이 검사에서 열지 않았다(브라우저 검사 `pcu:routing` 몫).
- 경험 번역 메뉴(`TRANSLATE_MENU`)는 ME · BIZ 만 전공 말이다. 나머지 18 Core 로 넓히려면 검사 화면 판본을 올려야 해 이번에 하지 않았다.
- 사전 168줄이 그 전공에서 자연스러운지는 전공자 검토가 필요하다.

## Track C · 찾고 고친 것

- `v3:runtime` 의 ‘팩을 바꿔도 Core 판정이 같다’ 가 **아무것도 재지 않고 있었다**: R33 이후 `submit()` 은 굳은 응시에 결과를 다시 쓰지
  않아 같은 줄을 두 번 읽었다. 팩을 바꾼 응답 묶음을 엔진에 바로 넣어 재게 고쳤다(29/29).
- 확인한 것: 중복 응시 없음 · 덮어쓰기 · 동시 저장 · 남의 응시 쓰기/제출 거절 · 이어하기 · 동시 제출 5번 → 결과 1벌 · 제출 뒤 쓰기 거절 ·
  사용자별 결과/경험 격리 · 저장된 응답으로 다시 채점하면 같은 판정 · **DB 연결을 끊은 직후 저장이 다시 붙음**(이 과정의 연결만 끊었다).
- 이 환경의 `pg` 는 저장소 밖 대체 드라이버(psycopg 다리)다. 재연결 판단 코드는 제품의 `db.ts` 그대로지만 드라이버가 다르다.

## Track D · 찾은 것 · 남은 것

- 결함 없음. 다만 이 개발 DB 에 PCU 의 실제(비시연) 응시가 0건이라 PCU 집계 대조는 0=0 이다. 실제 숫자 대조는 ZZTEST(6명 · 5명 완료)로 했다.
