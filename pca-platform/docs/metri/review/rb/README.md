## 1. 학교 계정의 `/v3/start` 직접 접근 (P0 · 고쳤다)

**무엇이 새고 있었나.** 학교가 발급한 계정이 학교 쿠키 없이 `/v3/start` 를 치면
학교 맥락만 버리고 **개인 응시(BASIC · 기계공학)가 그대로 열렸다**
(`shots/pairs/1-school-v3start-d.png` 왼쪽: 경영학과 학생에게 `기계공학 진로 진단 ·
BASIC` 시작 화면). 그 응시는 담당자 집계에 잡히지 않고, 등급과 전공이 학교 계약이
정한 것이 아니며, `학교 응시는 한 번` 정책도 그 길로 샜다. 학교 쿠키를 고쳐 넣어도
같았다(`campus:walk` 가 그것을 `맥락을 적지 못한다 = 통과` 로 세고 있었다).

**고친 것.** 판정 한 자리 `src/lib/campus/start-gate.ts` 의 `startGate()` 를 시작
화면(`/v3/start` page)과 서버 액션(`startV3`)이 함께 읽는다.

| 경우 | 결과 |
|---|---|
| 학교 쿠키 + 그 학교의 등록된 학생 | 학교 응시. **학교 이용권만** 쓴다(담당자 재응시) |
| 등록된 학교 학생 · 개인 이용권 있음 | 개인 응시. **개인 이용권만** 쓴다 |
| 등록된 학교 학생 · 개인 이용권 없음 | **응시를 열지 않고** `/campus/{학교}/start` 로 |
| 학교 학생이 아님 | 전과 같다(이용권 없으면 무료 등급) |

재응시 권한도 그 길의 이용권만 센다: 학교 응시를 끝낸 학생이 산 개인 이용권으로
학교 응시를 하나 더 여는 길이 없다.

**같은 자리에서 찾은 둘째 P0.** 담당자 화면의 `재응시 열어 주기`(`allowRetake`)가
`CM_V3_CAMPUS_PRO` 이용권을 적는데 **그 상품 줄이 DB 어디에도 없어** 외래키가 매번
거절했다. 단추는 서 있고 누르면 아무것도 열리지 않았다. `db/schema_campus_students.sql`
끝에 꺼 둔(`active=false` · 0원) 상품 한 줄을 멱등으로 더했다. **Staging/운영에는
`npm run db:upgrade` 한 번이 필요하다**(그 전까지 담당자 재응시는 실패한다).

**검증(실제 브라우저 + 실제 DB, `scripts/lab/rb-start-gate.ts`) · 34 / 34**
(`checks/start-gate.md`):

- 직접 URL: 학교 학생 `/v3/start` · `/v3/start?core=…` → `/campus/pcu/start`, 응시 0
- 서버 액션: 개인 회원 브라우저의 폼에서 세션만 학교 학생 것으로 갈아 끼우고 제출 →
  응시 0, 서버가 학교 경로로 돌려보냄(시작 전 · 결과 받은 뒤 두 번)
- 고친 학교 쿠키 넷(`campus:walk`) → 응시 0, 학교 시작 쪽으로
- 학교 경로 시작 → PRO · PCU · PCU26_BIZ 응시
- 개인 이용권을 든 학교 학생 → 개인 응시, 개인 이용권 소비, 학교 칸 NULL
- 개인 회원 → BASIC 무료 응시(전과 같다)
- 담당자 재응시 → 학교 이용권으로 학교 응시가 열린다(`allowRetake` 직접 호출도 ok)
