사람이 최신 렌더를 읽고 짚은 **마지막 세 자리**만 고쳤습니다. 전면
재설계를 하지 않았고, MATCH 로 판정된 화면은 한 줄도 건드리지
않았습니다.

측정은 `ME_V3_MEASUREMENT_FREEZE_1` 에 그대로 머뭅니다. 문항 은행 ·
채점 · 소유 판정 · 묶음 규칙 · ResultModel · 현재 상태 계산 · 제품 루프 ·

**목표 UI 이미지는 이번에도 첨부되지 않았습니다.** `/mnt/user-data/uploads`

## A. Assessment Desktop

### 무엇이 문제였는가

앞 회차가 격자의 상자와 칸 사이 선을 걷어 표 계산기로 읽히던 모양을
지웠습니다. 그러고 나니 반대쪽으로 넘어가서, **1~5 가 흰 자리에 놓인
숫자**로 보였습니다. 고르기 전까지 누를 수 있는 자리라는 신호가 화면에
한 가지도 없었습니다.

### 무엇을 바꿨는가

다섯 칸을 **하나의 segmented control** 로 세웠습니다.

| 자리 | 전 | 후 |
|---|---|---|
| 테 | 없음 | 덩이에 한 겹(`.qs-grade`) |
| 바탕 | 줄과 같음 | 흰 면으로 떠 있음 |
| 칸 사이 | 없음 | 위아래가 뜬 1px 눈금 |
| 칸마다 테 | 없음 | 없음(그대로) |
| hover | 옅은 면 | 옅은 면 + 테 한 겹 |
| 고른 칸 | 면 + 테 | 면 + 테 + 굵은 번호 |

눈금이 하는 일은 **척도의 금**입니다. 칸을 담는 상자로 읽히지 않게
위아래를 띄웠고, 그래서
상자로 닫히지 않으므로, 열두 줄 × 다섯 칸에 선이 예순 개 그어지던 V10
이전의 모양으로 돌아가지 않습니다. 고른 칸 양옆의 눈금은 숨깁니다:
고른 면의 모서리와 겹쳐 서면 그 한 칸만 두 겹으로 둘린 것처럼 보입니다.

### 지킨 것

- 압축된 줄 구조 그대로입니다. 카드형 설문으로 되돌리지 않았습니다
- 누르는 자리 46px(한도 44px)
- 척도의 뜻은 격자 머리에서 한 번만 적습니다(`1 전혀 관심 없음` …
  `5 매우 관심 있음`). 칸에는 번호만 섭니다
- `모르겠다` 는 척도 밖의 별도 action 입니다. 값이 비어 있다는
  뜻이므로 다섯 칸과 같은 무게로 세우지 않습니다. 관심이 낮다는
  뜻으로 읽히면 그 자리가 여섯째 칸이 됩니다
- 문항 은행과 저장되는 값과 `band()` 는 한 글자도 바뀌지 않았습니다.
  `ASSESSMENT_COPY_VERSION` 도 그대로입니다

### Domain 기본 노출

영역 한 자리에서 기본으로 보이는 것은 규격 §3 그대로입니다.

```
영역명 + 상태 딱지
현재 상태 한 줄
직접 판단한 것 ≤ 3
남긴 결과 ≤ 3
아직 확인이 부족한 부분 1
다음에 정리할 것 1
[상세 근거 보기]
```

여덟 축과 고르신 항목 전부와 확인된 판단의 수는 `상세 근거 보기` 안에
있습니다.

### 지원서 문장

긴 문단을 기본 화면의 큰 박스로 두지 않습니다. 기본으로 서는 것은
**이은 문장의 첫 줄**이고, 열 단계와 전체 문단은 `작성 근거 자세히
보기` 안입니다. **새 AI 생성 기능을 더하지 않았습니다**: 고르신 답을
이은 기존 결과를 그대로 자른 것이고, 자른 자리는 바로 아래에서 펴
봅니다.

### 정보를 지우지 않았다

접은 자리는 전부 눌러서 펴집니다. 종이에서는 인쇄 규칙이 단추를 지우고
속을 드러내므로 **PDF 는 전체를 그대로 들고 있습니다.**

그 과정에서 종이 쪽에 있던 탈 하나를 같이 고쳤습니다.
`.rs-disc > div { break-inside: avoid }` 가 모든 펼침에 걸려 있었는데,
본문의 긴 절을 펼침 안으로 옮기자 **한 쪽에 안 들어가는 상자가 통째로
밀려** 그 앞 쪽이 비어 뽑혔습니다. 붙여 두는 것을 각주로 좁혔습니다.

| 등급 | 고치기 전 | 지금 | 규격 |

고치기 전의 STANDARD 10쪽과 PRO 13쪽은 **이번 작업 전부터 규격을 넘고

## D. Result Continuation

### 무엇이 문제였는가

결과지 마지막의 `이 다음에` 가 같은 무게의 카드 여섯을 격자로 세우고
있었습니다. 다 읽은 사람이 **어디를 먼저 누를지 고르는 일**을 한 번 더
하게 되고, 그 자리는 결과지의 마지막 인상이라 메뉴판이 서면 이 제품이
결과를 나눠 주는 곳으로 읽힙니다.

### 무엇을 바꿨는가

```
이 결과는 그날의 기록으로 굳어 있습니다. 여기서부터는 경험을 더하면서
현재 상태를 이어서 보실 수 있습니다.

      [ 내 CareerMatri에서 계속하기 ]      ← 짙은 단추 하나

현재 상태   경험 추가   다음 할 일   산업·직무   PDF 저장   ← 글줄

CareerMatri Track 은 준비 중입니다.                        ← 한 줄
```

- 테를 두른 카드가 **1개**입니다(주된 단추 자신). 넷 이상이면 걸립니다
- 거드는 길은 밑줄 글줄입니다. 테를 두르면 그 순간 주된 길과 같은
  무게가 됩니다
- Track 은 한 줄로 적습니다. 테를 두르면 있는 기능처럼 보입니다

### CTA hierarchy (§8)

한 창에 짙은 단추가 하나를 넘지 않습니다. 쪽 전체에서 세지 않고 창을
반 칸씩 내리며 **그 창 안에서** 셉니다: 쪽 전체로 세면 위아래로 멀리
떨어진 둘이 걸리는데, 그 둘은 같은 순간에 보이지 않아 고르는 일을
만들지 않습니다.

- 접힌 기본 상태: `지금 할 일로 담기` 하나
- 펼친 끝: `내 CareerMatri에서 계속하기` 하나
- 데스크톱 1440 과 손전화 390 둘 다 최대 1

### CAREERMATRI_CORE_UI_FREEZE_1 (추가 LOCK B)

Core 화면 여덟(Home · Assessment · Experience · Current State ·
Next Action · Result Summary · Result Detail · Explore)을 한 묶음으로
얼었습니다. `sites/pca-platform/assessment/ME_V3/core-ui-lock.json` 과
`npm run v3:freeze:core` 입니다.

**측정 동결과 별개입니다.** 저쪽이 얼린 것은 응답을 받는 방식과 판단으로
바꾸는 방식이고, 여기가 얼린 것은 그 판단을 사람이 어떤 화면으로 읽고
어떤 차례로 누르는가입니다. 한 묶음으로 두면 홈의 카드 하나를 옮긴 날
측정 동결이 깨지고, 그러면 사람이 `UI 때문이니 다시 적자` 로 넘깁니다.

**판정을 두 곳에서 하지 않습니다.** 파일이 바뀌었는지는 이미 세 동결이
셉니다(`v3:freeze` · `v3:result:freeze` · `v3:workspace`). 묶음이 세는
것은 셋입니다.
