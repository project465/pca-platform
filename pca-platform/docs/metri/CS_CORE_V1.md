# 컴퓨터·소프트웨어 Core 를 콘텐츠만으로 더했다 (CS_CORE_V1 · 2026-10-13)

이번 회차의 1순위 목표는 **공통 엔진을 수정하지 않고 새 Major Core 를 더하는
것**이었다. 그래서 묻는 것이 `CS 검사가 도는가` 하나가 아니다. **CareerMatri
Major Core 생산 파이프라인이 실제로 반복 가능한가**가 같은 무게로 걸려 있다.

판정은 이렇다. 공통 채점 엔진과 결과 엔진의 **판정 로직 변경이 0** 이고,
Workspace UI 와 DB 스키마 변경이 0 이며, 기계공학과 전기전자의 결과지 한국어가
**글자까지 같다**(사람 열두 벌 × 등급 셋 × Core 둘 · 522줄 대조). 파이프라인
쪽 보고는 `docs/metri/MAJOR_CORE_PIPELINE.md` 다.

**학생에게 열지 않았다**(`open_to_students: false`). 자료와 자동 검사는 끝났고
남은 것은 그 전공 전문가가 읽는 일이다. 검토 묶음이
`docs/metri/CS_CORE_V1_REVIEW.md` 이고 그 판정이 돌아오기 전에는 그 칸을
올리지 않는다.

## 1. 측정 영역과 역량 구조

**자는 기계공학과 같다.** 판단축 여덟(J1~J8), 척도 둘(선별 S4 · 전체 S8),
소유 네 단계(L0~L3), 노출 세 마디, 결과 절 A~J 가 그대로다. 전공마다 자를 새로
만들면 같은 학교 안에서 두 전공의 결과를 견줄 수 없다.

갈리는 것은 **영역과 그 영역이 내놓는 산출물**이다.

| 코드 | 영역 | 빠지면 안 되는 축 |
|---|---|---|
| TD01 | 소프트웨어 설계·구조 | J2 요구사항 해석 · J3 직접 기술 판단 |
| TD02 | 자료구조·알고리즘 | J3 · J6 비교·검증 |
| TD03 | 서버·API 구현 | J3 · J5 산출물 |
| TD04 | 데이터 저장·질의 설계 | J3 · J6 |
| TD05 | 사용자 인터페이스 구현 | J3 · J5 |
| TD06 | 시스템·동시성 프로그래밍 | J3 · J7 실패·수정 |
| TD07 | 네트워크·분산 시스템 | J3 · J7 |
| TD08 | 정보보안 | J2 · J6 |
| TD09 | 기계학습·데이터 분석 | J4 방법·도구 · J6 |
| TD10 | 테스트·품질·배포 운영 | J6 · J7 |
| TD11 | 실시간 그래픽스·게임 구현 | J3 · J6 |

**열둘에 맞추려고 하나를 더 만들지 않았다.** 기계공학이 열둘이고 전기전자가
열둘인 것은 그 전공의 일이 그렇게 갈려서다. 컴퓨터·소프트웨어에서 열한 번째
다음에 둘 만한 자리를 찾아보면 `개발 환경과 도구` 와 `협업과 코드 리뷰` 가
나오는데, 둘 다 열한 영역 전부에 걸쳐 있는 **일하는 방식**이다. 영역으로 두면
같은 자리를 두 번 센다. 들어간 자리는 축 둘(J4 · J7)과 역할팩이다.

**필수 축을 영역마다 다르게 적었다.** 정보보안에서 직접 기술 판단보다 먼저
보는 것이 요구 해석(무엇을 지키고 누구에게 허용하는가)이고, 기계학습에서는
방법 선택이 그 자리다. 개수만으로 판정하지 않는 까닭이 여기다: 확인된 축이
여섯이어도 그 영역의 필수 축이 비면 근거가 서지 않는다.

역할기능 여덟(RF1 설계·개발 · RF2 해석·예측 · RF3 시험·검증 · RF4 빌드·배포
자동화 · RF5 서비스 운영 · RF6 통합·조정 · RF7 탐색·연구 · RF8 품질·신뢰성)은
**코드와 이름을 기계공학과 같게 두고 RF4·RF5 의 이름만** 이 전공의 말로 적었다.
조직환경 일곱은 자사 서비스 기업부터 스타트업·소규모 팀까지다.

## 4. 산업·역할 Pack 연결

산업 일곱: 플랫폼·온라인 서비스 · 금융·결제 · 게임·실시간 콘텐츠 ·
기업용 소프트웨어·수탁 개발 · 자동차·모빌리티 소프트웨어 · 의료·보건 정보 ·
공공·국방 정보화.

**여덟에 맞추지 않았다.** 받은 분류를 그대로 쪼개면 `플랫폼` 과 `커머스` 가
같은 판단을 묻게 되고, 그러면 고른 산업이 결과를 바꾸지 않는 칸이 하나 생긴다.

역할 여덟은 역할기능과 하나씩 맞물린다(설계·개발 → RF1 … 품질·신뢰성 → RF8).
**역할팩은 Core 의 자리를 가리키고 새 축을 만들지 않는다**: `core_ref` 가 영역
셋과 역할기능 하나를 가리키고, 더 묻는 것은 그 자리에서 가진 권한과 범위다.

관계표는 두 벌이다(영역×산업 77 · 영역×역할 88). 세 축을 곱한 표를 손으로
들고 있을 수 없어서다.

**산업팩 문항 전부에 쉬운 말 풀이(`gloss`)가 붙어 있다.** 금융의 멱등 처리를
모르는 학부생도 `같은 요청이 두 번 들어와도 결과가 한 번만 적히게 다룬 경험`
이면 같은 판단이다. 용어를 모른다고 부적합으로 적지 않는다.

## 5. Evidence · Gap · Career Action 예시

사람 열두 벌로 실제 엔진을 돌린 결과다. 전체 예시는 검토 묶음 6절에 있다.

- **근거가 선 영역**: 자료구조·알고리즘에서 입력 크기와 응답 시간을 받아
  자료 표현을 직접 정하고, 복잡도 근거 메모와 성능 측정 기록을 남기고,
  이론값과 실측을 견주었다. 확인된 축 여덟 · 소유 둘.
- **아직 덜 선 영역**: 테스트·품질·배포 운영에서 판단은 확인됐고 남은 것이
  없다(`MISSING_OUTPUT`). 다음 걸음은 시험 묶음과 통과 기준표를 한 벌 남기는
  일이다.
- **판단할 근거가 부족한 영역**: 관심은 높고 겪은 적이 없다. 다음 걸음은
  공부가 아니고 짧게 한 번 해 보는 것이다(`TRY_SHORT_EXPERIENCE`).

**적는 차례는 이 전공의 업무 흐름에서 뽑았다**(`result/chains.ts`). 서버·API
구현이면 `요청 종류와 호출 빈도 → 주소 체계와 응답 꼴 → 거래 범위와 재시도
처리 → 응답 규약과 시험 묶음 → 응답 시간 약속 대조` 다. 영역 코드만으로 적어
두면 기계공학의 `공차와 체결 결정 → 도면` 이 이 전공 응시자에게 나간다.

이름이 서고, 종이가 200 으로 나오고, 390px 에서 가로로 밀리지 않고, **되돌린

## 8. 기존 시스템 회귀

- **기계공학과 전기전자의 결과지 한국어가 글자까지 같다.** 사람 열두 벌 ×
  등급 셋 × Core 둘로 머리글과 빈자리와 할 일을 그려 522줄을 대조했고 다른
  줄이 0이다.
- **기계공학 판정 지문을 다시 적지 않았다.** `v3:scoring` 이 ME 31 / 31 로
  통과한다(`GOLDEN=update` 를 돌리지 않았다).
- **전기전자 콘텐츠 파일이 한 줄도 바뀌지 않았다.** 생성기를 다시 돌려
  `ee-*.json` 전부가 글자까지 같다.
- **동결 다섯이 기록을 다시 적지 않은 채로 통과한다**: 검사 화면 17벌 ·
  결과지 10벌 · 작업공간 44벌 · Core 화면 묶음 6가지 · 측정 동결 14가지.
- **DB 스키마를 한 줄도 바꾸지 않았다.** 마이그레이션이 필요 없다.

바뀐 fixture 둘을 적어 둔다. 기계공학 fixture 의 `cases.reading` 블록이
늘었고(읽는 규칙이 가리키는 자리를 자료로 옮긴 것이며 채점은 이 칸을 읽지
않는다), 전기전자 fixture 의 P03 에 **관심도 낮고 근거도 얕은 셋째 영역**이
늘었다. 뒤엣것은 전기전자 판정 지문 한 줄을 다시 적게 했고, 그 벌의 결과지
한국어는 그대로다.

## 9. 남은 오류와 고치지 않은 까닭

### ① 읽는 규칙 검사가 남의 Core 자료로 돌고 있었다 (닫았다)

`scripts/v3-persona-check.ts` 가 사람 열두 벌의 경로를
`assessment/ME_V3/personas.json` 으로 **글자로** 들고 있었다. 그래서
`CORE=EE_CORE_V1` 과 `CORE=CS_CORE_V1` 로 돌린 결과가 **기계공학 열두 벌을 그
Core 의 은행에 얹어 읽은 것**이었고, 그 상태로는 통과도 걸림도 그 Core 에
대한 답이 아니다. 전기전자가 `15 / 15` 로 적혀 있던 것이 그래서 틀린 값이고,
자기 fixture 로 돌리면 `8 / 15` 였다.

경로를 등록부(`fixtures.personas`)에서 읽게 하고, **어느 벌의 어느 영역이 어느
상태를 맡는지**도 fixture 의 `cases.reading` 으로 옮겼다. 벌 번호와 영역 코드는
Core 안에서만 뜻이 있어서다. 돌아오지 못하게 `v3:extend` 의 `core 를 모르게 짠
파일` 목록에 그 파일을 더하고 **한 Core 의 fixture 폴더를 글자로 적은 자리**를
세는 그림을 하나 더 두었다. 되돌려 걸리는 것까지 확인했다.

같은 자리에서 전기전자 fixture 의 빈 칸 하나가 드러났다. 관심과 근거의 네 칸
가운데 `관심도 낮고 근거도 얕은` 칸이 어느 벌에도 없어서, 결과지의 그 칸을 한
번도 그려 보지 않은 상태였다. P03 에 셋째 영역을 세워 메웠다.

### ② 열어 둔 Core 만 보는 검사 둘 (적어 두고 밟아서 메웠다)

`v3:runtime` 과 `v3:ui` 와 `v3:length` 가 볼 Core 를
`sellableCores("KR")[0]` 으로 골랐다. 짓고 있는 Core 는 `open_to_students:
false` 라 그 목록에 들지 않으므로, `CORE` 를 넘겨도 **기계공학을 재고 그 수를
그 Core 의 수로 읽는다.** 자료만 보는 둘(`v3:ui` · `v3:length`)은 `CORE` 를
따르게 고쳤고, 고치자마자 `v3:ui` 가 이 Core 에서 걸렸다: 세는 줄이 **산업
여덟**을 글자로 요구하고 있어서 산업이 일곱인 Core 의 콘텐츠가 모자란 것으로
읽혔다. 수를 팩 파일에서 읽게 바꿨고 세 Core 전부 28 / 28 이다.

`v3:runtime` 은 고치지 않았다. 응시를 여는 길이 `openAttempt` 하나이고 그
함수가 닫힌 Core 를 거절하는 것이 **설계**다(주소로 등급을 올리는 길을 막는
것과 같은 까닭이다). 그 자리의 증거는 `cs:walk` 가 개방 칸을 잠시 열고 밟은
뒤 되돌리는 것으로 대신한다.

### ③ 결과지 작성 차례가 콘텐츠 밖에 있다

`result/chains.ts` 는 Core 를 열쇠로 둔 **자료 표**이고 판정에 들어가지
않는다. 다만 그 표가 TypeScript 파일이라, Core 를 하나 더 만드는 일이
`content/` 밖에 한 벌을 적는 일을 남긴다. 이번 회차에서 공통 층에 손을 댄
자리가 여기 하나다.

고칠 방향은 그 표를 `*-domains.json` 의 영역마다 한 줄로 옮기고 `chainFor` 가
그 줄을 읽게 하는 것이다. 그러면 다음 Core 는 `content/` 안에서 끝난다. **이번
회차에 하지 않은 까닭**은 결과 층을 읽는 자리를 바꾸는 일이고, 기계공학과
전기전자의 차례를 콘텐츠로 옮기면서 글자가 한 자라도 달라지면 이미 응시한
사람의 결과지가 바뀌기 때문이다. 승인받고 따로 한다.

### ④ 이용권이 Core 를 가리키지 않는다

`v3Grants` 가 거르는 칸은 엔진의 전역 판본이고 상품표의 `product_code` 는
기계공학 쪽 줄이다. 그래서 이 Core 의 응시도 그 줄로 열린다. 고치는 일은
이용권과 상품 구조를 건드리므로 범위 밖이고, 전기전자 보고의 같은 항목과
한 자리다. **파는 줄을 새로 만들지 않았다**: 쓰는 상품은 꺼져 있다.

### ⑤ `recompute.ts:377`

`autoRecompute()` 의 `catch` 안에서 줄을 닫는 `finish()` 가 조용히 넘어간다.
닫기가 실패하면 그 줄이 `running` 으로 남는데, 5분 지난 줄을 다시 집으므로
저절로 풀리고 굳은 결과와 채점에 닿지 않는다. 재분석 동작을 건드리는 일이라
승인받고 한다.

### ⑥ `v3:migrate` 가 이 Core 에 돌지 않는다

그 검사가 세는 것은 ME_V3 에서 ME_V3_2 로 옮긴 길이다. 이 Core 에는 옮겨 올 옛
은행이 없어서 셀 것이 없다.

## 10. 개방 가능 여부

**아직 열지 않는다.** 등록부가 `open_to_students: false` 이고 내부 성숙도가
`READY_FOR_DOMAIN_REVIEW` 다. 그 글자는 운영 화면에만 서고 손님 화면에 0건인
것을 `v3:majors` 가 센다.

### 아직 하지 않은 검증

- 컴퓨터·소프트웨어 전공자와 현직자의 검토가 돌아오지 않았다. 문항 344개가
  현장 말인지는 기계가 세지 못한다.
- 인지 면접을 돌리지 않았다. 보기 둘(`조건은 주어짐`)과 셋(`내가 수행`)을
  응시자가 실제로 가르는지는 거기서만 답이 나온다.
- 실제 응답으로 신뢰도와 타당도를 재지 않았다. 그래서 어느 자리에서도
  `검증된 검사` 로 적지 않고, 규준도 백분위도 적합도 비율도 내지 않는다.
- 산업팩 일곱의 용어는 그 산업 경력자가 읽어 주셔야 한다.

### 운영

운영 배포본을 밖에서 열지 못했다(네트워크 정책이 막는다). 위의 결과는 전부
이 기계에서 운영과 같은 배치로 띄워 돌린 것이다. DB 스키마를 바꾸지 않았으므로
마이그레이션은 필요 없고, 바뀐 것이 전부 이미지 안으로 들어가는 파일이라
재배포가 먼저다.
