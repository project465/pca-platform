# CareerMatri 플랫폼 전수 감사

> 사업주 지시는 이 글을 `67_platform_audit.md` 로 적으라고 했는데, 67 과 68 은
> 바로 앞 회차가 이미 쓰고 있다(`67_arch_debt.md` · `68_owner_verification.md`).
> 번호만 69 로 밀고 내용은 지시 그대로다. 짝은 `70_workspace_ia.md`.

조사한 것은 `src/app` 의 실제 파일이다. 추측하지 않았고, 화면마다 무엇을
읽는지(어느 표를 보는지)까지 열어 봤다.

---

## 0. 한 줄 진단

**개인 사용자용 작업공간이 두 벌 서 있고, 로그인은 옛 쪽으로 떨어진다.**

```
/my   ← 로그인한 학생이 떨어지는 자리.  껍데기 sf-  ·  옛 표(attempts · v2_responses · report_snapshots)
/me   ← CareerMatri V3 작업공간.        껍데기 cm-  ·  V3 표(v3_attempts · v3_snapshots · career_profiles)
```

둘은 메뉴도 껍데기도 읽는 표도 다르다. 그래서 **V3 를 끝낸 사람이
로그인하면 `아직 응시한 검사가 없습니다` 를 읽고 옛 검사로 보내진다.**
`/me` 로 가는 길은 결과지 맨 아래와 `/cores` 안의 단추뿐이다.

나머지 문제는 거의 전부 이 하나에서 갈라져 나온다.

## 1. 사용자용 route 전수

로그인 전(공개) · 로그인 후 개인 · 기관 · 운영 넷으로 나눴다.
`유지/통합/redirect/삭제후보` 는 §33 의 네 갈래(KEEP, MERGE, REDIRECT,
DEPRECATE)로 적는다.

|---|---|---|---|---|---|

### 1-5. 기관·운영

`/org/*` 아홉 쪽과 `/admin/*` 스물넷은 **이번 범위가 아니다**(§31).
한 가지만 적어 둔다: `/admin/v3-pilot` 이 V3 파일럿의 유일한 운영 화면이고
초대와 등급이 거기서 나온다.

## 2. 문제를 P0~P4 로

### P0 · 기능 · 데이터 · 권한 오류

| # | 무엇 | 어디 | 왜 P0 인가 |
|---|---|---|---|
| P0-1 | 로그인한 학생이 **옛 작업공간**으로 떨어진다 | `roles.ts` `homePathFor('student') → /my` | V3 를 끝낸 사람이 `아직 응시한 검사가 없습니다` 를 읽는다. 자기 결과가 사라진 것으로 보인다 |
| P0-2 | 그 화면의 주된 단추가 **옛 검사**로 간다 | `/my` → `/test`(좌석 있으면) · `/pricing`(없으면) | 지금 파는 제품이 아닌 쪽이 첫 걸음이 된다 |
| P0-3 | `/my/results` 가 V3 결과를 못 읽는다 | `report_snapshots` 만 본다 | 결과 목록을 열면 비어 있다. **데이터는 있고 화면이 못 본다** |

세 줄 다 데이터가 깨진 것은 아니고 **보는 자리가 틀린 것**이다. 그래서
고치는 일이 표를 건드리지 않는다.

### P1 · 사용 흐름

| # | 무엇 |
|---|---|
| P1-1 | 작업공간이 두 벌이고 사이드바도 두 벌이다(`CM_NAV` · `NAV_INDIVIDUAL`) |
| P1-2 | `/me` 사이드바의 `설정` 이 `/my/account` 로 가면서 껍데기가 바뀐다 |
| P1-3 | 결과지에서 작업공간으로 돌아가는 길이 **맨 아래에만** 있다 |
| P1-4 | `/me` 가 모든 사용자에게 같은 아홉 칸이다. 검사 전·진행 중·완료가 갈리지 않는다 |
| P1-5 | V3 결과 목록 화면이 없다. 두 번 응시한 사람의 앞 결과는 `/me` 카드 한 줄로만 닿는다 |
| P1-6 | `/me/gap` 이 현재 상태와 할 일을 한 쪽에 담아 둘의 성격이 섞인다 |
| P1-7 | `/pricing` 의 로그인 상태 CTA 가 `/my` 다 |
| P1-8 | `/cores` 가 로그인 벽이라 처음 온 사람은 전공 목록을 못 본다 |

### P2 · 제품 의미가 잘못 전달됨

| # | 무엇 |
|---|---|
| P2-1 | `재분석` 이 사용자 화면에 열 자리 넘게 있다. 기술 용어다 |
| P2-2 | `/sample` 이 **ME_V2 결과지**인데 그 사실이 적혀 있지 않다 |
| P2-3 | `/me/jobs` 가 사이드바에 있고 자료가 0줄이다. 점 하나로만 구별된다 |
| P2-4 | `/my/evidence` 의 `검사에서 확인된 경험 신호` 와 V3 의 `설명할 수 있는 경험` 이 같은 말로 읽힌다 |
| P2-5 | `/me/experience/new` 가 **왜 적는지**를 맨 위에 적지 않는다 |
| P2-6 | 등급 이름이 `BASIC` · `STANDARD` · `PRO` 로 화면에 그대로 나간다. 무엇이 다른지는 다른 쪽에 있다 |

**P2 에 없는 것도 적어 둔다.** 아래 셋은 **이미 지켜지고 있다**.

- 지역을 추천처럼 적은 자리 0 (`추천 지역` · `취업 가능성이 높은` 네 가지 전수 0회)
- 재분석을 점수 상승처럼 적은 자리 0 (`직접 수행` 까지만 올라간다고 적혀 있다)
- 근거 없는 주장 0 (`npm run claims:check` 가 공개 원고 85벌에서 0)

## 3. 옛 V1 / V2 / PCA 흔적

**사용자 화면에 남아 있는 것**

| 흔적 | 어디 | 처분 |
|---|---|---|
| ME_V1 응시 입구 | `/my` → `/test` | 링크 제거 |
| ME_V2 응시 입구 | `/my` V2Panel → `/assessment/start` | 이미 응시한 사람의 이어하기만 남긴다 |
| 옛 결과 목록 | `/my/results` | `옛 검사 결과` 로 표기하고 계정 영역으로 |
| 옛 경험 신호 | `/my/evidence` | 같음 |
| 옛 견본 결과지 | `/sample` | ME_V2 임을 적는다 |
| `적합도`, `1군`, `FIT` | 공개 화면 **0회** | 이미 없다 |

**지우지 않는 것.** `/report/[id]` 와 `/assessment/[id]/report` 와 `/pca/*`,
그리고 그 뒤의 표 다섯(`attempts`, `responses`, `v2_responses`,
`report_snapshots`, `evidence_profiles`)은 **이미 응시한 사람의 결과를 다시
열 수 있어야** 하므로 한 줄도 건드리지 않는다(설계 원칙 4).

## 6. 디자인 문제

**이미 잘 된 것(기준으로 삼을 것).** 결과지와 검사 화면이다. 흰 바탕,
얇은 선, 작은 둥글기, 또렷한 제목 위계, 짧은 상태 문장, 강조색을 한
자리에만. 토큰은 이미 한 벌이다(`surface.css` 의 `:root` 하나를
`.qs` 와 `.rs` 와 `.cm` 이 함께 읽는다). **토큰을 다시 만들 일이 없다.**

**고칠 것.**

| 무엇 | 지금 | 바꿀 방향 |
|---|---|---|
| 껍데기 | 둘(`sf-` 위 띠 · `cm-` 왼쪽 띠) | 작업공간은 `cm-` 하나 |
| 사이드바 | 평평한 아홉 줄 | 묶음 넷 + 하단 계정 |
| 전공 맥락 | 없다 | 사이드바 머리에 `기계공학` |
| 손전화 | 아래 띠 다섯 칸, 나머지 못 닿음 | 네 칸 + `메뉴` 서랍 |
| `/me` 카드 | 아홉 칸이 같은 무게 | 상태별로 셋에서 여섯 |
| 숫자 | `확인된 축 5개` 류가 카드 머리에 | 문장 먼저, 수는 보조로 |

**금지한 것을 지금 어기고 있는가.** 과한 gradient, 네온, glassmorphism,
거대한 hero, 의미 없는 일러스트, chip 스무 개, progress bar 로 모든 것
표현. **전부 0회다.** 숫자 카드(`cm-num`)가 `/me` 에 넷 있어 그것만 줄인다.

## 7. 목표 IA

`70_workspace_ia.md` 에 적었다. 요지만 셋.

1. **`/me` 가 본체다.** 로그인한 개인은 여기로 떨어진다.
2. **`/my` 는 계정이다.** 비밀번호 · 주문 · 이용권 · 파기 · 옛 검사 기록.
3. **검사 당시 결과와 지금 상태를 화면에서 가른다.** 표가 다르고
   (`v3_snapshots` · `career_profiles`) 카드 모양도 다르게 둔다.

## 8. route 이사 계획

| Route | 처분 | 어떻게 |
|---|---|---|
| `/` (학생) | MERGE | `homePathFor('student')` 를 `/me` 로 |
| `/my` | MERGE | 계정 영역 홈으로 다시 쓰고, 작업공간 링크를 맨 위에 |
| `/my/results` | KEEP + 안내 | 제목을 `옛 검사 결과` 로. V3 결과가 있으면 `/me/results` 로 가는 줄을 맨 위에 |
| `/my/assessments` · `/my/evidence` | KEEP + 안내 | 같음 |
| `/my/applications` | DEPRECATE | 쪽은 남기고 메뉴에서 뺀다(이미 꺼져 있다) |
| `/me/gap` | REDIRECT | `/me/state` 로 308. Gap 은 상태, 할 일은 `/me/next` |
| `/test` 링크 | DEPRECATE | `/my` 에서 그 단추를 없앤다. 쪽과 표는 그대로 |
| `/me/results` `/me/state` `/me/next` | 신설 | — |
| 그 밖 전부 | KEEP | 주소가 바뀌지 않는다 |

**404 로 버리는 route 는 없다.** 북마크와 메일과 운영 문서에 적혀 나간
주소(결과 링크, PDF 링크, `/my/results`, 이어하기 주소, 파일럿 링크)가
전부 그대로 열린다.
