## A. 실제 화면에서 다시 드러난 문제

과거 보고서를 믿지 않고 **찍힌 그림을 다시 읽었다.** 지난 회차에
`고쳤다` 고 적힌 자리 가운데 넷이 실제로는 고쳐지지 않았다.

## B. 고친 정보구조

### B-1. 홈 (`/me`)

세로 차례가 곧 중요도다(규격 §12).

```
머리  내 커리어 · 기계공학 · 마지막 분석 날짜 · 한 줄
      [지금 할 일]  경험 추가              ← 짙은 단추는 하나다
1     현재 상태     영역 셋 + 먼저 채워볼 부분 · [전체 기술영역 보기]
2     지금 할 일    Action 한 문장 · [지금 할 일 보기]
3     최근 변화     달라진 점 / 아직 반영하지 않은 경험    ← 있을 때만 선다
4     기록          검사 당시 결과 · 최근 경험 · 지원 기록 · 관심 산업과 직무
```

**주된 단추가 늘 `지금 할 일` 이다.** 상태마다 다른 단추를 세우면 그
자리의 뜻이 매번 달라지고, 결과를 받은 사람에게 다음 걸음은 하나뿐이다.

### B-2. 띠 (규격 §13)

```
지금      홈 · 검사 · 다음 할 일
내 커리어  현재 상태 · 경험 · 결과 기록
탐색      산업·직무 · 지역·기관 · 지원 기록
기타      Track · 계정
손전화    홈 · 검사 · 경험 · 더보기
```

`다음 할 일` 이 `지금` 으로 올라온 까닭은 그 줄이 **오늘 누를 자리**여서다.
쌓인 기록은 아래 묶음이 들고 간다. `내 커리어` 의 차례는 읽는 차례다:
지금 상태 → 그 상태를 바꾸는 경험 → 굳어 있는 기록.

## F. 경험 추가와 반영

```
/me/experience/new
  새 경험 하나 추가
  대부분 고르는 칸입니다. 적는 칸은 제목 한 줄이면 됩니다.
  ＋ 이걸 적으면 무엇이 달라지나요            ← 접힘
  어떤 경험인가요 · 무엇을 했는지 한 줄로 · 언제
  어느 기술영역의 일인가요 · 이 경험에서 무엇을 하셨나요
  ＋ 더 적을 것이 있으면 (선택)               ← 쓰인 자리 · 끝난 달 · 한 줄
  [저장]
  저장하면 무엇이 달라지는지 먼저 보여 드리고, 거기서 반영을 누르면
  현재 상태에 들어갑니다. 검사 당시 결과는 그대로 남습니다.
      ↓
/me/recompute   올라가는 판단 · 달라지는 묶음 · 메워지는 자리 + 표
      ↓ [지금 값에 반영하기]
/me/state?r=1   새 경험을 반영했습니다. 판단 N개가 올라갔고 영역 M곳이
                달라졌습니다.      ← 바뀐 것이 없으면 그 사실을 적는다
                [지금 할 일]  경험 추가
```

**저장하는 순간 자동으로 반영하지 않는다.** 계산이 깨진 날 저장까지
막히지 않게 하려는 것이 하나이고, 무엇이 달라지는지 먼저 보고 누르게
하려는 것이 둘이다.

## K-2. 시각 규칙 (규격 §19)

색은 Primary 하나 · 중성 회색 한 벌 · Success 하나 · Warning 하나 ·
Error 하나다. 활자는 여섯 단(`--ui-t-page … --ui-t-cap`), 여백은 4의
배수 여덟(4·8·12·16·24·32·48·64), 글 폭은 셋(760·920·1040).

**둥글기는 셋을 그대로 둔다**(8 · 12 · 16). 규격이 적어 둔 보기는
6 · 10 · 14 인데, 재는 것은 `3단계 이하` 이고 지금이 정확히 셋이다.
2px 을 옮기면 토큰을 읽는 네 벌의 잠금을 전부 다시 적어야 하고,
**화면에서 달라지는 것이 없다.** 바꿀 값이 아니라 지킬 규칙이다.

한 화면에 짙은 단추 하나와 빈 카드 0 은 `v3:loop` 3번이 매번 센다.

## M. End-to-End 행동 루프

`npm run v3:loop` 열다섯 가지가 실제 브라우저로 돈다.

```
로그인 → /me(짙은 단추 하나) → 그 단추가 200 → 작업공간 13쪽 링크 20개 전부 200
      → 경험 추가(기술영역 12개 고를 수 있다) → 저장 → /me/recompute
      → [지금 값에 반영하기] → /me/state → `새 경험을 반영했습니다. 판단 N개…`
      → /me 홈이 최근 경험에 그 제목을 적는다
      → 쿠키를 버리면 /login → 다시 들어오면 그 경험이 그대로 있다
```

**`v3:gate` 와 다른 질문이다.** 저쪽이 묻는 것은 `쪽이 서는가` 이고
여기가 묻는 것은 **그 쪽에서 다음 쪽으로 갈 수 있는가**다. 열두 쪽이
전부 200 이면서 그 사이를 이을 길이 하나도 없을 수 있다.

만들면서 거짓 통과를 두 번 냈고 둘 다 고쳤다. `.cm-pick` 을 앞에서부터
여섯 개 누르면 전부 `어떤 경험인가요` 라디오라 기술영역이 하나도 안
골리고, 그러면 반영 계획이 늘 비어 **끊긴 루프를 이 검사가
통과시킨다.** 그리고 끝낸 응시를 베껴 올 때 결과 안에 적힌 응시 번호를
함께 옮기지 않아, 홈이 **남의 응시로 가는 링크**를 세우고 404 가 났다.

## Q. 운영 확인 (규격 §33)

**이 세션에서 운영 배포본을 한 번도 열지 못했다.** 네트워크 정책이
`app.careermatri.com:443` 을 막고(`CONNECT tunnel failed, response 403`)
Railway Shell 권한도 없다. 그래서 아래는 **사업주가 직접 눌러야 하는
절차**이고, 돌렸다고 적지 않는다.

### STEP 1. DB 가 지금 코드까지 올라와 있는가

- 어디: Railway → 서비스 → ⋯ → Shell
- 누를 것: `npm run db:verify`
- 정상이라면: `핵심 표 7 / 7 · ME_V3 표 5 / 5 · 내 CareerMatri 5 / 5`
- FAIL: 셋 가운데 하나라도 모자라면 → `npm run db:upgrade` 한 줄을 치고
  다시 `db:verify`. **`db:upgrade` 는 두 번 돌려도 안전하다**(모든 파일이
  `IF NOT EXISTS`·`ON CONFLICT` 이고 모든 psql 이 `--single-transaction`)
- Railway log: Deployments → 그 서비스 → Logs

### STEP 2. 배포본이 떠 있는가

- URL: `https://app.careermatri.com/api/health`
- 정상이라면: `200` · 본문에 DB 까지 물어본 결과
- FAIL: 200 이 아니면 Deployments 의 마지막 빌드 상태부터 본다

### STEP 3. 로그인하면 작업공간으로 가는가

- URL: `https://app.careermatri.com/login`
- 누를 것: 학생 계정으로 로그인
- 정상이라면: 주소가 `/me` 이고 왼쪽 띠에 `지금 / 내 커리어 / 탐색 / 기타`
  네 묶음이 선다. 짙은 단추는 **하나**(`지금 할 일` 또는 `기계공학 검사 시작`)
- FAIL: `/my` 로 떨어지거나 띠가 두 벌이면 배포본이 옛 코드다

### STEP 4. 검사가 끝까지 도는가

- 누를 것: `검사` → 기계공학 → 끝까지
- 정상이라면: 머리띠 오른쪽이 `BASIC · n / m` · 보기 넷이 넓은 화면에서
  한 행 · 영역 훑기 위에 다섯 단계의 말이 한 번 선다
- FAIL: 보기 넷이 세로로 쌓이거나 격자 머리가 없으면 CSS 가 안 올라갔다
- Railway log: `[v3]` 로 시작하는 줄

### STEP 5. 결과가 행동 화면으로 서는가

- URL: 완료 화면의 `결과 보기`
- 정상이라면: 첫 화면에 셋(지금 확인된 것 · 비어 있는 것 · 정리할 것)과
  `[지금 할 일로 담기]` 가 서고, 그 아래가 `자세한 내용 보기` 로 접혀 있다
- FAIL: 아홉 절이 전부 펼쳐져 있으면 옛 코드다

### STEP 6. 종이가 뽑히는가

- 누를 것: 결과 화면의 `결과 PDF 저장`
- 정상이라면: 몇 초 뒤 PDF 가 내려받아지고 **본문 아홉 절이 다 들어 있다**
- FAIL: `PDF를 만들지 못했습니다` 쪽이 뜨면 거기 적힌 대로 [다시 시도]
- Railway log: `[v3-pdf] attempt=… step=…` 한 줄이 까닭을 적는다.
  `step=browser` 면 chromium 경로, `step=cookie`/`auth` 면 쿠키,
  `step=render` 면 결과 쪽이다

### STEP 7. 행동 루프가 이어지는가

- 누를 것: `[지금 할 일로 담기]` → `경험 추가` → 제목 한 줄과 기술영역
  하나 → `저장` → `지금 값에 반영하기`
- 정상이라면: 저장 뒤에 **달라진 것을 먼저 보여 주고**, 반영을 누르면
  `현재 상태` 로 가서 `새 경험을 반영했습니다. 판단 N개가 올라갔고…` 가
  초록 줄로 선다. 홈의 `최근 경험` 에 그 제목이 선다
- FAIL: 저장 뒤 목록으로 가거나 초록 줄이 없으면 옛 코드다

### STEP 8. 손님 화면

- URL: `/` · `/pricing` · `/product`
- 정상이라면: `공개 전 시험 배포` 가 **한 글자도 없다.** 통신판매업
  신고번호가 비어 있는 동안 `/pricing` 과 `/product` 는 `아직 판매를
  열지 않았습니다` 로 선다(결제 UI 자체가 없다)
- FAIL: 결제 단추가 보이면 `publicCommerceGate` 가 열린 것이다

1. **운영 배포본을 밖에서 열어 보지 못했다.** 이 회차의 모든 판정은

   터치를 씌운 것까지다.
4. **여덟 벌 전부를 브라우저로 끝까지 누르지 않았다.** O 절.
5. 공고 자료와 지역 기관 수가 0줄이다. Track 구독 결제가 없다.
6. 영어판은 한 줄도 쓰지 않았다.
