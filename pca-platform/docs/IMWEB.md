# 아임웹(앞단)과 붙이기

2026-09-14 결정: **아임웹은 앞단, 이 코드는 서비스.**

- 아임웹 — 소개·영업·회사 정보. 디자인을 자주 고치고, 개발자 없이 운영한다
- 이 코드 — 갤러리·신청·결제·멘토 콘솔·정산·학과 담당자 화면

아임웹으로 현멘 전체를 만들 수 없어서 이렇게 나눴다. 아임웹의 예약은 **사업자
한 명이 여는 일정**이라 멘토 여러 명이 각자 시간대를 여는 구조가 안 되고,
멀티 판매자 정산이 없어서 수수료 10% · 원천징수 3.3% 를 자동으로 뗄 수 없다.
승낙 워크플로, 줌 자동 생성, 환불 사다리, 기관 이용권 차감도 마찬가지다.

## 도메인

| | 무엇 |
|---|---|
| `careerpeak.co.kr` | 아임웹. 소개·영업 |
| **`hyunmen.kr`** | 이 코드. 서비스 **정본** (2026-09-14 결정) |
| `hyunmen.com` 등 나머지 | 사두고 `hyunmen.kr` 로 보낸다. 서비스로 쓰지 않는다 |

`.kr` 을 정본으로 둔 이유는 대상이 한국 석·박사뿐이기 때문이다. 학과와 계약하고
통신판매업 신고와 원천징수 신고를 하는 서비스라 `.kr` 쪽이 신뢰를 얻기 쉽다.
해외로 넓힐 대상은 검사(PCA)이지 현멘이 아니다.

`.com` 은 방어용으로 같이 산다. 이름을 들은 사람은 기본값으로 `.com` 을 친다.

### 여러 개를 사도 정본은 하나다

이름을 여러 개 사두는 것은 좋다(오타·방어). 다만 **전부 같은 서버를 가리키게
두면 안 된다.** 사람마다 다른 주소로 들어와서 이런 일이 생긴다.

- 세션 쿠키는 도메인마다 따로다. `.com` 으로 로그인하고 `.kr` 로 가면 로그아웃이다
- 소셜 로그인 콜백은 개발자 콘솔에 등록한 **주소 하나**에만 맞는다. 다른 도메인에서
  누르면 로그인이 통째로 깨진다
- 결제 성공·실패 주소는 지금 브라우저 주소를 쓴다. 별칭으로 들어오면 결제 뒤
  돌아오는 곳도 별칭이 된다

그래서 `AUTH_URL` 의 호스트(`hyunmen.kr`)가 아니면 **308 로 정본에 보낸다**
(`src/middleware.ts`).
경로와 쿼리는 그대로 따라간다. 상태 확인(`/api/health`)과 localhost·IP 접속은
예외다 — 컨테이너 점검이 밖으로 튕기면 안 된다.

리버스 프록시에서도 같이 막는 편이 낫지만, 프록시 설정은 빠뜨리기 쉽고 빠뜨려도
화면이 멀쩡해 보인다. 코드에서 한 번 더 막아둔 이유다.

`.env` 세 줄이면 된다.

```
AUTH_URL=https://hyunmen.kr
MAIL_FROM=no-reply@hyunmen.kr
NEXT_PUBLIC_SITE_URL=https://careerpeak.co.kr   # 푸터에 '소개 사이트' 링크가 뜬다
```

`NEXT_PUBLIC_SITE_URL` 은 푸터를 그리는 서버 컴포넌트에서 읽으므로 **재시작만 하면
반영된다** (빌드 없이 넣고 확인했다). 다만 같은 접두사를 쓰는 토스 클라이언트 키
(`NEXT_PUBLIC_TOSS_CLIENT_KEY`)는 브라우저로 내려가느라 빌드에 박히니, 그쪽을
바꿨으면 다시 빌드해야 한다.

`npm run check:env` 가 `AUTH_URL` 이 아직 localhost 인지, `MAIL_FROM` 도메인이
어긋나는지 알려준다.

## 아임웹에서 **만들지 말아야 할 것**

두 벌이 되면 반드시 어긋나고, 어긋난 안내는 없는 것보다 나쁘다.

**① 요금표·환불 규정을 아임웹에 옮겨 적지 않는다.**
이 값들은 운영사가 `/admin/prices` 에서 바꾸고 화면이 DB 에서 읽어 그린다.
아임웹에 숫자를 박아두면 요율을 바꾼 날 두 곳이 달라지고, 분쟁에서는 **싼 쪽이
기준이 된다.** 링크로 보낸다.

**② 문의 폼을 아임웹에 따로 두지 않는다.**
들어온 문의는 `/admin/inquiries` 한 곳에 쌓여야 답한 것과 안 답한 것이 갈린다.
아임웹 문의함에도 쌓이면 놓친 문의가 어디 있는지 아무도 모른다.
아임웹의 '문의' 버튼은 `/mentoring/contact` 로 보낸다.

**③ 약관·개인정보처리방침을 아임웹에 복사하지 않는다.**
이 문서들은 코드가 실제로 하는 동작(환불 사다리·노쇼 처리·정산)을 그대로 옮겨
쓴 것이다. 코드가 바뀌면 이쪽만 고치면 되게 한 벌로 둔다.

**④ 회원가입·로그인을 아임웹에 만들지 않는다.**
계정은 이 코드의 `users` 하나다(설계 원칙 1). 아임웹 회원과 서비스 회원이
갈리면 "가입했는데 로그인이 안 된다"가 그날부터 시작된다.

## 아임웹에서 **해야 할 것**

- 회사 소개, 브랜드, 연혁, 언론 노출
- 학과·기관 대상 영업 페이지와 **기관 문의 폼** (이건 아임웹에 둬도 된다 —
  학생 문의와 성격이 다르고 운영사가 직접 받는다)
- 사업자 정보 표기(상호·대표자·사업자등록번호·통신판매업 신고번호·주소·연락처).
  전자상거래법상 표시 의무라 **소개 사이트와 서비스 양쪽에** 있어야 한다.
  서비스 쪽은 `/terms` 아래 표에 자리를 비워뒀다
- 블로그·후기 홍보 글

## 두 도메인이라서 생기는 것

- **쿠키는 공유되지 않는다.** 아임웹에서 로그인 상태를 보여줄 수 없다.
  '멘토 둘러보기' 버튼은 로그인 여부와 무관하게 늘 같은 곳으로 보내면 된다 —
  갤러리는 로그인 없이 열린다
- **유입 추적**을 붙일 거면 양쪽에 같은 분석 도구를 걸어야 한다. 지금은 없다
- 서비스 화면 푸터에 '소개 사이트' 링크가 뜬다(`NEXT_PUBLIC_SITE_URL`).
  이 값을 비워두면 링크가 뜨지 않는다 — 아임웹이 아직 없을 때 깨진 링크를
  보여주지 않기 위해서다

## 도메인을 산 날 할 일

1. **`hyunmen.kr` 등록.** 같이 살 것: `hyunmen.com`(오타 방어), 여유가 되면 `.co.kr`
2. 전부 **같은 서버 IP** 로 A 레코드를 건다. 코드가 `hyunmen.kr` 로 모은다
3. 인증서는 별칭까지 함께 받는다. 별칭에 인증서가 없으면 308 이 나가기 전에
   브라우저가 경고를 띄운다 — 리다이렉트가 있어도 소용없다
4. `.env` 세 줄을 채우고 `npm run check:env`
5. **소셜 로그인 콜백**을 카카오·네이버 콘솔에 등록한다.
   `https://hyunmen.kr/api/auth/callback/kakao` · `.../naver`.
   정본 하나만 등록한다 — 별칭은 어차피 여기로 넘어온다
6. **메일 도메인 인증**(SPF·DKIM·DMARC)을 `hyunmen.kr` 로 잡는다.
   빼면 확정 안내와 리마인더가 스팸함으로 가고, 그러면 노쇼가 늘어난다
7. 아임웹에서 버튼들의 링크를 `https://hyunmen.kr/...` 로 건다 (위 표)
