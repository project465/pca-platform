## 4-B. 18:55 지시 — 라이브 플랫폼 연동 (처리 완료)

✅확인함 — 총괄이 알려준 경로를 **직접 확인한 뒤** 반영했다. 확인은 이
세션에서 HTTP 로 직접 눌러 본 것이다.

```
$ for p in "" /login /admin/login /survey /privacy; do curl -s -o /dev/null -w "%{http_code} $p\n" -L "https://pcagroup.haricareer.com$p"; done
200
404 /login
200 /admin/login
200 /survey
404 /privacy
```

총괄이 알려준 두 가지가 그대로 맞았다 — `/login` 없음, `/admin/login` 있음.

고친 것:

| 무엇 | 전 | 후 |
|---|---|---|
| 로그인 주소 | `PLATFORM_URL + /login` | `PLATFORM_URL + /admin/login` |
| `PLATFORM_URL` 기본값 | `https://app.metri.example` (가짜) | `https://pcagroup.haricareer.com` |
| 단추 글자 (한국) | "로그인" | "담당자 로그인" |
| 꼬리 안내 (한국) | "계정은 학과를 통해 발급됩니다" | "학생은 학교에서 받은 전용 링크로 들어갑니다" |

영어판·카자흐어판도 같은 뜻으로 고쳤다.

**학생용 전용 링크는 소개 사이트에서 만들지 않았다.** `/survey?univ=…&pwd=…`
는 학교마다 값이 달라 소개 사이트가 지어낼 수 없다. 총괄 지시대로 "학교에서
받으세요" 안내만 둔다.

⚠️**함께 발견한 것 — `/privacy` 도 404다.** 소개 사이트 꼬리와 문의 폼이
`PLATFORM_URL + /privacy` 로 개인정보 처리방침을 걸고 있었다. 그대로 두면
죽은 링크가 된다. 그래서 **처리방침 주소를 `privacyUrl` 이라는 별도 값으로
빼고, 값이 있을 때만 링크를 건다.** 지금은 세 판 모두 비어 있어 링크가 없다.

- 알리는 문장은 남겼다. 문의 폼에서 "기관명·담당자 이름·이메일은 도입
  상담에만 씁니다" 는 그대로 뜬다. 무엇을 받는지 보내기 전에 알리는 것이
  본질이고 전문 링크는 곁들이다
- 방침 화면 자체는 이 저장소 `src/app/privacy` 에 있으나 배포된 적이 없다
- **방침을 어디에 올릴지 정해 주시면** 원고의 `privacyUrl` 한 줄로 살아난다

⚠️미확인 — **눌러서 넘어가는 것까지는 확인하지 못했다.** 이 검사 환경의
브라우저가 바깥 주소로 나가지 못한다(프록시). 주소가 맞는지(HTML의 href)와
그 주소가 살아 있는지(HTTP 200)는 확인했고, 클릭 후 화면 전환은 못 봤다.
검사 스크립트도 그 경우를 '실패' 가 아니라 '못봄' 으로 적도록 고쳤다 —
나가지 못한 것과 진짜 실패는 구별되어야 한다.

```
  통과  머리에 로그인 단추가 있다
  통과  담당자 로그인을 가리킨다 (https://pcagroup.haricareer.com/admin/login)
  못봄  브라우저가 바깥으로 못 나가 눌러보지는 못했다. 주소는 살아 있다 (HTTP 200)
  통과  꼬리에도 로그인이 있다
  통과  꼬리도 같은 곳을 가리킨다
  통과  이 나라 사이트에는 처리방침 링크가 없다
  통과  좁은 화면 메뉴에도 있다
```
