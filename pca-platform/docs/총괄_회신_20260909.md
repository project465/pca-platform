### 24-3. 도메인 — 안 두 개를 여쭙는다 ⚠️

지시대로 **코드는 아직 바꾸지 않았다.** 원고에는 임시값(`metri.co.kr` ·
`metri.kz` · `metri.example`)이 그대로 있다. `harimetri.com` 등록이 끝나면
한 번에 바꾼다.

바꾸기 전에 정해야 할 것이 하나 있다. **판 셋을 한 도메인 안에서 나눌 것인가,
도메인을 나눌 것인가.**

#### A안 — 경로로 나눈다

```
harimetri.com/        글로벌 (영어)
harimetri.com/kr      한국
harimetri.com/kz      카자흐스탄
```

- 도메인을 하나만 사면 된다. 갱신도 한 번이다
- 검색 평판이 한 곳에 쌓인다. 한국판에서 얻은 신뢰가 카자흐판에도 붙는다
- ⚠️ **코드를 손봐야 한다.** 지금은 `SITE=kr npm run build` 로 판마다 통째로
  한 사이트를 굽는 구조다. 셋을 한 주소 아래 붙이려면 각 판에 basePath 를
  주고 세 결과물을 한 배포 뒤에 이어 붙이는 작업이 든다 — 반나절치 일이다
- ⚠️ 카자흐스탄 기관이 `.kz` 주소를 요구하면 갈아타기가 번거롭다

#### B안 — 하위 도메인으로 나눈다

```
harimetri.com         글로벌 (영어)
kr.harimetri.com      한국
kz.harimetri.com      카자흐스탄
```

- **지금 구조 그대로다.** 판마다 굽고 세 곳에 올리면 끝난다.
  고칠 것은 원고의 `domain` 문자열 세 줄과 지역 선택 메뉴의 링크뿐이다
- 나라별로 서버 위치·언어·배포 시점을 따로 가져갈 수 있다
- 나중에 `metri.kz` 같은 나라 도메인을 사더라도 그 앞에 붙이기만 하면 된다
- ⚠️ 검색 평판이 셋으로 나뉜다. 새로 여는 나라는 맨바닥에서 시작한다

**정리하면** — A안은 도메인 관리와 검색이 유리하고 코드 작업이 붙는다.
B안은 지금 구조에 맞고 나라별로 갈라 두기 좋으나 검색 평판이 나뉜다.
지금 판이 셋이고 앞으로 더 늘 전개(터키·독일·미국·일본·중국·프랑스·남아공·
필리핀)를 보면 **B안이 손이 덜 간다**고 본다. 다만 이건 대표가 정할 일이다.

⚠️ **확인하지 못한 것** — 카자흐스탄 대학·정부기관이 `.kz` 도메인을 요구하는
관행이 있는지는 알아보지 않았다. 있다면 그것만으로 답이 정해진다.

   *사이트 꼬리* 표시사항이지 처리방침 기재사항이 아니다. **개인 진단 결제를
   여는 시점에** 꼬리에 상호·대표자·주소·등록번호·통신판매업신고번호를 한 줄로
   넣는 것이 맞다. 지금은 결제가 없어 넣지 않았다
3. **영문 상호와 대표자 영문 표기를 지어내지 않았다.** 등록된 영문 상호를
   모르고, `조건희` 의 영문 표기도 Cho/Jo · Geon-hee/Gun-hee 로 갈린다.
   해외판·카자흐판에도 **한글 그대로** 두었다. 등록 표기를 주시면 넣는다
4. **보호책임자의 직위를 받지 못했다.** 이름만 적혀 있다. 원래 칸은
   "이름·직위" 다

**그리고 무거운 것 하나.** 이렇게 내면 METRI 의 개인정보 처리자는 법적으로
**주식회사 에이치에이연구원**이 된다. METRI 를 별도 법인이나 ACADEMIX 이름으로
운영할 계획이 있으면 그때 처리방침을 다시 써야 하고, 그전에 받은 동의도
승계 문제가 생긴다. 대표가 이 점을 알고 정하신 것인지 확인해 주시라.

**채웠지만 배포하지 않는다.** 지시대로다. 빈칸 셋도 아직 남아 있다.

## 30. 회신 10 처리 — 위탁처와 배포 준비

### 30-1. 위탁처 두 칸 — 하나는 채우고 하나는 없앴다 ✅

| 칸 | 처리 |
|---|---|
| 호스팅 | **Vercel Inc. — 서버 운영과 데이터 보관 (국외 처리 포함)** |
| 메일 | **줄을 뺐다** — 위탁이 없기 때문이다 |

**메일 위탁처를 비워 두지 않고 아예 없앤 이유.** 문의 폼은 메일을 보내지
않는다. `marketing/src/app/actions.ts` 어디에도 SMTP 도 메일 서비스도 없다.
없는 위탁을 방침에 적으면 그것도 사실과 다르다. 지시하신 "문의는 이메일로
직접" 도 지금 동작과 다르다 — 폼은 메일로 가지 않는다.

**처리방침의 빈칸은 이제 없다.**

### 30-2. 문의 폼이 실제로 하는 일 ⚠️

한 줄로 적으라 하셨는데, 한 줄로는 위험한 것이 나왔다.

```
폼 제출 → ① 서버의 파일에 한 줄 덧붙임 (.inquiries/contact.jsonl)
        → ② PLATFORM_INTAKE_URL 로 POST (환경변수가 있을 때만)
        → 메일은 보내지 않음
```

**⚠️ 이 상태로 Vercel 에 올리면 문의가 전부 사라진다.**

- ① 서버리스의 파일 칸은 **읽기 전용**이다. 파일 저장이 실패한다
- ② 라이브 플랫폼에는 접수 엔드포인트가 **없다.** 직접 확인했다(2026-09-10):
  `/api/applications` · `/api/intake` · `/api/health` **모두 404**
- 그런데 원래 코드는 둘 다 실패해도 `{ ok: true }` 를 돌려주고 있었다 →
  화면에는 **"문의가 접수되었습니다"** 가 뜬다

접수됐다고 해 놓고 아무 데도 남지 않는 것이 이 사이트에서 가장 나쁜
고장이다. 학과 담당자는 회신을 기다리고, 우리는 받은 적이 없다.

**그래서 이번에 고쳤다.** 어디에도 남지 못하면 접수됐다고 하지 않는다.

> 지금은 문의를 접수할 수 없습니다.
> hari_info@hari.re.kr 로 보내주시면 같은 담당자가 확인합니다.

이건 응급 처치다. **배포 전에 셋 중 하나를 골라야 한다.**

| 안 | 무엇이 필요한가 | 방침에 미치는 영향 |
|---|---|---|
| A · 메일 발송 | SMTP 사업자 하나 (예: Resend·SendGrid·Naver Works) | 메일 위탁처 한 줄이 **생긴다** |
| B · 라이브 플랫폼에 접수 엔드포인트 | web 방 소관. `src/` 에 만들어 둔 것이 있으나 라이브에는 없다 | 위탁처 그대로 |
| C · 폼을 없애고 메일 주소만 | 코드는 가장 단순 | 위탁처 그대로 |

**총괄 판단을 구한다.** 이 방 의견은 **A** 다 — 폼이 살아 있어야 문의가
들어오고, SMTP 한 곳이면 끝난다. B 는 web 방 일정에 묶이고, C 는 문의 수를
줄인다.

### 30-3. 배포 준비 — DNS 표 ✅ / ⚠️

**대표가 도메인 등록 사이트에 넣을 값.** Vercel 은 프로젝트를 만들면
대시보드가 정확한 값을 보여준다 — **그 값이 정본**이고, 아래는 Vercel 이
문서로 안내하는 표준값이다.

| 이름 | 종류 | 값 | 쓰는 곳 |
|---|---|---|---|
| `@` (뿌리) | **A** | `76.76.21.21` | harimetri.com — 글로벌판 |
| `kr` | **CNAME** | `cname.vercel-dns.com` | kr.harimetri.com — 한국판 |
| `kz` | **CNAME** | `cname.vercel-dns.com` | kz.harimetri.com — 카자흐판 |
| `www` | **CNAME** | `cname.vercel-dns.com` | www → 뿌리로 넘김 (선택) |

이 방에서 확인한 것 —

- `cname.vercel-dns.com` 은 실제로 풀린다 (76.76.21.98 · 66.33.60.67)
- `76.76.21.21` 은 살아서 응답한다 (403 — 아직 이 도메인을 모르니 정상)

⚠️ **TTL 은 낮게(300초) 두고 시작하시라.** 잘못 넣었을 때 되돌리는 시간이
그만큼 짧아진다. 연결이 안정되면 올린다.

### 30-4. 배포 체크리스트 — 지금 상태

```

Error: SITE=trr 에 해당하는 원고가 없습니다. 지금 있는 것: global, kr, kz
```

| | 결정 | 지금 상태 |

④ 의 **교체 자리는 기억해 두었다.** 사진은 `marketing/public/photos/01.jpg` ~

### 34-1. ⑥ Firebase — 정적 내보내기가 되는가 ⚠️

**직접 해 봤다. 지금 이대로는 안 된다. 막는 것은 딱 하나다.**

```
$ SITE=kr npm run build        # next.config 에 output: "export" 를 넣고

> Server Actions are not supported with static export.
```

**문의 폼의 서버 액션 하나뿐이다.** 그것을 빼고 다시 돌리니 **16개 화면이
전부 정적으로 나왔다**(`out/` 7.5MB, HTML 11장 + 자산). 지도·레이더·결과지·
처리방침·사이트맵 전부 정적으로 나온다.

곁들여 두 곳을 고쳐야 했다 — `sitemap.ts` 와 `robots.ts` 에
`export const dynamic = "force-static"` 이 없어 내보내기가 거기서 먼저
멈췄다. 값이 빌드 때 다 정해지는 경로라 붙여 두는 것이 맞고, **이번에
넣었다**(정적으로 가지 않아도 해가 없다).

### 34-2. ⚠️ 그런데 이것이 ⑦ 을 건드린다 — **web 방이 만들기 전에 정해야 한다**

정적 사이트에는 서버가 없다. 그래서 문의 폼이 **브라우저에서 직접**
`/api/intake` 를 부르게 된다. 여기서 두 가지가 따라온다.

1. **비밀 헤더를 쓸 수 없다.** 브라우저에 넣은 값은 누구나 볼 수 있다.
   `x-intake-secret` 을 정적 사이트에 넣으면 그건 비밀이 아니다
2. **CORS 를 열어야 한다** — `harimetri.com` · `kr.` · `kz.` 세 오리진

지금 web 방이 `POST /api/intake` 를 만들고 있다. **비밀 헤더를 전제로
만들면 정적 사이트에서는 못 쓴다.** 세 길 중 하나를 지금 골라야 한다.

| | 어떻게 | 값 |
|---|---|---|
| **가 · 공개 접수 창구** | 비밀 없이 받고, 그 대신 오리진 검사 · 속도 제한 · 허니팟 | 정적 유지 · 이 방과 web 방 모두 작업 작음 · **권고** |
| 나 · Firebase App Hosting | Next 를 서버째 돌린다. 서버 액션·비밀 그대로 | 정적이 아님. Blaze(유료) 필요 · 대표 계정에 결제 연결 |
| 다 · Cloud Function 한 개 | 정적 사이트 + 함수가 비밀을 들고 중계 | Blaze 필요 · 움직이는 부품 하나 늘어남 |

**가를 권한다.** 도입 문의는 학과명·이름·이메일이고, 새는 것이 문제가 아니라
쓰레기가 들어오는 것이 문제다. 그건 비밀 헤더가 아니라 속도 제한과
허니팟으로 막는 것이다. 하리로 홈페이지도 같은 성격의 폼을 정적으로 받고 있다.

⚠️ **총괄이 web 방에 이 한 줄을 지금 전해 주시라** — "소개 사이트는 정적이라
비밀 헤더를 못 쓴다. 오리진 검사와 속도 제한으로 막고, CORS 에 세 도메인을
넣어 달라."

응답 규격 `200 {ok:true, refCode}` 는 확인했다. 지금 코드가 이미 `refCode` 를
읽고 있어 **이름은 맞다.**

### 34-3. ⑥ 멀티사이트인가 경로인가 — **멀티사이트** ✅

| | 도메인 B안에 맞는가 |
|---|---|
| **멀티사이트 (한 프로젝트 안에 사이트 셋)** | **맞는다.** 사이트마다 도메인을 따로 붙인다 |
| 사이트 하나 + 경로 | 맞지 않는다. `kr.harimetri.com` 은 경로가 아니라 도메인이다 |

멀티사이트여야 하는 이유가 하나 더 있다. **카자흐판만 늦게 열 수 있다.**
사이트를 안 만들면 그 도메인은 열리지 않고, 검수가 끝난 뒤 사이트 하나를
더해 도메인만 붙이면 된다. 배포도 `--only hosting:<대상>` 으로 따로 나간다.

**프로젝트는 새로 만드시기를 권한다.** 하리로 홈페이지가 있는 프로젝트에
얹어도 동작은 같지만, METRI 는 브랜드도 도메인도 다르고 — 무엇보다 언젠가
**처리자 명의를 옮길 일이 생기면 프로젝트를 통째로 넘기면 된다.** 지금
①에서 하리로 명의로 가기로 한 것과 짝이 되는 대비다.

> 4. 각 사이트에서 "맞춤 도메인 추가" 를 누른다
> 5. 도메인을 넣는다 — `harimetri.com` / `kr.harimetri.com` / `kz.harimetri.com`
> 6. 콘솔이 **TXT 한 개**(소유 확인)를 준다 → 도메인 등록 사이트에 넣는다
> 7. 확인이 끝나면 콘솔이 **A 레코드**를 준다 → 그 값을 넣는다
> 8. 자물쇠(SSL)가 켜질 때까지 기다린다 (보통 몇 시간, 최대 하루)

**레코드 종류는 A 와 TXT 다.** Vercel 안내문의 CNAME 은 쓰지 않는다 —
Firebase 는 하위 도메인에도 A 를 준다.

**값은 콘솔이 정본**이지만, 이 방에서 확인한 것이 있다. 하리로 홈페이지가
이미 Firebase 에 있고 그 값이 이것이다.

```
haricareer.com      → 199.36.158.100
www.haricareer.com  → 199.36.158.100
firebaseapp.com     → 199.36.158.100      (Firebase Hosting 의 주소)
```

콘솔이 보여 줄 값도 이것일 가능성이 높다. **TTL 300 권고는 그대로 유효하다.**

⚠️ 곁들여 확인한 것 — **라이브 플랫폼은 Firebase 가 아니다.**

```
pcagroup.haricareer.com → 64.29.17.1 · 216.198.79.1   (Firebase 아님)
```

하리로 홈페이지(Firebase)와 검사 플랫폼(다른 곳)이 서로 다른 데 있다.
섞어서 안내하면 대표가 헷갈린다.

## 36. 회신 13 처리 — 정적 전환 완료

### 36-0. ⚠️ 먼저 — **message 10자 규칙이 빠른 문의 폼을 통째로 막습니다**

web 방에 전달하신 규칙 중 하나가 지금 화면과 부딪힙니다.

**첫 화면의 "1분이면 됩니다" 폼에는 하고 싶은 말 칸이 아예 없습니다.**
기관명·이름·이메일 셋뿐입니다. 문턱을 낮추려고 그렇게 만든 것이고,
바로 옆에 이렇게 적혀 있습니다.

> 학과명과 인원만 주시면 적용안을 정리해 회신드립니다.

`message` 를 10자 이상 요구하면 **이 폼으로 들어온 문의는 하나도 통과하지
못합니다.** 사람은 다 채웠는데 "접수할 수 없습니다" 만 보게 됩니다.

세 길이 있습니다.

| | 어떻게 | 값 |
|---|---|---|
| **가 · 규칙을 값이 있을 때만** | `message` 가 비어 있으면 통과, 있으면 10자 이상 | web 방 한 줄 · **권고** |
| 나 · 빠른 폼에 말 칸을 더한다 | 필수 칸이 하나 는다 | "1분이면 됩니다" 가 거짓이 된다. 문의 수가 준다 |
| 다 · 빠른 폼을 없앤다 | 긴 폼만 남긴다 | 첫 화면에서 문의가 사라진다 |

**가를 권합니다.** 빈 `message` 는 스팸의 표지가 아닙니다 — 스팸은 오히려
말을 길게 씁니다. 막는 일은 허니팟과 속도 제한이 이미 합니다.

지금 코드는 있는 값을 그대로 보냅니다. **규칙이 그대로면 빠른 폼이 죽고,
사람에게는 응급 문구가 뜹니다** — 조용히 사라지지는 않습니다.

### 36-1. 정적 내보내기 전환 ✅확인함

|---|---|
| `output: "export"` | 넣음 |
| 서버 액션 | **없앴다** (`src/app/actions.ts` 삭제) |
| 폼 | 브라우저에서 `fetch` — `src/lib/contact.ts` |
| 창구 주소 | `https://pcagroup.haricareer.com/api/intake` (`lib/platform.ts` 의 `intakeUrl`) |
| 허니팟 | 숨은 칸 `website`. 채워져 오면 조용히 삼킨다 |
| 비밀 헤더 | **쓰지 않는다** |
| robots · sitemap | `force-static` 그대로 |

**`ok:false` 를 성공으로 보이지 않게** 했습니다. 지시하신 그대로입니다 —

### 36-7. 곁들여 — CI 를 제가 깼고 고쳤습니다 ⚠️→✅
