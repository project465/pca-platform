# KUS-CR-04 — CONTRA 응답 검토 요청 (측정 담당 · 미적용)

작성 2026-10-20 · 가지 `claude/ecstatic-cori-sv6lh5`

## 무엇이 일어나는가 (재현: `scripts/kus/verify.ts` 의 CONTRA)

CONTRA 학생은 BIZ PRO 의 영역 넷 전부에서 보기 넷의 맨 위(`직접 정했고 그 결과가 쓰였다`)를
고르고, 근거 체크리스트는 **하나도 고르지 않았다.** 공통 판정이 내놓는 값:

| 칸 | CONTRA | RICH(견줄 학생) |
|---|---|---|
| 응답으로 확인된 판단 | 32칸 | 32칸 |
| 직접 정했고 근거 둘이 받친 판단(owned) | 0칸 | 28칸 |
| 고른 근거 항목 | 0개 | 93개 |
| 근거가 선 영역(Z1) | 0개 | 4개 |
| 응답 품질 | `LOW_VARIANCE` | `OK` |
| 공통 결과지 머리 상태 | **정리만 하면 돼요** | 지원서에 쓸 경험이 있어요 |

소유(owned)는 `근거 둘` 규칙이 막아 0 이 맞게 섰다. 걸리는 것은 **확인(confirmed) 32칸과
머리 상태**다. 근거가 하나도 없는 응답이 `정리만 하면 돼요` 를 받으면, 학생은 해 본 일이
충분하고 글로 옮기기만 하면 된다고 읽는다.

## KUS 쪽에서 한 것 (판정은 그대로)

`src/lib/kus/analysis.ts` 의 `reliabilityOf()` 가 응답 · 근거 · 응답 품질을 나란히 적는다
(점수로 합치지 않는다). 근거 항목이 0 이고 확인된 칸이 있으면 KUS 화면 · PDF 의 머리에
공통 상태 이름을 그대로 세우지 않고 `근거 확인 전` 으로 적으며, **공통 상태 이름은
`coreBadge` 로 남겨 신뢰도 상자에 그대로 적는다.** 감추지 않는다.

이 층은 KUS 전용 파일 안에서 끝난다. 공통 결과지(`/v3/{id}/result`)는 여전히
`정리만 하면 돼요` 를 적는다.

## 측정 담당에게 묻는 것

1. 근거 항목 0 인 응답에서 `확인` 이 32칸 서는 것이 **의도된 동작인가.**
   (보기 셋째 이상이면 근거 없이도 확인으로 세는 규칙이라면, 그 규칙을 그대로 둘지)
2. `LOW_VARIANCE` 와 근거 0 이 함께 선 응답의 머리 상태를 공통 결과지에서도 낮출지.

## 제안 (승인 대상을 둘로 가른다)

- **CR-04a 문장만 (결과 문장 판본 하나):** `result/text.ko.ts` 의 머리 상태를 고를 때
  `evidence_items === 0 && confirmed_axes > 0` 이면 `근거 확인 전` 계열 문장을 쓴다. 채점 · 묶음 ·
  결과 모델은 그대로이고 `me-v3-result-copy` 판본만 오른다. KUS 층과 같은 규칙이라 승인되면
  KUS 쪽 덮어쓰기를 걷는다.
- **CR-04b 판정 (측정 동결 해제가 필요):** 확인 규칙 자체를 바꿀지는 측정 담당이 정한다.
  KUS 는 이 안을 쓰지 않았고 제안하지도 않는다. 바꾸면 이미 응시한 사람의 결과가 달라지므로
  판본을 올리는 일이다.

KUS 는 둘 다 적용하지 않았다.
