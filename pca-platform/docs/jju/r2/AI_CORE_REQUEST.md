# 변경 요청 C10-R2 — AI Major Core (또는 CS Core AI 영역 판본 올림)

받는 곳: Core 담당 세션 · 보내는 곳: JJU 세션 · 근거: `TRACK_B_COVERAGE.md`(문항 번호 기준), `coverage.json`

## 무엇이 비어 있는가

JJU 공식 과정(사업주 확인 · 출처 S1·S2)은 AI 융합 교과목과 **2026 AI 기초 과정(파이썬·데이터 처리·시각화·통계·딥러닝 기초)** 을 운영한다.
지금 Core 셋(CS_CORE_V1 · EE_CORE_V1 · ME_CORE_V3)의 판정 문항(`axis_level`)으로 재는 AI 쪽은 이것뿐이다.

| 역량 | 판정 문항 | 상태 |
|---|---|---|
| 기계학습 모형 평가·개선 | CS `TD09_*` Core 12 (+ 팩 14) | 측정 |
| 데이터 처리 | CS `TD09_J4_1` · `TD09_J5_2` | 측정 (2문항) |
| 센서 신호 처리 | EE `TD04_*` Core 12 · `TD11_J3_2` · `TD11_J7_1` | 측정 |
| 파이썬 · 시각화 · 딥러닝 | 0 | **교육과정만** |
| LLM·생성형 AI · 컴퓨터 비전 · MLOps · 엣지 AI · 로봇 인지 | 0 | **미측정** |

그래서 지금 이름의 `LLM 응용 트랙` 과 `스마트팩토리 트랙` 은 **부적합**, 나머지 셋은 **부분 적합**이다.
JJU 쪽은 미측정 영역에 **역량 값을 만들지 않고**, 결과·리포트에 `이 검사가 재지 않는 영역` 으로 적는다.

## 요청

선택지 셋 가운데 하나를 사업주와 Core 담당이 정한다. JJU 세션은 어느 쪽도 직접 만들지 않는다.

1. **CS Core 판본 올림** — `CS_V1_ITEM_BANK` 에 AI 영역 2~3개를 더한다(예: 신경망 학습·평가, LLM 응용·평가, 모델 배포·운영).
   측정 동결(`ME_V3_MEASUREMENT_FREEZE_1`)과 같은 규칙으로 판본을 올리고, 이미 응시한 결과는 그 판본으로 남는다.
2. **AI Major Core 신설** (`AI_CORE_V1`) — 콘텐츠만으로 Core 를 더하는 파이프라인(`MAJOR_CORE_PIPELINE.md`)을 따른다.
   후보 영역: 자료 준비·품질 · 모형 선택·학습 · 평가 설계 · 신경망 학습 · 언어 모델 응용 · 영상 인식 · 모델 배포·운영 · 온디바이스 추론 · 로봇 인지 · AI 윤리·안전 · 데이터 시각화·보고 · 문제 정의(12).
   축 여덟·척도·소유 판정·묶음 규칙은 공통 엔진 그대로 쓴다.
3. **트랙 이름 조정** — 측정하는 것에 맞게 트랙을 다시 부른다(예: `LLM 응용` → `소프트웨어 개발`). 콘텐츠 작업 없이 오해를 없앤다.

## 선택지 1·2 의 합격선 (자료보다 먼저 적는다)

- 각 AI 영역마다 판정 문항 8개 이상(선별 4축 × 2) · 필수 축 2개 지정
- 문면은 `l2` 행동을 묻는다(`해 본 적` 이 아니라 `직접 정한 것`) · 기계공학 말 0
- 부트캠프 저학년이 고를 수 있는 근거(수업·PBL·스터디) 체크리스트 항목 영역당 6개 이상
- 전공자 검토 · 인지 면접 전에는 `open_to_students: false`

## 막는 것

JJU AI·LLM·피지컬 AI 트랙을 `AI 역량을 진단한다` 고 소개하는 일. 그 전까지 화면과 리포트는 측정 범위를 위 표 그대로 적는다.
