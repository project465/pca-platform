# 무엇을 만드는가 — 정의와 나누는 축

## 한 줄

**공학 학습자의 Career Profile 을 만들고, 그것을 채용 수요에 붙여
직무·기업·부족 역량·다음에 할 일까지 내려주는 엔진.**

적성검사가 아니다. 채용공고 추천도 아니다. 둘을 잇는 **Skill Graph 가 제품**이고,
검사와 공고는 그 그래프의 입구와 출구다.

---

## 나누는 축은 학교급이 아니라 전공이다

이걸 먼저 못 박는다. 제품을 쪼갤 때 기준이 두 개 있었다.

| 나누는 축 | 상품이 몇 개가 되나 | 매출로 이어지나 |
|---|---|---|
| ~~학교급~~ (일반계고 / 마이스터고 / 대학 / 대학원) | 4개. 문항 4벌, 결과지 4벌, 영업 채널 4개 | **아니다.** 고교는 단가가 낮고 결재선이 길다 |
| **전공** (기계 → 전기전자 → 컴퓨터) | 전공당 1개. 문항은 공유 | **그렇다.** 학과가 결재권을 갖고, 전공 하나가 곧 계약 하나다 |

**전공으로 나눈다.** 기계공학 한 벌을 끝까지 완성해서 팔고, 그 다음 전기전자, 그 다음 컴퓨터다.
전공이 늘어나는 것은 매출이 늘어나는 것이고, 학교급이 늘어나는 것은 비용만 늘어난다.

### 그럼 고등학생은 어떻게 되나

**빼지 않는다. 상품으로 쪼개지 않을 뿐이다.**

- 트랙은 `HS` **하나**다. 일반계고와 마이스터고를 나누지 않는다
- 검사지는 **고교판 한 벌**이다. 두 학교가 같은 문항을 푼다
- 갈리는 곳은 **결과지 뒷부분 한 군데**뿐이고, `learner_goals` 값 하나가 그걸 결정한다

| `goal` | 누가 | 결과지 뒷부분 |
|---|---|---|
| `univ` 진학형 | 일반계고 (기본값) | 전공 적합 → **과목 처방** (고교학점제 선택과목) |
| `job` 취업형 | 마이스터고·특성화고 (기본값) | 직무 적합 → **자격·NCS 처방** + 지역 기업 |

값은 학교가 명단 올릴 때 자동으로 정해지고, 학생이 바꿀 수도 있다
(마이스터고에도 진학할 학생이 있고, 일반계고에도 고졸 취업할 학생이 있다).
**학교 유형이 몇 개로 늘어나든 코드는 안 늘어난다.**

## 그래서 실제로 만드는 것은 몇 개인가

| | 개수 | 무엇 |
|---|---|---|
| 검사지 | **2** | 고교판 · 대학판 |
| 결과지 템플릿 | **2** | 고교판(뒷부분 분기) · 대학판 |
| 트랙 | 4 | `HS` `UNIV_LOW` `UNIV_HIGH` `GRAD` — **상품이 아니라 채점 가중치 행이다** |
| Skill Tree | 3 | 기계 · 전기전자 · 컴퓨터 |
| 판매 단위 | 전공 × 고객유형 | 기계공학 × (학과 / 개인) 부터 시작 |

트랙 4개를 보고 "4개를 만든다"고 읽으면 안 된다.
트랙은 `scoring_profiles` 테이블의 행이고, 코드에는 `if (트랙)` 이 없다.

## 두 개의 문을 동시에 연다 — B2B(대학)와 B2C

한쪽만 열면 다른 쪽이 죽는다. 이유가 각각 있다.

**B2B(학과)만 하면** — 계약이 학기 단위로 끊긴다. 방학에 매출이 0이고,
학생은 검사 한 번 보고 사라진다. 재방문이 없으니 데이터가 안 쌓인다.

**B2C만 하면** — 획득 비용이 매출을 먹는다. 개인 학생 한 명 데려오는 광고비가
리포트 값보다 비싸다. 이공계 취업 키워드는 단가가 높다.

**둘을 붙이면 서로를 먹인다.**

```
학과 계약 (B2B)
   └→ 학생 500명이 무료로 검사를 본다      ← 획득 비용 0
        └→ 그중 일부가 개인 결제로 넘어간다 (B2C)
             · 글로벌 공고 열람
             · 이력서·면접 준비
             · 졸업 후에도 이어지는 Career Profile
                  └→ 취업 결과가 학과 리포트로 돌아간다 (B2B 재계약 근거)
```

**B2C 는 별도 사업이 아니라 B2B 위에 얹는 층이다.** 그래서 두 가지가 1차 범위에 들어간다.

1. **셀프 가입과 개인 결제** — 기존 `CLAUDE.md` 는 이걸 후순위로 뒀다. **바꾼다.**
   기관 발급 계정과 개인 계정은 어차피 `users` 하나에 들어가므로(설계 원칙 1) 추가 비용이 작다
2. **무료 간이 진단** — 12문항 5분. 결과의 상위 1개만 보여주고 나머지는 결제.
   B2C 유입의 입구이자, 학과 영업 때 담당자에게 보여주는 데모다

## 기존 PCA 와의 관계

레포에 있는 단체 PCA 플랫폼을 버리지 않는다. **ECI 는 PCA 의 확장이다.**

| | 기존 PCA | ECI 확장 |
|---|---|---|
| 대상 | 대학 재학생 | 고교 ~ 대학원 |
| 축 | 업무 성향 6 + 직무 영역 10 | 성향 6 **+ 공학 활동 선호 8** |
| 산출 | 직무 적합도 · 역량 · 과목 | + **Skill Gap · JD 매칭 · 기업 매칭** |
| 데이터 | 검사 응답 | + **이수 과목 · 프로젝트 · 자격 · 인턴** |
| 계약 | 학과 좌석 | 학과 좌석 **+ 개인 결제** |

기존 `db/schema.sql` 의 테이블은 하나도 지우지 않는다. `db/schema_eci.sql` 이 위에 얹힌다.
`users` 하나 · `translations` · 산식은 데이터 — **설계 원칙 세 개를 그대로 지킨다.**

## 고교를 굳이 남겨 두는 이유

단가가 낮은데도 남기는 이유는 하나다.

**Career Data 의 연속성이 유일한 해자이기 때문이다.**
경쟁자는 전부 한 시점만 본다. Cognavi 는 취업 시점, 적성검사는 진학 시점.
고1의 검사 결과와 대학 3학년의 Skill Profile 이 **같은 `user_id` 에 쌓이면**
"고1 때 해석 성향이 높았던 학생이 실제로 CAE 로 갔다" 는 종단 데이터가 생긴다.
후발주자는 이걸 4년 기다려야 얻는다.

부수적으로, 2025년 3월 고교학점제 전면 시행으로 **열여섯 살이 진짜 결정을 내리게 됐다.**
졸업까지 192학점, 진로선택 과목을 학생이 고른다. 근거를 대주는 제품이 아직 없다.

> 정리 — **고교는 지금 매출이 아니라 4년 뒤 자산이다.** 그래서 트랙 하나, 검사 한 벌,
> 분기 한 군데로 **가장 싸게** 붙여 둔다. 영업 자원은 대학에 쓴다.

## 지금 하는 것과 안 하는 것

**한국만 한다.** 미국 JD 구조는 [05번 문서](05_jd_pipeline.md)에 설계해 두지만 1차에는 만들지 않는다.
이유는 [09번 문서](09_global_flow.md) 3장에 있다 — 한국은 채용공고 원천이 공공 API 로 무료고,
미국은 민간 공고 전량이 유료다. 같은 화면인데 원가가 열 배 다르다.

경계를 못 박아 둔다.

- **AI 가 점수를 만들지 않는다.** 점수는 산식이 만들고 모델은 문장만 쓴다
- **지역정주 취업률을 우리가 산출한다고 말하지 않는다.** 졸업 후 통계로 확정되는 지표다.
  우리가 대는 것은 앞단의 과정 데이터다 (기존 `CLAUDE.md` 판단 유지)
- **전공은 셋으로 시작한다.** 기계 → 전기전자 → 컴퓨터
- **채용 대행을 하지 않는다.** 매칭까지가 우리 몫이다
