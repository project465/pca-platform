# Skill Graph — 온톨로지 구조와 3개 전공 Skill Tree

전체 표는 [`generated/skill_tree.md`](generated/skill_tree.md) 에 있다 (자동 생성).
**고칠 곳은 `data/eci/*.json` 이고**, 고친 뒤 `npm run eci:build` 를 돌리면
시드 SQL·문서 표·프리뷰 데이터가 한 번에 다시 만들어진다.

현재 규모 — **역량 138개 · 직무군 24개 · 요구관계 261개 · 동의어 565개.**

---

## 1. 왜 그래프여야 하나

학생과 기업이 다른 말을 쓴다.

```
학생:  "열역학 A+ 받았고 SolidWorks 좀 합니다"
기업:  "3D 모델링 및 열유동 해석 유경험자 우대"
```

이 둘은 같은 얘기인데 문자열로는 하나도 안 겹친다.
**Skill Graph 는 이 번역표다.** 이게 자산이고, 검사·공고·리포트는 그 위의 얇은 층이다.

---

## 2. 다섯 계층

역량을 한 덩어리로 두면 "열역학"과 "SolidWorks"가 같은 무게로 취급된다. 계층을 나눈다.

| 계층 | 뜻 | 특징 | 예 |
|---|---|---|---|
| **L1** 기초과학 | 전공 이전의 바탕 | 잘 안 변한다. 고교 처방이 여기로 떨어진다 | 공학수학, 일반물리 |
| **L2** 전공 핵심 | 그 전공의 이론 | 학교가 가르친다. 성적으로 증거가 나온다 | 열역학, 회로이론, 자료구조 |
| **L3** 도구·소프트웨어 | 실제로 손에 쥐는 것 | **공고에 가장 많이 적히는 층** | ANSYS, Verilog, Kubernetes |
| **L4** 응용 도메인 | 산업에 붙은 지식 | 인턴·프로젝트로만 얻는다 | 배터리 팩 열관리, 자동차 전장 |
| **L5** 공통 역량 | 전공을 안 가림 | 전공 간 이동의 다리 | 기술문서, 기술영어, 협업 |

**설계상 중요한 점.** L5 는 `competencies.major_id` 가 NULL 이다.
그래서 기계공학 학생과 컴퓨터공학 학생이 "기술영어" 라는 **같은 행**을 공유한다.
전공이 늘어도 공통 역량은 안 늘어난다.

L3 가 가장 많이 팔린다. 공고에 적히는 건 "고체역학" 이 아니라 "ABAQUS" 다.
하지만 L2 없이 L3 만 있으면 그건 학원이지 공학교육이 아니므로, 결과지는 둘을 같이 보여준다.

## 3. 직무군에 붙는 두 가지

각 직무군(`job_clusters`)은 두 벌의 데이터를 갖는다.

**(1) 요구 역량** — `job_competency_map`

```
구조·유동 해석 (CAE)
  유한요소법        요구 4  ★★★ 필수
  ANSYS Mechanical  요구 4  ★★★ 필수
  고체역학          요구 4  ★★★ 필수
  ABAQUS            요구 3  ★★  중요
  Python            요구 3  ★★  중요
  기계진동          요구 2  ★   보조
```

**필수도(criticality)를 안 쓰면 모든 직무의 적합도가 비슷해진다.**
12개 역량을 평등하게 평균 내면 변별이 사라진다. 필수 3개를 못 채운 학생과
보조 3개를 못 채운 학생은 전혀 다른 상태다.

**(2) 활동 지표 가중치** — `job_axis_weights`

```
구조·유동 해석 (CAE)
  해석·계산 0.40 · 탐구·이론 0.20 · 설계·구상 0.14
  구현·코딩 0.12 · 개선·효율 0.10 · 제작·실험 0.04     (합 1.00)
```

이건 **역량이 아니라 성향**이다. ANSYS 를 못 다뤄도 해석 성향이 높은 1학년에게
"너는 CAE 쪽이다" 라고 말할 수 있어야 한다. 그래서 두 벌이 필요하다.

## 4. 동의어 사전 — 이게 실제로 돈이 되는 부분

`competency_aliases` 에 565개 행이 들어 있다.

```
ME.GDT (공차·GD&T)  ←  "gd&t" "기하공차" "치수공차" "tolerance"
SW.ANSYS_MECH       ←  "ansys mechanical" "앤시스" "구조해석"
CE.DL (딥러닝)       ←  "deep learning" "cnn" "transformer" "llm"
```

공고에서 스킬을 뽑는 1차 관문이 이 표다. 사전으로 걸리는 게 80% 정도 되고,
나머지를 임베딩과 LLM 이 처리한다([4장](04_matching.md) 참조).
**사전이 클수록 LLM 호출이 줄고 원가가 내려간다.** 그래서 이 표는 비용 구조이기도 하다.

한국어와 영어를 같은 행에 매다는 것이 글로벌 확장의 핵심이다.
`lang` 컬럼만 늘리면 일본어 공고도 같은 `competency_id` 로 떨어진다.

## 5. 트랙 표시 — 고졸로 갈 수 있는 직무

`job_cluster_tracks` 에 `HS` 가 붙은 직무는 **고졸 채용이 실제로 존재하는 직무**다.
현재 24개 중 10개.

| 전공 | `HS` 표시 직무 |
|---|---|
| 기계 | 생산기술·제조엔지니어링, 품질·신뢰성, 반도체·디스플레이 장비 |
| 전기전자 | 임베디드 SW·펌웨어, 전력전자·전력시스템, 하드웨어 시험·신뢰성 |
| 컴퓨터 | 백엔드, 프론트엔드, DevOps·SRE, SW 품질·테스트 |

**마이스터고 학생에게 "항공우주 R&D 적합도 1위" 를 보여주면 그 결과지는 버려진다.**
이 표시가 그걸 막는다.

## 6. 3개 전공 요약

| 전공 | 역량 | 직무군 | 특징 |
|---|---|---|---|
| **기계공학** ME | 49 | 8 | L2(4대 역학)가 두껍고 L3(CAD/CAE)가 공고를 지배한다 |
| **전기·전자공학** EE | 50 | 8 | 반도체·전력·통신·임베디드로 **갈래가 가장 넓다**. 직무 간 역량 겹침이 적다 |
| **컴퓨터공학** CE | 49 | 8 | L3 비중이 압도적. **학교 밖 증거(프로젝트·오픈소스)가 가장 중요** |

전공별로 채점이 달라져야 하는 이유가 여기서 나온다.
컴퓨터공학은 이수 과목만으로 실력이 안 잡히고, 기계공학은 반대로 과목이 상당히 잘 잡는다.
그래서 `scoring_profiles` 를 전공별로도 덮어쓸 수 있게 열어 둔다(기존 `scoring_weights` 가 그 자리다).

## 7. 늙지 않게 하는 장치

온톨로지의 진짜 위험은 틀리는 게 아니라 **늙는 것**이다.
2년 뒤에도 "Kubernetes" 가 없으면 그 제품은 죽는다.

```
공고 수집 → 스킬 추출 → 사전에 없는 말 → skill_candidates 에 적립
                                              ↓
                                     주 1회 사람이 판정
                                     (병합 / 신규 / 기각)
                                              ↓
                                     competency_aliases 또는 competencies
```

**자동 승인은 하지 않는다.** 자동으로 스킬을 늘리면 6개월 뒤 "리액트"와 "React"와 "react.js"가
서로 다른 역량으로 갈라져 있고, 그때는 되돌릴 수 없다.
관리자 화면 A5 가 이 큐를 처리한다([1장](01_screens.md) 5절).
