# JD 수집 구조 — 국내와 미국

**1차는 국내만 만든다.** 미국 구조는 여기 설계해 두지만 코드로 옮기지 않는다.
이유는 원가다 — 같은 화면인데 데이터 비용이 열 배 다르다([09번](09_global_flow.md) 3장).

---

## 1. 소스별 실태

### 국내

| 소스 | 종류 | 비용 | 제약 | 1차 사용 |
|---|---|---|---|---|
| **워크넷/고용24 Open API** (공공데이터포털) | 공공 API | **무료** (인증키 신청) | **OpenAPI 제공에 동의한 기업 공고만** 나온다. XML/UTF-8 | ✅ 주력 |
| 고용행정통계 Open API | 공공 API | 무료 | 통계. 개별 공고 아님 | ✅ 보조 지표 |
| 워크넷 직무데이터사전 | 공공 데이터 | 무료 | 직무 분류 기준으로 유용 | ✅ 분류 학습 |
| 사람인·잡코리아 | 민간 | 제휴 협의 | **무단 크롤링 안 한다.** 파트너 API 를 협의한다 | ❌ 2차 |
| 기업 채용 페이지 | 직접 | 무료 | robots.txt 준수, 허용 범위만 | △ 지역 앵커기업 한정 |

**"동의한 기업만" 이 실제 제약이다.** 워크넷 API 로는 대기업 공고가 잘 안 잡힌다.
그래서 **지역 중견·중소기업 커버리지가 좋다** — 앵커사업 논지와는 오히려 맞는다.
대기업 공고는 공식 채용 페이지에서 허용 범위 내로 보완한다.

### 미국 (2차 이후)

| 소스 | 종류 | 비용 | 쓸모 |
|---|---|---|---|
| **O*NET Web Services** | 공공 | 무료 | 직무–스킬 표준. **공고가 아니라 뼈대** |
| **USAJOBS API** | 공공 | 무료 | 연방 공고만. 커버리지 좁음 |
| **Adzuna API** | 상용 | 월 1,000콜 무료 | 집계·임금 추세에 적합 |
| BLS / JOLTS | 공공 | 무료 | 거시 통계 |
| Lightcast · Coresignal · LinkUp | 상용 | **유료** | 민간 공고 전량. 미국 진출의 실질 관문 |

**미국은 공고 원문을 우리 화면에 못 띄우는 경우가 많다.**
그래서 미국판 화면은 "공고 목록" 이 아니라 **"집계된 수요"** 로 축소된다.
`jd_sources.redistributable` 컬럼이 이 차이를 데이터로 들고 있고,
화면은 그 값을 보고 렌더링을 바꾼다.

## 2. 파이프라인

```
[수집]      소스별 어댑터 → jd_raw (원문 JSONB + body_hash)
   ↓                          원문을 절대 지우지 않는다
[정규화]    회사·지역·학력·경력·급여 → jd_postings
   ↓
[중복제거]  dedup_key = 회사 + 직무명 + 지역 + 본문 simhash
   ↓
[분류]      직무명 + 본문 → job_clusters 24개 중 하나 (+ 신뢰도)
   ↓
[스킬추출]  사전 → 임베딩 → LLM 판정 → jd_skills (+ 근거 문장)
   ↓
[집계]      jd_skill_stats (국가 × 지역 × 직무 × 역량 × 월)
   ↓
[만료]      expires_at 지나면 status='expired'. 통계에서는 빠지고 행은 남는다
```

### 원문을 지우지 않는 이유

스킬 추출기는 계속 고쳐진다. 사전에 단어가 하나 추가되면 **과거 공고를 전량 재처리**해야 한다.
원문이 없으면 작년 공고는 영영 옛 기준으로 남고, 수요 추세가 기법 변경 때문에 꺾인 것처럼 보인다.

### 중복 제거가 없으면 생기는 일

같은 공고가 워크넷과 기업 사이트에 동시에 올라온다.
중복을 안 지우면 **수요 집계가 두 배로 부풀고**, 그 위에서 계산한
`demand_share` 가 틀리고, 그걸로 만든 Skill Gap 처방이 틀린다.
`dedup_key` UNIQUE 제약이 DB 차원에서 이걸 막는다.

## 3. 직무 분류

공고 제목만으로는 안 된다. "선임연구원" 이 CAE 인지 소자인지 알 수 없다.

```
1차: 제목 규칙 매칭 (신뢰도 높으면 확정)
2차: 제목 + 본문 임베딩 → job_clusters 24개와 유사도
3차: 0.6 미만이면 미분류로 두고 검수 큐로
```

**미분류를 억지로 분류하지 않는다.** 억지 분류가 통계를 오염시킨다.
`jd_postings.classify_conf` 를 남겨서 낮은 것은 집계에서 뺄 수 있게 한다.

## 4. 라이선스를 데이터로 둔다

`jd_sources` 의 두 컬럼이 화면 동작을 바꾼다.

```sql
license_note     TEXT NOT NULL   -- 비워두면 수집하지 않는다
redistributable  BOOLEAN         -- false 면 원문 대신 링크와 요약만
```

| 값 | 화면 |
|---|---|
| `redistributable = true` | 공고 본문 발췌 표시 가능 |
| `redistributable = false` | **제목·회사·요약 + 원문 링크만.** 본문을 우리 화면에 안 띄운다 |

라이선스를 코드에 박으면 소스를 추가할 때마다 배포해야 하고,
사람이 실수해서 못 쓸 데이터를 화면에 띄운다. 그건 소송이다.

## 5. 수집 주기와 규모

| 소스 | 주기 | 예상 |
|---|---|---|
| 워크넷 Open API | 일 1회 | 이공계 관련 일 300~800건 |
| 기업 채용 페이지 | 주 1회 | 앵커기업 200곳 |
| 만료 처리 | 일 1회 | 게시 30일 경과 |

1차 목표 — **3개 전공 관련 공고 누적 20,000건.**
`demand_share` 가 안정되려면 직무당 최소 200건이 필요하다.
24개 직무 × 200 = 4,800 이 하한이고, 지역별로 쪼개면 그 4배가 필요하다.

---

## 6. 개인정보와 위생

- 공고에서 **담당자 이름·개인 연락처는 저장하지 않는다.** 정규화 단계에서 버린다
- 기업 식별은 사업자번호 우선(`companies.biz_no`), 없으면 이름 정규화
- 크롤링은 robots.txt 를 따르고, 요청 간격을 두고, User-Agent 에 연락처를 밝힌다
- 제휴 없이 민간 채용 플랫폼을 긁지 않는다. **초기에 이걸 어기면 나중에 제휴가 막힌다**

## 7. 국내 → 미국으로 넘어갈 때 안 바꿔도 되는 것

설계상 미리 맞춰둔 것들.

| 항목 | 지금 | 미국 갈 때 |
|---|---|---|
| 직무 코드 | `job_clusters.onet_code` 를 이미 채워 뒀다 | 그대로 쓴다 |
| 스킬 사전 | `competency_aliases.lang` 에 ko/en 이 이미 같이 있다 | 행만 는다 |
| EU 확장 | — | **ESCO↔O*NET 공식 크로스워크**가 있어 O*NET 만 붙들면 딸려온다 |
| 통화·급여 | `currency CHAR(3)` | 그대로 |

**직무를 O*NET 에 먼저 붙이는 순서가 중요하다.**
한국 코드로 먼저 만들고 나중에 번역하면 전부 다시 해야 한다.
