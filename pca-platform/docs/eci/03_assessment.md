# 검사 문항 설계

**만드는 검사지는 두 벌이다.** 고교판(`HS_V1`)과 대학판(`UNIV_V1`).
트랙이 넷이어도 대학 1학년과 졸업예정자는 같은 문항을 푼다. 다른 건 채점 가중치뿐이다.

## 0. 문항은 새로 쓰지 않는다 — 기존 PCA 문항을 뼈대로 쓴다 (2026-09-11 결정)

ACADEMIX 가 이미 만든 PCA 문항이 있다. **그걸 쓴다.** 새로 쓰는 것보다 명백히 낫다.

| 이유 | 내용 |
|---|---|
| 개발 근거가 이미 있다 | 전공자 2,346명 · 설문 2,091명 · 채용공고 428건 · 직무기술서 137건 · NCS 62건 · 현직자 48명 |
| 저작권이 등록돼 있다 | C-2025-058658 / C-2025-059731 / C-2025-059732 (한국저작권위원회) |
| 기존 응시자와 비교가 이어진다 | 축을 바꾸면 지금까지 본 학생들의 결과가 버려진다 |
| 일정이 줄어든다 | 140문항 집필 + 전문가 검수는 4~5주. 이걸 **1.5주로 줄인다** |

**다만 그대로 전부 되지는 않는다. 한 가지가 빈다.** 다음 절에서 정확히 무엇이 비는지 적는다.

## 1. 측정하는 축

### 1-1. 공학 활동 선호 8축 (새로 만드는 것)

기존 PCA 의 업무 성향 6축은 **일하는 방식**을 잰다. 공학 직무를 가르려면
**어떤 활동을 즐기는가**가 필요하다. "협력형" 은 CAE 와 생산기술을 못 가른다.

| 축 | 뜻 | 이 축이 높으면 |
|---|---|---|
| `ANALYZE` 해석·계산 | 현상을 수식과 모델로 푼다 | CAE, 통신, 소자 |
| `DESIGN` 설계·구상 | 요구조건에서 형상을 만든다 | 기계설계, 회로설계, 프론트엔드 |
| `BUILD` 제작·실험 | 만들고 측정해 확인한다 | 시험·신뢰성, 로봇, 임베디드 |
| `CODE` 구현·프로그래밍 | 코드로 동작을 만든다 | SW 전반, RTL, 펌웨어 |
| `FIELD` 현장·설비 | 설비가 있는 데서 돌아가게 한다 | 생산기술, 장비, 전력 |
| `OPTIMIZE` 개선·효율 | 있는 걸 더 낫게 만든다 | 품질, 수율, SRE |
| `RESEARCH` 탐구·이론 | 원리를 파고든다 | R&D, 소자, ML |
| `ORCHESTRATE` 조율·관리 | 사람·일정을 맞춘다 | PM, 품질보증, 생산관리 |

### 1-2. 업무 성향 6축 (기존 유지)

독립 · 협력 · 도전 · 안정 · 속도중시 · 품질중시.
기존 PCA 결과지의 육각형을 그대로 쓴다. **바꾸면 기존 응시자와 비교가 끊긴다.**

### 1-3. 선호 (산업·지역·기업형태)

점수가 아니라 **선택**이다. 매칭 산식의 P 항으로 들어간다.

### 1-4. 역량 자기평가

`questions.competency_id` 가 붙은 문항. "ANSYS 를 어느 정도 다루나" 를 직접 묻는다.
**신뢰도 0.5 로 가장 낮게 가중한다** — 자기보고이기 때문이다.
과목·자격이 있으면 그쪽이 이긴다.

## 2. 기존 문항으로 되는 것과 안 되는 것

### 2-1. 빈 곳은 하나다 — 공학 직무를 가르는 축

| 기존 PCA 가 재는 것 | ECI 에서 쓸 수 있나 |
|---|---|
| 업무 성향 6축 (독립·협력·도전·안정·속도중시·품질중시) | ✅ **그대로 쓴다.** 육각형도 결과지에 유지 |
| 직무 영역 10개 (경영·전략 … 컨설팅) | ✅ 전 학과 공통 층으로 유지 |
| 직무 흥미 | ✅ 선호(P 항)의 일부로 쓴다 |
| **공학 활동 선호 8축** | ❌ **없다** |

**왜 이게 문제인가.** 직무 영역 10개는 경영·인사·재무 쪽에 무게가 실려 있고,
공학에 닿는 건 「생산·운영관리」와 「IT·데이터」 둘뿐이다.
그런데 우리가 가려야 하는 건 **기계공학 안에서 8개 직무**다.

```
"협력형 · 품질중시형 · 생산운영관리 적합"
   → 이 학생은 CAE 인가 생산기술인가 품질인가?
   → 기존 축으로는 셋이 전부 똑같이 나온다
```

CAE 와 생산기술을 가르는 건 협력이냐 독립이냐가 아니라
**해석·계산을 즐기느냐 현장·설비를 즐기느냐**다. 그 축이 지금 없다.

### 2-2. 그래서 추가할 최소량 — 48문항

전부 새로 쓰는 게 아니라 **비는 축만 채운다.**

| 추가 | 문항 수 | 왜 이만큼인가 |
|---|---|---|
| 공학 활동 선호 8축 | **48** (축당 6, 역채점 2 포함) | 5문항 아래면 내적 일관성(α) 0.7 을 못 넘긴다. 6이 실무 하한 |
| 역량 자기평가 (전공별) | 9 | 성향이 아니라 보유 역량. 전공마다 다른 문항이 나간다 |
| 주의 확인 | 3 | 기존 문항에 있으면 추가하지 않는다 |
| 산업·지역 선호 | 12 | 점수 문항이 아니다. 선택지만 만들면 된다 |

**실제 집필이 필요한 건 48문항뿐이다.** 나머지 24개는 문항이라기보다 선택지 목록이다.
이 문서 3장에 그중 16개 초안을 이미 써 두었다.

### 2-3. 합쳐진 검사지

```
대학판 UNIV_V1 = 기존 PCA 문항 (N) + 48 + 24
고교판 HS_V1   = 기존 문항 중 고교에 맞는 것 + 48 (고교 어휘판) + 21
```

`N` 은 기존 문항 수라 지금 알 수 없다. **응시 시간 35분을 넘지 않게 맞추는 것이 기준이다.**
기존 문항이 100개를 넘으면 공학 축을 축당 6 → 5로 줄인다 (40문항).

### 2-4. 기존 문항을 넣을 때 지키는 것

**기존 문항을 한 글자도 고치지 않는다** (설계 원칙 4).
`questions` 테이블에 그대로 행으로 넣고, 컬럼 하나만 매단다.

```sql
-- 기존 문항은 내용 그대로, axis_code 만 붙인다
UPDATE questions SET axis_code = 'COLLAB' WHERE id = ...;
```

`indicator_axes` 에 `INDEP`·`COLLAB`·`CHALLENGE`·`STABLE`·`SPEED`·`QUALITY` 가 이미 시드돼 있다.
기존 문항이 어느 축인지만 연결하면 **그 순간부터 ECI 산식이 기존 문항으로 돌아간다.**

기존 문항 + 추가 48문항을 묶은 것은 **새 버전**이다 (`instruments.version`).
기존 버전은 그대로 두고 은퇴시킨다. 작년 응시자의 결과는 바뀌지 않는다.

### 2-5. 넘겨받아야 하는 것

이 세 가지가 있으면 바로 이식한다.

| 필요한 것 | 없으면 |
|---|---|
| **문항 원문** (엑셀·워드 무엇이든) | 이식 자체가 안 된다 |
| **채점 키** — 문항별 축, 역채점 여부, 배점 | 문항은 있는데 점수가 안 나온다 |
| 기존 응시 데이터 (있으면) | 규준을 처음부터 다시 모아야 한다. 있으면 첫날부터 T점수가 나온다 |

**채점 키가 제일 중요하다.** 문항만 있고 키가 없으면 결국 축을 다시 짜야 한다.

### 2-6. 만약 한 문항도 추가할 수 없다면

가능은 하다. 대신 **대가를 알고 결정해야 한다.**

| | 48문항 추가 | 기존 문항만 |
|---|---|---|
| 집필·검수 | 1.5주 | 0 |
| 직무 변별 | 8개 직무가 갈린다 | **3~4개 덩어리로만 갈린다** |
| 저학년(1–2학년) | 성향으로 방향을 잡아준다 | **결과가 거의 안 나온다.** 증거가 없어서 |
| 고학년·졸업예정 | 잘 나온다 | 잘 나온다 (S 항이 증거로 굴러가므로) |

대안은 `scoring_profiles` 에서 `wA` 를 낮추고 `wS` 를 올리는 것이다
(예: `UNIV_HIGH` 0.30/0.40 → 0.15/0.55). 산식은 데이터라 **코드를 안 고치고 바꿀 수 있다.**
다만 저학년은 과목·프로젝트가 아직 없어서 이 방법이 안 통한다.

> **판단** — 48문항은 기존 자산을 버리는 게 아니라 **모자란 한 축만 메우는 값**이다.
> 1.5주에 8개 직무 변별을 얻는 거래라 하는 게 맞다.

### 2-7. 참고 — 기존 문항을 못 쓰게 될 경우의 전량 신규안

기존 문항을 못 쓰게 될 때만 쓰는 안이다. **1안은 위의 재사용안이다.**

| 구분 | 대학판 | 고교판 |
|---|---|---|
| 공학 활동 선호 | 64 (축당 8) | 48 (축당 6) |
| 업무 성향 | 36 (축당 6) | 24 (축당 4) |
| 양자택일 | 12 | — |
| 관심 대상 선택 | — | 12 |
| 산업·근무 선호 | 16 | 9 |
| 역량 자기평가 | 9 | — |
| 주의 확인 | 3 | 3 |
| **합계** | **140** · 약 26분 | **96** · 약 18분 |

**성적을 묻지 않는다.** 고1 성적으로 공학 적합을 판정하면 결과지가 성적표의 재탕이 되고,
학교가 사지 않는다. 취업형(`goal=job`)은 여기에 **이수한 NCS 능력단위와 자격증**을 추가로 받는다
— 성적이 아니라 증거다.

### 2-8. 무료 간이판 `LITE_V1` — 12문항 · 약 3분

두 안 어느 쪽이든 똑같이 필요하다. B2C 입구다.

B2C 입구. 활동 8축에서 각 1문항 + 양자택일 4문항.
**정밀도가 낮으므로 1위 직무만 보여주고 점수는 안 보여준다.**
12문항으로 뽑은 순위에 점수를 찍으면 그건 거짓말이다.

## 3. 실제 문항 (예시 30개)

**이 중 업무 성향 6문항은 기존 PCA 문항으로 교체된다.** 여기 쓴 건 초안일 뿐이다.
실제로 필요한 건 **공학 활동 8축 문항 48개**이고, 그중 16개가 아래에 있다.

### 공학 활동 선호 — 대학판

| # | 축 | 문항 | 역채점 |
|---|---|---|---|
| 1 | ANALYZE | 답이 맞는지 확인하려고 같은 계산을 다른 방법으로 다시 해 본 적이 있다 | |
| 2 | ANALYZE | 실험 결과가 이론값과 다르면, 원인을 끝까지 찾아야 마음이 편하다 | |
| 3 | ANALYZE | 수식을 세우는 것보다 일단 만들어 보는 편이 낫다고 생각한다 | ● |
| 4 | DESIGN | 조건이 여러 개 겹칠 때, 그걸 다 만족시키는 형태를 궁리하는 게 재미있다 | |
| 5 | DESIGN | 남이 만든 물건을 보면 "왜 이렇게 생겼을까" 를 먼저 생각한다 | |
| 6 | BUILD | 도면만 보는 것보다 실물을 만져 봐야 이해된다 | |
| 7 | BUILD | 장비를 처음 다룰 때 설명서보다 직접 눌러 보며 익힌다 | |
| 8 | CODE | 반복되는 작업이 있으면 자동화할 방법부터 찾는다 | |
| 9 | CODE | 코드를 짜는 것보다 결과를 해석하는 쪽이 더 끌린다 | ● |
| 10 | FIELD | 공장이나 실험실처럼 장비가 돌아가는 공간에서 일하고 싶다 | |
| 11 | FIELD | 예상 못 한 문제가 현장에서 터졌을 때 오히려 집중이 잘 된다 | |
| 12 | OPTIMIZE | 이미 돌아가는 것을 더 빠르거나 싸게 만드는 일에 보람을 느낀다 | |
| 13 | OPTIMIZE | 낭비되는 시간이나 재료가 보이면 그냥 못 지나친다 | |
| 14 | RESEARCH | 당장 쓸모없어 보여도 원리가 궁금하면 찾아본다 | |
| 15 | RESEARCH | 논문이나 기술 문서를 읽는 것이 부담스럽지 않다 | |
| 16 | ORCHESTRATE | 팀에서 일정과 역할을 정리하는 역할을 자주 맡는다 | |

### 업무 성향 — **기존 PCA 문항으로 교체될 자리** (아래는 초안)

| # | 축 | 문항 | 역채점 |
|---|---|---|---|
| 17 | INDEP | 혼자 집중할 시간이 확보돼야 일이 잘 된다 | |
| 18 | COLLAB | 막히면 혼자 붙들기보다 먼저 물어본다 | |
| 19 | CHALLENGE | 해 본 적 없는 방식이라도 더 나아 보이면 시도한다 | |
| 20 | STABLE | 절차가 정해져 있는 일이 마음이 편하다 | |
| 21 | SPEED | 완벽하지 않아도 기한 안에 내는 쪽을 택한다 | |

21번과 22번은 서로 반대다. **둘 다 높게 답하면 응답 일관성 경고가 뜬다.**

### 양자택일 (중앙 쏠림 보정)

| # | A | B |
|---|---|---|
| 23 | 설계도를 그린다 | 만들어진 것을 시험한다 |

| 26 | 혼자 깊게 판다 | 여럿이 넓게 본다 |

### 역량 자기평가 (전공별) — 기계공학 예시

| # | 대상 역량 | 문항 |
|---|---|---|
| 27 | `SW.SOLIDWORKS` | SolidWorks 로 부품과 조립체를 직접 모델링할 수 있다 (0=써 본 적 없다 ~ 5=실무 수준) |
| 28 | `SW.ANSYS_MECH` | ANSYS 로 구조해석을 돌리고 결과를 해석할 수 있다 |
| 29 | `ME.GDT` | 도면의 기하공차 기호를 보고 의미를 설명할 수 있다 |

### 고교판 — 같은 축을 다른 말로

| # | 축 | 대학판 | 고교판 |
|---|---|---|---|
| 30 | ANALYZE | 실험 결과가 이론값과 다르면 원인을 끝까지 찾는다 | 실험 결과가 예상과 다르게 나오면 왜 그런지 알아내고 싶다 |
| — | CODE | 반복 작업을 자동화할 방법부터 찾는다 | 같은 걸 여러 번 해야 하면 더 편한 방법이 없나 찾아본다 |
| — | FIELD | 장비가 돌아가는 공간에서 일하고 싶다 | 기계나 장비가 실제로 움직이는 걸 보는 게 재미있다 |

**축은 같고 말만 바꾼다.** 그래야 고1 결과와 대학 3학년 결과를 같은 자로 비교할 수 있다.
`indicator_axes` 가 검사 버전을 건너뛰어 고정되는 이유다.

## 4. 응답 품질 — 못 믿을 응답을 골라낸다

500명이 단체로 보면 **성의 없는 응답이 반드시 섞인다.** 이걸 못 거르면
학과 리포트의 집계가 오염되고, 그 리포트로 계약을 갱신할 수 없다.

`attempt_quality` 에 네 가지를 남긴다.

| 지표 | 판정 | 임계 |
|---|---|---|
| `straightline_run` | 같은 보기를 연속으로 고른 최대 횟수 | 15 이상이면 경고 |
| `fast_ratio` | 1.5초 미만 응답 비율 | 0.25 이상이면 경고 |
| `attention_pass` | 주의 확인 문항 통과 수 | 3개 중 2개 미만이면 경고 |
| `evidence_fill` | 증거 충실도 (과목·프로젝트를 얼마나 채웠나) | 낮으면 구간을 넓힌다 |

**중요 — 신뢰도로 점수를 깎지 않는다.**

깎으면 학생 간 비교가 깨진다. 대신 **결과지의 구간 폭(`band_width`)을 넓힌다.**

```
증거 충실   82 (±4)   ← 과목·프로젝트·자격이 다 있다
증거 부족   82 (±12)  ← 검사 응답만 있다
```

같은 82점인데 하나는 신뢰할 만하고 하나는 아니라는 걸 **화면이 정직하게 말한다.**
경고가 뜬 응시는 학과 리포트 집계에서 빼고, 그 사실을 리포트에 적는다
("487명 중 12명 제외 — 응답 품질").

## 5. 규준 — 점수를 무엇과 비교하나

원점수는 의미가 없다. "설계 성향 4.2점" 이 높은 건지 낮은 건지 알 수 없다.

```
raw   → 문항 수로 정규화 → 0~100
      → 규준집단 대비 z  → T = 50 + 10z  (20~80 절단)
```

규준집단(`norm_groups`)은 **트랙 · 전공 · 학년 · 국가** 넷으로만 나눈다.

**성별과 출신 학교를 넣지 않는다.** 넣으면 "여학생 기준으로 상위 20%" 같은 값이 나오고,
그건 차별이면서 동시에 쓸모도 없다 — 학생이 취업할 시장은 성별로 나뉘어 있지 않다.

초기에는 규준이 없다. 100명 검증 전까지는 **전문가 설정 기준점**을 쓰고,
`norm_groups.n_size` 가 200을 넘으면 실측 규준으로 자동 교체한다.
결과지에는 그때까지 "잠정 기준" 이라고 적는다.

## 6. 문항을 고칠 때

**절대로 기존 문항을 수정하지 않는다** (기존 설계 원칙 4).

```
v1.0 published  ─→  응시자 500명의 결과가 여기 묶여 있다
v1.1 draft      ─→  문항 12개 교체
     published  ─→  이후 응시자만 여기로
```

작년 응시자의 결과가 올해 문항 수정으로 바뀌면, 학과가 작년 리포트를 못 믿게 된다.
축(`indicator_axes`)만 버전을 건너뛰어 유지되므로 **비교는 계속 가능하다.**
