## 0. 확인된 요구사항과 제안을 가른다

진흥원과의 계약 요구사항은 아직 확정되지 않았다. 그래서 이 문서는 아래 두 종류를 섞지 않는다.

**확인된 요구사항** (사업주 지시. 2026-10-20 세션)
- 세 가지가 이어지는 서비스여야 한다: 사용자 플랫폼(검사·Evidence·결과), 관리자 페이지(사용자·검사·운영·성과),
  개인별 PDF(실제 결과 + 기관 콘텐츠). 흐름은 검사 → 분석 → PDF → 사용자 확인 → 관리자 현황 반영이다.
- 공통 엔진을 재사용한다. 기관별로 갈라 두는 것은 설정·검사 버전·산업·기업 콘텐츠·PDF 템플릿·관리자 권한 여섯이다.
- 지역 범위
  - 세종특별자치시가 핵심이다. 사업장 소재지를 기준으로 하고, 본사와 사업장을 가른다.
  - 대전·충남·충북은 통근과 취업 연계가 있는 경우에만 보조로 다룬다.
  - 지원사업에 지역 제한 조건이 있으면 그 조건을 우선한다.
- **채용 중인지 확인되지 않은 기업을 채용 기업으로 표시하지 않는다.**
- 보존해야 할 것: 측정·채점·taxonomy·DB 계약과 R35 안정화 상태.
- 금지된 것
  - 공통 엔진 변경, 운영 PDF 연결, Production 배포
  - 배재대·전주대·본체 가지 수정
  - 기존 가지 삭제와 강제 푸시
- 배재대 납품 작업이 우선한다.

**저장소 규칙에서 오는 제약** (CLAUDE.md)
- 직업정보제공사업 신고(J1700020220007)만 있다.
  - 알선을 하지 않는다. 이력서 발송 대행과 추천서도 금지다.
  - "추천 기업"이라는 말을 쓰지 않는다.
- 점수는 산식이 만들고 문장은 따로 쓴다.
  - 경험(Evidence)은 적합도에 들어가지 않는다.
  - ME_V3 는 총점을 만들지 않는다.
- 집계에서 다섯 명 미만인 칸은 보여 주지 않는다.
- 지역정주 취업률이나 실제 취업 성과를 플랫폼이 산출한다고 쓰지 않는다.

**제안** — 아래 본문에서 `[제안]` 으로 표시한 것 전부. 진흥원 확인을 거쳐야 한다.

## 1. 대상자와 검사 형태

| 대상 | 진입 기준 | Core 고르는 법 | 지금 엔진으로 가능한가 |
|---|---|---|---|
| 청년 재학·졸업예정자 | 전공이 있다 | 전공명 → `major-cores.json` 별칭 → Core | 가능. 대학 학생과 같은 경로 (`audience=student`) |
| 청년 미취업 졸업자 | 전공이 있다, 경험이 있다 | 위와 같음 + 경험 입력 비중을 키움 | 가능. 다만 단계값이 `bachelor` 로 적힌다 → **CR-2 필요** |
| 일반 구직자 (고졸·비전공) | 희망 직무가 있다 | 희망 직무 영역 → Core | **CR-2 전에는 불가.** 문항·경험 어휘가 학업 장면이다 |
| 경력 전환·신중년 | 경력이 있다 | 희망 직무 영역 → Core, 경력 경험(`kind=work`) 먼저 | **CR-2 전에는 불가.** 경험 저장 구조는 이미 맞다 |

`[제안]` 검사 경험
- **처음 묻는 것은 셋이다**
  - 대상 구분
  - 희망 직무 영역
  - 희망 근무 지역 범위: 세종만 / 대전·충남·충북까지 / 무관 / 아직 모름. 기존 `move_ranges` 와 같은 코드를 쓴다
  
  이 셋은 Core 선택과 PDF 기업 장의 범위만 정한다. **판정에는 들어가지 않는다.**
- **등급** — 기관 응시는 대학처럼 PRO 로 고정하는 방안과, STANDARD 로 시간을 줄이는 방안이 있다.
  학교 진입은 늘 PRO 라는 결정(CLAUDE.md 2026-10-13)이 있어서 같은 원칙을 권한다. 진흥원과 정할 것이다.
- **경험 먼저(경력자)** — 검사 전에 경력 한두 건을 적게 하는 순서는 검사 화면 동결(`v3:freeze`)을 건드린다.
  그래서 동결 안에서는 지금 순서(검사 → 경험)를 유지하고, 입장 화면 안내 문구로만 유도한다.
- **열 수 있는 Core** — 지금 학생에게 열린 Core 는 `BIZ_CORE_V1` 하나다.
  세종 산업 구조에 맞는 후보(공공행정 `PUBADM`, 컴퓨터 `CS`, 보건 `HEALTH`, 바이오 `BT`, 식품 `FOOD`, 전기전자 `EE`)는
  모두 `building` 이다. **어느 Core 를 언제 여는가는 본체 결정이다.**

## 3. 세종 산업·기업 콘텐츠

### 3-1. 원칙
- **사업장 소재지가 기준이다.** 본사(`hq`)와 세종 사업장(`sejong_sites[]`)을 따로 적는다.
  `location_basis` 는 세 값 중 하나다.
  - `HQ_IN_SEJONG`
  - `SITE_IN_SEJONG_HQ_ELSEWHERE`
  - `UNCONFIRMED`: 결과지에 내지 않는다
- **채용 여부는 확인하지 않는다.** `hiring.status = "UNVERIFIED"` 를 고정한다.
  - 화면에 "채용 중"을 쓰지 않는다.
  - 원 출처 링크와 고지 문구를 붙인다.
- **추천하지 않는다.** 표현은 "탐색해 볼 기업·기관"으로 쓴다. 적합도 숫자를 쓰지 않는다(Gold Master 규칙과 같다).
- **출처와 검증 상태를 줄마다 적는다.**

  | 검증 상태 | 뜻 | 결과지에 내는가 |
  |---|---|---|
  | `OFFICIAL_CROSSCHECKED` | 공식 출처 둘 이상이 일치한다 | 낸다 |
  | `OFFICIAL_SINGLE` | 공식 출처가 하나다 | 낸다 |
  | `SECONDARY_ONLY` | 2차 출처만 있다 | 내지 않는다 |
  | `CONFLICTING` | 출처끼리 다르다 | 내지 않는다 |
  | `UNREACHABLE` | 출처에 닿지 못했다 | 내지 않는다 |
- **보조 권역**(대전·충남·충북)은 따로 묶는다. 통근권 안내와 함께 낸다.
  지원사업에 지역 제한이 있으면 그 사업 참여자에게는 보조 권역 장을 끈다.
- 재무·신용 같은 제3자 유료 자료를 옮겨 적지 않는다.

### 3-2. `region-layer.json` 과의 관계
- `region-layer.json` 은 **고치지 않는다.** 이 파일은 "기업 이름을 담지 않는" 집계 계약으로 남는다.
- 세종 기업 자료는 **테넌트 콘텐츠 층**에 따로 둔다(CR-4). 법률 확인 전까지 PREVIEW_ONLY 다.
- 지금 위치는 `docs/sejong/data/sejong-orgs.preview.json` 이다. 앱이 읽지 않는 자리다.
  CR-4 가 받아들여지면 `sites/pca-platform/content/tenants/<code>/orgs.json` 으로 옮긴다.

### 3-3. 1차 조사 결과
자세한 것은 `docs/sejong/data/README.md` 에 있다.

- 35곳: 민간 15, 국책연구기관 14, 지방 공기업·출연기관 5, 공공기관 1.
- 검증 상태(검색 발췌 기준): 공식 교차확인 12, 공식 단일 20, 2차 출처만 2, 불일치 1.
- **공식 원문을 직접 열지 못했다**(프록시 거절). 그래서 35줄 모두 `display_ready: false` 다.
- 결과지 후보에서 빼는 곳
  - 세종 사업장이 없는 1곳
  - 계획 보도뿐인 2곳
  - 주소가 불일치하는 1곳
  - 본사 소재지를 확인하지 못한 2곳
- 세종 산업은 세 덩어리로 나뉜다.
  - 공공행정·정책연구: 세종국책연구단지, 정부세종청사
  - 소재·부품·화학·이차전지: 명학·전의·부강 산업단지
  - 바이오·제약·식품·화장품: 전의·전동 산업단지
  
  이 구성은 Core 우선순위(PUBADM, CHE/MSE, BT/HEALTH/FOOD)를 정할 때 근거가 된다. Core 를 여는 결정은 본체가 한다.

### 3-4. 앞으로 쓸 공식 출처 `[제안]`

| 목적 | 출처 | 비고 |
|---|---|---|
| 상장·외감 법인의 본점·사업장 | OpenDART 기업개황·사업보고서 | 본체 가지가 이미 OpenDART 대조를 시작했다(`3c67c09d`) |
| 공공기관·출연연 소재지 | ALIO 기관 정보, 경제·인문사회연구회 | 세종 국책연구단지 |
| 산업단지 입주 기업 | 한국산업단지공단 공장 등록 정보(팩토리온), 세종시 산업단지 현황 | 사업장 주소가 바로 나온다 |
| 지역 산업 구조 | 통계청 전국사업체조사(KOSIS), 세종시 통계 | 업종별 사업체·종사자 수. 기업 이름 없이 집계로만 |
| 실제 채용 여부 | 고용24(워크넷) 채용정보 Open API | **표시는 하지 않고**, 원 공고로 가는 링크만. 이용약관·저작권을 먼저 따진다 |
| 진흥원 지원사업 | 진흥원 공식 누리집·공고 | 사업명·지역 제한은 진흥원이 준 자료가 기준이다 |

## 4. 개인별 취업 전략 PDF

`[제안]` Gold Master 13장 구조(`render3.ts` `chaptersOf`)를 기관용으로 고른다. 장마다 데이터 원천을 함께 적는다.

| # | 장 | 원천 | 비고 |
|---|---|---|---|
| 1 | 표지 | 테넌트 브랜드, 참여자 이름, 사업명, 응시일 | 진흥원 로고는 받은 파일만 쓴다(다시 그리지 않는다) |
| 2 | 한눈에 보기 | `result_model` 요약 | 총점·순위 없음 |
| 3 | 역량 프로파일 | 축 상태·영역 묶음 | 판정 그대로 |
| 4 | 경험과 경력 근거 | `v3_experiences`(경력 포함), 교차 대조 | 경험은 판정을 올릴 뿐 점수를 만들지 않는다 |
| 5 | 강점 활용 / 채울 것 | `result_model` | |
| 6 | 희망 직무의 실제 업무 | Core 역할 팩 | |
| 7 | 세종 산업 환경 | 테넌트 `region-profile.json`, 집계 통계 | 출처·기준 연도 필수 |
| 8 | 세종 사업장 기업·기관 탐색 | 테넌트 `orgs.json` (`verify ≥ OFFICIAL_SINGLE`) | **채용 미확인 고지**, 정보 제공 고지, 원 출처 링크 |
| 9 | 보조 권역 탐색 | 같은 자료의 보조 권역 줄 | 희망 범위가 "세종만"이면 끈다 |
| 10 | 지원서·면접 준비 | 결과 + 경험 | |
| 11 | 진흥원 지원사업 안내 | 진흥원 제공 사업 목록 | **진흥원 확정 전 비움** |

- PDF 는 **굳힌 결과 모델과 같은 값**을 읽는다. 웹 결과와 종이가 갈리지 않게 하기 위해서다(현행 원칙).
- 운영 PDF 경로 연결은 **승인 전 금지**다. 세종 템플릿은 고정자료로만 렌더한다.

## 5. 관리자 대시보드와 사업성과

`[제안]` 지표를 셋으로 나눈다. 플랫폼이 낼 수 있는 것과 낼 수 없는 것을 섞지 않는다.

| 층 | 지표 | 원천 | 플랫폼이 산출하는가 |
|---|---|---|---|
| 운영 | 발급 → 첫 로그인 → 검사 시작 → 완료 → 결과 공개 → PDF 생성 → PDF 열람 | `tenant_participants`, `v3_attempts`, `v3_report_releases`, `v3_report_renders` | 예 |
| 과정 성과 | 세종 취업 희망 전후 변화, 지역 기업 인지 전후 변화, 만족도, 실행 계획 수립 수, 경험 기록 수 | CR-3 설문, `v3_actions`, `v3_experiences` | 예. 본인 응답과 활동 기록 |
| 결과 성과 | 취업 여부, 세종 내 취업, 유지 취업 | 진흥원 행정 자료 또는 추적 설문 | **아니오.** 플랫폼은 본인 응답 추적만 받는다. 확정 수치는 진흥원 자료 |

- 모든 집계는 n<5 칸을 가린다(`organizations.aggregate_min_cell`).
- 개인 순위표를 만들지 않는다.
- 사업·회차·대상 구분·기간으로 나눠 볼 수 있게 한다.

## 8. 검증 환경

2026-10-20 에 GitHub deployments API 로 확인한 사실이다.
- **Staging 은 있다.**
  - Railway 프로젝트 `feisty-generosity` 의 `staging` 환경이다.
  - 주소는 `https://charming-reverence-staging.up.railway.app` 다(R34·R35 문서).
  - CareerMatri 작업 가지(`claude/careermatri-screen-review-p0c8kb`)를 커밋마다 자동 배포한다.
  - `0bff307c` 배포는 05:46Z 에 `success` 였다. `3c67c09d` 는 06:32Z 에 `in_progress` 였다.
- **Production** 은 `claude/amazing-thompson-w3f2o2` @ `02b6c610` 이다. 2026-10-19 02:04Z 에 `success` 였다.
- 이 컨테이너는 두 주소 모두 열지 못한다. 프록시가 CONNECT 403 을 낸다. 그래서 화면과 DB 를 직접 확인하지 못했다.

그 전까지 검증은 로컬 PostgreSQL 과 고정자료로만 한다.
