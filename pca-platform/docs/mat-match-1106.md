# MAT 공고 맞춤 고침 (2026-11-06)

브랜치 `work/mat-match`, 528b0277 에서 시작. 운영 배포 · 운영 DB 는 건드리지 않았다.

## 무엇이 문제였나

전주대 인공지능학과(`JJU26_AI`, 11/03 부터 `AI_CORE_V1` / `SPEC_AI_DATA`) 학생의 MAT 공고 화면에 인공지능과 무관한 공고가 섞이고,
맞는 공고는 1건뿐이었다. 학과 → Core · 갈래 → 공고 분야 → 공고로 가는 길을 따라가 보니 원인이 다섯 가지였다.

1. **전공 사전에 인공지능이 없다.** `mat-terms.json` 에 Core 20개가 있고 `AI_CORE_V1` 은 없다. 제목에서 전공 낱말을 찾는
   `matchDomains` 가 인공지능학과에는 아무것도 돌려주지 않아, 제목에 `인공지능` 이 그대로 적힌 공고 1건만 맞춤이 됐다.
2. **다른 Core 의 별칭이 맞춤 글에 섞였다.** 모을 때(`mapPosting`) 단 `role_code` 는 그 공고를 맞춘 Core 의 별칭이다. 이것을
   제목과 붙여 읽어서, 다른 전공 쪽으로 단 별칭이 이 전공 낱말처럼 걸렸다.
3. **두 글자 낱말이 말 속에서 걸렸다.** `부품사` 의 `품사`(국어국문), `기술기획` 의 `술기` 처럼.
4. **게시판 분류를 보지 않았다.** 잡인더스트리 게시판(430 · 439 · 486 · 487 · 488)은 공고마다 분류(`IT/AI/빅데이터/블록체인`,
   `기계/모빌리티/로봇/조선` 등 10가지)를 단다. 이것을 보지 않아 다른 산업 공고의 흔한 말(진동 · 음향 시험의 `음향`,
   바이오 회사의 `생산관리`, `R&D`, `시설관리`, `통계 분석`)로 엉뚱한 학과에 맞췄다.
5. **기관 이름 속 낱말로 행정 일자리를 맞췄다.** `한국생산기술연구원 … 행정원` 의 `생산기술` 로 공학 학과에 섰다.
   커리어피크의 `2026년 하반기 정규직 채용` 처럼 분야를 적지 않은 공고는 아무 학과에도 서지 못했다.

고정 견본(공고 112건)으로 네 기관 210개 학과를 재 보니 맞춤 971건 가운데 518건(53%)이 그 학과와 무관한 공고였다.

## 고친 것

- `src/lib/mat/job-fit.ts`(새 파일): 학과의 Core · 갈래 · 학과 자리로 분야어 묶음을 만들고, 공고의 **제목 · 모집 분야**에
  그 낱말이 걸리는지로 맞춤을 정한다. 본문에만 나온 낱말은 차례만 조금 올린다.
  - 공고 분류(게시판 분류 칸, 없으면 기관 이름)를 묶음으로 바꾸고, 그 묶음을 가진 다른 전공의 낱말이면 이 전공 공고로 치지 않는다.
  - 한글 두 글자 낱말은 낱말 첫머리에서만 걸린다. 로마자 약어(`AI` · `SW`)는 낱말 경계로 잰다.
  - 제목 앞의 해 · 공공기관 이름은 떼고 읽는다.
  - 공학 · 보건 계열 학생에게는 행정 · 사무 · 시설 관리 일자리를 세우지 않는다(경영 · 행정 계열에게는 그대로 선다).
- `sites/pca-platform/content/mat-job-fields.json`(새 파일): 위 규칙이 읽는 표. 분류 → 묶음, 기관 → 묶음, 묶음 산업의 직무 말,
  흔한 말, Core 마다의 분야어(필수급 `strong` · 둘이 걸려야 하는 `weak` · 짝으로만 세는 `pair`).
  - `AI_CORE_V1` 분야어: 인공지능 · 머신러닝 · 딥러닝 · LLM · 컴퓨터 비전 · 머신비전 · 데이터 분석 · 빅데이터 · 온톨로지 · GPU 등.
  - 피지컬 AI 갈래(`SPEC_AI_PHYSICAL`)와 전주대 AI 부트캠프(`JJU26_BOOTCAMP_AI`)는 기계 · 전기 묶음을 더하고, 로봇 · 휴머노이드 ·
    자율주행 · 위치추정 · 머신비전 · 자동화 공고를 맞춤 안에서 위로 올린다.
  - `SPEC_CS_AI`(전주대 인공지능학과의 11/03 전 응시 · 학교 계정 줄, 그리고 AI 부트캠프)는 인공지능 분야어를 더 읽는다.
    그래서 인공지능학과 학생이 `AI_CORE_V1` / `SPEC_AI_DATA` 로 읽히든 옛 `CS_CORE_V1` / `SPEC_CS_AI` 로 읽히든 인공지능 공고가 위에 선다.
- `src/lib/mat/pick-jobs.ts`: `rankJobs` 가 `job-fit` 으로 맞춤을 정한다. 무관한 공고는 보이지 않는다. 갈래 · 학과 자리는
  마지막 응시가 같은 Core 이면 그 응시에서, 아니면 학교 계정(`campus_students`)에서 읽는다. 공고 표의 `모집분야`
  (`posting_fields`)와 커리어피크 직군(`job_family`)을 함께 읽는다.
- `scripts/mat-jobs-coverage.ts`: 같은 규칙으로 센다.
- `src/lib/assistant/rules.ts`: 전공 사전 낱말을 꺼내는 `dictTerms` 하나를 더했다. 공고를 읽는 규칙(`matchDomains`)은 그대로다.
- 석박사 공고 맞춤 화면: 점수 옆 `맞은 낱말` → **`겹친 분야어`**(영어 `Overlapping field terms`). 같은 말을 쓰는 곳도 맞췄다:
  입력 칸 `분야어(쉼표로 나눔)`, 빈 화면 안내, MAT 공고 카드 칩 묶음 이름(`겹친 분야어`), MAT 질문 문맥, 연구 이력 AI 입력 줄, 주석.

**DB 구조 변경은 필요 없다.** `posting_fields` · `job_family` 는 `db/schema_jobs_meta.sql` 에 이미 있는 칸이고, 칸이 없는 DB 에서는
빈 값으로 읽는다.

## 점검 명령

```
npm run mat:match                       # 고정 견본(scripts/fixtures/mat-match-postings.json)으로
MAT_MATCH_SHOW=JJU26_AI npm run mat:match  # 그 학과의 맞춤 · 무관 · 놓친 공고를 다 적는다
MAT_MATCH_DB=1 npm run mat:match        # 로컬 DB 공고로(무관 판정 없이 수만)
```

"이 공고가 맞는 전공"(`fit`)이 있고, 학과가 그 전공이 아닌 공고를 맞춤으로 세우면 무관으로 센다. 다음이면 실패로 끝난다:
인공지능학과 위 10건에 무관 공고가 있음 · 인공지능학과 맞춤 5건 미만 · 인공지능학과를 네 가지 Core / 갈래 짝
(`AI_CORE_V1`/`SPEC_AI_DATA` · `AI_CORE_V1`/`SPEC_CS_AI` · `CS_CORE_V1`/`SPEC_CS_AI` · 갈래 없음)으로 읽었을 때 위 10건에
무관 공고가 있거나 인공지능 공고가 5건 미만 · AI 부트캠프 위 5건에 로봇 · 자동화 공고가 없음 · 전체 무관 비율 10% 초과.

견본의 경영 · 행정 공고 8건은 처음에 경영학과(`BIZ`)만 맞는 전공으로 적었다가 행정학(`PUBADM`)도 맞는 것으로 넓혔다(연구행정 ·
사업 행정 공고). 아래 "전" 숫자도 넓힌 견본으로 다시 쟀다.

## 확인하지 못한 것

- 운영 DB 의 실제 공고로 돌려 보지 않았다(금지). 로컬 임시 DB(`127.0.0.1:55432`, 지어낸 자료)에서는 새 SQL(`모집분야` · `job_family`
  칸, 갈래 · 학과 자리 읽기)과 `pickJobs` 가 오류 없이 도는 것만 봤다. 그 DB 에는 공고가 0건이라 맞춤 수는 견본으로만 쟀다.
- 분야어 표는 사람이 검토하지 않았다. 견본에 없는 산업 공고에서는 새로 틀릴 수 있다.
- 이미 모아 둔 공고의 `core_code` · `role_code` 는 다시 모을 때까지 그대로다(지금은 맞춤에 쓰지 않고, 맞춤이 0건일 때 서는
  "넓힌 공고" 에만 쓴다).
- 어문 · 법 · 심리 · 교육 · 미디어 학과는 잡인더스트리 공학 · 연구 게시판에 맞는 공고가 거의 없어 빈 화면이 선다.
- 브라우저로 화면을 열어 보지 않았다.
- 인공지능 검사 작업자가 `mat-terms.json` 에 `AI_CORE_V1` 을 넣으면 그 사전 이름도 `strong` 분야어로 함께 읽힌다(겹쳐도 맞춤이
  넓어질 뿐 규칙은 같다). 넣은 뒤 `npm run mat:match` 를 다시 돌려야 한다.
