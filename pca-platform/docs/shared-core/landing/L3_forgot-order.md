## 왜

로그인(`auth.ts`)은 아이디가 같은 줄을 먼저 고른다. 비밀번호 찾기는 같은 조건에 **차례 없이** `LIMIT 1` 이다.
한 사람(A)의 아이디가 다른 사람(B)의 이메일과 같은 글자이면:

| 쌓인 차례 | 로그인이 고르는 계정 | 찾기가 고르는 계정 |
|---|---|---|
| B 먼저 | A | **B** |
| A 먼저 | A | A |

(`evidence/R40/gate/current-l3-forgot.log` 의 `# L3-REPRO-1` 줄 · 일회용 PostgreSQL)

A 가 자기 아이디로 재설정을 누르면 링크가 B 의 계정으로 만들어져 B 의 메일로 간다. **A 는 재설정을 못 하고, B 는
요청하지 않은 메일을 받는다.** 남의 계정을 여는 길은 아니다(링크는 B 의 계정을 연다). 학교 계정은 아이디가 학번이라
겹칠 일이 적지만, 개인 회원의 아이디를 이메일 꼴로 받는 자리가 있어 0 은 아니다.
