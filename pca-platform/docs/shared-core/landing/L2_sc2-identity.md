## 무엇이 갈렸나

R40 에서 가지마다 패치를 대어 보다가, **전주 가지가 같은 문제를 다른 방식으로 이미 고쳤다**는 것이 드러났다
(`f144368f` "C16 공통 수정 적용(승인)" · 그 가지에만 · 운영 미병합).

| | Core SC-2 (`sc2-p0.patch`) | 전주 C16 (`feature/jju-campus`) |
|---|---|---|
| 다른 학교의 같은 학번 | **각자의 계정**이 된다 (새 학교는 `<CODE>:<학번>` 손잡이) | **거절**한다(`LoginTaken`) — 두 번째 학교 학생은 계정을 못 받는다 |
| 앞 학교 학생이 다치는가 | 아니다 | 아니다 |
| 원자성 | **거래 · 잠금 없음** — 확인하고 쓰는 사이에 같은 아이디의 다른 요청이 끼어들 수 있다 | **한 거래 + 아이디별 advisory lock** — 동시 등록에 더 단단하다 |
| 배재 동작 | 아이디 = 학번 그대로 · 재등록 수렴 | 같다 |

## Core 권고

1. **방식은 SC-2(학교별 계정)** — 두 번째 학교부터 같은 학번이 흔하다. 거절 방식이면 그 학생은 검사를 볼 수 없다.
2. **전주 C16 의 거래 · advisory lock 을 SC-2 에 합친다** — 동시 명단 적용에서 더 단단하다. Core 가 합친 패치를 다시
   쓰고 두 테스트(`p0-login-collision` · 전주 `jju-c16`)를 같이 통과시키는 것을 다음 걸음으로 둔다.
3. 운영 가지에는 **한 벌만** 들어간다. 전주 가지의 C16 은 합친 패치가 들어갈 때 그 가지 세션이 되돌리거나 덮는다
   (Core 는 그 가지에 쓰지 않는다).
