## 1. 왜 지금 이 순서인가

지금 구조는 그 원칙과 반대로 가는 신호가 셋 있다.

| 신호 | 지금 | 그대로 두면 |
|---|---|---|
| 기관마다 가지 | 배재 · 전주 · 세종 · 운영 가지가 같은 공통 파일을 따로 고친다 | 기관이 늘수록 합칠 때마다 충돌 · 한 기관의 고침이 다른 기관에 조용히 들어가거나 빠진다 |
| 학교 등록부가 파일 하나 | `campus-universities.json` 에 배재 블록 | 두 번째 학교부터 서로의 파일을 고친다 |
| 나라별 자리가 비어 있음 | `country_packs` 0줄 · 파기가 한국 법 기준으로 코드에 박혀 있음 | 해외 첫 나라에서 법정 보존 · 삭제 · 문서가 코드 분기로 들어간다 |

## 2. 안 바뀌는 것 (모든 단계)

| 고정 | 까닭 |
|---|---|
| 측정 축 · 척도 · 채점 · 문항의 뜻 (`ME_V3_MEASUREMENT_FREEZE_1`) | 국가 · 기관 간 비교가 이 회사의 자산이다. 기관 · 나라 · 언어가 판정을 바꾸면 그 자산이 사라진다 |
| 플랫폼 하나 · DB 하나 | 설계 원칙 5 |
| 기관은 기본으로 개인 결과를 못 본다 | CC-005 · 계약 · 동의 · 기록이 다 맞을 때만 |
| Core 는 승인하지 않고 운영 가지에 직접 올리지 않는다 | 착지 권한 범위 |

## 3. 단계

### 단계 0 — 두 번째 학교 전 (지금)

**목표: 두 번째 학교 명단을 받아도 앞 학교 학생이 다치지 않는다는 것을 실행 증거로 보인다.**

| # | 일 | 산출물 | 끝의 정의 |
|---|---|---|---|
| 0-1 | L1 파기 최소 (`v3_experiences` → REMOVE) | `proposed/cc009-l1.patch` · 수정 사본 실행 테스트 | 지금 코드: 재현 PASS · 수정 사본: ER-FIX-1 PASS · 측정 동결 그대로 |
| 0-2 | L2 학교 학생 신원 (CC-002 1단계) | `proposed/sc2-p0.patch` (R36) · 수정 사본 실행 테스트 | 수정 사본 FIX 전부 PASS · 배재 호환 PASS |
| 0-3 | L3 비밀번호 찾기 조회 차례 | `proposed/l3-forgot-order.patch` · 실행 테스트 | 지금 코드: 아이디와 남의 이메일이 겹치면 차례가 정해지지 않음 재현 · 수정 사본: 늘 아이디 쪽 |
| 0-4 | **공통 출시 관문 v1** | `scripts/shared-core/gate.sh` · `gate/summary.tsv` | 한 명령으로 신원 · 파기 · 찾기 · 기관 경계 · 동결을 **지금 코드**와 **수정 사본** 두 줄로 판정 |
| 0-5 | 착지 요청서 셋 | `landing/L1·L2·L3.md` | PM 이 읽고 승인 / 반려할 수 있는 한 장 |

관문 판정의 뜻:

| 판정 | 뜻 |
|---|---|
| `SECOND_TENANT_BLOCKED` | 지금 코드에 P0 재현이 남아 있다 (지금 상태) |
| `READY_WHEN_LANDED` | 수정 사본에서 전부 통과 — 승인 · 합치기만 남았다 |
| `SECOND_TENANT_READY` | 운영 가지에 합쳐진 코드에서 전부 통과 |

| 필요 | 까닭 | 지금 |
