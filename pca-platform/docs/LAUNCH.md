# 오늘 여는 데 필요한 것

현멘을 오늘 실제로 열려면 무엇이 남았는지 적는다. 코드는 대부분 끝났고,
남은 것은 **계약·신고·키 발급** 쪽이다. 이쪽은 코드로 못 줄인다.

결론부터: **오늘 안에 결제까지 되는 상태로는 못 연다.** 토스페이먼츠 계약 심사와
통신판매중개업 신고가 당일에 끝나지 않는다. 대신 오늘 열 수 있는 형태가 하나 있고,
아래 "오늘 할 수 있는 것"에 적었다.

---

## 지금 상태

```
$ npm run check:env
올릴 수 없습니다. 없으면 멈추는 항목 2개가 비어 있습니다.
  없음  결제 (토스페이먼츠)   → 개인 회원이 신청을 마칠 수 없다
  없음  줌 회의 생성          → 멘토가 승낙해도 회의가 만들어지지 않아 승낙 자체가 실패한다
  없음  알림 발송             → 확정 안내와 리마인더가 큐에 쌓이기만 한다
```

코드 쪽에서 만들어 둔 것은 이렇다. 다시 손대지 않아도 된다.

| | |
|---|---|
| 멘토 갤러리 · 상세 · 후기 | 로그인 없이 열린다 |
| 신청 → 결제 → 승낙 → 줌 링크 | 서버 액션으로 이어져 있다 |
| 환불 사다리 (48h 100% · 24h 50% · 이후 0%) | `/admin/prices` 에서 값만 바꾸면 화면·계산 동시 반영 |
| 수수료 10% · 원천징수 3.3% | `npm run check:money` 로 금액 검산 |
| 노쇼 신고와 처리 | 신고 기한 48시간, 인정되면 전액 환불 |
| 정산 보류 → 지급 | 계좌 미등록 멘토는 지급이 막힌다 |
| 환불 실패 재시도 | 부분 환불 금액을 기억해 다시 보낸다 |
| 문의 창구 | 로그인 없이 접수, `/admin/inquiries` 에 모인다 |

## 1. 없으면 문이 안 열리는 것

### 토스페이먼츠 (`NEXT_PUBLIC_TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`)

- 사업자등록증과 **통신판매업 신고증**을 내고 심사를 받는다. 며칠 걸린다.
- 심사 전에도 **테스트 키**는 즉시 받을 수 있다. 흐름 점검은 이걸로 한다.
- 키를 넣은 뒤 `PAYMENTS_DRY_RUN` 을 **지워야** 실제 결제가 일어난다.
- 클라이언트 키는 `NEXT_PUBLIC_` 이라 빌드 시점에 박힌다. 바꾸면 다시 빌드한다.

### 줌 Server-to-Server OAuth (`ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET`)

- Zoom App Marketplace → Build App → **Server-to-Server OAuth**. 유료 계정이 필요하다.
- 회의를 만들고 지우므로 `meeting:write:admin` 계열 스코프가 필요하다.
  (`POST /users/{host}/meetings`, `DELETE /meetings/{id}` 를 쓴다)
- 없으면 **멘토가 승낙을 눌러도 실패한다.** 회의 생성이 승낙 트랜잭션 안에 있다.
- 넣은 뒤 `ZOOM_DRY_RUN` 을 지운다.

### 도메인과 서버

- `AUTH_URL` 에 실제 주소가 들어가야 한다. 메일 속 링크와 로그인 리다이렉트가 이 값을 쓴다.
- HTTPS 필수. 결제창이 http 에서 뜨지 않는다.
- `MAIL_FROM` 을 **같은 도메인**으로 맞춘다. 다른 도메인으로 보내면 SPF·DKIM 이
  어긋나 메일이 스팸함으로 간다. `check:env` 가 둘이 다르면 알려준다.
- 서버는 셋을 띄운다: 웹, PostgreSQL, **5분 크론**(`npm run notify`).
  세 번째를 빠뜨리면 화면은 멀쩡한데 메일이 한 통도 안 나간다. `docker-compose.yml` 에 들어 있다.

#### 도메인

**정본은 `hyunmen.kr`** (2026-09-14 결정). `hyunmen.com` 은 오타 방어용으로 같이 사서
같은 서버를 가리키게 두면, 코드가 `hyunmen.kr` 로 308 로 모은다(`src/middleware.ts`).

2026-09-14 기준 `hyunmen.kr` · `.co.kr` · `.com` · `.net` · `.io` 모두 DNS 응답이 없다.
등록 여부는 등록기관에서 다시 봐야 한다 — 사두고 안 쓰는 도메인은 여기서 구분되지 않는다.
`careerpeak.co.kr` 과 `academix.co.kr` 은 쓰고 있는 브랜드 사이트이고,
`mentorlab.kr` · `phdmentor.com` 은 남이 쓰고 있어 못 쓴다.

소개 사이트는 아임웹(`careerpeak.co.kr`)이 맡는다. 무엇을 어디에 두는지는
[IMWEB.md](IMWEB.md) 에 있다.

#### 도메인이 생긴 날 할 일

```bash
# 1. DNS A 레코드를 서버 IP 로 (별칭까지 전부)
# 2. 인증서를 별칭까지 함께 발급 — 별칭에 인증서가 없으면 308 이 나가기 전에
#    브라우저가 경고를 띄운다. 리다이렉트가 있어도 소용없다
AUTH_URL=https://hyunmen.kr              # .env
MAIL_FROM=no-reply@hyunmen.kr
NEXT_PUBLIC_SITE_URL=https://careerpeak.co.kr
npm run check:env                        # localhost·도메인 불일치를 여기서 잡는다
npm run build                            # NEXT_PUBLIC_TOSS_CLIENT_KEY 가 바뀌었으면 필수
```

소셜 로그인 콜백은 **정본 하나만** 등록한다 — 별칭은 어차피 여기로 넘어온다.

```
https://hyunmen.kr/api/auth/callback/kakao
https://hyunmen.kr/api/auth/callback/naver
```

메일 도메인 인증(SPF·DKIM·DMARC)은 발송사 쪽 안내를 따른다. 이걸 빼면 확정 안내와
리마인더가 스팸함으로 가고, 그러면 노쇼가 늘어난다.

### 통신판매중개업 신고

- 관할 구청. 토스페이먼츠 심사가 이 신고증을 요구한다. **이게 제일 앞에 있다.**
- 신고번호는 `/terms` 의 사업자 정보 표에 `[ ]` 로 비워 두었다.

## 2. 없으면 반쪽인 것

### 알림 (`MAIL_WEBHOOK_URL`)

- 없어도 서비스는 돈다. 큐에 쌓이고, **보낸 척하지 않는다.**
- 다만 확정 안내와 하루 전 리마인더가 안 나가면 노쇼가 늘어난다.
- 형태는 JSON POST 하나다. 어느 발송사든 붙는다.

### 운영 관리자 계정

```bash
ADMIN_EMAIL=ops@example.com ADMIN_PW='...' ADMIN_NAME=박운영 npm run make:admin
```

`npm run db:seed` 는 **운영에 돌리면 안 된다.** 데모 기관과 학생 계정이 딸려 오고
비밀번호가 소스에 박혀 있다.

---

## 3. 있어도 되고 없어도 되는 것

- 카카오·네이버 로그인 — 없으면 버튼이 안 뜰 뿐, 이메일 가입은 그대로 된다.
- 약관·방침 변호사 검토 — 지금 문안은 실제 동작과 맞춰 써 두었지만 검토를 받은 적이 없다.
  `[ ]` 로 비워 둔 상호·주소·대표자·신고번호를 채워야 한다.
- 원천징수 3.3% 신고 절차 — 세무사와 한 번 맞춰야 한다. 계산과 보관은 이미 되어 있다.

## 4. 여는 날 순서

```bash
npm run check:env                 # "올릴 수 없습니다" 가 안 나올 때까지
psql "$DATABASE_URL" -f db/schema.sql
ADMIN_EMAIL=... ADMIN_PW=... npm run make:admin
npm run db:fees                   # 수수료 10% · 원천징수 3.3% · 환불 사다리
npm run check:money               # 3만원 세션 기준 금액 검산
npm run typecheck && npm run build
docker compose up -d              # 웹 + DB + 5분 크론
curl https://hyunmen.kr/api/health   # DB까지 확인한다
```

열고 나서 눈으로 볼 것:

1. `/mentoring` 이 로그인 없이 열린다
2. `/mentoring/contact` 로 문의를 넣고 `/admin/inquiries` 에 뜨는지
3. 테스트 카드로 한 건 결제 → 승낙 → 줌 링크 → 취소·환불까지 한 바퀴
4. 5분 뒤 `notify` 로그에 발송 건수가 찍히는지

## 5. 멘토가 없으면 아무 일도 안 일어난다

키를 다 채워도 갤러리가 비어 있으면 신청이 0이다. 여는 날 기준으로 **경로당 한 명씩,
여섯 명**은 있어야 필터가 의미를 가진다.

멘토 한 명이 올라가는 데 필요한 것:

1. 가입 후 `/mentoring/mentor` 에서 프로필 작성 (별명·학위·진로 경로·연차·회사 규모)
2. 재직 증빙 제출 — 운영사가 `/admin/mentors` 에서 **무엇으로 확인했는지 기록**해야 승인된다.
   근거가 비면 데이터베이스가 갤러리 등재를 막는다.
3. 지급 계좌 등록 — 안 하면 금액이 계산돼도 이체가 막힌다
4. 시간대 열기 — 열지 않으면 신청이 들어오지 않는다

이건 키 발급과 별개로 **오늘 시작할 수 있다.**

## 오늘 할 수 있는 것

결제가 막혀 있어도 이 순서는 오늘 된다.

1. 도메인 연결하고 서버에 올린다 (`PAYMENTS_DRY_RUN=1`, `ZOOM_DRY_RUN=1` 그대로)
2. 관리자 계정을 만들고 수수료·환불 규칙을 확인한다
3. 멘토 모집을 시작한다 — 갤러리·이용 안내·FAQ·문의가 이미 다 열려 있다
4. 그 사이 통신판매중개업 신고 → 토스 심사 → 줌 키를 진행한다
5. 키가 들어오면 `DRY_RUN` 두 줄을 지우고 다시 빌드한다. 그때부터 실제 결제다

**주의**: `PAYMENTS_DRY_RUN=1` 인 상태로 신청을 받으면 결제 없이 세션이 확정된다.
멘토 모집 기간에는 시간대를 열지 않는 편이 안전하다.
