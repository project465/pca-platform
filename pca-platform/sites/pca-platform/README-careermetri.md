# 이 폴더는 무엇인가

`project465.github.io/pca-platform/` 로 나가려는 **정적 진단 플랫폼**입니다.
2026-09-28 에 zip 으로 넘겨받아 여기에 넣었고, 그 뒤에 고친 것이 아래에
전부 적혀 있습니다. 원본 폴더의 `README.md` · `CLAUDE.md` · `HANDOFF.md` 는
넘겨받은 그대로 두었습니다.

이 레포의 `src/` 에 있는 Next.js 플랫폼과는 **다른 물건**입니다. 이쪽은
빌드 없이 파일만으로 도는 무료 진단이고, 문항 은행도 자도 다릅니다.
커리어메트리 한국어 소개 사이트(`sites/careermetri/imweb/01c-try.html`)의
"무료 진단" 단추가 여기를 가리킵니다.

## 넘겨받은 뒤 고친 것

### 1. 더블탭하면 검사가 절반에서 끝나던 것 (`assets/app.js`)

선택지를 두 번 두드리면 문항이 두 칸 넘어가, 28문항 중 13개만 답하고
결과지가 나왔습니다. 5회 중 5회 재현되었고 1회는 JS 오류까지 났습니다.
넘어가는 동안 잠그고 없는 문항이면 아무 일도 하지 않게 고쳤습니다.
고친 뒤 186회를 두드려도 28/28, 오류 0건입니다.

### 2. 1·2·3위를 순위로 내보내던 것 (`assets/engine.js` · `app.js`)

문항을 복원추출해 FIT 의 흔들림을 쟀더니 표준오차가 QUICK ±12.6 ·
STANDARD ±11.7 · PRO ±11.3 인데, 1위와 2위의 차이는 평균 6~8점이었습니다.
**오차가 차이보다 큽니다.** 오차 안에 드는 직무를 한 군으로 묶어 `1군`
배지로 내보냅니다. 값은 `CONFIG.fitSe` 한 곳에 있습니다.

### 3. 세 직무가 어떤 응답으로도 1위가 안 되던 것 (`data/me.js`)

직무 8개를 8축으로 적었는데 그 8축이 실제로 갈라내는 것은 3축이었습니다
(APS~DD +0.87, ST~OPT −0.91). 3차원에 여덟 점을 갈리게 놓을 수는 없어서,
생산기술 · 품질·신뢰성 · 설비·유지보수가 1위가 되지 못했습니다.

원래 값에서 **가장 적게 움직이는 지점**을 찾아 고쳤습니다. 한 칸 ±8점,
직무마다 1위 축과 꼴찌 축은 그대로, 축 순서는 스피어만 0.90 이상, 평균
요구 수준 ±3점 — 이 안에서만 찾았고, 움직인 것은 64칸 중 16칸 109점입니다.
QUICK 28문항도 120문항 중에서 다시 골랐습니다(문항 원문은 한 글자도
바뀌지 않았고, 어느 것을 QUICK 으로 낼지만 바뀝니다).

| | 도달 못 하는 직무 | 되찾기 | 최대 편중 |
|---|---|---|---|
| QUICK 전 / 후 | 3 → **0** | 39.3% → **63.2%** | 31.9% → 22.8% |
| STANDARD 전 / 후 | 2 → **0** | 50.8% → **56.9%** | 22.7% → 21.8% |
| PRO 전 / 후 | 2 → **0** | 48.4% → **56.8%** | 22.6% → 22.7% |

무작위가 12.5% 입니다.

### 4. 단계 선택 (`index.html` · `app.js` · `data/grad.js`)

첫 화면이 다섯 단계를 먼저 묻습니다 — 학부 재학/졸업예정(UNDERGRAD) ·
학부 졸업(EARLY CAREER) · 석사(GRAD M.S.) · 박사(GRAD Ph.D.) ·
석·박사 졸업 후(RESEARCH CAREER). 주소로도 됩니다(`?stage=MS`).

**학과보다 단계를 먼저 묻습니다.** 단계에 따라 문항 수가 28↔54 로 달라져서,
나중에 물으면 이미 시작한 사람의 문항 수가 도중에 바뀝니다.

대학원·연구 세 단계에서는 연구 역량 문항 26개가 붙고 결과지에 **연구 역량
8축** 절이 생깁니다. 축 이름·신호·"읽는 곳" 은 전부 원본
`grad_track_definitions.json` 의 값입니다.

## `data/me.js` 는 임시입니다

원본 규칙대로라면 `data/*.js` 는 `tools/build_major.py` 의 산출물이고 손으로
고치지 않습니다. 지금 들어 있는 파일은 xlsx 를 고치기 전에 화면으로 먼저
보라고 만든 것입니다. **정본으로 만들려면** `source/` 의 두 파일을 원본
xlsx 에 옮기고 도구를 다시 돌립니다.

```
source/job_matrix_me_v2.csv   →  03_*_Job_Matrix 시트
source/quick_tier_v2.csv      →  04_*_QuestionBank_120 의 Form 칸 (28줄)
python3 tools/build_major.py --xlsx ... --code ME --name 기계공학과 \
        --content content/me.json --out data/me.js
node source/fit3.mjs           # 도달 못 하는 직무가 0인지 다시 본다
python3 source/matrix.py source/job_matrix_me_v2.csv
```

`source/job_matrix_me_v1.csv` 는 고치기 전 원본입니다. 되돌릴 때 씁니다.

## 올리기

지금 `project465.github.io/pca-platform/` 는 **이 레포의 어느 브랜치에서도
서비스되고 있지 않습니다.** `gh-pages` 브랜치가 없고 `main` 루트에는
`index.html` 이 없습니다(그쪽은 Next.js 입니다). 켜는 방법은 둘입니다.

1. **`gh-pages` 브랜치** — 이 폴더의 내용을 그 브랜치의 루트로 올리고,
   Settings › Pages 에서 `gh-pages` / `/ (root)` 를 고릅니다.
   주소가 `project465.github.io/pca-platform/` 그대로 유지됩니다
2. **`main` 의 `/docs`** — 이 폴더를 `docs/` 로 옮기고 Pages 를
   `main` / `/docs` 로 놓습니다. Next.js 와 한 브랜치에 같이 삽니다

`.nojekyll` 이 이미 들어 있습니다(밑줄로 시작하는 파일이 있을 때 필요합니다).
