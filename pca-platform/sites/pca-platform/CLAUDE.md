# 작업 규칙

## 배포

- GitHub Pages, `main` 브랜치 루트에서 서비스합니다.
- 빌드 단계가 없습니다. `main`에 push하면 그대로 반영됩니다.
- push 전에 반드시 로컬에서 확인합니다.
  ```bash
  python3 -m http.server 8000
  ```
  최소한 다음 3개는 눈으로 확인하고 올립니다.
  - `/?major=ME&form=QUICK` 를 끝까지 응시해 결과가 나오는지
  - 학과 선택 화면에서 준비중 학과가 눌리지 않는지
  - 문항 중간에 새로고침했을 때 이어지는지
- 커밋은 의미 있는 작업 단위로 나누고, 커밋 메시지는 한국어로 씁니다.

## 코드

- 외부 프레임워크를 추가하지 않습니다. 정적 파일 그대로 유지합니다.
- `assets/engine.js`는 계산만 합니다. DOM·화면 관련 코드를 넣지 않습니다.
- `data/*.js`는 `tools/build_major.py`의 산출물입니다. 직접 편집하지 않습니다.
  문항·가중치 수정은 원본 xlsx → 도구 재실행 순서로 합니다.
- 사람이 쓰는 문구는 `content/<code>.json`과 `assets/app.js` 상단 상수에 모읍니다.

## 채점 로직

`assets/engine.js`의 `CONFIG`만 바꾸면 채점 방식이 바뀝니다.
이 값을 바꾸면 기존 응시자의 점수가 달라집니다. 바꿀 때는

1. 왜 바꾸는지 커밋 메시지에 남기고
2. `scoring_engine` 버전 문자열을 올리고
3. 결과에 버전이 찍히는지 확인합니다.

인수인계 문서 원안과 다르게 설정한 항목은 `engine.js` 맨 위 주석에 이유와 함께
정리되어 있습니다. 되돌리려면 그 주석의 설명대로 `CONFIG` 값만 바꾸면 됩니다.

## 하지 말아야 할 것

- 문항 원문·가중치·직무 매트릭스를 "검증 완료"라고 표현하지 않습니다.
- FIT을 취업 가능성으로 설명하지 않습니다. FIT은 업무방식의 유사성입니다.
- 결과 화면에서 직무를 확정 판정처럼 쓰지 않습니다. 탐색 우선순위로 표현합니다.
- 응시자 이름·학번을 결과 계산에 쓰지 않습니다. 표시 용도로만 씁니다.
