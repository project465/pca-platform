# 아임웹에 붙이는 코드

아임웹에 붙일 수 있게 쪼갠 한 벌이다. **셀렉터를 전부 `cm-` 으로 감쌌다.**
`body`·`section`·`h2` 같은 태그를 직접 잡으면 아임웹 테마가 같이 바뀐다.

**바탕은 밝다.** 비즈니스 홍보 템플릿은 머리글과 하단이 밝은데 본문만
어두우면 페이지가 밝고 어두운 띠로 번갈아 끊겨 보인다. 그래서 딥네이비는
바탕이 아니라 활자로 쓰고, 어두운 띠는 맨 위 한 장만 둔다.

`sites/careermetri/index.html` 은 어두운 채로 남겼다. 그쪽은 혼자 서는 한
장이라 밝은 테마와 맞출 상대가 없고, 한 가지 색으로 밀고 가는 것이 그
화면에는 낫다. 놓이는 자리가 달라서 그렇다.

### 띠는 위젯에 붙이는 class 로 고른다

| class | 바탕 | 쓰는 곳 |
|---|---|---|
| `cm` | 흰색 | 기본. 대부분의 절 |
| `cm cm-tint` | 연회색 `#F2F4F7` | 절이 길게 이어질 때 하나를 눌러 쉼표를 만든다 (지금은 가격) |
| `cm cm-dark` | 딥네이비 | 맨 위 한 장 (`01-hero`) |

### Head Code 는 여기서 고치지 않는다 (2026-09-18)

`00-head-code.html` 과 `00b-head-code-as-widget.html` 은 머리말만 빼면
`../imweb-en/00-head-code.html` 과 **한 글자도 다르지 않다.** 디자인은 두
사이트가 한 벌이어야 하고, 두 벌을 따로 고치면 반드시 한쪽만 고쳐지는
날이 온다. 고칠 곳은 영문판 하나이고, 고친 뒤 여기로 복사한다.

`npm run copy:audit` 이 세 파일의 몸통이 갈라졌는지 확인한다. 눈으로 지킬
수 없는 약속이라 숫자로 지킨다. 주석이 영어인 것도 같은 이유다. 번역본을
두면 그것부터 갈라진다.

### 모서리와 글꼴

**각진 모서리를 쓰지 않는다.** 그릇(표·받침·칸·패키지·슬라이드)은 24px,
안에 든 이미지는 16px, 단추는 알약(999px)이다. 값은 `:root` 의 `--cm-r` ·
`--cm-r2` · `--cm-pill` 세 개에 있다.

올라온 면에는 아주 얕은 그림자(`--cm-lift`)를 하나 둔다. 선만으로 층을
나누면 평면이 되고, 짙게 주면 옛날 카드가 된다.

**글꼴은 Pretendard 하나다.** 제목·본문·숫자가 같은 집안이어야 한 화면으로
읽힌다. 숫자는 폰트를 바꾸는 대신 `tabular-nums` 로 줄을 맞춘다. Head Code
가 글꼴 링크를 둘 싣는데, 앞이 Pretendard(jsDelivr)이고 뒤가 Noto Sans
KR(Google Fonts)이다. **뒤엣것은 앞이 못 뜬 날에만 실제로 내려받는다.**
쓰이지 않는 `@font-face` 는 파일을 가져오지 않기 때문이다.

색은 `class` 안에서 토큰이 바뀌는 방식이라, 띠를 옮기려면 `class` 한 곳만
고친다. 글자 대비는 재서 골랐다: 본문 17.3:1, 보조 6.4:1, 금색 글자 5.9:1.
**금색 `#C9A227` 은 흰 바탕에서 2.4:1 이라 글자로 쓰지 않는다** — 채움과
괘선에만 쓰고, 글자로 쓸 때는 `--cm-acc`(`#7A6214`) 를 쓴다.

## 1. CSS 는 한 번만

`00-head-code.html` 을 통째로 복사해서

```
관리자 > 설정 > SEO > (아래로 내려) 공통 코드삽입 > Header Code
```

**칸 이름은 `Header Code` 다.** `Head Code` 가 아니다. 대시보드 성장하기
카드의 [검색엔진 최적화] 를 눌러도 같은 화면으로 간다.

이 칸을 못 찾으면 `00b-head-code-as-widget.html` 을 쓴다. 같은 내용인데
**페이지마다 맨 위 코드 위젯**에 하나씩 붙이는 판이다. 일곱 장 전부에
넣어야 하고, 한 장이라도 빠지면 그 페이지만 맨몸으로 나온다.

에 붙인다. 모든 페이지에 적용된다. **폰트 링크가 여기 들어 있으니 이걸
먼저 붙여야** 나머지 위젯이 제 모양으로 나온다.

## 2. 섹션마다 코드 위젯

디자인 모드에서 섹션을 만들고 **코드 위젯**을 얹은 뒤, 아래 파일을 하나씩
붙인다. 위젯 하나가 한 절이다.

| 페이지 | 붙일 파일 (위에서 아래 순서) |
|---|---|
| 홈 | `01-hero` · `16-screens` · `17-measure` · `14-target` · `02-problem` · `03-output` |
| 진단 | `04-measure` · `07-survey` |
| 결과 예시 | `05-result` · `18-two` · `06-cohort` |
| 제공 학과 | `08-majors` |
| 지역 연계 | `09-region` |
| 도입 안내 | `10-price` · `15-effect` · `11-evidence` |
| 문의 | `12-contact` + 그 아래 아임웹 폼 위젯 |
| 문의 뺀 모든 페이지 | 맨 아래에 `19-cta` |
| 모든 페이지 | 아무 자리에나 `21-dock` 하나 |
| 모든 페이지 하단 | `13-footer` |

메뉴는 코드로 만들지 않는다. **아임웹 메뉴 설정으로 만든다.** 그래야
모바일 햄버거와 현재 위치 표시가 알아서 붙는다.

## 2-1. 옆으로 넘기는 판

`05-result`(결과지 11절)와 `16-screens`(실제 화면 3장)에 들어 있다. **배선은
`00-head-code.html` 의 스크립트가 한다.** 위젯에는 마크업만 있다.

- `scroll-snap` 이라 스크립트가 죽어도 손가락과 트랙패드로는 넘어간다
- 아임웹이 위젯을 늦게 심어도 `MutationObserver` 가 새로 생긴 판을 잡는다
- 화살표 키로도 넘어가고, 끝에 닿으면 단추가 흐려진다
- **장이 다섯을 넘으면 점 대신 채워지는 선을 쓴다.** 열한 장에서 점은 지금
  어디인지를 더는 말해 주지 않는다. 둘 중 하나만 쓴다
- **자동 넘김은 절마다 켜고 끈다.** `cm-sl` 에 `data-cm-auto="6500"` 이
  붙으면 그만큼 머물다 넘어간다. 포인터가 올라오면, 안쪽에 초점이 있으면,
  탭이 숨으면 멈추고, 모션 최소화를 요청한 방문자에게는 아예 돌지 않는다.
  글 슬라이더에는 걸지 않았다. 읽는 중에 넘어가는 글은 안 넘어가는 글보다
  나쁘다
- **마우스로 끌기는 이미지 슬라이더(`cm-sl-img`)에만 걸었다.** 글 슬라이드에서는
  같은 동작이 줄을 긁어 고르는 동작이다. 끄는 동안 `scroll-snap` 을 꺼야
  한다. mandatory 스냅이 매 프레임 제자리로 당겨서, 잘게 나뉜 드래그는 자기
  장을 영영 못 벗어난다

## 3. 이미지 세 장

`sites/careermetri/img/` 의 셋을 아임웹 이미지로 올린 뒤, 위젯 코드 안의
자리표시자를 올라간 주소로 바꾼다.

| 자리표시자 | 올릴 파일 | 있는 곳 |
|---|---|---|
| `IMG_TEST` | `img/test.png` | `16-screens` |
| `IMG_REPORT` | `img/report.png` | `05-result` · `16-screens` |
| `IMG_ORG` | `img/org.png` | `06-cohort` · `16-screens` |

셋 다 우리 플랫폼에서 실제로 뽑은 기계공학 화면이다.

## 4. 코드로 만들지 않는 것 셋

**문의 폼.** `12-contact.html` 은 머리글까지다. 폼은 **아임웹 폼 위젯**으로
넣는다. 코드로 만든 `<form>` 은 받는 곳이 없어서 누르면 아무 일도 일어나지
않는다.

**법적 표시.** 상호·대표자·사업자등록번호·통신판매업 신고번호는 아임웹의
**[하단 필수정보]** 기능으로 넣는다. 그쪽이 전자상거래법 제10조 항목을
칸으로 갖고 있어서 빠뜨릴 일이 없다. `13-footer.html` 은 브랜드 줄과
직업정보제공사업 신고번호만 담았다.

**버튼 주소.** `01-hero.html` 의 `href="/contact"` · `href="/result"` 는
아임웹에서 만든 실제 페이지 주소로 바꾼다.

## 5. 고칠 때 한 군데씩

| 바꾸는 것 | 고칠 곳 |
|---|---|
| 기관 계약 단가 | `10-price.html` 의 세 패키지와 단가표 첫 줄 |
| 개인 업그레이드 값 | `10-price.html` 의 "개인으로 오신 경우" 와 `products.amount` 의 `UNIV_UPGRADE` |
| 색·활자 | `00-head-code.html` 의 `:root` 변수 |
| 어느 절을 어두운 띠로 | 그 위젯의 `class="cm"` 을 `class="cm cm-dark"` 로 |
| 학과 목록 | `08-majors.html` 표 |
| 브랜드 이름 | `01-hero.html`·`13-footer.html` 과 `00-head-code.html` 의 `.cm-brand` |

## 6. 주의

- 코드 위젯은 **HTML 만** 넣는다. `<style>` 이나 `<script>` 를 위젯마다 넣으면
  같은 규칙과 같은 배선이 여러 번 실리고, 아임웹이 위젯을 옮길 때 순서가
  뒤집힌다. 슬라이더 배선도 Head Code 에 한 번만 있다
- 위젯 안 여백은 `.cm` 의 `padding:56px 20px` 이 준다. 아임웹 섹션 여백을
  따로 주면 두 배가 되니 한쪽을 0 으로 둔다
- 400px 폭에서 가로 스크롤이 없는 것을 확인했다. 표는 각자 스크롤 칸 안에 있다

## 7. 쪽마다 형식이 다르다 (2026-09-18)

일곱 쪽이 전부 "두 칸 머리 다음에 표 하나" 였다. 표는 줄끼리 견주라고 있는
형식인데 이 쪽들의 내용은 아무도 줄끼리 견주지 않는다. 쪽마다 형식을 갈랐다.

| 쪽 | 형식 |
|---|---|
| 홈 | 큰 숫자(`cm-kpi`) · 화면 슬라이더 · 방사형과 막대 · 카드 |
| 진단 | 숫자 타일 · **눌러 보는 문항**(`cm-try`) · 레일(`cm-time`) |
| 결과 예시 | 11절 슬라이더 · **두 사람 도형 나란히** · 표 |
| 도입 안내 | 패키지 카드 · 가격표 · 번호 차례(`cm-steps`) · 숫자 타일 |
| 문의 | 레일. 누른 다음 무엇이 언제 오는지 |

**`17-measure` 와 `18-two` 는 손으로 고치지 않는다.** `npm run metri:radar`
가 DB 에서 채점 결과를 읽어 좌표까지 계산해 두 사이트에 같이 쓴다. 값만
고치고 도형을 다시 계산하지 않으면 그림이 옆의 숫자와 다른 말을 한다.

**눌러 보는 문항은 점수를 만들지 않는다.** 문항 하나로는 못 만들고, 만드는
척하는 것이 이 사이트가 처음 하는 거짓말이 된다. 대신 그 한 답이 어느
직무영역과 어느 성향으로 가는지, 그리고 결과를 얼마나 움직이는지를 적는다.
쓰는 문항은 실제 검사지 1번(`PCA.ME.001`)이고 성향이 함께 실린 문항이다.

## 8. 문의로 가는 길 (2026-09-18)

`19-cta` 를 **모든 쪽 맨 아래, 푸터 바로 위**에 붙인다. 쪽마다 같은 모양인
것이 일부러다. 문의할 준비가 된 사람이 쪽마다 새 배치를 배울 이유가 없다.

`21-dock` 은 쪽을 따라 내려오는 막대다. 쪽마다 하나씩, 아무 자리에나 붙이면
된다(창 아래에 붙으므로 문서에서의 위치는 상관없다). 쪽의 55% 가 지나간
뒤에만 올라오고, 한 번 닫으면 다시 뜨지 않는다.

**문의 쪽은 "연락 주세요" 에서 끝나지 않는다.** 누른 다음 무엇이 언제
오는지를 네 단계로 적어 둔다. 대부분의 문의 쪽은 그 셋을 읽는 사람이
상상하게 둔다.
